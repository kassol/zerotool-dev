## 修正要点

- **ssl-certificate-decoder**：隐私题补本站每项 50 KB 的存储上限与超限后保留旧值；MD5 由页面 JS 计算，改称「SHA 指纹用 Web Crypto」；证书链上限 200 张；`X509 CERTIFICATE` 与 `TRUSTED CERTIFICATE` 标为非标准 / OpenSSL；BR 有效期改为按签发日期的档位表述，并写明 2020-09-01 之前的规则未建模。
- **cookie-parser**：400 天截断限定为 Chrome 104+ 与 RFC 6265bis §5.5 的建议；SameSite 缺省改为「Firefox / Safari 不采用 Lax 默认，Safari 另默认拦第三方」；Domain 等于响应主机时，只有「公共后缀且等于主机」才按 host-only；`__Http-` 只需 Secure + HttpOnly，`__Host-Http-` 才需四项；Chromium 偏差补到六条；公共后缀列表的加载触发条件补上聚焦输入与生成器填 Domain。
- **bcrypt-generator**：Spring Security 拒绝 72 字节以上密码的版本由「6.3+」改为 6.3.8 / 6.4.4；中文「加密」改为「哈希」（RuoYi 段保留方法名 `encryptPassword`）；CJK 字符改为「通常 3 字节」，补充平面汉字为 4 字节。
- **hmac-generator**：密钥编码按平台分开：Stripe 用含 `whsec_` 的整串、Chatwork 解码令牌、Standard Webhooks 只解码 `whsec_` 之后；Stripe 5 分钟为默认且可配置；5 分钟 / 1 小时限定为本工具的检查范围，Standard Webhooks 未规定固定容差；密钥与消息对调的诊断仅限 Custom HMAC；Shift_JIS / GBK / EUC-KR 文本可按十六进制或 Base64 粘贴。
- **json-schema-validator**：`$recursiveRef` 与 `unevaluated*` 的组合条件按引擎实际判断收窄；「浏览器校验器都做不到 2^53」限定为「只比较 `JSON.parse` 结果的校验器」；YAML 语法错误有行列，只有 YAML 数据的校验错误没有行号；重复键最后胜出限定为 JSON，YAML 重复键是解析错误；阈值改为 1,000,000 个 UTF-16 编码单元与 20 MiB；数值关键字补 `exclusiveMinimum` / `exclusiveMaximum`。

## 发现的问题

- **B 档（已修）**：`SslCertificateDecoderTool.astro` 的 PEM 分支把 `-----BEGIN PKCS12-----` 当「非证书」跳过，但没有置 `hasPrivateKey`，该输入仍会写入 localStorage，与页面「含私钥的输入不保存」不符。DER 形态的 `.p12` 不受影响。修法是该分支置位；`test-ssl-certificate-decoder.mjs` 新增两条回归（引擎层 `hasPrivateKey` 与页面层不保存 / 清除），修前 2 项失败，修后 1,059 项通过。
- **待定**：`bcrypt-generator` 的 zh seoTitle 仍写「加密与校验」，正文已说明是单向哈希。保留是为搜索意图；`tools.ts` 的 zh 名称与描述同属此决定，本批未改。
- **C 档（已核实 / 已标注）**：hmac 的「刷新即清空」用 ego-browser（Ego Lite 2.1.0，Chromium 内核）在本地构建上重载验证，两栏清空且 localStorage 无本工具键；各工具竞品段已逐处确认带 2026-10-01 / 02 日期，未复测的数字保留为历史观察；json-schema 的 Test Suite 计数已补 commit 5b0ee16 与 2026-10-02，6 MB 耗时的英文段也补上日期。
