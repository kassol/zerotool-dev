## 修正要点

- **eyedropper-color-picker**：11 组修正、42 处字符串；按组件的真实限制与 CSS Color 4 / EyeDropper 支持数据改写不支持 API 时的行为、取样与 P3 说明。2026-10-01 竞品观察保留日期。
- **wifi-qr-code-generator**：WIFI URI 在 WPA3 规范的 **v3.0** 加入（非 v3.5）；`T:WEP` / `nopass` 是 ZXing / Android 值；`R:1` 的 bit 0 是 WPA3-Personal Only，会停用 PSK；规范的 `I` 是 SAE Password Identifier，企业字段限制拆成两条；补 `%XX` 字面量与百分号编码的歧义。
- **color-blindness-simulator**：画布上限写明 iOS Safari 4,096 × 4,096 与面积上限 16,777,216，极端长宽比可能导出失败；P3 占比补「按预览统计、≥0.1% 才显示」；ja 的 `#008000` 改为 CSS 色名 `green`；多个未复核的患病率与 CUDO 数字标为 unverified。
- **har-file-analyzer**：HAR 1.2 链接从 W3C 的「DO NOT USE」页换成正式规范；Chrome 脱敏还会省略 EventSource 消息数据；导出保留输入的 `log.version`；1.5 ms 容差改为「≥ 1.5 ms」；`_transferSize` 只归 Chrome，Firefox 用 `bodySize`；客户端 IP 头随 IP 选项清除；`errVersion` 改为任意 1.x。
- **qr-code-generator**：201 条陈述逐项核对；修正模式、容量、纠错、汉字模式、颜色与导出相关的具体说法，保留 2026-10-01 竞品观察。

## 发现的问题

- **A 档（引擎冻结，未改）**：eyedropper 的 `MAX_CANVAS_AREA` 只按面积缩放，5,000 × 3,000 这类图不超过面积上限却超过 MDN 的 iOS 4,096 px 单边限制，iOS 可能无法取色。页面已写明限制，引擎块未改。
- **B 档（文案已限定，代码未改）**：color-blindness 的 `fitImageSize` 只限面积不限单边（`ColorBlindnessSimulatorTool.astro:839-845`），页面已写明极端长宽比可能失败。
- **C 档（已标注）**：HAR 组件的 `exDone` / `exCheckScope` 对「已去掉的值」复查范围的措辞仍略强于代码；Safari 导出步骤与 TLS 拆分未复核。
