# AGENTS.md — scripts/

## 职责

构建管线辅助脚本与维护工具，全部用 Node 直接跑（`.mjs` 或 `.js`），无 TypeScript 编译步骤。

- **副作用清晰**：脚本注释开头必须写明读写哪些文件
- **idempotent**：重复运行不应产生差异（`generate-blog-redirects.mjs` 当前是 append 模式，依赖 `astro build` 每次重写 `_redirects` 实现幂等）
- **退出码语义**：失败用 `process.exit(1)`，禁止吞错继续
- **路径**：用 `import.meta.url` + `fileURLToPath` 拿绝对路径，不假设 cwd
- **调用系统工具链的测试按 CI 环境核对**：CI 跑在 Ubuntu（`cc` 是 GCC、`bash` 4.2+），本机 macOS 是 Apple clang 与 bash 3.2，同一输入的报错 / 警告行为可能不同。断言「编译器 / 解释器拒绝某输入」时显式给出让两边一致的参数（如 GCC 默认只对超范围转义告警，要加 `-pedantic-errors`），并在合并前用与 CI 相同的工具链（或 `gcc-*` 等同类工具）跑一遍
- **依赖运行时内置实现的测试按 CI 的 Node 版本核对**：CI 用 Node 22（`.github/workflows/ci.yml`），本机可能更新。引擎直接调用 `URL`、`Intl`、`TextDecoder` 等内置实现时，拿规范测试集（如 WPT）断言前先看运行时本身是否符合；不符合的项记 SKIP 并写明 Node 版本，不算工具失败。合并前用 `npx -y -p node@22 node scripts/test-xxx.mjs` 跑一遍
- **合并前用 CI 的 Node 版本跑全部测试**：本地验证在 `npm ci` 之后用 Node 22 运行全部 `scripts/test-*.mjs`，不只跑改动过的测试；依赖版本以 lockfile 为准（未重新安装的 node_modules 会让测试读到旧版本）
- **对照外部实现的测试固定版本**：拿 Python 包、CLI 等外部实现的结果做断言时，只在装的正好是记录时的版本才比较（如 jsonschema 4.26.0、PyJWT 2.10.1、protego 0.7.0），其他版本记 SKIP 并写明版本。CI 的 Ubuntu runner 自带一些旧版 Python 包（2026-10-02 为 jsonschema 4.10.3），按「有就比」会在本机通过、CI 失败
- **标准库与系统 CLI 的行为随版本变化时按行为分支**：Python 标准库、`openssl` 这类无法固定版本的对照对象，新旧行为各记一份期望，运行时用探测（而非只看版本号）决定比哪一份，并在测试输出中打印版本与所选行为；解析 CLI 文本输出时同时接受新旧格式，遇到两种都不认识的格式报 FAIL，不默默得到 null
- **测试不依赖随机结果的长度或本机速度**：随机输出（签名、随机串）按结构断言，不写固定长度区间；耗时上限乘 `PERF_SLACK`（`process.env.CI ? 4 : 1`），只拦数量级的退化
