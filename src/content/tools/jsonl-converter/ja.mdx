<h2>例：注文ログの大きな注文番号</h2>
<p>注文番号などを 64 ビット整数で扱うシステムでは、値が 2<sup>53</sup> を超えることがあります。JavaScript で <code>JSON.parse()</code> してから <code>JSON.stringify()</code> すると末尾の桁が変わりますが、このツールは <code>JSON.parse()</code> を構文チェックだけに使い、数値は入力の文字をそのまま書き出します。</p>

{/* jlc-check: {"dir":"jsonl","out":"json","status":"2 件の JSONL レコードを JSON 配列に変換しました。"} */}
```json
{"order_no":9007199254740993,"price":1980.00,"store":"渋谷店"}
{"order_no":9007199254740995,"price":550.50,"store":"\u6885\u7530\u5e97"}
```

```json
[
  {
    "order_no": 9007199254740993,
    "price": 1980.00,
    "store": "渋谷店"
  },
  {
    "order_no": 9007199254740995,
    "price": 550.50,
    "store": "梅田店"
  }
]
```

<p>解析してから文字列に戻す方法では <code>9007199254740992</code>、<code>9007199254740996</code>、<code>1980</code>、<code>550.5</code> になります。文字列は <code>JSON.stringify()</code> の標準の書き方で出力するため、<code>{'"\\u6885\\u7530\\u5e97"'}</code> は <code>"梅田店"</code> になり、コンパクトな JSONL ではカンマの後の空白も消えます。</p>

<p>逆方向でも数値は残ります。</p>

{/* jlc-check: {"dir":"json","out":"jsonl","status":"2 件の JSON 配列アイテムを JSONL に変換しました。"} */}
```json
[
  {"order_no": 9007199254740993, "price": 1980.00},
  {"order_no": 9007199254740995, "price": 550.50}
]
```

```json
{"order_no":9007199254740993,"price":1980.00}
{"order_no":9007199254740995,"price":550.50}
```

<h2>コピーと保存</h2>
<p>
  <strong>コピー</strong>ボタンと 2 つの保存ボタンは、最後に成功した変換の結果を使います。<strong>JSONL → JSON</strong> の後、<strong>.json を保存</strong>は右側の配列を保存し、
  JSONL 側の<strong>コピー</strong>と<strong>.jsonl を保存</strong>は変換したレコードを 1 行 1 件のコンパクトな形で出します。貼り付けた原文とは違い、「有効な行だけ変換」で除いたエラー行は含まれず、空白も取り除かれています。
  <strong>JSON → JSONL</strong> の後は、<strong>.json を保存</strong>が現在の「JSON を整形」の設定で配列を保存します。
</p>
<p>
  最初の変換までボタンは使えません。どちらかのパネルを編集したとき、「空行を無視」「有効な行だけ変換」を切り替えたとき、<strong>クリア</strong>（またはツール内で Ctrl+L / Cmd+L）を押したとき、変換やファイル読み込みに失敗したときも、すぐに使えなくなります。変換に失敗すると出力側は空になるので、古い入力の結果をコピーすることはありません。自動検証だけではボタンは使えるようになりません。「JSON を整形」を切り替えると、JSONL 側に内容があれば <strong>JSONL → JSON</strong> をやり直します。
</p>

<h2>JSONL と JSON 配列</h2>
<p>
  JSON 配列はすべてのレコードを 1 つの大きなドキュメントに包みます。JSONL は各レコードを独立した JSON 値として 1 行に書きます。
  この行指向の形は、ログ、ストリーミングエクスポート、コマンドライン処理、大規模データセットに向いています。
</p>

<h2>例：3 行のエクスポートに壊れた行が 1 つ</h2>
<p>次の内容を JSONL パネルに貼り付け、350 ms 後の自動検証を待ちます。</p>

{/* jlc-validate: {"counts":[3,2,1,0],"line":2,"message":"27 列目、閉じかっこの前に余分なカンマがあります。"} */}
```json
{"id":1,"event":"signup"}
{"id":2,"event":"purchase",}
{"id":3,"event":"cancel"}
```

<p>カウンターは全 3 行、有効 2、エラー 1、空行 0 になります。問題パネルには<strong>2 行目</strong>と、エラーの列と原因が表示されます：<code>{"27 列目、閉じかっこの前に余分なカンマがあります。"}</code>（列はその行の先頭から数えた値）。この行を直すか<strong>有効な行だけ変換</strong>をオンにするまで、<strong>JSONL → JSON</strong> はエラーで止まります。オンにすると 1 件目と 3 件目が出力されて「2 件の JSONL レコードを JSON 配列に変換しました。」と表示され、<strong>.jsonl を保存</strong>では次の内容が保存されます。</p>

{/* jlc-check: {"dir":"jsonl","validOnly":true,"out":"download-jsonl","status":"2 件の JSONL レコードを JSON 配列に変換しました。"} */}
```json
{"id":1,"event":"signup"}
{"id":2,"event":"purchase",}
{"id":3,"event":"cancel"}
```

```json
{"id":1,"event":"signup"}
{"id":3,"event":"cancel"}
```

<h2>コマンドラインでの同等操作</h2>
<p>スクリプトに組み込むなら <a href="https://jqlang.org/manual/" target="_blank" rel="noopener">jq</a> で同じ変換ができます（jq 1.7.1 の実際の出力）。</p>

```bash
jq -c '.[]' data.json > data.jsonl   # JSON 配列 → JSONL
jq -s '.' data.jsonl > data.json     # JSONL → JSON 配列
jq -c . bad.jsonl                    # 最初のエラーで停止する:
# jq: parse error: Expected another key-value pair at line 2, column 28
```

<p>jq は最初のエラーで止まります。このツールは全行を解析し、エラー行をまとめて一覧にします。</p>

<h2>制限</h2>
<ul>
  <li><strong>重複キーは最後の値になります</strong>。<code>JSON.parse()</code> と同じで、<code>{`{"x":1,"x":2}`}</code> は最初の <code>x</code> の位置で <code>{`{"x":2}`}</code> になります。</li>
  <li><strong>配列の添字のようなキーはオブジェクトの先頭に移り</strong>、数値の昇順に並びます（JavaScript のオブジェクトと同じ）。<code>{`{"b":1,"2":2,"1":3}`}</code> は <code>{`{"1":3,"2":2,"b":1}`}</code> になります。値は変わりません。</li>
  <li><strong>JSON → JSONL</strong> はトップレベルの配列だけを受け付けます。オブジェクトや単一の値では「JSON 入力は配列である必要があります。」と表示されます。</li>
  <li>1 レコードは 1 行に収める必要があります。複数行に整形したオブジェクトは、またがる行がすべてエラーになります。改行で分割し各行の前後の空白を除くため、Windows の CRLF ファイルはそのまま使えます。</li>
  <li>問題パネルに表示するのは最初の 40 行までです。エラー数のカウンターは全件を数えます。</li>
</ul>
