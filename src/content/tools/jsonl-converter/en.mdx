<h2>Worked Example</h2>
<p>Input JSONL:</p>

{/* jlc-check: {"dir":"jsonl","out":"json","status":"Converted 2 JSONL records to a JSON array."} */}
```json
{"id":1,"event":"signup","user":"alice"}
{"id":2,"event":"purchase","user":"bob","amount":29.99}
```

<p>Output JSON array:</p>

```json
[
  {
    "id": 1,
    "event": "signup",
    "user": "alice"
  },
  {
    "id": 2,
    "event": "purchase",
    "user": "bob",
    "amount": 29.99
  }
]
```

<h2>Numbers Keep Their Digits</h2>
<p>
  The tool uses <code>JSON.parse()</code> only to check the syntax. It writes every number with the characters from the input, so IDs
  above 2<sup>53</sup>, trailing zeros and exponents survive both directions:
</p>

{/* jlc-check: {"dir":"jsonl","out":"json"} */}
```json
{"order_id":9007199254740993,"total":1.50,"rate":1e-7}
{"order_id":9007199254740994, "note":"caf\u00e9", "total":0}
```

```json
[
  {
    "order_id": 9007199254740993,
    "total": 1.50,
    "rate": 1e-7
  },
  {
    "order_id": 9007199254740994,
    "note": "café",
    "total": 0
  }
]
```

<p>
  A plain <code>JSON.parse()</code> followed by <code>JSON.stringify()</code> would write <code>9007199254740992</code> and
  <code>1.5</code>. Strings are a different case: the tool writes them in the standard
  <code>JSON.stringify()</code> form, so <code>{'"caf\\u00e9"'}</code> becomes <code>"café"</code>, and the space after a comma
  disappears in compact JSONL.
</p>

<h2>Copy and Download</h2>
<p>
  The <strong>Copy</strong> buttons and both downloads use the result of the last successful conversion. After
  <strong>JSONL → JSON</strong>, <strong>Download .json</strong> saves the array shown on the right, and the JSONL
  <strong>Copy</strong> and <strong>Download .jsonl</strong> give the converted records one per line in compact form. That is not the
  text you pasted: invalid lines left out by <strong>Convert valid lines only</strong> are gone and spacing is removed. After
  <strong>JSON → JSONL</strong>, <strong>Download .json</strong> saves your array formatted with the current <strong>Pretty JSON output</strong>
  setting.
</p>
<p>
  The buttons are disabled before the first conversion and again as soon as you edit either panel, change <strong>Ignore empty
  lines</strong> or <strong>Convert valid lines only</strong>, click <strong>Clear</strong> (or press Ctrl+L / Cmd+L in the tool),
  or a conversion or a file read fails. Changing <strong>Pretty JSON output</strong> runs <strong>JSONL → JSON</strong> again when the JSONL panel has text. A failed conversion also empties the output panel, so you cannot
  copy a result that belongs to older input. Automatic validation on its own never enables them.
</p>

<h2>JSONL vs JSON Arrays</h2>
<p>
  A JSON array wraps every record inside one large document. JSONL writes each record as a standalone JSON value on its own line.
  That line-oriented shape works well for logs, streaming exports, command-line processing, and large datasets where each record can be handled independently.
</p>

<h2>Command-Line Equivalents</h2>
<p>For repeatable scripts, <a href="https://jqlang.org/manual/" target="_blank" rel="noopener">jq</a> does the same conversions (jq 1.7.1 output):</p>

```bash
jq -c '.[]' data.json > data.jsonl   # JSON array → JSONL
jq -s '.' data.jsonl > data.json     # JSONL → JSON array
jq -c . bad.jsonl                    # stops at the first bad line:
# jq: parse error: Expected another key-value pair at line 2, column 28
```

<p>jq stops at the first error. The tool parses every line and lists all failing lines at once.</p>

<h2>Limits</h2>
<ul>
  <li><strong>Duplicate keys keep the last value</strong>, as <code>JSON.parse()</code> does: <code>{`{"x":1,"x":2}`}</code> becomes <code>{`{"x":2}`}</code>, at the place of the first <code>x</code>.</li>
  <li><strong>Keys that look like array indexes move to the front</strong> of their object, in ascending order, as in a JavaScript object: <code>{`{"b":1,"2":2,"1":3}`}</code> becomes <code>{`{"1":3,"2":2,"b":1}`}</code>. Values do not change.</li>
  <li><strong>JSON → JSONL</strong> accepts only a top-level array. An object or a single value produces "JSON input must be an array."</li>
  <li>Each record must sit on one line. A pretty-printed object spread across several lines fails on every line it spans. Lines are split on line feeds and trimmed, so Windows CRLF files work.</li>
  <li>The issue panel shows the first 40 failing lines; the error counter still counts all of them.</li>
</ul>
