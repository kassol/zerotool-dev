<h2>사용 방법</h2>
<ol>
  <li>왼쪽 패널에 JSONL / NDJSON을 붙여넣거나 로컬 <code>.jsonl</code>, <code>.ndjson</code>, <code>.json</code>, <code>.txt</code> 파일을 엽니다.</li>
  <li><strong>검증</strong>을 클릭하면 각 줄을 확인하고 파싱 오류의 줄 번호를 보여 줍니다.</li>
  <li><strong>JSONL → JSON</strong>을 클릭하면 레코드로 JSON 배열을 만듭니다.</li>
  <li>오른쪽 패널에 JSON 배열을 붙여넣고 <strong>JSON → JSONL</strong>을 클릭하면 compact JSON Lines를 출력합니다.</li>
  <li><strong>복사</strong>, <strong>.json 저장</strong>, <strong>.jsonl 저장</strong>으로 변환 결과를 가져갑니다.</li>
</ol>

<h2>예시: 주문 로그의 큰 주문번호</h2>
<p>주문번호를 64비트 정수로 쓰는 시스템에서는 값이 2<sup>53</sup>을 넘기도 합니다. JavaScript에서 <code>JSON.parse()</code> 후 <code>JSON.stringify()</code>하면 끝자리가 바뀌지만, 이 도구는 <code>JSON.parse()</code>를 문법 검사에만 쓰고 숫자는 입력한 문자를 그대로 씁니다.</p>

{/* jlc-check: {"dir":"jsonl","out":"json","status":"JSONL 레코드 2개를 JSON 배열로 변환했습니다."} */}
```json
{"order_no":9007199254740993,"amount":15000.0,"region":"부산"}
{"order_no":9007199254740995,"amount":8900.50,"region":"\uc11c\uc6b8"}
```

```json
[
  {
    "order_no": 9007199254740993,
    "amount": 15000.0,
    "region": "부산"
  },
  {
    "order_no": 9007199254740995,
    "amount": 8900.50,
    "region": "서울"
  }
]
```

<p>파싱한 뒤 다시 문자열로 만들면 <code>9007199254740992</code>, <code>9007199254740996</code>, <code>15000</code>, <code>8900.5</code>가 됩니다. 문자열은 <code>JSON.stringify()</code>의 표준 표기로 출력하므로 <code>{'"\\uc11c\\uc6b8"'}</code>은 <code>"서울"</code>이 되고, compact JSONL에서는 쉼표 뒤 공백도 사라집니다.</p>

<p>반대 방향에서도 숫자는 유지됩니다.</p>

{/* jlc-check: {"dir":"json","out":"jsonl","status":"JSON 배열 항목 2개를 JSONL로 변환했습니다."} */}
```json
[
  {"order_no": 9007199254740993, "amount": 15000.0},
  {"order_no": 9007199254740995, "amount": 8900.50}
]
```

```json
{"order_no":9007199254740993,"amount":15000.0}
{"order_no":9007199254740995,"amount":8900.50}
```

<h2>복사와 저장</h2>
<p>
  <strong>복사</strong> 버튼과 두 저장 버튼은 마지막으로 성공한 변환의 결과를 씁니다. <strong>JSONL → JSON</strong> 후에는 <strong>.json 저장</strong>이 오른쪽 배열을 저장하고,
  JSONL 쪽 <strong>복사</strong>와 <strong>.jsonl 저장</strong>은 변환된 레코드를 한 줄에 하나씩 compact 형식으로 내보냅니다. 붙여넣은 원문과는 다르며, '유효한 줄만 변환'으로 뺀 오류 줄은 없고 공백도 제거되어 있습니다.
  <strong>JSON → JSONL</strong> 후에는 <strong>.json 저장</strong>이 현재 'JSON 보기 좋게 출력' 설정으로 배열을 저장합니다.
</p>
<p>
  첫 변환 전에는 버튼을 쓸 수 없습니다. 어느 쪽 패널이든 편집하거나, '빈 줄 무시'·'유효한 줄만 변환'을 바꾸거나, <strong>지우기</strong>(또는 도구 안에서 Ctrl+L / Cmd+L)를 누르거나, 변환이나 파일 읽기에 실패하면 바로 쓸 수 없게 됩니다. 변환에 실패하면 출력 쪽이 비워지므로 이전 입력의 결과를 복사하는 일은 없습니다. <strong>검증</strong>만으로는 버튼이 활성화되지 않습니다. 'JSON 보기 좋게 출력'을 바꾸면 JSONL 쪽에 내용이 있을 때 <strong>JSONL → JSON</strong>을 다시 실행합니다.
</p>

<h2>JSONL과 JSON 배열</h2>
<p>
  JSON 배열은 모든 레코드를 하나의 큰 문서 안에 감쌉니다. JSONL은 각 레코드를 독립적인 JSON 값으로 한 줄에 씁니다.
  이 줄 중심 형식은 로그, 스트리밍 내보내기, 명령줄 처리, 대형 데이터셋에 잘 맞습니다.
</p>

<h2>예시: 3줄짜리 내보내기에 잘못된 줄이 하나</h2>
<p>아래 내용을 JSONL 패널에 붙여넣고 <strong>검증</strong>을 누릅니다.</p>

{/* jlc-validate: {"counts":[3,2,1,0],"line":2,"message":"Expected double-quoted property name in JSON at position 27 (line 1 column 28)"} */}
```json
{"id":1,"event":"signup"}
{"id":2,"event":"purchase",}
{"id":3,"event":"cancel"}
```

<p>카운터는 전체 3줄, 유효 2, 오류 1, 빈 줄 0을 표시합니다. 문제 패널에는 <strong>2번째 줄</strong>과 브라우저의 파서 메시지가 나오며, Chrome에서는 <code>{"Expected double-quoted property name in JSON at position 27 (line 1 column 28)"}</code>입니다(위치는 해당 줄의 시작부터 센 값). Firefox와 Safari는 문구가 다릅니다. 이 줄을 고치거나 <strong>유효한 줄만 변환</strong>을 켜기 전까지 <strong>JSONL → JSON</strong>은 오류로 멈춥니다. 옵션을 켜면 1번과 3번 레코드가 출력되고 "JSONL 레코드 2개를 JSON 배열로 변환했습니다."가 표시되며, <strong>.jsonl 저장</strong>은 다음 내용을 저장합니다.</p>

{/* jlc-check: {"dir":"jsonl","validOnly":true,"out":"download-jsonl","status":"JSONL 레코드 2개를 JSON 배열로 변환했습니다."} */}
```json
{"id":1,"event":"signup"}
{"id":2,"event":"purchase",}
{"id":3,"event":"cancel"}
```

```json
{"id":1,"event":"signup"}
{"id":3,"event":"cancel"}
```

<h2>명령줄에서 같은 작업</h2>
<p>스크립트에 넣을 때는 <a href="https://jqlang.org/manual/" target="_blank" rel="noopener">jq</a>로 같은 변환을 할 수 있습니다(jq 1.7.1 실제 출력).</p>

```bash
jq -c '.[]' data.json > data.jsonl   # JSON 배열 → JSONL
jq -s '.' data.jsonl > data.json     # JSONL → JSON 배열
jq -c . bad.jsonl                    # 첫 오류에서 멈춤:
# jq: parse error: Expected another key-value pair at line 2, column 28
```

<p>jq는 첫 오류에서 멈춥니다. 이 도구는 모든 줄을 파싱해 오류 줄을 한 번에 보여 줍니다.</p>

<h2>제한</h2>
<ul>
  <li><strong>중복 키는 마지막 값이 남습니다.</strong> <code>JSON.parse()</code>와 같이 <code>{`{"x":1,"x":2}`}</code>는 첫 <code>x</code> 자리에서 <code>{`{"x":2}`}</code>가 됩니다.</li>
  <li><strong>배열 인덱스처럼 보이는 키는 객체 맨 앞으로 옮겨져</strong> 숫자 오름차순으로 정렬됩니다(JavaScript 객체와 동일). <code>{`{"b":1,"2":2,"1":3}`}</code>는 <code>{`{"1":3,"2":2,"b":1}`}</code>가 됩니다. 값은 바뀌지 않습니다.</li>
  <li><strong>JSON → JSONL</strong>은 최상위 배열만 받습니다. 객체나 단일 값이면 "JSON 입력은 배열이어야 합니다."가 표시됩니다.</li>
  <li>레코드 하나는 한 줄에 있어야 합니다. 여러 줄로 정렬된 객체는 걸친 줄마다 오류가 납니다. 줄바꿈으로 나눈 뒤 각 줄의 앞뒤 공백을 제거하므로 Windows CRLF 파일도 그대로 쓸 수 있습니다.</li>
  <li>문제 패널은 처음 40개 오류 줄만 보여 주며, 오류 카운터는 전부 셉니다.</li>
</ul>
