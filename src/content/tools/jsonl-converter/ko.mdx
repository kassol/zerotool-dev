<h2>사용 방법</h2>
<ol>
  <li>JSONL / NDJSON을 왼쪽 패널에 붙여넣거나 로컬 <code>.jsonl</code>, <code>.ndjson</code>, <code>.json</code>, <code>.txt</code> 파일을 엽니다.</li>
  <li><strong>검증</strong>을 클릭해 각 줄을 검사하고 파싱 오류가 있는 줄 번호를 확인합니다.</li>
  <li><strong>JSONL → JSON</strong>을 클릭해 유효한 레코드로 JSON 배열을 만듭니다.</li>
  <li>오른쪽 패널에 JSON 배열을 붙여넣고 <strong>JSON → JSONL</strong>을 클릭해 compact JSON Lines 출력을 생성합니다.</li>
  <li><strong>.json 저장</strong> 또는 <strong>.jsonl 저장</strong>으로 변환 결과를 저장합니다.</li>
</ol>

<h2>예시</h2>
<p>입력 JSONL:</p>

```json
{"id":1,"event":"signup","user":"alice"}
{"id":2,"event":"purchase","user":"bob","amount":29.99}
```

<p>출력 JSON 배열:</p>

```json
[
  {
    "id": 1,
    "event": "signup",
    "user": "alice"
  },
  {
    "id": 2,
    "event": "purchase",
    "user": "bob",
    "amount": 29.99
  }
]
```

<h2>JSONL과 JSON 배열</h2>
<p>
  JSON 배열은 모든 레코드를 하나의 큰 문서 안에 감쌉니다. JSONL은 각 레코드를 독립적인 JSON 값으로 한 줄에 씁니다.
  이 줄 중심 형식은 로그, 스트리밍 내보내기, 명령줄 처리, 대형 데이터셋에 잘 맞습니다.
</p>

<h2>검증 방식</h2>
<p>
  검증기는 빈 줄을 제외한 각 줄을 <code>JSON.parse()</code>로 파싱합니다. 성공한 줄은 유효 레코드로 집계됩니다.
  실패한 줄은 문제 패널에 표시되며 줄 번호, 파서 메시지, 원본 줄의 짧은 미리보기를 확인할 수 있습니다.
</p>

<h2>예시: 3줄짜리 내보내기에 잘못된 줄이 하나</h2>
<p>아래 내용을 JSONL 패널에 붙여넣고 <strong>검증</strong>을 누릅니다.</p>

```json
{"id":1,"event":"signup"}
{"id":2,"event":"purchase",}
{"id":3,"event":"cancel"}
```

<p>카운터는 전체 3줄, 유효 2, 오류 1, 빈 줄 0을 표시합니다. 문제 패널에는 <strong>2번째 줄</strong>과 브라우저의 파서 메시지가 나오며, Chrome에서는 <code>{"Expected double-quoted property name in JSON at position 27 (line 1 column 28)"}</code>입니다(위치는 해당 줄의 시작부터 센 값). Firefox와 Safari는 문구가 다릅니다. 이 줄을 고치거나 <strong>유효한 줄만 변환</strong>을 켜기 전까지 <strong>JSONL → JSON</strong>은 오류로 멈춥니다. 옵션을 켜면 1번과 3번 레코드가 출력되고 "JSONL 레코드 2개를 JSON 배열로 변환했습니다."가 표시됩니다.</p>

<h2>명령줄에서 같은 작업</h2>
<p>스크립트에 넣을 때는 <a href="https://jqlang.org/manual/" target="_blank" rel="noopener">jq</a>로 같은 변환을 할 수 있습니다(jq 1.7.1 실제 출력).</p>

```bash
jq -c '.[]' data.json > data.jsonl   # JSON 배열 → JSONL
jq -s '.' data.jsonl > data.json     # JSONL → JSON 배열
jq -c . bad.jsonl                    # 첫 오류에서 멈춤:
# jq: parse error: Expected another key-value pair at line 2, column 28
```

<p>jq는 첫 오류에서 멈춥니다. 이 도구는 모든 줄을 파싱해 오류 줄을 한 번에 보여 줍니다.</p>

<h2>제한</h2>
<ul>
  <li>숫자는 JavaScript <code>JSON.parse()</code>로 파싱하므로 2<sup>53</sup>을 넘는 정수는 양방향 모두 정밀도가 떨어집니다. <code>{`{"order_id":9007199254740993}`}</code>은 <code>9007199254740992</code>가 됩니다. jq 1.7은 원래 리터럴을 유지합니다. 큰 ID를 그대로 왕복해야 하면 문자열로 저장하세요.</li>
  <li><strong>JSON → JSONL</strong>은 최상위 배열만 받습니다. 객체나 단일 값이면 "JSON 입력은 배열이어야 합니다."가 표시됩니다.</li>
  <li>레코드 하나는 한 줄에 있어야 합니다. 여러 줄로 정렬된 객체는 걸친 줄마다 오류가 납니다. 줄바꿈으로 나눈 뒤 각 줄의 앞뒤 공백을 제거하므로 Windows CRLF 파일도 그대로 쓸 수 있습니다.</li>
  <li>문제 패널은 처음 40개 오류 줄만 보여 주며, 오류 카운터는 전부 셉니다.</li>
</ul>
