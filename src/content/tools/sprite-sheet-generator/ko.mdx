## Unity에서 그리드 시트 자르기

{/* ssg-check: {"items":[["run_1.png",32,32],["run_2.png",32,32],["run_3.png",32,32],["run_4.png",32,32],["run_5.png",32,32],["run_6.png",32,32]],"opts":{"layout":"grid","columns":4,"spacing":0},"expect":{"size":[128,64],"unique":6}} */}

달리기 동작 6프레임(각 32 × 32)을 Unity의 Sprite Editor로 자르는 경우입니다. 배치를 그리드, 열 수 4, 간격·바깥 여백·가장자리 확장 0으로 두면 시트는 **128 × 64 px**이고, 둘째 줄 오른쪽 두 칸은 비어 있습니다.

[Unity 매뉴얼의 자동 슬라이싱](https://docs.unity3d.com/kr/2022.3/Manual/sprite-automatic-slicing.html) 설명대로 Slice 메뉴에서 **Grid By Cell Size**를 고르고 **Pixel Size**에 32 × 32를 넣습니다. Offset은 이미지 왼쪽 위에서 격자를 옮기는 값이라 0으로 둡니다. 매뉴얼에 따르면 **Keep Empty Rects**를 켰을 때만 픽셀이 없는 SpriteRect가 남으므로, 끈 상태에서는 빈 두 칸이 프레임으로 만들어지지 않습니다.

그리드는 가장 큰 이미지를 셀 크기로 쓰고 작은 이미지는 셀 가운데에 둡니다. 크기가 제각각인 프레임을 Unity에서 이름으로 쓰려면 Unity 자체의 Sprite Atlas를 쓰는 편이 맞고, 이 도구의 JSON은 Phaser·PixiJS 같은 웹 엔진용입니다.

## CSS 스프라이트와 웹 접근성

{/* ssg-check: {"items":[["call.png",32,32],["mail.png",32,32],["map.png",32,32]],"opts":{"trim":false},"format":"css","image":"icons.png","expect":{"size":[32,100]},"text":["background-position: 0 -34px;"],"notes":[]} */}

'고객센터' 영역의 전화·메일·지도 아이콘(각 32 × 32)을 한 장으로 묶어 봅니다. '투명 여백 트림'을 끄고(CSS는 트림한 크기로 내보내므로 아이콘 둘레의 여백이 사라집니다) 데이터 형식을 CSS, 시트 이름을 `icons`로 두면 시트는 **32 × 100 px**입니다. 메일 아이콘 규칙은 다음과 같습니다.

```css
.icons-mail {
  width: 32px;
  height: 32px;
  background-position: 0 -34px;
}
```

CSS 배경 이미지에는 `alt`가 없어서 화면 낭독기가 아이콘의 뜻을 읽지 못합니다. [한국형 웹 콘텐츠 접근성 지침(KWCAG) 2.2](https://a11ykr.github.io/docs/kwcag2/)의 5.1.1(적절한 대체 텍스트 제공)은 '의미 있는 배경 이미지'의 뜻이 보조기술로 전달되도록 대체 텍스트를 제공하라고 정합니다. 아이콘만 있는 링크나 버튼에는 aria-label을 주거나 화면에서만 숨긴 텍스트를 넣습니다. aria-label을 쓰면 이렇습니다.

```html
<a href="tel:15880000" class="icons icons-call" aria-label="전화 문의"></a>
```

옆에 '전화 문의'라는 글자가 이미 있으면 아이콘은 장식이므로 대체 텍스트를 넣지 않습니다.

## Phaser·PixiJS용 JSON

데이터 형식 JSON Hash는 Phaser 3.90.0 / 4.2.1과 PixiJS 8.22.0의 파서로 읽어 확인했습니다. 이름이 끝의 숫자만 다른 프레임(`run_1.png` … `run_6.png`)은 `animations`의 `run`으로 묶여 PixiJS에서 `new AnimatedSprite(sheet.animations.run)`으로 바로 재생됩니다. PixiJS는 JSON Array의 프레임을 이름이 아니라 `"0"`, `"1"` 번호로 등록하므로 PixiJS에는 JSON Hash를 쓰세요. Phaser 3.90 이하는 XML에서 트림한 프레임의 원래 크기를 잘못 읽습니다([Phaser issue #7245](https://github.com/phaserjs/phaser/issues/7245), 4.0.0에서 수정). 이 경우 도구가 알려 주며, Phaser 3에서는 JSON Hash를 쓰면 됩니다.

## 번짐 방지와 텍스처 크기

크기를 바꾸거나 소수 좌표에 그리면 선형 필터링이 옆 프레임의 색을 섞습니다. **간격**은 프레임 사이에 투명 픽셀을 넣고, **가장자리 확장**은 바깥 픽셀을 1~8px 복제해 타일 이음매를 막고, **바깥 여백**은 시트 가장자리에서 띄웁니다. 최근접 필터로 정수 좌표에 그리는 픽셀 아트라면 모두 0이어도 됩니다.

[Web3D Survey](https://web3dsurvey.com/webgl2/parameters/MAX_TEXTURE_SIZE)(2026-10-02 확인)에서 모든 Android 기기는 한 변 4,096px WebGL2 텍스처를 지원하지만 8,192px는 77%만 지원합니다. 한 변이 4,096px를 넘으면 도구가 알려 줍니다.

## 다른 도구와 비교

2026-10-02에 같은 파일(64 × 64 걷기 4프레임 중 1프레임 중복, 4프레임 GIF, SVG 1개)로 시험했습니다. 세 도구 모두 이미지를 업로드하지 않았습니다.

- **MergeImage 스프라이트 시트 만들기**: PNG·JPEG·WebP만 받으며(GIF·SVG를 함께 고르면 아무것도 추가되지 않았습니다) 최대 30프레임입니다. 기본 프레임 크기가 128 × 128이라 64 × 64 이미지가 확대되었고, JSON에는 `frame` 128 × 128과 `sourceSize` 64 × 64가 함께 적혔습니다.
- **CodeAndWeb Free Sprite Sheet Packer**(TexturePacker 개발사): Phaser·PixiJS·CSS 데이터를 내보내지만 트림은 TexturePacker Pro 기능으로 안내되어 적용되지 않았고, 중복 프레임도 두 번 배치했습니다.
- **free-tex-packer.org 0.6.7**: 트림과 같은 이미지 감지를 지원하지만 프레임 회전이 기본으로 켜져 있고 간격은 0이며, GIF는 첫 프레임만, SVG·WebP는 읽지 못했습니다.

## 제한

- 이미지는 1,000개까지, 한 장은 한 변 8,192px까지. 시트는 한 변 16,384px, 총 16,777,216픽셀까지이고 WebP는 한 변 16,383px까지입니다.
- WebP는 Chrome·Edge에서 무손실로 저장됩니다. Safari는 WebP를 인코딩하지 못해 선택할 수 없습니다.
- canvas는 미리 곱한 알파로 색을 보관합니다. Chrome 152에서 알파 1인 `rgb(200, 100, 50)` 픽셀은 `rgb(255, 0, 0)`으로, 알파 128이면 `rgb(199, 100, 50)`으로 저장되었습니다. 불투명한 픽셀은 바뀌지 않습니다.
- 움직이는 WebP와 APNG는 첫 프레임만 씁니다. 프레임 회전, 여러 페이지, plist와 Unity·Godot 전용 파일은 내보내지 않습니다.
