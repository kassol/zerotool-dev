## RPGツクールMZ の歩行グラフィックを作る

{/* ssg-check: {"items":[["hero_01.png",48,48],["hero_02.png",48,48],["hero_03.png",48,48],["hero_04.png",48,48],["hero_05.png",48,48],["hero_06.png",48,48],["hero_07.png",48,48],["hero_08.png",48,48],["hero_09.png",48,48],["hero_10.png",48,48],["hero_11.png",48,48],["hero_12.png",48,48]],"opts":{"layout":"grid","columns":3,"spacing":0},"image":"$hero.png","expect":{"size":[144,192],"unique":12} } */}

[RPGツクールMZ の素材規格](https://rpgmakerofficial.com/product/mz/rpgmz_manual/01_11_01.html)では、歩行キャラクターは 1 キャラクターあたり 48 × 48 を基準に、4 方向（下・左・右・上）× 3 パターンの計 12 パターンを並べます。標準は 1 ファイルに 8 キャラクターですが、ファイル名の頭に `$` を付けると 1 キャラクター = 1 ファイルとして扱われます。

ドット絵ツールから 1 コマずつ書き出した `hero_01.png` ～ `hero_12.png`（01–03 が下向き、04–06 が左向き…）を読み込み、次のように設定します。

- 配置：グリッド、列数：3
- 間隔・外側余白・エッジ拡張：0（規格はコマの隙間を想定していません）
- 2 のべき乗：オフ
- シート名：`$hero`

結果は **144 × 192 px** で、`$hero.png` を `img/characters` に置けば読み込めます。間隔を初期値の 2 のままにすると 148 × 198 px になり、ツクールが計算する 1 コマの大きさ（幅の 1/3、高さの 1/4）がずれるので注意してください。グリッドはいちばん大きい画像をセルの大きさにし、小さい画像はセルの中央に置きます。

## トリムした連番アニメーション

{/* ssg-check: {"items":[["slime_1.png",48,48,[8,26,32,22]],["slime_2.png",48,48,[10,18,28,24],"s2"],["slime_3.png",48,48,[12,6,24,26]],["slime_4.png",48,48,[10,18,28,24],"s2"]],"format":"xml","image":"slime.png","expect":{"size":[32,76],"unique":3},"text":["<SubTexture name=\"slime_4.png\" x=\"0\" y=\"24\" width=\"28\" height=\"24\" frameX=\"-10\" frameY=\"-18\" frameWidth=\"48\" frameHeight=\"48\"/>"],"notes":["xmlTrim"]} */}

跳ねるスライムの 4 コマ（1→2→3→2 の順で、4 コマ目は 2 コマ目と同じ絵）を詰め込み配置にすると、透明な余白を削ったうえで同じ絵は 1 か所にまとまり、**32 × 76 px**、「スプライト 4 個（重複なし 3 個）」になります。データ形式を XML（Sparrow / Starling）にした場合の 4 コマ目：

```xml
<SubTexture name="slime_4.png" x="0" y="24" width="28" height="24" frameX="-10" frameY="-18" frameWidth="48" frameHeight="48"/>
```

`frameX` と `frameY` は削った余白の分だけ元の 48 × 48 の中で絵をどこに戻すかを表し、エンジンはこの値で足元の位置を保ちます。ただし Phaser 3.90 以前はこの XML の元サイズを誤って読む不具合があり（[Phaser issue #7245](https://github.com/phaserjs/phaser/issues/7245)、4.0.0 で修正）、既定以外の origin を使うスプライトがずれます。トリムしたフレームを XML で書き出すとツールにも注意が出ます。Phaser 3 なら JSON Hash を選ぶか、トリムをオフにしてください。

## Phaser・PixiJS で読み込む

書き出した JSON は Phaser 3.90.0 / 4.2.1 と PixiJS 8.22.0 のパーサーで読み込んで確認しています。JSON Hash では、末尾の数字だけが違うフレームが `animations` にまとめられます。

```js
// Phaser 3 / 4
this.load.atlas('slime', 'assets/slime.png', 'assets/slime.json');

// PixiJS 8
const sheet = await Assets.load('assets/slime.json');
const jump = new AnimatedSprite(sheet.animations.slime);
```

PixiJS は JSON Array のフレームを名前ではなく `"0"`、`"1"` の番号で登録するため、PixiJS では JSON Hash を使います。

## にじみ対策と最大サイズ

拡大縮小や小数座標で描くと、バイリニア補間で隣のコマの色がにじみます。**間隔**はコマの間に透明なピクセルを入れ、**エッジ拡張**は外周のピクセルを 1～8 px 外へ複製してタイルの継ぎ目を防ぎ、**外側余白**はシートの端から離します。ニアレストネイバーで整数座標に描くドット絵なら、すべて 0 でかまいません。

[Web3D Survey](https://web3dsurvey.com/webgl2/parameters/MAX_TEXTURE_SIZE)（2026-10-02 参照）では、Android の報告はすべて一辺 4,096 px の WebGL2 テクスチャに対応していますが、8,192 px に対応するのは 77% です。どちらかの辺が 4,096 px を超えるとツールに注意が表示されます。

## ほかのツールとの違い

2026-10-02 に同じファイル（64 × 64 の歩行 4 コマのうち 1 コマが重複、4 フレームの GIF、SVG 1 枚）で試しました。いずれも画像をアップロードしていません。

- **のんびりスタジオ「スプライトシート作成ツール」**：いちばん大きい画像に合わせたグリッドで並べ、「1コマ 64×64px / 4列 2行」のようにエンジンに入力する値を表示します。足元を揃える「中央下」の配置もあります。出力は PNG のみで座標データはなく、GIF は最初のフレームだけ、SVG は追加されませんでした。
- **CodeAndWeb Free Sprite Sheet Packer**（TexturePacker の開発元）：Phaser・PixiJS・CSS 用データを出せますが、トリムは TexturePacker Pro の機能とされていて行われず、重複コマも 2 回配置されました。
- **free-tex-packer.org 0.6.7**：トリムと同一画像の検出に対応しますが、フレームの回転が初期値でオンになり、間隔は 0、GIF は 1 フレーム、SVG と WebP は読み込めませんでした。

## 制限

- 画像は 1,000 枚まで、1 枚は一辺 8,192 px まで。シートは一辺 16,384 px、合計 16,777,216 ピクセルまで。WebP は一辺 16,383 px まで。
- WebP は Chrome・Edge ではロスレスで書き出します。Safari は WebP を書き出せないため選べません。
- canvas は乗算済みアルファで色を保持します。Chrome 152 では、アルファ 1 の `rgb(200, 100, 50)` が `rgb(255, 0, 0)` になり、アルファ 128 では `rgb(199, 100, 50)` になりました。不透明なピクセルは変わりません。
- アニメーション WebP と APNG は最初のフレームだけを使います。フレームの回転、複数ページ、plist や Unity・Godot 向けの書き出しはありません。
