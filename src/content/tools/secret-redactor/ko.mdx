<h2>사용 방법</h2>

<ol>
  <li>물어볼 로그, 스택 트레이스, <code>.env</code>, 설정 파일을 ① 칸에 붙여넣습니다. 입력하는 동안 감지가 진행됩니다.</li>
  <li>② 칸을 확인합니다. 시크릿은 <code>[OPENAI_KEY_1]</code> 같은 플레이스홀더로 바뀌어 있습니다. <strong>감지 목록</strong>을 펼치면 어떤 규칙이 잡았는지 보이고, 오탐이 나는 카테고리는 끌 수 있습니다.</li>
  <li>② 칸을 복사해 ChatGPT, Claude 등에 붙여넣습니다. 질문 앞에 "대괄호 안의 [OPENAI_KEY_1] 같은 값은 마스킹된 것이니 그대로 두세요"라고 적어 두면 복원이 잘 됩니다.</li>
  <li>받은 답변을 ③ 칸에 붙여넣으면 남아 있던 플레이스홀더가 실제 값으로 돌아옵니다. 그대로 터미널이나 에디터에 복사하면 됩니다.</li>
</ol>

<p>복원을 마칠 때까지 ① 칸은 바꾸지 마세요. 플레이스홀더와 값의 매핑은 이 텍스트에서 매번 새로 만들어지고 다른 곳에는 저장되지 않습니다.</p>

<h2>예시 1: 네이버 검색 API 호출</h2>

<p>네이버 검색 API는 두 개의 헤더로 인증합니다(<a href="https://developers.naver.com/docs/serviceapi/search/blog/blog.md">네이버 개발자 센터</a>). 값은 모두 예시입니다.</p>

```bash
$ curl "https://openapi.naver.com/v1/search/blog.json?query=%EB%A7%88%EC%8A%A4%ED%82%B9" \
    -H "X-Naver-Client-Id: DemoClientId0000" \
    -H "X-Naver-Client-Secret: DemoSecr3t"
```

<p>② 칸 결과:</p>

```bash
$ curl "https://openapi.naver.com/v1/search/blog.json?query=%EB%A7%88%EC%8A%A4%ED%82%B9" \
    -H "X-Naver-Client-Id: DemoClientId0000" \
    -H "X-Naver-Client-Secret: [SECRET_1]"
```

<p>헤더 이름이 <code>Secret</code>으로 끝나는 Client Secret만 바뀌고, Client Id는 이름이 <code>Id</code>로 끝나서 그대로 남습니다. Client Id도 숨기고 싶다면 복사한 뒤 직접 지우세요.</p>

<h2>예시 2: Spring 설정 파일과 답변 복원</h2>

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/shop
spring.datasource.password=shop-local-pw!
kakao.rest-api-key=0a1b2c3d4e5f60718293a4b5c6d7e8f9
jwt.secret=local-dev-jwt-signing-secret-please-change
```

<p>비밀번호, 카카오 키, JWT 서명 키가 차례로 <code>[SECRET_1]</code>, <code>[SECRET_2]</code>, <code>[SECRET_3]</code>가 됩니다. 이 예시의 카카오 키는 16진수라 고엔트로피 검사에는 걸리지 않지만, 이름이 <code>api-key</code>로 끝나서 가려집니다. 답변이 이렇게 왔다고 해 봅시다.</p>

```text
로컬 설정은 환경 변수로 빼 두세요.
export KAKAO_REST_API_KEY=[ SECRET_2 ]
export JWT_SECRET='[secret_3]'
운영 키는 [API_KEY_1]처럼 따로 관리하세요.
```

<p>③ 칸에서는 공백이 들어간 <code>[ SECRET_2 ]</code>와 소문자 <code>[secret_3]</code>가 원래 값으로 돌아오고, 상태 표시는 "2곳 복원 완료 (매핑 3개 중 2개 사용)"입니다. 매핑에 없는 <code>[API_KEY_1]</code>은 그대로 두고 "알 수 없는 플레이스홀더"로 따로 알려 줍니다. 설정 파일에 어떤 변수가 있는지 먼저 훑어보려면 <a href="/ko/tools/env-file-parser/">.env 파일 파서</a>를 쓰면 됩니다.</p>

<h2>국내 서비스 키는 어떻게 처리되나</h2>

<table>
  <thead>
    <tr><th>대상</th><th>결과</th><th>근거</th></tr>
  </thead>
  <tbody>
    <tr><td>네이버 <code>X-Naver-Client-Secret</code></td><td>가림</td><td>헤더 이름</td></tr>
    <tr><td>카카오 REST API 키, 토스페이먼츠 시크릿 키를 담은 변수(<code>…_API_KEY</code>, <code>…_SECRET_KEY</code>)</td><td>가림</td><td>변수 이름</td></tr>
    <tr><td>토스페이먼츠 API의 <code>Authorization: Basic …</code>(<a href="https://docs.tosspayments.com/reference/using-api/authorization">토스페이먼츠 문서</a>)</td><td>가림</td><td>Basic 헤더 규칙</td></tr>
    <tr><td>카카오 <code>Authorization: KakaoAK …</code>(<a href="https://developers.kakao.com/docs/latest/ko/local/dev-guide">카카오 문서</a>)</td><td>키를 <code>[KAKAO_API_KEY_n]</code>으로 가림</td><td>인증 방식 이름 <code>KakaoAK</code> 뒤의 영숫자 16자 이상</td></tr>
    <tr><td>네이버 <code>X-Naver-Client-Id</code></td><td>가려지지 않음</td><td>이름이 Id로 끝남</td></tr>
  </tbody>
</table>

<p>해외 서비스는 형식으로 찾습니다. GitHub의 <code>ghp_</code> 등 접두사는 <a href="https://github.blog/engineering/platform-security/behind-githubs-new-authentication-token-formats/">GitHub 공식 블로그</a>, AWS의 <code>AKIA</code>·<code>ASIA</code>는 <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html">IAM 문서</a>, Anthropic의 <code>sk-ant-</code>는 <a href="https://platform.claude.com/docs/en/get-api-key">Anthropic 문서</a>를 따릅니다. JWT는 <a href="https://www.rfc-editor.org/rfc/rfc7519">RFC 7519</a>, Bearer 헤더는 <a href="https://www.rfc-editor.org/rfc/rfc6750">RFC 6750</a>, Basic 헤더는 <a href="https://www.rfc-editor.org/rfc/rfc7617">RFC 7617</a>, PEM 개인 키는 <a href="https://www.rfc-editor.org/rfc/rfc7468">RFC 7468</a> 형식입니다. 로그에 찍힌 JWT가 만료됐는지는 <a href="/ko/tools/jwt-decoder/">JWT 디코더</a>로 로컬에서 확인할 수 있습니다.</p>

<p>이름 없는 긴 문자열은 base64 문자가 32자 이상 이어지고, 대문자·소문자·숫자를 모두 포함하며, 섀넌 엔트로피가 문자당 4.2비트 이상일 때만 바꿉니다. 같은 길이의 무작위 base64는 평균 약 4.56비트입니다. 커밋 SHA, SHA-256, UUID는 16진수이거나 대소문자 한 가지만 쓰므로 해당하지 않습니다.</p>

<h2>gitleaks·로그 마스킹과의 차이</h2>

<p><a href="https://github.com/gitleaks/gitleaks">gitleaks</a>와 <a href="https://github.com/trufflesecurity/trufflehog">TruffleHog</a>는 저장소와 git 기록에 이미 들어간 시크릿을 찾습니다. gitleaks 기본 설정은 2026년 9월 기준 222개 규칙입니다(이 도구는 30개 규칙과 엔트로피 검사). 결과를 보고서로 알려 줄 뿐 붙여넣을 텍스트는 만들지 않으며, pre-commit이나 CI에 두는 도구입니다. GitHub Actions의 <code>::add-mask::</code>는 값을 <code>*</code>로 바꿉니다(<a href="https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands">GitHub 문서</a>). 모든 값이 똑같이 보이고 되돌릴 수 없어서, AI는 두 키가 같은 값인지도 알 수 없습니다.</p>

<p>이 도구가 맡는 것은 붙여넣기 직전 단계입니다. 값마다 다른 번호를 붙이고, 같은 값에는 같은 번호를 쓰며, 답변은 되돌릴 수 있습니다. <strong>예제 불러오기</strong>를 누르면 <code>[OPENAI_KEY_1]</code>이 <code>.env</code>와 재시도 로그 줄 양쪽에 나타납니다. AI는 이것으로 재시도가 설정된 키를 썼다는 것을 알 수 있습니다.</p>

<h2>한계</h2>

<ul>
  <li>입력 한도는 1,000,000자입니다. 넘으면 상태 표시에 "입력이 N자입니다. 한도는 1,000,000자입니다. 나눠서 붙여넣으세요."가 나옵니다.</li>
  <li>개인 키 규칙을 뺀 모든 규칙은 줄 끝에서 멈추므로, 터미널에서 줄바꿈된 값은 감지하지 못합니다. 원본 파일에서 복사하세요.</li>
  <li>카테고리를 켜고 끄면 다시 감지하면서 번호가 바뀔 수 있습니다. 복원은 마스킹할 때와 같은 설정으로 하세요.</li>
  <li>이메일, 이름, 전화번호, 주민등록번호, IP 주소 같은 개인 정보는 다루지 않습니다. 호스트명은 일부러 남깁니다.</li>
  <li>키가 아직 유효한지는 확인하지 않습니다. 확인하려면 키를 제공자에게 보내야 하기 때문입니다.</li>
</ul>
