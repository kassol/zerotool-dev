<h2>示例一：Spring Boot 的 application.yml</h2>

<p>一份常见的配置：数据库密码、阿里云 OSS 的 AccessKey、DeepSeek 的 API Key。以下取值均为演示值。</p>

```yaml
spring:
  datasource:
    url: jdbc:mysql://10.0.3.12:3306/order?useSSL=false
    username: order_rw
    password: Order@2026!
aliyun:
  oss:
    access-key-id: LTAI-demo-key-id
    access-key-secret: demo-secret-not-real-0123456789
deepseek:
  api-key: sk-demo-not-a-real-key-0123456789abcdef
```

<p>② 号框输出，共 3 处：</p>

```yaml
spring:
  datasource:
    url: jdbc:mysql://10.0.3.12:3306/order?useSSL=false
    username: order_rw
    password: [SECRET_1]
aliyun:
  oss:
    access-key-id: LTAI-demo-key-id
    access-key-secret: [SECRET_2]
deepseek:
  api-key: [API_KEY_1]
```

<p>数据库地址、用户名保持原样，AI 仍然能判断连的是哪个库。<code>api-key</code> 的值按 <code>sk-</code> 前缀识别为 <code>[API_KEY_1]</code>；即使不是 sk- 开头，变量名 api-key 也会让它被替换。<code>access-key-id</code> 没有被替换：变量名以 id 结尾，取值也不到 32 位。AccessKey ID 和 Secret 成对使用，介意的话手动删掉这一行。想先看清一份 <code>.env</code> 里到底定义了哪些变量，可以用 <a href="/zh/tools/env-file-parser/">.env 文件解析器</a>。</p>

<h2>示例二：钉钉机器人 Webhook，回复里丢了方括号</h2>

<p>部署脚本里发群通知的一行，令牌放在 URL 的 <code>access_token</code> 参数里（格式见<a href="https://open.dingtalk.com/document/orgapp/customize-robot-security-settings">钉钉开放平台文档</a>）：</p>

```bash
curl -s 'https://oapi.dingtalk.com/robot/send?access_token=6f1c0e7a9b2d4c8e1f3a5b7c9d0e2f4a6b8c0d1e3f5a7b9c1d3e5f7a9b0c2d4e' \
  -H 'Content-Type: application/json' -d '{"msgtype":"text","text":{"content":"发布完成"}}'
```

<p>这个令牌是 64 位十六进制，高熵检查不会处理它，靠的是参数名 <code>access_token</code>，结果是 <code>access_token=[SECRET_1]</code>。假设 AI 的回复是：</p>

```text
机器人开了加签，URL 里还要带 timestamp 和 sign：
curl -s "https://oapi.dingtalk.com/robot/send?access_token=[SECRET_1]&timestamp=$TS&sign=$SIGN" ...
其中 SECRET_1 保持不变。
```

<p>贴进 ③ 号框后，命令里的 <code>[SECRET_1]</code> 换回了原令牌；最后一行的 <code>SECRET_1</code> 没有方括号，保持原样。</p>

<p>阿里云 AccessKey ID 发送前请手动删掉或改写。飞书令牌与企业微信 key 只在完整网址里识别，单独放在变量里时要靠变量名（如 <code>…_TOKEN</code>）。其余格式与出处：GitHub 令牌前缀见 <a href="https://github.blog/engineering/platform-security/behind-githubs-new-authentication-token-formats/">GitHub 官方博客</a>，AWS <code>AKIA</code> / <code>ASIA</code> 见 <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html">IAM 文档</a>，JWT、Bearer、PEM 私钥分别按 <a href="https://www.rfc-editor.org/rfc/rfc7519">RFC 7519</a>、<a href="https://www.rfc-editor.org/rfc/rfc6750">RFC 6750</a>、<a href="https://www.rfc-editor.org/rfc/rfc7468">RFC 7468</a> 识别。JWT 是否已过期，可以先用 <a href="/zh/tools/jwt-decoder/">JWT 解码器</a> 在本地看一眼。</p>

<p>没有变量名的长串走高熵检查：连续 32 位以上的 base64 字符，同时含大写、小写和数字，且香农熵不低于每字符 4.2 bit 才替换（同长度随机 base64 平均约 4.56 bit）。commit SHA、SHA-256、UUID 都是十六进制或单一大小写，不会被误伤。</p>

<h2>和 gitleaks、日志打码有什么不同</h2>

<p><a href="https://github.com/gitleaks/gitleaks">gitleaks</a>、<a href="https://github.com/trufflesecurity/trufflehog">TruffleHog</a> 扫描的是仓库和 git 历史，gitleaks 默认配置在 2026 年 9 月有 222 条规则（本工具 30 条加熵值检查），适合放进 pre-commit 或 CI；它们给出报告，不产出可以直接粘贴的文本。GitHub Actions 的 <code>::add-mask::</code> 会把值换成 <code>*</code>（<a href="https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands">GitHub 文档</a>），所有值长得一样，也无法还原，AI 分不清两个被遮住的 key 是不是同一个。</p>

<p>本工具处理的是粘贴之前那一步：不同的值得到不同编号，同一个值处处相同，回复还能换回来。点<strong>加载示例</strong>就能看到：<code>[OPENAI_KEY_1]</code> 同时出现在 <code>.env</code> 和重试日志里，AI 据此能看出重试用的就是配置里的那个 key。</p>

<h2>限制与常见提示</h2>

<ul>
  <li>单次输入上限 1,000,000 个字符，超出时状态栏提示“输入共 N 个字符，上限为 1,000,000。请拆分后再粘贴”。</li>
  <li>除私钥规则外，所有规则都在行尾停止，被终端折行的密钥检测不到，请从原始文件复制。</li>
  <li>切换类别开关会重新检测，编号可能变化；还原时保持和脱敏时相同的开关。</li>
  <li>不处理邮箱、手机号、身份证号、IP 等个人信息；主机名刻意保留。需要时手动编辑。</li>
  <li>不验证密钥是否仍然有效，因为验证就意味着把密钥发给服务商。</li>
</ul>
