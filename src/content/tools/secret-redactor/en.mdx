<h2>How to use</h2>

<ol>
  <li>Paste the log, stack trace, <code>.env</code> file or config into box ①. Detection runs as you type.</li>
  <li>Read box ②. Each secret is replaced by a placeholder such as <code>[OPENAI_KEY_1]</code>. Open <strong>Findings</strong> to see which rule matched each one, and turn off a category if it flags something harmless.</li>
  <li>Copy box ② into ChatGPT, Claude or any other assistant. It helps to start the prompt with: <em>"Values in square brackets like [OPENAI_KEY_1] are redacted. Keep them exactly as written."</em></li>
  <li>Paste the reply into box ③. Every placeholder it kept comes back as the real value, ready to copy into your terminal or editor.</li>
</ol>

<p>Keep box ① unchanged until you have restored the reply. The mapping from placeholder to value is rebuilt from that text on every change, and nothing else stores it.</p>

<h2>Example: a failing CI job log</h2>

<p>A deploy step ran <code>curl -v</code>, so the log shows the request headers, and a debug line printed two AWS variables. The AWS values are the example keys from the <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html">AWS IAM documentation</a>.</p>

```text
Run curl -sv https://api.example.com/v1/deploy
> POST /v1/deploy HTTP/2
> Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
< HTTP/2 403
env AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
env AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
env GIT_SHA=3f786850e387550fdab836ed7e6dc881de23001b
Error: Process completed with exit code 22.
```

<p>Box ② shows this, with 3 findings:</p>

```text
Run curl -sv https://api.example.com/v1/deploy
> POST /v1/deploy HTTP/2
> Authorization: Bearer [JWT_1]
< HTTP/2 403
env AWS_ACCESS_KEY_ID=[AWS_ACCESS_KEY_1]
env AWS_SECRET_ACCESS_KEY=[AWS_SECRET_KEY_1]
env GIT_SHA=3f786850e387550fdab836ed7e6dc881de23001b
Error: Process completed with exit code 22.
```

<p>The header name and the <code>Bearer</code> scheme stay, so the assistant can still see that an authenticated request got a 403. The commit SHA stays because it is hex only. If you want to know whether that token had already expired, decode it in the <a href="/tools/jwt-decoder/">JWT Decoder</a> first; it also runs locally.</p>

<h2>Example: one password in two places, then restore</h2>

```text
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: hunter2-staging
  api:
    environment:
      DATABASE_URL: postgres://app:hunter2-staging@db:5432/app
      MAX_TOKENS: 1024
```

<p>Both copies of the password become <code>[SECRET_1]</code>, although two different rules found them. That tells the assistant the two values match without showing either. <code>MAX_TOKENS: 1024</code> is left alone: a name counts only when it <em>ends</em> in a keyword such as <code>token</code>. Suppose the reply comes back with one escaped and one lower-case placeholder:</p>

```text
Run this from the api container to check the login:
`psql postgres://app:\[SECRET_1\]@db:5432/app`
If it fails, recreate the volume: the image only reads [secret_1] on first start.
```

<p>Box ③ restores both to <code>hunter2-staging</code>, and the status line reads "Restored 2 placeholders (1 distinct of 1 in the mapping)". To check which variables a larger <code>.env</code> defines before you paste any of it, the <a href="/tools/env-file-parser/">.env File Parser</a> lists them.</p>

<h2>What gets redacted</h2>

<table>
  <thead>
    <tr><th>Category</th><th>Examples</th><th>What stays visible</th></tr>
  </thead>
  <tbody>
    <tr><td>AI provider keys</td><td><code>sk-ant-…</code>, <code>sk-proj-…</code>, <code>hf_…</code>, other <code>sk-</code> keys of 32+ characters</td><td>The variable name</td></tr>
    <tr><td>Cloud &amp; SaaS tokens</td><td><code>AKIA…</code> / <code>ASIA…</code> and the AWS secret next to an <code>aws…secret</code> name, <code>AIza…</code>, <code>ghp_…</code>, <code>github_pat_…</code>, <code>glpat-…</code>, <code>xoxb-…</code>, Slack webhook URLs, <code>sk_live_…</code>, <code>whsec_…</code>, SendGrid, npm, PyPI, Telegram bot tokens</td><td>The variable name</td></tr>
    <tr><td>JWT &amp; auth headers</td><td><code>eyJ….eyJ….…</code>, <code>Authorization: Basic …</code>, <code>Bearer …</code></td><td>The header name and scheme</td></tr>
    <tr><td>Private keys</td><td>PEM blocks from <code>-----BEGIN … PRIVATE KEY-----</code> to the matching END line</td><td>Nothing; the block becomes one placeholder</td></tr>
    <tr><td>Passwords &amp; connection strings</td><td><code>postgres://app:…@db</code>, <code>DB_PASSWORD=…</code>, <code>client_secret: …</code>, <code>?api_key=…</code></td><td>User, host, port and database</td></tr>
    <tr><td>High-entropy strings</td><td>Unlabelled random strings of 32+ characters</td><td>Everything around them</td></tr>
  </tbody>
</table>

<p>The prefixes come from the vendors. GitHub documents <code>ghp_</code>, <code>gho_</code>, <code>ghu_</code>, <code>ghs_</code> and <code>ghr_</code> in its <a href="https://github.blog/engineering/platform-security/behind-githubs-new-authentication-token-formats/">token format post</a>. AWS lists <code>AKIA</code> and <code>ASIA</code> in its <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html">IAM identifier reference</a>. Anthropic keys start with <code>sk-ant-</code> (<a href="https://platform.claude.com/docs/en/get-api-key">Anthropic docs</a>). Stripe <code>pk_</code> publishable keys are not matched, because <a href="https://docs.stripe.com/keys">Stripe</a> says they are safe to embed in client-side code. The other shapes are defined by standards: JWT by <a href="https://www.rfc-editor.org/rfc/rfc7519">RFC 7519</a>, Bearer by <a href="https://www.rfc-editor.org/rfc/rfc6750">RFC 6750</a>, Basic by <a href="https://www.rfc-editor.org/rfc/rfc7617">RFC 7617</a>, and PEM labels by <a href="https://www.rfc-editor.org/rfc/rfc7468">RFC 7468</a>.</p>

<p>Values that are obviously not secrets are skipped: <code>$&#123;DB_PASS&#125;</code> references, <code>&lt;your-key&gt;</code> templates, <code>****</code> and literals such as <code>true</code> or <code>null</code>. An unlabelled string of 32+ base64 characters is redacted only when it mixes upper case, lower case and digits and reaches 4.2 bits of Shannon entropy per character. Random base64 of that length averages 4.56 bits. The mixed-case rule keeps git SHAs, SHA-256 digests and UUIDs readable. Lockfile <code>sha512-</code> hashes, <code>data:</code> URIs, file paths and certificate or public key blocks are excluded as well.</p>

<h2>How this differs from gitleaks and log masking</h2>

<p>Two kinds of tools already deal with secrets in text. Each covers a different moment.</p>

<ul>
  <li><strong>Repository scanners</strong> such as <a href="https://github.com/gitleaks/gitleaks">gitleaks</a> and <a href="https://github.com/trufflesecurity/trufflehog">TruffleHog</a> find secrets that are already in files or git history. The gitleaks default config had 222 rules in September 2026, against 26 rules plus the entropy check here, and TruffleHog can test whether a key is still live. They report findings. They do not give you a copy to paste. Run them in a pre-commit hook or CI.</li>
  <li><strong>Log masking</strong> hides values with one fixed mask. In GitHub Actions, <code>::add-mask::</code> replaces each masked word with <code>*</code> (<a href="https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands">GitHub docs</a>). The mask cannot be reversed, and every value looks the same, so an assistant cannot tell two keys apart.</li>
</ul>

<p>This page covers the moment before a paste. Every distinct value gets its own numbered placeholder, the same value keeps it everywhere, and the reply can be turned back. To see it, press <strong>Load example</strong>: <code>[OPENAI_KEY_1]</code> appears in both the <code>.env</code> line and the retry log line, which shows the assistant that the retry used the configured key. Then type <code>rotate [OPENAI_KEY_1]</code> into box ③.</p>

<h2>Limits</h2>

<table>
  <thead>
    <tr><th>Not done here</th><th>Use instead</th></tr>
  </thead>
  <tbody>
    <tr><td>Scanning files, folders or git history</td><td><code>gitleaks git</code> / <code>gitleaks dir</code> or <code>trufflehog</code> on your machine</td></tr>
    <tr><td>Personal data: emails, names, phone numbers, IP addresses</td><td>Edit by hand. Hostnames stay on purpose so the assistant can still read your config.</td></tr>
    <tr><td>Un-redacting one false positive</td><td>Turn off its category, or edit the copied text</td></tr>
    <tr><td>Checking whether a key is still live</td><td>Not done, because it would mean sending the key to the provider</td></tr>
  </tbody>
</table>

<ul>
  <li>Input is limited to 1,000,000 characters. Above that, the status line reads "Input is N characters; the limit is 1,000,000. Split the text."</li>
  <li>Every rule except the private key rule stops at the end of a line, so a token wrapped onto two lines is not detected. Copy from the raw file.</li>
  <li>Switching a category on or off re-runs detection, and placeholder numbers can change. Restore with the same toggles you redacted with.</li>
  <li>A long CamelCase identifier with a digit, such as <code>AbstractSingletonProxyFactoryBean2Impl</code> (4.33 bits), is redacted as high-entropy. Turn off that category if it gets in the way.</li>
</ul>
