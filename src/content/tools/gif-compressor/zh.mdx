## 使用步骤

1. 把 GIF 拖进上传区，或点击选择文件，也可以用 **Ctrl/Cmd+V** 粘贴已复制的 GIF 文件。
2. 载入后页面会按当前设置自动压缩一次，左右并排显示原图和结果，并给出两者的体积。
3. 调整设置后点「压缩」重新生成。编码开销较大，拖动滑块时不会实时重算。
4. 点「下载 GIF」保存结果，文件名为 `{原名}-compressed.gif`。

## 各项设置如何影响体积

| 设置 | 作用 | 对体积的影响 |
|---|---|---|
| **有损程度**（0–100，默认 40） | 允许 LZW 复用颜色偏差在「有损程度 × 0.6」以内的序列 | 对视频类 GIF 通常效果最明显。一段 231 帧录屏：40 时为原图的 42%，100 时为 19% |
| **颜色数**（256 到 4） | 颜色表大小，其中 1 位留给透明 | 颜色越少，编码越短、重复越多。原图用到的颜色不超过可用数量时，调色板保持原色不变 |
| **宽度** | 等比缩小，高度自动跟随 | 像素数按缩放比例的平方下降：宽度减半，数据量约为四分之一 |
| **帧** | 每 2、3 或 4 帧保留 1 帧 | 需要存的帧变少。保留帧的显示时长会加上被丢弃帧的时长，动画总时长不变 |
| **抖动** | Floyd–Steinberg 误差扩散 | 颜色少时渐变更平滑，但文件通常更大 |

宽度只能缩小。留空、填 0 或大于原宽，都按原宽处理。缩放时，每个输出像素取它覆盖的原像素的面积加权平均；不透明部分不足一半的输出像素变成透明。

帧延迟以 10 ms 为单位写入，最小 20 ms。原文件写 0 或 10 ms 的帧按 100 ms 写入，因为浏览器实际就是这样播放的。

## 帧优化原理

GIF 的每一帧不必覆盖整张画布。本工具的第一帧总是完整写入；之后每一帧都和屏幕上已显示的画面比较，只写包含变化像素的最小矩形。矩形内没变的像素用透明色，让上一帧透出来，同时连成长串，压缩效果更好。完全没变化的帧只写 1 个透明像素，保留它的延迟。

透明像素还要多处理一步：原本可见的像素要变成透明时，在上面画一个透明像素没有任何效果。这时本工具把前一帧的处置方式设为 2（恢复为背景），并把前一帧的矩形扩大到覆盖这些像素，浏览器会在画下一帧之前清空这块区域。

调色板对整段动画只生成一次。所有帧用到的颜色总数不超过颜色表容量时，颜色原样保留；否则用中值切割把颜色空间分成若干块，每块取平均色。

## 范围说明

- 输出始终是 GIF。[WebP 转换器](/zh/tools/webp-converter/)可以把 GIF 的第一帧转成静态 WebP；要得到动态 WebP，请在电脑上用 libwebp 自带的 `gif2webp`：

```bash
gif2webp -lossy -q 75 in.gif -o out.webp
```

- MP4 往往比同样内容的 GIF 小好几倍，请在电脑上用 ffmpeg 转换。宽或高是奇数时加上 `-vf "scale=trunc(iw/2)*2:trunc(ih/2)*2"`，因为 yuv420p 要求偶数尺寸：

```bash
ffmpeg -i in.gif -movflags +faststart -pix_fmt yuv420p out.mp4
```

- 不能裁剪、重排或编辑帧。要把 GIF 拆成 PNG 帧，请用 [GIF 拆帧工具](/zh/tools/gif-splitter/)。
- 尺寸上限：解码后 5000 万像素、1000 帧、单帧 16,777,216 像素。
- JPEG、PNG、WebP 图片请用[图片压缩工具](/zh/tools/image-compressor/)。
