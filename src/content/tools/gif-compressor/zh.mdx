## 实测：两个 GIF 压缩前后

两个文件都来自维基共享资源，可以下载后自己复现。体积单位为字节，设置为默认值（有损程度 40、256 色、保留全部帧、不抖动）。

**三维渲染动画。**[Newtons cradle animation book 2.gif](https://commons.wikimedia.org/wiki/File:Newtons_cradle_animation_book_2.gif)（牛顿摆）尺寸 480 × 360，36 帧，308,156 字节。压缩后 109,817 字节，是原图的 36%，共 178 色。

**网页操作录屏。**[Auto-citing a source using VisualEditor, small.gif](https://commons.wikimedia.org/wiki/File:Auto-citing_a_source_using_VisualEditor,_small.gif) 录的是维基百科可视化编辑器插入引用的过程，500 × 245，114 帧，698,529 字节。默认设置压到 245,538 字节（35%）；宽度再减半到 250 px，只剩 40,134 字节（5.7%）。

在一台 M1 Max 笔记本的 Chrome 里，从选中文件到出现结果，多次测量下牛顿摆用了 1.9–3.2 秒，录屏用了 3.5–4.8 秒。

## 公众号、README 里的动图怎么压

- **公众号文章。**微信开放文档写明，公众号图片素材上限 10M，支持 GIF（[永久素材接口说明](https://developers.weixin.qq.com/doc/subscription/api/material/permanent/api_addmaterial.html)）。读者多在手机上看，先把宽度降到手机屏幕放得下的尺寸，比单纯调高有损程度更省体积：上面的录屏宽度减半后只剩 5.7%。
- **GitHub README 与 Issue。**[GitHub 文档](https://docs.github.com/zh/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)规定图片和 GIF 附件最大 10MB。能传上去不等于合适，访问者每次打开页面都要下载这些字节。
- **内部系统录屏。**给同事演示还没上线的后台、复现带客户数据的 bug，这类 GIF 不适合传到在线压缩网站。本页在标签页里处理，不会上传文件。

## 各项设置的作用

| 设置 | 作用 | 在上面录屏上的效果 |
|---|---|---|
| **有损程度**（0–100，默认 40） | 允许 LZW 复用颜色偏差在「有损程度 × 0.6」以内的序列 | 0 时 100%，40 时 35%，100 时 11% |
| **颜色数**（256 到 4） | 颜色表大小，其中 1 位留给透明 | 64 色、有损程度 40 时为 33% |
| **宽度** | 等比缩小，高度自动跟随，只能缩小 | 宽度减半时为 5.7% |
| **帧** | 每 2、3 或 4 帧保留 1 帧 | 每 2 帧留 1 帧时为 22% |
| **抖动** | Floyd–Steinberg 误差扩散 | 64 色时从 33% 升到 41% |

有损程度 100 虽然只剩 11%，但 SSIM（与原图的结构相似度，1 为完全相同）从 0.991 降到 0.932：浅灰色的细节（比如「Edit」按钮的边框）会消失，之前几帧的淡淡痕迹也会留在画面上，因为这么小的变化不会被重画。

## 与 gifsicle、ezgif 的区别

[ezgif](https://ezgif.com/optimize) 需要上传文件，它的页面写明用 gifsicle 及其有损 LZW 编码器压缩。[gifsicle](https://www.lcdf.org/gifsicle/man.html) 是本机命令行工具。本页在标签页里运行，有损阈值用在两处：一处在 LZW 里，和 gifsicle 的 `--lossy` 同类；另一处在帧与帧之间，新颜色与屏幕上已有颜色的距离在阈值以内的像素不再重画。画面大部分静止的录屏，靠第二步能省掉每帧的大部分数据。ezgif 也有类似的帧间处理，是单独的「Optimize Transparency」方法，配合 fuzz 系数使用。

两者的有损数值刻度不同（gifsicle 在伽马校正后的颜色空间里算误差），数字相同不代表设置相同。所以下表比较的是 SSIM 接近时的体积。SSIM 用 ffmpeg 9.0 对照原图计算，gifsicle 版本为 1.93。

| 文件 | 本工具（默认） | `gifsicle -O3 --lossy=80` |
|---|---|---|
| [旋转地球](https://commons.wikimedia.org/wiki/File:Rotating_earth_(large).gif)，400 × 400，44 帧，1,001,718 字节 | 541,524 字节，SSIM 0.956 | 575,411 字节，SSIM 0.965 |
| 牛顿摆 | 109,817 字节，SSIM 0.971 | 182,247 字节，SSIM 0.967 |
| 可视化编辑器录屏 | 245,538 字节，SSIM 0.991 | 549,574 字节，SSIM 0.991 |

地球每一帧几乎所有像素都在变，两者接近；另外两个文件，本工具的结果小 40% 和 55%，SSIM 持平或更高。复现命令（`out.gif` 是从本页下载的文件）：

```bash
gifsicle -O3 --lossy=80 in.gif -o gifsicle.gif
ffmpeg -i in.gif -i out.gif -lavfi "[0:v]format=yuv444p[a];[1:v]format=yuv444p[b];[a][b]ssim" -f null -
```

批量处理、裁剪、多种调色板与抖动算法、超出本页上限的大文件，请用 gifsicle 或 ezgif。

## 限制

- **尺寸上限。**解码后 5000 万像素、1000 帧、单帧 16,777,216 像素。终端录屏很容易超限：[lazygit](https://github.com/jesseduffield/lazygit) README 里的 `commit_and_push-compressed.gif` 是 1140 × 828、67 帧，共 6320 万像素，本页会拒绝并给出 gifsicle 命令。这个文件已经优化过，`gifsicle -O3 --lossy=80 --colors 128` 反而让它大了 1%；加上 `--resize-width 570` 后从 472,611 字节降到 147,386 字节。
- **极短帧延迟。**Chromium 与 Firefox 都把 0 或 10 ms 的延迟按 100 ms 播放（[Chromium 源码](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/platform/graphics/deferred_image_decoder.cc)、[Firefox 源码](https://searchfox.org/mozilla-central/source/image/FrameTimeout.h)），本工具把这类帧直接写成 100 ms；其他延迟按 10 ms 取整，最小 20 ms。
- **输出。**始终是只有一张全局颜色表的 GIF，不能裁剪、重排或编辑帧。要把 GIF 拆成 PNG 帧，用 [GIF 拆帧工具](/zh/tools/gif-splitter/)；JPEG、PNG、WebP 用[图片压缩工具](/zh/tools/image-compressor/)。
- **换格式。**照片类动画转成动态 WebP 或 MP4 会小得多。[WebP 转换器](/zh/tools/webp-converter/)只转 GIF 的第一帧，动态版本请在电脑上运行：

```bash
gif2webp -lossy -q 75 in.gif -o out.webp
ffmpeg -i in.gif -movflags +faststart -pix_fmt yuv420p -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2" out.mp4
```
