## Qiita・Zenn に貼る前の GIF 軽量化

記事に貼る操作 GIF は、サービスごとの容量制限に収める必要があります。

- **Zenn**：GitHub リポジトリ連携で置く画像は [3MB 以内](https://zenn.dev/zenn/articles/deploy-github-images)で、超えるとデプロイ時にエラーになります。
- **Qiita**：[1 枚 10MB まで、月の合計 100MB まで](https://help.qiita.com/ja/articles/qiita-image-upload)です。重い GIF を何枚も貼ると月の枠が早く減ります。
- **GitHub の Issue・PR**：[画像と GIF は 10MB まで](https://docs.github.com/ja/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)です。

Zenn の `=250x` 記法や HTML の `width` で表示を縮めても、読者がダウンロードするのは元の GIF です。バイト数を減らすには GIF の幅そのものを縮めます。未公開の管理画面や顧客データが映った録画は、アップロード型のサービスに送らずこのページで処理できます。

## 実測：録画 GIF と 3D アニメーション

どちらもウィキメディア・コモンズで公開されているファイルで、ダウンロードすれば同じ結果を再現できます。既定値（ロッシー 40、256 色、全フレーム、ディザリングなし）での結果です。

**ブラウザ操作の録画。**[Auto-citing a source using VisualEditor, small.gif](https://commons.wikimedia.org/wiki/File:Auto-citing_a_source_using_VisualEditor,_small.gif) はウィキペディアのビジュアルエディターで出典を挿入する操作の録画です。500 × 245 px、114 フレーム、698,529 バイトが 245,538 バイト（35%）になりました。ロッシー 100 にすると 75,168 バイト（11%）まで減りますが、元画像との SSIM（構造の類似度、1 で完全一致）は 0.991 から 0.932 に下がります。「Edit」ボタンの枠のような薄いグレーが消え、前のフレームの跡がうっすら残ります。変化が小さすぎて描き直されないためです。記事用なら既定値のまま使うのが無難です。

**3D の地球。**[Rotating earth (large).gif](https://commons.wikimedia.org/wiki/File:Rotating_earth_(large).gif) は 400 × 400 px、44 フレーム、1,001,718 バイト。回転でほぼ全画素が毎フレーム変わる素材です。既定値で 541,524 バイト（54%）、幅を半分の 200 px にすると 180,441 バイト（18%）でした。

M1 Max のノート PC の Chrome で、ファイルを選んでから結果が出るまで、数回測って録画は 3.5〜4.8 秒、地球は 0.8〜2.8 秒でした。

## 設定ごとの効果

| 設定 | 働き | 上の録画での結果 |
|---|---|---|
| **ロッシー**（0–100、既定 40） | 色ずれが「ロッシー × 0.6」以内なら、LZW が既知の並びを使い続ける | 0 で 100%、40 で 35%、100 で 11% |
| **色数**（256〜4） | カラーテーブルの大きさ。1 枠は透明用 | 64 色・ロッシー 40 で 33% |
| **幅** | 縦横比を保って縮小（拡大はしない） | 半分の幅で 5.7% |
| **フレーム** | 2・3・4 フレームごとに 1 枚を残す | 2 フレームごとで 22% |
| **ディザリング** | Floyd–Steinberg 誤差拡散 | 64 色で 33% から 41% に増える |

間引いたフレームの表示時間は直前の残ったフレームに足すので、全体の再生時間は変わりません。

## gifsicle・ezgif との違い

[ezgif](https://ezgif.com/optimize) はファイルをアップロードし、ページの説明どおり gifsicle とそのロッシー LZW エンコーダーで圧縮します。[gifsicle](https://www.lcdf.org/gifsicle/man.html) は手元で動くコマンドラインツールです。このページはタブの中で動き、ロッシーのしきい値を 2 か所で使います。1 つは LZW の中で、gifsicle の `--lossy` と同じ種類の処理です。もう 1 つはフレーム間で、表示中の色との距離がしきい値以内の画素は描き直しません。画面の大半が止まっている録画では、この 2 つ目が各フレームの大部分を削ります。ezgif にも、fuzz 係数を指定する「Optimize Transparency」という別メソッドとして、似たフレーム間の処理があります。

ロッシー値の尺度は両者で違う（gifsicle はガンマ補正した色空間で誤差を測る）ので、同じ数字でも同じ設定ではありません。そこで SSIM が近いところでサイズを比べました。SSIM は ffmpeg 9.0 で元ファイルと比較し、gifsicle は 1.93 を使っています。

| ファイル | このツール（既定値） | `gifsicle -O3 --lossy=80` |
|---|---|---|
| 地球 | 541,524 バイト、SSIM 0.956 | 575,411 バイト、SSIM 0.965 |
| [ニュートンのゆりかご](https://commons.wikimedia.org/wiki/File:Newtons_cradle_animation_book_2.gif)、480 × 360、36 フレーム、308,156 バイト | 109,817 バイト、SSIM 0.971 | 182,247 バイト、SSIM 0.967 |
| ビジュアルエディターの録画 | 245,538 バイト、SSIM 0.991 | 549,574 バイト、SSIM 0.991 |

全画素が動く地球では差が小さく、ほかの 2 つではこのツールのほうが 40% と 55% 小さく、SSIM は同等以上でした。再現用のコマンドです（`out.gif` はこのページで保存したファイル）。

```bash
gifsicle -O3 --lossy=80 in.gif -o gifsicle.gif
ffmpeg -i in.gif -i out.gif -lavfi "[0:v]format=yuv444p[a];[1:v]format=yuv444p[b];[a][b]ssim" -f null -
```

一括処理、トリミング、複数のパレット・ディザリング方式、このページの上限を超える大きなファイルには、gifsicle か ezgif を使ってください。

## 制限

- **サイズ上限。**デコード後 5,000 万ピクセル、1,000 フレーム、1 フレーム 16,777,216 ピクセルまで。ターミナル録画は超えやすく、[lazygit](https://github.com/jesseduffield/lazygit) の README にある `commit_and_push-compressed.gif`（1140 × 828 px、67 フレーム、6,320 万ピクセル）は受け付けず、gifsicle のコマンドを表示します。このファイルは最適化済みで、`gifsicle -O3 --lossy=80 --colors 128` では 1% 増えました。`--resize-width 570` を足すと 472,611 バイトから 147,386 バイトになります。
- **ごく短いディレイ。**Chromium と Firefox は 0 ms や 10 ms のディレイを 100 ms で再生します（[Chromium のソース](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/platform/graphics/deferred_image_decoder.cc)、[Firefox のソース](https://searchfox.org/mozilla-central/source/image/FrameTimeout.h)）。このツールはそうしたフレームを 100 ms で書き出し、ほかのディレイは 10 ms 単位に丸めます（最小 20 ms）。
- **出力。**常にグローバルカラーテーブル 1 つの GIF です。フレームのトリミング・並べ替え・編集はできません。PNG のコマに分けるなら [GIF 分解ツール](/ja/tools/gif-splitter/)、JPEG・PNG・WebP は[画像圧縮ツール](/ja/tools/image-compressor/)を使ってください。
- **ほかの形式。**写真のような動きなら、アニメーション WebP や MP4 のほうがずっと小さくなります。[WebP 変換器](/ja/tools/webp-converter/)は GIF の最初のフレームだけを変換するので、アニメーションのまま変換するには PC で次を実行します。

```bash
gif2webp -lossy -q 75 in.gif -o out.webp
ffmpeg -i in.gif -movflags +faststart -pix_fmt yuv420p -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2" out.mp4
```
