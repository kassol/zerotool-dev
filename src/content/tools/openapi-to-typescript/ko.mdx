<h2>사용 방법</h2>
<ol>
  <li>OpenAPI 3.0.x 또는 3.1.x 문서(YAML 또는 JSON)를 왼쪽 패널에 붙여 넣습니다.</li>
  <li>입력하면 300 ms 디바운스로 실시간 생성됩니다.</li>
  <li>선택적으로 <strong>루트 네임스페이스</strong> 변경, 모든 속성을 optional 처리, path 오퍼레이션 타입 포함, Zod 스키마 동시 출력을 선택할 수 있습니다.</li>
  <li><strong>복사</strong> 버튼으로 전체 TypeScript 출력을 가져갑니다.</li>
</ol>

<h2>생성되는 내용</h2>
<ul>
  <li><strong>components/schemas</strong>: 각 스키마가 `export interface` 또는 `export type`이 됩니다. 객체는 interface, 기본형 / 유니언 / enum / 교차 타입은 type alias로 출력됩니다.</li>
  <li><strong>$ref</strong>: `#/components/schemas/...` 참조는 타입 이름으로 해석되며, 스펙의 선언 순서를 그대로 따릅니다.</li>
  <li><strong>oneOf / anyOf</strong>: 유니언 타입 `A | B | C`. <strong>allOf</strong>는 교차 타입 `A & B`.</li>
  <li><strong>enum</strong>: 문자열 또는 숫자 리터럴 유니언.</li>
  <li><strong>nullable</strong>: 3.0의 `nullable: true`와 3.1의 `type: ['X', 'null']` 모두 `X | null`로 변환.</li>
  <li><strong>format 힌트</strong>: `format: date-time`에는 ISO 8601 JSDoc 주석을 추가하고, `format: binary`는 `Blob`이 됩니다.</li>
  <li><strong>additionalProperties</strong>: 인덱스 시그니처 또는 `Record&lt;string, T&gt;`.</li>
</ul>

<h2>Path 타입(선택)</h2>
<p><strong>path 타입 포함</strong>을 켜면 각 오퍼레이션마다 타입 엔벨로프가 생성됩니다:</p>
<pre><code>{`export namespace Components {
  export namespace GetPetById {
    export interface PathParameters {
      id: number;
    }
    export type Response200 = Pet;
  }
}`}</code></pre>
<p>오퍼레이션에 <code>operationId</code>가 없으면 method와 path로 합성합니다(예: <code>GetPetsId</code>).</p>

<h2>Zod 스키마(선택)</h2>
<p><strong>Zod 스키마 포함</strong>을 켜면 각 컴포넌트별로 `XSchema`를 함께 출력합니다:</p>
<pre><code>{`import { z } from 'zod';

export const PetSchema = z.object({
  id: z.number().int(),
  name: z.string(),
  status: z.enum(["available", "pending", "sold"]),
});`}</code></pre>
<p>OpenAPI 스펙이 아니라 손으로 쓴 TS 타입에서 Zod를 만들고 싶다면 <a href="/ko/tools/typescript-to-zod/">TypeScript → Zod</a>를 사용하세요.</p>

<h2>예시: 내장 Pet Store 명세</h2>
<p><strong>예시</strong>를 누르면 <code>Pet</code>, <code>NewPet</code> 두 스키마와 세 개의 오퍼레이션이 있는 작은 OpenAPI 3.0.3 명세를 불러옵니다. 출력의 스키마 부분입니다.</p>
<pre><code>{`export interface Pet {
  id: number;
  name: string;
  tag?: string | null;
  status: "available" | "pending" | "sold";
  photo?: Blob;
}

export interface NewPet {
  name: string;
  tag?: string;
}`}</code></pre>
<p>필수 속성은 필수로 남고 나머지는 <code>?</code>가 붙습니다. <code>nullable: true</code>는 <code>| null</code>이 되고 <code>format: binary</code>는 <code>Blob</code>이 됩니다. <strong>path 타입 포함</strong>을 켜면 <code>getPetById</code>가 <code>PathParameters &#123; id: number &#125;</code>와 <code>Response200 = Pet</code>를 가진 <code>Components.GetPetById</code>가 됩니다. <strong>Zod 스키마 포함</strong>을 켜고 만든 <code>PetSchema</code>는(zod 3.25로 확인) <code>status: "lost"</code>를 거부하고 <code>tag: null</code>을 받아들입니다.</p>

<h2>예시: const, 타입 배열, 외부 참조</h2>
<p>다음 OpenAPI 3.1 스키마는 <code>const</code>, 타입 배열, 다른 파일에 대한 참조를 씁니다.</p>
<pre><code>{`openapi: 3.1.0
info: { title: Events, version: 1.0.0 }
paths: {}
components:
  schemas:
    Event:
      type: object
      required: [id, kind, createdAt]
      properties:
        id: { type: integer, format: int64 }
        kind: { const: order.created }
        createdAt: { type: string, format: date-time }
        note: { type: [string, 'null'] }
        owner: { $ref: 'https://example.com/schemas/user.yaml#/User' }`}</code></pre>
<p>도구의 출력입니다.</p>
{/* o2t: event */}
<pre><code>{`export interface Event {
  id: number;
  kind: "order.created";
  /** ISO 8601 date-time */ createdAt: string;
  note?: string | null;
  owner?: unknown /* unresolved $ref: https://example.com/schemas/user.yaml#/User */;
}`}</code></pre>
<p><code>type: [string, "null"]</code>은 <code>string | null</code>이 되고, <code>const</code>는 리터럴 타입 <code>"order.created"</code>(Zod에서는 <code>z.literal("order.created")</code>)가 됩니다. <code>user.yaml</code>에 대한 참조는 다른 문서에 있어 도구가 가져오지 않습니다. <code>owner</code>는 <code>unknown</code>이 되고 참조는 주석에 남으며, 상태 표시줄에 "지원하지 않음: https://example.com/schemas/user.yaml#/User에 대한 $ref"가 표시됩니다. 먼저 <a href="https://redocly.com/docs/cli/commands/bundle" target="_blank" rel="noopener">redocly bundle</a>로 외부 파일을 <code>components</code>에 합친 뒤, 합친 스펙을 붙여 넣으세요.</p>

<h2>예시: Zod의 전방 참조와 재귀</h2>
<p>Zod 스키마는 JavaScript 상수이므로 정의하는 줄보다 앞에서는 쓸 수 없습니다. 다음 스키마에서 <code>Order</code>는 나중에 선언되는 <code>Customer</code>를 참조하고, <code>Node</code>는 자기 자신을 참조합니다.</p>
<pre><code>{`components:
  schemas:
    Order:
      type: object
      required: [customer]
      properties:
        customer: { $ref: '#/components/schemas/Customer' }
    Customer:
      type: object
      required: [name]
      properties:
        name: { type: string }
    Node:
      type: object
      required: [value]
      properties:
        value: { type: string }
        children:
          type: array
          items: { $ref: '#/components/schemas/Node' }`}</code></pre>
<p>Zod 출력은 두 참조를 모두 <code>z.lazy</code>로 감싸, 모듈을 불러올 때가 아니라 데이터를 검사할 때 스키마를 찾습니다. 직접 또는 다른 스키마를 거쳐 자기 자신을 참조하는 스키마에는 <code>z.ZodType&lt;Node&gt;</code> 타입 표기도 붙습니다. TypeScript는 자기 초기화 식에 나오는 상수의 타입을 추론하지 못하기 때문입니다(오류 TS7022).</p>
{/* o2t: recur */}
<pre><code>{`export const OrderSchema = z.object({
  customer: z.lazy(() => CustomerSchema),
});
export const CustomerSchema = z.object({
  name: z.string(),
});
export const NodeSchema: z.ZodType<Node> = z.object({
  value: z.string(),
  children: z.array(z.lazy(() => NodeSchema)).optional(),
});`}</code></pre>
<p>생성된 모듈은 TypeScript 5.9 strict 모드에서 컴파일되고, zod 3.25로 3단계 트리를 검사할 수 있습니다.</p>

<h2>제한</h2>
<ul>
  <li><code>#/components/schemas/...</code> 참조와 path 타입의 <code>#/components/parameters/...</code>만 해석합니다. 그 밖의 참조(URL, 다른 파일, <code>#/components/responses/...</code>)는 <code>unknown</code>이 되며 상태 표시줄에 목록이 나옵니다.</li>
  <li>TypeScript 식별자로 쓸 수 없는 스키마 이름은 바뀝니다. 영문자, 숫자, <code>{'_'}</code>, <code>$</code> 외의 문자는 <code>{'_'}</code>로(<code>pet-status</code> → <code>{'pet_status'}</code>), 숫자로 시작하는 이름은 앞에 <code>{'_'}</code>를, <code>unknown</code>이나 <code>class</code> 같은 키워드는 뒤에 <code>{'_'}</code>를 붙입니다.</li>
  <li>값이 객체나 배열인 <code>const</code>는 <code>unknown</code>이 됩니다. 문자열·숫자·불리언·null은 리터럴 타입이 됩니다.</li>
  <li><code>format: int64</code>인 <code>integer</code>는 <code>number</code>가 되어 2<sup>53</sup>을 넘으면 정밀도가 떨어집니다. API가 이런 ID를 문자열로 보낸다면 <code>string</code>으로 바꾸세요.</li>
  <li>path 타입은 <code>application/json</code> 요청 본문과 응답 본문만 읽습니다.</li>
</ul>
