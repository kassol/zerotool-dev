<h2>使い方</h2>
<ol>
  <li>OpenAPI 3.0.x または 3.1.x のドキュメント（YAML / JSON）を左側パネルに貼り付けます。</li>
  <li>入力中は 300 ms デバウンスでリアルタイム生成されます。</li>
  <li>必要に応じて <strong>ルート名前空間</strong> の変更、全プロパティを optional 化、path 型の追加、Zod スキーマの同時出力を切り替えられます。</li>
  <li><strong>コピー</strong> ボタンで TypeScript 出力全文をコピーします。</li>
</ol>

<h2>生成される内容</h2>
<ul>
  <li><strong>components/schemas</strong>：各スキーマが `export interface` または `export type` になります。オブジェクトは interface、プリミティブ / union / enum / intersection は type alias として出力されます。</li>
  <li><strong>$ref</strong>：`#/components/schemas/...` への参照は型名で解決され、仕様の宣言順を維持します。</li>
  <li><strong>oneOf / anyOf</strong>：union 型 `A | B | C`。<strong>allOf</strong> は intersection `A & B` になります。</li>
  <li><strong>enum</strong>：文字列または数値のリテラル union。</li>
  <li><strong>nullable</strong>：3.0 の `nullable: true` も 3.1 の `type: ['X', 'null']` も `X | null` に変換。</li>
  <li><strong>format ヒント</strong>：`format: date-time` には ISO 8601 の JSDoc を付与し、`format: binary` は `Blob` になります。</li>
  <li><strong>additionalProperties</strong>：インデックスシグネチャまたは `Record&lt;string, T&gt;`。</li>
</ul>

<h2>Path 型（任意）</h2>
<p><strong>path 型を含める</strong> を有効にすると、各オペレーションに型エンベロープが生成されます：</p>
<pre><code>{`export namespace Components {
  export namespace GetPetById {
    export interface PathParameters {
      id: number;
    }
    export type Response200 = Pet;
  }
}`}</code></pre>
<p><code>operationId</code> がない場合は method と path から合成します（例：<code>GetPetsId</code>）。</p>

<h2>Zod スキーマ（任意）</h2>
<p><strong>Zod スキーマを含める</strong> を有効にすると、各コンポーネントに対して `XSchema` を並行して出力します：</p>
<pre><code>{`import { z } from 'zod';

export const PetSchema = z.object({
  id: z.number().int(),
  name: z.string(),
  status: z.enum(["available", "pending", "sold"]),
});`}</code></pre>
<p>OpenAPI 仕様ではなく既存の手書き TS 型から Zod を作りたい場合は <a href="/ja/tools/typescript-to-zod/">TypeScript → Zod</a> を使ってください。</p>

<h2>例：組み込みの Pet Store 仕様</h2>
<p><strong>サンプル</strong>を押すと、<code>Pet</code> と <code>NewPet</code> の 2 スキーマと 3 つのオペレーションを持つ小さな OpenAPI 3.0.3 仕様が読み込まれます。出力のスキーマ部分です。</p>
<pre><code>{`export interface Pet {
  id: number;
  name: string;
  tag?: string | null;
  status: "available" | "pending" | "sold";
  photo?: Blob;
}

export interface NewPet {
  name: string;
  tag?: string;
}`}</code></pre>
<p>必須プロパティは必須のまま、それ以外には <code>?</code> が付きます。<code>nullable: true</code> は <code>| null</code> になり、<code>format: binary</code> は <code>Blob</code> になります。<strong>path 型を含める</strong>をオンにすると、<code>getPetById</code> は <code>PathParameters &#123; id: number &#125;</code> と <code>Response200 = Pet</code> を持つ <code>Components.GetPetById</code> になります。<strong>Zod スキーマを含める</strong>をオンにして生成した <code>PetSchema</code> は（zod 3.25 で確認）、<code>status: "lost"</code> を拒否し、<code>tag: null</code> を受け付けます。</p>

<h2>例：3.1 の出力で手直しが必要な箇所</h2>
<p>次の OpenAPI 3.1 スキーマは <code>const</code>、型の配列、別ファイルへの参照を使っています。</p>
<pre><code>{`openapi: 3.1.0
info: { title: Events, version: 1.0.0 }
paths: {}
components:
  schemas:
    Event:
      type: object
      required: [id, kind, createdAt]
      properties:
        id: { type: integer, format: int64 }
        kind: { const: order.created }
        createdAt: { type: string, format: date-time }
        note: { type: [string, 'null'] }
        owner: { $ref: 'https://example.com/schemas/user.yaml#/User' }`}</code></pre>
<p>ツールの出力です。</p>
<pre><code>{`export interface Event {
  id: number;
  kind: Record<string, unknown>;
  /** ISO 8601 date-time */ createdAt: string;
  note?: string | null;
  owner?: unknown;
}

export type unknown = unknown;`}</code></pre>
<p><code>type: [string, "null"]</code> は正しく <code>string | null</code> になります。手直しが必要なのは 3 か所です。<code>const</code> は読み取られず、<code>kind</code> は <code>"order.created"</code> ではなく <code>Record&lt;string, unknown&gt;</code> になります。外部の <code>$ref</code> は <code>unknown</code> になり、仮置きの <code>export type unknown = unknown;</code> はコンパイルできません（TypeScript 5.9 では "Type alias name cannot be 'unknown'"）。この行を削除し、<code>owner</code> の型は手で書いてください。</p>

<h2>制限</h2>
<ul>
  <li>解決できるのは <code>#/components/schemas/...</code> の参照だけです。他のファイルや URL への参照は <code>unknown</code> になり、上の無効な <code>export type unknown = unknown;</code> 行が付きます。</li>
  <li><code>const</code> は無視されます。リテラル型が必要なら値が 1 つの <code>enum</code> を使ってください。</li>
  <li>英数字、<code>{'_'}</code>、<code>$</code> 以外の文字を含むスキーマ名（<code>pet-status</code> など）は <code>{'pet_status'}</code> に変わり、TypeScript 側では元のスキーマが見つからなくなります。<code>pet-status</code> という enum は <code>{'export type pet_status = unknown;'}</code> として出力されます。Zod 側では enum が残ります。</li>
  <li>Zod スキーマは <code>components/schemas</code> の順に <code>z.lazy</code> なしで出力されます。後で宣言されるスキーマや自分自身を参照するスキーマがあると、モジュールの読み込み時に <code>ReferenceError</code> になります。宣言の順序を入れ替え、再帰する参照は <code>z.lazy(() =&gt; ...)</code> で包んでください。</li>
  <li><code>format: int64</code> の <code>integer</code> は <code>number</code> になり、2<sup>53</sup> を超えると精度が落ちます。API がそうした ID を文字列で送るなら <code>string</code> に変えてください。</li>
  <li>path 型が読み取るのは <code>application/json</code> のリクエストボディとレスポンスボディだけです。</li>
</ul>
