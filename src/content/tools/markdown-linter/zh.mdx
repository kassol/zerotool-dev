<h2>检测内容</h2>
<p>
  检查器应用完整的 <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint 规则</a>，包括：
</p>
<ul>
  <li><strong>MD001</strong> — 标题层级每次只能增加一级</li>
  <li><strong>MD009</strong> — 行尾不应有空格</li>
  <li><strong>MD010</strong> — 不使用制表符（应使用空格）</li>
  <li><strong>MD012</strong> — 不连续出现多个空行</li>
  <li><strong>MD018</strong> — ATX 标题的 # 后要有空格</li>
  <li><strong>MD022</strong> — 标题前后应有空行</li>
  <li><strong>MD025</strong> — 文档中只能有一个顶级标题</li>
  <li><strong>MD026</strong> — 标题末尾不加标点</li>
  <li><strong>MD031</strong> — 代码围栏前后应有空行</li>
  <li><strong>MD034</strong> — 不使用裸 URL，应使用链接语法</li>
  <li><strong>MD041</strong> — 第一行应为顶级标题</li>
</ul>

<h2>中文文档里常见的报错</h2>

<p>用中文输入法写 Markdown，常见的两种情况是 <code>#</code> 后面忘了空格，以及标题末尾带了全角冒号。下面这份安装说明粘贴进工具后，「复制结果」得到三行：</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`#安装说明

## 注意事项：

运行 \`npm install\` 之前先确认 Node.js 版本。`}</code></pre>

<pre><code>{`行 1 [MD018] No space after hash on atx style heading [#安装说明]
行 3 [MD026] Trailing punctuation in heading — Punctuation: '：'
行 1 [MD041] First line in a file should be a top-level heading [#安装说明]`}</code></pre>

<ul>
  <li><code>{"#安装说明"}</code> 少了空格，不是标题，而是一行普通文字，所以同一行还报了 MD041（第一行不是一级标题）。</li>
  <li>MD026 默认检查的标点是 <code>{".,;:!。，；：！"}</code>，包含全角的句号、逗号、分号、冒号和感叹号；问号不在其中，<code>{"## 常见问题？"}</code> 不会被报（见 <a href="https://github.com/DavidAnson/markdownlint/blob/v0.40.0/doc/md026.md" target="_blank" rel="noopener">MD026 文档</a>）。</li>
  <li>结果按规则编号排序，同一规则内再按行号排序，所以行 1 的 MD041 排在行 3 的 MD026 后面。</li>
</ul>

<h2>检查器看不出的问题</h2>

<p>markdownlint 检查的是写法，不渲染文档。下面这段内容在页面上有两处显示不对，检查结果却是空的：</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`# 填写说明

**注意：**这里必须填写手机号。

- 基本信息
　- 姓名`}</code></pre>

<pre><code>{`未发现问题`}</code></pre>

<ul>
  <li>第 3 行的加粗不会生效。结束的 <code>{"**"}</code> 前面是全角冒号、后面紧跟汉字，按 <a href="https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis" target="_blank" rel="noopener">CommonMark 0.31.2 第 6.2 节</a>的规则它不能结束强调，两组 <code>{"**"}</code> 会原样显示。</li>
  <li>第 6 行开头是全角空格（U+3000），不是缩进，所以「- 姓名」不会成为子列表，而是接在「基本信息」后面的文字。</li>
</ul>

<p>这类问题要在 <a href="/zh/tools/markdown-preview/">Markdown 预览</a>里看渲染结果才能发现。</p>

<h2>示例：一份更新日志</h2>

<p>按 Keep a Changelog 的结构写的中文更新日志，每个版本下面都有「新增」：</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`# 更新日志

## 1.2.0

### 新增

- 导出按钮

## 1.1.0

### 新增

* 深色模式

详见 https://example.com/releases`}</code></pre>

<p>「复制结果」得到（markdownlint 0.40，默认规则，输入以换行结尾；没有末尾换行时还会多报一条 MD047）：</p>

<pre><code>{`行 13 [MD004] Unordered list style — Expected: dash; Actual: asterisk
行 11 [MD024] Multiple headings with the same content [新增]
行 15 [MD034] Bare URL used [https://example.com/releases]`}</code></pre>

<ul>
  <li>两个版本下都有「新增」标题，所以触发 MD024。这正是 Keep a Changelog 的标准写法；在你自己的配置里写 <code>{"\"MD024\": { \"siblings_only\": true }"}</code>，就允许不同父标题下出现同名标题。</li>
  <li>MD004 要求整篇文档用同一种列表符号；第一个列表用了 <code>{"-"}</code>，所以 <code>{"*"}</code> 被标出。</li>
  <li>MD034 要求把裸 URL 写成 <code>{"<https://example.com/releases>"}</code> 或 Markdown 链接。</li>
</ul>

<h2>这里改不了的默认设置</h2>

<p>工具按默认设置运行 markdownlint 默认启用的全部规则（见 <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint rules</a>）。页面没有配置项，有两条默认规则经常带来噪音：</p>

<ul>
  <li><strong>MD013 行长度</strong>上限 80 个字符。一行 104 个字符的英文段落会报 <code>{"Expected: 80; Actual: 104"}</code>。第 80 列之后没有空格的长行不报，所以不含空格的长中文行通常能通过；但中英文之间加了空格（如「运行 npm install 之前」）或用了全角空格，只要第 80 列之后出现空格，这一行仍会被报。</li>
  <li><strong>MD024</strong> 会标出文档里任何重复的标题文字，比如上面的更新日志。</li>
</ul>

<p>想按自己的规则检查，把配置写进 <code>{".markdownlint.json"}</code>，在本地或 CI 里运行 <a href="https://github.com/DavidAnson/markdownlint-cli2" target="_blank" rel="noopener">markdownlint-cli2</a>：</p>

<pre><code>{`{
  "MD013": { "line_length": 120 },
  "MD024": { "siblings_only": true }
}`}</code></pre>

<p>markdownlint 会跳过文件开头的 YAML front matter，其中的 <code>{"title"}</code> 在 MD041 里算作一级标题。</p>

<h2>限制</h2>
<ul>
  <li>规则描述和详情来自 markdownlint，在所有语言版本中都是英文。</li>
  <li>工具只报告问题，不自动修复；markdownlint-cli2 的 <code>{"--fix"}</code> 可以修复其中一部分。</li>
  <li>一次检查一份文档，使用默认设置，不能上传 <code>{".markdownlint.json"}</code>。文内的 <code>{"<!-- markdownlint-disable MD013 -->"}</code>、<code>{"<!-- markdownlint-enable MD013 -->"}</code> 和 <code>{"<!-- markdownlint-disable-next-line MD034 -->"}</code> 注释可以对局部停用规则。</li>
  <li>不检查拼写、文档外链接是否有效，也不判断 GitHub 等渲染器的实际显示效果。</li>
</ul>
