<h2>チェック内容</h2>
<p>
  <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlintの全ルール</a>を適用します。主な内容：
</p>
<ul>
  <li><strong>MD001</strong> — 見出しレベルは一度に1段階だけ増やす</li>
  <li><strong>MD009</strong> — 行末にスペースを置かない</li>
  <li><strong>MD012</strong> — 連続する空行を複数置かない</li>
  <li><strong>MD018</strong> — ATX 見出しの # の後に空白を入れる</li>
  <li><strong>MD022</strong> — 見出しの前後には空行を入れる</li>
  <li><strong>MD026</strong> — 見出しの末尾に句読点を付けない</li>
  <li><strong>MD034</strong> — 裸のURLは使わず、リンク記法を使う</li>
  <li><strong>MD041</strong> — 最初の行はトップレベルの見出し</li>
</ul>

<h2># の後の全角スペースと末尾の記号</h2>

<p><code>{"#"}</code> の後ろに全角スペースが入った見出しと、末尾に「！」や「？」を付けた見出しを例にします。次の文書で「結果をコピー」を押すと 3 行になります。</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`#　インストール

## よくある質問？

## 注意！

\`npm install\` を実行します。`}</code></pre>

<pre><code>{`行 1 [MD018] No space after hash on atx style heading [#　インストール]
行 5 [MD026] Trailing punctuation in heading — Punctuation: '！'
行 1 [MD041] First line in a file should be a top-level heading [#　インストール]`}</code></pre>

<ul>
  <li><a href="https://spec.commonmark.org/0.31.2/#atx-headings" target="_blank" rel="noopener">CommonMark の ATX 見出し</a>は # の後に半角スペースかタブ（または行末）が必要です。全角スペース（U+3000）では見出しにならず普通の段落になるため、1 行目は MD018 と MD041 の両方に該当します。</li>
  <li>MD026 の既定の対象は <code>{".,;:!。，；：！"}</code> で、全角の「！」は入っていますが、疑問符は FAQ 形式の見出しでよく使うため除かれています（<a href="https://github.com/DavidAnson/markdownlint/blob/v0.40.0/doc/md026.md" target="_blank" rel="noopener">MD026 のドキュメント</a>）。そのため「よくある質問？」は指摘されません。</li>
  <li>結果はルール番号順、同じルールの中では行番号順に並びます。</li>
</ul>

<h2>指摘されないが表示が崩れる書き方</h2>

<p>markdownlint は書き方を検査するもので、文書を描画しません。次の文書は「問題なし」になりますが、表示は期待どおりになりません。</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`# 記事の書き方

**「重要」**です。

日本語の文章は単語のあいだに空白を入れないため、一つの段落を一行で書くとこの行のように八十文字を大きく超えますが、MD013は八十桁目より後ろに空白のない行を報告しないので、この行は問題として表示されません。`}</code></pre>

<pre><code>{`問題なし`}</code></pre>

<ul>
  <li>3 行目の太字は効きません。閉じる <code>{"**"}</code> の前が「」」、後ろが「で」なので、<a href="https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis" target="_blank" rel="noopener">CommonMark 0.31.2 の 6.2 節</a>の規則では強調を閉じられず、アスタリスクがそのまま表示されます。</li>
  <li>5 行目は 104 文字ありますが、MD013 は 80 桁目より後ろに空白がない行を対象外にするため指摘されません（<a href="https://github.com/DavidAnson/markdownlint/blob/v0.40.0/doc/md013.md" target="_blank" rel="noopener">MD013 のドキュメント</a>）。英文の行なら同じ長さで <code>{"Expected: 80; Actual: 104"}</code> が出ます。</li>
</ul>

<p>太字が効かない場面と回避方法は<a href="/ja/blog/markdown-cheat-sheet/">マークダウン記法 一覧</a>にまとめています。描画結果は <a href="/ja/tools/markdown-preview/">Markdown プレビュー</a>で確かめられます。</p>

<h2>例：CHANGELOG</h2>

{/* mdl-check: {"eol":true} */}

<p>入力：</p>

<pre><code>{`# Changelog

## 1.2.0

### Added

- Export button

## 1.1.0

### Added

* Dark mode

See https://example.com/releases`}</code></pre>

<p>「結果をコピー」の内容（markdownlint 0.40、既定のルール、末尾に改行あり。末尾の改行がないと MD047 も出ます）：</p>

<pre><code>{`行 13 [MD004] Unordered list style — Expected: dash; Actual: asterisk
行 11 [MD024] Multiple headings with the same content [Added]
行 15 [MD034] Bare URL used [https://example.com/releases]`}</code></pre>

<ul>
  <li>どちらのバージョンにも「Added」見出しがあるため MD024 が出ます。Keep a Changelog の標準的な書き方なので、自分の設定では <code>{"\"MD024\": { \"siblings_only\": true }"}</code> として親が異なる同名見出しを許可します。</li>
  <li>MD004 は文書内でリスト記号を 1 種類にそろえるよう求めます。最初のリストが <code>{"-"}</code> なので <code>{"*"}</code> が指摘されます。</li>
  <li>MD034 は裸の URL を <code>{"<https://example.com/releases>"}</code> か Markdown のリンクにするよう求めます。</li>
</ul>

<h2>ここでは変えられない既定値</h2>

<p>ツールは markdownlint が既定で有効にしているルールをすべて、既定の設定で実行します（<a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint rules</a> を参照）。設定画面はないため、次の 2 つがよく余計な指摘になります：</p>

<ul>
  <li><strong>MD013 行の長さ</strong>は 80 文字です。上で見たとおり、80 桁目以降に空白のない日本語の長い行はたいてい通ります。80 桁目より後ろに半角・全角を問わずスペースがある行（英単語をスペースで区切って混ぜた行など）は対象になります。</li>
  <li><strong>MD024</strong> は文書内で同じ見出しの文字列が繰り返されると指摘します。上の CHANGELOG がその例です。</li>
</ul>

<p>自分の設定で検査するなら <code>{".markdownlint.json"}</code> に書き、ローカルや CI で <a href="https://github.com/DavidAnson/markdownlint-cli2" target="_blank" rel="noopener">markdownlint-cli2</a> を実行します：</p>

<pre><code>{`{
  "MD013": { "line_length": 120 },
  "MD024": { "siblings_only": true }
}`}</code></pre>

<p>markdownlint はファイル先頭の YAML Front Matter を読み飛ばし、その中の <code>{"title"}</code> は MD041 ではトップレベルの見出しとして扱われます。</p>

<h2>制限事項</h2>
<ul>
  <li>ルールの説明と詳細は markdownlint のもので、どの言語版でも英語です。</li>
  <li>問題を報告するだけで、自動修正はしません。markdownlint-cli2 の <code>{"--fix"}</code> で多くは自動修正できます。</li>
  <li>一度に検査するのは 1 文書で、設定は既定値のままです。<code>{".markdownlint.json"}</code> のアップロードはできません。文書内の <code>{"<!-- markdownlint-disable MD013 -->"}</code>、<code>{"<!-- markdownlint-enable MD013 -->"}</code>、<code>{"<!-- markdownlint-disable-next-line MD034 -->"}</code> コメントで一部だけルールを止められます。</li>
  <li>スペル、文書外のリンク切れ、GitHub などのレンダラーでの実際の見え方は確認しません。</li>
</ul>

<h2>プライバシー</h2>
<p>markdownlint はこのページの中で動きます。Markdown はアップロードされず、ブラウザーのストレージにも保存しません。ページを再読み込みすると、エディタはサンプル文書に戻ります。アクセス解析が記録するのは「結果をコピー」でコピーできたことだけで、コピーに失敗したときは記録しません。</p>
