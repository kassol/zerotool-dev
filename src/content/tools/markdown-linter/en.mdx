<h2>How to Use</h2>
<ol>
  <li>Paste or type Markdown in the left pane.</li>
  <li>Lint results appear in real time on the right — no button press needed.</li>
  <li>Click any result to jump to that line in the editor.</li>
  <li>Fix the flagged issues and watch the results update instantly.</li>
</ol>

<h2>What Gets Checked</h2>
<p>
  The linter applies the full set of <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint rules</a>, including:
</p>
<ul>
  <li><strong>MD001</strong> — Heading levels should only increment by one level at a time</li>
  <li><strong>MD009</strong> — No trailing spaces at end of lines</li>
  <li><strong>MD010</strong> — No hard tabs (use spaces instead)</li>
  <li><strong>MD012</strong> — No multiple consecutive blank lines</li>
  <li><strong>MD022</strong> — Headings should be surrounded by blank lines</li>
  <li><strong>MD025</strong> — Only one top-level heading per document</li>
  <li><strong>MD031</strong> — Fenced code blocks surrounded by blank lines</li>
  <li><strong>MD034</strong> — No bare URLs — use link syntax instead</li>
  <li><strong>MD041</strong> — First line should be a top-level heading</li>
</ul>

<h2>Example: A Changelog</h2>

<p>Input:</p>

<pre><code>{`# Changelog

## 1.2.0

### Added

- Export button

## 1.1.0

### Added

* Dark mode

See https://example.com/releases`}</code></pre>

<p>Results (markdownlint 0.40, default rules):</p>

<pre><code>{`L13  MD004 / ul-style            Unordered list style — Expected: dash; Actual: asterisk
L11  MD024 / no-duplicate-heading Multiple headings with the same content
L15  MD034 / no-bare-urls         Bare URL used`}</code></pre>

<ul>
  <li>MD024 fires because both versions have an "Added" heading. That is the normal layout of a Keep a Changelog file; in your own config, <code>{"\"MD024\": { \"siblings_only\": true }"}</code> allows repeated headings under different parents.</li>
  <li>MD004 wants one bullet style per document; the first list used <code>{"-"}</code>, so <code>{"*"}</code> is flagged.</li>
  <li>MD034 asks for <code>{"<https://example.com/releases>"}</code> or a Markdown link instead of a bare URL.</li>
</ul>

<h2>Defaults You Cannot Change Here</h2>

<p>The tool runs every rule that markdownlint enables by default, with default settings (see <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint rules</a>). There is no configuration panel, so two defaults often produce noise:</p>

<ul>
  <li><strong>MD013 line length</strong> is 80 characters. A 104-character English paragraph line is reported as <code>{"Expected: 80; Actual: 104"}</code>. A long line with no spaces after column 80 is not reported, so long Chinese, Japanese or Korean lines without spaces usually pass.</li>
  <li><strong>MD024</strong> flags any repeated heading text in the document, as in the changelog above.</li>
</ul>

<p>To lint with your own settings, put them in <code>{".markdownlint.json"}</code> and run <a href="https://github.com/DavidAnson/markdownlint-cli2" target="_blank" rel="noopener">markdownlint-cli2</a> locally or in CI:</p>

<pre><code>{`{
  "MD013": { "line_length": 120 },
  "MD024": { "siblings_only": true }
}`}</code></pre>

<p>markdownlint skips YAML front matter at the top of a file, and a <code>{"title"}</code> in it counts as the top-level heading for MD041.</p>
