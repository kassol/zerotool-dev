<h2>What Gets Checked</h2>
<p>
  The linter applies the full set of <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint rules</a>, including:
</p>
<ul>
  <li><strong>MD001</strong> — Heading levels should only increment by one level at a time</li>
  <li><strong>MD009</strong> — No trailing spaces at end of lines</li>
  <li><strong>MD010</strong> — No hard tabs (use spaces instead)</li>
  <li><strong>MD012</strong> — No multiple consecutive blank lines</li>
  <li><strong>MD022</strong> — Headings should be surrounded by blank lines</li>
  <li><strong>MD025</strong> — Only one top-level heading per document</li>
  <li><strong>MD031</strong> — Fenced code blocks surrounded by blank lines</li>
  <li><strong>MD034</strong> — No bare URLs — use link syntax instead</li>
  <li><strong>MD041</strong> — First line should be a top-level heading</li>
</ul>

<h2>Reading a Result</h2>
<p>Each result line has the rule ID, the line number, the rule description, details after a dash and the text in brackets, then the rule alias. This input:</p>

<pre><code>{`Intro paragraph
## Setup
#### Install
Run \`npm install\`.
\`\`\`
npm test
\`\`\``}</code></pre>

<p>with a final line break gives eight results, including:</p>
<ul>
  <li><code>{"MD001 L 3 Heading levels should only increment by one level at a time — Expected: h3; Actual: h4"}</code>: <code>{"####"}</code> follows <code>{"##"}</code>, so a level was skipped.</li>
  <li><code>{"MD022 L 2 Headings should be surrounded by blank lines — Expected: 1; Actual: 0; Above [## Setup]"}</code>, reported once for the missing blank line above and once below each heading.</li>
  <li><code>{"MD031"}</code> and <code>{"MD040"}</code> on line 5: the code fence needs a blank line before it and a language name such as <code>{"```sh"}</code>.</li>
  <li><code>{"MD041 L 1 First line in a file should be a top-level heading [Intro paragraph]"}</code>.</li>
</ul>
<p><strong>Copy Results</strong> copies one line per result in the form <code>{"L 3 [MD001] Heading levels should only increment by one level at a time — Expected: h3; Actual: h4"}</code>, which is easy to paste into a review comment.</p>

<h2>Turning a Rule Off for One Section</h2>
<p>
  markdownlint reads configuration comments inside the document, and so does this tool. Wrapping a paragraph in
  <code>{"<!-- markdownlint-disable MD013 -->"}</code> and <code>{"<!-- markdownlint-enable MD013 -->"}</code> stops the line-length
  report for that part only; <code>{"<!-- markdownlint-disable-next-line MD034 -->"}</code> skips one line. Use these when one table or
  URL has to break a rule, and keep the rule on for the rest of the file. Renderers that pass HTML through treat them as HTML comments and hide them; the <a href="/tools/markdown-preview/">Markdown Preview</a> on this site escapes raw HTML, so it shows them as text.
</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`# Notes

<!-- markdownlint-disable-next-line MD034 -->
See https://example.com
Also https://example.org`}</code></pre>

<p>The comment covers line 4 only, so the second bare URL is still reported:</p>

<pre><code>{`L 5 [MD034] Bare URL used [https://example.org]`}</code></pre>

<h2>Limitations</h2>
<ul>
  <li>Rule descriptions and details come from markdownlint and are in English on every language version of this page.</li>
  <li>The tool reports problems but does not fix them. markdownlint-cli2 with <code>{"--fix"}</code> can fix many of them automatically.</li>
  <li>One document at a time, with default settings; no <code>{".markdownlint.json"}</code> upload.</li>
  <li>markdownlint checks Markdown style. It does not check spelling, broken links outside the document, or whether a renderer such as GitHub shows the file the way you expect; use the <a href="/tools/markdown-preview/">Markdown Preview</a> for that.</li>
</ul>

<h2>Privacy</h2>
<p>markdownlint runs in this page. Your Markdown is not uploaded, and the tool does not save it in browser storage; reloading the page brings back the sample document. Analytics records only that Copy Results was clicked.</p>

<h2>Example: A Changelog</h2>

{/* mdl-check: {"eol":true} */}

<p>Input:</p>

<pre><code>{`# Changelog

## 1.2.0

### Added

- Export button

## 1.1.0

### Added

* Dark mode

See https://example.com/releases`}</code></pre>

<p>Copy Results gives these lines (markdownlint 0.40, default rules, input ending with a line break; without the final line break MD047 is reported as well). The order is markdownlint's: by rule, then by line.</p>

<pre><code>{`L 13 [MD004] Unordered list style — Expected: dash; Actual: asterisk
L 11 [MD024] Multiple headings with the same content [Added]
L 15 [MD034] Bare URL used [https://example.com/releases]`}</code></pre>

<ul>
  <li>MD024 fires because both versions have an "Added" heading. That is the normal layout of a Keep a Changelog file; in your own config, <code>{"\"MD024\": { \"siblings_only\": true }"}</code> allows repeated headings under different parents.</li>
  <li>MD004 wants one bullet style per document; the first list used <code>{"-"}</code>, so <code>{"*"}</code> is flagged.</li>
  <li>MD034 asks for <code>{"<https://example.com/releases>"}</code> or a Markdown link instead of a bare URL.</li>
</ul>

<h2>Defaults You Cannot Change Here</h2>

<p>The tool runs every rule that markdownlint enables by default, with default settings (see <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint rules</a>). There is no configuration panel, so two defaults often produce noise:</p>

<ul>
  <li><strong>MD013 line length</strong> is 80 characters. A 104-character English paragraph line is reported as <code>{"Expected: 80; Actual: 104"}</code>. A long line with no spaces after column 80 is not reported, so long Chinese, Japanese or Korean lines without spaces usually pass.</li>
  <li><strong>MD024</strong> flags any repeated heading text in the document, as in the changelog above.</li>
</ul>

<p>To lint with your own settings, put them in <code>{".markdownlint.json"}</code> and run <a href="https://github.com/DavidAnson/markdownlint-cli2" target="_blank" rel="noopener">markdownlint-cli2</a> locally or in CI:</p>

<pre><code>{`{
  "MD013": { "line_length": 120 },
  "MD024": { "siblings_only": true }
}`}</code></pre>

<p>markdownlint skips YAML front matter at the top of a file, and a <code>{"title"}</code> in it counts as the top-level heading for MD041.</p>
