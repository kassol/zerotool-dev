<h2>검사 내용</h2>
<p>
  <a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint 전체 규칙</a>을 적용합니다. 주요 내용:
</p>
<ul>
  <li><strong>MD001</strong> — 제목 레벨은 한 번에 1단계씩만 증가</li>
  <li><strong>MD004</strong> — 목록 기호는 문서 안에서 한 가지로</li>
  <li><strong>MD009</strong> — 줄 끝에 공백을 두지 않음</li>
  <li><strong>MD012</strong> — 연속 빈 줄을 여러 개 두지 않음</li>
  <li><strong>MD013</strong> — 한 줄은 80자까지</li>
  <li><strong>MD022</strong> — 제목 앞뒤에 빈 줄 삽입</li>
  <li><strong>MD026</strong> — 제목 끝에 문장 부호를 붙이지 않음</li>
  <li><strong>MD034</strong> — 노출된 URL 사용 금지, 링크 문법 사용</li>
  <li><strong>MD041</strong> — 첫 줄은 최상위 제목이어야 함</li>
</ul>

<h2>한국어 문서에서 자주 나오는 지적</h2>

<p>한국어는 띄어쓰기를 하므로 중국어·일본어 문서와 달리 긴 문단이 MD013에 걸립니다. 한 문단을 한 줄로 쓴 README를 붙여 넣으면 다음과 같이 나옵니다.</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`# 안내

이 문장은 한국어로 작성한 긴 설명이며 띄어쓰기가 있어서 줄 길이 규칙이 적용됩니다. 이 문장은 한국어로 작성한 긴 설명이며 띄어쓰기가 있어서 줄 길이 규칙이 적용됩니다.`}</code></pre>

<pre><code>{`줄 3 [MD013] Line length — Expected: 80; Actual: 95`}</code></pre>

<p>3번째 줄은 95자입니다. MD013은 글자 수를 세며, 한글 음절이 영문자보다 넓게 보여도 한 글자로 계산합니다. 80번째 글자 뒤에 공백이 하나도 없는 줄만 예외로 둡니다(<a href="https://github.com/DavidAnson/markdownlint/blob/v0.40.0/doc/md013.md" target="_blank" rel="noopener">MD013 문서</a>). 문장 단위로 줄을 바꾸거나, 자신의 <code>{".markdownlint.json"}</code>에서 <code>{"line_length"}</code>를 늘려 해결합니다.</p>

<h2>제목의 문장 부호와 굵게</h2>

<p>다음 문서에서는 한 가지만 지적되고, 화면에서 깨지는 부분은 지적되지 않습니다.</p>

{/* mdl-check: {"eol":true} */}

<pre><code>{`# 설치 안내

## 설치 방법:

**"중요"**합니다. **굵게**는 됩니다.`}</code></pre>

<pre><code>{`줄 3 [MD026] Trailing punctuation in heading — Punctuation: ':'`}</code></pre>

<ul>
  <li>MD026의 기본 대상은 <code>{".,;:!。，；：！"}</code>이며, 물음표는 FAQ 형식의 제목에서 자주 쓰여 기본값에서 빠져 있습니다(<a href="https://github.com/DavidAnson/markdownlint/blob/v0.40.0/doc/md026.md" target="_blank" rel="noopener">MD026 문서</a>). ‘## 설치 방법:’의 콜론은 지적되고, ‘## 설치가 안 되나요?’는 지적되지 않습니다.</li>
  <li>5번째 줄의 <code>{"**\"중요\"**합니다"}</code>는 굵게 표시되지 않습니다. 닫는 <code>{"**"}</code> 앞이 따옴표이고 뒤에 바로 한글 조사가 붙어 있어서, <a href="https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis" target="_blank" rel="noopener">CommonMark 0.31.2의 6.2절</a> 규칙으로는 강조를 닫을 수 없습니다. 같은 줄의 <code>{"**굵게**는"}</code>은 앞에 문장 부호가 없으므로 굵게 표시됩니다. markdownlint는 이 차이를 검사하지 않습니다.</li>
</ul>

<p>굵게가 풀리는 경우와 해결 방법은 <a href="/ko/blog/markdown-cheat-sheet/">마크다운 문법 정리</a>에, 실제 표시 결과는 <a href="/ko/tools/markdown-preview/">Markdown 미리보기</a>에서 확인할 수 있습니다.</p>

<h2>예시: CHANGELOG</h2>

{/* mdl-check: {"eol":true} */}

<p>입력:</p>

<pre><code>{`# Changelog

## 1.2.0

### Added

- Export button

## 1.1.0

### Added

* Dark mode

See https://example.com/releases`}</code></pre>

<p>‘결과 복사’ 결과(markdownlint 0.40, 기본 규칙, 입력이 줄바꿈으로 끝남. 마지막 줄바꿈이 없으면 MD047도 나옵니다). 결과는 규칙 번호 순, 같은 규칙 안에서는 줄 번호 순입니다.</p>

<pre><code>{`줄 13 [MD004] Unordered list style — Expected: dash; Actual: asterisk
줄 11 [MD024] Multiple headings with the same content [Added]
줄 15 [MD034] Bare URL used [https://example.com/releases]`}</code></pre>

<ul>
  <li>두 버전 모두 ‘Added’ 제목이 있어 MD024가 나옵니다. Keep a Changelog의 표준 구성이므로, 자신의 설정에서 <code>{"\"MD024\": { \"siblings_only\": true }"}</code>로 부모가 다른 같은 이름의 제목을 허용합니다.</li>
  <li>MD004는 문서 전체에서 목록 기호를 한 가지로 맞추라고 요구합니다. 첫 목록이 <code>{"-"}</code>이므로 <code>{"*"}</code>가 지적됩니다.</li>
  <li>MD034는 노출된 URL을 <code>{"<https://example.com/releases>"}</code>나 Markdown 링크로 쓰라고 요구합니다.</li>
</ul>

<h2>여기서 바꿀 수 없는 기본값</h2>

<p>도구는 markdownlint가 기본으로 켜는 규칙 전체를 기본 설정으로 실행합니다(<a href="https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md" target="_blank" rel="noopener">markdownlint rules</a> 참고). 설정 화면이 없어서 다음 두 규칙이 자주 불필요한 지적을 만듭니다:</p>

<ul>
  <li><strong>MD013 줄 길이</strong>는 80자입니다. 위에서 본 것처럼 띄어쓰기가 있는 한국어 문단도 대상입니다.</li>
  <li><strong>MD024</strong>는 문서 안에서 같은 제목 텍스트가 반복되면 지적합니다. 위의 CHANGELOG가 그 예입니다.</li>
</ul>

<p>자신의 설정으로 검사하려면 <code>{".markdownlint.json"}</code>에 적고 로컬이나 CI에서 <a href="https://github.com/DavidAnson/markdownlint-cli2" target="_blank" rel="noopener">markdownlint-cli2</a>를 실행합니다:</p>

<pre><code>{`{
  "MD013": { "line_length": 120 },
  "MD024": { "siblings_only": true }
}`}</code></pre>

<p>markdownlint는 파일 앞의 YAML Front Matter를 건너뛰며, 그 안의 <code>{"title"}</code>은 MD041에서 최상위 제목으로 취급합니다.</p>

<h2>제한 사항</h2>
<ul>
  <li>규칙 설명과 세부 정보는 markdownlint가 제공하며, 모든 언어 버전에서 영어입니다.</li>
  <li>문제를 보고만 하고 자동으로 고치지는 않습니다. markdownlint-cli2의 <code>{"--fix"}</code>로 상당수를 자동 수정할 수 있습니다.</li>
  <li>한 번에 문서 하나를 기본 설정으로 검사하며 <code>{".markdownlint.json"}</code>을 올릴 수 없습니다. 문서 안의 <code>{"<!-- markdownlint-disable MD013 -->"}</code>, <code>{"<!-- markdownlint-enable MD013 -->"}</code>, <code>{"<!-- markdownlint-disable-next-line MD034 -->"}</code> 주석으로 일부 구간만 규칙을 끌 수 있습니다.</li>
  <li>맞춤법, 문서 밖 링크의 유효성, GitHub 같은 렌더러에서의 실제 표시는 확인하지 않습니다.</li>
</ul>

<h2>개인정보</h2>
<p>markdownlint는 이 페이지 안에서 실행됩니다. Markdown은 업로드되지 않고 브라우저 저장소에도 저장되지 않습니다. 페이지를 새로 고치면 에디터는 예시 문서로 돌아갑니다. 통계에는 ‘결과 복사’를 눌렀다는 사실만 기록됩니다.</p>
