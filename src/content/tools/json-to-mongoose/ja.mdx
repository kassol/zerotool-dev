<h2>型マッピング</h2>
<ul>
  <li><code>null</code> はどの型にも入るので推論では読み飛ばします。すべてのサンプルで <code>null</code> のフィールド → <code>mongoose.Schema.Types.Mixed</code></li>
  <li>サンプルごとに型が違うフィールド（数値と文字列、オブジェクトと文字列）→ <code>mongoose.Schema.Types.Mixed</code>。ISO 日時とほかの文字列が混ざる場合 → <code>String</code></li>
  <li>ISO 8601 の日時で始まる文字列（<code>2026-10-01T09:30:00Z</code>）→ <code>Date</code>。日付だけの <code>2026-10-01</code>、<code>T</code> の代わりに空白を入れた <code>2026-10-01 09:30:00</code>、配列の中の日時は <code>String</code> のまま</li>
  <li>文字列 → <code>String</code></li>
  <li>数値 → <code>Number</code></li>
  <li>真偽値 → <code>Boolean</code></li>
  <li>プリミティブ配列 → <code>[String]</code> / <code>[Number]</code> / <code>[Boolean]</code></li>
  <li>オブジェクト配列 → <code>[subSchema]</code>（独立サブスキーマを生成）</li>
  <li>ネストオブジェクト → 独立スキーマ変数をインライン参照</li>
</ul>

<h2>例</h2>

{/* jtm-check: {"json":"{\"username\": \"alice\", \"age\": 28, \"tags\": [\"admin\"], \"address\": {\"city\": \"London\"}}","model":"User","mode":"javascript","timestamps":true,"required":false} */}

<p>モデル名 <code>User</code>、以下のJSONを入力した場合：</p>
<pre><code>{`{"username": "alice", "age": 28, "tags": ["admin"], "address": {"city": "London"}}`}</code></pre>
<p>JavaScript出力（timestampsオン）：</p>
<pre><code>{`const mongoose = require('mongoose');\nconst { Schema } = mongoose;\n\nconst addressSchema = new Schema({\n  city: { type: String },\n});\n\nconst userSchema = new Schema({\n  username: { type: String },\n  age: { type: Number },\n  tags: [String],\n  address: addressSchema,\n}, { timestamps: true });\n\nmodule.exports = mongoose.model('User', userSchema);`}</code></pre>

<h2>例：すべてのサンプルで型を決める</h2>

{/* jtm-check: {"json":"[{\"code\":1,\"note\":null,\"seller\":{\"meta\":{\"x\":1}},\"buyer\":{\"meta\":{\"y\":\"2\"}}},{\"code\":\"A-2\",\"note\":\"gift\",\"tags\":[\"a\",1]}]","model":"Order","mode":"javascript","timestamps":false,"required":false} */}

<p>注文 2 件のルート配列、モデル名 <code>Order</code>、JavaScript、timestamps オフ：</p>
<pre><code>{`[{"code":1,"note":null,"seller":{"meta":{"x":1}},"buyer":{"meta":{"y":"2"}}},{"code":"A-2","note":"gift","tags":["a",1]}]`}</code></pre>

<p>出力：</p>
<pre><code>{`const mongoose = require('mongoose');
const { Schema } = mongoose;

const metaSchema = new Schema({
  x: { type: Number },
});

const sellerSchema = new Schema({
  meta: metaSchema,
});

const buyerMetaSchema = new Schema({
  y: { type: String },
});

const buyerSchema = new Schema({
  meta: buyerMetaSchema,
});

const orderSchema = new Schema({
  code: { type: mongoose.Schema.Types.Mixed },
  note: { type: String },
  seller: sellerSchema,
  buyer: buyerSchema,
  tags: [mongoose.Schema.Types.Mixed],
}, { timestamps: false });

module.exports = mongoose.model('Order', orderSchema);`}</code></pre>
<ul>
  <li><code>code</code> は 1 件目が <code>1</code>、2 件目が <code>"A-2"</code> なので <code>Mixed</code> です。<code>Number</code> だと <code>"A-2"</code> を拒否します。<code>note</code> は <code>null</code> と <code>"gift"</code> なので <code>String</code> です。<code>tags</code> は文字列と数値が混ざるので要素が <code>Mixed</code> です。</li>
  <li>2 つの <code>meta</code> はフィールドが違うので、2 つ目は親のキーを前に付けます（<code>buyerMetaSchema</code>）。同じキーでフィールドと型が同じオブジェクトは 1 つのスキーマを共有します。前置きしても名前が重なるときは番号を付けます。</li>
</ul>
<p>ツールのテストでは、生成した JavaScript を Mongoose 9.10.3 で実行し、各サンプルからドキュメントを作って <code>validateSync()</code> が通ること、すべてのフィールドと値が残ることを確認しています（ISO 日時は <code>Date</code> になり、<code>toISOString()</code> の形で比較。サンプルにない配列フィールドは Mongoose の既定値 <code>[]</code> になります）。</p>

<h2>気象庁の天気予報 JSON から作る</h2>

{/* jtm-check: {"json":"[{\"publishingOffice\":\"気象庁\",\"reportDatetime\":\"2026-10-08T17:00:00+09:00\",\"timeSeries\":[{\"timeDefines\":[\"2026-10-08T17:00:00+09:00\",\"2026-10-09T00:00:00+09:00\"],\"areas\":[{\"area\":{\"name\":\"東京地方\",\"code\":\"130010\"},\"weatherCodes\":[\"100\",\"101\"],\"weathers\":[\"晴れ\",\"晴れ　時々　くもり\"]}]},{\"timeDefines\":[\"2026-10-08T18:00:00+09:00\",\"2026-10-09T00:00:00+09:00\"],\"areas\":[{\"area\":{\"name\":\"東京地方\",\"code\":\"130010\"},\"pops\":[\"0\",\"10\"]}]}]}]","model":"forecast","mode":"typescript","timestamps":false,"required":false} */}

<p>気象庁が公開している天気予報の JSON（東京都は <code>https://www.jma.go.jp/bosai/forecast/data/forecast/130000.json</code>）を、取得した予報をそのまま保存するコレクションの下書きに使う例です。2026 年 10 月 8 日 17 時発表分から、東京地方の 2 つの時系列を 2 時点ずつ残して短くしました（モデル名 <code>forecast</code>、TypeScript、timestamps オフ）：</p>
<pre><code>{`[{"publishingOffice":"気象庁","reportDatetime":"2026-10-08T17:00:00+09:00","timeSeries":[{"timeDefines":["2026-10-08T17:00:00+09:00","2026-10-09T00:00:00+09:00"],"areas":[{"area":{"name":"東京地方","code":"130010"},"weatherCodes":["100","101"],"weathers":["晴れ","晴れ　時々　くもり"]}]},{"timeDefines":["2026-10-08T18:00:00+09:00","2026-10-09T00:00:00+09:00"],"areas":[{"area":{"name":"東京地方","code":"130010"},"pops":["0","10"]}]}]}]`}</code></pre>
<p>出力：</p>
<pre><code>{`import mongoose, { Schema } from 'mongoose';

export interface IArea {
  name: string;
  code: string;
}

export interface IAreas {
  area: IArea;
  weatherCodes: string[];
  weathers: string[];
  pops: string[];
}

export interface ITimeSeries {
  timeDefines: string[];
  areas: IAreas[];
}

export interface IForecast {
  publishingOffice: string;
  reportDatetime: Date;
  timeSeries: ITimeSeries[];
}

const areaSchema = new Schema({
  name: { type: String },
  code: { type: String },
});

const areasSchema = new Schema({
  area: areaSchema,
  weatherCodes: [String],
  weathers: [String],
  pops: [String],
});

const timeSeriesSchema = new Schema({
  timeDefines: [String],
  areas: [areasSchema],
});

const forecastSchema = new Schema<IForecast>({
  publishingOffice: { type: String },
  reportDatetime: { type: Date },
  timeSeries: [timeSeriesSchema],
}, { timestamps: false });

export default mongoose.model<IForecast>('Forecast', forecastSchema);`}</code></pre>

{/* jtm-date: {"in":"2026-10-08T17:00:00+09:00","iso":"2026-10-08T08:00:00.000Z"} */}

<ul>
  <li>天気の時系列と降水確率（<code>pops</code>）の時系列は <code>areas</code> の形が違いますが、どちらも <code>timeSeries</code> の要素なので 1 つの <code>areasSchema</code> にまとめられ、<code>weatherCodes</code>・<code>weathers</code>・<code>pops</code> がすべて入ります。インターフェースではどれも必須の形なので、片方の時系列にしかないものには <code>?</code> を付けてください。</li>
  <li><code>reportDatetime</code> は <code>+09:00</code> 付きの ISO 日時なので <code>Date</code> になります。MongoDB の日付は時刻の一点だけを記録し、タイムゾーンを持ちません（<a href="https://mongoosejs.com/docs/tutorials/dates.html">Mongoose: Working With Dates</a>）。保存後に読むと <code>2026-10-08T08:00:00.000Z</code> になるので、日本時間で表示するときは表示側で変換します。</li>
  <li><code>timeDefines</code> は同じ形の日時ですが、配列の中なので <code>[String]</code> です。時刻で検索するなら <code>[Date]</code> に書き換えます。</li>
  <li>降水確率は <code>"10"</code> のように文字列で入っているので <code>[String]</code> です。数値として集計するなら、保存前に変換するか <code>[Number]</code> に変えて Mongoose に変換させます。</li>
</ul>

<h2>制限</h2>
<ul>
  <li><strong>Mixed は何でも受け入れます。</strong>サンプルの型がそろわず <code>Mixed</code> になったフィールドは型変換も検証もされず、中を変更したときは <code>markModified()</code> を呼ばないと Mongoose が保存しません。データが許すなら 1 つの型にしてください。</li>
  <li><strong>Date になる書き方は 1 つです。</strong><code>YYYY-MM-DDThh:mm:ss</code> で始まる文字列だけが <code>Date</code> になります。データベースから書き出した <code>2026-10-08 09:30:00</code> のような空白区切りは <code>String</code> のままです。</li>
  <li><strong>ルート配列はオブジェクトだけを見ます。</strong>スキーマはドキュメントを表すので、オブジェクトと並ぶ数値・文字列・null・配列はスキーマに入れず、何個あってどの JSON 型だったかをステータス行に出します（例：<code>ルート配列のうちオブジェクトでない 5 個の値はスキーマに入れていません（number × 2, string, null, array）。</code>）。すべてプリミティブならスキーマは作らず、コメント <code>{"// Array of primitives — no schema to generate"}</code> だけを出します。</li>
  <li><strong>パスにならないキー名が 3 つあります。</strong>Mongoose 9.10.3 はスキーマを作るときに <code>{"__proto__"}</code>・<code>constructor</code>・<code>prototype</code> というキーを読み飛ばします（<a href="https://github.com/Automattic/mongoose/blob/9.10.3/lib/schema.js">lib/schema.js</a>。プロトタイプ汚染対策）。出力にはこれらのキーも残し、<code>{"__proto__"}</code> はオブジェクトリテラルがプロトタイプとして扱わないよう <code>{'["__proto__"]'}</code> と書き、ステータス行にキー名を出します。保存する前にキー名を変えてください。</li>
  <li><strong>ObjectId・enum・インデックス・検証は作りません。</strong>24 文字の 16 進文字列も <code>String</code> です。<code>Schema.Types.ObjectId</code> と <code>ref</code>、<code>unique</code>、<code>enum</code>、<code>min</code>/<code>max</code> は自分で足してください。</li>
  <li><strong>日本語のキーは引用符付きで残ります。</strong><code>"住所"</code> のようにパスとしてはそのまま使えますが、スキーマ変数名は ASCII だけで作るため <code>fieldSchema</code> になります。わかる名前に付け替えてください。</li>
  <li><strong>型引数はルートスキーマだけです。</strong>サブスキーマの <code>new Schema()</code> には型引数がなく、「必須フィールド」がオフでもインターフェースのフィールドに <code>?</code> は付きません。Mongoose はインターフェースとスキーマが合っているか確かめないので、任意のフィールドには自分で <code>?</code> を付けます。</li>
</ul>
