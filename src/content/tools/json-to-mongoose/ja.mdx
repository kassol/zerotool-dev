<h2>型マッピング</h2>
<ul>
  <li><code>null</code> はどの型にも入るので推論では読み飛ばします。すべてのサンプルで <code>null</code> のフィールド → <code>mongoose.Schema.Types.Mixed</code></li>
  <li>サンプルごとに型が違うフィールド（数値と文字列、オブジェクトと文字列）→ <code>mongoose.Schema.Types.Mixed</code>。ISO 日時とほかの文字列が混ざる場合 → <code>String</code></li>
  <li>文字列 → <code>String</code></li>
  <li>数値 → <code>Number</code></li>
  <li>真偽値 → <code>Boolean</code></li>
  <li>プリミティブ配列 → <code>[String]</code> / <code>[Number]</code> / <code>[Boolean]</code></li>
  <li>オブジェクト配列 → <code>[subSchema]</code>（独立サブスキーマを生成）</li>
  <li>ネストオブジェクト → 独立スキーマ変数をインライン参照</li>
</ul>

<h2>例</h2>
<p>モデル名 <code>User</code>、以下のJSONを入力した場合：</p>
<pre><code>{`{"username": "alice", "age": 28, "tags": ["admin"], "address": {"city": "London"}}`}</code></pre>
<p>JavaScript出力（timestampsオン）：</p>
<pre><code>{`const mongoose = require('mongoose');\nconst { Schema } = mongoose;\n\nconst addressSchema = new Schema({\n  city: { type: String },\n});\n\nconst userSchema = new Schema({\n  username: { type: String },\n  age: { type: Number },\n  tags: [String],\n  address: addressSchema,\n}, { timestamps: true });\n\nmodule.exports = mongoose.model('User', userSchema);`}</code></pre>

<h2>例：すべてのサンプルで型を決める</h2>

{/* jtm-check: {"json":"[{\"code\":1,\"note\":null,\"seller\":{\"meta\":{\"x\":1}},\"buyer\":{\"meta\":{\"y\":\"2\"}}},{\"code\":\"A-2\",\"note\":\"gift\",\"tags\":[\"a\",1]}]","model":"Order","mode":"javascript","timestamps":false,"required":false} */}

<p>注文 2 件のルート配列、モデル名 <code>Order</code>、JavaScript、timestamps オフ：</p>
<pre><code>{`[{"code":1,"note":null,"seller":{"meta":{"x":1}},"buyer":{"meta":{"y":"2"}}},{"code":"A-2","note":"gift","tags":["a",1]}]`}</code></pre>

<p>出力：</p>
<pre><code>{`const mongoose = require('mongoose');
const { Schema } = mongoose;

const metaSchema = new Schema({
  x: { type: Number },
});

const sellerSchema = new Schema({
  meta: metaSchema,
});

const buyerMetaSchema = new Schema({
  y: { type: String },
});

const buyerSchema = new Schema({
  meta: buyerMetaSchema,
});

const orderSchema = new Schema({
  code: { type: mongoose.Schema.Types.Mixed },
  note: { type: String },
  seller: sellerSchema,
  buyer: buyerSchema,
  tags: [mongoose.Schema.Types.Mixed],
}, { timestamps: false });

module.exports = mongoose.model('Order', orderSchema);`}</code></pre>
<ul>
  <li><code>code</code> は 1 件目が <code>1</code>、2 件目が <code>"A-2"</code> なので <code>Mixed</code> です。<code>Number</code> だと <code>"A-2"</code> を拒否します。<code>note</code> は <code>null</code> と <code>"gift"</code> なので <code>String</code> です。<code>tags</code> は文字列と数値が混ざるので要素が <code>Mixed</code> です。</li>
  <li>2 つの <code>meta</code> はフィールドが違うので、2 つ目は親のキーを前に付けます（<code>buyerMetaSchema</code>）。同じキーでフィールドと型が同じオブジェクトは 1 つのスキーマを共有します。前置きしても名前が重なるときは番号を付けます。</li>
  <li><code>Mixed</code> のフィールドは型変換も検証もされず、中を変更したときは <code>markModified()</code> を呼ばないと Mongoose が保存しません。データが許すなら 1 つの型にしてください。</li>
</ul>
<p>ツールのテストでは、生成した JavaScript を Mongoose 9.10.3 で実行し、各サンプルからドキュメントを作って <code>validateSync()</code> が通ること、すべてのフィールドと値が残ることを確認しています（ISO 日時は <code>Date</code> になり、<code>toISOString()</code> の形で比較。サンプルにない配列フィールドは Mongoose の既定値 <code>[]</code> になります）。</p>
