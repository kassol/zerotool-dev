<h2>타입 매핑</h2>
<ul>
  <li><code>null</code>은 어떤 타입에도 들어가므로 추론에서 건너뜁니다. 모든 샘플에서 <code>null</code>인 필드 → <code>mongoose.Schema.Types.Mixed</code></li>
  <li>샘플마다 타입이 다른 필드(숫자와 문자열, 객체와 문자열) → <code>mongoose.Schema.Types.Mixed</code>. ISO 날짜·시간과 다른 문자열이 섞이면 → <code>String</code></li>
  <li>ISO 8601 날짜·시간으로 시작하는 문자열(<code>2026-10-01T09:30:00Z</code>) → <code>Date</code>. 날짜만 있는 <code>2026-10-01</code>, <code>T</code> 대신 공백을 넣은 <code>2026-10-01 09:30:00</code>, 배열 안의 날짜·시간은 <code>String</code>으로 남습니다</li>
  <li>문자열 → <code>String</code></li>
  <li>숫자 → <code>Number</code></li>
  <li>불리언 → <code>Boolean</code></li>
  <li>기본 타입 배열 → <code>[String]</code> / <code>[Number]</code> / <code>[Boolean]</code></li>
  <li>객체 배열 → <code>[subSchema]</code>(별도 서브스키마 생성)</li>
  <li>중첩 객체 → 별도 스키마 변수를 만들어 그 자리에서 참조</li>
</ul>

<h2>예시</h2>

{/* jtm-check: {"json":"{\"username\": \"alice\", \"age\": 28, \"tags\": [\"admin\"], \"address\": {\"city\": \"London\"}}","model":"User","mode":"javascript","timestamps":true,"required":false} */}

<p>모델 이름 <code>User</code>, 다음 JSON 입력 시:</p>
<pre><code>{`{"username": "alice", "age": 28, "tags": ["admin"], "address": {"city": "London"}}`}</code></pre>
<p>JavaScript 출력(timestamps 켜짐):</p>
<pre><code>{`const mongoose = require('mongoose');\nconst { Schema } = mongoose;\n\nconst addressSchema = new Schema({\n  city: { type: String },\n});\n\nconst userSchema = new Schema({\n  username: { type: String },\n  age: { type: Number },\n  tags: [String],\n  address: addressSchema,\n}, { timestamps: true });\n\nmodule.exports = mongoose.model('User', userSchema);`}</code></pre>

<h2>예시: 모든 샘플로 타입 결정</h2>

{/* jtm-check: {"json":"[{\"code\":1,\"note\":null,\"seller\":{\"meta\":{\"x\":1}},\"buyer\":{\"meta\":{\"y\":\"2\"}}},{\"code\":\"A-2\",\"note\":\"gift\",\"tags\":[\"a\",1]}]","model":"Order","mode":"javascript","timestamps":false,"required":false} */}

<p>주문 2건의 루트 배열, 모델 이름 <code>Order</code>, JavaScript, timestamps 끔:</p>
<pre><code>{`[{"code":1,"note":null,"seller":{"meta":{"x":1}},"buyer":{"meta":{"y":"2"}}},{"code":"A-2","note":"gift","tags":["a",1]}]`}</code></pre>

<p>출력:</p>
<pre><code>{`const mongoose = require('mongoose');
const { Schema } = mongoose;

const metaSchema = new Schema({
  x: { type: Number },
});

const sellerSchema = new Schema({
  meta: metaSchema,
});

const buyerMetaSchema = new Schema({
  y: { type: String },
});

const buyerSchema = new Schema({
  meta: buyerMetaSchema,
});

const orderSchema = new Schema({
  code: { type: mongoose.Schema.Types.Mixed },
  note: { type: String },
  seller: sellerSchema,
  buyer: buyerSchema,
  tags: [mongoose.Schema.Types.Mixed],
}, { timestamps: false });

module.exports = mongoose.model('Order', orderSchema);`}</code></pre>
<ul>
  <li><code>code</code>는 한 건이 <code>1</code>, 다른 건이 <code>"A-2"</code>라서 <code>Mixed</code>입니다. <code>Number</code>면 <code>"A-2"</code>를 거부합니다. <code>note</code>는 <code>null</code>과 <code>"gift"</code>라서 <code>String</code>입니다. <code>tags</code>는 문자열과 숫자가 섞여 요소가 <code>Mixed</code>입니다.</li>
  <li>두 <code>meta</code>는 필드가 달라서 두 번째에 부모 키를 앞에 붙입니다(<code>buyerMetaSchema</code>). 같은 키에서 필드와 타입이 같은 객체는 스키마 하나를 함께 씁니다. 앞에 붙여도 이름이 겹치면 번호를 붙입니다.</li>
</ul>
<p>도구 테스트는 생성된 JavaScript를 Mongoose 9.10.3으로 실행해 샘플마다 문서를 만들고, <code>validateSync()</code>가 통과하는지와 모든 필드·값이 남는지 확인합니다(ISO 날짜·시간은 <code>Date</code>가 되어 <code>toISOString()</code> 형태로 비교. 샘플에 없는 배열 필드는 Mongoose 기본값 <code>[]</code>가 됩니다).</p>

<h2>한글 키 주문 데이터와 한국 시간</h2>

{/* jtm-check: {"json":"{\"주문번호\":\"20261008-0001\",\"주문일시\":\"2026-10-08T09:30:00+09:00\",\"배송지\":{\"우편번호\":\"04524\",\"주소\":\"서울특별시 중구 세종대로 110\"},\"상품\":[{\"상품명\":\"무선 마우스\",\"수량\":1,\"가격\":29000},{\"상품명\":\"마우스 패드\",\"수량\":2,\"가격\":5000}]}","model":"order","mode":"javascript","timestamps":true,"required":true} */}

<p>쇼핑몰 관리자 페이지에서 내려받은 주문을 MongoDB로 그대로 옮길 때처럼, 키가 한글인 데이터의 예입니다. 모델 이름 <code>order</code>, JavaScript, timestamps 켜짐, 필수 필드 켜짐:</p>
<pre><code>{`{"주문번호":"20261008-0001","주문일시":"2026-10-08T09:30:00+09:00","배송지":{"우편번호":"04524","주소":"서울특별시 중구 세종대로 110"},"상품":[{"상품명":"무선 마우스","수량":1,"가격":29000},{"상품명":"마우스 패드","수량":2,"가격":5000}]}`}</code></pre>
<p>출력:</p>
<pre><code>{`const mongoose = require('mongoose');
const { Schema } = mongoose;

const fieldSchema = new Schema({
  "우편번호": { type: String, required: true },
  "주소": { type: String, required: true },
});

const orderFieldSchema = new Schema({
  "상품명": { type: String, required: true },
  "수량": { type: Number, required: true },
  "가격": { type: Number, required: true },
});

const orderSchema = new Schema({
  "주문번호": { type: String, required: true },
  "주문일시": { type: Date, required: true },
  "배송지": fieldSchema,
  "상품": [orderFieldSchema],
}, { timestamps: true });

module.exports = mongoose.model('Order', orderSchema);`}</code></pre>

{/* jtm-date: {"in":"2026-10-08T09:30:00+09:00","iso":"2026-10-08T00:30:00.000Z"} */}

<ul>
  <li>한글 키는 따옴표로 감싸 경로 이름 그대로 남기므로 생성된 파일은 바로 실행됩니다. 변수 이름은 ASCII로만 만들기 때문에 <code>배송지</code>의 서브스키마는 <code>fieldSchema</code>, 필드가 다른 <code>상품</code> 요소는 모델 이름을 앞에 붙여 <code>orderFieldSchema</code>가 됩니다. 커밋 전에 <code>shippingSchema</code>, <code>itemSchema</code>처럼 알아볼 수 있는 이름으로 바꾸세요.</li>
  <li>필수 필드를 켜도 <code>배송지</code>와 <code>상품</code> 자체에는 <code>required</code>가 붙지 않고, 그 안의 필드에만 붙습니다.</li>
  <li><code>주문일시</code>는 <code>+09:00</code>이 붙은 ISO 날짜·시간이라 <code>Date</code>입니다. MongoDB 날짜는 시각 하나만 기록하고 시간대를 저장하지 않으므로(<a href="https://mongoosejs.com/docs/tutorials/dates.html">Mongoose: Working With Dates</a>) 저장 후 읽으면 <code>2026-10-08T00:30:00.000Z</code>입니다. 한국 시간으로 보여 줄 때는 화면 쪽에서 변환합니다.</li>
  <li><code>우편번호</code> <code>04524</code>는 문자열이라 <code>String</code>이 되고 앞의 0이 남습니다. JSON 숫자는 앞자리에 0을 쓸 수 없으므로(<a href="https://www.rfc-editor.org/rfc/rfc8259#section-6">RFC 8259 6장</a>) 숫자로 내보내면 0이 이미 사라진 상태입니다.</li>
</ul>

{/* jtm-date: {"in":"20161208","iso":"1970-01-01T05:36:01.208Z"} */}

<p>네이버 검색 API처럼 날짜를 <code>20161208</code> 같은 8자리 숫자 문자열로 주는 응답(<a href="https://developers.naver.com/docs/serviceapi/search/blog/blog.md">블로그 검색 API</a>의 <code>postdate</code>)도 조심해야 합니다. 이 도구는 이런 값을 <code>String</code>으로 둡니다. 직접 <code>Date</code>로 바꾸면 Mongoose는 숫자로만 된 큰 문자열을 밀리초로 읽기 때문에(<a href="https://mongoosejs.com/docs/tutorials/dates.html">Casting Edge Cases</a>) 오류 없이 <code>1970-01-01T05:36:01.208Z</code>가 저장됩니다. 날짜로 다루려면 저장 전에 <code>2016-12-08</code> 형식으로 바꾸세요.</p>

<h2>제한</h2>
<ul>
  <li><strong>Mixed는 무엇이든 받습니다.</strong> 샘플 타입이 달라 <code>Mixed</code>가 된 필드는 타입 변환과 검증을 하지 않고, 내부를 바꾸면 <code>markModified()</code>를 호출해야 Mongoose가 저장합니다. 데이터가 허용하면 한 타입으로 맞추세요.</li>
  <li><strong>Date로 인식하는 형식은 하나입니다.</strong> <code>YYYY-MM-DDThh:mm:ss</code>로 시작해야 <code>Date</code>가 되고, <code>2026-10-08 09:30:00</code> 같은 공백 구분이나 날짜만 있는 값은 <code>String</code>입니다.</li>
  <li><strong>루트 배열은 객체만 봅니다.</strong> 스키마는 문서를 나타내므로 객체 옆의 숫자·문자열·null·배열은 스키마에 넣지 않고, 몇 개였고 어떤 JSON 타입이었는지 상태 표시줄에 알려 줍니다(예: <code>루트 배열에서 객체가 아닌 값 5개는 스키마에 넣지 않았습니다(number × 2, string, null, array).</code>). 모두 기본 타입이면 스키마를 만들지 않고 주석 <code>{"// Array of primitives — no schema to generate"}</code>만 출력합니다.</li>
  <li><strong>경로가 되지 않는 키 이름이 세 개 있습니다.</strong> Mongoose 9.10.3은 스키마를 만들 때 <code>{"__proto__"}</code>, <code>constructor</code>, <code>prototype</code>이라는 키를 건너뜁니다(<a href="https://github.com/Automattic/mongoose/blob/9.10.3/lib/schema.js">lib/schema.js</a>, 프로토타입 오염 방지). 출력에는 이 키들도 남기되 <code>{"__proto__"}</code>는 객체 리터럴이 프로토타입으로 처리하지 않도록 <code>{'["__proto__"]'}</code>로 쓰고, 상태 표시줄에 키 이름을 알려 줍니다. 저장하기 전에 키 이름을 바꾸세요.</li>
  <li><strong>ObjectId, enum, 인덱스, 검증은 만들지 않습니다.</strong> 24자리 16진수 문자열도 <code>String</code>입니다. <code>Schema.Types.ObjectId</code>와 <code>ref</code>, <code>unique</code>, <code>enum</code>, <code>min</code>/<code>max</code>는 직접 추가하세요.</li>
  <li><strong>타입 인수는 루트 스키마에만 붙습니다.</strong> 서브스키마의 <code>new Schema()</code>에는 타입 인수가 없고, 필수 필드를 꺼도 인터페이스 필드에 <code>?</code>가 붙지 않습니다. Mongoose는 인터페이스와 스키마가 맞는지 확인하지 않으므로 선택 필드에는 직접 <code>?</code>를 붙이세요.</li>
</ul>
