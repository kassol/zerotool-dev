<h2>Type Mapping</h2>
<ul>
  <li><code>null</code> fits any type and is skipped; a field that is <code>null</code> in every sample → <code>mongoose.Schema.Types.Mixed</code></li>
  <li>a field whose samples have different types (number and string, object and string) → <code>mongoose.Schema.Types.Mixed</code>; ISO date-times mixed with other strings → <code>String</code></li>
  <li>string that starts like an ISO 8601 date-time (<code>2026-10-01T09:30:00Z</code>) → <code>Date</code>; a plain date such as <code>2026-10-01</code>, a date-time with a space instead of <code>T</code> (<code>2026-10-01 09:30:00</code>) and date-times inside an array stay <code>String</code></li>
  <li>string → <code>String</code></li>
  <li>number → <code>Number</code></li>
  <li>boolean → <code>Boolean</code></li>
  <li>array of primitives → <code>[String]</code> / <code>[Number]</code> / <code>[Boolean]</code></li>
  <li>array of objects → <code>[subSchema]</code> (separate schema generated)</li>
  <li>nested object → separate schema variable referenced inline</li>
</ul>

<h2>Example</h2>

{/* jtm-check: {"json":"{\"username\": \"alice\", \"age\": 28, \"tags\": [\"admin\"], \"address\": {\"city\": \"London\"}}","model":"User","mode":"javascript","timestamps":true,"required":false} */}

<p>Given this JSON with model name <code>User</code>:</p>
<pre><code>{`{"username": "alice", "age": 28, "tags": ["admin"], "address": {"city": "London"}}`}</code></pre>
<p>JavaScript output (timestamps On):</p>
<pre><code>{`const mongoose = require('mongoose');\nconst { Schema } = mongoose;\n\nconst addressSchema = new Schema({\n  city: { type: String },\n});\n\nconst userSchema = new Schema({\n  username: { type: String },\n  age: { type: Number },\n  tags: [String],\n  address: addressSchema,\n}, { timestamps: true });\n\nmodule.exports = mongoose.model('User', userSchema);`}</code></pre>

<p>
  Sub-schemas are named after the key (<code>address</code> → <code>addressSchema</code>) and written before the schema that uses them,
  so the file runs top to bottom. The model name is converted to PascalCase for <code>mongoose.model()</code>; Mongoose then derives the
  collection name by lowercasing and pluralizing it (<code>User</code> → <code>users</code>).
</p>

<h2>Example: TypeScript With required On</h2>

{/* jtm-check: {"json":"{\"sku\":\"A-1\",\"price\":9.5,\"created_at\":\"2026-10-01T09:30:00Z\",\"release-date\":\"2026-10-01\",\n \"variants\":[{\"color\":\"red\",\"stock\":3},{\"color\":\"blue\",\"size\":\"M\"}],\"meta\":null}","model":"product","mode":"typescript","timestamps":true,"required":true} */}

<p>Model name <code>product</code>, TypeScript, timestamps On, required On:</p>
<pre><code>{`{"sku":"A-1","price":9.5,"created_at":"2026-10-01T09:30:00Z","release-date":"2026-10-01",
 "variants":[{"color":"red","stock":3},{"color":"blue","size":"M"}],"meta":null}`}</code></pre>
<pre><code>{`import mongoose, { Schema } from 'mongoose';

export interface IVariants {
  color: string;
  stock: number;
  size: string;
}

export interface IProduct {
  sku: string;
  price: number;
  created_at: Date;
  "release-date": string;
  variants: IVariants[];
  meta: any;
  createdAt: Date;
  updatedAt: Date;
}

const variantsSchema = new Schema({
  color: { type: String, required: true },
  stock: { type: Number, required: true },
  size: { type: String, required: true },
});

const productSchema = new Schema<IProduct>({
  sku: { type: String, required: true },
  price: { type: Number, required: true },
  created_at: { type: Date, required: true },
  "release-date": { type: String, required: true },
  variants: [variantsSchema],
  meta: { type: mongoose.Schema.Types.Mixed, required: true },
}, { timestamps: true });

export default mongoose.model<IProduct>('Product', productSchema);`}</code></pre>
<p>Two things to fix by hand before using it:</p>
<ul>
  <li><code>size</code> and <code>stock</code> each appear in only one variant, yet both are <code>required</code>. The array elements are merged into one sub-schema with every key, and the switch applies to all of them.</li>
  <li><code>meta</code> was <code>null</code>, so it is <code>Mixed</code> and <code>required</code>: Mongoose would reject the very document you pasted. Give it a real type or drop <code>required</code>.</li>
</ul>
<p>The interface is a plain document interface, passed as <code>{'Schema<IProduct>'}</code> and <code>{'mongoose.model<IProduct>'}</code>, as in the <a href="https://mongoosejs.com/docs/typescript.html">Mongoose TypeScript guide</a> ("Using Generics"); it does not extend <code>Document</code>. With timestamps On, Mongoose adds <code>createdAt</code> and <code>updatedAt</code> of type <code>Date</code> (<a href="https://mongoosejs.com/docs/timestamps.html">Timestamps</a>), so the interface lists both and <code>doc.createdAt</code> type-checks on a document from <code>new Product()</code> and on a <code>.lean()</code> result. <code>created_at</code> from the JSON is a separate field. If the JSON already has a <code>createdAt</code> or <code>updatedAt</code> key, its own type is kept, because Mongoose then keeps that path as you defined it. The tool's test compiles every generated TypeScript file with TypeScript 5.9.3 in strict mode against Mongoose 9.10.3.</p>
<p>Keys that are not JavaScript identifiers, such as <code>release-date</code>, are quoted so the generated file parses.</p>

<h2>Example: Every Sample Decides the Type</h2>

{/* jtm-check: {"json":"[{\"code\":1,\"note\":null,\"seller\":{\"meta\":{\"x\":1}},\"buyer\":{\"meta\":{\"y\":\"2\"}}},{\"code\":\"A-2\",\"note\":\"gift\",\"tags\":[\"a\",1]}]","model":"Order","mode":"javascript","timestamps":false,"required":false} */}

<p>A root array with two orders, model name <code>Order</code>, JavaScript, timestamps Off:</p>
<pre><code>{`[{"code":1,"note":null,"seller":{"meta":{"x":1}},"buyer":{"meta":{"y":"2"}}},{"code":"A-2","note":"gift","tags":["a",1]}]`}</code></pre>

<p>Output:</p>
<pre><code>{`const mongoose = require('mongoose');
const { Schema } = mongoose;

const metaSchema = new Schema({
  x: { type: Number },
});

const sellerSchema = new Schema({
  meta: metaSchema,
});

const buyerMetaSchema = new Schema({
  y: { type: String },
});

const buyerSchema = new Schema({
  meta: buyerMetaSchema,
});

const orderSchema = new Schema({
  code: { type: mongoose.Schema.Types.Mixed },
  note: { type: String },
  seller: sellerSchema,
  buyer: buyerSchema,
  tags: [mongoose.Schema.Types.Mixed],
}, { timestamps: false });

module.exports = mongoose.model('Order', orderSchema);`}</code></pre>
<ul>
  <li><code>code</code> is <code>1</code> in one order and <code>"A-2"</code> in the other, so it is <code>Mixed</code>; <code>Number</code> would reject <code>"A-2"</code>. <code>note</code> is <code>null</code> once and <code>"gift"</code> once, so it is <code>String</code>. <code>tags</code> mixes a string and a number, so its elements are <code>Mixed</code>.</li>
  <li>The two <code>meta</code> objects have different fields, so the second gets the parent key as a prefix (<code>buyerMetaSchema</code>). Objects under the same key with the same fields and types share one schema; if the prefixed name is taken too, a number is added.</li>
</ul>
<p>The tool's test runs each generated JavaScript file with Mongoose 9.10.3, builds a document from every sample, and checks that <code>validateSync()</code> passes and that every field and value comes back (ISO date-times come back as <code>Date</code>, in <code>toISOString()</code> form; an array path missing from a sample comes back as <code>[]</code>, Mongoose's default for arrays).</p>

<h2>Limits</h2>
<ul>
  <li><strong>Mixed accepts anything.</strong> A field typed <code>Mixed</code> because its samples disagree is not cast or validated, and Mongoose does not track changes inside it unless you call <code>markModified()</code>. Pick one type when the data allows it.</li>
  <li><strong>Only one date format becomes Date.</strong> A string must start with <code>YYYY-MM-DDThh:mm:ss</code>. A database export such as <code>2026-10-08 09:30:00</code> stays <code>String</code>. A value with an offset (<code>+08:00</code>) is stored as that instant in UTC; MongoDB keeps no time zone with a date (<a href="https://mongoosejs.com/docs/tutorials/dates.html">Mongoose: Working With Dates</a>).</li>
  <li><strong>Non-ASCII keys get placeholder schema names.</strong> Keys such as <code>收货地址</code> or <code>주소</code> are quoted and kept as paths, but the tool builds variable names from ASCII only, so the sub-schema becomes <code>fieldSchema</code>, and the next shape gets the parent prefix (<code>orderFieldSchema</code> with model name <code>order</code>). Rename them before you commit the file.</li>
  <li><strong>Only objects at the root.</strong> A schema describes documents, so in a root array the numbers, strings, null and arrays next to the objects are left out, and the status line says how many and which JSON types, for example <code>Skipped 5 root array values that are not objects (number × 2, string, null, array).</code></li>
  <li><strong>Reserved path names stay, with a warning.</strong> Mongoose 9.10.3 lists <code>collection</code>, <code>emit</code>, <code>errors</code>, <code>get</code>, <code>init</code>, <code>isModified</code>, <code>isNew</code>, <code>listeners</code>, <code>populated</code>, <code>remove</code>, <code>removeListener</code>, <code>save</code>, <code>toObject</code>, <code>validate</code> as reserved (<code>Schema.reserved</code> in <a href="https://github.com/Automattic/mongoose/blob/9.10.3/lib/schema.js">lib/schema.js</a>). Such a key stays a path and the value is stored, but Mongoose prints a warning, and on a document the field value replaces the method or property of the same name (<code>errors</code> and <code>isNew</code> are properties): with a field named <code>save</code>, <code>doc.save</code> is the value and <code>doc.save()</code> fails. The status line names these keys. The <code>suppressReservedKeysWarning</code> schema option only hides the warning, so the tool does not add it; rename the key instead.</li>
  <li><strong>Other document member names can break a document.</strong> Mongoose warns only about the reserved names, but a document has more members, and the status line names two groups of keys checked against Mongoose 9.10.3 documents. Mongoose calls the first group itself, so such a field can make building, validating or serializing a document fail, and the status line uses the warning color: with a field named <code>markModified</code>, <code>new Model()</code> throws <code>this.markModified is not a function</code>; <code>_doc</code> ends in <code>Maximum call stack size exceeded</code>; <code>schema</code> works while the input has only schema keys, then fails on any other key with <code>Cannot read properties of undefined (reading 'discriminatorKey')</code>; <code>toJSON</code> makes <code>JSON.stringify(doc)</code> print Mongoose's internal state (<code>$__</code>, <code>_doc</code>). This group is <code>_doc</code>, <code>__index</code>, <code>__parentArray</code>, <code>get</code>, <code>isDirectModified</code>, <code>markModified</code>, <code>modifiedPaths</code>, <code>schema</code>, <code>toBSON</code>, <code>toJSON</code>, <code>toObject</code> and <code>validateSync</code>, plus 29 names that start with <code>$</code> (<code>get</code> and <code>toObject</code> are also reserved). For 83 other names Mongoose shows no warning, and the field value only replaces the method or property: with fields named <code>model</code> and <code>set</code>, <code>doc.model</code> and <code>doc.set</code> are the field values. The tool's test rebuilds both groups from real Mongoose 9.10.3 documents. Rename such keys.</li>
  <li><strong>Three key names never become paths.</strong> Mongoose 9.10.3 skips schema keys named <code>{"__proto__"}</code>, <code>constructor</code> and <code>prototype</code> (<a href="https://github.com/Automattic/mongoose/blob/9.10.3/lib/schema.js">lib/schema.js</a>, to avoid prototype pollution). The output still lists them, with <code>{"__proto__"}</code> written as <code>{'["__proto__"]'}</code> so the object literal does not set its prototype, and the status line names them; rename these keys before you store such data.</li>
  <li><strong>The model name is a string.</strong> It goes into <code>mongoose.model()</code> in PascalCase with quotes and backslashes escaped (<code>{"it's"}</code> → <code>{"'It\\'s'"}</code>); variable and interface names use only ASCII letters, digits, <code>_</code> and <code>$</code>.</li>
  <li><strong>No ObjectId, enum, index or validation.</strong> A 24-character hex string stays <code>String</code>; add <code>Schema.Types.ObjectId</code> and <code>ref</code>, <code>unique</code>, <code>enum</code> or <code>min</code>/<code>max</code> yourself.</li>
  <li><strong>Only the root schema is typed.</strong> Sub-schemas get an interface for the root interface to use, but <code>new Schema()</code> for them has no type argument, and fields are not optional even when <code>required</code> is Off. Mongoose does not check that the interface matches the schema (TypeScript guide), so mark optional fields with <code>?</code> yourself.</li>
  <li><strong>A root array of primitives</strong> such as <code>["a", "b"]</code> generates no schema, only the comment <code>{"// Array of primitives — no schema to generate"}</code>.</li>
</ul>
