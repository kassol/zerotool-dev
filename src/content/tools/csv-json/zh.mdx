## 从订单导出到 JSON

下面是一段常见的电商订单导出。订单号是 19 位，手机号是 11 位，第二行的金额带千分位逗号、加了引号：

{/* cj-check: {"to":"json"} */}

```csv
订单号,收货人,手机号,金额,已付款
1830000000000000001,张伟,13800138000,128.50,TRUE
1830000000000000002,李娜,13912345678,"1,299.00",FALSE
```

```json
[
  {
    "订单号": "1830000000000000001",
    "收货人": "张伟",
    "手机号": 13800138000,
    "金额": 128.5,
    "已付款": true
  },
  {
    "订单号": "1830000000000000002",
    "收货人": "李娜",
    "手机号": 13912345678,
    "金额": "1,299.00",
    "已付款": false
  }
]
```

逐项看结果：

- 订单号超出 JavaScript 能精确表示的整数范围（2^53 − 1，约 9 千万亿），工具不把它转成数字，保留为字符串，19 位一位不少。写成指数形式的大整数也一样：`1e21` 保留为字符串 `"1e21"`；长订单号如果已经被表格软件写成 `1.83E+18`，也保留为文本，不会变成看似完整的 `1830000000000000000`。
- 手机号在安全范围内，又没有前导零，会变成 JSON 数字。接收方如果按字符串读取手机号，请取消勾选「推断数字和布尔值」，或在 CSV 里给这一列加引号。
- `128.50` 变成 `128.5`，末尾的 0 不保留；`"1,299.00"` 加了引号，原样保留为字符串。
- `TRUE`、`FALSE` 不区分大小写，转成 JSON 的 `true`、`false`。

## 空字段转成 null

下面这份 CSV 里，Bob 没有 email，第 3 行没有 name。默认情况下空字段转成 `""`，勾选「空字段 → null」后：

{/* cj-check: {"to":"json","emptyNull":true} */}

```csv
id,name,email
1,Alice,alice@example.com
2,Bob,
3,,charlie@example.com
```

```json
[
  {
    "id": 1,
    "name": "Alice",
    "email": "alice@example.com"
  },
  {
    "id": 2,
    "name": "Bob",
    "email": null
  },
  {
    "id": 3,
    "name": null,
    "email": "charlie@example.com"
  }
]
```

加了引号的空字段（`""`）不受这个选项影响，仍是空字符串。

## 全角逗号不是分隔符

用中文输入法录入时，很容易打出全角逗号：

{/* cj-check: {"to":"json"} */}

```csv
姓名，部门
王芳，研发
```

```json
[
  {
    "姓名，部门": "王芳，研发"
  }
]
```

整行成了一个键和一个值。分号、制表符同理：从表格软件里直接复制出来的单元格是制表符分隔的，也会变成一列。

## JSON 转 CSV

后端接口返回的订单常带嵌套对象和数组。下面的订单号是 19 位的雪花算法 ID（[MyBatis-Plus](https://baomidou.com/reference/annotation/) 的主键策略 `IdType.ASSIGN_ID` 默认用雪花算法生成 ID）：

{/* cj-check: {"to":"csv"} */}

```json
[
  { "订单号": 1830000000000000001, "收货人": "张伟", "收货地址": { "省": "浙江省", "市": "杭州市" }, "商品": ["键盘", "鼠标"] },
  { "订单号": 1830000000000000002, "收货人": "李娜", "收货地址": { "省": "广东省", "市": "深圳市" }, "商品": [] }
]
```

```csv
订单号,收货人,收货地址.省,收货地址.市,商品
1830000000000000001,张伟,浙江省,杭州市,"[""键盘"",""鼠标""]"
1830000000000000002,李娜,广东省,深圳市,[]
```

嵌套的收货地址展开成 `收货地址.省`、`收货地址.市` 两列（与 pandas [`json_normalize`](https://pandas.pydata.org/docs/reference/api/pandas.json_normalize.html) 的列名规则相同），数组写成 JSON 文本，字段里的双引号按 CSV 规则写成两个。

两行的订单号都超过了 2^53 − 1。浏览器自带的 `JSON.parse` 会把它们舍入成同一个 `1830000000000000000`；本工具在支持 `JSON.rawJSON` 的浏览器（Chrome 114、Firefox 135、Safari 18.4 及以后）里按 JSON 原文写出，所以 CSV 里仍是两个不同的订单号。更旧的浏览器会把这类数字按文本写出（数组单元格里会带引号），并在状态栏列出这些数字，不会写出舍入后的值。

## 支持的 CSV 格式

本工具遵循 RFC 4180 的引号规则：字段以逗号分隔；字段里有逗号、换行或双引号时，要用双引号包住整个字段，字段内的双引号写成两个（`""`）。第一行固定当作表头；表头重名时依次加 `_2`、`_3`，超出表头的字段用 `column_N` 作键，两种情况都会在状态栏说明。

## 限制

- **只认半角逗号。** 制表符、分号、全角逗号都不是分隔符。
- **只有字段开头的双引号算引号。** 没加引号的字段里出现的 `"` 是普通字符，`5" 管,x` 就是 `5" 管` 和 `x` 两个字段。引号字段一直没有闭合时，转换会停止并报出引号开始的行号，JSON 面板保持为空：

{/* cj-check: {"to":"json","error":true} */}

```csv
商品,价格
"无线鼠标,99
键盘,199
```

  状态栏显示 `错误：第 2 行开始的引号字段没有闭合。请补上结尾的 "，或删掉开头的 "。`
- **只有 JSON 写法的数字才转成数字。** 按 [RFC 8259 第 6 节](https://www.rfc-editor.org/rfc/rfc8259#section-6)的数字语法（可带负号、不能有前导零和 `+`、小数点两边都要有数字），而且 JavaScript 的数字能原样保存时才转换。电话区号就是常见的例子：

{/* cj-check: {"to":"json"} */}

```csv
地区,区号
中国大陆,+86
香港,+852
```

```json
[
  {
    "地区": "中国大陆",
    "区号": "+86"
  },
  {
    "地区": "香港",
    "区号": "+852"
  }
]
```

  `+86` 不是 JSON 数字写法，保持字符串。同理，`.5`、`-0`、会下溢成 0 的 `1e-400` 和有效数字太多的长小数也都保留原文。
- **大数字按原文写出**，见上面的订单号示例；`1e-400`、`-0` 这类 JavaScript 无法原样保留的数字也一样。JavaScript 能精确保存的数字则按 JavaScript 的写法写出（[ECMA-262 Number::toString](https://tc39.es/ecma262/#sec-numeric-types-number-tostring)）：`128.50` 写成 `128.5`，`1e21` 写成 `1e+21`。把这份 CSV 再转回 JSON，得到 `128.5` 和字符串 `"1e+21"`，因为超过 2^53 − 1 的整数保持为文本：

{/* cj-check: {"to":"csv"} */}

```json
[{ "金额": 128.50, "浏览量": 1e21 }]
```

```csv
金额,浏览量
128.5,1e+21
```
- **表头里的空格会留在键名里。** [RFC 4180 第 2 节](https://www.rfc-editor.org/rfc/rfc4180#section-2)把空格算作字段的一部分，所以 `姓名, 城市` 的第二个键是 `" 城市"`，值 `" 北京"` 也带着空格。开头或结尾有空白（含全角空格）的表头名会列在状态栏里；不需要这些空格时，请在源数据里删掉：

{/* cj-check: {"to":"json","status":true} */}

```csv
姓名, 城市
张三, 北京
```

```json
[
  {
    "姓名": "张三",
    " 城市": " 北京"
  }
]
```

  状态栏显示 `已将 1 行转换为 JSON。 这些表头名开头或结尾有空白，空白会留在键名里：" 城市"。`
- **键的顺序。** 像整数的键（如 `2023`）会排在其他键前面，两个方向都是这样，值本身不受影响。
- **不处理编码。** 工具只处理粘贴进来的文本。用 GBK 等编码保存的 CSV，如果在编辑器里打开时已经是乱码，粘贴进来仍是乱码，请先用正确的编码打开文件。
- **JSON 语法错误**会停止转换并清空 CSV 面板，状态栏写出出错的行、列和原因，行列从 JSON 面板开头算起。例如键名后面混入了全角冒号：

{/* cj-check: {"to":"csv","error":true} */}

```json
[{"姓名"："张三","城市":"北京"}]
```

  状态栏显示 `这不是有效的 JSON：第 1 行第 7 列，全角字符 ：；JSON 的标点和空格必须是半角。`
