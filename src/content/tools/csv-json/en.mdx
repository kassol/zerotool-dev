<h2>Worked Examples</h2>

<h3>Simple table</h3>

With the default options, unquoted numbers become JSON numbers and the rest stays text:

{/* cj-check: {"to":"json"} */}

```csv
name,age,city
Alice,30,London
Bob,25,Paris
```

```json
[
  {
    "name": "Alice",
    "age": 30,
    "city": "London"
  },
  {
    "name": "Bob",
    "age": 25,
    "city": "Paris"
  }
]
```

<h3>Repeated header and an extra field</h3>

A product export where two columns are both called `sku` and one row carries a fourth value:

{/* cj-check: {"to":"json","status":true} */}

```csv
sku,sku,qty
A-1,A-1-RED,3,boxed
```

```json
[
  {
    "sku": "A-1",
    "sku_2": "A-1-RED",
    "qty": 3,
    "column_4": "boxed"
  }
]
```

The status line reads `Converted 1 row to JSON. Duplicate header names were renamed: sku → sku_2. Some rows have more fields than the header, so these keys were added: column_4.` Rename the columns in your source if you want other key names.

<h3>Quoted fields with commas</h3>
<p>Input CSV:</p>
<pre><code>product,description,price
Widget,"Small, round widget",9.99
Gadget,"Includes ""turbo"" mode",24.50</code></pre>
<p>The <code>description</code> field contains a comma and escaped quotes — both are handled correctly. The price <code>24.50</code> becomes the JSON number <code>24.5</code>.</p>

<h2>Supported CSV Format</h2>
<p>
  This tool follows the quoting rules of <strong>RFC 4180</strong>. Fields are separated by commas.
  If a field contains a comma, newline, or double-quote, it must be enclosed in double quotes.
  A literal double-quote inside a quoted field is escaped as two consecutive double-quotes (<code>""</code>).
  The first row is always interpreted as column headers.
</p>

## Edge Cases: What This Converter Does

**Empty fields.** In this CSV, Bob has no email and row 3 has no name. By default an empty field becomes `""`. With **Empty → null** ticked:

{/* cj-check: {"to":"json","emptyNull":true} */}

```csv
id,name,email
1,Alice,alice@example.com
2,Bob,
3,,charlie@example.com
```

```json
[
  {
    "id": 1,
    "name": "Alice",
    "email": "alice@example.com"
  },
  {
    "id": 2,
    "name": "Bob",
    "email": null
  },
  {
    "id": 3,
    "name": null,
    "email": "charlie@example.com"
  }
]
```

**Type inference.** With **Parse numbers & booleans** ticked (the default), unquoted `true`, `false`, and `null` (any case) become JSON literals. A value becomes a JSON number only when it is written in the JSON number syntax of [RFC 8259 §6](https://www.rfc-editor.org/rfc/rfc8259#section-6) (an optional minus, no leading zeros, no `+`, digits on both sides of a decimal point) and a JavaScript number keeps it exactly. Everything else stays a string so that nothing is lost: quoted fields (`"42"`), `007`, `+44`, `.5`, integers above 2^53 − 1 such as long order IDs, and values a double cannot hold (`-0`, `1e-400`, decimals with more than about 17 significant digits):

{/* cj-check: {"to":"json"} */}

```csv
code,value
plus,+44
zero,007
dot,.5
exp,1e3
negzero,-0
tiny,1e-400
```

```json
[
  {
    "code": "plus",
    "value": "+44"
  },
  {
    "code": "zero",
    "value": "007"
  },
  {
    "code": "dot",
    "value": ".5"
  },
  {
    "code": "exp",
    "value": 1000
  },
  {
    "code": "negzero",
    "value": "-0"
  },
  {
    "code": "tiny",
    "value": "1e-400"
  }
]
```

`1e3` is valid JSON number syntax and becomes `1000`; `1.50` would become `1.5`, because a JSON number has no trailing-zero form.

**Header row.** The first row is always the header. A CSV without one needs a header line added before converting. A repeated name gets a suffix (`sku_2`); a field beyond the last header gets the key `column_N` by position; missing trailing fields are treated as empty.

**JSON → CSV.** The input must be an array of objects. The columns are every key that appears in any object, in the order the keys first appear; a row without a key gets an empty field. Nested objects are flattened into dot-path columns such as `user.name` (the same layout as pandas [`json_normalize`](https://pandas.pydata.org/docs/reference/api/pandas.json_normalize.html)), arrays and empty objects are written as JSON text, and `null` becomes an empty field:

{/* cj-check: {"to":"csv"} */}

```json
[
  { "id": 1, "user": { "name": "Alice", "city": "London" }, "tags": ["admin", "ops"], "manager": null },
  { "id": 2, "user": { "name": "Bob" } }
]
```

```csv
id,user.name,user.city,tags,manager
1,Alice,London,"[""admin"",""ops""]",
2,Bob,,,
```

Converting that CSV back to JSON does not rebuild the nesting: `user.name` stays a flat key and the array stays a string.

## Limits

- **Commas only.** Tabs and semicolons are not separators. Tab-separated text, such as cells copied from a spreadsheet, becomes one field per line under a single long key.
- **Quotes count only at the start of a field.** A `"` inside an unquoted field is text, so `5" pipe,x` gives the two fields `5" pipe` and `x`. A quoted field that is never closed stops the conversion with an error that names the line where it starts, and the JSON pane stays empty:

{/* cj-check: {"to":"json","error":true} */}

```csv
name,price
"Gadget, large,24.99
Widget,9.99
```

  The status line reads `Error: A quoted field that starts on line 2 is never closed. Add the closing " or remove the opening one.`
- **No other number formats.** Thousands separators, `+` signs, spaces around a number and full-width digits keep the value a string; remove them in the source if you need numbers.
- **Large JSON numbers keep their digits.** A JSON number that a JavaScript number cannot hold exactly, such as `12345678901234567890`, `1e-400` or `-0`, is written to the CSV as it appears in the JSON. This needs `JSON.rawJSON`, which Chrome 114, Firefox 135 and Safari 18.4 and later have. An older browser writes such a number as text (inside an array cell it gets quotes, `"12345678901234567890"`), and the status line lists those numbers. No number is written rounded.
- **Key order.** JavaScript lists keys that look like whole numbers (`2024`) before the other keys, in both directions. The values are not affected.
- **JSON syntax errors** are shown with the browser's own message, which is in English.
