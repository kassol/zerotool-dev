<h2>Supported CSV Format</h2>
<p>
  This tool follows the <strong>RFC 4180</strong> standard. Fields are separated by commas.
  If a field contains a comma, newline, or double-quote, it must be enclosed in double quotes.
  A literal double-quote inside a quoted field is escaped as two consecutive double-quotes (<code>""</code>).
  The first row is always interpreted as column headers.
</p>

## Edge Cases: What This Converter Does

**Empty fields.** In this CSV, Bob has no email and row 3 has no name:

```csv
id,name,email
1,Alice,alice@example.com
2,Bob,
3,,charlie@example.com
```

By default an empty field becomes `""`. Tick **Empty → null** to get `null` instead:

```json
[
  { "id": 1, "name": "Alice", "email": "alice@example.com" },
  { "id": 2, "name": "Bob", "email": null },
  { "id": 3, "name": null, "email": "charlie@example.com" }
]
```

**Type inference.** With **Parse numbers & booleans** ticked (the default), unquoted `true`, `false`, and `null` (any case) become JSON literals and numbers become JSON numbers. Three kinds of values stay strings so that nothing is lost: quoted fields (`"42"`), values with a leading zero (`007`, `0123`), and integers too large for a JavaScript number (above 2^53 − 1), such as long order IDs.

**Header row.** The first row is always the header. A CSV without one needs a header line added before converting. If two columns share a name, the later column overwrites the earlier one in each object, so rename duplicates first. Fields beyond the last header are dropped; missing trailing fields are treated as empty.

**Delimiter.** Only commas are recognized. Convert semicolon- or tab-separated files to commas first.

**JSON → CSV.** The input must be an array of objects. The columns are every key that appears in any object, in the order the keys first appear; a row without a key gets an empty field. Nested objects are flattened into dot-path columns such as `user.name` (the same layout as pandas [`json_normalize`](https://pandas.pydata.org/docs/reference/api/pandas.json_normalize.html)), arrays and empty objects are written as JSON text, and `null` becomes an empty field:

```json
[
  { "id": 1, "user": { "name": "Alice", "city": "London" }, "tags": ["admin", "ops"], "manager": null },
  { "id": 2, "user": { "name": "Bob" } }
]
```

```csv
id,user.name,user.city,tags,manager
1,Alice,London,"[""admin"",""ops""]",
2,Bob,,,
```

Converting that CSV back to JSON does not rebuild the nesting: `user.name` stays a flat key and the array stays a string.
