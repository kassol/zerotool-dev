<h2>Type Inference Rules</h2>
<ul>
  <li><code>null</code> on an object property → optional <code>null</code> (<code>field?: null</code>); in an array of objects, a key that is <code>null</code> in every item stays required (<code>field: null</code>)</li>
  <li>string → <code>string</code></li>
  <li>number → <code>number</code></li>
  <li>boolean → <code>boolean</code></li>
  <li>empty array → <code>unknown[]</code></li>
  <li>array of objects → merged interface + <code>ItemName[]</code></li>
  <li>array of mixed primitives → union, e.g. <code>(string | number)[]</code></li>
  <li>nested object → separate named interface</li>
</ul>

<p>Given this JSON:</p>
<pre><code>{`{"user": {"name": "Alice", "age": 30}, "tags": ["admin", "user"]}`}</code></pre>
<p>The tool generates:</p>
<pre><code>{`interface RootObject {\n  user: User;\n  tags: string[];\n}\n\ninterface User {\n  name: string;\n  age: number;\n}`}</code></pre>

## Example: An API Response

{/* jtt-check: {"root":"RootObject"} */}

```json
{
  "user": {
    "id": 42,
    "name": "Alice",
    "email": "alice@example.com",
    "roles": ["admin", "editor"],
    "preferences": { "theme": "dark", "notifications": true },
    "lastLogin": null
  },
  "pagination": { "page": 1, "perPage": 20, "total": 143 }
}
```

generates

```typescript
interface RootObject {
  user: User;
  pagination: Pagination;
}

interface User {
  id: number;
  name: string;
  email: string;
  roles: string[];
  preferences: Preferences;
  lastLogin?: null;
}

interface Preferences {
  theme: string;
  notifications: boolean;
}

interface Pagination {
  page: number;
  perPage: number;
  total: number;
}
```

The root interface comes first, then each nested interface in the order it is found. A `null` value is typed `null` and marked optional, because one sample cannot show what the field holds when it is set. After checking the API docs, change it to something like `lastLogin: string | null`.

## Example: Arrays With Different Shapes

{/* jtt-check: {"root":"RootObject"} */}

```json
{
  "items": [
    { "id": 1, "name": "a", "tags": [] },
    { "id": 2, "price": 9.5, "tags": ["x", 1] }
  ],
  "messages": [
    { "type": "text", "content": "hi" },
    { "type": "image", "url": "/a.png" }
  ]
}
```

generates

```typescript
interface RootObject {
  items: ItemsItem[];
  messages: MessagesItem[];
}

interface ItemsItem {
  id: number;
  name?: string;
  tags: (unknown[] | (string | number)[]);
  price?: number;
}

interface MessagesItem {
  type: string;
  content?: string;
  url?: string;
}
```

All objects in an array are merged: a key that is missing from some elements gets `?`. The `messages` array is really two shapes keyed by `type`. The merged interface accepts invalid mixes such as a text message with a `url`, so rewrite it as a discriminated union ([TypeScript Handbook: Narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions)):

```typescript
type Message =
  | { type: "text"; content: string }
  | { type: "image"; url: string };
```

## Example: Two Objects Under the Same Key

{/* jtt-check: {"root":"RootObject"} */}

```json
{
  "order": { "id": "A-1001", "meta": { "createdBy": "alice", "source": "web" } },
  "payment": { "status": "paid", "meta": { "provider": "stripe", "fee": 0.3 } }
}
```

generates

```typescript
interface RootObject {
  order: Order;
  payment: Payment;
}

interface Order {
  id: string;
  meta: Meta;
}

interface Meta {
  createdBy: string;
  source: string;
}

interface Payment {
  status: string;
  meta: PaymentMeta;
}

interface PaymentMeta {
  provider: string;
  fee: number;
}
```

`order.meta` takes the name `Meta`. `payment.meta` has different fields, so it gets its own interface, named with its parent in front: `PaymentMeta`. If it had the same fields as `order.meta`, both would share `Meta`. Merging the two into one `Meta` with every field optional would accept objects that neither API returns, so each shape keeps its own type. If the name is still taken, a number is added (`Meta2`). The root keeps the name you chose even when a nested key has the same name.

## What to Refine by Hand

- `null` fields: replace `?: null` with the real type plus `| null`.
- Empty arrays: `[]` gives `unknown[]`; supply the element type.
- Dates: ISO 8601 strings and Unix timestamps stay `string` and `number`.
- Keys that are not valid identifiers (`user-name`, `2fa`) are written in quotes, which is valid TypeScript.
- Generated names such as `PaymentMeta` or `Meta2` come from the JSON keys; rename them to match your domain.
- A key that gives no valid type name (`2fa`, an empty key) gets a `T` prefix for its interface (`T2fa`); the property itself keeps the original key in quotes.

## Limits

- {/* jtt-error: {"input":"{\"a\":1,}"} */}The input must be valid JSON (no comments or trailing commas). When it is not, the output is cleared and the status line gives the line, the column and the likely cause, counted in the input as you typed it: `{"a":1,}` gives `Invalid JSON: line 1, column 7, trailing comma before the closing bracket.` {/* jtt-error: {"input":"{'id': 7}"} */}A Python dict pasted as is, `{'id': 7}`, gives `Invalid JSON: line 1, column 2, JSON strings and property names need double quotes (").`
- A root array that mixes objects with other values, such as `[{"id": 1}, "x", null]`, gives the objects one interface named after the root and adds an alias for the whole array, written like a nested array: `type RootObjectArray = (string | null | RootObject)[];`. Use `RootObjectArray` for the response.
- The root name keeps Unicode letters, digits, `$` and `_` (the ECMAScript identifier rules). Other characters are removed and the next letter is capitalized (`user profile` gives `userProfile`), a name that cannot start an identifier gets a `T` prefix (`2fa` gives `T2fa`), and a reserved word or a primitive type name gets a `_` suffix (`class` gives `class_`). A name with nothing left uses RootObject.
- A name that TypeScript's standard library (`lib.dom.d.ts` and the `lib.es*.d.ts` files) already uses for a one-word global type, such as `Promise`, `Date`, `Map`, `Record`, `Body`, `Response`, `Event`, `JSON` or `URL`, is not used as is: in a file without `import` or `export` such a declaration merges with the global type, and in a module it hides the global type. A nested object gets its parent's name in front (`{"date": {"year": 2026}}` gives `RootObjectDate`, and a `"URL"` key gives `RootObjectURL`; a `"url"` key gives `Url`, which is not a global type), and a root name gets `_` (`Map` gives `Map_`). The root name `globalThis` gets `_` as well (`globalThis_`): TypeScript rejects a declaration with that name in a file without `import` or `export`. Names that exist only as global values, such as `Image`, `Intl` or `Proxy`, are kept, because an interface or a type alias of the same name does not conflict with them.
- Global types whose names have more than one word, such as `FormData` from a `formData` key, keep the generated name; rename the interface if you paste it into a file without `import` or `export`, or into a module that also uses that global type.
- Very deep nesting can exceed the browser's call stack. The status line then shows the error and the previous output is cleared.
- Integers larger than 9007199254740991 (`Number.MAX_SAFE_INTEGER`) are read by `JSON.parse` and lose digits, and the type is `number`. If an API sends such IDs, ask for them as strings and type them as `string`.
- Types come only from the sample you paste. A field that is a string in your sample but sometimes a number in production stays `string`.
- With **Use type instead of interface**, each declaration is written as `type Name = { ... }`; the status line still says "interfaces".
