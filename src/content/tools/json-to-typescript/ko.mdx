## 예시: 카카오 로컬 API 키워드 장소 검색 응답

[카카오 로컬 API 개발 가이드](https://developers.kakao.com/docs/latest/ko/local/dev-guide)의 ‘키워드로 장소 검색’ 응답 예제에서 문서 하나만 남겨 붙여 넣고, 루트 인터페이스 이름을 `KeywordSearchResponse`로 지정합니다.

{/* jtt-check: {"root":"KeywordSearchResponse"} */}

```json
{
  "meta": {
    "same_name": {
      "region": [],
      "keyword": "카카오프렌즈",
      "selected_region": ""
    },
    "pageable_count": 14,
    "total_count": 14,
    "is_end": true
  },
  "documents": [
    {
      "place_name": "카카오프렌즈 코엑스점",
      "distance": "418",
      "place_url": "http://place.map.kakao.com/26338954",
      "category_name": "가정,생활 > 문구,사무용품 > 디자인문구 > 카카오프렌즈",
      "address_name": "서울 강남구 삼성동 159",
      "road_address_name": "서울 강남구 영동대로 513",
      "id": "26338954",
      "phone": "02-6002-1880",
      "category_group_code": "",
      "category_group_name": "",
      "x": "127.05902969025047",
      "y": "37.51207412593136"
    }
  ]
}
```

생성 결과:

```typescript
interface KeywordSearchResponse {
  meta: Meta;
  documents: DocumentsItem[];
}

interface Meta {
  same_name: Same_name;
  pageable_count: number;
  total_count: number;
  is_end: boolean;
}

interface Same_name {
  region: unknown[];
  keyword: string;
  selected_region: string;
}

interface DocumentsItem {
  place_name: string;
  distance: string;
  place_url: string;
  category_name: string;
  address_name: string;
  road_address_name: string;
  id: string;
  phone: string;
  category_group_code: string;
  category_group_name: string;
  x: string;
  y: string;
}
```

결과를 문서의 응답 표와 맞춰 보면 고칠 곳이 보입니다.

- `x`, `y`, `distance`는 숫자처럼 보여도 문서에서 String으로 정의되어 있고 JSON에서도 문자열이므로 `string`이 맞습니다. 거리를 비교하거나 계산하려면 `Number()`로 바꿔야 합니다.
- `region`은 예제에서 빈 배열이라 `unknown[]`이 되었습니다. 문서의 타입은 String[]이므로 `string[]`로 고칩니다.
- `same_name` 키에서 만든 이름은 `Same_name`입니다. 밑줄 뒤의 글자는 대문자가 되지 않으므로, 문서처럼 `SameName`으로 바꾸면 읽기 쉽습니다.

## 예시: 두 응답의 meta 합치기

같은 문서의 ‘카테고리로 장소 검색’ 응답 예제에서는 `same_name`이 `null`입니다. 키워드 검색 하나만 보고 만든 타입으로는 이 응답을 받을 수 없습니다. 두 응답의 `meta`를 배열에 넣어 붙여 넣으면 요소들이 합쳐지고, 요소 하나의 타입이 루트 이름(`Meta`)으로 출력됩니다.

{/* jtt-check: {"root":"Meta"} */}

```json
[
  {"same_name": {"region": [], "keyword": "카카오프렌즈", "selected_region": ""}, "pageable_count": 14, "total_count": 14, "is_end": true},
  {"same_name": null, "pageable_count": 11, "total_count": 11, "is_end": true}
]
```

생성 결과:

```typescript
interface Meta {
  same_name: (null | Same_name);
  pageable_count: number;
  total_count: number;
  is_end: boolean;
}

interface Same_name {
  region: unknown[];
  keyword: string;
  selected_region: string;
}
```

`same_name`이 `null`과 객체의 유니언 타입이 되어 두 응답을 모두 받습니다. 키가 모든 요소에 있으므로 `?`는 붙지 않습니다.

## 예시: 한글 키

사내 시스템이나 엑셀에서 변환한 JSON은 한글 키를 쓰기도 합니다. 루트 이름을 `회원`으로 지정하면:

{/* jtt-check: {"root":"회원"} */}

```json
{"이름":"홍길동","연락처":{"휴대전화":"010-1234-5678","이메일":"hong@example.com"},"관심분야":["개발","디자인"]}
```

생성 결과:

```typescript
interface 회원 {
  "이름": string;
  "연락처": 연락처;
  "관심분야": string[];
}

interface 연락처 {
  "휴대전화": string;
  "이메일": string;
}
```

속성 이름은 따옴표로 감싸고(도구는 ASCII 영문자, 숫자, `_`, `$`로만 된 키만 식별자로 봅니다), 인터페이스 이름은 한글 그대로 씁니다. 둘 다 TypeScript에서 유효합니다. 휴대전화 번호는 앞자리 0이 있으므로 문자열로 두어야 합니다.

## 직접 다듬을 부분

- 객체 속성의 `null`은 `?: null`이 되고, 객체 배열의 모든 요소에서 `null`인 키는 `?` 없이 `null`이 됩니다. 문서를 확인해 `string | null` 같은 실제 타입으로 바꿉니다.
- 숫자는 정수와 소수를 구분하지 않고 `number`입니다.
- 날짜: ISO 8601 문자열과 Unix 타임스탬프는 각각 `string`, `number`로 남습니다.
- 같은 키 이름에 필드가 다른 객체가 둘 있으면 두 번째에는 부모 이름이 붙고(`payment.meta`는 `PaymentMeta`), 그 이름도 쓰이고 있으면 숫자가 붙습니다(`Meta2`). 루트는 지정한 이름을 유지합니다.
- 올바른 타입 이름이 되지 않는 키(`2fa`, 빈 키)는 인터페이스 이름 앞에 `T`를 붙입니다(`T2fa`).

## 제한 사항

- {/* jtt-error: {"input":"{\"a\":1,}"} */}입력은 유효한 JSON이어야 합니다(주석, 끝 쉼표 불가). 유효하지 않으면 출력이 지워지고, 상태 표시에 몇 행 몇 열인지와 예상 원인이 나옵니다. 행과 열은 입력한 그대로의 텍스트에서 셉니다. 예를 들어 `{"a":1,}`은 `잘못된 JSON: 1행 7열, 닫는 괄호 앞에 쉼표가 남아 있습니다.`로 표시됩니다. {/* jtt-error: {"input":"{“이름”: \"홍길동\"}"} */}문서에서 복사해 둥근 따옴표가 섞인 `{“이름”: "홍길동"}`은 `잘못된 JSON: 1행 2열, “는 둥근 따옴표입니다. 곧은 큰따옴표(")를 쓰세요.`로 표시됩니다.
- 루트 배열에 객체와 다른 값이 섞여 있으면(`[{"id": 1}, "x", null]` 등) 객체는 루트 이름의 인터페이스로 합쳐지고, 배열 전체를 나타내는 타입 별칭이 중첩 배열과 같은 방식으로 추가됩니다: `type RootObjectArray = (string | null | RootObject)[];`. 응답 타입에는 `RootObjectArray`를 씁니다.
- 루트 인터페이스 이름은 ECMAScript 식별자 규칙으로 정리합니다. 각 언어의 문자, 숫자, `$`, `_`는 남기고, 그 밖의 문자는 지운 뒤 다음 글자를 대문자로 바꿉니다(`user profile`은 `userProfile`). 식별자 첫 글자로 쓸 수 없는 이름은 앞에 `T`를 붙이고(`2fa`는 `T2fa`), 예약어나 기본 타입 이름은 뒤에 `_`를 붙입니다(`class`는 `class_`). 남는 글자가 없으면 RootObject를 씁니다.
- TypeScript 표준 라이브러리에 있는 한 단어짜리 전역 타입(`Promise`, `Date`, `Map`, `Record`, `Body`, `Response`, `Event` 등)과 같은 이름은 그대로 쓰지 않습니다. `import`나 `export`가 없는 파일에서는 그 선언이 전역 타입과 병합되고, 모듈에서는 전역 타입을 가리기 때문입니다. 중첩 객체는 앞에 부모 이름을 붙이고(`{"date": {"year": 2026}}`는 `RootObjectDate`), 루트 이름에는 `_`를 붙입니다(`Map`은 `Map_`). `formData` 키에서 만들어지는 `FormData`처럼 여러 단어로 된 전역 타입 이름은 생성된 이름 그대로입니다. `import`나 `export`가 없는 파일에 붙여 넣거나, 붙여 넣을 모듈에서 그 전역 타입도 쓴다면 이름을 바꾸세요.
- 중첩이 아주 깊으면 브라우저의 호출 스택을 넘을 수 있습니다. 이때 상태 표시에 오류가 나오고 이전 출력은 지워집니다.
- 9007199254740991(`Number.MAX_SAFE_INTEGER`)보다 큰 정수는 `JSON.parse`에서 자릿수가 바뀌고 타입은 `number`가 됩니다.
- 타입은 붙여 넣은 샘플에서만 정해집니다. 샘플에서는 문자열이지만 실제로는 가끔 숫자인 필드도 `string`으로 남습니다.
- **interface 대신 type 사용**을 선택하면 각 선언이 `type Name = { ... }`로 출력되지만 상태 표시는 ‘인터페이스’ 그대로입니다.
