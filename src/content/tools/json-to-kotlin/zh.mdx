<h2>类型映射</h2>
<ul>
  <li>字符串 → <code>String</code>；布尔 → <code>Boolean</code></li>
  <li>−2,147,483,648 到 2,147,483,647 的整数 → <code>Int</code>；更大 → <code>Long</code>；超出 <code>Long</code> 范围 → <code>Double</code></li>
  <li>写有小数点或指数的数字（<code>9.5</code>、<code>19.0</code>、<code>1e3</code>）→ <code>Double</code></li>
  <li>数组 → <code>List&lt;T&gt;</code>；<code>Int</code>、<code>Long</code>、<code>Double</code> 混合时取最宽的类型；其他混合与空数组 → <code>List&lt;JsonElement&gt;</code></li>
  <li><code>null</code> → 可空类型；始终为 <code>null</code> 的字段 → <code>JsonElement?</code></li>
  <li>嵌套对象 → 独立的 <code>data class</code>；空对象 <code>{"{}"}</code> → <code>class Name</code>（data class 至少要有一个属性）</li>
</ul>

<h2>示例：snake_case 的 API 响应</h2>

<p>输入含 snake_case 键、一个 null 字段、一个超过 <code>Int.MAX_VALUE</code> 的计数和写成 <code>4.0</code> 的评分：</p>

{/* kt: {"roundTrip": true} */}

<pre><code>{`{"user_id": 1024, "display_name": "Alice", "is_active": true, "last_login": null, "follower_count": 3000000000, "rating": 4.0, "tags": ["admin", "editor"], "address": {"city": "Tokyo", "zip_code": "100-0001"}}`}</code></pre>

<p>输出：</p>

<pre><code>{`import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable
import kotlinx.serialization.json.JsonElement

@Serializable
data class RootObject(
    @SerialName("user_id")
    val userId: Int = 0,
    @SerialName("display_name")
    val displayName: String = "",
    @SerialName("is_active")
    val isActive: Boolean = false,
    @SerialName("last_login")
    val lastLogin: JsonElement? = null,
    @SerialName("follower_count")
    val followerCount: Long = 0L,
    val rating: Double = 0.0,
    val tags: List<String> = emptyList(),
    val address: Address = Address()
)

@Serializable
data class Address(
    val city: String = "",
    @SerialName("zip_code")
    val zipCode: String = ""
)`}</code></pre>

<p>camelCase 名与 JSON 键不同的字段用 <code>{"@SerialName"}</code> 保留原键。用作键的 Kotlin 关键字（<code>class</code>、<code>in</code>、<code>fun</code>）会加反引号。没有字母或数字的键（如空键 <code>{'""'}</code>、<code>{'"-"'}</code>）生成属性 <code>field</code>（下一个是 <code>field2</code>），原键记在 <code>{"@SerialName"}</code> 里；Kotlin 2.4.20 不接受名为 <code>_</code> 的属性。<code>last_login</code> 在样本里只有 <code>null</code>，所以是 <code>JsonElement?</code>；确认它是时间戳后改成 <code>String?</code>。</p>

<h2>示例：对象数组</h2>

<p>根是数组时，所有对象合并为一个类。<code>price</code> 一个是 <code>2</code>、一个是 <code>1.5</code>，合并为 <code>Double</code>。部分元素缺少的键可空，默认 <code>{"null"}</code>：</p>

{/* kt: {} */}

<pre><code>{`[{"id": 1, "name": "Pen", "price": 2}, {"id": 2, "name": "Ink", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val id: Int = 0,
    val name: String = "",
    val price: Double = 0.0,
    val discount: Double? = null
)`}</code></pre>

<p>状态栏会提示按 <code>{"List<RootObject>"}</code> 解码。</p>

<h2>示例：同名键、不同对象</h2>

<p>两个名为 <code>meta</code>、字段不同的嵌套对象会生成两个类，第二个以父级名为前缀：</p>

{/* kt: {"roundTrip": true} */}

<pre><code>{`{"order": {"id": 7, "meta": {"source": "web"}}, "payment": {"meta": {"method": "card", "last4": "4242"}}}`}</code></pre>

<pre><code>{`import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val order: Order = Order(),
    val payment: Payment = Payment()
)

@Serializable

    val meta: Meta = Meta()

@Serializable

    val source: String = ""
)

@Serializable
data class Payment(
    val meta: PaymentMeta = PaymentMeta()
)

@Serializable
data class PaymentMeta(
    val method: String = "",
    val last4: String = ""
)`}</code></pre>

<h2>示例：高德天气查询的成功与失败响应</h2>

<p>高德开放平台的天气查询接口（<code>restapi.amap.com/v3/weather/weatherInfo</code>）在文档里列出了返回字段：<code>status</code>（1 成功、0 失败）、<code>count</code>、<code>info</code>、<code>infocode</code>（10000 代表正确）和实况数组 <code>lives</code>。下面的样本按这些字段编写，值是示例；样本里的数字写成带引号的字符串：</p>

{/* kt: {"roundTrip": true, "decodes": [["{\"status\":\"0\",\"info\":\"INVALID_USER_KEY\",\"infocode\":\"10001\"}", "{\"status\":\"0\",\"count\":\"\",\"info\":\"INVALID_USER_KEY\",\"infocode\":\"10001\",\"lives\":[]}"]]} */}

<pre><code>{`{"status": "1", "count": "1", "info": "OK", "infocode": "10000", "lives": [{"province": "浙江", "city": "西湖区", "adcode": "330106", "weather": "晴", "temperature": "23", "winddirection": "东北", "windpower": "≤3", "humidity": "62", "reporttime": "2026-10-08 14:02:45"}]}`}</code></pre>

<pre><code>{`import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val status: String = "",
    val count: String = "",
    val info: String = "",
    val infocode: String = "",
    val lives: List<LivesItem> = emptyList()
)

@Serializable
data class LivesItem(
    val province: String = "",
    val city: String = "",
    val adcode: String = "",
    val weather: String = "",
    val temperature: String = "",
    val winddirection: String = "",
    val windpower: String = "",
    val humidity: String = "",
    val reporttime: String = ""
)`}</code></pre>

<p>样本里带引号的 <code>"23"</code> 是字符串，所以这份样本生成的 <code>temperature</code> 是 <code>String</code>；拿到真实响应后按它的类型重新生成，字符串要做计算时自己转成数字。数组里的对象以键名加 <code>Item</code> 命名为 <code>LivesItem</code>。</p>

<p>2026-10-08 不带有效 key 请求这个接口，返回的是 <code>{'{"status":"0","info":"INVALID_USER_KEY","infocode":"10001"}'}</code>。用上面生成的类解码这份失败响应不会报错：缺少的 <code>count</code> 和 <code>lives</code> 取默认值，重新编码得到 <code>{'"count":""'}</code> 和 <code>{'"lives":[]'}</code>。所以解码后先判断 <code>status</code> 是否为 <code>"1"</code>，不要只看有没有异常。</p>

<h2>示例：微信支付回调通知</h2>

<p>下面是微信支付「支付成功回调通知」文档（更新时间 2024.12.27）给出的示例报文，原样粘贴：</p>

{/* kt: {"roundTrip": true, "decodes": [["{\"id\":\"EV-1\",\"create_time\":\"2026-10-08T10:00:00+08:00\",\"resource_type\":\"encrypt-resource\",\"event_type\":\"TRANSACTION.SUCCESS\",\"summary\":\"支付成功\",\"resource\":{\"original_type\":\"transaction\",\"algorithm\":\"AEAD_AES_256_GCM\",\"ciphertext\":\"\",\"nonce\":\"\"}}", "{\"id\":\"EV-1\",\"create_time\":\"2026-10-08T10:00:00+08:00\",\"resource_type\":\"encrypt-resource\",\"event_type\":\"TRANSACTION.SUCCESS\",\"summary\":\"支付成功\",\"resource\":{\"original_type\":\"transaction\",\"algorithm\":\"AEAD_AES_256_GCM\",\"ciphertext\":\"\",\"associated_data\":\"\",\"nonce\":\"\"}}"]]} */}

<pre><code>{`{"id": "EV-2018022511223320873", "create_time": "2015-05-20T13:29:35+08:00", "resource_type": "encrypt-resource", "event_type": "TRANSACTION.SUCCESS", "summary": "支付成功", "resource": {"original_type": "transaction", "algorithm": "AEAD_AES_256_GCM", "ciphertext": "", "associated_data": "", "nonce": ""}}`}</code></pre>

<pre><code>{`import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val id: String = "",
    @SerialName("create_time")
    val createTime: String = "",
    @SerialName("resource_type")
    val resourceType: String = "",
    @SerialName("event_type")
    val eventType: String = "",
    val summary: String = "",
    val resource: Resource = Resource()
)

@Serializable
data class Resource(
    @SerialName("original_type")
    val originalType: String = "",
    val algorithm: String = "",
    val ciphertext: String = "",
    @SerialName("associated_data")
    val associatedData: String = "",
    val nonce: String = ""
)`}</code></pre>

<p>snake_case 的键都变成 camelCase 属性，并用 <code>{"@SerialName"}</code> 记下原键。文档把 <code>associated_data</code> 标为选填，没有这个键的报文照样能解码，<code>associatedData</code> 取默认值 <code>""</code>。<code>ciphertext</code> 解密后才是订单信息，那是另一份 JSON，需要单独生成。</p>

<p>JSON 键也可以是中文：<code>{'{"订单号": "202610080001"}'}</code> 生成 <code>{'val 订单号: String = ""'}</code>。Kotlin 的标识符允许中文字符，名字与键相同时不加 <code>{"@SerialName"}</code>。</p>

<h2>解码</h2>

<p>在构建配置里加入序列化插件和 JSON 库（见 <a href="https://kotlinlang.org/docs/serialization.html" target="_blank" rel="noopener">Kotlin 序列化指南</a>），然后解码：</p>

<pre><code>{`import kotlinx.serialization.json.Json

val user = Json.decodeFromString<RootObject>(body)
val items = Json.decodeFromString<List<RootObject>>(arrayBody)

// 允许样本里没有的键
val lenient = Json { ignoreUnknownKeys = true }`}</code></pre>

<p>默认的 <code>Json</code> 遇到类里没有的键会报错。本页所有示例都用 Kotlin 2.4.20 与 kotlinx.serialization 1.11.0 编译，并用默认配置解码通过。</p>

<h2>限制</h2>
<ul>
  <li>类型只看一份样本。样本里较小的 ID 会生成 <code>Int</code>，生产环境的 ID 若超过 2,147,483,647，需要自己改成 <code>Long</code>。</li>
  <li>浏览器按 64 位浮点数解析 JSON 数字，大于 9,007,199,254,740,991 的整数在判断类型前就丢了精度。类型仍为 <code>Long</code>，范围需要自己核对。</li>
  <li>只有向 <code>JSON.parse</code> 提供源文本的浏览器（Chrome 114+、Firefox 135+、Safari 18.4+）能把 <code>19.0</code> 识别为小数，旧浏览器会生成 <code>Int</code>。</li>
  <li><code>JsonElement</code> 字段只适用于 <code>Json</code> 格式，不适用于 CBOR、ProtoBuf。</li>
  <li>日期保持 <code>String</code>。JSON 没有日期类型，解码后自行解析或加自定义序列化器。</li>
  <li>每个属性都有默认值，缺少的键会静默解码成默认值。必须出现的键请删掉默认值。</li>
</ul>
