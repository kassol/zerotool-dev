<h2>Type Mapping</h2>
<ul>
  <li>string → <code>String</code>; boolean → <code>Boolean</code></li>
  <li>whole number from −2,147,483,648 to 2,147,483,647 → <code>Int</code>; larger → <code>Long</code>; beyond the <code>Long</code> range → <code>Double</code></li>
  <li>number written with a decimal point or exponent (<code>9.5</code>, <code>19.0</code>, <code>1e3</code>) → <code>Double</code></li>
  <li>array → <code>List&lt;T&gt;</code>; <code>Int</code>, <code>Long</code> and <code>Double</code> elements widen to the largest; other mixes, and empty arrays, give <code>List&lt;JsonElement&gt;</code></li>
  <li><code>null</code> → nullable type; a field that is only <code>null</code> → <code>JsonElement?</code></li>
  <li>nested object → separate <code>data class</code>; an empty object <code>{"{}"}</code> → <code>class Name</code> (a data class needs at least one property)</li>
</ul>

<h2>Example: snake_case API Response</h2>

<p>Input with snake_case keys, a null field, a counter above <code>Int.MAX_VALUE</code> and a rating written as <code>4.0</code>:</p>

{/* kt: {"roundTrip": true} */}

<pre><code>{`{"user_id": 1024, "display_name": "Alice", "is_active": true, "last_login": null, "follower_count": 3000000000, "rating": 4.0, "tags": ["admin", "editor"], "address": {"city": "Tokyo", "zip_code": "100-0001"}}`}</code></pre>

<p>Output:</p>

<pre><code>{`import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable
import kotlinx.serialization.json.JsonElement

@Serializable
data class RootObject(
    @SerialName("user_id")
    val userId: Int = 0,
    @SerialName("display_name")
    val displayName: String = "",
    @SerialName("is_active")
    val isActive: Boolean = false,
    @SerialName("last_login")
    val lastLogin: JsonElement? = null,
    @SerialName("follower_count")
    val followerCount: Long = 0L,
    val rating: Double = 0.0,
    val tags: List<String> = emptyList(),
    val address: Address = Address()
)

@Serializable
data class Address(
    val city: String = "",
    @SerialName("zip_code")
    val zipCode: String = ""
)`}</code></pre>

<p>Each key whose camelCase name differs from the JSON key keeps the original in <code>{"@SerialName"}</code>. Kotlin keywords used as keys (<code>class</code>, <code>in</code>, <code>fun</code>) are written in backticks. <code>last_login</code> is only ever <code>null</code> in the sample, so it is <code>JsonElement?</code>; change it to <code>String?</code> once you know it holds a timestamp.</p>

<h2>Example: Array of Objects</h2>

<p>When the root is an array, the tool merges all objects into one class. <code>price</code> is <code>2</code> in one item and <code>1.5</code> in the other, so it becomes <code>Double</code>. A key that is missing from some items becomes nullable with <code>{"null"}</code> as the default:</p>

{/* kt: {} */}

<pre><code>{`[{"id": 1, "name": "Pen", "price": 2}, {"id": 2, "name": "Ink", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val id: Int = 0,
    val name: String = "",
    val price: Double = 0.0,
    val discount: Double? = null
)`}</code></pre>

<p>The status line reminds you to decode this input as <code>{"List<RootObject>"}</code>.</p>

<h2>Example: Same Key, Different Objects</h2>

<p>Two nested objects called <code>meta</code> with different fields get two classes. The second takes its parent's name as a prefix:</p>

{/* kt: {"roundTrip": true} */}

<pre><code>{`{"order": {"id": 7, "meta": {"source": "web"}}, "payment": {"meta": {"method": "card", "last4": "4242"}}}`}</code></pre>

<pre><code>{`import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val order: Order = Order(),
    val payment: Payment = Payment()
)

@Serializable
data class Order(
    val id: Int = 0,
    val meta: Meta = Meta()
)

@Serializable
data class Meta(
    val source: String = ""
)

@Serializable
data class Payment(
    val meta: PaymentMeta = PaymentMeta()
)

@Serializable
data class PaymentMeta(
    val method: String = "",
    val last4: String = ""
)`}</code></pre>

<h2>Decoding</h2>

<p>Add the serialization plugin and the JSON library to your build (see the <a href="https://kotlinlang.org/docs/serialization.html" target="_blank" rel="noopener">Kotlin serialization guide</a>), then decode:</p>

<pre><code>{`import kotlinx.serialization.json.Json

val user = Json.decodeFromString<RootObject>(body)
val items = Json.decodeFromString<List<RootObject>>(arrayBody)

// tolerate keys the sample did not have
val lenient = Json { ignoreUnknownKeys = true }`}</code></pre>

<p>The default <code>Json</code> rejects keys that are not in the class. Every example on this page was compiled with Kotlin 2.4.20 and kotlinx.serialization 1.11.0 and decoded with that default configuration.</p>

<h2>Limitations</h2>
<ul>
  <li>Types come from one sample. An ID that is small in the sample is typed <code>Int</code> even if production IDs exceed 2,147,483,647; change it to <code>Long</code> yourself.</li>
  <li>The browser parses JSON numbers as 64-bit floating point, so integers above 9,007,199,254,740,991 lose digits before the type is chosen. The type is still <code>Long</code>, but check the range by hand.</li>
  <li><code>19.0</code> is recognised as a decimal only in browsers that give <code>JSON.parse</code> the source text (Chrome 114+, Firefox 135+, Safari 18.4+). Older browsers type it <code>Int</code>.</li>
  <li><code>JsonElement</code> fields work with the <code>Json</code> format only, not with CBOR or ProtoBuf.</li>
  <li>Dates stay <code>String</code>. JSON has no date type; parse them after decoding or add a custom serializer.</li>
  <li>Every property has a default value, so a missing key decodes silently. Remove a default if that key must be present.</li>
</ul>
