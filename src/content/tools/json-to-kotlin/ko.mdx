<h2>타입 매핑</h2>
<ul>
  <li>문자열 → <code>String</code>, 불리언 → <code>Boolean</code></li>
  <li>−2,147,483,648~2,147,483,647 정수 → <code>Int</code>, 더 크면 → <code>Long</code>, <code>Long</code> 범위 밖 → <code>Double</code></li>
  <li>소수점이나 지수가 있는 숫자(<code>9.5</code>, <code>19.0</code>, <code>1e3</code>) → <code>Double</code></li>
  <li>배열 → <code>List&lt;T&gt;</code>. <code>Int</code>·<code>Long</code>·<code>Double</code>이 섞이면 가장 넓은 타입, 그 밖의 혼합과 빈 배열은 <code>List&lt;JsonElement&gt;</code></li>
  <li><code>null</code> → nullable 타입, 항상 <code>null</code>인 필드 → <code>JsonElement?</code></li>
  <li>중첩 객체 → 별도 <code>data class</code>, 빈 객체 <code>{"{}"}</code> → <code>class Name</code>(data class는 속성이 하나 이상 필요)</li>
</ul>

<h2>예시: snake_case API 응답</h2>

<p>snake_case 키, null 필드, <code>Int.MAX_VALUE</code>를 넘는 카운터, <code>4.0</code>으로 쓴 평점이 있는 입력:</p>

{/* kt: {"roundTrip": true} */}

<pre><code>{`{"user_id": 1024, "display_name": "Alice", "is_active": true, "last_login": null, "follower_count": 3000000000, "rating": 4.0, "tags": ["admin", "editor"], "address": {"city": "Tokyo", "zip_code": "100-0001"}}`}</code></pre>

<p>출력:</p>

<pre><code>{`import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable
import kotlinx.serialization.json.JsonElement

@Serializable
data class RootObject(
    @SerialName("user_id")
    val userId: Int = 0,
    @SerialName("display_name")
    val displayName: String = "",
    @SerialName("is_active")
    val isActive: Boolean = false,
    @SerialName("last_login")
    val lastLogin: JsonElement? = null,
    @SerialName("follower_count")
    val followerCount: Long = 0L,
    val rating: Double = 0.0,
    val tags: List<String> = emptyList(),
    val address: Address = Address()
)

@Serializable
data class Address(
    val city: String = "",
    @SerialName("zip_code")
    val zipCode: String = ""
)`}</code></pre>

<p>camelCase 이름이 JSON 키와 다른 필드는 <code>{"@SerialName"}</code>으로 원래 키를 유지합니다. 키로 쓰인 Kotlin 키워드(<code>class</code>, <code>in</code>, <code>fun</code>)는 백틱으로 감쌉니다. <code>last_login</code>은 샘플에서 <code>null</code>뿐이라 <code>JsonElement?</code>가 됩니다. 타임스탬프임을 알면 <code>String?</code>으로 바꾸세요.</p>

<h2>예시: 객체 배열</h2>

<p>루트가 배열이면 모든 객체를 하나의 클래스로 합칩니다. <code>price</code>가 <code>2</code>와 <code>1.5</code>이므로 <code>Double</code>이 됩니다. 일부 요소에만 있는 키는 nullable이며 기본값은 <code>{"null"}</code>입니다.</p>

{/* kt: {} */}

<pre><code>{`[{"id": 1, "name": "Pen", "price": 2}, {"id": 2, "name": "Ink", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val id: Int = 0,
    val name: String = "",
    val price: Double = 0.0,
    val discount: Double? = null
)`}</code></pre>

<p>상태 표시줄에 <code>{"List<RootObject>"}</code>로 디코딩하라는 안내가 나옵니다.</p>

<h2>예시: 같은 이름의 키, 다른 객체</h2>

<p>필드가 다른 <code>meta</code> 객체가 두 개 있으면 클래스도 두 개가 생성되고, 두 번째에는 부모 이름이 앞에 붙습니다.</p>

{/* kt: {"roundTrip": true} */}

<pre><code>{`{"order": {"id": 7, "meta": {"source": "web"}}, "payment": {"meta": {"method": "card", "last4": "4242"}}}`}</code></pre>

<pre><code>{`import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val order: Order = Order(),
    val payment: Payment = Payment()
)

@Serializable
data class Order(
    val id: Int = 0,
    val meta: Meta = Meta()
)

@Serializable
data class Meta(
    val source: String = ""
)

@Serializable
data class Payment(
    val meta: PaymentMeta = PaymentMeta()
)

@Serializable
data class PaymentMeta(
    val method: String = "",
    val last4: String = ""
)`}</code></pre>

<h2>카카오 로그인 응답으로 확인하기</h2>

<p>카카오 로그인 REST API 문서의 토큰 받기 응답 예제를 그대로 붙여 넣으면 다음 클래스가 나옵니다. <code>$&#123;ACCESS_TOKEN&#125;</code> 같은 값은 문서의 자리 표시자입니다.</p>

{/* kt: {"roundTrip": true, "rejects": [["{\"token_type\": \"bearer\", \"access_token\": \"${ACCESS_TOKEN}\", \"id_token\": \"${ID_TOKEN}\", \"expires_in\": 7199, \"refresh_token\": \"${REFRESH_TOKEN}\", \"refresh_token_expires_in\": 86399, \"scope\": \"profile_image openid profile_nickname\"}", "kotlinx.serialization.json.JsonDecodingException"]]} */}

<pre><code>{`{"token_type": "bearer", "access_token": "\${ACCESS_TOKEN}", "expires_in": 43199, "refresh_token": "\${REFRESH_TOKEN}", "refresh_token_expires_in": 5184000, "scope": "account_email profile"}`}</code></pre>

<pre><code>{`import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    @SerialName("token_type")
    val tokenType: String = "",
    @SerialName("access_token")
    val accessToken: String = "",
    @SerialName("expires_in")
    val expiresIn: Int = 0,
    @SerialName("refresh_token")
    val refreshToken: String = "",
    @SerialName("refresh_token_expires_in")
    val refreshTokenExpiresIn: Int = 0,
    val scope: String = ""
)`}</code></pre>

<p>같은 문서에는 OpenID Connect를 활성화한 앱의 응답 예제도 있는데, 여기에는 <code>id_token</code>이 더 들어 있습니다. 위 클래스로 이 응답을 디코딩하면 기본 <code>Json</code>이 모르는 키를 오류로 처리해 <code>JsonDecodingException</code>이 납니다. 두 응답 예제를 배열로 묶어 생성하면 <code>id_token</code>이 한쪽에만 있으므로 nullable이 됩니다.</p>

{/* kt: {"decodeAs": "RootObject", "decodes": ["{\"token_type\": \"bearer\", \"access_token\": \"${ACCESS_TOKEN}\", \"expires_in\": 43199, \"refresh_token\": \"${REFRESH_TOKEN}\", \"refresh_token_expires_in\": 5184000, \"scope\": \"account_email profile\"}", "{\"token_type\": \"bearer\", \"access_token\": \"${ACCESS_TOKEN}\", \"id_token\": \"${ID_TOKEN}\", \"expires_in\": 7199, \"refresh_token\": \"${REFRESH_TOKEN}\", \"refresh_token_expires_in\": 86399, \"scope\": \"profile_image openid profile_nickname\"}"]} */}

<pre><code>{`[{"token_type": "bearer", "access_token": "\${ACCESS_TOKEN}", "expires_in": 43199, "refresh_token": "\${REFRESH_TOKEN}", "refresh_token_expires_in": 5184000, "scope": "account_email profile"}, {"token_type": "bearer", "access_token": "\${ACCESS_TOKEN}", "id_token": "\${ID_TOKEN}", "expires_in": 7199, "refresh_token": "\${REFRESH_TOKEN}", "refresh_token_expires_in": 86399, "scope": "profile_image openid profile_nickname"}]`}</code></pre>

<pre><code>{`import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    @SerialName("token_type")
    val tokenType: String = "",
    @SerialName("access_token")
    val accessToken: String = "",
    @SerialName("expires_in")
    val expiresIn: Int = 0,
    @SerialName("refresh_token")
    val refreshToken: String = "",
    @SerialName("refresh_token_expires_in")
    val refreshTokenExpiresIn: Int = 0,
    val scope: String = "",
    @SerialName("id_token")
    val idToken: String? = null

<p>상태 표시는 루트가 배열이라며 <code>{"List<RootObject>"}</code>로 디코딩하라고 안내하지만, 토큰 응답은 한 번에 객체 하나이므로 <code>{"Json.decodeFromString<RootObject>(body)"}</code>로 읽습니다. 두 응답 예제 모두 이 클래스로 디코딩되는 것을 확인했습니다.</p>

<p>사용자 정보 가져오기 응답에서는 회원번호 <code>id</code>의 타입이 문서에 <code>Long</code>으로 적혀 있습니다. 문서의 필드 이름으로 만든 아래 샘플처럼 값이 작으면 도구는 <code>Int</code>를 고릅니다.</p>

{/* kt: {"roundTrip": true, "rejects": [["{\"id\": 3000000000, \"connected_at\": \"2026-10-08T01:23:45Z\", \"kakao_account\": {\"profile_nickname_needs_agreement\": false, \"profile\": {\"nickname\": \"홍길동\", \"is_default_nickname\": false}}}", "kotlinx.serialization.json.JsonDecodingException"]]} */}

<pre><code>{`{"id": 123456789, "connected_at": "2026-10-08T01:23:45Z", "kakao_account": {"profile_nickname_needs_agreement": false, "profile": {"nickname": "홍길동", "is_default_nickname": false}}}`}</code></pre>

<pre><code>{`import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable

@Serializable
data class RootObject(
    val id: Int = 0,
    @SerialName("connected_at")
    val connectedAt: String = "",
    @SerialName("kakao_account")
    val kakaoAccount: KakaoAccount = KakaoAccount()
)

@Serializable
data class KakaoAccount(
    @SerialName("profile_nickname_needs_agreement")
    val profileNicknameNeedsAgreement: Boolean = false,
    val profile: Profile = Profile()
)

@Serializable
data class Profile(
    val nickname: String = "",
    @SerialName("is_default_nickname")
    val isDefaultNickname: Boolean = false
)`}</code></pre>

<p><code>id</code>가 <code>3000000000</code>인 응답은 이 클래스로 디코딩하면 <code>JsonDecodingException</code>이 납니다. 문서대로 <code>val id: Long = 0L</code>로 고쳐 두세요. 중첩된 <code>kakao_account</code>와 <code>profile</code>은 각각 <code>KakaoAccount</code>, <code>Profile</code> 클래스가 됩니다. 값은 이 페이지용 예시입니다.</p>

<h2>디코딩</h2>

<p>빌드 설정에 직렬화 플러그인과 JSON 라이브러리를 추가하고(<a href="https://kotlinlang.org/docs/serialization.html" target="_blank" rel="noopener">Kotlin 직렬화 가이드</a> 참고) 다음처럼 디코딩합니다.</p>

<pre><code>{`import kotlinx.serialization.json.Json

val user = Json.decodeFromString<RootObject>(body)
val items = Json.decodeFromString<List<RootObject>>(arrayBody)

// 샘플에 없던 키 허용
val lenient = Json { ignoreUnknownKeys = true }`}</code></pre>

<p>기본 <code>Json</code>은 클래스에 없는 키를 오류로 처리합니다. 이 페이지의 예시는 모두 Kotlin 2.4.20과 kotlinx.serialization 1.11.0으로 컴파일하고 기본 설정으로 디코딩되는 것을 확인했습니다.</p>

<h2>제한 사항</h2>
<ul>
  <li>타입은 샘플 하나로만 정합니다. 샘플의 ID가 작으면 <code>Int</code>가 되므로, 실제 ID가 2,147,483,647을 넘는다면 <code>Long</code>으로 바꾸세요.</li>
  <li>브라우저는 JSON 숫자를 64비트 부동소수점으로 읽기 때문에 9,007,199,254,740,991보다 큰 정수는 타입을 정하기 전에 자릿수를 잃습니다. 타입은 <code>Long</code>이지만 범위는 직접 확인하세요.</li>
  <li><code>19.0</code>을 소수로 판단하는 것은 <code>JSON.parse</code>에 원본 텍스트를 넘겨주는 브라우저(Chrome 114+, Firefox 135+, Safari 18.4+)뿐입니다. 오래된 브라우저에서는 <code>Int</code>가 됩니다.</li>
  <li><code>JsonElement</code> 필드는 <code>Json</code> 포맷에서만 동작하며 CBOR, ProtoBuf에서는 쓸 수 없습니다.</li>
  <li>날짜는 <code>String</code>으로 남습니다. JSON에는 날짜 타입이 없으므로 디코딩 후 파싱하거나 커스텀 시리얼라이저를 추가하세요.</li>
  <li>모든 속성에 기본값이 있어 키가 빠져도 조용히 기본값이 됩니다. 꼭 있어야 하는 키는 기본값을 지우세요.</li>
</ul>
