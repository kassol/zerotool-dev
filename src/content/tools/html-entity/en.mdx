<h2>Worked Examples</h2>

{/* he-check: {"encode":"<div class=\"box\">"} */}
<h3>Encoding a code snippet for display</h3>
<p>
  You want to show <code>&lt;div class="box"&gt;</code> as visible text on a web page.
  Paste it into the input and select <strong>Encode</strong>. The output will be:
</p>
<pre><code>&amp;lt;div class=&amp;quot;box&amp;quot;&amp;gt;</code></pre>
<p>This safely renders as the literal HTML tag text in any browser.</p>

{/* he-check: {"decode":"Tom &amp; Jerry &mdash; Season 1"} */}
<h3>Decoding received HTML content</h3>
<p>
  You received a string from an API: <code>Tom &amp;amp; Jerry &amp;mdash; Season 1</code>.
  Paste it in and select <strong>Decode</strong>. The output will be:
</p>
<pre><code>Tom &amp; Jerry — Season 1</code></pre>

{/* he-check: {"encode":"Café © 2024"} */}
<h3>Encoding non-ASCII characters</h3>
<p>
  Paste <code>Caf&eacute; &copy; 2024</code> and select <strong>Encode</strong>.
  Non-ASCII characters are converted to numeric entities:
</p>
<pre><code>Caf&amp;#233; &amp;#169; 2024</code></pre>

{/* he-check: {"encode":"<a title=\"Tom's café\">","count":6,"status":true} */}
<h3>Encoding an attribute value</h3>
<p>Input <code>{`<a title="Tom's café">`}</code> gives <code>{'&lt;a title=&quot;Tom&#39;s caf&#233;&quot;&gt;'}</code> and the status "Encoded — 6 characters converted." The apostrophe becomes <code>{'&#39;'}</code>, so the result is safe inside both single-quoted and double-quoted attributes.</p>

{/* he-check: {"encode":"Ship it 🚀"} */}
<h3>Emoji and other characters outside the BMP</h3>
<p><code>Ship it 🚀</code> encodes to <code>{'Ship it &#128640;'}</code>: one reference with the code point U+1F680. Some encoders loop over UTF-16 code units and write <code>{'&#55357;&#56960;'}</code> instead. Those two numbers are surrogates, which the HTML parser replaces with U+FFFD, so the rocket turns into two replacement characters.</p>

<h2>What Encode Changes</h2>
<ul>
  <li>The five characters with meaning in markup: <code>&amp;</code> → <code>{'&amp;'}</code>, <code>&lt;</code> → <code>{'&lt;'}</code>, <code>&gt;</code> → <code>{'&gt;'}</code>, <code>"</code> → <code>{'&quot;'}</code>, <code>'</code> → <code>{'&#39;'}</code>.</li>
  <li>Every character above U+007F, as a decimal reference. Accented letters, CJK text and emoji all become numbers, which makes the output pure ASCII. That helps when a template or e-mail system is not UTF-8 clean, but the file gets larger: <code>中</code> (3 bytes in UTF-8) becomes <code>{'&#20013;'}</code> (8 bytes). In a UTF-8 page you only need the first five.</li>
  <li>Nothing else. Line breaks, tabs and spaces are kept. The encoder never writes named entities such as <code>{'&copy;'}</code>; the tables on this page list names for reading, not output.</li>
</ul>

<h2>How Decode Works</h2>
<p>Decode hands the input to the browser's own HTML parser (it sets the <code>innerHTML</code> of a <code>&lt;textarea&gt;</code> and reads the text back). Tags in the input are not created or run; only character references are replaced. The result therefore follows the <a href="https://html.spec.whatwg.org/multipage/parsing.html#character-reference-state" target="_blank" rel="noopener">HTML character reference rules</a>:</p>
<ul>
  <li>Every name in the <a href="https://html.spec.whatwg.org/multipage/named-characters.html" target="_blank" rel="noopener">HTML named character list</a> is recognized (2,231 entries, counting the legacy forms without a semicolon), plus decimal (<code>{'&#169;'}</code>) and hex (<code>{'&#xA9;'}</code>) forms.</li>
  <li>Some legacy names work without the semicolon: <code>{'&copy 2024'}</code> decodes to <code>© 2024</code>. The status count only includes references that end in <code>;</code>, so it can be lower than the number actually decoded.</li>
  <li><code>{'&#128;'}</code> to <code>{'&#159;'}</code> are mapped as Windows-1252, as the spec requires: <code>{'&#128;'}</code> becomes €. <code>{'&#0;'}</code> and surrogate numbers become U+FFFD.</li>
</ul>

<h2>Limits</h2>
<ul>
  <li>Encoding is for HTML text and quoted attribute values. Inside <code>&lt;script&gt;</code>, inline event handlers, CSS or URLs, other escaping rules apply. Use <a href="/tools/string-escape/">String Escape</a> for JavaScript and JSON strings and <a href="/tools/url-encode/">URL Encode</a> for query parameters.</li>
  <li>Decoding twice is not undone: <code>{'&amp;lt;'}</code> decodes to <code>{'&lt;'}</code>, not <code>&lt;</code>. For double-encoded text, put the output back into Input while Decode is selected.</li>
  <li>The conversion status messages are in English on every language version of this page.</li>
</ul>
