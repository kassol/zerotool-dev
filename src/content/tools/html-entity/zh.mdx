## 示例：编码与解码

下面的输出都由本工具的编码函数和浏览器同款解析规则算出。

{/* he-check: {"encode":"<div class=\"box\">"} */}
### 在网页上显示一段代码

想把 `<div class="box">` 作为文字显示在文章里，选择 **编码** 后输入它，得到：

```text
&lt;div class=&quot;box&quot;&gt;
```

把这段结果放进 HTML，浏览器显示的就是原来的标签文字，不会生成一个 div。

{/* he-check: {"decode":"&ldquo;双十一&rdquo;活动 &middot; 满 300 减 40"} */}
### 解码后台接口返回的商品文案

很多内容管理系统保存文案时会把引号和间隔号写成命名实体。接口返回 `&ldquo;双十一&rdquo;活动 &middot; 满 300 减 40`，选择 **解码** 后得到：

```text
“双十一”活动 · 满 300 减 40
```

状态行显示 `Decoded — 3 entities converted.`：`&ldquo;`、`&rdquo;` 和 `&middot;` 各算一个。

{/* he-check: {"encode":"<b>新品</b>“限时”特价 & 包邮","count":15,"status":true} */}
### 带中文的标签文字

输入 `<b>新品</b>“限时”特价 & 包邮` 并选择 **编码**，输出为：

```text
&lt;b&gt;&#26032;&#21697;&lt;/b&gt;&#8220;&#38480;&#26102;&#8221;&#29305;&#20215; &amp; &#21253;&#37038;
```

状态行是 `Encoded — 15 characters converted.`。尖括号和 `&` 换成了名称，每个汉字和中文引号都换成了十进制数字。如果只是想在 UTF-8 页面里安全地显示这句话，汉字其实不用编码，见下一节。

{/* he-check: {"encode":"下单成功 🎉"} */}
### 表情符号只占一个引用

`下单成功 🎉` 编码后是 `&#19979;&#21333;&#25104;&#21151; &#127881;`。🎉 的码点是 U+1F389，十进制 127881，只写成一个引用。有些编码器按 UTF-16 码元处理，会写出两个代理项数字，浏览器把它们解析成两个替换字符 �。

## 中文要不要编码

W3C 的《[Using character escapes in markup and CSS](https://www.w3.org/International/questions/qa-escapes)》建议页面使用 UTF-8，普通文字直接写字符，并举例说「你好」这样的中文不需要转义；必须转义的只有 `<`、`>`、`&`，以及属性值里与外层相同的引号。

本工具的「编码」不区分页面编码，会把 U+007F 以上的每个字符都写成十进制引用。这样输出全是 ASCII，适合送进不支持 UTF-8 的旧模板或邮件系统，代价是体积变大：「你好」在 UTF-8 下是 6 字节，编码后的 `&#20320;&#22909;` 是 16 字节，正文越长差距越明显。同一份 W3C 文档也提到，这种写法会让源代码难读、难维护。所以在 UTF-8 的页面里，只需要处理那几个语法字符；中文、全角标点和表情符号保持原样即可。

## 解码按什么规则读

「解码」把输入交给浏览器自己的 HTML 解析器（写入一个 `textarea` 的 `innerHTML` 再读出文字），只替换字符引用，输入里的标签不会被创建或执行。结果遵循 HTML 标准的字符引用规则：

- HTML 名称表里的全部名字都能识别，十进制和十六进制写法也都能识别。
- 部分旧名称可以省略分号：`&yen1,980` 解码为 `¥1,980`。状态行只统计以分号结尾的引用，这一例显示为 0 个，但内容已经转换。
- `&#128;` 到 `&#159;` 按 Windows-1252 解释，`&#128;` 得到 `€`；`&#0;` 和代理项数字变成 U+FFFD。

## 限制

- 编码结果只用于 HTML 正文和带引号的属性值。放进 `<script>`、事件处理器、CSS 或 URL 时，要用对应语境的转义；JavaScript 和 JSON 字符串可以用[字符串转义 / 反转义](/zh/tools/string-escape/)，查询参数用 [URL 编码 / 解码](/zh/tools/url-encode/)。
- 解码只做一次：`&amp;lt;` 解码为 `&lt;`，不是 `<`。处理被编码了两次的文字时，把输出再放回「输入」并保持「解码」。
- 「编码」从不输出 `&copy;` 这类命名实体，下面的表格只供查阅。
- 状态行在所有语言版本中都显示英文。
