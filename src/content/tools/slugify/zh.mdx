## 中文标题会得到什么

工具不做拼音转写。汉字和中文标点会被删掉（删掉的位置按空格处理），留下来的只有标题里的英文、数字，以及下文映射表中的符号；全角字母和数字会先换成半角再保留。以下是默认选项（连字符、小写、修剪）的实际结果：

- {/* slug-check: {"in":"如何用 Python 3.12 解析 JSON"} */}`如何用 Python 3.12 解析 JSON` → `python-3-12-json`
- {/* slug-check: {"in":"Vue 3 + Vite 项目配置指南"} */}`Vue 3 + Vite 项目配置指南` → `vue-3-plus-vite`（`+` 换成了 plus）
- {/* slug-check: {"in":"微信小程序 setData 性能优化"} */}`微信小程序 setData 性能优化` → `setdata`
- {/* slug-check: {"in":"微信小程序 setData 性能优化","lower":false} */}同一个标题关闭「小写」：`微信小程序 setData 性能优化` → `setData`
- {/* slug-check: {"in":"如何用 Python 3.12 解析 JSON","sep":"_"} */}分隔符选下划线：`如何用 Python 3.12 解析 JSON` → `python_3_12_json`

第三个例子只剩一个词，已经看不出文章讲什么。这时可以先写一个英文标题或拼音，再交给工具。带声调的拼音可以直接粘贴，声调符号在 NFD 分解后会被去掉：

- {/* slug-check: {"in":"Rúhé yòng Python jiěxī JSON"} */}`Rúhé yòng Python jiěxī JSON` → `ruhe-yong-python-jiexi-json`

## ¥ 与全角字符

人民币和日元都写作 `¥`（U+00A5），工具按映射表一律换成单词 `yen`，不会区分货币：

- {/* slug-check: {"in":"价格 ¥99 起"} */}`价格 ¥99 起` → `yen-99`

全角的 `￥`（U+FFE5）、`％` 和全角字母、数字会先按 NFKC 换成半角，再查映射表，所以结果与半角输入相同：

- {/* slug-check: {"in":"价格 ￥99 起"} */}`价格 ￥99 起` → `yen-99`
- {/* slug-check: {"in":"Ｎｏｄｅ．ｊｓ ２０ 入门"} */}`Ｎｏｄｅ．ｊｓ ２０ 入门` → `node-js-20`

汉字和全角空格（U+3000）被删掉的位置按空格处理，中文夹在英文中间、没有半角空格时，英文单词也会分开：

- {/* slug-check: {"in":"Hello　World"} */}`Hello　World`（中间是全角空格）→ `hello-world`
- {/* slug-check: {"in":"Vue3入门Vite教程"} */}`Vue3入门Vite教程` → `vue3-vite`


<h2>字符映射</h2>

<h2>限制</h2>
<ul>
  <li>去掉附加符号时不按语言区分：德语 <code>{"ä ö ü"}</code> 变成 <code>{"a o u"}</code>（不是 <code>{"ae oe ue"}</code>），土耳其语 <code>{"İ"}</code> 变成 <code>{"I"}</code>。</li>
  <li>非拉丁文字会被删除，只输入中文、日文或韩文时结果为空。</li>
  <li>夹在两个字母之间的撇号（<code>{"'"}</code>、<code>{"’"}</code>、<code>{"ʼ"}</code>）直接删除：{/* slug-check: {"in":"John's Guide"} */}<code>{"John's Guide"}</code> → <code>{"johns-guide"}</code>；旁边是空格、数字或文字开头结尾时，撇号当作分隔符：{/* slug-check: {"in":"rock 'n' roll"} */}<code>{"rock 'n' roll"}</code> → <code>{"rock-n-roll"}</code>。</li>
  <li>关闭「修剪」时，开头和结尾的分隔符会保留：<code>{"Hello World!"}</code> → <code>{"hello-world-"}</code>。</li>
  <li>不做拼音转写，也不按汉字读音生成单词。</li>
  <li>不删除 a、the、of 这类虚词，也没有长度上限，长标题会得到长 slug；如果 CMS 限制 slug 长度，请手动截短。</li>
  <li>一次只转换一段文字，换行按空格处理，粘贴多行标题会得到一个很长的 slug。</li>
  <li><code>#</code> 换成单词 <code>hash</code>，所以 <code>{"C#"}</code> 得到 <code>{"c-hash"}</code>，不是 <code>{"c-sharp"}</code>；这类名称请先改写再转换。</li>
</ul>

<h2>Slug 的使用场景</h2>
<ul>
  <li><strong>博客文章 URL：</strong> <code>/blog/how-to-use-slugs</code></li>
  <li><strong>商品页面：</strong> <code>/products/red-running-shoes</code></li>
  <li><strong>文件名：</strong> <code>my-important-document.pdf</code></li>
  <li><strong>数据库键：</strong> 无空格的可读唯一标识符。</li>
</ul>
<p>
  一致的 Slug 生成策略可确保 URL 保持稳定且对 SEO 友好，即使原始标题在格式或标点上发生变化也不受影响。
</p>
