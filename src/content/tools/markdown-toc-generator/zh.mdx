<h2>使用步骤</h2>

<ol>
  <li>把 Markdown 粘贴到左侧输入区。</li>
  <li>在 <strong>锚点风格</strong> 里选目标平台：GitHub / Hugo、GitLab、Jekyll（kramdown GFM）、kramdown 或 Bitbucket Cloud。</li>
  <li>用 <strong>最小标题级别</strong> 与 <strong>最大标题级别</strong> 圈定要进 TOC 的层级范围。</li>
  <li>如果文档标题由模板单独渲染，关掉 <strong>包含 H1</strong>。</li>
  <li>直接复制生成的目录；或者打开 <strong>标记模式</strong>，得到带 <code>&lt;!-- toc --&gt;</code> 标记的完整 Markdown。</li>
</ol>

<h2>五种锚点风格</h2>

<p>工具提供五种锚点风格，按你的渲染器选择：</p>

<ul>
  <li><strong>GitHub / Hugo</strong>：转小写；保留字母、组合符号、数字、<code>{'_'}</code>、<code>-</code> 和空格；每个空格换成 <code>-</code>。连续空格变成连续连字符，首尾的连字符保留。这就是 <a href="https://github.com/Flet/github-slugger" target="_blank" rel="noopener">github-slugger</a> 2.0.0 的规则，工具以它为基准测试。Hugo 的 Goldmark 渲染器默认 <code>autoHeadingIDType: github</code>。</li>
  <li><strong>GitLab</strong>：规则相同，见 <a href="https://docs.gitlab.com/user/markdown/#heading-anchors" target="_blank" rel="noopener">GitLab 标题锚点文档</a>（GitLab 17.0 起）。连续连字符不合并：<code>a --- b</code> 变成 <code>a-----b</code>。</li>
  <li><strong>Jekyll（kramdown GFM）</strong>：Jekyll 默认 <code>input: GFM</code>，使用 <a href="https://github.com/kramdown/parser-gfm/blob/master/lib/kramdown/parser/gfm.rb" target="_blank" rel="noopener">kramdown-parser-gfm</a>，与 GitHub 一样保留 Unicode，另外把 Tab 也换成连字符，去重按每个基础名计数。</li>
  <li><strong>kramdown（input: kramdown）</strong>：kramdown 自己的解析器（<a href="https://github.com/gettalong/kramdown/blob/master/lib/kramdown/converter/base.rb" target="_blank" rel="noopener">basic_generate_id</a>）。先删掉第一个 ASCII 字母之前的字符，只保留 <code>a-z</code>、<code>0-9</code>、空格和连字符，什么都不剩时用 <code>section</code>。</li>
  <li><strong>Bitbucket Cloud</strong>：每个锚点以 <code>markdown-header-</code> 开头（Atlassian 问题 <a href="https://jira.atlassian.com/browse/BCLOUD-8276" target="_blank" rel="noopener">BCLOUD-8276</a>），重复项用 <code>_N</code>。Atlassian 没有公开其余规则，工具在前缀之后沿用 GitHub 规则。Bitbucket Data Center 不给标题加 id。</li>
</ul>

<h2>标记模式</h2>

<p>
  标记模式让 TOC 永远新鲜，又不动原文其它部分。
  在你想放目录的位置写两条 HTML 注释：
</p>

<pre><code>&lt;!-- toc --&gt;
&lt;!-- /toc --&gt;</code></pre>

<p>
  之后随时跑一遍生成器，两条注释之间的内容会被替换为新 TOC。
  如果文档还没有标记，工具会在第一个标题之前自动插入一段标记块，
  复制粘贴回去就能 commit。
</p>

<h2>实例</h2>

<h3>简单目录，GitHub 风格</h3>

<p>输入：</p>

```markdown
# API 参考

## 鉴权

### OAuth 流程

## 接口

### GET /users
### POST /users
```

<p>输出（GitHub 锚点，缩进 2 空格）：</p>

```markdown
- [API 参考](#api-参考)
  - [鉴权](#鉴权)
    - [OAuth 流程](#oauth-流程)
  - [接口](#接口)
    - [GET /users](#get-users)
    - [POST /users](#post-users)
```

<h3>重复标题</h3>

<p>两个 <code>## 示例</code> 在 GitHub / GitLab / Jekyll 下分别变成 <code>#示例</code> 和 <code>#示例-1</code>；Bitbucket Cloud 下变成 <code>#markdown-header-示例</code> 和 <code>#markdown-header-示例_1</code>；kramdown 风格下中文被删光，变成 <code>#section</code> 和 <code>#section-1</code>。</p>

<h3>跳过 H1</h3>

<p>如果你的静态站从 frontmatter 渲染 H1，关掉 <strong>包含 H1</strong>，TOC 会从第一个 H2 开始，整体缩进降一级。</p>

<h2>同一份文档，不同平台</h2>

<p>这份文档有重复的 <code>### Examples</code>、标点和一个中文标题。最小级别 2、最大级别 3 时：</p>

<pre><code>{`# Install Guide
## Requirements
### Examples
## Usage
### Examples
## Q&A: what's new?
## 安装 (Install)`}</code></pre>

<p>GitHub、GitLab 和 Jekyll（GFM）得到相同的目录：</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## 安装 (Install)","opts":{"style":"github","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [安装 (Install)](#安装-install)`}</code></pre>

<p>kramdown 风格下 <code>安装</code> 被删掉，只剩 <code>install</code>：</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## 安装 (Install)","opts":{"style":"kramdown","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [安装 (Install)](#install)`}</code></pre>

<p>Bitbucket Cloud 的 id 与 GitHub 相同，只是前面加了 <code>markdown-header-</code>，第二个 <code>Examples</code> 变成 <code>#markdown-header-examples_1</code>。</p>

<h2>限制</h2>

<ul>
  <li>工具读取 ATX（<code>#</code>）和 setext（<code>===</code>、<code>---</code>）标题，不读取用 HTML 写的标题（<code>&lt;h2&gt;</code>）。行内 Markdown 用简单规则去除，强调里套链接这类少见写法可能在目录文字里留下多余字符。</li>
  <li>不读取自定义 id（kramdown 和 Hugo 的 <code>## 标题 &#123;#custom-id&#125;</code>），工具只计算自动生成的 id。</li>
  <li>这里没有列出的渲染器（例如 VS Code）可能用不同规则。提交长目录前先点一个生成的链接确认。</li>
</ul>
