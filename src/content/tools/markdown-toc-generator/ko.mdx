<h2>다섯 가지 앵커 스타일</h2>

<p>앵커 스타일은 다섯 가지입니다. 쓰는 렌더러에 맞춰 고르세요.</p>

<ul>
  <li><strong>GitHub / Hugo</strong>: 소문자로 바꾸고, 문자·결합 부호·숫자·<code>{'_'}</code>·<code>-</code>·공백을 남기며, 공백 하나를 <code>-</code> 하나로 바꿉니다. 연속된 공백은 연속된 하이픈이 되고, 앞뒤 하이픈도 남습니다. <a href="https://github.com/Flet/github-slugger" target="_blank" rel="noopener">github-slugger</a> 2.0.0과 같은 규칙이며, 도구는 이것과 대조해 테스트합니다. Hugo의 Goldmark 렌더러는 기본값이 <code>autoHeadingIDType: github</code>입니다.</li>
  <li><strong>GitLab</strong>: 같은 규칙입니다(<a href="https://docs.gitlab.com/user/markdown/#heading-anchors" target="_blank" rel="noopener">GitLab 제목 앵커 문서</a>, GitLab 17.0 이후). 연속된 하이픈을 합치지 않으므로 <code>a --- b</code>는 <code>a-----b</code>가 됩니다.</li>
  <li><strong>Jekyll(kramdown GFM)</strong>: Jekyll의 기본값은 <code>input: GFM</code>이며 <a href="https://github.com/kramdown/parser-gfm/blob/master/lib/kramdown/parser/gfm.rb" target="_blank" rel="noopener">kramdown-parser-gfm</a>를 씁니다. GitHub처럼 Unicode를 남기고, 탭도 하이픈으로 바꾸며, 중복은 기본 이름별로 셉니다.</li>
  <li><strong>kramdown(input: kramdown)</strong>: kramdown 자체 파서(<a href="https://github.com/gettalong/kramdown/blob/master/lib/kramdown/converter/base.rb" target="_blank" rel="noopener">basic_generate_id</a>)입니다. 첫 ASCII 영문자 앞의 문자를 지우고 <code>a-z</code>, <code>0-9</code>, 공백, 하이픈만 남기며, 아무것도 남지 않으면 <code>section</code>을 씁니다.</li>
  <li><strong>Bitbucket Cloud</strong>: 모든 앵커가 <code>markdown-header-</code>로 시작하고(Atlassian 이슈 <a href="https://jira.atlassian.com/browse/BCLOUD-8276" target="_blank" rel="noopener">BCLOUD-8276</a>) 중복은 <code>_N</code>을 씁니다. 나머지 규칙은 공개되어 있지 않아 접두사 뒤에는 GitHub 규칙을 씁니다. Bitbucket Data Center는 제목에 id를 붙이지 않습니다.</li>
</ul>

<h2>마커 모드</h2>

<p>
  마커 모드는 목차를 항상 최신으로 유지하면서, 문서의 나머지 부분은 건드리지 않습니다.
  목차가 위치할 자리에 두 개의 HTML 주석을 미리 적어 두세요:
</p>

<pre><code>&lt;!-- toc --&gt;
&lt;!-- /toc --&gt;</code></pre>

<p>
  이후 생성기를 실행할 때마다 두 주석 사이의 내용이 새로운 TOC로 교체됩니다.
  아직 마커가 없다면 첫 제목 바로 앞에 새 마커 블록이 삽입되므로,
  결과를 복사해 commit하기만 하면 됩니다.
</p>

<h2>예제</h2>

<h3>간단한 목차, GitHub 스타일</h3>

<p>입력:</p>

```markdown
# API 레퍼런스

## 인증

### OAuth 흐름

## 엔드포인트

### GET /users
### POST /users
```

<p>출력 (GitHub 앵커, 들여쓰기 공백 2칸):</p>

```markdown
- [API 레퍼런스](#api-레퍼런스)
  - [인증](#인증)
    - [OAuth 흐름](#oauth-흐름)
  - [엔드포인트](#엔드포인트)
    - [GET /users](#get-users)
    - [POST /users](#post-users)
```

<h3>중복된 제목</h3>

<p><code>## 예제</code>가 두 번 나오면 GitHub / GitLab / Jekyll에서는 <code>#예제</code>와 <code>#예제-1</code>, Bitbucket Cloud에서는 <code>#markdown-header-예제</code>와 <code>#markdown-header-예제_1</code>이 됩니다. kramdown 스타일에서는 한글이 지워져 <code>#section</code>과 <code>#section-1</code>이 됩니다.</p>

<h3>H1 제외</h3>

<p>정적 사이트가 frontmatter에서 H1을 렌더링한다면 <strong>H1 포함</strong>을 끄세요. TOC는 첫 H2부터 시작하고 들여쓰기가 한 단계씩 얕아집니다.</p>

<h2>같은 문서, 다른 플랫폼</h2>

<p>이 문서에는 중복된 <code>### Examples</code>, 문장 부호, 한글 제목이 있습니다. 최소 레벨 2, 최대 레벨 3일 때:</p>

<pre><code>{`# Install Guide
## Requirements
### Examples
## Usage
### Examples
## Q&A: what's new?
## 설치 (Install)`}</code></pre>

<p>GitHub, GitLab, Jekyll(GFM)은 같은 목차를 만듭니다.</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## 설치 (Install)","opts":{"style":"github","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [설치 (Install)](#설치-install)`}</code></pre>

<p>kramdown 스타일에서는 <code>설치</code>가 지워지고 <code>install</code>만 남습니다.</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## 설치 (Install)","opts":{"style":"kramdown","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [설치 (Install)](#install)`}</code></pre>

<p>Bitbucket Cloud는 GitHub과 같은 id 앞에 <code>markdown-header-</code>를 붙이고, 두 번째 <code>Examples</code>는 <code>#markdown-header-examples_1</code>이 됩니다.</p>

<h2>제한</h2>

<ul>
  <li>ATX(<code>#</code>)와 setext(<code>===</code>, <code>---</code>) 제목을 읽으며, HTML로 쓴 제목(<code>&lt;h2&gt;</code>)은 읽지 않습니다. 인라인 Markdown은 단순한 규칙으로 지우므로, 강조 안의 링크 같은 드문 구조에서는 목차 문구에 남는 기호가 있을 수 있습니다.</li>
  <li>사용자 지정 id(kramdown과 Hugo의 <code>## 제목 &#123;#custom-id&#125;</code>)는 읽지 않고, 자동 생성 id를 계산합니다.</li>
  <li>여기 없는 렌더러(VS Code 등)는 규칙이 다를 수 있습니다. 긴 목차를 커밋하기 전에 생성된 링크 하나를 열어 확인하세요.</li>
</ul>
