<h2>How to Use</h2>

<ol>
  <li>Paste your Markdown into the input area.</li>
  <li>Pick the <strong>Anchor style</strong> matching your target platform: GitHub / Hugo, GitLab, Jekyll (kramdown GFM), kramdown or Bitbucket Cloud.</li>
  <li>Adjust <strong>Min</strong> and <strong>Max</strong> heading levels to control which headings appear in the TOC.</li>
  <li>Toggle <strong>Include H1</strong> off if your document title is rendered separately.</li>
  <li>Copy the generated TOC, or enable <strong>Marker mode</strong> to get the full Markdown with the TOC inserted between <code>&lt;!-- toc --&gt;</code> markers.</li>
</ol>

<h2>Anchor Styles</h2>

<p>The tool ships with five anchor styles. Pick the one that matches your renderer:</p>

<ul>
  <li><strong>GitHub / Hugo</strong>: lowercase; keep letters, marks, digits, <code>{'_'}</code>, <code>-</code> and spaces; turn each space into <code>-</code>. Runs of spaces become runs of hyphens and leading or trailing hyphens stay. This is <a href="https://github.com/Flet/github-slugger" target="_blank" rel="noopener">github-slugger</a> 2.0.0, which the tool is tested against. Hugo's Goldmark renderer uses <code>autoHeadingIDType: github</code> by default.</li>
  <li><strong>GitLab</strong>: the same rules, as listed in <a href="https://docs.gitlab.com/user/markdown/#heading-anchors" target="_blank" rel="noopener">GitLab's heading anchor docs</a> (GitLab 17.0 and later). Repeated hyphens are kept: <code>a --- b</code> becomes <code>a-----b</code>.</li>
  <li><strong>Jekyll (kramdown GFM)</strong>: Jekyll's default <code>input: GFM</code> uses <a href="https://github.com/kramdown/parser-gfm/blob/master/lib/kramdown/parser/gfm.rb" target="_blank" rel="noopener">kramdown-parser-gfm</a>, which keeps Unicode like GitHub, also turns tabs into hyphens, and de-duplicates by counting each base name.</li>
  <li><strong>kramdown (input: kramdown)</strong>: kramdown's own parser (<a href="https://github.com/gettalong/kramdown/blob/master/lib/kramdown/converter/base.rb" target="_blank" rel="noopener">basic_generate_id</a>). It drops leading characters until the first ASCII letter, keeps only <code>a-z</code>, <code>0-9</code>, spaces and hyphens, and uses <code>section</code> when nothing is left.</li>
  <li><strong>Bitbucket Cloud</strong>: every anchor starts with <code>markdown-header-</code> (Atlassian issue <a href="https://jira.atlassian.com/browse/BCLOUD-8276" target="_blank" rel="noopener">BCLOUD-8276</a>) and duplicates use <code>_N</code>. Atlassian does not document the rest of the rules, so the tool applies the GitHub rules after the prefix. Bitbucket Data Center does not add heading ids.</li>
</ul>

<h2>Marker Mode</h2>

<p>
  Marker mode keeps your TOC fresh without touching the rest of the document.
  Wrap the spot you want the TOC to live with two HTML comments:
</p>

<pre><code>&lt;!-- toc --&gt;
&lt;!-- /toc --&gt;</code></pre>

<p>
  Run the generator any time and the block between the two comments is replaced
  with a new TOC. If your document has no markers yet, the tool inserts a fresh
  block right before the first heading and you can commit the result.
</p>

<h2>Worked Examples</h2>

<h3>Simple TOC, GitHub style</h3>

<p>Input:</p>

```markdown
# API Reference

## Authentication

### OAuth Flow

## Endpoints

### GET /users
### POST /users
```

<p>Output (GitHub anchors, 2-space indent):</p>

```markdown
- [API Reference](#api-reference)
  - [Authentication](#authentication)
    - [OAuth Flow](#oauth-flow)
  - [Endpoints](#endpoints)
    - [GET /users](#get-users)
    - [POST /users](#post-users)
```

<h3>Duplicate headings</h3>

<p>Two sections named <code>## Examples</code> become <code>#examples</code> and <code>#examples-1</code> on GitHub, GitLab, Jekyll and kramdown, or <code>#markdown-header-examples</code> and <code>#markdown-header-examples_1</code> on Bitbucket Cloud.</p>

<h3>Skipping H1</h3>

<p>If your static site renders the H1 from frontmatter, turn off <strong>Include H1</strong> so the TOC starts at the first H2 and indentation flattens by one level.</p>

<h2>One Document, Different Platforms</h2>

<p>This document has a repeated <code>### Examples</code>, punctuation and a heading in Chinese. With min level 2 and max level 3:</p>

<pre><code>{`# Install Guide
## Requirements
### Examples
## Usage
### Examples
## Q&A: what's new?
## 安装 (Install)`}</code></pre>

<p>GitHub, GitLab and Jekyll (GFM) give the same TOC:</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## 安装 (Install)","opts":{"style":"github","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [安装 (Install)](#安装-install)`}</code></pre>

<p>With the kramdown style, <code>安装</code> is dropped and only <code>install</code> is left:</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## 安装 (Install)","opts":{"style":"kramdown","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [安装 (Install)](#install)`}</code></pre>

<p>Bitbucket Cloud gives the same ids as GitHub with <code>markdown-header-</code> in front, and the second <code>Examples</code> becomes <code>#markdown-header-examples_1</code>.</p>

<h2>Limits</h2>

<ul>
  <li>The tool reads ATX (<code>#</code>) and setext (<code>===</code>, <code>---</code>) headings. It does not read headings written as HTML (<code>&lt;h2&gt;</code>), and it removes inline Markdown with simple patterns, so unusual nesting such as a link inside emphasis can leave stray characters in the label.</li>
  <li>Custom ids (<code>## Title &#123;#custom-id&#125;</code> in kramdown and Hugo) are not read; the tool computes the automatic id.</li>
  <li>Hugo, VS Code and other renderers that are not listed here can use different rules. Check one generated link before you commit a long TOC.</li>
</ul>
