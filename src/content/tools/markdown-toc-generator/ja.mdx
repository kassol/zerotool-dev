<h2>5 つのアンカー形式</h2>

<p>アンカー形式は 5 種類あります。使うレンダラーに合わせて選んでください。</p>

<ul>
  <li><strong>GitHub / Hugo</strong>：小文字化し、文字・結合記号・数字・<code>{'_'}</code>・<code>-</code>・空白を残して、空白 1 つを <code>-</code> 1 つに変えます。連続した空白は連続したハイフンになり、先頭や末尾のハイフンも残ります。<a href="https://github.com/Flet/github-slugger" target="_blank" rel="noopener">github-slugger</a> 2.0.0 と同じ規則で、ツールはこれと照合してテストしています。Hugo の Goldmark レンダラーは既定で <code>autoHeadingIDType: github</code> です。</li>
  <li><strong>GitLab</strong>：同じ規則です（<a href="https://docs.gitlab.com/user/markdown/#heading-anchors" target="_blank" rel="noopener">GitLab の見出しアンカーの説明</a>、GitLab 17.0 以降）。連続したハイフンはまとめません。<code>a --- b</code> は <code>a-----b</code> になります。</li>
  <li><strong>Jekyll（kramdown GFM）</strong>：Jekyll の既定は <code>input: GFM</code> で、<a href="https://github.com/kramdown/parser-gfm/blob/master/lib/kramdown/parser/gfm.rb" target="_blank" rel="noopener">kramdown-parser-gfm</a> を使います。GitHub と同じく Unicode を残し、タブもハイフンにします。重複は基本名ごとに数えます。</li>
  <li><strong>kramdown（input: kramdown）</strong>：kramdown 独自のパーサー（<a href="https://github.com/gettalong/kramdown/blob/master/lib/kramdown/converter/base.rb" target="_blank" rel="noopener">basic_generate_id</a>）です。最初の ASCII 英字より前の文字を削除し、<code>a-z</code>・<code>0-9</code>・空白・ハイフンだけを残します。何も残らなければ <code>section</code> になります。</li>
  <li><strong>Bitbucket Cloud</strong>：すべてのアンカーが <code>markdown-header-</code> で始まり（Atlassian の課題 <a href="https://jira.atlassian.com/browse/BCLOUD-8276" target="_blank" rel="noopener">BCLOUD-8276</a>）、重複は <code>_N</code> です。それ以外の規則は公開されていないため、プレフィックスの後は GitHub の規則を使います。Bitbucket Data Center は見出しに id を付けません。</li>
</ul>

<h2>マーカーモード</h2>

<p>
  マーカーモードは目次を常に最新に保ちつつ、本文の他の部分には触れません。
  目次を置きたい場所に 2 つの HTML コメントを書いておきます：
</p>

<pre><code>&lt;!-- toc --&gt;
&lt;!-- /toc --&gt;</code></pre>

<p>
  あとはジェネレーターを実行するたび、2 つのコメント間の内容が新しい TOC に置換されます。
  マーカーがまだ無い場合は、最初の見出しの直前に新しいマーカー付きブロックが挿入されるので、
  コピーして commit するだけで運用に乗ります。
</p>

<h2>実例</h2>

<h3>シンプルな目次（GitHub 形式）</h3>

<p>入力：</p>

```markdown
# API リファレンス

## 認証

### OAuth フロー

## エンドポイント

### GET /users
### POST /users
```

<p>出力（GitHub アンカー、インデント半角スペース 2）：</p>

```markdown
- [API リファレンス](#api-リファレンス)
  - [認証](#認証)
    - [OAuth フロー](#oauth-フロー)
  - [エンドポイント](#エンドポイント)
    - [GET /users](#get-users)
    - [POST /users](#post-users)
```

<h3>重複した見出し</h3>

<p>2 つの <code>## 例</code> は GitHub / GitLab / Jekyll では <code>#例</code> と <code>#例-1</code>、Bitbucket Cloud では <code>#markdown-header-例</code> と <code>#markdown-header-例_1</code> になります。kramdown 形式では日本語が削除され、<code>#section</code> と <code>#section-1</code> になります。</p>

<h3>H1 を除外する</h3>

<p>静的サイトが H1 を frontmatter から描画している場合は <strong>H1 を含む</strong> をオフにします。TOC は最初の H2 から始まり、インデントが 1 段階浅くなります。</p>

<h2>同じ文書をプラットフォームごとに</h2>

<p>この文書には重複した <code>### Examples</code>、記号、日本語の見出しがあります。最小レベル 2、最大レベル 3 のとき：</p>

<pre><code>{`# Install Guide
## Requirements
### Examples
## Usage
### Examples
## Q&A: what's new?
## インストール (Install)`}</code></pre>

<p>GitHub・GitLab・Jekyll（GFM）では同じ目次になります。</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## インストール (Install)","opts":{"style":"github","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [インストール (Install)](#インストール-install)`}</code></pre>

<p>kramdown 形式では <code>インストール</code> が削除され、<code>install</code> だけが残ります。</p>

{/* mtoc: {"md":"# Install Guide\n## Requirements\n### Examples\n## Usage\n### Examples\n## Q&A: what's new?\n## インストール (Install)","opts":{"style":"kramdown","minLevel":2,"maxLevel":3}} */}
<pre><code>{`- [Requirements](#requirements)
  - [Examples](#examples)
- [Usage](#usage)
  - [Examples](#examples-1)
- [Q&A: what's new?](#qa-whats-new)
- [インストール (Install)](#install)`}</code></pre>

<p>Bitbucket Cloud は GitHub と同じ id の前に <code>markdown-header-</code> を付け、2 つ目の <code>Examples</code> は <code>#markdown-header-examples_1</code> になります。</p>

<h2>制限</h2>

<ul>
  <li>読み取るのは ATX（<code>#</code>）と setext（<code>===</code>、<code>---</code>）の見出しで、HTML で書いた見出し（<code>&lt;h2&gt;</code>）は読みません。インラインの Markdown は単純な規則で取り除くため、強調の中のリンクのような珍しい書き方では目次の文字に余分な記号が残ることがあります。</li>
  <li>独自 id（kramdown と Hugo の <code>## 見出し &#123;#custom-id&#125;</code>）は読みません。ツールは自動生成される id を計算します。</li>
  <li>ここにないレンダラー（VS Code など）は規則が違うことがあります。長い目次をコミットする前に、生成したリンクを 1 つ開いて確かめてください。</li>
</ul>
