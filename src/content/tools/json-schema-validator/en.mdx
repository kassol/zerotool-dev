<h2>JSON Schema Validator Online</h2>
<p>
  Use this JSON Schema validator to check JSON data against a Draft-07 or Draft 2020-12 schema directly in your browser.
  It is useful for validating API payloads, configuration files, webhook examples, test fixtures, and generated JSON before you ship them.
</p>
<ul>
  <li><strong>Schema validation, not just syntax:</strong> check required fields, types, enum values, number ranges, string lengths, regex patterns, nested arrays, and object shapes.</li>
  <li><strong>Precise error paths:</strong> see where validation failed, such as <code>/items/0/name</code> or <code>(root)</code>.</li>
  <li><strong>Client-side privacy:</strong> validation runs locally with AJV; your JSON and schema are not uploaded.</li>
</ul>

<h2>How to Use</h2>
<ol>
  <li>Paste your <strong>JSON Schema</strong> on the left and your <strong>JSON Data</strong> on the right.</li>
  <li>Select the schema draft (Draft-07 or Draft 2020-12) from the dropdown.</li>
  <li>Click <strong>Validate</strong> (or press <kbd>Ctrl</kbd>+<kbd>Enter</kbd>).</li>
  <li>If valid, a green message confirms the data matches the schema.</li>
  <li>If invalid, each error is listed with its <strong>JSON path</strong>, error message, and additional parameters.</li>
</ol>

<p>Click <strong>Load Example</strong> to populate both panels with a sample User schema and matching JSON for a quick demo.</p>

<h2>Reading the Error Output</h2>

<p>Each validation error shows three things:</p>
<ul>
  <li><strong>Path</strong> — the JSON Pointer to the failing value (e.g. <code>/items/0/price</code> or <code>(root)</code> for the top level).</li>
  <li><strong>Message</strong> — a plain-English description from AJV (e.g. <em>must be integer</em>, <em>must have required property 'name'</em>).</li>
  <li><strong>Parameters</strong> — additional context such as the allowed types, minimum value, or pattern that was required.</li>
</ul>

<h2>Common JSON Schema Keywords</h2>
<ul>
  <li><code>type</code> — restrict to a JSON type: <code>string</code>, <code>number</code>, <code>integer</code>, <code>boolean</code>, <code>array</code>, <code>object</code>, <code>null</code>.</li>
  <li><code>required</code> — array of property names that must be present in an object.</li>
  <li><code>properties</code> — define constraints for each named property of an object.</li>
  <li><code>additionalProperties: false</code> — reject any property not listed in <code>properties</code>.</li>
  <li><code>minimum</code> / <code>maximum</code> — numeric range constraints.</li>
  <li><code>minLength</code> / <code>maxLength</code> — string length constraints.</li>
  <li><code>pattern</code> — validate a string against a regex (e.g. <code>"^[a-z]+"</code>).</li>
  <li><code>enum</code> — restrict to a fixed set of values.</li>
  <li><code>format</code> — check a string format such as <code>email</code>, <code>date</code>, or <code>uuid</code> (see below).</li>
  <li><code>items</code> — define the schema for array elements.</li>
</ul>

<h2>Format Validation</h2>
<p>This validator checks the <code>format</code> keyword in both Draft-07 and Draft 2020-12 for these formats (implemented by <a href="https://github.com/ajv-validator/ajv-formats" rel="noopener">ajv-formats</a>): <code>email</code>, <code>uri</code>, <code>uri-reference</code>, <code>uri-template</code>, <code>date</code>, <code>time</code>, <code>date-time</code>, <code>duration</code>, <code>hostname</code>, <code>ipv4</code>, <code>ipv6</code>, <code>uuid</code>, <code>json-pointer</code>, <code>relative-json-pointer</code>, <code>regex</code>. A value that does not match fails with <em>must match format "email"</em>.</p>
<ul>
  <li>Other formats (<code>idn-email</code>, <code>idn-hostname</code>, <code>iri</code>, <code>iri-reference</code>, and custom names) are not checked; they are accepted without an error.</li>
  <li><code>format</code> applies to strings only. A number with <code>"format": "email"</code> passes.</li>
  <li>Other validators can give a different result for the same schema. <a href="https://json-schema.org/draft/2020-12/json-schema-validation" rel="noopener">JSON Schema 2020-12</a> (Validation, section 7.2) makes <code>format</code> an annotation by default, and checking it is optional; <a href="https://json-schema.org/draft-07/json-schema-validation" rel="noopener">Draft-07</a> (section 7.2) also lets a validator choose. If your production validator does not check formats, data that fails here can pass there.</li>
  <li><code>date-time</code> and <code>time</code> need a time zone (<code>Z</code> or <code>+09:00</code>), as in RFC 3339.</li>
</ul>

<h2>Example Schema</h2>

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["name", "age"],
  "properties": {
    "name":  { "type": "string", "minLength": 1 },
    "age":   { "type": "integer", "minimum": 0 },
    "email": { "type": "string" }
  },
  "additionalProperties": false
}
```

<p>Valid data: <code>{'{"name":"Alice","age":30}'}</code><br />
Invalid data: <code>{'{"name":"","age":-1,"extra":true}'}</code> — would produce three errors.</p>
