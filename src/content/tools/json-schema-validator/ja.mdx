<h2>使い方</h2>
<ol>
  <li>左側に <strong>JSONスキーマ</strong>、右側に <strong>JSONデータ</strong>を貼り付けます。</li>
  <li>ドロップダウンからスキーマドラフト（Draft-07またはDraft 2020-12）を選択します。</li>
  <li><strong>Validate</strong> ボタンをクリックします（または <kbd>Ctrl</kbd>+<kbd>Enter</kbd>）。</li>
  <li>有効な場合、データがスキーマに適合していることを示す緑のメッセージが表示されます。</li>
  <li>無効な場合、各エラーの <strong>JSONパス</strong>・エラーメッセージ・追加パラメータが一覧表示されます。</li>
</ol>

<p><strong>Load Example</strong> をクリックすると、サンプルのUserスキーマとJSONが自動入力され、すぐに試せます。</p>

<h2>エラー出力の見方</h2>

<p>各バリデーションエラーは3つの情報を含みます：</p>
<ul>
  <li><strong>パス</strong> — 失敗した値へのJSONポインター（例：<code>/items/0/price</code>、トップレベルは<code>(root)</code>）。</li>
  <li><strong>メッセージ</strong> — AJVによる分かりやすいエラー説明（例：<em>must be integer</em>、<em>must have required property 'name'</em>）。</li>
  <li><strong>パラメータ</strong> — 許可される型・最小値・必要なパターンなどの追加情報。</li>
</ul>

<h2>よく使うJSONスキーマのキーワード</h2>
<ul>
  <li><code>type</code> — JSONの型を制限：<code>string</code>・<code>number</code>・<code>integer</code>・<code>boolean</code>・<code>array</code>・<code>object</code>・<code>null</code>。</li>
  <li><code>required</code> — オブジェクトに必須のプロパティ名の配列。</li>
  <li><code>properties</code> — オブジェクトの各プロパティの制約を定義。</li>
  <li><code>additionalProperties: false</code> — <code>properties</code>に定義されていないプロパティを拒否。</li>
  <li><code>minimum</code> / <code>maximum</code> — 数値の範囲制約。</li>
  <li><code>minLength</code> / <code>maxLength</code> — 文字列の長さ制約。</li>
  <li><code>pattern</code> — 正規表現で文字列を検証（例：<code>"^[a-z]+"</code>）。</li>
  <li><code>enum</code> — 固定の値セットに制限。</li>
  <li><code>format</code> — <code>email</code>、<code>date</code>、<code>uuid</code> などの文字列形式を検証（下記参照）。</li>
  <li><code>items</code> — 配列要素のスキーマを定義。</li>
</ul>

<h2>format の検証</h2>
<p>このツールは Draft-07 と Draft 2020-12 のどちらでも <code>format</code> キーワードを検証します。対象の形式は次のとおりです（<a href="https://github.com/ajv-validator/ajv-formats" rel="noopener">ajv-formats</a> が実装）：<code>email</code>、<code>uri</code>、<code>uri-reference</code>、<code>uri-template</code>、<code>date</code>、<code>time</code>、<code>date-time</code>、<code>duration</code>、<code>hostname</code>、<code>ipv4</code>、<code>ipv6</code>、<code>uuid</code>、<code>json-pointer</code>、<code>relative-json-pointer</code>、<code>regex</code>。適合しない値は <em>must match format "email"</em> のエラーになります。</p>
<ul>
  <li>それ以外の形式（<code>idn-email</code>、<code>idn-hostname</code>、<code>iri</code>、<code>iri-reference</code>、独自の名前）は検証せず、そのまま通します。</li>
  <li><code>format</code> は文字列にだけ適用されます。数値に <code>"format": "email"</code> を指定しても通ります。</li>
  <li>同じスキーマでも、他のバリデーターでは結果が変わることがあります。<a href="https://json-schema.org/draft/2020-12/json-schema-validation" rel="noopener">JSON Schema 2020-12</a>（Validation 7.2 節）では <code>format</code> は既定で注釈で、検証は任意です。<a href="https://json-schema.org/draft-07/json-schema-validation" rel="noopener">Draft-07</a>（7.2 節）も実装に選択を任せています。本番のバリデーターが format を検証しない場合、ここで失敗するデータがそちらでは通ることがあります。</li>
  <li><code>date-time</code> と <code>time</code> には RFC 3339 のとおりタイムゾーン（<code>Z</code> や <code>+09:00</code>）が必要です。</li>
</ul>

<h2>スキーマの例</h2>

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["name", "age"],
  "properties": {
    "name":  { "type": "string", "minLength": 1 },
    "age":   { "type": "integer", "minimum": 0 },
    "email": { "type": "string" }
  },
  "additionalProperties": false
}
```

<p>有効なデータ：<code>{'{"name":"Alice","age":30}'}</code><br />
無効なデータ：<code>{'{"name":"","age":-1,"extra":true}'}</code> — 3つのエラーが発生します。</p>
