## 예시: 서울 열린데이터광장 대기환경 API

서울 열린데이터광장의 실시간 대기환경 API(`RealtimeCityAir`)는 샘플 인증키로도 JSON을 돌려줍니다. 2026-10-02 11시 측정분에서 중구 한 행만 가져와 정렬해 보았습니다.

{/* jf: {"opts":{}} */}
```json
{"MSRMT_DT":"202610021100","MSRSTN_NM":"중구","PM":20.0,"FPM":5.0,"OZON":0.034,"CAI_GRD":"보통","CAI_IDX":53.0}
```

공백 2칸으로 정렬한 결과:

```json
{
  "MSRMT_DT": "202610021100",
  "MSRSTN_NM": "중구",
  "PM": 20.0,
  "FPM": 5.0,
  "OZON": 0.034,
  "CAI_GRD": "보통",
  "CAI_IDX": 53.0
}
```

미세먼지(PM)와 통합대기환경지수(CAI_IDX)가 응답에 쓰인 대로 20.0, 53.0으로 남습니다. 「숫자」를 「JavaScript가 읽는 값」으로 바꾸면 브라우저 코드가 받는 값으로 씁니다.

{/* jf: {"opts":{"numbers":"js","indent":""}} */}
```json
{"MSRMT_DT":"202610021100","MSRSTN_NM":"중구","PM":20.0,"FPM":5.0,"OZON":0.034,"CAI_GRD":"보통","CAI_IDX":53.0}
```

JavaScript가 읽는 값(압축):

```json
{"MSRMT_DT":"202610021100","MSRSTN_NM":"중구","PM":20,"FPM":5,"OZON":0.034,"CAI_GRD":"보통","CAI_IDX":53}
```

20.0과 20은 같은 값이므로 안내는 나오지 않습니다. 반면 2^53 − 1(9,007,199,254,740,991)을 넘는 정수는 값 자체가 바뀌므로, 「쓰인 그대로」에서도 바뀌는 숫자를 안내에 나열합니다. [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) 6절은 숫자를 IEEE 754 배정밀도로 읽는 소프트웨어와는 −(2^53 − 1)부터 2^53 − 1까지의 정수만 확실히 주고받을 수 있다고 설명합니다. 19자리 주문 번호처럼 큰 ID는 문자열로 보내는 것이 안전합니다.

## 중복 키

[RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) 4절은 객체 안의 이름이 고유해야 한다(SHOULD)고 하며, 중복되었을 때의 동작은 구현마다 다르다고 적고 있습니다. 설정 파일을 합치다 보면 같은 키가 두 번 들어가기 쉽습니다.

{/* jf: {"opts":{"indent":""}} */}
```json
{"user_id":42,"plan":"free","plan":"pro"}
```

「모두 유지」(기본값)에서는 두 항목이 그대로 남고, 안내에 두 번째 plan의 위치가 나옵니다.

```json
{"user_id":42,"plan":"free","plan":"pro"}
```

JSON.parse, jq, Python은 마지막 값만 남기므로 실제 프로그램이 읽는 값은 "pro"입니다. 「마지막만 유지」를 고르면 그 결과와 같아집니다.

## 오류 메시지

오류가 나면 상태 줄에 원인을 쓰고, 출력란에 앞 줄·오류가 난 줄·위치 표시를 보여 줍니다. Python 딕셔너리를 그대로 붙여넣은 경우:

{/* jf: {"error":{"code":"singleQuote","line":1,"col":2}} */}
```json
{'name': '홍길동', 'active': True}
```

상태 줄은 「1행 2열: JSON 문자열과 속성 이름은 큰따옴표(")로 감쌉니다」입니다.

```text
1 | {'name': '홍길동', 'active': True}
  |  ^
```

| 입력 | 메시지 |
|---|---|
| `{"a":1,}` | 닫는 괄호 앞에 쉼표가 남아 있습니다 |
| `{a: 1}` | 속성 이름은 큰따옴표로 감싸야 합니다 |
| `{"ok": True}` | 알 수 없는 단어입니다. JSON에는 true, false, null만 있습니다 (True는 Python 표기라는 안내 포함) |
| `[01]` | 숫자 형식이 잘못되었습니다 |
| `{"a":1} // 메모` | JSON에는 주석을 쓸 수 없습니다 |

JSON에 가까운 입력에는 한 번에 고치는 버튼이 나옵니다. Markdown 코드 블록(```)에 든 JSON(AI 채팅 답변에서 흔함), 문자열로 이스케이프된 JSON(로그의 `{\"a\":1}`), JSON을 담은 문자열 하나가 해당합니다. 한 줄에 값이 하나씩 있는 JSON Lines에는 [JSONL 변환기](/ko/tools/jsonl-converter/) 링크를 보여 줍니다. VS Code의 `settings.json`처럼 주석과 끝 쉼표가 있는 [JSON with Comments](https://code.visualstudio.com/docs/languages/json#_json-with-comments)는 「JSON5 / JSONC 허용」으로 변환할 수 있으며, [JSON5](https://spec.json5.org/) 규칙으로 읽습니다.

## EUC-KR 파일

RFC 8259 8.1절은 주고받는 JSON에 UTF-8을 요구합니다. Windows에서 「ANSI」로 저장한 한글 파일은 EUC-KR(CP949)이어서 「홍길동」이 C8 AB B1 E6 B5 BF 6바이트가 되고, UTF-8로는 잘못된 바이트열입니다. 이 도구로 열면 「파일이 UTF-8이 아닙니다: N번째 바이트부터 잘못된 바이트열입니다」라고 알려 주고, 깨진 글자를 그대로 정렬하지 않습니다. UTF-8로 다시 저장하세요. BOM이 있는 UTF-16 파일은 변환해서 읽고 그 사실을 알려 줍니다. 맨 앞의 BOM(U+FEFF)은 JSON.parse가 오류로 처리하므로 제거합니다.

## 다른 도구와의 차이

2026-10-02 데스크톱 Chromium에서 `{"id":12345678901234567890,"price":19.90,"big":1e400,"z":-0,"a":1,"a":2}`와 오류가 있는 입력으로 확인했습니다. 테스트하는 동안 어느 사이트도 JSON을 서버로 보내지 않았습니다.

- **비볼디(vivoldi.com, Bing에서 「json 정렬」 상위)**: 결과는 12345678901234567000, 19.9, null, 0이 되고 중복된 `a`는 2만 남으며 안내가 없습니다. 오류 메시지는 「Property Name Error on line 2, Column 3」처럼 영어로 나오고, 오른쪽 결과 창에는 이전 입력의 결과가 그대로 남아 있어 지금 입력이 잘못되었는지 헷갈립니다.
- **jsonformatter.org**: 숫자와 중복 키를 같은 방식으로 바꿉니다.
- **이 도구**: 숫자를 그대로 출력하고 바뀌는 값은 안내에 나열하며, 중복 키는 모두 남기고 위치를 보여 줍니다. 입력이 잘못되면 이전 결과 대신 오류 위치를 표시합니다.

`python3 -m json.tool`과도 비교했습니다. Python은 기본적으로 한글을 `\ud64d\uae38\ub3d9`처럼 바꾸지만 이 도구는 그대로 둡니다. 「비 ASCII 이스케이프」를 켜고 공백 4칸으로 하면 Python 3.12와 같은 출력이 나오고, 「키 정렬」은 `jq -S`, `--sort-keys`와 같은 유니코드 코드 포인트 순서입니다. 테스트 스크립트는 매번 무작위 문서 400개를 jq 1.7.1과, 120개를 Python 3.12와 비교합니다(버전이 다르면 건너뜀).
