<h2>JSON 포매팅에 대하여</h2>
<p>JSON(JavaScript Object Notation)은 가장 널리 사용되는 데이터 교환 형식입니다. 포매터는 들여쓰기를 추가하여 중첩 구조를 읽기 쉽게 하고, 압축 도구는 공백을 제거하여 데이터 크기를 줄입니다. 아래 '제한 사항'에 적은 경우를 빼면 두 작업 모두 해석된 데이터를 바꾸지 않습니다.</p>
<p>이 도구는 브라우저에서 완전히 동작하며, 데이터가 기기 밖으로 나가는 일은 없습니다.</p>

## 자주 나는 오류와 표시되는 메시지

이 도구는 브라우저의 `JSON.parse`로 입력을 해석하므로, "유효하지 않은 JSON:" 뒤의 오류 문구는 브라우저가 낸 것입니다. 흔한 실수에 대해 Chrome이 보여 주는 메시지는 아래와 같습니다. Firefox와 Safari는 문구가 다릅니다.

| 입력 | 문제 | Chrome 메시지 | 고치는 법 |
|---|---|---|---|
| `{"a":1,}` | 끝에 남은 쉼표 | `Expected double-quoted property name in JSON at position 7 (line 1 column 8)` | 마지막 쉼표 삭제 |
| `{'a':'b'}` | 작은따옴표 | `Expected property name or '}' in JSON at position 1 (line 1 column 2)` | 큰따옴표 사용 |
| `{a: 1}` | 따옴표 없는 키 | `Expected property name or '}' in JSON at position 1 (line 1 column 2)` | 키를 큰따옴표로 감싸기 |
| `{"x": undefined}` | `undefined`는 JSON 값이 아님 | `Unexpected token 'u', ... is not valid JSON` | `null`로 바꾸기 |
| `{"a":1} // 메모` | 주석 | `Unexpected non-whitespace character after JSON at position 8` | 주석 삭제. [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)에는 주석 문법이 없음 |

## 제한 사항

- **큰 정수는 정밀도를 잃습니다.** 숫자는 JavaScript 배정밀도 부동소수점으로 바뀌므로 2^53 − 1보다 큰 정수는 값이 달라집니다. `{"id": 12345678901234567890}`은 `{"id": 12345678901234567000}`으로 포맷됩니다. 긴 ID는 문자열로 두세요.
- **중복 키는 마지막 값만 남습니다.** `{"a":1,"a":2}`는 `{"a":2}`가 됩니다.
- **숫자 표기가 바뀝니다.** `1.0`은 `1`, `1e3`은 `1000`이 됩니다.
- **들여쓰기는 2칸으로 고정입니다.**
