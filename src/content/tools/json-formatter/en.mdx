## What Formatting Keeps and What It Rewrites

The formatter reads the text with its own parser, written to [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) and tested against all 318 files of [JSONTestSuite](https://github.com/nst/JSONTestSuite): it accepts the same documents as `JSON.parse`. It differs from a `JSON.parse` + `JSON.stringify` round trip in three places:

- **Numbers are copied as written.** `1.0`, `0.10`, `1e2` and `12345678901234567890` come out unchanged.
- **Duplicate keys are kept.** RFC 8259 §4 says names SHOULD be unique and that parsers handle duplicates in different ways; this tool keeps every copy and tells you where they are.
- **A byte order mark is removed and reported.** `JSON.parse` rejects a leading U+FEFF; RFC 8259 §8.1 lets a parser ignore it.

Whitespace and string escapes are rewritten. Strings are written the way `JSON.stringify` writes them, so `"\u00e9"` becomes `"é"` and `"\/"` becomes `"/"`. Turn on **Escape non-ASCII** to write every character above U+007E as `\uXXXX`, as `python3 -m json.tool` does by default.

## Example: An Order ID Longer Than 16 Digits

{/* jf: {"opts":{}} */}
```json
{"order_id":1830000000000000001,"total":19.90,"currency":"USD","items":[{"sku":"A-100","qty":2,"price":9.95}],"paid":true,"coupon":null}
```

Output with 2 spaces:

```json
{
  "order_id": 1830000000000000001,
  "total": 19.90,
  "currency": "USD",
  "items": [
    {
      "sku": "A-100",
      "qty": 2,
      "price": 9.95
    }
  ],
  "paid": true,
  "coupon": null
}
```

A note lists 1830000000000000001 → 1830000000000000000 at /order_id: that is what JSON.parse returns. RFC 8259 §6 explains why: software that reads numbers as IEEE 754 doubles only exchanges integers between −(2^53 − 1) and 2^53 − 1 reliably. If a browser will read the field, send it as a string.

Set **Numbers** to **As JavaScript reads them** to see what a script gets:

{/* jf: {"opts":{"indent":""}} */}
```json
[1.0, 1e2, 0.10, -0, 1e400]
```

Kept as written (minified):

```json
[1.0,1e2,0.10,-0,1e400]
```

{/* jf: {"opts":{"indent":"","numbers":"js"}} */}
```json
[1.0, 1e2, 0.10, -0, 1e400]
```

As JavaScript reads them:

```json
[1,100,0.1,0,1e400]
```

`1e400` overflows a double: `JSON.parse` returns Infinity and `JSON.stringify` writes `null`, so the tool keeps the literal and says so.

## Error Messages

The status line names the cause in plain words, and the output panel shows the line before, the line with the error, and a caret:

{/* jf: {"error":{"code":"trailingComma","line":3,"col":15}} */}
```json
{
  "name": "api",
  "port": 8080,
}
```

Status: "Line 3, column 15: trailing comma before the closing bracket".

```text
2 |   "name": "api",
3 |   "port": 8080,
  |               ^
```

| Input | Message |
|---|---|
| `{"a":1} // note` | comments are not allowed in JSON |
| `{'a': 1}` | JSON strings and property names need double quotes (") |
| `{a: 1}` | property names must be in double quotes |
| `{"ok": True}` | unknown word; JSON only has true, false and null, plus a note that True is Python and JSON writes it as true |
| `[01]` | invalid number (no leading zeros, "+", ".5", NaN or Infinity in JSON) |
| `{"a":“b”}` | curly quotes (“) are not JSON quotes; use straight double quotes (") |

Near-JSON gets a one-click fix: JSON inside a Markdown code fence (common in chatbot answers), JSON escaped as a string (`{\"a\":1}`, common in logs), and one string holding JSON. JSON Lines input gets a link to the [JSONL Converter](/tools/jsonl-converter/).

## Comments: JSONC and JSON5

VS Code's `settings.json`, `tasks.json` and `launch.json` use [JSON with Comments](https://code.visualstudio.com/docs/languages/json#_json-with-comments): `//` and `/* */` comments, and trailing commas, which VS Code accepts with a warning. Plain JSON rejects both. With **Accept JSON5 / JSONC** on, the tool reads [JSON5](https://spec.json5.org/) (a superset of JSONC) and writes JSON:

{/* jf: {"json5":true,"opts":{}} */}
```jsonc
{
  // Editor
  "editor.tabSize": 2,
  "files.exclude": {
    "**/.git": true,
  },
}
```

Output, with the note "Changed to make it JSON: 1 comment removed, 2 trailing commas":

```json
{
  "editor.tabSize": 2,
  "files.exclude": {
    "**/.git": true
  }
}
```

Hex numbers become decimal (`0x1F90` → `8080`, exact at any size), `.5` becomes `0.5`, and single quotes become double quotes. On 103 test inputs the result matches the json5 2.2.3 package, except NaN and Infinity, which JSON cannot store.

## Sorting Keys and Matching jq or Python

**Sort keys** orders keys by Unicode code point at every level, the same order as `jq -S` and `python3 -m json.tool --sort-keys`. With 4 spaces and Escape non-ASCII on, the output is byte-for-byte what Python 3.12's `json.tool` prints for integer data:

{/* jf: {"opts":{"sortKeys":true,"ascii":true,"indent":"    "}} */}
```json
{"name":"Zoë","city":"Kraków","age":30}
```

Output:

```json
{
    "age": 30,
    "city": "Krak\u00f3w",
    "name": "Zo\u00eb"
}
```

Where the three differ on numbers: jq 1.7.1 keeps literals but rewrites exponents (`1e2` → `1E+2`); Python turns `1e2` into `100.0` and `1e400` into `Infinity`, which is not valid JSON; this tool keeps both as written. The test script compares 400 random documents with jq and 120 with Python on every run where those exact versions are installed.
