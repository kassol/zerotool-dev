<h2>使い方</h2>
<ol>
  <li>左のパネルにJSONを貼り付けるか入力します。ツールがリアルタイムで検証します。</li>
  <li>必要に応じて<strong>ルートクラス名</strong>を設定します（デフォルト：<code>Root</code>）。</li>
  <li>出力モードを選択：<strong>@dataclass</strong>、<strong>Pydantic v2</strong>、または<strong>TypedDict</strong>。</li>
  <li><strong>Python を生成</strong>をクリックするか、リアルタイム変換を待ちます。</li>
  <li><strong>コピー</strong>で出力をコピー、または<strong>.py ダウンロード</strong>でファイルとして保存します。</li>
</ol>

<h2>型マッピング</h2>
<ul>
  <li><code>null</code> → <code>Optional[Any] = None</code></li>
  <li>文字列 → <code>str</code></li>
  <li>整数 → <code>int</code></li>
  <li>浮動小数点数 → <code>float</code></li>
  <li>真偽値 → <code>bool</code></li>
  <li>配列 → <code>List[T]</code></li>
  <li>混合配列 → <code>List[Union[T1, T2]]</code></li>
  <li>ネストオブジェクト → 別クラス</li>
</ul>

<h2>例</h2>
<p>このJSONが与えられた場合：</p>
<pre><code>{`{"user": {"first_name": "Alice", "age": 30}, "tags": ["admin"], "note": null}`}</code></pre>
<p>@dataclassモードで生成されるコード：</p>
<pre><code>{`from dataclasses import dataclass\nfrom typing import Any, List, Optional\n\n@dataclass\nclass User:\n    first_name: str\n    age: int\n\n@dataclass\nclass Root:\n    user: User\n    tags: List[str]\n    note: Optional[Any] = None`}</code></pre>

<h2>例：ネストしたオブジェクトと欠けているキー</h2>

<p>入力：</p>

<pre><code>{`{"id": 7, "title": "Release notes", "author": {"name": "Alice", "email": null}, "tags": ["python", "json"], "score": 4.5, "comments": [{"user": "bob", "text": "nice"}, {"user": "carol"}]}`}</code></pre>

<p>@dataclass モードの出力：</p>

<pre><code>{`from dataclasses import dataclass
from typing import Any, List, Optional

@dataclass
class Author:
    name: str
    email: Optional[Any] = None

@dataclass
class CommentsItem:
    user: str
    text: Optional[str] = None

@dataclass
class Root:
    id: int
    title: str
    author: Author
    tags: List[str]
    score: float
    comments: List[CommentsItem]`}</code></pre>

<p>クラスは使われる前に定義される順に並びます。2 件目のコメントには <code>{"text"}</code> がないので <code>{"Optional[str] = None"}</code> になります。</p>

<h2>dataclass・Pydantic・TypedDict の違い</h2>

<p>3 つのモードは同じ構造を表しますが、実行時の動きが違います（Python 3.12、Pydantic 2.13 で確認）：</p>

<pre><code>{`root = Root(**json.loads(raw))
type(root.author)          # <class 'dict'>, not Author`}</code></pre>

<pre><code>{`root = Root.model_validate(json.loads(raw))   # Pydantic mode
root.comments[1]           # CommentsItem(user='carol', text=None)`}</code></pre>

<ul>
  <li><strong>@dataclass</strong> は検証も変換もしません。<code>{"Root(**data)"}</code> ではネストしたオブジェクトはただの dict のままで、型が違っても受け付けます。信頼できるデータに使うか、ネストしたフィールドを自分で変換します。</li>
  <li><strong>Pydantic</strong> は型を検証し、ネストしたモデルを組み立てます。自分で管理していない API のレスポンスに向いています。<code>{"model_validate_json(raw)"}</code> でパースと検証を一度に行えます。</li>
  <li><strong>TypedDict</strong> は型チェッカー向けに dict の型を書くだけで、実行時には何も確認しません。キーは既定ですべて必須なので、ツールは一部の要素にしかないキーを <code>{"NotRequired[...]"}</code> にします（PEP 655。Python 3.11 以降は <code>typing</code>、それ以前は <code>typing_extensions</code>）。<code>{"Optional[...]"}</code> は値が <code>None</code> になりうることを表すだけで、キーは必須のままです。</li>
</ul>

<h2>例：キーが欠ける TypedDict</h2>

<p><code>note</code> が 1 件目では null、2 件目では欠けていて、<code>discount</code> は 2 件目にしかない商品データ（ルートクラス名 <code>Product</code>、TypedDict モード）：</p>

<pre><code>{`[{"id": 1, "sku": "PEN-01", "price": 2, "note": null}, {"id": 2, "sku": "INK-07", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`from typing import Any, NotRequired, Optional, TypedDict

class Product(TypedDict):
    id: int
    sku: str
    price: float
    note: NotRequired[Optional[Any]]
    discount: NotRequired[float]`}</code></pre>

<p><code>price</code> は <code>2</code> と <code>1.5</code> です。PEP 484 では <code>int</code> を <code>float</code> として扱えるので、型は <code>float</code> になります。実行時の <code>Product.__required_keys__</code> は <code>{"{'id', 'sku', 'price'}"}</code>、<code>__optional_keys__</code> は <code>{"{'note', 'discount'}"}</code> です（Python 3.12 で確認）。</p>

<h2>制限</h2>

<ul>
  <li><code>{"null"}</code> は <code>{"Optional[Any]"}</code> になります。<code>{"Any"}</code> を実際の型に置き換えてください。</li>
  <li>Python の識別子として使えないキー（<code>{"user-id"}</code> や <code>{"class"}</code> のような予約語）は名前を変え、Pydantic では <code>{"Field(alias=\"user-id\")"}</code> を付けます。</li>
  <li>日付は <code>{"str"}</code> のままです。型を <code>{"datetime"}</code> に変えれば Pydantic が ISO 8601 文字列を変換します。</li>
  <li>ルートがプリミティブの配列のときはクラスを生成しません。</li>
</ul>
