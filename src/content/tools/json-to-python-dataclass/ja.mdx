<h2>型マッピング</h2>
<ul>
  <li><code>null</code> → <code>Optional[Any] = None</code></li>
  <li>文字列 → <code>str</code></li>
  <li>整数 → <code>int</code></li>
  <li>浮動小数点数 → <code>float</code></li>
  <li>真偽値 → <code>bool</code></li>
  <li>配列 → <code>List[T]</code></li>
  <li>混合配列 → <code>List[Union[T1, T2]]</code></li>
  <li>ネストオブジェクト → 別クラス</li>
</ul>

<h2>例</h2>

{/* jpdc-check: {"root":"Root","mode":"dataclass"} */}

<p>このJSONが与えられた場合：</p>
<pre><code>{`{"user": {"first_name": "Alice", "age": 30}, "tags": ["admin"], "note": null}`}</code></pre>
<p>@dataclassモードで生成されるコード：</p>
<pre><code>{`from dataclasses import dataclass\nfrom typing import Any, List, Optional\n\n@dataclass\nclass User:\n    first_name: str\n    age: int\n\n@dataclass\nclass Root:\n    user: User\n    tags: List[str]\n    note: Optional[Any] = None`}</code></pre>

<h2>例：ネストしたオブジェクトと欠けているキー</h2>

<p>入力：</p>

<pre><code>{`{"id": 7, "title": "Release notes", "author": {"name": "Alice", "email": null}, "tags": ["python", "json"], "score": 4.5, "comments": [{"user": "bob", "text": "nice"}, {"user": "carol"}]}`}</code></pre>

<p>@dataclass モードの出力：</p>

<pre><code>{`from dataclasses import dataclass
from typing import Any, List, Optional

@dataclass
class Author:
    name: str
    email: Optional[Any] = None

@dataclass
class CommentsItem:
    user: str
    text: Optional[str] = None

@dataclass
class Root:
    id: int
    title: str
    author: Author
    tags: List[str]
    score: float
    comments: List[CommentsItem]`}</code></pre>

<p>クラスは使われる前に定義される順に並びます。2 件目のコメントには <code>{"text"}</code> がないので <code>{"Optional[str] = None"}</code> になります。</p>

<h2>dataclass・Pydantic・TypedDict の違い</h2>

<p>3 つのモードは同じ構造を表しますが、実行時の動きが違います（Python 3.12、Pydantic 2.13 で確認）：</p>

<pre><code>{`root = Root(**json.loads(raw))
type(root.author)          # <class 'dict'>, not Author`}</code></pre>

<pre><code>{`root = Root.model_validate(json.loads(raw))   # Pydantic mode
root.comments[1]           # CommentsItem(user='carol', text=None)`}</code></pre>

<ul>
  <li><strong>@dataclass</strong> は検証も変換もしません。<code>{"Root(**data)"}</code> ではネストしたオブジェクトはただの dict のままで、型が違っても受け付けます。信頼できるデータに使うか、ネストしたフィールドを自分で変換します。</li>
  <li><strong>Pydantic</strong> は型を検証し、ネストしたモデルを組み立てます。自分で管理していない API のレスポンスに向いています。<code>{"model_validate_json(raw)"}</code> でパースと検証を一度に行えます。</li>
  <li><strong>TypedDict</strong> は型チェッカー向けに dict の型を書くだけで、実行時には何も確認しません。キーは既定ですべて必須なので、ツールは一部の要素にしかないキーを <code>{"NotRequired[...]"}</code> にします（PEP 655。Python 3.11 以降は <code>typing</code>、それ以前は <code>typing_extensions</code>）。<code>{"Optional[...]"}</code> は値が <code>None</code> になりうることを表すだけで、キーは必須のままです。</li>
</ul>

<h2>例：キーが欠ける TypedDict</h2>

{/* jpdc-check: {"root":"Product","mode":"typeddict"} */}

<p><code>note</code> が 1 件目では null、2 件目では欠けていて、<code>discount</code> は 2 件目にしかない商品データ（ルートクラス名 <code>Product</code>、TypedDict モード）：</p>

<pre><code>{`[{"id": 1, "sku": "PEN-01", "price": 2, "note": null}, {"id": 2, "sku": "INK-07", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`from typing import Any, NotRequired, Optional, TypedDict

class Product(TypedDict):
    id: int
    sku: str
    price: float
    note: NotRequired[Optional[Any]]
    discount: NotRequired[float]`}</code></pre>

<p><code>price</code> は <code>2</code> と <code>1.5</code> です。PEP 484 では <code>int</code> を <code>float</code> として扱えるので、型は <code>float</code> になります。実行時の <code>Product.__required_keys__</code> は <code>{"{'id', 'sku', 'price'}"}</code>、<code>__optional_keys__</code> は <code>{"{'note', 'discount'}"}</code> です（Python 3.12 で確認）。</p>

<h2>気象庁の天気予報 JSON を TypedDict にする</h2>

{/* jpdc-check: {"root":"Forecast","mode":"typeddict"} */}

<p>気象庁が公開している天気予報の JSON（東京都は <code>https://www.jma.go.jp/bosai/forecast/data/forecast/130000.json</code>）を TypedDict にする例です。2026 年 10 月 8 日 17 時発表分から東京地方だけを取り出し、天気の時系列は 3 時点すべて、降水確率の時系列は最初の 2 時点だけを残しました（値は発表時のまま）。1 つ目の時系列には天気（<code>weatherCodes</code>、<code>weathers</code>）、2 つ目には降水確率（<code>pops</code>）が入っています（ルートクラス名 <code>Forecast</code>、TypedDict モード）：</p>

<pre><code>{`[{"publishingOffice":"気象庁","reportDatetime":"2026-10-08T17:00:00+09:00","timeSeries":[{"timeDefines":["2026-10-08T17:00:00+09:00","2026-10-09T00:00:00+09:00","2026-10-10T00:00:00+09:00"],"areas":[{"area":{"name":"東京地方","code":"130010"},"weatherCodes":["100","100","101"],"weathers":["晴れ","晴れ","晴れ　時々　くもり"]}]},{"timeDefines":["2026-10-08T18:00:00+09:00","2026-10-09T00:00:00+09:00"],"areas":[{"area":{"name":"東京地方","code":"130010"},"pops":["0","0"]}]}]}]`}</code></pre>

<pre><code>{`from typing import List, NotRequired, TypedDict

class Area(TypedDict):
    name: str
    code: str

class AreasItem(TypedDict):
    area: Area
    weatherCodes: NotRequired[List[str]]
    weathers: NotRequired[List[str]]
    pops: NotRequired[List[str]]

class TimeSeriesItem(TypedDict):
    timeDefines: List[str]
    areas: List[AreasItem]

class Forecast(TypedDict):
    publishingOffice: str
    reportDatetime: str
    timeSeries: List[TimeSeriesItem]`}</code></pre>

<ul>
  <li>2 つの時系列の <code>areas</code> は中身が違いますが、同じキーのオブジェクトはすべてのサンプルをまとめて 1 つのクラスにするので、<code>AreasItem</code> には天気と降水確率の両方が入り、片方の時系列にしかない <code>weatherCodes</code>・<code>weathers</code>・<code>pops</code> は <code>NotRequired</code> になります。</li>
  <li><code>reportDatetime</code> と <code>timeDefines</code> は <code>+09:00</code> 付きの日時ですが <code>str</code> のままです。Pydantic で <code>datetime</code> に変えると、オフセット付きの値として読み込まれます。</li>
  <li>降水確率は <code>"0"</code> のように文字列で入っているので <code>{"List[str]"}</code> です。Pydantic のモデルで <code>{"List[int]"}</code> に変えると、既定の lax モードでは文字列が数値に変換されます（たとえば <code>{'["0", "10"]'}</code> は <code>{"[0, 10]"}</code>。Pydantic 2.13.5 で確認）。</li>
  <li><code>weathers</code> の「晴れ　時々　くもり」には全角スペースが入っていますが、文字列なので型には影響しません。</li>
</ul>

<h2>制限</h2>

<ul>
  <li><code>{"null"}</code> は <code>{"Optional[Any]"}</code> になります。<code>{"Any"}</code> を実際の型に置き換えてください。</li>
  <li>そのままではフィールド名にできないキー（<code>{"class"}</code> などの予約語、<code>{"user-id"}</code> や <code>2fa</code> のように識別子でないもの、全角の <code>ｎａｍｅ</code> のように NFKC で変わるもの、<code>{"__"}</code> で始まるもの、出力が import する名前や型として使う名前（<code>str</code>、<code>Field</code>）や生成したクラスと同じ名前のもの。Pydantic ではさらに <code>{"_"}</code> や <code>{"model_"}</code> で始まるキー（MongoDB の <code>{"_id"}</code> など）と、<code>json</code> など <code>BaseModel</code> の属性名）は、使える名前に置き換えます。@dataclass モードは行末のコメントに元のキーを書くので、<code>{"Root(**data)"}</code> の前に自分で対応させます。Pydantic モードは <code>{"Field(alias=...)"}</code> を付けるので <code>{"model_validate()"}</code> は元のキーのまま読めます（<code>{"model_dump()"}</code> はフィールド名で出力するので、元のキーに戻すには <code>{"model_dump(by_alias=True)"}</code> を使います）。TypedDict モードは関数形式 <code>{'TypedDict("Name", {...})'}</code> に切り替えて、キーをすべてそのまま残します。ツールのテストでは Python 3.12 と 3.14 で 3 つの出力を実行し、サンプルを読み戻しています。</li>
  <li>日付は <code>{"str"}</code> のままです。型を <code>{"datetime"}</code> に変えれば Pydantic が ISO 8601 文字列を変換します。</li>
  <li>ルートがプリミティブの配列のときはクラスを生成しません。ルート配列にオブジェクトとそれ以外の値が混ざっている場合は、オブジェクトからルートクラスを作り、配列全体の型を最後に別名 <code>{"RootArray = List[Union[...]]"}</code> として出力します（null の要素は <code>None</code>）。Pydantic では <code>{"TypeAdapter(RootArray)"}</code> で配列全体を検証できます。</li>
  <li><code>10.0</code> と書いた数値は、ツールに届いた時点で整数 <code>10</code> です（JavaScript の <code>JSON.parse</code> は末尾の 0 を残しません）。そのため <code>{"price: int"}</code> になり、後で <code>10.5</code> が来ると Pydantic は <code>Input should be a valid integer, got a number with a fractional part</code> で拒否します。小数がありうる値は <code>float</code> に直してください。</li>
  <li>ルートクラス名は Python の識別子として使えればそのまま使い、使えなければ変換します：<code>{"order-item"}</code> → <code>OrderItem</code>、数字で始まる <code>2fa</code> → <code>{"_2fa"}</code>、予約語の <code>class</code> → <code>{"class_"}</code>、先頭の <code>{"__"}</code> は <code>{"_"}</code> 1 つに（ネストしたクラス名はルートクラス名で始まり、Python はクラス本体の中で 2 つの下線で始まる名前を書き換えるため）、識別子に使える文字がなければ <code>Root</code>。</li>
  <li>漢字や仮名のキーでも、クラス名にすべての文字がそのまま残ります。ただし JSON のキーと同じ名前のクラスは作らないので（Pydantic では、既定値のあるフィールドが同名のクラスを隠します）、親クラス名を前に付けます。</li>
</ul>

<p>会員データの例（ルートクラス名 <code>Member</code>、@dataclass モード）：</p>

<pre><code>{`{"氏名": "山田太郎", "住所": {"都道府県": "東京都", "市区町村": "千代田区"}}`}</code></pre>

<pre><code>{`from dataclasses import dataclass

@dataclass
class Member住所:
    都道府県: str
    市区町村: str

@dataclass
class Member:
    氏名: str
    住所: Member住所`}</code></pre>

<p>Python 3 は識別子に日本語を使えるので、<code>氏名</code> や <code>住所</code> はそのままフィールド名になり、このコードは実行できます。住所のクラスは親の名前を付けた <code>Member住所</code> です。英語の名前にしたいときは <code>Address</code> などに付け替えてください。</p>

<h2>空の配列とサンプルの範囲</h2>

<p>空の配列からは要素の型を判断できないため、<code>{`{"tags": []}`}</code> は <code>tags: List[Any]</code> になります。同じ入力配列に <code>{`{"tags": ["admin"]}`}</code> を持つ別のオブジェクトを加えると、統合したフィールドは <code>List[str]</code> になります。生成器は入力したサンプルに基づいて型を推測し、どのサンプルにもないフィールドは推測できません。クラスをコピーする前に、キーの欠落や null 値を含む代表的なオブジェクトを加えてください。</p>
