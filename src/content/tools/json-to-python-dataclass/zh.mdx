<h2>类型映射</h2>
<ul>
  <li><code>null</code> → <code>Optional[Any] = None</code></li>
  <li>字符串 → <code>str</code></li>
  <li>整数 → <code>int</code></li>
  <li>浮点数 → <code>float</code></li>
  <li>布尔值 → <code>bool</code></li>
  <li>数组 → <code>List[T]</code></li>
  <li>混合数组 → <code>List[Union[T1, T2]]</code></li>
  <li>嵌套对象 → 独立类</li>
</ul>

<h2>示例</h2>

{/* jpdc-check: {"root":"Root","mode":"dataclass"} */}

<p>给定如下 JSON：</p>
<pre><code>{`{"user": {"first_name": "Alice", "age": 30}, "tags": ["admin"], "note": null}`}</code></pre>
<p>@dataclass 模式下生成：</p>
<pre><code>{`from dataclasses import dataclass\nfrom typing import Any, List, Optional\n\n@dataclass\nclass User:\n    first_name: str\n    age: int\n\n@dataclass\nclass Root:\n    user: User\n    tags: List[str]\n    note: Optional[Any] = None`}</code></pre>

<h2>示例：嵌套对象与缺失的键</h2>

<p>输入：</p>

<pre><code>{`{"id": 7, "title": "Release notes", "author": {"name": "Alice", "email": null}, "tags": ["python", "json"], "score": 4.5, "comments": [{"user": "bob", "text": "nice"}, {"user": "carol"}]}`}</code></pre>

<p>@dataclass 模式的输出：</p>

<pre><code>{`from dataclasses import dataclass
from typing import Any, List, Optional

@dataclass
class Author:
    name: str
    email: Optional[Any] = None

@dataclass
class CommentsItem:
    user: str
    text: Optional[str] = None

@dataclass
class Root:
    id: int
    title: str
    author: Author
    tags: List[str]
    score: float
    comments: List[CommentsItem]`}</code></pre>

<p>类的顺序保证每个类在被使用前已定义。第二条评论缺少 <code>{"text"}</code>，所以它是 <code>{"Optional[str] = None"}</code>。</p>

<h2>dataclass、Pydantic 还是 TypedDict</h2>

<p>三种模式描述的结构相同，运行时行为不同（Python 3.12、Pydantic 2.13 实测）：</p>

<pre><code>{`root = Root(**json.loads(raw))
type(root.author)          # <class 'dict'>, not Author`}</code></pre>

<pre><code>{`root = Root.model_validate(json.loads(raw))   # Pydantic mode
root.comments[1]           # CommentsItem(user='carol', text=None)`}</code></pre>

<ul>
  <li><strong>@dataclass</strong> 不校验也不转换。<code>{"Root(**data)"}</code> 里的嵌套对象仍是普通 dict，类型不对也照样接受。数据可信时再用，或者自己转换嵌套字段。</li>
  <li><strong>Pydantic</strong> 会校验类型并构造嵌套模型，适合处理你控制不了的 API 响应。<code>{"model_validate_json(raw)"}</code> 一步完成解析和校验。</li>
  <li><strong>TypedDict</strong> 只给类型检查器描述 dict 的结构，运行时什么都不检查。所有键默认都是必需的，工具把只在部分元素里出现的键写成 <code>{"NotRequired[...]"}</code>（PEP 655，Python 3.11+ 在 <code>typing</code> 中，更早版本用 <code>typing_extensions</code>）。<code>{"Optional[...]"}</code> 只表示值可以是 <code>None</code>，键仍然必需。</li>
</ul>

<h2>示例：带缺失键的 TypedDict</h2>

{/* jpdc-check: {"root":"Product","mode":"typeddict"} */}

<p>两个商品：<code>note</code> 在第一个里为 null、在第二个里缺失，<code>discount</code> 只出现在第二个里（根类名 <code>Product</code>，TypedDict 模式）：</p>

<pre><code>{`[{"id": 1, "sku": "PEN-01", "price": 2, "note": null}, {"id": 2, "sku": "INK-07", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`from typing import Any, NotRequired, Optional, TypedDict

class Product(TypedDict):
    id: int
    sku: str
    price: float
    note: NotRequired[Optional[Any]]
    discount: NotRequired[float]`}</code></pre>

<p><code>price</code> 一个是 <code>2</code>、一个是 <code>1.5</code>，PEP 484 允许 <code>int</code> 当作 <code>float</code> 使用，所以字段是 <code>float</code>。运行时 <code>Product.__required_keys__</code> 为 <code>{"{'id', 'sku', 'price'}"}</code>，<code>__optional_keys__</code> 为 <code>{"{'note', 'discount'}"}</code>（Python 3.12 实测）。</p>

<h2>高德地理编码响应：同一个字段既是字符串又是数组</h2>

{/* jpdc-check: {"root":"GeocodeResponse","mode":"pydantic"} */}

<p>高德 Web 服务 API 的地理编码接口按 JSON 返回结果。返回参数说明写明 <code>status</code> 的值为 0 或 1（1 表示成功），并提示：「部分返回值当返回值存在时，将以字符串类型返回；当返回值不存在时，则以数组类型返回」（<a href="https://lbs.amap.com/api/webservice/guide/api/georegeo">地理/逆地理编码</a>）。下面按文档里的字段写了两条结果：第一条匹配到门牌号，第二条只匹配到区县，所以 <code>street</code> 和 <code>number</code> 是空数组。数值按上面那条说明都写成字符串，坐标为示意值（根类名 <code>GeocodeResponse</code>，Pydantic v2 模式）：</p>

<pre><code>{`{"status":"1","info":"OK","count":"2","geocodes":[{"formatted_address":"北京市朝阳区阜通东大街6号","province":"北京市","city":"北京市","district":"朝阳区","street":"阜通东大街","number":"6号","adcode":"110105","location":"116.483038,39.990633","level":"门牌号"},{"formatted_address":"浙江省杭州市西湖区","province":"浙江省","city":"杭州市","district":"西湖区","street":[],"number":[],"adcode":"330106","location":"120.130396,30.259242","level":"区县"}]}`}</code></pre>

<pre><code>{`from pydantic import BaseModel
from typing import Any, List, Union

class GeocodesItem(BaseModel):
    formatted_address: str
    province: str
    city: str
    district: str
    street: Union[str, List[Any]]
    number: Union[str, List[Any]]
    adcode: str
    location: str
    level: str

class GeocodeResponse(BaseModel):
    status: str
    info: str
    count: str
    geocodes: List[GeocodesItem]`}</code></pre>

<ul>
  <li><code>street</code> 和 <code>number</code> 在两条结果里分别是字符串和空数组，所以生成 <code>{"Union[str, List[Any]]"}</code>。用这段代码的 <code>GeocodeResponse.model_validate()</code> 读入上面的 JSON，两条都能通过（工具测试用 Pydantic 实跑）。如果只拿第一条门牌级结果生成，字段会是 <code>str</code>，之后遇到区县级结果时 Pydantic 会报校验错误。所以生成前要把不同匹配级别的结果放进同一个样本。</li>
  <li><code>status</code>、<code>count</code>、<code>adcode</code> 是字符串，生成的是 <code>str</code>。判断成功要写 <code>{'resp.status == "1"'}</code>，写成 <code>== 1</code> 永远不成立。</li>
  <li><code>location</code> 是「经度,纬度」一个字符串，工具不会拆成两个数字，需要时自己 <code>split(",")</code>。</li>
</ul>

<h2>限制</h2>

<ul>
  <li><code>{"null"}</code> 会变成 <code>{"Optional[Any]"}</code>，请把 <code>{"Any"}</code> 换成真实类型。</li>
  <li>不能原样作字段名的键（<code>{"class"}</code> 等关键字、<code>{"user-id"}</code> 和 <code>2fa</code> 这类非标识符、NFKC 会改变的键（如全角的 <code>ｎａｍｅ</code>）、以 <code>{"__"}</code> 开头的键、与输出导入或用作类型的名字（<code>str</code>、<code>Field</code>）或生成的类同名的键；Pydantic 模式下还有以 <code>{"_"}</code> 或 <code>{"model_"}</code> 开头的键，如 MongoDB 的 <code>{"_id"}</code>，以及 <code>json</code> 这类 <code>BaseModel</code> 属性名）会换成合法的字段名：@dataclass 模式在行尾用注释写出原键（用 <code>{"Root(**data)"}</code> 构造前要自己对应一下），Pydantic 模式加 <code>{"Field(alias=...)"}</code>，<code>{"model_validate()"}</code> 照样按原键读取（<code>{"model_dump()"}</code> 输出的是字段名，要还原原键请用 <code>{"model_dump(by_alias=True)"}</code>），TypedDict 模式改用函数式写法 <code>{'TypedDict("Name", {...})'}</code>，原键全部保留。工具的测试在 Python 3.12 和 3.14 下运行这三种输出并读回样例。</li>
  <li>日期保持为 <code>{"str"}</code>；把类型改成 <code>{"datetime"}</code> 后，Pydantic 会解析 ISO 8601 字符串。</li>
  <li>根节点是基础类型数组时不生成类。根数组里对象和其他值混在一起时，对象生成根类，整个数组在最后写成别名 <code>{"RootArray = List[Union[...]]"}</code>（<code>None</code> 表示 null 元素），Pydantic 里可以用 <code>{"TypeAdapter(RootArray)"}</code> 校验整个数组。</li>
  <li>写成 <code>10.0</code> 的数字到工具里已经是整数 <code>10</code>（JavaScript 的 <code>JSON.parse</code> 不保留末尾的 0），所以生成 <code>{"price: int"}</code>。之后 Pydantic 遇到 <code>10.5</code> 会报 <code>Input should be a valid integer, got a number with a fractional part</code>。金额可能带小数时，请改成 <code>float</code>，或者按分存成整数。</li>
  <li>根类名称是合法的 Python 标识符时原样使用，否则转换：<code>{"order-item"}</code> → <code>OrderItem</code>，数字开头的 <code>2fa</code> → <code>{"_2fa"}</code>，关键字 <code>class</code> → <code>{"class_"}</code>，开头的 <code>{"__"}</code> 改成一个 <code>{"_"}</code>（嵌套类名以根类名开头，Python 会在类体里改写以两个下划线开头的名字），没有可用字符时用 <code>Root</code>。</li>
  <li>中文键名在类名里保留全部字符。类名不会和 JSON 里的键名相同（Pydantic 里带默认值的字段会遮住同名的类），所以会加上父级类名作前缀，见下例。</li>
</ul>

{/* jpdc-check: {"root":"Order","mode":"dataclass"} */}

<p>例如收货地址和发票地址（根类名 <code>Order</code>，@dataclass 模式）：</p>

<pre><code>{`{"收货地址": {"省": "浙江省", "市": "杭州市"}, "发票地址": {"抬头": "杭州示例科技有限公司"}}`}</code></pre>

<pre><code>{`from dataclasses import dataclass

@dataclass
class Order收货地址:
    省: str
    市: str

@dataclass
class Order发票地址:
    抬头: str

@dataclass
class Order:
    收货地址: Order收货地址
    发票地址: Order发票地址`}</code></pre>

<p>Python 3 允许非 ASCII 标识符，中文键名可以直接作字段名，这段代码能运行；两个地址结构不同，各自生成一个类，<code>抬头</code> 字段也会保留。想要英文类名时，可以把 <code>Order收货地址</code>、<code>Order发票地址</code> 改成 <code>ShippingAddress</code>、<code>InvoiceInfo</code>。</p>

<h2>空数组与样本覆盖</h2>

<p>空数组没有提供元素类型的依据，因此 <code>{`{"tags": []}`}</code> 会生成 <code>tags: List[Any]</code>。在同一输入数组中加入另一个含 <code>{`{"tags": ["admin"]}`}</code> 的对象，合并后的字段就变为 <code>List[str]</code>。生成器依据你提供的样本推断类型，无法推断所有样本中都未出现的字段。复制类定义前，请加入具有缺失键和 null 值的代表性对象。</p>
