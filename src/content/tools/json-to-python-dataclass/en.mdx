<h2>How to Use</h2>
<ol>
  <li>Paste or type your JSON into the left panel. The tool validates it in real time.</li>
  <li>Optionally set a <strong>Root class name</strong> (default: <code>Root</code>).</li>
  <li>Choose an output mode: <strong>@dataclass</strong>, <strong>Pydantic v2</strong>, or <strong>TypedDict</strong>.</li>
  <li>Click <strong>Generate Python</strong> or wait for real-time conversion.</li>
  <li>Click <strong>Copy</strong> to copy the output, or <strong>Download .py</strong> to save as a file.</li>
</ol>

<h2>Type Mapping</h2>
<ul>
  <li><code>null</code> → <code>Optional[Any] = None</code></li>
  <li>string → <code>str</code></li>
  <li>integer → <code>int</code></li>
  <li>float → <code>float</code></li>
  <li>boolean → <code>bool</code></li>
  <li>array → <code>List[T]</code></li>
  <li>mixed array → <code>List[Union[T1, T2]]</code></li>
  <li>nested object → separate class</li>
</ul>

<h2>Example</h2>
<p>Given this JSON:</p>
<pre><code>{`{"user": {"first_name": "Alice", "age": 30}, "tags": ["admin"], "note": null}`}</code></pre>
<p>The tool generates (@dataclass mode):</p>
<pre><code>{`from dataclasses import dataclass\nfrom typing import Any, List, Optional\n\n@dataclass\nclass User:\n    first_name: str\n    age: int\n\n@dataclass\nclass Root:\n    user: User\n    tags: List[str]\n    note: Optional[Any] = None`}</code></pre>

<h2>Example: Nested Objects and Missing Keys</h2>

<p>Input:</p>

<pre><code>{`{"id": 7, "title": "Release notes", "author": {"name": "Alice", "email": null}, "tags": ["python", "json"], "score": 4.5, "comments": [{"user": "bob", "text": "nice"}, {"user": "carol"}]}`}</code></pre>

<p>Output in @dataclass mode:</p>

<pre><code>{`from dataclasses import dataclass
from typing import Any, List, Optional

@dataclass
class Author:
    name: str
    email: Optional[Any] = None

@dataclass
class CommentsItem:
    user: str
    text: Optional[str] = None

@dataclass
class Root:
    id: int
    title: str
    author: Author
    tags: List[str]
    score: float
    comments: List[CommentsItem]`}</code></pre>

<p>Classes are ordered so that each one is defined before it is used. <code>{"text"}</code> is missing from the second comment, so it becomes <code>{"Optional[str] = None"}</code>.</p>

<h2>dataclass, Pydantic or TypedDict</h2>

<p>The three modes describe the same shape but behave differently at runtime (checked with Python 3.12 and Pydantic 2.13):</p>

<pre><code>{`root = Root(**json.loads(raw))
type(root.author)          # <class 'dict'>, not Author`}</code></pre>

<pre><code>{`root = Root.model_validate(json.loads(raw))   # Pydantic mode
root.comments[1]           # CommentsItem(user='carol', text=None)`}</code></pre>

<ul>
  <li><strong>@dataclass</strong> does not validate or convert. <code>{"Root(**data)"}</code> keeps nested objects as plain dicts and accepts wrong types. Use it when the data is already trusted, or convert nested fields yourself.</li>
  <li><strong>Pydantic</strong> validates types and builds nested models; use it for API responses you do not control. <code>{"model_validate_json(raw)"}</code> parses and validates in one step.</li>
  <li><strong>TypedDict</strong> only describes dict types for a type checker; nothing is checked at runtime. Every key is required by default, so the tool marks a key that is missing from some items as <code>{"NotRequired[...]"}</code> (PEP 655, <code>typing</code> in Python 3.11+, <code>typing_extensions</code> before that). <code>{"Optional[...]"}</code> only means the value may be <code>None</code>; the key would still be required.</li>
</ul>

<h2>Example: TypedDict with Missing Keys</h2>

<p>Two products where <code>note</code> is null in the first and absent from the second, and <code>discount</code> only appears in the second (root class name <code>Product</code>, TypedDict mode):</p>

<pre><code>{`[{"id": 1, "sku": "PEN-01", "price": 2, "note": null}, {"id": 2, "sku": "INK-07", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`from typing import Any, NotRequired, Optional, TypedDict

class Product(TypedDict):
    id: int
    sku: str
    price: float
    note: NotRequired[Optional[Any]]
    discount: NotRequired[float]`}</code></pre>

<p><code>price</code> is <code>2</code> in one item and <code>1.5</code> in the other; PEP 484 lets an <code>int</code> stand in for a <code>float</code>, so the field is <code>float</code>. At runtime <code>Product.__required_keys__</code> is <code>{"{'id', 'sku', 'price'}"}</code> and <code>__optional_keys__</code> is <code>{"{'note', 'discount'}"}</code> (checked with Python 3.12). A type checker then accepts a product without <code>discount</code> and rejects one without <code>sku</code> (mypy 2.3.1: Missing key "sku" for TypedDict "Product").

<h2>Limits</h2>

<ul>
  <li><code>{"null"}</code> becomes <code>{"Optional[Any]"}</code>; replace <code>{"Any"}</code> with the real type.</li>
  <li>Keys that are not valid Python identifiers (for example <code>{"user-id"}</code> or keywords such as <code>{"class"}</code>) need renaming, plus <code>{"Field(alias=\"user-id\")"}</code> in Pydantic.</li>
  <li>Dates stay <code>{"str"}</code>; Pydantic converts ISO 8601 strings if you change the type to <code>{"datetime"}</code>.</li>
  <li>Arrays of primitives at the root generate no class.</li>
</ul>
