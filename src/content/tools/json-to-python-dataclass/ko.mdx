<h2>타입 매핑</h2>
<ul>
  <li><code>null</code> → <code>Optional[Any] = None</code></li>
  <li>문자열 → <code>str</code></li>
  <li>정수 → <code>int</code></li>
  <li>부동소수점 → <code>float</code></li>
  <li>불리언 → <code>bool</code></li>
  <li>배열 → <code>List[T]</code></li>
  <li>혼합 배열 → <code>List[Union[T1, T2]]</code></li>
  <li>중첩 객체 → 별도 클래스</li>
</ul>

<h2>예시</h2>

{/* jpdc-check: {"root":"Root","mode":"dataclass"} */}

<p>다음 JSON이 주어졌을 때:</p>
<pre><code>{`{"user": {"first_name": "Alice", "age": 30}, "tags": ["admin"], "note": null}`}</code></pre>
<p>@dataclass 모드에서 생성되는 코드:</p>
<pre><code>{`from dataclasses import dataclass\nfrom typing import Any, List, Optional\n\n@dataclass\nclass User:\n    first_name: str\n    age: int\n\n@dataclass\nclass Root:\n    user: User\n    tags: List[str]\n    note: Optional[Any] = None`}</code></pre>

<h2>예시: 중첩 객체와 빠진 키</h2>

<p>입력:</p>

<pre><code>{`{"id": 7, "title": "Release notes", "author": {"name": "Alice", "email": null}, "tags": ["python", "json"], "score": 4.5, "comments": [{"user": "bob", "text": "nice"}, {"user": "carol"}]}`}</code></pre>

<p>@dataclass 모드 출력:</p>

<pre><code>{`from dataclasses import dataclass
from typing import Any, List, Optional

@dataclass
class Author:
    name: str
    email: Optional[Any] = None

@dataclass
class CommentsItem:
    user: str
    text: Optional[str] = None

@dataclass
class Root:
    id: int
    title: str
    author: Author
    tags: List[str]
    score: float
    comments: List[CommentsItem]`}</code></pre>

<p>클래스는 사용되기 전에 정의되도록 정렬됩니다. 두 번째 댓글에는 <code>{"text"}</code>가 없어서 <code>{"Optional[str] = None"}</code>이 됩니다.</p>

<h2>dataclass, Pydantic, TypedDict 차이</h2>

<p>세 모드는 같은 구조를 나타내지만 실행 시 동작이 다릅니다(Python 3.12, Pydantic 2.13으로 확인):</p>

<pre><code>{`root = Root(**json.loads(raw))
type(root.author)          # <class 'dict'>, not Author`}</code></pre>

<pre><code>{`root = Root.model_validate(json.loads(raw))   # Pydantic mode
root.comments[1]           # CommentsItem(user='carol', text=None)`}</code></pre>

<ul>
  <li><strong>@dataclass</strong>는 검증도 변환도 하지 않습니다. <code>{"Root(**data)"}</code>에서 중첩 객체는 그냥 dict로 남고, 타입이 달라도 받아들입니다. 믿을 수 있는 데이터에 쓰거나 중첩 필드를 직접 변환하세요.</li>
  <li><strong>Pydantic</strong>은 타입을 검증하고 중첩 모델을 만듭니다. 직접 관리하지 않는 API 응답에 적합합니다. <code>{"model_validate_json(raw)"}</code>로 파싱과 검증을 한 번에 합니다.</li>
  <li><strong>TypedDict</strong>는 타입 검사기에 dict 구조를 알려 줄 뿐 실행 시에는 아무것도 확인하지 않습니다. 모든 키가 기본적으로 필수이므로 도구는 일부 항목에만 있는 키를 <code>{"NotRequired[...]"}</code>로 씁니다(PEP 655, Python 3.11+는 <code>typing</code>, 그 이전은 <code>typing_extensions</code>). <code>{"Optional[...]"}</code>은 값이 <code>None</code>일 수 있다는 뜻일 뿐이고 키는 여전히 필수입니다.</li>
</ul>

<h2>예시: 키가 빠지는 TypedDict</h2>

{/* jpdc-check: {"root":"Product","mode":"typeddict"} */}

<p><code>note</code>가 첫 항목에서는 null, 둘째 항목에서는 없고, <code>discount</code>는 둘째 항목에만 있는 상품 데이터(루트 클래스 이름 <code>Product</code>, TypedDict 모드):</p>

<pre><code>{`[{"id": 1, "sku": "PEN-01", "price": 2, "note": null}, {"id": 2, "sku": "INK-07", "price": 1.5, "discount": 0.1}]`}</code></pre>

<pre><code>{`from typing import Any, NotRequired, Optional, TypedDict

class Product(TypedDict):
    id: int
    sku: str
    price: float
    note: NotRequired[Optional[Any]]
    discount: NotRequired[float]`}</code></pre>

<p><code>price</code>는 <code>2</code>와 <code>1.5</code>입니다. PEP 484는 <code>int</code>를 <code>float</code> 자리에 쓸 수 있게 하므로 타입은 <code>float</code>입니다. 실행 시 <code>Product.__required_keys__</code>는 <code>{"{'id', 'sku', 'price'}"}</code>, <code>__optional_keys__</code>는 <code>{"{'note', 'discount'}"}</code>입니다(Python 3.12에서 확인).</p>

<h2>네이버 블로그 검색 API 응답을 Pydantic 모델로</h2>

{/* jpdc-check: {"root":"BlogSearch","mode":"pydantic"} */}

<p>네이버 검색 API의 블로그 검색은 결과를 XML 또는 JSON으로 돌려주며, JSON에서는 개별 결과가 <code>items</code> 배열로 옵니다(<a href="https://developers.naver.com/docs/serviceapi/search/blog/blog.md">블로그 검색 API 레퍼런스</a>). 아래는 문서의 XML 응답 예에 나온 값을 JSON 모양으로 옮기고 <code>link</code>와 <code>description</code>을 줄인 샘플입니다(루트 클래스 이름 <code>BlogSearch</code>, Pydantic v2 모드):</p>

<pre><code>{`{"lastBuildDate":"Mon, 26 Sep 2016 10:39:37 +0900","total":8714891,"start":1,"display":10,"items":[{"title":"명예훼손 없이 <b>리뷰</b>쓰기","link":"http://openapi.naver.com/l?AAAB...","description":"명예훼손 없이 <b>리뷰</b>쓰기 우리 블로그하시는 분들께는...","bloggername":"건짱의 Best Drawing World2","bloggerlink":"http://blog.naver.com/yoonbitgaram","postdate":"20161208"}]}`}</code></pre>

<pre><code>{`from pydantic import BaseModel
from typing import List

class ItemsItem(BaseModel):
    title: str
    link: str
    description: str
    bloggername: str
    bloggerlink: str
    postdate: str

class BlogSearch(BaseModel):
    lastBuildDate: str
    total: int
    start: int
    display: int
    items: List[ItemsItem]`}</code></pre>

<ul>
  <li><code>title</code>과 <code>description</code>에는 검색어를 감싼 <code>{"<b>"}</code> 태그가 그대로 들어 있습니다. 타입은 <code>str</code>이고 태그는 지워지지 않으니, 화면에 보여 주기 전에 직접 제거하세요.</li>
  <li><code>postdate</code>는 <code>20161208</code> 같은 8자리 문자열이라 <code>str</code>입니다. 여기서 타입을 <code>date</code>로 바꾸면 Pydantic 2.13.5는 숫자로만 된 문자열을 Unix 타임스탬프로 읽기 때문에(<a href="https://docs.pydantic.dev/latest/api/standard_library_types/">Pydantic 표준 라이브러리 타입 문서</a>) <code>Datetimes provided to dates should have zero time - e.g. be exact dates</code> 오류가 납니다. 날짜로 쓰려면 <code>{'datetime.strptime(v, "%Y%m%d").date()'}</code>로 직접 변환하세요.</li>
  <li><code>lastBuildDate</code>는 <code>Mon, 26 Sep 2016 10:39:37 +0900</code> 형식이라 <code>datetime</code>으로 바꾸면 <code>Input should be a valid datetime or date, invalid character in year</code> 오류가 납니다. 표준 라이브러리의 <code>email.utils.parsedate_to_datetime()</code>은 이 형식을 읽어 <code>2016-09-26 10:39:37+09:00</code>을 돌려줍니다.</li>
</ul>

<h2>제한</h2>

<ul>
  <li><code>{"null"}</code>은 <code>{"Optional[Any]"}</code>가 됩니다. <code>{"Any"}</code>를 실제 타입으로 바꾸세요.</li>
  <li>그대로는 필드 이름이 될 수 없는 키(<code>{"class"}</code> 같은 예약어, <code>{"user-id"}</code>나 <code>2fa</code>처럼 식별자가 아닌 것, 전각 <code>ｎａｍｅ</code>처럼 NFKC로 바뀌는 것, <code>{"__"}</code>로 시작하는 것, 출력이 import하거나 타입으로 쓰는 이름(<code>str</code>, <code>Field</code>)이나 생성된 클래스와 이름이 같은 것. Pydantic에서는 <code>{"_"}</code>나 <code>{"model_"}</code>로 시작하는 키(MongoDB <code>{"_id"}</code> 등)와 <code>json</code> 같은 <code>BaseModel</code> 속성 이름도 포함)는 쓸 수 있는 이름으로 바꿉니다. @dataclass 모드는 줄 끝 주석에 원래 키를 적으므로 <code>{"Root(**data)"}</code> 전에 직접 맞춰 주세요. Pydantic 모드는 <code>{"Field(alias=...)"}</code>를 붙여 <code>{"model_validate()"}</code>가 원래 키로 읽고(<code>{"model_dump()"}</code>는 필드 이름으로 출력하므로 원래 키가 필요하면 <code>{"model_dump(by_alias=True)"}</code>를 쓰세요), TypedDict 모드는 함수형 문법 <code>{'TypedDict("Name", {...})'}</code>로 바꿔 키를 모두 그대로 남깁니다. 도구 테스트는 Python 3.12와 3.14에서 세 출력을 실행하고 샘플을 다시 읽습니다.</li>
  <li>날짜는 <code>{"str"}</code>로 남습니다. 타입을 <code>{"datetime"}</code>으로 바꾸면 Pydantic이 ISO 8601 문자열을 변환합니다.</li>
  <li>루트가 기본 타입 배열이면 클래스를 만들지 않습니다. 루트 배열에 객체와 다른 값이 섞여 있으면 객체로 루트 클래스를 만들고, 배열 전체의 타입을 마지막에 별칭 <code>{"RootArray = List[Union[...]]"}</code>으로 출력합니다(null 요소는 <code>None</code>). Pydantic에서는 <code>{"TypeAdapter(RootArray)"}</code>로 배열 전체를 검증할 수 있습니다.</li>
  <li><code>10.0</code>으로 쓴 숫자는 도구에 들어올 때 이미 정수 <code>10</code>입니다(JavaScript의 <code>JSON.parse</code>는 끝자리 0을 남기지 않음). 그래서 <code>{"price: int"}</code>가 되고, 나중에 <code>10.5</code>가 오면 Pydantic이 <code>Input should be a valid integer, got a number with a fractional part</code>로 거부합니다. 소수가 올 수 있는 값은 <code>float</code>로 고치세요.</li>
  <li>루트 클래스 이름은 Python 식별자로 쓸 수 있으면 그대로 쓰고, 아니면 바꿉니다: <code>{"order-item"}</code> → <code>OrderItem</code>, 숫자로 시작하는 <code>2fa</code> → <code>{"_2fa"}</code>, 예약어 <code>class</code> → <code>{"class_"}</code>, 앞의 <code>{"__"}</code>는 <code>{"_"}</code> 하나로(중첩 클래스 이름은 루트 클래스 이름으로 시작하는데, Python은 클래스 본문 안에서 밑줄 두 개로 시작하는 이름을 바꿔 버림), 쓸 수 있는 글자가 없으면 <code>Root</code>.</li>
  <li>한글 키도 클래스 이름에 글자가 모두 그대로 들어갑니다. 다만 JSON 키와 같은 이름의 클래스는 만들지 않으므로(Pydantic에서는 기본값이 있는 필드가 같은 이름의 클래스를 가립니다) 부모 클래스 이름을 앞에 붙입니다.</li>
</ul>

{/* jpdc-check: {"root":"Member","mode":"dataclass"} */}

<p>회원 데이터 예(루트 클래스 이름 <code>Member</code>, @dataclass 모드):</p>

<pre><code>{`{"이름": "홍길동", "주소": {"시도": "서울특별시", "시군구": "중구"}}`}</code></pre>

<pre><code>{`from dataclasses import dataclass

@dataclass
class Member주소:
    시도: str
    시군구: str

@dataclass
class Member:
    이름: str
    주소: Member주소`}</code></pre>

<p>Python 3은 식별자에 한글을 쓸 수 있어 <code>이름</code>, <code>주소</code>가 그대로 필드 이름이 되고 이 코드는 실행됩니다. 주소 클래스는 부모 이름을 붙인 <code>Member주소</code>입니다. 영문 이름이 필요하면 <code>Address</code> 같은 이름으로 바꾸세요.</p>

<h2>빈 배열과 샘플 범위</h2>

<p>빈 배열에는 요소 타입을 판단할 정보가 없으므로 <code>{`{"tags": []}`}</code>는 <code>tags: List[Any]</code>를 생성합니다. 같은 입력 배열에 <code>{`{"tags": ["admin"]}`}</code>가 있는 다른 객체를 넣으면 병합된 필드는 <code>List[str]</code>가 됩니다. 생성기는 입력한 샘플을 기준으로 타입을 추론하며, 어떤 샘플에도 없는 필드는 추론할 수 없습니다. 클래스를 복사하기 전에 키가 빠지거나 null 값이 있는 대표 객체를 포함하세요.</p>
