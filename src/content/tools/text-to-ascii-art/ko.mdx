## 예시

### 블로그 코드 블록

velog처럼 Markdown으로 쓰는 블로그에서는 「Markdown 코드 블록」 형식으로 복사해 붙입니다. 코드 블록 밖에서는 연속 공백이 하나로 합쳐지고, 줄 끝 공백 두 개는 [강제 줄바꿈](https://spec.commonmark.org/0.31.2/#hard-line-breaks)이 됩니다. `velog`를 Slant로 만든 결과입니다.

{/* figlet: {"font":"Slant","text":"velog"} */}

```text
             __
 _   _____  / /___  ____ _
| | / / _ \/ / __ \/ __ `/
| |/ /  __/ / /_/ / /_/ /
|___/\___/_/\____/\__, /
                 /____/
```

### 너비를 정하면 단어 단위로 넘어갑니다

`Hello World`를 Standard, 너비 40열로 만들면 두 번째 단어가 다음 단락으로 넘어갑니다. `figlet -f standard -w 40`과 같은 결과입니다.

{/* figlet: {"font":"Standard","text":"Hello World","width":40} */}

```text
 _   _      _ _
| | | | ___| | | ___
| |_| |/ _ \ | |/ _ \
|  _  |  __/ | | (_) |
|_| |_|\___|_|_|\___/

__        __         _     _
\ \      / /__  _ __| | __| |
 \ \ /\ / / _ \| '__| |/ _` |
  \ V  V / (_) | |  | | (_| |
   \_/\_/ \___/|_|  |_|\__,_|
```

### 한글은 건너뜁니다

`안녕 OK`를 입력하면 Standard는 `OK`만 그리고, 출력 아래에 「건너뜀: Standard 글꼴에 없는 문자: 안 녕」이 표시됩니다. 앞쪽 빈칸은 `안녕` 뒤의 공백입니다.

{/* figlet: {"font":"Standard","text":"안녕 OK"} */}

```text
   ___  _  __
  / _ \| |/ /
 | | | | ' /
 | |_| | . \
  \___/|_|\_\
```

## 역슬래시가 ₩로 보일 때

FIGlet 글꼴은 `\`를 많이 씁니다. 한국어 Windows의 코드 페이지 949에서 0x5C는 원화 기호이고, 시스템 로캘이 한국어이면 한국어 글꼴은 U+005C를 `₩` 모양으로 그립니다(Microsoft의 Michael Kaplan이 쓴 「[When is a backslash not a backslash?](http://archives.miloush.net/michkap/archive/2005/09/17/469941.html)」). 그래서 메모장이나 터미널 글꼴에 따라 위 예시의 `\`가 모두 `₩`로 보여 그림이 깨진 것처럼 보입니다. 데이터는 `\` 그대로이므로 붙여 넣은 내용은 정상이며, `₩`로 보이는 것은 그 환경의 글꼴 때문입니다. Consolas, Cascadia Code 같은 영문 고정폭 글꼴로 바꾸면 바르게 보입니다.

## figlet 명령과 같은 출력

조판 부분은 [figlet 2.2.5](https://github.com/cmatsuoka/figlet/tree/2.2.5)를 옮긴 것입니다. 같은 글꼴 파일로 figlet 2.2.5를 실행한 840가지 경우(12개 글꼴 × 5가지 자간, 여러 줄, 5가지 너비의 줄바꿈, 글꼴에 없는 문자)와 한 글자씩 비교해 모두 일치합니다. 이전 버전은 [figlet.js](https://github.com/patorjk/figlet.js) 1.11을 썼고, `Hello World`에서 12개 중 8개 글꼴이 figlet과 달랐습니다. Mini와 Shadow는 글꼴 파일이 겹치기를 요구하는데도 겹치지 않아, Mini가 26열이 아니라 37열이 되었습니다.

Banner, Big, Block, Lean, Mini, Script, Slant, Small, Standard는 figlet 2.2.5에 들어 있는 글꼴과 글리프가 같습니다. Doom과 3D-ASCII는 figlet에 포함되지 않고, 이 사이트의 Shadow는 공백을 넓힌 2007년 수정판입니다. 이 세 글꼴을 쓸 때(그리고 Standard에서 ಠ를 쓸 때) 표시되는 명령은 이 사이트의 `.flf` 파일을 읽습니다.

## 자간 선택지

[FIGfont 사양](https://github.com/cmatsuoka/figlet/blob/2.2.5/figfont.txt)은 글꼴마다 기본 배치와 최대 6개의 「합치기」 규칙(같은 문자 둘은 하나로, `/`와 `\`는 `|`로 등)을 정할 수 있게 합니다.

| 선택지 | figlet 옵션 | 동작 |
|---|---|---|
| 글꼴 기본값 | 없음 | 글꼴 작성자가 정한 배치 |
| 전체 폭 (-W) | `-W` | 빈 열까지 포함해 글자마다 원래 폭을 유지 |
| 붙이기 (-k) | `-k` | 닿을 때까지 붙이고 겹치지 않음 |
| 합치기 (-S) | `-S` | 글꼴 규칙으로 한 열 겹침. 기본값이 「붙이기」인 글꼴도 합침 |
| 겹치기 (-o) | `-o` | 어떤 문자가 만나든 한 열 겹침 |

이 도구로 측정(줄 끝 공백과 앞뒤 빈 줄 제거):

| 글꼴 | `Hello World` 줄 수 | `Hello World` 열 수 | 너비 80에서 한 단락에 들어가는 `ABC…Z` 글자 수 |
|---|---|---|---|
| Mini | 2 | 26 | 26 |
| Small | 4 | 43 | 16 |
| Doom | 6 | 50 | 12 |
| Standard | 5 | 52 | 13 |
| Slant | 5 | 57 | 12 |
| Block | 5 | 90 | 7 |
| 3D-ASCII | 7 | 117 | 7 |

## 다른 생성기와 비교

2026-10-01에 `Hello World`와 `Hi 中文`으로 확인했습니다.

- [TAAG](https://patorjk.com/software/taag/): figlet.js 기반이라 Standard의 첫 열에 공백이 하나 더 있고, Mini는 37열입니다. 한자는 안내 없이 사라집니다. 글꼴 수는 이 도구보다 훨씬 많고 이미지 저장도 됩니다.
- [asciiart.eu](https://www.asciiart.eu/text-to-ascii-art): Standard는 figlet과 같지만 Mini는 겹치지 않아 37열입니다. 한자가 한 글자라도 있으면 출력이 비어 버립니다.

이 도구는 figlet 명령과 일치하고, 건너뛴 문자를 알려 주며, 같은 결과를 내는 명령도 보여 줍니다. 채팅이나 프로필에서 한 줄짜리 장식 영문이 필요하면 [영어 글씨체 변환기](/ko/tools/unicode-text-converter/)를, README에서 어떻게 보이는지는 [Markdown 미리보기](/ko/tools/markdown-preview/)로 확인하세요. JSON 문자열에 넣으려면 먼저 [문자열 이스케이프](/ko/tools/string-escape/)로 `\`와 줄바꿈을 이스케이프하세요.

## 제한 사항

- **글꼴은 12가지**이며 글꼴을 추가할 수 없습니다.
- **라틴 문자 중심입니다.** 글꼴에 없는 문자는 그려지지 않고 출력 아래에 표시됩니다. 탭은 figlet처럼 공백이 되고, 나머지 제어 문자는 버려지며 함께 표시됩니다.
- **최대 2,000자**까지 처리합니다. 넘으면 출력 대신 안내가 나옵니다.
- **텍스트 한 줄이 한 단락이 됩니다.** figlet 2.2.5는 세로 방향으로 합치지 않아 단락이 그대로 위아래로 놓입니다.
- **PNG 크기**는 한 변 16,384픽셀, 전체 16,777,216픽셀(iOS Safari 캔버스 한도)까지입니다. 넘으면 너비를 지정하세요.
- 고정폭 글꼴에서만 줄이 맞습니다.
