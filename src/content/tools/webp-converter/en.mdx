<h2>Limits</h2>
<ul>
  <li><strong>Animation is lost.</strong> The image is drawn to a canvas once, so an animated GIF becomes a still WebP of its first frame, and an animated WebP becomes a one-frame PNG. To shrink an animated GIF instead, use the <a href="/tools/gif-compressor/">GIF compressor</a>.</li>
  <li><strong>Metadata is dropped.</strong> EXIF (camera, GPS, date) and XMP are not copied.</li>
  <li><strong>Input types:</strong> PNG, JPEG and GIF for the WebP direction, WebP for the PNG direction. Files are checked by the type the browser reports, which <a href="https://developer.mozilla.org/en-US/docs/Web/API/Blob/type">MDN</a> says is assumed from the file extension. HEIC, AVIF or BMP is listed as "Not a supported format"; a PNG renamed to .jpg is accepted and converted, and a file that is not an image but has an image extension fails with "Failed to load image".</li>
  <li><strong>The encoder is your browser's.</strong> Sizes differ between Chrome and Firefox for the same quality. Safari has no WebP encoder for canvas; there the tool reports that WebP cannot be encoded instead of saving a PNG under a .webp name.</li>
  <li><strong>Quality and lossless only.</strong> There is no resize, crop, or setting for encoder effort or near-lossless mode. For those, use <code>cwebp</code> from libwebp, for example <code>cwebp -q 80 in.png -o out.webp</code> or <code>cwebp -lossless in.png -o out.webp</code>.</li>
</ul>

<h2>When to Convert Images to WebP</h2>
<ul>
  <li><strong>Web performance:</strong> Replace JPEG/PNG assets on websites to reduce page weight and improve Core Web Vitals scores.</li>
  <li><strong>Email campaigns:</strong> only after checking that your readers' mail clients display WebP (support differs between clients); otherwise keep JPEG or PNG for email.</li>
  <li><strong>App development:</strong> Use WebP in mobile and web apps to reduce asset bundle size.</li>
  <li><strong>CDN cost reduction:</strong> Smaller files mean less egress bandwidth billed by your CDN.</li>
</ul>

<h2>WebP vs JPEG vs PNG</h2>
<p>
  WebP supports both lossy and lossless compression, as well as transparency (like PNG) and animation (like GIF).
  <a href="https://developers.google.com/speed/webp">Google's published comparison</a> reports lossless WebP 26% smaller than PNG and
  lossy WebP 25–34% smaller than JPEG at equal SSIM. All current major browsers display WebP, so on the web you can usually serve it directly;
  use <code>&lt;picture&gt;</code> with a JPEG or PNG fallback only if you must support very old browsers.
</p>
