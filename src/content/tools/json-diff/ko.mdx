  <li>설정 파일 변경 감사.</li>
  <li>애플리케이션의 예상치 못한 데이터 변경 디버그.</li>

<p>관련 도구: <a href="/ko/tools/json-formatter/">JSON Formatter (JSON 정렬)</a> — 비교 전 JSON을 정리하고 검증합니다.</p>

## 예시

**이전:**

```json
{"name":"Alice","status":"pending","legacy_id":12345,"tags":["a","b","c"],"profile":{"age":30,"city":"Paris"}}
```

**이후**(키 순서 변경, `status` 변경, `legacy_id` 삭제, `role` 추가, 첫 번째 태그 삭제):

```json
{"status":"active","name":"Alice","role":"admin","tags":["b","c"],"profile":{"age":31,"city":"Paris"}}
```

**JSON Patch:**

{/* diff: {"before":{"name":"Alice","status":"pending","legacy_id":12345,"tags":["a","b","c"],"profile":{"age":30,"city":"Paris"}},"after":{"status":"active","name":"Alice","role":"admin","tags":["b","c"],"profile":{"age":31,"city":"Paris"}}} */}

```json
[
  { "op": "replace", "path": "/status", "value": "active" },
  { "op": "remove", "path": "/legacy_id" },
  { "op": "replace", "path": "/tags/0", "value": "b" },
  { "op": "replace", "path": "/tags/1", "value": "c" },
  { "op": "remove", "path": "/tags/2" },
  { "op": "replace", "path": "/profile/age", "value": 31 },
  { "op": "add", "path": "/role", "value": "admin" }
]
```

키 순서는 결과에 영향을 주지 않습니다. `name`은 위치가 바뀌었지만 보고되지 않습니다. 이 패치를 Python `jsonpatch` 1.33으로 적용하면 이후 문서가 됩니다.

## 예시: 카카오 로컬 검색 응답 비교

[카카오 로컬 API](https://developers.kakao.com/docs/latest/ko/local/dev-guide) ‘키워드로 장소 검색’ 응답 예제에서 `meta`와 `documents` 첫 항목의 일부 필드를 이전으로 두고, 다른 위치에서 다시 검색했다고 가정해 숫자를 바꾼 문서를 이후로 둡니다.

{/* diff: {"before":{"meta":{"pageable_count":14,"total_count":14,"is_end":true},"documents":[{"place_name":"카카오프렌즈 코엑스점","distance":"418","id":"26338954","phone":"02-6002-1880"}]},"after":{"meta":{"pageable_count":15,"total_count":15,"is_end":false},"documents":[{"place_name":"카카오프렌즈 코엑스점","distance":"1033","id":"26338954","phone":"02-6002-1880"}]}} */}

```json
[
  { "op": "replace", "path": "/meta/pageable_count", "value": 15 },
  { "op": "replace", "path": "/meta/total_count", "value": 15 },
  { "op": "replace", "path": "/meta/is_end", "value": false },
  { "op": "replace", "path": "/documents/0/distance", "value": "1033" }
]
```

응답 예제에서 `distance`와 `id`는 숫자가 아니라 문자열(`"418"`, `"26338954"`)이므로 패치 값도 문자열 `"1033"`입니다. 문자열 `"418"`과 숫자 `418`은 다른 값이라, 한쪽만 숫자로 바뀐 응답을 비교하면 `replace`로 나옵니다. 같은 장소가 목록의 다른 위치로 옮겨 가면 인덱스로 비교하기 때문에 여러 필드의 `replace`로 보입니다.

## 배열 비교 방식

배열은 내용이 아니라 인덱스로 비교합니다. `["a","b","c"]`에서 첫 번째 태그를 빼면 `remove /tags/0` 하나가 아니라 교체 두 개와 삭제 하나로 표시됩니다. 같은 배열에서 여러 요소를 지우면 삭제는 큰 인덱스부터 씁니다. 예를 들어 주문 항목 3개가 1개로 줄고 수량도 바뀐 경우:

{/* diff: {"before":{"id":7,"items":[{"sku":"A1","qty":2},{"sku":"B2","qty":1},{"sku":"C3","qty":5}]},"after":{"id":7,"items":[{"sku":"A1","qty":3}]}} */}

```json
[
  { "op": "replace", "path": "/items/0/qty", "value": 3 },
  { "op": "remove", "path": "/items/2" },
  { "op": "remove", "path": "/items/1" }
]
```

`remove /items/2` 뒤에도 배열에 2개가 남아 있으므로 `/items/1`은 여전히 존재합니다. 작은 인덱스부터 쓰면 두 번째 삭제가 배열 끝을 넘어가고, 연산 하나라도 실패하면 패치 전체가 실패합니다([RFC 6902 5절](https://www.rfc-editor.org/rfc/rfc6902#section-5)).

## 경로와 JSON Pointer 이스케이프

patch 경로는 JSON Pointer([RFC 6901](https://www.rfc-editor.org/rfc/rfc6901))입니다. `~`는 `~0`, `/`는 `~1`로 쓰고, 한글 키는 그대로 씁니다. 키에 `/`나 `~`가 들어간 설정을 비교하면:

{/* diff: {"before":{"입/출금":{"한도":1000000},"수수료~면제":true,"통장":"주거래"},"after":{"입/출금":{"한도":3000000},"통장":"주거래"}} */}

```json
[
  { "op": "replace", "path": "/입~1출금/한도", "value": 3000000 },
  { "op": "remove", "path": "/수수료~0면제" }
]
```

`입/출금`을 `/입/출금`이라고 쓰면 `입` 안의 `출금`을 가리키게 되므로, 패치는 `/`를 `~1`로 바꿉니다. 같은 규칙의 예시:

{/* diff: {"before":{"a/b":1,"m~n":2,"list":[1,2,3]},"after":{"a/b":2,"list":[1,2,3,4],"x":null}} */}

```json
[
  { "op": "replace", "path": "/a~1b", "value": 2 },
  { "op": "remove", "path": "/m~0n" },
  { "op": "add", "path": "/list/3", "value": 4 },
  { "op": "add", "path": "/x", "value": null }
]
```

루트 타입이 다르면(객체와 배열 등) 패치는 문서 전체를 교체하고 경로는 빈 문자열 `""`입니다(RFC 6901에서 `/`는 이름이 빈 문자열인 멤버를 가리킴):

{/* diff: {"before":{"a":1},"after":[1]} */}

```json
[
  { "op": "replace", "path": "", "value": [1] }
]
```

시각적 차이는 키를 점으로 이어 보여 줍니다(`profile.age`, `입/출금.한도`). 읽기용 표기이므로 코드에서는 JSON Patch의 경로를 쓰세요.

## 제한 사항

- move, copy 연산은 만들지 않습니다. 이름이 바뀐 키는 `remove`와 `add`로 표시됩니다.
- 객체 배열을 `id` 필드로 짝짓지 않습니다.
- 양쪽 모두 유효한 JSON이어야 합니다. 상태 표시줄에 어느 쪽 파싱이 실패했는지 나옵니다(예: `이전 JSON 파싱 오류: Expected double-quoted property name in JSON at position 7`. 원인 부분은 브라우저가 내는 영어 그대로입니다).
- 숫자는 JavaScript로 파싱한 뒤 비교하므로 `1.0`과 `1`은 같고, `-0`은 패치에 `0`으로 씁니다. 2^53을 넘는 정수, 아주 긴 소수, `1e400` 같은 숫자는 반올림되며 상태 표시줄에 목록이 나옵니다(최대 10개, 나머지는 개수). 패치에는 반올림된 값을 씁니다(`1e400`은 `null`).
- 한 객체 안에서 중복된 키는 마지막 값만 남으며 상태 표시줄에 표시됩니다.
- 약 1,900단계(Node.js 22에서 측정, 브라우저마다 다름)로 중첩된 문서는 비교하지 못하고, 상태 표시줄에 그렇게 알려 줍니다.
- 도구의 테스트는 생성한 패치를 엄격한 RFC 6902 구현(설치되어 있으면 Python `jsonpatch`도)으로 "이전"에 적용해 결과가 "이후"와 같은지 확인하며, 무작위 문서 3,000쌍도 검사합니다.
