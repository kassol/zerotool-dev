<h2>使い方</h2>
<ol>
  <li>SVG マークアップを貼り付け、または「ファイルをアップロード」タブで <code>.svg</code> をドロップします。</li>
  <li>必要なプラグインを切り替えます。既定値は SVGO の <em>preset-default</em> に揃え、主トグル 8 件で最頻出の判断をカバーします。</li>
  <li><strong>SVG を最適化</strong>を押下。最適化前 / 後でバイト数・削減率・実際の描画結果を並べて表示し、視覚的なリグレッションを即座に確認できます。</li>
  <li><strong>出力をコピー</strong>でコードベースに即貼付、または<strong>.svg をダウンロード</strong>でファイル保存。</li>
</ol>

<h2>削除される内容</h2>
<p>
  SVGO はエディタのメタデータ、コメント、非表示要素、既定属性など描画に影響しないマークアップを削除し、パスデータを書き直し、隣接パスを統合し、色記法を短縮します。どれだけ減るかはファイルにそうした要素がどれだけあるかで変わります。下の例のエクスポートしたアイコンは 511 バイトから 254 バイトになります。
</p>

<h2>注意すべき 2 つのトグル</h2>
<p>
  <strong>viewBox を削除</strong>と<strong>width/height を削除</strong>が既定でオフなのには理由があります。<code>viewBox</code> がない SVG はレスポンシブにスケールできず、<code>width</code> / <code>height</code> がない SVG は親要素から描画ボックスを継承します — ダウンロード可能なアイコンとして配布する場合はまず望ましくない結果です。埋め込みコンテキストを完全に制御している場合（親 <code>&lt;use&gt;</code> でサイズを指定したスプライトシートなど）に限り有効化してください。
</p>

<h2>最適化のタイミング</h2>
<ul>
  <li><strong>本番ビルド：</strong><code>vite-plugin-svgo</code> 等でバンドラ側に SVGO を組み込みます。本ツールは CLI を起動せず結果を即確認したい場合に便利です。</li>
  <li><strong>手書き / エクスポートされた SVG：</strong>Figma・Illustrator・Sketch はエディタのメタデータと未使用 <code>id</code> 属性を大量に残します。SVGO はそれらをきれいに除去します。</li>
  <li><strong>HTML へのインライン SVG：</strong>マークアップが直接埋め込まれる場合、1 KB ごとに初回描画が遅れます — 小さければ小さいほど良好です。</li>
</ul>

<h2>仕様：1 ファイル単位</h2>
<p>
  本ツールは 1 ファイルずつ最適化します。バッチ最適化、カスタムプラグイン記述、CI 統合は SVGO コマンドラインに任せましょう — <code>npm install -g svgo</code> 後、<code>svgo input.svg -o output.svg</code> でディレクトリや glob を一括処理できます。本ツールでトグル構成を確定したら、SVGO 公式ドキュメントから対応する <code>svgo.config.js</code> をコピーしてビルドに組み込めます。
</p>

<p>
  最適化後に PNG へ変換、または React へ抽出したい場合は <a href="/ja/tools/svg-to-png-converter/">SVG → PNG 変換</a> と <a href="/ja/tools/svg-to-jsx/">SVG → JSX</a> を続けて使用してください。
</p>

<h2>例：デザインツールから書き出したアイコン</h2>
<p>既定のトグル（SVGO 4.0.1、マルチパス有効、精度 3）で、この 511 バイトのファイルは</p>

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- Generator: Figma -->
<svg width="24" height="24" viewBox="0 0 24 24" fill="none" xmlns="http://www.w3.org/2000/svg">
  <title>Check</title>
  <defs>
    <style>.stroke { stroke: #000000; stroke-width: 2.000000; }</style>
  </defs>
  <g id="icon-check">
    <rect x="0" y="0" width="24" height="24" fill="none"/>
    <path class="stroke" d="M 5.000000 12.000000 L 10.000000 17.000000 L 19.000000 7.000000" stroke-linecap="round" stroke-linejoin="round"/>
  </g>
</svg>
```

<p>254 バイトになります。</p>

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" fill="none" viewBox="0 0 24 24"><title>Check</title><path d="M0 0h24v24H0z"/><path stroke-linecap="round" stroke-linejoin="round" d="m5 12 5 5 9-10" style="stroke:#000;stroke-width:2"/></svg>
```

<p>XML 宣言、コメント、参照されていない <code>id="icon-check"</code> が消えました。1 回しか使われない <code>.stroke</code> クラスは <code>style</code> 属性に展開され、<code>&lt;style&gt;</code> ブロックは削除されています。パスは相対コマンドに書き直され、<code>#000000</code> は <code>#000</code> になりました。<code>&lt;title&gt;</code> は残ります。SVGO 4 では既定で削除しません。<strong>viewBox を削除</strong>だけをオンにすると、<code>width="24" height="24"</code> が残り viewBox がない出力になり、アイコンは拡大縮小できなくなります。リスクのある 2 つのトグルを両方オンにすると、viewBox があり幅と高さがない結果になります。<code>removeViewBox</code> が viewBox を消したあと、<code>removeDimensions</code> がサイズを消して、そこから viewBox を書き戻すためです。</p>

<h2>制限</h2>
<ul>
  <li><strong>ID は短縮されます。</strong><code>cleanupIds</code> は参照されている ID を <code>a</code>、<code>b</code> などに付け替えます。<code>id="brand-gradient"</code> のグラデーションは <code>id="a"</code> になります。最適化した SVG を 1 つの HTML に複数インラインで埋め込むと ID が衝突し、あるアイコンが別のアイコンのグラデーションを使ってしまうことがあります。ID のトグルを外すか、ビルド時に SVGO の <code>prefixIds</code> でファイルごとに接頭辞を付けてください。</li>
  <li>ページの CSS や JavaScript からだけ参照される ID とクラスは SVGO から見えません。未使用の ID は削除され、1 回だけ使うクラスは展開されるため、外部からそれらを指定したスタイルは効かなくなります。</li>
  <li>座標は既定で小数点以下 3 桁に丸めます。viewBox のスケールが小さい精細な図形で「後」のプレビューの点がずれる場合は精度を上げてください。</li>
  <li>処理は 1 ファイルずつです。フォルダーや CI では SVGO のコマンドライン（<code>npx svgo -f icons/ -o dist/</code>）を同じ設定で使ってください。</li>
</ul>
