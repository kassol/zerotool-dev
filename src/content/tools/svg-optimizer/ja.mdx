<h2>最適化で壊れていないかを確かめる</h2>
<p>
  SVGO の処理が終わると、元のファイルと結果を長辺 400 ピクセルでブラウザに描かせ、1 ピクセルずつ比べます。色かアルファの差が 24/255 を超えるピクセルを「変化あり」と数え、全体の 0.1% 以下ならアンチエイリアスの誤差として「描画結果は同じです」と表示します。それを超えると、変わった場所を赤で示した差分画像が出ます。
</p>
<p>
  HTML からコピーした SVG には <code>xmlns="http://www.w3.org/2000/svg"</code> がないことがよくあります。インラインなら表示されますが、<code>.svg</code> ファイルとしては画像として開けません。このツールは最適化の前に補い、注意として表示します。
</p>

<h2>例：レイヤー名が ID に残った SVG</h2>
{/* svgo-check: {"fixture":"illustrator_ja","bytes":[373,209],"notes":["idsGone","classesGone"],"render":"same","output":"<svg xmlns=\"http://www.w3.org/2000/svg\" data-name=\"レイヤー 1\" viewBox=\"0 0 120 40\"><rect width=\"120\" height=\"40\" rx=\"8\" ry=\"8\" style=\"fill:#e60012\"/><circle cx=\"20\" cy=\"20\" r=\"8\" style=\"fill:#fff\"/></svg>"} */}
<p>
  Illustrator はレイヤー名やグループ名を SVG の ID として書き出します（<a href="https://ascii.jp/elem/000/001/522/1522707/" rel="noopener">ASCII.jp「基礎から学ぶ、IllustratorでSVGを最適化して書き出す方法」</a>）。次は、レイヤー名「レイヤー 1」がルートの <code>id</code> と <code>data-name</code> に残り、色が <code>.cls-1</code> などのクラスで指定された 373 バイトのボタン背景です。
</p>

```xml
<svg id="_レイヤー_1" data-name="レイヤー 1" xmlns="http://www.w3.org/2000/svg" viewBox="0 0 120 40">
  <defs>
    <style>
      .cls-1 {
        fill: #e60012;
      }

      .cls-2 {
        fill: #fff;
      }
    </style>
  </defs>
  <rect class="cls-1" x="0" y="0" width="120" height="40" rx="8" ry="8"/>
  <circle class="cls-2" cx="20" cy="20" r="8"/>
</svg>
```

<p>既定の設定では 209 バイトになり、描画は同じです。</p>

```xml
<svg xmlns="http://www.w3.org/2000/svg" data-name="レイヤー 1" viewBox="0 0 120 40"><rect width="120" height="40" rx="8" ry="8" style="fill:#e60012"/><circle cx="20" cy="20" r="8" style="fill:#fff"/></svg>
```

<p>
  注意は 2 件です。<code>#_レイヤー_1</code> はファイル内で参照されていないので削除され、<code>.cls-1</code> と <code>.cls-2</code> は 1 回しか使われていないので <code>style</code> 属性に書き込まれました（<a href="https://svgo.dev/docs/plugins/inlineStyles/" rel="noopener">inlineStyles</a>）。サイトの CSS で <code>.cls-1</code> の色を変えていた場合、見た目は同じでもその指定は効かなくなります。一方、<code>data-*</code> 属性は SVGO の既定では消えないため、<code>data-name="レイヤー 1"</code> は残ります。消したい場合は Illustrator 側の書き出し設定を見直すか、出力を手で直してください。
</p>

<h2>例：小さくならないファイル</h2>
{/* svgo-check: {"fixture":"korea","bytes":[589,816],"notes":["larger"],"render":"same"} */}
{/* svgo-check: {"fixture":"korea","precision":1,"bytes":[589,603],"notes":["lowPrecision","larger"],"render":"minor"} */}
<p>
  Wikimedia Commons の<a href="https://commons.wikimedia.org/wiki/File:Flag_of_South_Korea.svg" rel="noopener">大韓民国の国旗</a>（589 バイト）は、すでに手作業で最適化されています。SVGO にかけると 816 バイトに増えます。卦の <code>rotate(33.69006752598)</code> を <a href="https://svgo.dev/docs/plugins/convertTransform/" rel="noopener">convertTransform</a> がパスの座標に書き込み、回転後の座標は桁数が多いためです。このツールは「元のファイルより大きい」と表示します。小数点以下を 1 桁にしても 603 バイトで、描画比較では卦の線の位置にわずかな差が出ます。
</p>

<h2>スクリプトと出所のわからない SVG</h2>
<p>
  既定の SVGO は <code>&lt;script&gt;</code> や <code>onclick</code> などのイベント属性を残します。このツールはその数を注意に表示します。「スクリプトとイベント属性を削除」をオンにすると <a href="https://svgo.dev/docs/plugins/removeScripts/" rel="noopener">removeScripts</a> が動き、SVGO 4.1.0 では <code>&lt;foreignObject&gt;</code> 内の HTML のイベント属性も削除されます。ブラウザは画像として使われた SVG（<code>&lt;img&gt;</code> や CSS 背景）ではスクリプトも外部ファイルも読み込みませんが、直接開いたとき、インラインで置いたとき、<code>&lt;object&gt;</code> や <code>&lt;iframe&gt;</code> で埋め込んだときは実行されます（<a href="https://developer.mozilla.org/ja/docs/Web/SVG/Guides/SVG_as_an_image" rel="noopener">MDN「画像としての SVG」</a>）。このページのプレビューは画像なので、貼り付けた SVG のスクリプトはここでは動きません。SVGO は最適化ツールで、ユーザーがアップロードした SVG を無害化する専用の仕組みの代わりにはなりません。
</p>

<h2>複数ファイルとビルドへの組み込み</h2>
<p>
  アイコンのフォルダをまとめてドロップすると、ファイルごとに最適化前後のサイズ、削減率、描画比較の結果が 1 行ずつ並び、「すべてダウンロード（.zip）」で元のファイル名のまま保存できます（<code>.svgz</code> は展開して <code>.svg</code> で保存）。設定が決まったら設定パネルの <code>svgo.config.mjs</code> をコピーし、プロジェクトで <code>npx svgo@4.1.0 --config svgo.config.mjs -f icons -o icons-min</code> を実行すれば、同じ結果が得られます。
</p>

<h2>ほかのツールとの違い</h2>
<p>
  2026 年 10 月 2 日、同じファイルで試しました。<a href="https://www.miniwebtool.com/ja/svg%E6%9C%80%E9%81%A9%E5%8C%96%E3%83%84%E3%83%BC%E3%83%AB/" rel="noopener">MiniWebtool の SVG 最適化ツール</a>（Bing「svg 最適化」1 位）は、貼り付けた SVG コードをフォームで自社サーバーに送信します。xmlns のない SVG は 119 → 119 バイトのまま、コメントも残って返ってきましたが、何のメッセージも出ませんでした。iLoveIMG（Bing「svg 圧縮」1 位）はファイルを <code>api11.iloveimg.com/v1/upload</code> にアップロードします。<a href="https://jakearchibald.github.io/svgomg/" rel="noopener">SVGOMG</a> は SVGO 4.0.0 をローカルで動かしますが、1 ファイルずつで、ID の削除やファイルの増加を知らせません。いずれも最適化前後の描画比較はありません。
</p>

<h2>制限</h2>
<ul>
  <li>1 ファイル 50 MB まで。10 MB を超えるファイルは最適化しますが、描画は比較しません。</li>
  <li>XML のエラーは、入力したテキストでの行と列（文字単位）と、ページの言語での理由を表示します。xmlns のない <code>&lt;svg&gt;&lt;rect&gt;&lt;/svg&gt;</code> は 1 行 17 列で、終了タグ &lt;/svg&gt; が最後に開いた要素と対応していないと表示します。ツールが補う xmlns は列に数えません。</li>
  <li>アニメーションは最初のフレームだけを比較します。外部の画像・フォント・<code>&lt;use href="other.svg#id"&gt;</code> は画像として読み込まれないため、比較の対象外です。</li>
  <li>ファイル外の CSS や JavaScript がどの ID・class を使っているかは SVGO にはわかりません。注意には消えたものだけが出ます。</li>
  <li>埋め込まれた PNG・JPEG は再圧縮されません。パラメーターが必要な 5 つのプラグイン（removeAttrs など）にはスイッチがありません。</li>
  <li>「React コンポーネント（JSX）」形式のコピーでは、コメント・<code>&lt;style&gt;</code> ブロック・<code>style</code> 属性を <a href="/ja/tools/svg-to-jsx/">SVG → JSX コンバーター</a>と同じ方法で変換します。React のスタイルオブジェクトで保持できない <code>style</code>（SVGO が残す <code>fill:red!important</code> など）は変換せず、ボタンの下に理由を表示してそのファイルのコピーを無効にします。ダウンロード、一覧の行ごとのダウンロード、ZIP は最適化した SVG をそのまま保存し、ほかのコピー形式にも影響しません。</li>
</ul>
<p>
  最適化した SVG をビットマップにするなら <a href="/ja/tools/svg-to-png-converter/">SVG PNG 変換ツール</a>、TypeScript や forwardRef 付きの React コンポーネントにするなら <a href="/ja/tools/svg-to-jsx/">SVG → JSX コンバーター</a>、Data URI で埋め込むなら <a href="/ja/tools/image-to-base64/">画像 Base64 変換ツール</a>が使えます。
</p>
