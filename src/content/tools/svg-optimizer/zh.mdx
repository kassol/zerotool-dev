<h2>用法</h2>
<ol>
  <li>把一个或多个 <code>.svg</code>、<code>.svgz</code> 文件拖到上传框，或点击选择；也可以把 SVG 代码粘贴到输入框，或在页面任意位置按 Ctrl+V。</li>
  <li>文件会立即用 SVGO 的 <a href="https://svgo.dev/docs/preset-default/" rel="noopener">preset-default</a>（34 个插件）、多轮优化和 3 位小数压缩。</li>
  <li>看体积下方那一行：它说明压缩后的渲染结果是否与原文件相同。再往下是提示，列出可能在使用处出问题的改动。</li>
  <li>下载 <code>.svg</code>，或按 SVG 代码、Data URI、CSS、React 组件复制；多个文件可一次下载 ZIP。</li>
  <li>改动设置后会自动重新压缩。展开「在构建中使用这组设置」可复制对应的 <code>svgo.config.mjs</code>。</li>
</ol>

<h2>压缩后怎么确认没改坏</h2>
<p>
  SVGO 处理完后，工具用浏览器把原文件和结果都按长边 400 像素画出来，逐个像素比较。颜色通道或不透明度相差超过 24/255 的像素算作有变化；有变化的像素不超过 0.1% 时属于抗锯齿误差，显示「渲染结果相同」，超过时用红色标出变化的位置。
</p>
<p>
  从网页 HTML 里复制出来的 SVG 常常没有 <code>xmlns="http://www.w3.org/2000/svg"</code>，这样的代码内联在网页里能显示，存成 <code>.svg</code> 文件却打不开。工具会在压缩前补上，并在提示里说明。
</p>

<h2>示例：ECharts 服务端渲染导出的图表</h2>
{/* svgo-check: {"fixture":"echarts","bytes":[3553,2452],"gzip":[852,690],"notes":[],"render":"same"} */}
<p>
  ECharts 的<a href="https://echarts.apache.org/handbook/zh/how-to/cross-platform/server/" rel="noopener">服务端渲染</a>可以用 <code>renderToSVGString()</code> 直接得到 SVG 字符串，适合放进报告或邮件。下面这段代码用 ECharts 6.1.0 生成一张 600 × 360 的柱状图：
</p>

```js
const chart = echarts.init(null, null, { renderer: 'svg', ssr: true, width: 600, height: 360 });
chart.setOption({
  animation: false,
  title: { text: '2026 年各季度销售额（万元）' },
  xAxis: { type: 'category', data: ['一季度', '二季度', '三季度', '四季度'] },
  yAxis: { type: 'value' },
  series: [{ type: 'bar', data: [120, 200, 150, 80] }]
});
const svg = chart.renderToSVGString();
```

<p>
  得到的文件是 3,553 字节，压缩后 2,452 字节（gzip 后 852 → 690 字节），渲染结果相同，没有提示。五条网格线被合并成一条路径，四根柱子也合并成一条路径。ECharts 写在 <code>&lt;style&gt;</code> 里的 <code>.zr0-cls-1:hover</code> 这类悬停规则无法写进元素属性，所以对应的 class 都保留了下来，中文标题和坐标轴文字不变。
</p>

<h2>示例：设计稿导出的图标</h2>
{/* svgo-check: {"fixture":"figma","bytes":[512,254],"notes":["idsGone","classesGone"],"render":"same"} */}
<p>
  点「示例」会载入一个 512 字节、按 Figma 导出格式写的对勾图标。压缩后是 254 字节，渲染相同，但会出现两条提示：<code>#icon-check</code> 被删除（外层分组被合并，文件内没有用到这个 ID），<code>.stroke</code> 被删除（只用一次的 class 被写进了 <code>style</code> 属性）。如果页面 CSS 用 <code>.stroke</code> 改颜色，或 JavaScript 用 <code>#icon-check</code> 取元素，图标看起来没变，代码却失效了。这时取消「缩短并删除 ID」，或在「全部 SVGO 插件」里取消 inlineStyles 和 minifyStyles。
</p>

<h2>哪些设置会改坏 SVG</h2>
<ul>
  <li><strong>缩短并删除 ID</strong>（默认开）：被引用的 ID 改成 <code>a</code>、<code>b</code>，没被引用的删掉。同一页面内联多个 SVG 时，可以填「ID 前缀」避免冲突。</li>
  <li><strong>删除 viewBox</strong>（默认关）：只删除与 width、height 相同的 viewBox，删掉后 SVG 不再随 CSS 缩放（<a href="https://svgo.dev/docs/plugins/removeViewBox/" rel="noopener">SVGO 文档</a>）。SVGO 4 已把它和 removeTitle 移出默认配置。</li>
  <li><strong>删除 width/height</strong>（默认关）：尺寸改由 CSS 或容器决定；没有 viewBox 时 SVGO 会按原尺寸补一个。</li>
  <li><strong>删除 &lt;title&gt;</strong>（默认关）：读屏软件会失去图片名称。</li>
  <li><strong>小数位数</strong>（默认 3）：设成 0 或 1 时图形上的点可能明显移动，像素比对会标出来。</li>
</ul>

<h2>脚本与来源不明的 SVG</h2>
<p>
  默认设置下 SVGO 会保留 <code>&lt;script&gt;</code> 和 <code>onclick</code> 等事件属性，工具会统计数量并提示。勾选「删除脚本和事件属性」会运行 <a href="https://svgo.dev/docs/plugins/removeScripts/" rel="noopener">removeScripts</a>，SVGO 4.1.0 还会清理 <code>&lt;foreignObject&gt;</code> 里的 HTML 事件属性。浏览器把 SVG 当图片用时（<code>&lt;img&gt;</code>、CSS 背景）不执行脚本、不加载外部文件（<a href="https://developer.mozilla.org/zh-CN/docs/Web/SVG/Guides/SVG_as_an_image" rel="noopener">MDN</a>），直接打开、内联或用 <code>&lt;object&gt;</code>、<code>&lt;iframe&gt;</code> 嵌入时则会执行。本页的预览都是图片，粘贴进来的 SVG 里的脚本不会在页面上运行。SVGO 是压缩工具，处理用户上传的 SVG 时不能代替专门的过滤。
</p>

<h2>批量处理与构建</h2>
<p>
  一次拖入一整个图标文件夹，每个文件一行，显示压缩前后体积、减少比例和渲染比对结果，「全部下载（.zip）」按原文件名打包（<code>.svgz</code> 会解压后保存为 <code>.svg</code>）。确定设置后，从配置面板复制 <code>svgo.config.mjs</code>，在项目里执行 <code>npx svgo@4.1.0 --config svgo.config.mjs -f icons -o icons-min</code> 就能得到同样的结果。
</p>

<h2>与同类工具的差别</h2>
<p>
  2026 年 10 月 2 日用同一组文件实测。<a href="https://svgoptimizer.com/zh" rel="noopener">svgoptimizer.com</a>（cn.bing.com「svg压缩」第一）在浏览器内处理，但韩国国旗和含 <code>&lt;script&gt;</code> 的文件都显示「-0%」，下载得到的是原文件（连注释都没删）；只有 viewBox 的文件在结果里多出了 <code>width="24" height="24"</code>，内联后不再撑满容器。iLoveIMG 的 SVG 压缩会把文件上传到 <code>api11.iloveimg.com/v1/upload</code>（在其日文版页面实测）。<a href="https://jakearchibald.github.io/svgomg/" rel="noopener">SVGOMG</a> 在本地运行 SVGO 4.0.0，一次一个文件，没有 xmlns 的文件压缩后仍然没有，ID 被删、文件变大时都不提示。这几款都不做压缩前后的像素比对。
</p>

<h2>限制</h2>
<ul>
  <li>单个文件最大 50 MB；超过 10 MB 的文件照常压缩，但不做像素比对。</li>
  <li>动画只比对第一帧；外部图片、字体和 <code>&lt;use href="other.svg#id"&gt;</code> 在图片模式下不加载，比对不包含它们。</li>
  <li>文件外的 CSS、JavaScript 用到哪些 ID 和 class，SVGO 看不到；提示只列出被删掉的，不知道谁在用。</li>
  <li>内嵌的 PNG、JPEG 数据不会被重新压缩，需要参数的插件（removeAttrs 等 5 个）没有提供开关。</li>
</ul>
<p>
  压缩后要转成位图，用 <a href="/zh/tools/svg-to-png-converter/">SVG 转 PNG 工具</a>；要做成带 TypeScript 或 forwardRef 的 React 组件，用 <a href="/zh/tools/svg-to-jsx/">SVG 转 JSX 转换器</a>；要以 Data URI 嵌入，也可以用 <a href="/zh/tools/image-to-base64/">图片转 Base64 工具</a>。
</p>
