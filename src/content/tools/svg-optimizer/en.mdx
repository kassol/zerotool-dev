<h2>How to use</h2>
<ol>
  <li>Paste your SVG markup, or switch to the <strong>Upload File</strong> tab and drop a <code>.svg</code> file.</li>
  <li>Toggle the plugins you want. Defaults match SVGO's <em>preset-default</em>; the eight primary toggles cover the most common decisions.</li>
  <li>Click <strong>Optimize SVG</strong>. The before / after preview shows byte counts, the saved percentage, and rendered visuals so you can spot regressions immediately.</li>
  <li>Use <strong>Copy output</strong> for a quick paste into your codebase, or <strong>Download .svg</strong> to save the cleaned file.</li>
</ol>

<h2>What gets removed</h2>
<p>
  SVGO removes editor metadata, comments, hidden elements, default attributes, and other markup that does not affect rendering. It also rewrites path data, merges adjacent paths, and shortens color values. How much you save depends on how much of that the file carries; the exported icon in the example below goes from 511 to 254 bytes.
</p>

<h2>The two risky toggles</h2>
<p>
  <strong>Remove viewBox</strong> and <strong>Remove width/height</strong> are off by default for a reason: an SVG without <code>viewBox</code> loses its responsive scaling, and one without <code>width</code>/<code>height</code> attributes inherits the rendering box from its parent — which is rarely what you want for downloadable icons. Turn them on only when you fully control the embedding context (for example, sprite sheets where the parent <code>&lt;use&gt;</code> sets the size).
</p>

<h2>When to optimize</h2>
<ul>
  <li><strong>Production builds:</strong> ship icons through your bundler with a <code>vite-plugin-svgo</code> or similar step. Use this tool to spot-check the output without spinning up a CLI.</li>
  <li><strong>Hand-authored or exported SVGs:</strong> Figma, Illustrator, and Sketch all leave editor metadata and unused <code>id</code> attributes that SVGO strips cleanly.</li>
  <li><strong>Inline SVGs in HTML:</strong> if you embed the markup directly, every kilobyte counts — the document blocks first paint until parsed.</li>
</ul>

<h2>Single-file by design</h2>
<p>
  This tool optimizes one SVG at a time. Batch optimization, custom plugin authoring, and CI pipelines belong to the SVGO command-line tool — install it with <code>npm install -g svgo</code> and run <code>svgo input.svg -o output.svg</code> against folders or globs. Once you find the right toggle combination here, copy the equivalent <code>svgo.config.js</code> snippet from the SVGO docs and ship the same configuration into your build.
</p>

<h2>Example: An Icon Exported from a Design Tool</h2>
<p>With the default toggles (SVGO 4.0.1, multipass on, precision 3), this 511-byte file:</p>

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- Generator: Figma -->
<svg width="24" height="24" viewBox="0 0 24 24" fill="none" xmlns="http://www.w3.org/2000/svg">
  <title>Check</title>
  <defs>
    <style>.stroke { stroke: #000000; stroke-width: 2.000000; }</style>
  </defs>
  <g id="icon-check">
    <rect x="0" y="0" width="24" height="24" fill="none"/>
    <path class="stroke" d="M 5.000000 12.000000 L 10.000000 17.000000 L 19.000000 7.000000" stroke-linecap="round" stroke-linejoin="round"/>
  </g>
</svg>
```

<p>becomes 254 bytes:</p>

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" fill="none" viewBox="0 0 24 24"><title>Check</title><path d="M0 0h24v24H0z"/><path stroke-linecap="round" stroke-linejoin="round" d="m5 12 5 5 9-10" style="stroke:#000;stroke-width:2"/></svg>
```

<p>The XML declaration, the comment and the unused <code>id="icon-check"</code> are gone. The one-off <code>.stroke</code> class was inlined into a <code>style</code> attribute and the <code>&lt;style&gt;</code> block removed. The path was rewritten with relative commands, and <code>#000000</code> became <code>#000</code>. <code>&lt;title&gt;</code> stays: SVGO 4 no longer removes it by default. Ticking only <strong>Remove viewBox</strong> leaves <code>width="24" height="24"</code> and no viewBox, so the icon no longer scales. Ticking both risky toggles ends with a viewBox and no width or height: <code>removeViewBox</code> drops the viewBox, then <code>removeDimensions</code> removes the size and writes a viewBox back from it.</p>

<h2>Limits</h2>
<ul>
  <li><strong>IDs are shortened.</strong> <code>cleanupIds</code> renames referenced IDs to <code>a</code>, <code>b</code> and so on: a gradient with <code>id="brand-gradient"</code> becomes <code>id="a"</code>. If several optimized SVGs are inlined in one HTML page, their IDs can collide and one icon picks up another's gradient. Untick the IDs toggle, or give each file a prefix with SVGO's <code>prefixIds</code> in your build.</li>
  <li>IDs and classes that only your page CSS or JavaScript refers to are invisible to SVGO. Unused IDs are removed and single-use classes are inlined, so styles that target them from outside stop working.</li>
  <li>Coordinates are rounded to 3 decimal places by default. For detailed artwork at small viewBox scales, raise the precision if the after preview shows shifted points.</li>
  <li>One file at a time. For folders or CI, use the SVGO command line (<code>npx svgo -f icons/ -o dist/</code>) with the same settings.</li>
</ul>
