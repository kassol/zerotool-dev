<h2>The rendering check</h2>
<p>
  After SVGO finishes, the tool draws the original and the result with your browser at 400 pixels on the long side and compares every pixel. A pixel counts as changed when a color channel or the opacity differs by more than 24 of 255. Up to 0.1 % changed pixels is anti-aliasing noise and is reported as <strong>Renders the same</strong>; more than that shows the changed pixels in red so you can see where the drawing moved.
</p>
<p>
  The tool also adds a missing <code>xmlns="http://www.w3.org/2000/svg"</code> before optimizing. SVG copied out of an HTML page often lacks it, and without it a <code>.svg</code> file does not open as an image.
</p>

<h2>Example: an icon exported from a design tool</h2>
{/* svgo-check: {"fixture":"figma","bytes":[512,254],"gzip":[314,196],"notes":["idsGone","classesGone"],"render":"same","output":"<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"24\" height=\"24\" fill=\"none\" viewBox=\"0 0 24 24\"><title>Check</title><path d=\"M0 0h24v24H0z\"/><path stroke-linecap=\"round\" stroke-linejoin=\"round\" d=\"m5 12 5 5 9-10\" style=\"stroke:#000;stroke-width:2\"/></svg>"} */}
<p>The <strong>Example</strong> button loads this 512-byte icon, written the way Figma exports one:</p>

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- Generator: Figma -->
<svg width="24" height="24" viewBox="0 0 24 24" fill="none" xmlns="http://www.w3.org/2000/svg">
  <title>Check</title>
  <defs>
    <style>.stroke { stroke: #000000; stroke-width: 2.000000; }</style>
  </defs>
  <g id="icon-check">
    <rect x="0" y="0" width="24" height="24" fill="none"/>
    <path class="stroke" d="M 5.000000 12.000000 L 10.000000 17.000000 L 19.000000 7.000000" stroke-linecap="round" stroke-linejoin="round"/>
  </g>
</svg>
```

<p>With the default settings it becomes 254 bytes (gzip: 314 → 196 bytes) and renders the same:</p>

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" fill="none" viewBox="0 0 24 24"><title>Check</title><path d="M0 0h24v24H0z"/><path stroke-linecap="round" stroke-linejoin="round" d="m5 12 5 5 9-10" style="stroke:#000;stroke-width:2"/></svg>
```

<p>
  Two notes appear. <code>#icon-check</code> is gone, because the group was collapsed and its ID was not used inside the file. <code>.stroke</code> is gone, because a class used once was written into a <code>style</code> attribute (<a href="https://svgo.dev/docs/plugins/inlineStyles/" rel="noopener">inlineStyles</a>). If your page CSS colors the icon through <code>.stroke</code>, or your JavaScript looks it up with <code>#icon-check</code>, the optimized file breaks that code although it looks identical. <code>&lt;title&gt;</code> stays: SVGO 4 took <code>removeTitle</code> and <code>removeViewBox</code> out of the default preset (<a href="https://svgo.dev/docs/migrations/migration-from-v3-to-v4/" rel="noopener">migration guide</a>).
</p>

<h2>Example: a file that gets bigger</h2>
{/* svgo-check: {"fixture":"korea","bytes":[589,816],"notes":["larger"],"render":"same"} */}
<p>
  The <a href="https://commons.wikimedia.org/wiki/File:Flag_of_South_Korea.svg" rel="noopener">Flag of South Korea</a> on Wikimedia Commons is 589 bytes and already hand-optimized. SVGO returns 816 bytes: <a href="https://svgo.dev/docs/plugins/convertTransform/" rel="noopener">convertTransform</a> writes the <code>rotate(33.69006752598)</code> of the trigrams into the path coordinates, and rotated coordinates need more digits. The tool flags the result as larger and tells you to keep the original. A batch run shows the same in the table, so you can leave such files out of the ZIP.
</p>

<h2>Settings that can break an SVG</h2>
<table>
  <thead><tr><th>Setting</th><th>What changes</th><th>Note shown</th></tr></thead>
  <tbody>
    <tr><td>Shorten and remove IDs (on)</td><td>Referenced IDs become <code>a</code>, <code>b</code>…; unreferenced ones are deleted</td><td>Lists the IDs that are gone</td></tr>
    <tr><td>inlineStyles, minifyStyles (on)</td><td>One-off classes move into <code>style</code> attributes</td><td>Lists the classes that are gone</td></tr>
    <tr><td>Remove viewBox (off)</td><td>Removes a viewBox that equals width and height; the SVG no longer scales (<a href="https://svgo.dev/docs/plugins/removeViewBox/" rel="noopener">SVGO docs</a>)</td><td>Fixed size, with the pixels</td></tr>
    <tr><td>Remove width/height (off)</td><td>Size comes from CSS or the container; SVGO adds a viewBox if there was none</td><td>Size removed</td></tr>

<h2>Scripts and SVG from unknown sources</h2>
<p>
  With default settings SVGO keeps <code>&lt;script&gt;</code> and event attributes such as <code>onclick</code>; the tool counts them and says so. <strong>Remove scripts and event handlers</strong> runs <a href="https://svgo.dev/docs/plugins/removeScripts/" rel="noopener">removeScripts</a>, which in SVGO 4.1.0 also catches <code>java&amp;#9;script:</code> links and HTML inside <code>&lt;foreignObject&gt;</code>. Browsers disable scripts and external files for SVG used as an image (<a href="https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image" rel="noopener">MDN</a>), but not when the file is opened directly, inlined, or embedded with <code>&lt;object&gt;</code>, <code>&lt;embed&gt;</code> or <code>&lt;iframe&gt;</code>. The previews here are images, so nothing in a pasted SVG runs on this page.
</p>

<h2>Many files and your build</h2>
<p>
  Drop a folder's worth of icons at once: each file gets a row with its size before and after, the saving and the rendering result, and <strong>Download all (.zip)</strong> packs the results under their original names. The config panel shows the matching file, for example:
</p>

```js
// npx svgo@4.1.0 --config svgo.config.mjs -f icons -o icons-min
export default {
  multipass: true,
  floatPrecision: 3,
  plugins: [
    'preset-default',
  ],
};
```

<p>The tool's tests run generated configs through the SVGO command line and check that the output equals the tool's.</p>

<h2>How it compares</h2>
<p>
  Tested on 2 October 2026 with the same files. <a href="https://jakearchibald.github.io/svgomg/" rel="noopener">SVGOMG</a> runs SVGO 4.0.0 locally, one file at a time; it returned an SVG without <code>xmlns</code> unchanged in that respect, deleted the <code>icon-check</code> ID and grew the Korean flag (shown as 128.66 % of the gzipped size) without a warning, and offers a "Show original" toggle instead of a pixel check. <a href="https://vecta.io/nano" rel="noopener">Vecta Nano</a> takes up to 10 files of 5 MB; its requests carried no file content, only counters with the saved percentage, but the page has no plugin settings and no code view. </p>

<h2>Limits</h2>
<ul>
  <li>50 MB per file. Files over 10 MB are optimized but not compared pixel by pixel.</li>
  <li>Invalid XML is reported with the line and column in the text you entered, counted in characters, and a reason in the page language. <code>&lt;svg&gt;&lt;rect&gt;&lt;/svg&gt;</code> without xmlns is reported at line 1, column 17: the closing tag &lt;/svg&gt; does not close the element opened last. The xmlns the tool adds is not counted.</li>
  <li>The comparison shows the first frame of animated SVG and cannot see external images, fonts or <code>&lt;use href="other.svg#id"&gt;</code>, because browsers do not load them into an SVG image.</li>
  <li>IDs and classes used by CSS or JavaScript outside the file are invisible to SVGO; the notes list what disappeared, not who used it.</li>
  <li>SVGO does not recompress embedded PNG or JPEG data. Plugins that need parameters (removeAttrs, removeElementsByAttr, removeAttributesBySelector, addAttributesToSVGElement, addClassesToSVGElement) are not offered.</li>
  <li>Copy as “React component (JSX)” converts comments, <code>&lt;style&gt;</code> blocks and <code>style</code> attributes the same way as <a href="/tools/svg-to-jsx/">SVG to JSX</a>. A <code>style</code> that a React style object cannot keep, such as <code>fill:red!important</code> (SVGO keeps <code>!important</code>), is refused: the reason appears under the buttons, Copy is disabled for that file, and Download, the row downloads and the ZIP still save the optimized SVG. The other copy formats are not affected.</li>
</ul>
