<h2>WCAG 对比度公式</h2>
<p>WCAG 2.x 对比度基于两种颜色的<em>相对亮度</em>计算。每个 sRGB 通道经分段 gamma 解码后，按 <code>0.2126·R + 0.7152·G + 0.0722·B</code> 加权得到亮度，对比度公式为 <code>(L1 + 0.05) / (L2 + 0.05)</code>，其中 L1 为较亮一方。结果取值范围 1（无对比）到 21（纯黑配纯白）。</p>

<h2>三档场景：正文 / 大号 / UI</h2>
<p>WCAG 2 按使用场景分档：</p>
<ul>
  <li><strong>正文（成功标准 1.4.3）</strong>——AA ≥ <code>4.5 : 1</code>，AAA ≥ <code>7 : 1</code>。涵盖小于 24&nbsp;px 常规字号或小于 18.66&nbsp;px 粗体的文字。</li>
  <li><strong>大号文字</strong>——AA ≥ <code>3 : 1</code>，AAA ≥ <code>4.5 : 1</code>。涵盖 18.66&nbsp;px 粗体及以上或 24&nbsp;px 常规及以上的文字。WCAG 原文写的是 18 点或 14 点粗体，并注明中日韩文字取「等效的字号」。</li>
  <li><strong>UI 组件与图形（成功标准 1.4.11）</strong>——≥ <code>3 : 1</code>。涵盖边框、聚焦环、图标、图表线条等非文字视觉元素。WCAG 2 在此处未规定 AAA 阈值。</li>
</ul>

## 用 Ant Design 的主色检查主按钮

{/* contrast-check: {"fg":"#ffffff","bg":"#1677ff"} */}

Ant Design 的主色 `colorPrimary` 默认是 `#1677ff`，主按钮的文字色取 `colorTextLightSolid`，默认就是白色 `#fff`（见 antd 6.6.5 源码 `theme/themes/seed.js` 与 `button/style/token.js`）。在工具里把前景填 `#ffffff`、背景填 `#1677ff`，对比度是 `4.10 : 1`：正文 AA 不通过，大号文字 AA 和 UI 组件 AA 通过。这时给出的修正是 `#131313`（`4.52 : 1`）。原因是工具只改前景，白色没有色相，只能往黑色方向找。

{/* contrast-check: {"fg":"#1677ff","bg":"#ffffff"} */}

如果想保留白字、把按钮的蓝调深一点，先点交换按钮，让 `#1677ff` 成为前景。对比度不变，仍是 `4.10 : 1`；修正建议变成 `#086FF7`（`4.53 : 1`），色相还是同一种蓝。对比度对前后景是对称的，所以这个值放回按钮背景、上面写白字，同样是 `4.53 : 1`。

{/* contrast-check: {"fg":"#ff4d4f","bg":"#ffffff"} */}

错误色 `colorError` 的默认值 `#ff4d4f` 写在白底上是 `3.26 : 1`，大号文字 AA 通过。如果拿它写表单报错这类小于 24 px 的文字，要看正文那一列，不通过；建议值 `#E22D37`（`4.50 : 1`）仍是红色。

## 适老化规范里的对比度

工业和信息化部办公厅 2021 年 4 月 6 日印发的通知附有《移动互联网应用（APP）适老化通用设计规范》，其中 1.3 对比度一条写道：「文本/文本图像呈现方式、图标等元素间的对比度至少为4.5：1（字号大于18 dp/pt时文本及文本图像对比度至少为3：1）。」

这条和 WCAG 有两处不同。第一，大字的门槛是大于 18 dp/pt，WCAG 是 24 px 常规或 18.66 px 粗体。用本工具判断 APP 时，18 dp/pt 以上的文字看「大号文字 AA」那一格（3:1），其余文字看「正文 AA」（4.5:1）。第二，图标和文本写在同一句里，门槛也是 4.5:1；工具的「UI 组件」卡只按 WCAG 1.4.11 的 3:1 判断，所以图标请看「正文 AA」。

{/* contrast-check: {"fg":"＃７６７６７６","bg":"#ffffff"} */}

中文输入法在全角状态下，打出来的是 `＃７６７６７６` 这样的全角字符。工具先按 NFKC 换成半角再读取，得到的结果与 `#767676` 相同：白底上 `4.54 : 1`，正文 AA 通过。

## 为什么是「保留色相、调整亮度」
<p>品牌色与设计 token 通常按色相身份选定，而非按亮度。当对比不达标时，直接换成纯黑或纯白会破坏视觉语言。本工具沿前景的 OKLCH 亮度轴（感知均匀）行进，保留原始色相与饱和度，在第一个达到 <code>4.5 : 1</code> 的亮度处停下。每个候选色先取整为 8 位 HEX 再判定对比度，复制出去的 HEX 本身就达标。结果是离原色最近、且能通过正文 AA 的颜色。若该色相在 sRGB 色域内无法达成目标，工具回退到通过的纯黑或纯白。</p>

## 限制

- 只读不透明的 HEX。`rgb()`、`hsl()`、颜色名和透明度都不读；`rgba(0,0,0,0.88)` 这类带透明度的文字色，要先和背景混合成不透明色再检查。其他格式可先用[颜色转换器](/zh/tools/color-converter/)转成 HEX。
- 一次只比较一对颜色。图片、渐变上的文字没有单一背景色，请分别检查文字后面最亮和最暗的地方。
- 修正建议只改前景，目标是正文 AA（4.5 : 1），不追求 AAA（7 : 1）。
- 工具不知道文字的字号和粗细，哪一列适用由你按实际字号判断。
