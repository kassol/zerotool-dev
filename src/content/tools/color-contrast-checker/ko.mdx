<h2>WCAG 대비비 공식</h2>
<p>WCAG 2.x의 대비비는 두 색상의 <em>상대 휘도</em>로 계산합니다. 각 sRGB 채널을 분할 함수로 gamma 디코딩하고, <code>0.2126·R + 0.7152·G + 0.0722·B</code>로 가중하여 휘도를 구한 뒤, 비율은 <code>(L1 + 0.05) / (L2 + 0.05)</code>(L1은 더 밝은 쪽)입니다. 값의 범위는 1(대비 없음)부터 21(순수 검정/순수 흰색)까지입니다.</p>

<h2>세 가지 단계: 본문 / 큰 글자 / UI</h2>
<p>WCAG 2는 사용 사례별로 목표를 나눕니다:</p>
<ul>
  <li><strong>본문 (성공 기준 1.4.3)</strong> — AA ≥ <code>4.5 : 1</code>, AAA ≥ <code>7 : 1</code>. 24&nbsp;px 미만 보통 글자 또는 18.66&nbsp;px 미만 굵은 글자에 적용됩니다.</li>
  <li><strong>큰 글자</strong> — AA ≥ <code>3 : 1</code>, AAA ≥ <code>4.5 : 1</code>. 18.66&nbsp;px 굵은 글자 이상 또는 24&nbsp;px 보통 이상에 적용됩니다. WCAG 정의는 18포인트 또는 14포인트 굵은 글자이며, 한중일 글꼴은 '동등한 크기'로 본다는 주석이 있습니다.</li>
  <li><strong>UI 구성요소 및 그래픽 (성공 기준 1.4.11)</strong> — ≥ <code>3 : 1</code>. 테두리, 포커스 링, 아이콘, 차트 선 등 비텍스트 시각 요소에 적용됩니다. WCAG 2는 이 영역에 AAA를 규정하지 않습니다.</li>
</ul>

## KWCAG 2.2의 명도 대비 기준

한국형 웹 콘텐츠 접근성 지침(KWCAG) 2.2의 검사항목 5.4.3은 "텍스트 콘텐츠와 배경 간의 명도 대비는 4.5 대 1 이상이어야 한다."입니다. 같은 항목에서 18pt 이상 또는 14pt 굵은 폰트를 쓰는 텍스트, 그리고 화면 확대가 가능하도록 구현한 텍스트는 명도 대비를 3 대 1까지 낮출 수 있다고 정하고 있습니다. 화면 확대 조건은 WCAG 1.4.3에는 없는 KWCAG만의 완화 규정입니다. 예외로는 로고, 장식 목적의 콘텐츠, 초점을 받았을 때 명도 대비가 커지는 콘텐츠를 들고 있습니다.

KWCAG 2.2의 33개 검사항목 중 명도 대비를 다루는 항목은 이 하나뿐이고, 대상은 텍스트입니다. 이 도구의 UI 구성요소 칸은 WCAG 2.1 / 2.2의 1.4.11을 따르는 참고 값으로 보면 됩니다.

## KRDS 색상 토큰으로 확인하기

대한민국 디지털 정부 디자인 시스템 KRDS의 npm 패키지 `krds-uiux` 1.1.0에 들어 있는 `krds_tokens.css`와 `component.css`의 값으로 확인해 봅니다.

{/* ccc-check: {"fg":"#ffffff","bg":"#256ef4"} */}

기본(primary) 버튼은 배경이 primary-50(`#256ef4`), 글자가 gray-0(흰색)입니다. 흰 글자를 `#256ef4` 위에 두면 `4.55 : 1`로 본문 AA를 통과합니다.

{/* ccc-check: {"fg":"#256ef4","bg":"#ecf2fe"} */}

같은 primary-50 글자를 연한 배경 primary-5(`#ecf2fe`) 위에 두면 `4.05 : 1`로 떨어져 본문 AA를 통과하지 못합니다. 수정 제안은 `#1D66EB`(`4.50 : 1`)로, 같은 파란색 계열에서 조금 어두워진 색입니다.

{/* ccc-check: {"fg":"#8a949e","bg":"#ffffff"} */}

gray-40(`#8a949e`)은 토큰 파일에서 `--krds-light-color-text-disabled`, 즉 비활성 텍스트 색으로 쓰입니다. 흰 배경에서 `3.08 : 1`이고 수정 제안은 `#6E7881`(`4.50 : 1`)입니다. WCAG 1.4.3은 비활성 UI 구성요소의 텍스트를 대비 요구에서 제외하지만, 위에 적은 KWCAG 5.4.3의 예외 목록에는 이 경우가 따로 적혀 있지 않습니다. 어느 기준으로 검사하는지에 따라 판단이 달라질 수 있는 부분입니다.

{/* ccc-check: {"fg":"#6d7882","bg":"#ffffff"} */}

한 단계 진한 gray-50(`#6d7882`)은 `4.50 : 1`입니다. 실제 값은 4.507이라 통과하지만 여유가 거의 없으므로, 흰색보다 조금이라도 어두운 배경에 올리면 다시 확인해야 합니다.

<h2>“색상은 유지, 명도만 조정”의 이유</h2>
<p>브랜드 컬러와 디자인 토큰은 휘도가 아닌 색상 정체성으로 선택됩니다. 대비가 부족할 때 검정이나 흰색으로 무작정 바꾸면 시각 언어가 깨질 수 있습니다. 본 도구는 전경의 OKLCH 명도 축(지각적으로 균일)을 따라 이동하면서 원래 색상과 채도를 유지하고, 현재 배경에 대해 <code>4.5 : 1</code>을 처음으로 만족하는 명도에서 멈춥니다. 후보 색은 8비트 HEX로 반올림한 뒤 판정하므로 복사한 HEX 자체가 기준을 충족합니다. 결과는 원본에 가장 가까우면서 본문 AA를 통과하는 색입니다. 해당 색상이 sRGB 색역 안에서 목표에 도달하지 못하면, 통과하는 검정 또는 흰색으로 폴백합니다.</p>

## 제한 사항

- 불투명한 HEX만 읽습니다. `rgb()`, `hsl()`, 색 이름, 투명도는 읽지 않습니다. `krds_tokens.css`의 `#000000bf` 같은 알파 토큰은 배경과 합성한 불투명 색으로 바꾼 뒤 확인하세요.
- 한 번에 한 쌍만 비교합니다. 사진이나 그라데이션 위의 글자는 글자 뒤에서 가장 밝은 곳과 가장 어두운 곳을 각각 확인합니다.
- 수정 제안은 전경만 바꾸고 본문 AA(4.5 : 1)를 목표로 합니다. AAA(7 : 1)는 목표로 하지 않습니다.
- 글자 크기와 굵기는 도구가 알 수 없습니다. 어느 칸을 볼지는 실제 글자에 맞춰 고릅니다.

<p>HEX 파싱, OKLCH 변환, 대비비 계산, 수정 제안 탐색은 모두 브라우저 안에서 처리됩니다. 색상은 전송하거나 저장하지 않으며, 페이지 통계에는 도구 이름과 <code>check</code> 같은 동작 이름만 기록됩니다.</p>
