<h2>WCAG コントラスト比の仕組み</h2>
<p>WCAG 2.x のコントラスト比は 2 色の<em>相対輝度</em>から計算します。各 sRGB チャンネルを区分関数で gamma 復号し、<code>0.2126·R + 0.7152·G + 0.0722·B</code> で重み付けして輝度を求め、比は <code>(L1 + 0.05) / (L2 + 0.05)</code>（L1 は明るい方）。値は 1（コントラストなし）〜21（純黒×純白）の範囲。</p>

<h2>本文・大きな文字・UI の 3 階層</h2>
<p>WCAG 2 はユースケースごとに目標値を分けています：</p>
<ul>
  <li><strong>本文（達成基準 1.4.3）</strong>—— AA ≥ <code>4.5 : 1</code>、AAA ≥ <code>7 : 1</code>。24&nbsp;px 未満の通常文字、または 18.66&nbsp;px 未満の太字が対象。</li>
  <li><strong>大きな文字</strong>—— AA ≥ <code>3 : 1</code>、AAA ≥ <code>4.5 : 1</code>。18.66&nbsp;px 太字以上または 24&nbsp;px 通常以上のテキストが対象。WCAG の定義は 18 ポイント・14 ポイント太字で、日本語などの CJK フォントは「同等のサイズ」と注記されています。</li>
  <li><strong>UI コンポーネントと図形（達成基準 1.4.11）</strong>—— ≥ <code>3 : 1</code>。枠線・フォーカスリング・アイコン・グラフ線などの非テキスト視覚要素を対象。WCAG 2 はここでは AAA を規定していません。</li>
</ul>

## デジタル庁デザインシステムのグレーで確かめる

デジタル庁デザインシステムのカラーパレットのページには、「Gray-536が、白（#FFFFFF）に対してコントラスト比4.5:1を確保できるカラー」、「Gray-420が、白（#FFFFFF）に対してコントラスト比3:1を確保できるカラー」と書かれています。npm パッケージ `@digital-go-jp/design-tokens` 2.0.1 の値は Gray-536 が `#767676`、Gray-420 が `#949494` です。

{/* contrast-check: {"fg":"#767676","bg":"#ffffff"} */}

`#767676` を白地に置くと `4.54 : 1` で、本文 AA に合格します。

{/* contrast-check: {"fg":"#949494","bg":"#ffffff"} */}

`#949494` は `3.03 : 1` です。大きな文字の AA と UI コンポーネントの AA には合格し、本文 AA は不合格になります。修正案は Gray-536 と同じ `#767676`（`4.54 : 1`）です。1 段だけ明るい `#959595` は `2.99 : 1` となり、3:1 にも届きません。境界の色は 1 段の差で合否が変わるので、値は丸めずに確かめる必要があります。

{/* contrast-check: {"fg":"#767676","bg":"#f2f2f2"} */}

注意したいのは背景が白でない場合です。Gray-536 を Gray-50（`#f2f2f2`）の上に置くと `4.05 : 1` まで下がり、本文 AA に届きません。修正案は `#6E6E6E`（`4.55 : 1`）です。デザインシステムのカラー概要のページにも、コントラスト比はグレーの階調の組み合わせによって変化するので注意するよう書かれています。

なお、同デザインシステムのアクセシビリティのページでは、「サイズの大きなテキスト」の規定を除外し、文字の大きさに関わらず 4.5:1 以上を確保する方針が示されています。この方針に合わせるなら、文字には常に本文 AA の欄を使います。

## JIS X 8341-3:2016 との関係

JIS X 8341-3:2016 は WCAG 2.0 と同じ内容の一致規格です。コントラストの達成基準 1.4.3（最低限）と 1.4.6（高度）は本ツールの本文・大きな文字の欄と同じしきい値ですが、UI コンポーネントの欄に当たる 1.4.11 は WCAG 2.1 で加わったもので、JIS 2016 には入っていません。

{/* contrast-check: {"fg":"＃９４９４９４","bg":"#ffffff"} */}

IME が全角のまま `＃９４９４９４` と入力しても、NFKC で半角に直してから読み取るので、`#949494` と同じ `3.03 : 1` になります。修正案も `#767676`（`4.54 : 1`）です。

## 「色相を保ったまま明度を調整」する理由
<p>ブランドカラーやデザイントークンは輝度ではなく色相のアイデンティティで選ばれることが多いため、コントラスト不足のときに黒や白へ切り替えると視覚言語が崩れます。本ツールは前景の OKLCH 明度軸（知覚的に均一）を歩み、原色相と彩度を保持したまま、現在の背景に対して <code>4.5 : 1</code> を最初に満たす明度で停止します。候補色は 8 ビットの HEX に丸めてから判定するため、コピーした HEX そのものが基準を満たします。結果として元の色に最も近く本文 AA を通過する色が得られます。色相が sRGB 色域内で目標に届かない場合は、合格する黒または白にフォールバックします。</p>

## 制限事項

- 読み取るのは不透明な HEX だけです。`rgb()`・`hsl()`・色名・透明度は読みません。デジタル庁デザインシステムの Opacity Gray のように黒の透過度で決まる色は、背景と合成した不透明な色に直してから確かめてください。
- 一度に比べるのは 1 組です。写真やグラデーションの上の文字は、文字の背後で最も明るい部分と最も暗い部分をそれぞれ確かめます。
- 修正案が変えるのは前景だけで、目標は本文 AA（4.5 : 1）です。AAA（7 : 1）は狙いません。
- 文字サイズや太さはツールに伝わりません。どの欄を見るかは実際の文字に合わせて選びます。
