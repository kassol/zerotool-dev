<h2>What Are Design Tokens?</h2>
<p>
  Design tokens are the single source of truth for your design decisions — color palettes,
  type scales, spacing rhythms, and corner radii. By storing them as CSS custom properties
  in a <code>:root</code> block, you make every value accessible throughout your entire
  stylesheet. Changing a token in one place cascades to every component that uses it.
</p>

<h2>Example: the Default Tokens</h2>
<p>With the default prefix and the pre-filled rows, the tool writes one <code>:root</code> block, group by group:</p>

{/* cvg-default */}

```css
:root {
  --primary: #3b82f6;
  --secondary: #6366f1;
  --bg: #ffffff;
  --text: #111827;
  --font-sans: Inter, system-ui, sans-serif;
  --font-mono: "Fira Code", monospace;
  --font-size-base: 16px;
  --font-size-lg: 18px;
  --space-1: 4px;
  --space-2: 8px;
  --space-4: 16px;
  --space-8: 32px;
  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 16px;
  --radius-full: 9999px;
}
```

<p>Use them with <code>var()</code>, for example <code>.card {'{'} padding: var(--space-4); border-radius: var(--radius-md); {'}'}</code>. A selector such as <code>:root</code> matches the <code>html</code> element and has the specificity of one class, so a later <code>.theme-dark</code> rule on the same element can override the tokens.</p>

<h2>Example: a Namespaced Set</h2>
<p>Set the prefix to <code>--ds</code>, keep three rows and let one token refer to another:</p>

{/* cvg-check: {"prefix":"--ds","tokens":[["primary","#3b82f6"],["radius-md","8px"],["space-4","calc(var(--ds-space-2) * 2)"]]} */}

```css
:root {
  --ds-primary: #3b82f6;
  --ds-radius-md: 8px;
  --ds-space-4: calc(var(--ds-space-2) * 2);
}
```

<p>The tool copies values as typed, so <code>var()</code> and <code>calc()</code> work in the value field. Here <code>--ds-space-2</code> is not defined in the block, so <code>--ds-space-4</code> has no usable value until you add that row. For a dark theme, copy the color rows into a second block by hand, such as <code>@media (prefers-color-scheme: dark) {'{'} :root {'{'} --bg: #111827; --text: #f9fafb; {'}'} {'}'}</code>.</p>

<p>If you type the prefix as <code>brand</code> and a name as <code>primary color</code>, the tool repairs both, because a custom property name must start with <code>--</code> and cannot contain a space:</p>

{/* cvg-check: {"prefix":"brand","tokens":[["primary color","#3b82f6"],["text","#111827"]]} */}

```css
:root {
  --brand-primary-color: #3b82f6;
  --brand-text: #111827;
}
```

<h2>Limits and Gotchas</h2>
<ul>
  <li><strong>Little validation.</strong> A prefix typed without <code>--</code> gets it (<code>brand</code> becomes <code>--brand-</code>), and spaces inside a name become hyphens (<code>primary color</code> becomes <code>--primary-color</code>), because a custom property name must start with <code>--</code> and cannot contain spaces. Values are copied as typed, and two rows with the same name both appear; the later one wins.</li>
  <li><strong>Names are case-sensitive.</strong> <code>var(--Primary)</code> does not read <code>--primary</code>. In Chrome, <code>color: var(--Primary, rgb(1, 2, 3))</code> fell back to the fallback color.</li>
  <li><strong>Fallbacks only cover missing tokens.</strong> With <code>--gap: red</code>, the declaration <code>padding: var(--gap, 8px)</code> computed to 0px, not 8px: the fallback is used only when the variable is undefined, and an unusable value makes the declaration invalid at computed-value time (<a href="https://www.w3.org/TR/css-variables-1/#invalid-at-computed-value-time">CSS Custom Properties Level 1 §3.1</a>). With an undefined variable the same line gave 8px.</li>
  <li><strong>One <code>:root</code> block.</strong> There is no output for themes, media queries, <code>@property</code> registrations, JSON or Sass maps, and the four groups are fixed (rows can be added to each).</li>
  <li>The color swatch follows hex values in the text field (3 or 6 digits). Values such as <code>rgb()</code> or <code>oklch()</code> are copied correctly but the swatch does not update.</li>
</ul>
<p>Custom properties and <code>var()</code> work in Chrome 49, Firefox 31, Safari 9.1 and Edge 15 and later (MDN browser compat data). To produce a full shade scale for one color token, use the <a href="/tools/color-shades-generator/">color shades generator</a>; for fluid sizes, paste a value from the <a href="/tools/css-clamp-calculator/">CSS clamp calculator</a>.</p>
