<h2>示例：整理微信推送的 XML</h2>

用户给服务号发消息时，微信服务器会把一段 XML 用 POST 发到开发者填写的 URL（[接收普通消息](https://developers.weixin.qq.com/doc/offiaccount/Message_Management/Receiving_standard_messages.html)）。服务端日志通常把它记成一行。下面沿用文档里文本消息的字段名和占位值，只把 `Content` 换成一句中文，并去掉了文档示例末尾的 `MsgDataId`、`Idx`：

{/* xf-check: {"op":"format","indent":"2"} */}
```xml
<xml><ToUserName><![CDATA[toUser]]></ToUserName><FromUserName><![CDATA[fromUser]]></FromUserName><CreateTime>1348831860</CreateTime><MsgType><![CDATA[text]]></MsgType><Content><![CDATA[你好，想查一下订单]]></Content><MsgId>1234567890123456</MsgId></xml>
```

用 2 个空格格式化后：

```xml
<xml>
  <ToUserName>
    <![CDATA[toUser]]>
  </ToUserName>
  <FromUserName>
    <![CDATA[fromUser]]>
  </FromUserName>
  <CreateTime>1348831860</CreateTime>
  <MsgType>
    <![CDATA[text]]>
  </MsgType>
  <Content>
    <![CDATA[你好，想查一下订单]]>
  </Content>
  <MsgId>1234567890123456</MsgId>
</xml>
```

结果里有两种写法：`CreateTime`、`MsgId` 这类只含普通文本的元素保持一行；`ToUserName`、`MsgType`、`Content` 里只有一个 CDATA 段，CDATA 会单独占一行，所以每个字段变成三行。

CDATA 里的中文和全角逗号原样保留，不会被转义成实体。要把它贴回日志或测试用例，对这段格式化结果点“压缩”，得到的正是上面那一行：压缩会去掉缩进产生的空白文本，CDATA 的内容不动。

<h2>示例：中文元素名和属性名</h2>

XML 的名字可以直接用汉字。XML 1.0 规定名字首字符的范围里有 `[#x3001-#xD7FF]`，常用汉字都在其中（[XML 1.0 §2.3](https://www.w3.org/TR/xml/#NT-NameStartChar)）。工具按浏览器解析出的名字写回，不会改写或转义：

{/* xf-check: {"op":"minify"} */}
```xml
<订单 编号="1001">
  <商品 数量="2">茶叶</商品>
  <商品 数量="1">紫砂壶</商品>
</订单>
```

点“压缩”后：

```xml
<订单 编号="1001"><商品 数量="2">茶叶</商品><商品 数量="1">紫砂壶</商品></订单>
```

压缩去掉的是标签之间用于缩进的换行和空格，它们在解析结果里是只含空白的文本节点。元素名、属性名、属性值和“茶叶”这类文字都不变。

## 常见错误

本工具用浏览器的 XML 解析器解析输入，遇到第一个[格式良好性](https://www.w3.org/TR/xml/#sec-well-formed)错误就停止，并显示浏览器给出的信息。常见原因如下：

| 错误 | 示例 | 改法 |
|---|---|---|
| 标签未闭合 | `<person><name>Alice</person>` | 用 `</name>` 闭合 `<name>` |
| 标签不匹配 | `<b>bold</i>` | 开始和结束标签用同一个名字，注意区分大小写 |
| 文本里直接写了 `&` 或 `<` | `<company>AT&T</company>` | 写成 `&amp;` 和 `&lt;` |
| 有两个根元素 | `<record/><record/>` | 用一个父元素包起来，例如 `<records>` |
| 属性值没加引号 | `<item id=42/>` | 加引号：`id="42"` |

中文输入法开着中文标点时，属性值的引号容易打成全角的 “ ”。下面的报错是 2026-10-08 在 Chrome 152 里实测的：{/* xf-error: {"in":"<item id=“1001”>茶叶</item>"} */}输入 `<item id=“1001”>茶叶</item>`，状态栏显示“错误：”和 `error on line 1 at column 10: AttValue: " or ' expected`。第 10 列正是 `“` 所在的位置，把两个全角引号换成半角 `"` 即可。报错正文是浏览器的英文原文，换用 Firefox 时措辞会不同，所以排查时以行号和列号为准。

## 限制

- **DOCTYPE 里声明的实体会被展开。** XML 声明和 DOCTYPE（含内部子集）原样保留，但引用其中声明的实体（如 `&company;`）时，输出写的是替换后的文本。
- **文本会被去掉首尾空白。** 元素内文本的首尾空白会删除，`xml:space="preserve"` 不生效；文本和元素混排的文档（如 XHTML）格式化后文字会分到多行，替换原文前请核对。
- **空元素的写法会变。** 格式化时 `<note></note>` 和 `<note> </note>` 都写成 `<note/>`；压缩时没有内容的 `<note></note>` 写成 `<note/>`，只含空格的 `<note> </note>` 写成 `<note></note>`。
- **引号与转义按统一写法输出。** 属性值一律用双引号；文本和属性里的 `&` `<` `>` `"` `'` 都写成实体，{/* xf-check: {"op":"format","in":"<note>It's \"ok\"</note>"} */}例如 `<note>It's "ok"</note>` 输出为 `<note>It&apos;s &quot;ok&quot;</note>`，含义不变。
- **只检查格式良好性。** 不按 DTD 或 XML Schema 校验，一次只报告第一处错误。
