## Two outputs you can reproduce

The default glass color is white at 15% opacity, with 12px blur and 180% saturation. The generated enhancement contains:

{/* gsg-check: {"settings":{},"contains":"background: rgba(255, 255, 255, 0.15);"} */}
```css
background: rgba(255, 255, 255, 0.15);
-webkit-backdrop-filter: blur(12px) saturate(180%);
backdrop-filter: blur(12px) saturate(180%);
```

This is only the enhancement excerpt. Copying from the tool includes the opaque baseline and state rules. Default text `#111111` on the solid white fallback has **18.88:1** contrast, displayed by truncating to two decimal places.

For a dark photo caption, enter `#123` as the glass color, set opacity to 60%, blur to 8px, and saturation to 100%. Choose white text and `#112233` as the fallback. The generated fill is:

{/* gsg-check: {"settings":{"bg":"#112233","alpha":60,"blur":8,"saturation":100},"contains":"background: rgba(17, 34, 51, 0.60);"} */}
```css
background: rgba(17, 34, 51, 0.60);
backdrop-filter: blur(8px) saturate(100%);
```

White text on the opaque `#112233` fallback is **16.14:1**. That number describes the fallback only. A bright patch in a photo can lower contrast through the transparent version; use your actual image rather than treating the fallback result as a glass result.

## An opaque baseline with progressive enhancement

The output begins with the fallback color. An `@supports` block applies transparency and filtering when either property spelling is supported. A vendor prefix supplies another spelling of the same feature; it does not supply a readable fallback by itself.

Both CSS and Tailwind output restore the solid color for `prefers-reduced-transparency: reduce`. A page control can add `glass-opaque` to an element already using `glass`. In forced-colors mode, the code uses `Canvas` and `CanvasText`, removes the shadow and disables filtering. These system colors leave color selection to the user's environment.

For Tailwind v4, paste the **@utility glass** block into the stylesheet that imports Tailwind, then use `class="glass"`. [Tailwind's custom utility documentation](https://tailwindcss.com/docs/adding-custom-styles#adding-custom-utilities) explains how these utilities participate in compilation. This output was compiled with Tailwind 4.3.3; it is not a Tailwind v3 configuration. Card markup and an application toggle are your responsibility.

## Why the background can stop blurring

[Filter Effects Level 2](https://drafts.fxtf.org/filter-effects-2/#BackdropRoot) describes backdrop roots. In a Chromium test on October 2, 2026, an ancestor with `filter: brightness(1)`, `opacity: .99`, or `will-change: opacity` stopped the card from blurring stripes outside that ancestor. A `transform: translateZ(0)` control retained the blur. Even a visually neutral filter can therefore change what the card samples.

The draft notes that the backdrop-root definition has not reached working-group consensus. Inspect your real ancestor chain when the effect differs from this isolated preview. To blur an image element itself, use the [CSS Filter Generator](/tools/css-filter-generator/); it operates on a different target.

## Contrast and browser boundaries

The tool estimates filtering with Canvas, composites the chosen glass fill over those pixels, and reports the minimum contrast in the padded inner rectangle. It uses the specified text color rather than antialiased glyph pixels. It does not check focus indicators, links, borders, or the complete WCAG checklist. [WCAG 2.2 contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) requires 4.5:1 for normal text and 3:1 for large text; 4.499:1 fails the first threshold. Use the [Color Contrast Checker](/tools/color-contrast-checker/) for individual solid color pairs.

[MDN compatibility data](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter#browser_compatibility) lists unprefixed support from Chrome 76, Edge 79, Firefox 103 and Safari 18. Safari 9–17 uses the prefix. The [reduced-transparency query](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-transparency#browser_compatibility) has narrower support: Chromium supports it from 118, Firefox support is preference-gated, and Safari is not listed as supporting it. Keep the manual override; a media query alone cannot serve every browser.

## Differences and limits

On October 2, 2026, changing opacity in [css.glass](https://css.glass/) and blur in [Hype4's generator](https://hype4.academy/tools/glassmorphism-generator) updated their CSS immediately. No fetch/XHR upload was observed during those edits. Their inspected output focused on the translucent declarations. This tool additionally exports state handling and checks a local preview background.

Images are limited to 20 MB and 50 million pixels. The preview is static and cropped; it does not model moving video, multiple glass layers or ancestors on your site. Canvas estimates can differ from CSS rendering, especially near blur edges. Unsupported Canvas filtering produces a notice instead of a fabricated score. HEX is the only color-input format. Shadow offset and blur remain fixed at `0 4px 24px`; use the [Box Shadow Generator](/tools/box-shadow-generator/) for a separate shadow design.
