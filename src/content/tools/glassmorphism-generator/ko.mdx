## 이미지 위의 유리 효과 만들기

1. 유리 색상을 HEX로 입력합니다. `abc`, `#abc`, `#aabbcc`를 사용할 수 있습니다.
2. 불투명도, 블러, 채도를 조절합니다. 수치를 바꾸면 코드와 미리보기가 갱신됩니다.
3. 배경을 선택하거나 기기의 이미지를 엽니다. 이미지는 가운데를 기준으로 잘라 채웁니다.
4. 「테두리·그림자·가독성」에서 글자 색상과 불투명 대체 배경색을 지정합니다.
5. CSS 또는 Tailwind v4를 선택해 복사합니다. 카드의 너비와 여백은 사용처에서 추가합니다.

잘못된 HEX는 이유를 표시하고 이전 카드와 코드를 숨깁니다. `#abz123`은 세 번째 문자 오류입니다. 전각 `＃ＡＢＣ`는 반각으로 정규화하지만 네 자리·여덟 자리 HEX, RGB와 HSL 함수는 받지 않습니다. 색상의 투명도는 별도 슬라이더에서 지정합니다. 입력을 고치기 전에는 복사할 수 없어 오래된 결과를 새 결과로 오해하지 않도록 했습니다.

## 노을 배경의 흰 카드와 어두운 카드

기본 흰 카드는 불투명도 15%, 블러 12px, 채도 180%입니다. 필터를 지원할 때 적용되는 부분은 다음과 같습니다.

{/* gsg-check: {"settings":{},"contains":"background: rgba(255, 255, 255, 0.15);"} */}
```css
background: rgba(255, 255, 255, 0.15);
backdrop-filter: blur(12px) saturate(180%);
```

복사 버튼은 전체 코드를 복사합니다. 불투명 대체 배경, 접두사 선언, 표시 상태별 규칙도 포함합니다. 기본 글자 `#111111`와 흰 대체 배경은 **18.88:1**입니다. 밤 배경으로 바꾸거나 사진의 어두운 부분 위에 놓으면 투명 카드의 결과는 달라집니다. 읽어야 하는 문구를 실제 페이지에 넣고 다시 확인하세요.

두 번째 예는 행사 안내 사진 위의 남색 카드입니다. 유리 색상 `#024`, 불투명도 80%, 블러 6px, 채도 100%, 흰 글자와 대체 배경 `#002244`를 선택합니다.

{/* gsg-check: {"settings":{"bg":"#002244","alpha":80,"blur":6,"saturation":100},"contains":"background: rgba(0, 34, 68, 0.80);"} */}
```css
background: rgba(0, 34, 68, 0.80);
backdrop-filter: blur(6px) saturate(100%);
```

흰 글자와 불투명 남색 배경의 대비는 **16.00:1**입니다. 사진을 열고 유리 효과 상태의 수치를 확인하세요. 이 값은 도구의 예제입니다. 밝은 조명이나 흰 간판이 카드 아래로 들어오면 투명한 상태의 최솟값이 바뀝니다.

## KRDS의 색상 단계와 투명 배경

[KRDS 색상 가이드](https://www.krds.go.kr/html/site/style/style_02.html)는 매직넘버 50을 4.5:1, 40을 3:1과 연결하며, Alpha 색상의 텍스트는 배경과의 명암비를 고려하라고 설명합니다. 단색 팔레트의 단계 차이를 그대로 투명 카드에 적용할 수는 없습니다. 사진과 합성된 색상이 실제 글자 배경이기 때문입니다.

행정 안내나 신청 화면에서는 배경의 분위기와 정보의 가독성을 따로 확인하세요. 카드 위치나 크기가 바뀌면 다른 화소를 덮습니다. 이 도구의 짧은 문구로 확인한 뒤, 사용처의 긴 한글 제목과 작은 안내 문구도 테스트해야 합니다. 단색 대체 배경의 조합은 [색상 명도 대비 검사기](/ko/tools/color-contrast-checker/)에서 비교할 수 있습니다. 링크, 오류 메시지와 키보드 초점도 따로 확인하세요.

## 필터가 없어도 읽을 수 있는 출력

출력은 불투명 배경부터 선언하고 `@supports`에서 반투명 배경과 필터를 덧붙입니다. 접두사는 같은 기능의 다른 이름이며 대체 배경을 만들어 주지는 않습니다. 두 이름을 모두 지원하지 않는 브라우저는 처음의 단색을 사용합니다.

`prefers-reduced-transparency: reduce`이면 단색으로 돌아가 필터를 끕니다. 앱에서 수동 토글을 제공할 때는 `glass` 요소에 `glass-opaque`를 추가하세요. 도구의 「투명 효과 끄기」는 불투명 버전을 만듭니다. 강제 색상 모드는 `Canvas`와 `CanvasText`를 쓰고 그림자를 없애며, 색상 선택을 사용자 시스템에 맡깁니다.

Tailwind v4 출력은 `@utility glass`입니다. Tailwind를 불러오는 CSS에 붙이고 HTML에 `class="glass"`를 사용합니다. Tailwind 4.3.3으로 실제 컴파일한 형식입니다. [사용자 정의 유틸리티 문서](https://tailwindcss.com/docs/adding-custom-styles#adding-custom-utilities)를 참고하세요. 버튼 이벤트, 카드의 배치나 배경 이미지 코드는 생성하지 않습니다.

## 블러가 사라질 때 살펴볼 요소

[Filter Effects Level 2](https://drafts.fxtf.org/filter-effects-2/#BackdropRoot)는 backdrop root가 배경을 가져오는 범위를 제한한다고 설명합니다. 2026-10-02 Chromium 테스트에서 조상에 `filter: brightness(1)`, `opacity: .99`, `will-change: opacity`를 적용하면 조상 밖의 흑백 줄무늬가 흐려지지 않았습니다. 대조군 `transform: translateZ(0)`에서는 블러가 남았습니다.

시각적으로 중립적인 필터도 범위를 바꿀 수 있으므로 조상 스타일을 확인하세요. 초안은 이 정의에 작업반 합의가 없다고 명시합니다. 사용처의 브라우저에서도 확인해야 합니다. 이미지 자체에 필터를 적용하려면 [CSS 필터 생성기](/ko/tools/css-filter-generator/)를 사용하세요.

## 대비 추정과 지원 범위

Canvas로 블러와 채도를 적용하고 채움색을 합성한 뒤, 카드 안쪽 사각형의 가장 낮은 대비를 계산합니다. 지정한 글자 색상을 사용합니다. [WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)는 일반 글자 4.5:1, 큰 글자 3:1을 요구합니다. 4.499를 반올림해 통과시키지 않습니다.

[MDN 데이터](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter#browser_compatibility)에서 접두사 없는 필터는 Chrome 76, Edge 79, Firefox 103, Safari 18부터 지원합니다. Safari 9–17은 접두사가 필요합니다. [투명도 줄이기 쿼리](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-transparency#browser_compatibility)는 Chromium 118부터 지원하고 Firefox는 설정으로 활성화하며 Safari는 지원 목록에 없습니다. 수동 토글을 함께 제공하는 이유입니다.

2026-10-02 css.glass에서 불투명도, Hype4에서 블러를 바꾸면 즉시 CSS가 변했습니다. 해당 편집 중 fetch/XHR 업로드는 관측하지 못했습니다. 확인한 출력은 반투명 선언이 중심이었으며 본 도구는 대체 상태의 규칙과 로컬 이미지의 대비 검사를 추가합니다.

## 처리 한계

이미지는 20 MB와 5천만 픽셀까지입니다. Canvas 필터가 없으면 알립니다. CSS와 Canvas는 블러 가장자리에서 다를 수 있습니다. 동영상, 여러 유리 층, 조상 효과, 시스템 색상의 대비는 모델링하지 않습니다. 이미지와 설정을 저장하지 않으며 배경 URL을 가져오지도 않습니다. 그림자 위치와 블러는 `0 4px 24px` 고정입니다. 별도의 그림자 설계는 [CSS 박스 섀도우 생성기](/ko/tools/box-shadow-generator/)에서 만들 수 있습니다.
