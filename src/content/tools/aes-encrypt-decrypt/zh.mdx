<h2>示例一：用密码加密一句话</h2>
<p>明文 <code>数据库只读账号下周一启用</code>，密码 <code>correct horse battery staple</code>，某一次的输出：</p>
<pre><code>v2:qXfeC+pkpC/F/K3PR6ucLX6MQOcmQtyj+UUn9SYWmygCNoyV6H080bCB6fI6r1FJzypkhN0oWVRkA1VMXiCkXm6soo3Tqi/PZM0fJ28ANQk=</code></pre>
<p>这 12 个汉字按 UTF-8 是 36 字节，所以 <code>v2:</code> 后面的 108 个 Base64 字符解码后是 80 字节：16 字节盐 + 12 字节 IV + 36 字节密文 + 16 字节认证标签。用同一个密码解密即可还原；再点一次加密，输出会变，因为盐和 IV 都是新的。</p>

<h2>示例二：解密微信支付 APIv3 回调报文</h2>
<p>微信支付的回调通知与平台证书下载接口用 AEAD_AES_256_GCM 加密 <code>resource</code> 字段，密钥是 32 字节的 APIv3 密钥，<code>nonce</code> 与 <code>associated_data</code> 按字符串参与解密，<code>ciphertext</code> 是 Base64 编码、末尾带 16 字节认证标签（见<a href="https://pay.weixin.qq.com/doc/v3/merchant/4012071382" rel="noopener">微信支付「如何解密回调报文和平台证书」</a>，2024-11-29 更新）。在本工具里这样填：</p>

<h2>密文格式与 Python 代码</h2>
<ul>
  <li>密码模式：<code>v2:</code> + Base64（或十六进制）的「盐 16 字节 | IV 12 字节 | 密文 | 认证标签 16 字节」，密钥由 PBKDF2-HMAC-SHA256 迭代 600,000 次得到 32 字节，取自 <a href="https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2" rel="noopener">OWASP 密码存储速查表</a>。</li>
  <li>无前缀：同样的布局，是本页 2026-09-30 之前生成的（20 万次迭代）。工具先试 20 万次，再试 60 万次，因此也能读取其他程序按同一布局写出的密文。</li>
  <li>原始密钥模式：Base64 或十六进制的「IV 12 字节 | 密文 | 认证标签」；填了 IV 时只有「密文 | 认证标签」，与微信支付的 <code>ciphertext</code> 相同。</li>
  <li>文件：同样的字节，不做 Base64；密码模式的文件以 <code>v2:</code> 三个字节开头。</li>
</ul>
<p>下面的 Python 代码（cryptography 45）与本工具互通：</p>

```python
import base64, os
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC

def _key(password: str, salt: bytes, iterations: int) -> bytes:
    kdf = PBKDF2HMAC(algorithm=hashes.SHA256(), length=32, salt=salt, iterations=iterations)
    return kdf.derive(password.encode("utf-8"))

def encrypt(text: str, password: str) -> str:
    salt, iv = os.urandom(16), os.urandom(12)
    ct = AESGCM(_key(password, salt, 600_000)).encrypt(iv, text.encode("utf-8"), None)
    return "v2:" + base64.b64encode(salt + iv + ct).decode()

def decrypt(token: str, password: str) -> str:
    # 有 "v2:" 前缀为 60 万次迭代；无前缀为本工具 2026-09-30 之前的格式（20 万次）
    token = token.strip()
    iterations = 600_000 if token.startswith("v2:") else 200_000
    data = base64.b64decode(token.removeprefix("v2:"))
    salt, iv, ct = data[:16], data[16:28], data[28:]
    return AESGCM(_key(password, salt, iterations)).decrypt(iv, ct, None).decode("utf-8")

def decrypt_raw(token: str, key_hex: str) -> str:
    # 原始密钥模式、IV 输入框留空：Base64 或十六进制的 iv(12) | 密文 | 标签(16)
    token = token.strip()
    is_hex = all(c in "0123456789abcdefABCDEF" for c in token)
    data = bytes.fromhex(token) if is_hex else base64.b64decode(token)
    return AESGCM(bytes.fromhex(key_hex)).decrypt(data[:12], data[12:], None).decode("utf-8")
```

<h2>OpenSSL 与 CBC 密文</h2>
<p><code>openssl enc</code> 读不了这种格式：<a href="https://docs.openssl.org/3.6/man1/openssl-enc/" rel="noopener">openssl-enc 手册</a>写明该命令不支持 CCM、GCM 等认证加密模式，以后也不会支持；OpenSSL 3.6.1 对 <code>-aes-256-gcm</code> 的回应是 <code>enc: AEAD ciphers not supported</code>。</p>
<p>以 <code>U2FsdGVkX1</code> 开头的密文是「Salted__」的 Base64，来自 <code>openssl enc</code> 或 CryptoJS 的 <code>AES.encrypt(文本, "口令")</code>，一般是 AES-256-CBC。CBC 没有认证标签，密码错了也可能输出乱码。本工具识别到这个头会直接说明，请改用下面的命令（2026-09-30 实测）：</p>

```bash
# 用 openssl enc -pbkdf2 加密的
openssl enc -d -aes-256-cbc -pbkdf2 -a -A -in message.txt
# 用 CryptoJS 4.2.0 AES.encrypt(文本, "口令") 加密的
openssl enc -d -aes-256-cbc -md md5 -a -A -in message.txt
```


<h2>与其他 AES 在线工具的实测差异</h2>
<p>2026-09-30 用桌面版 Chromium、同一段测试文本，观察页面发出的请求：</p>
<ul>
  <li><strong>锤子在线工具（toolhelper.cn）</strong>：点加密后把密钥、IV 与明文一起 POST 到 <code>/SymmetricEncryption/AesEncrypt</code>，在服务器端加密。它也有 GCM 的 nonce 与附加数据输入框，但用它解微信支付回调就意味着把 APIv3 密钥交给第三方服务器。</li>
  <li><strong>在线工具大全（lddgo.net）</strong>：把明文与密码 POST 到 <code>openapi.lddgo.net</code>，默认模式是 ECB。</li>
  <li><strong>CoderTools（codertools.net）</strong>：在浏览器内运行，默认 CBC、密钥按文本；密钥错误时结果框为空，没有任何提示。</li>
</ul>
<p>本工具只做 GCM，但每种失败都有明确提示，支持单独的 IV 与附加数据、文件加解密，页面不加载统计与广告。</p>

<h2>限制</h2>
<ul>
  <li>只支持 GCM，不做 CBC、ECB、CTR，读不了 openssl enc 与 CryptoJS 的输出，请用上面的命令。</li>
  <li>密码模式格式固定（PBKDF2-HMAC-SHA256、60 万次、16 字节盐、无附加数据），认证标签固定 128 位。</li>
  <li>文件上限 256 MB，整个在内存中处理。测试笔记本上 200 MB 文件约 0.8 秒，5 MB 文本约 1.7 秒（主要花在绘制文本框）。</li>
  <li>原始密钥配随机 96 位 IV 时，NIST SP 800-38D 第 8.3 节规定同一密钥最多加密 2<sup>32</sup> 次；密码模式每次都派生新密钥。</li>
  <li>文件名不加密，<code>合同.pdf.enc</code> 仍能看出原名；加密文件本身不保存文件名。</li>
  <li>弱密码加密后依然是弱密码，可用<a href="/zh/tools/password-generator/">密码生成器</a>生成；解密出的文件可用<a href="/zh/tools/file-hash-checker/">文件哈希校验</a>核对 SHA-256。</li>
</ul>
