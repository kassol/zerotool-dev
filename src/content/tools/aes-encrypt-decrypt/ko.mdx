<h2>사용 방법</h2>
<ol>
  <li>키 종류를 고릅니다. <strong>비밀번호</strong>는 PBKDF2로 256비트 키를 만들고, <strong>키 직접 입력</strong>은 128·192·256비트 키를 16진수·Base64·텍스트로 받습니다. "생성"을 누르면 무작위 키가 만들어집니다.</li>
  <li>암호화: 평문 칸에 입력하거나 <strong>파일…</strong>로 파일을 고른 뒤 <strong>암호화</strong>를 누릅니다. "출력"에서 Base64와 16진수를 바꿀 수 있습니다.</li>
  <li>복호화: 암호문을 붙여 넣거나 암호화 파일을 고르고 <strong>복호화</strong>를 누릅니다. 암호문 칸에서 Ctrl/⌘+Enter를 눌러도 됩니다.</li>
  <li>파일 결과는 다운로드 버튼으로 받습니다. 파일은 이 탭의 메모리 안에서만 처리됩니다.</li>
</ol>

<h2>예시 1: 비밀번호로 한 문장 암호화</h2>
<p>평문 <code>회의 자료는 금요일에 보낼게요</code>, 비밀번호 <code>correct horse battery staple</code>로 한 번 암호화한 결과입니다.</p>
<pre><code>v2:YG1w0RRceJRp9qzhdNMzvbZ7eX8AmQeIuhony1o1zSjfNPaAV5lBkfvl8KT7Q2NZ1XPl+HLtqfttXD8PQ+8IZ8EtFX68wchTNvUT/23rml8L9qRvK/o=</code></pre>
<p>한글 13자는 UTF-8로 39바이트, 공백 3개를 더하면 평문은 42바이트입니다. 그래서 <code>v2:</code> 뒤의 Base64는 86바이트(솔트 16 + IV 12 + 암호문 42 + 태그 16)입니다. 같은 비밀번호로 복호화하면 원문이 나오고, 다시 암호화하면 다른 문자열이 나옵니다. 솔트와 IV를 매번 새로 만들기 때문입니다.</p>

<h2>예시 2: 키와 IV를 정해 결과 재현하기</h2>
<p>다른 구현과 결과를 맞춰 볼 때는 키와 IV를 고정합니다. 키 종류 "키 직접 입력", 형식 Hex, 128비트 키 <code>00112233445566778899aabbccddeeff</code>, IV 칸 <code>a1b2c3d4e5f6a7b8c9d0e1f2</code>, 평문 <code>안녕하세요, ZeroTool</code>, 출력 Hex로 암호화하면 매번 다음 값이 나옵니다.</p>
<pre><code>9aabdcab3e4772d01c210ffdd44153dcaed5cfb2d26d821b54da9cfc72d4d337e5b2b770e70a7933d8</code></pre>
<p>41바이트로, 암호문 25바이트와 태그 16바이트입니다(IV 칸을 쓰면 IV는 출력에 넣지 않습니다). IV 칸은 16진수 딱 24자리면 12바이트로, 그 밖에는 텍스트의 UTF-8 바이트로 읽습니다. 고정 IV로 암호화하면 도구가 경고를 띄웁니다. 같은 키로 IV를 재사용하면 GCM의 안전성이 무너지기 때문입니다(<a href="https://csrc.nist.gov/pubs/sp/800/38/d/final" rel="noopener">NIST SP 800-38D</a> 8절). 실제 데이터는 IV 칸을 비워 두세요.</p>

<h2>KCMVP와의 관계</h2>
<p>한국인터넷진흥원의 <a href="https://seed.kisa.or.kr/kisa/kcmvp/EgovVerification.do" rel="noopener">KCMVP 검증대상 암호알고리즘</a> 목록(2026-09-30 확인)에는 블록암호로 ARIA, SEED, LEA, HIGHT와 함께 AES가 있고, AES의 운영모드로 기밀성/인증용 CCM, GCM이 올라 있습니다. 다만 KCMVP는 알고리즘이 아니라 이를 구현한 암호모듈을 검증하는 제도이며, 이 도구와 브라우저의 Web Crypto 구현은 KCMVP 검증을 받은 모듈이 아닙니다. 검증필 모듈이 필요한 시스템에서는 쓰지 말고, 개인적인 메모나 개발 중 암호문 확인 같은 용도로 쓰세요.</p>

<h2>암호문 형식과 Python 코드</h2>
<ul>
  <li>비밀번호: <code>v2:</code> + "솔트 16 | IV 12 | 암호문 | 태그 16"의 Base64(또는 16진수). 키는 PBKDF2-HMAC-SHA256을 600,000회(<a href="https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2" rel="noopener">OWASP Password Storage Cheat Sheet</a> 권장값) 돌려 32바이트로 유도합니다.</li>
  <li>접두사 없음: 같은 구성이며, 2026-09-30 이전에 이 페이지가 만든 것(200,000회)입니다. 도구는 200,000회, 이어서 600,000회를 시도하므로 같은 구성으로 쓰는 다른 프로그램의 출력도 읽습니다.</li>
  <li>키 직접 입력: "IV 12 | 암호문 | 태그 16". IV 칸을 쓰면 "암호문 | 태그"만 나옵니다.</li>
  <li>파일: Base64로 바꾸지 않은 같은 바이트이며, 비밀번호 모드 파일은 <code>v2:</code> 3바이트로 시작합니다.</li>
</ul>
<p>다음 Python 코드(cryptography 45)는 도구와 서로 암호화·복호화할 수 있습니다.</p>

```python
import base64, os
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC

def _key(password: str, salt: bytes, iterations: int) -> bytes:
    kdf = PBKDF2HMAC(algorithm=hashes.SHA256(), length=32, salt=salt, iterations=iterations)
    return kdf.derive(password.encode("utf-8"))

def encrypt(text: str, password: str) -> str:
    salt, iv = os.urandom(16), os.urandom(12)
    ct = AESGCM(_key(password, salt, 600_000)).encrypt(iv, text.encode("utf-8"), None)
    return "v2:" + base64.b64encode(salt + iv + ct).decode()

def decrypt(token: str, password: str) -> str:
    # "v2:"는 600,000회, 접두사 없음은 2026-09-30 이전 형식(200,000회)
    token = token.strip()
    iterations = 600_000 if token.startswith("v2:") else 200_000
    data = base64.b64decode(token.removeprefix("v2:"))
    salt, iv, ct = data[:16], data[16:28], data[28:]
    return AESGCM(_key(password, salt, iterations)).decrypt(iv, ct, None).decode("utf-8")

def decrypt_raw(token: str, key_hex: str) -> str:
    # 키 직접 입력, IV 칸이 빈 출력: iv(12) | 암호문 | 태그(16)의 Base64 또는 16진수
    token = token.strip()
    is_hex = all(c in "0123456789abcdefABCDEF" for c in token)
    data = bytes.fromhex(token) if is_hex else base64.b64decode(token)
    return AESGCM(bytes.fromhex(key_hex)).decrypt(data[:12], data[12:], None).decode("utf-8")
```

<h2>OpenSSL과 CBC 암호문</h2>
<p><code>openssl enc</code>는 이 형식을 읽지 못합니다. <a href="https://docs.openssl.org/3.6/man1/openssl-enc/" rel="noopener">openssl-enc 매뉴얼</a>은 CCM, GCM 같은 인증 암호화 모드를 지원하지 않으며 앞으로도 지원하지 않는다고 밝히고 있고, OpenSSL 3.6.1에 <code>-aes-256-gcm</code>을 주면 <code>enc: AEAD ciphers not supported</code>가 나옵니다.</p>
<p><code>U2FsdGVkX1</code>로 시작하는 문자열은 "Salted__"의 Base64로, <code>openssl enc</code>나 CryptoJS <code>AES.encrypt(텍스트, "암호 문구")</code>의 출력입니다(보통 AES-256-CBC). CBC에는 인증 태그가 없어서 비밀번호가 틀려도 깨진 결과가 나올 수 있습니다. 이 도구는 이 형식을 알아보고 안내만 합니다. 복호화는 다음 명령으로 하세요(2026-09-30 실행 확인).</p>

```bash
# openssl enc -pbkdf2로 암호화한 경우
openssl enc -d -aes-256-cbc -pbkdf2 -a -A -in message.txt
# CryptoJS 4.2.0 AES.encrypt(텍스트, "암호 문구")로 암호화한 경우
openssl enc -d -aes-256-cbc -md md5 -a -A -in message.txt
```


<h2>다른 AES 도구와의 차이(실측)</h2>
<p>2026-09-30 데스크톱 Chromium에서 같은 텍스트로 페이지가 보내는 요청을 확인했습니다.</p>
<ul>
  <li><strong>CoderTools(codertools.net, 한국어판)</strong>: 브라우저 안에서 처리하며, 기본값은 CBC이고 키를 텍스트 그대로 씁니다. 틀린 키로 복호화하면 결과 칸이 비기만 하고 메시지는 없습니다.</li>
  <li><strong>Go Tools(go-tools.org)</strong>: 브라우저 안에서 처리합니다. 영어판에서 확인한 암호 문구 방식은 AES-GCM, PBKDF2 600,000회로 이 도구와 같은 바이트 구성(접두사 없음)이며, 그 출력은 이 도구에서 그대로 복호화됐습니다.</li>
  <li><strong>devglan.com</strong>: 텍스트와 키를 <code>devglan.com/online-tools/aes-encryption</code>으로 POST 전송해 서버에서 암호화합니다.</li>
</ul>
<p>이 도구는 실패 종류마다 메시지를 보여 주고, IV와 추가 데이터를 지정하는 키 직접 입력과 파일 암호화를 지원하며, 페이지에서 분석 태그나 광고를 불러오지 않습니다.</p>

<h2>제한 사항</h2>
<ul>
  <li>GCM만 지원하며 CBC, ECB, CTR은 다루지 않습니다. openssl enc나 CryptoJS 출력은 위 명령으로 복호화하세요.</li>
  <li>비밀번호 모드 형식은 고정입니다(PBKDF2-HMAC-SHA256, 600,000회, 16바이트 솔트, 추가 데이터 없음). 태그는 항상 128비트입니다.</li>
  <li>파일은 256 MB까지이며 전체를 메모리에서 처리합니다. 테스트 노트북에서 200 MB 파일은 약 0.8초, 5 MB 텍스트는 약 1.7초(대부분 텍스트 칸 그리기)였습니다.</li>
  <li>무작위 96비트 IV를 쓸 때 NIST SP 800-38D 8.3절에 따라 한 키로 암호화할 수 있는 횟수는 2<sup>32</sup>번입니다. 비밀번호 모드는 매번 새 키를 유도합니다.</li>
  <li>파일 이름은 암호화되지 않습니다(<code>회의자료.pdf.enc</code>에서 원래 이름이 보입니다). 암호화 파일 자체에는 파일 이름을 저장하지 않습니다.</li>
  <li>약한 비밀번호는 암호화해도 약합니다. <a href="/ko/tools/password-generator/">비밀번호 생성기</a>로 만들고, 복호화한 파일은 <a href="/ko/tools/file-hash-checker/">파일 해시 검사기</a>로 SHA-256을 대조할 수 있습니다.</li>
</ul>
