<h2>使用步骤</h2>
<ol>
  <li>把 prompt、文档或代码粘贴到输入框，也可以点「打开文件」读取本地文本。o200k_base 的数量随输入实时更新。</li>
  <li>在 DeepSeek V4 或 cl100k_base 卡片上点「计算」，加载对应词表（0.5 MB 和 0.4 MB），之后会记住这个选择。</li>
  <li>填写预计输出 token 数，表格给出每个模型单次请求的输入、输出、合计费用，以及占输入上限的比例。</li>
  <li>在「Token 切分」里选择分词器，看每个 token 从哪里断开；打开 token id，可以和接口或调试输出对照。</li>
</ol>

<h2>DeepSeek：按字数估算和精确计数差多少</h2>
<p>
  DeepSeek 的 <a href="https://api-docs.deepseek.com/zh-cn/quick_start/token_usage">Token 用量计算</a>文档给出两条经验值：1 个英文字符约 0.3 个 token，1 个中文字符约 0.6 个 token，并提供离线计算的分词器压缩包。本工具的 DeepSeek V4 卡片就是用这个压缩包里的 <code>tokenizer.json</code> 生成的，计数与官方分词器一致。
</p>

<h2>哪些模型能精确计数</h2>
<ul>
  <li><strong>o200k_base</strong>：GPT-5.x、GPT-4.1、GPT-4o、o1、o3、o4-mini。依据是 OpenAI <a href="https://github.com/openai/tiktoken/blob/main/tiktoken/model.py">tiktoken 的模型对照表</a>。</li>
  <li><strong>cl100k_base</strong>：GPT-4、GPT-3.5 Turbo，以及 <a href="https://developers.openai.com/api/docs/guides/embeddings">向量模型文档</a>指定的 text-embedding-3 系列。做 RAG 分块时用它算 8,192 的输入上限。</li>
  <li><strong>DeepSeek V4</strong>：deepseek-flash、deepseek-v4-pro。</li>
  <li><strong>Claude、Gemini、GPT-6</strong>：没有公开本地分词器。Anthropic 的<a href="https://platform.claude.com/docs/en/build-with-claude/token-counting">计数接口</a>免费，但文档自己也说结果是估算；它还说明 Claude 4.7 及以后的模型对同一段文本约多 30% 的 token。Google 的<a href="https://ai.google.dev/gemini-api/docs/tokens">说明</a>只给出「约 4 个字符一个 token」。表格对它们用 o200k_base 数量作参考，标 ≈。</li>
</ul>
<p>通义千问、豆包、Kimi、GLM 等国内模型各有自己的词表，本工具不计算它们，请以各平台返回的 usage 为准。</p>

<h2>限制</h2>
<ul>
  <li>只计算纯文本。消息格式、system 提示、工具定义、图片和文件带来的 token 只有厂商接口能算。</li>
  <li><code>&lt;|endoftext|&gt;</code> 这类 OpenAI 特殊标记按普通文本计算（7 个 token），与 tiktoken 的 <code>encode_ordinary</code> 一致；DeepSeek 自己的标记如 <code>&lt;｜User｜&gt;</code> 按官方 tokenizer.json 计为 1 个。</li>
  <li>Claude、Gemini、GPT-6 的行只是参考值。</li>
  <li>DeepSeek 压缩包的示例脚本用 transformers 加载。我们实测 transformers 5.18.0 对这个包里的中文文本返回空列表，4.57.6 和 tokenizers 库返回的结果与本页一致。离线脚本请固定 transformers 4.x，或直接用 tokenizers。</li>
  <li>价格是 2026 年 10 月 1 日的快照，不含税费与协议折扣。</li>
</ul>
