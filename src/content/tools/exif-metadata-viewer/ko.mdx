<h2>사진을 공유하기 전에 EXIF를 제거해야 하는 이유</h2>

<p>위치 기능을 켠 스마트폰과 카메라는 사진마다 GPS 좌표, 기종, 촬영 시각을 기록합니다. EXIF를 제거하지 않은 채 게시판·블로그·메타데이터를 지우지 않는 메신저에 사진을 올리면, 무료 도구만으로도 촬영 장소가 몇 미터 단위로 드러날 수 있습니다.</p>

<p>이 도구로 사진에 무엇이 기록되어 있는지 먼저 확인하고, 메타데이터를 제거한 사본을 내려받을 수 있습니다. 읽기와 제거는 모두 지금 열려 있는 브라우저 탭 안에서 처리합니다.</p>

<h2>제거되는 세그먼트</h2>

<p>제거 단계는 JPEG 마커 스트림을 훑으면서 개인정보가 들어가기 쉬운 세그먼트를 제거합니다:</p>

<ul>
  <li><strong>APP1</strong> — EXIF(카메라, GPS, 타임스탬프)와 XMP(Adobe 메타데이터, 편집 이력)</li>
  <li><strong>APP13</strong> — Photoshop / IPTC(캡션, 저작권, 연락처)</li>
</ul>

<p>브라우저가 이미지를 올바르게 디코딩하는 데 필요한 세그먼트는 그대로 둡니다: SOI 시작 마커, JFIF(APP0), ICC 색상 프로파일(APP2), Adobe 색상 변환 마커(APP14, CMYK 이미지는 이것이 없으면 색이 틀어짐), SOS 스캔 마커, 압축 이미지 데이터, EOI 종료 마커. 유일한 예외는 APP1에 있는 방향(Orientation) 정보입니다. 값이 2–8이면 원래 APP1 자리에 이 항목 하나만 담은 APP1(Exif 2.32 / 3.0의 IFD0 태그 0x0112, 36바이트)을 다시 씁니다. 휴대폰은 세로로 찍은 사진을 가로로 저장하고 방향 값 6 또는 8로 회전해 보여 주므로, 이 값이 없으면 정리한 사진이 가로로 표시됩니다. 방향 정보는 회전 방법만 담고 있어 개인정보는 담기지 않습니다. 결과는 <code>{"exiftool -all= -tagsfromfile @ -Orientation photo.jpg"}</code>와 같습니다. 값이 1(정방향)이거나 1–8 범위 밖이면 다시 쓰지 않습니다. XMP에만 기록된 방향은 XMP와 함께 지워집니다.</p>

<h2>예시: 한글 소프트웨어 이름이 들어간 테스트 사진</h2>

<p>아래 두 예시의 파일은 테스트 스크립트가 만든 64 × 48 단색 JPEG에 적힌 필드만 기록한 것입니다(ExifTool 13.55로 다시 읽어 확인). 실제 사진이 아니며, 좌표는 남산서울타워 근처의 공개된 랜드마크로 특정 개인과 관련이 없습니다.</p>

<p>기록한 값: Make <code>Example</code>, Model <code>Test Phone</code>, Software <code>갤러리 편집 1.0</code>(ExifTool이 ASCII 형식 필드에 UTF-8 바이트로 기록), 촬영 시각 <code>2026:10:03 15:20:10</code>, 조리개 1.8, 셔터 1/120, ISO 64, 초점거리 6.3 mm, GPS 북위 37°33′4.21″·동경 126°59′17.62″, 고도 236 m. 도구는 다음과 같이 표시합니다.</p>

<p>초점거리 6.3 mm는 화면에서 반올림해 6 mm로 보이고, EXIF JSON 복사로 원래 값을 얻을 수 있습니다. 한글 소프트웨어 이름이 그대로 보이는 것은 ASCII 형식 필드의 바이트가 올바른 UTF-8이면 UTF-8로 읽기 때문입니다. 다만 Exif 3.0은 2바이트 이상의 문자에는 UTF-8 형식(129)을 쓰도록 정하고 있고, 이 형식은 아직 해석하지 못합니다(아래 제한 사항 참고).</p>

<h2>예시: 세로 사진을 정리하면 남는 것</h2>

<p>같은 정보에 방향 값 8(표시할 때 반시계 방향으로 90° 회전)을 더한 테스트 파일을 넣고 ‘메타데이터 제거된 JPEG 다운로드’를 누른 뒤, 내려받은 파일을 다시 읽으면 남은 EXIF는 <code>{'{"ifd0":{"Orientation":8},"exif":{},"gps":{}}'}</code>뿐입니다. 제조사, 모델, 소프트웨어, GPS 좌표는 사라지고 세로 방향 표시는 유지됩니다. 중고 거래 글처럼 집에서 찍은 사진을 올릴 때는 이렇게 정리한 파일을 쓰고, 원본 정보가 필요하면 다운로드 전에 EXIF JSON을 복사해 두세요.</p>

<h2>표시되는 EXIF 필드</h2>

<ul>
  <li><strong>카메라</strong>: 제조사, 모델, 렌즈 모델</li>
  <li><strong>시간</strong>: 원본 촬영 시각, 마지막 수정 시각(시간대 없음)</li>
  <li><strong>노출</strong>: 조리개(F값), 셔터, ISO, 초점거리</li>
  <li><strong>GPS</strong>: 위도, 경도, 고도, Google 지도 링크</li>
  <li><strong>소프트웨어</strong>: 파일을 기록한 OS 또는 편집 앱</li>
</ul>

<h2>제한 사항</h2>

<ul>
  <li><strong>JPEG만, 100 MB까지.</strong> PNG, HEIC, WebP, TIFF는 받지 않습니다. 붙여넣기는 클립보드에 JPEG가 있을 때만 동작하며, 스크린샷은 대개 PNG입니다.</li>
  <li><strong>표시하는 필드가 정해져 있습니다.</strong> 시리얼 번호, 시차(OffsetTimeOriginal), 측지계(GPSMapDatum) 같은 태그는 표시하지 않고 JSON 복사에도 없지만, 다운로드할 때 EXIF 블록과 함께 삭제됩니다.</li>
  <li><strong>문자 인코딩.</strong> ASCII 형식 필드는 바이트가 올바른 UTF-8이면 UTF-8로 표시하고, 아니면 1바이트를 1글자로 표시합니다(EUC-KR로 기록된 한글은 깨져 보입니다). Exif 3.0에 추가된 UTF-8 형식(129)은 해석하지 않아 그 행이 표시되지 않고 JSON에서는 <code>null</code>이 됩니다.</li>
  <li><strong>EXIF 안의 오프셋이 파일 밖을 가리키는 경우</strong> 읽을 수 있는 필드만 표시하고 ‘EXIF 블록 형식이 잘못되었습니다. 파싱 가능한 필드만 표시합니다.’라고 알립니다. 다운로드는 그대로 동작합니다. <strong>파일 자체가 이미지 데이터 앞에서 잘린 경우</strong>(마커 세그먼트 중간에서 끝난 경우)에는 정리할 이미지가 없으므로 다운로드는 파일을 저장하지 않고 ‘JPEG 파일이 이미지 데이터 앞에서 잘려 있어 정리된 사본을 만들 수 없습니다.’라고 표시합니다.</li>
  <li><strong>APP1과 APP13만 제거합니다.</strong> 주석(COM), 다른 애플리케이션 세그먼트(APP3–APP12, APP15), 종료 마커 뒤에 붙은 데이터(일부 휴대폰이 덧붙이는 HDR·심도 이미지)는 남습니다. 완전히 지우려면 <code>{"exiftool -all= photo.jpg"}</code>를 실행하거나 편집기에서 다시 저장하세요.</li>
</ul>

</ul>
