<h3>Array of tables</h3>
<p>TOML arrays of tables (using the double-bracket <code>[[table]]</code> syntax) become JSON arrays of objects. For example, two <code>[[fruits]]</code> table entries convert to a fruits array containing two objects.</p>

<h2>TOML vs JSON</h2>
<p>
  <strong>TOML</strong> (Tom's Obvious Minimal Language) is a configuration file format designed to be easy to read due to its obvious semantics.
  It is widely used in Rust projects (<code>Cargo.toml</code>), Hugo, and many other tools.
  <strong>JSON</strong> is the standard data interchange format for APIs and web services.
  This tool converts between them; the differences between the two type systems are listed under "What Changes in Conversion" below.
</p>

## What Changes in Conversion

TOML has types that JSON lacks, and the reverse. This input:

```toml
# build settings
title = "x"
created = 2026-09-29T10:00:00Z
day = 2026-09-29
ratio = inf

[server]
port = 8080
```

converts to:

```json
{
  "title": "x",
  "created": "2026-09-29T10:00:00.000Z",
  "day": "2026-09-29",
  "ratio": null,
  "server": {
    "port": 8080
  }
}
```

- **Comments are dropped.** JSON has no comments.
- **Dates and times become strings.** An offset date-time gains milliseconds (`.000Z`). Converting the JSON back gives a quoted string, not a TOML date.
- **`inf` and `nan` become `null`.** JSON has no infinity or NaN.
- **Integers above 2^53 − 1 are rejected.** [TOML 1.0](https://toml.io/en/v1.0.0) allows 64-bit integers, but the parser stops with `integer value cannot be represented losslessly` rather than round them.
- **JSON `null` is dropped when converting to TOML.** TOML has no null, so `{"a": null}` produces an empty document without an error. Replace nulls first.
