<h2>How to Use</h2>
<ol>
  <li>To convert <strong>TOML → JSON</strong>: paste your TOML into the left panel. The JSON updates 0.3 seconds after you stop typing; <strong>TOML → JSON</strong> converts at once.</li>
  <li>To convert <strong>JSON → TOML</strong>: paste your JSON into the right panel and click <strong>JSON → TOML</strong>.</li>
  <li>Use <strong>Ctrl+Enter</strong> (or <strong>Cmd+Enter</strong> on Mac) as a keyboard shortcut from whichever panel you're editing.</li>
  <li>Click <strong>Copy</strong> on either panel to copy the result to your clipboard.</li>
</ol>

<h2>Worked Examples</h2>

<h3>Simple table</h3>
<p>Input TOML:</p>
<pre><code>[database]
host = "localhost"
port = 5432
enabled = true</code></pre>
<p>Output JSON: <code>{'{ "database": { "host": "localhost", "port": 5432, "enabled": true } }'}</code>, indented with two spaces.</p>

<h3>Array of tables</h3>
<p>Two <code>[[fruits]]</code> entries become one array, and each entry keeps only the keys it has:</p>

```toml
[[fruits]]
name = "apple"

[[fruits]]
name = "banana"
color = "yellow"
```

```json
{
  "fruits": [
    { "name": "apple" },
    { "name": "banana", "color": "yellow" }
  ]
}
```

<p>(The tool indents every object over several lines; it is shortened here.) A <code>pyproject.toml</code> works the same way:
<code>[tool.ruff.lint]</code> becomes <code>{'"tool": { "ruff": { "lint": { ... } } }'}</code>, and keys with dashes such as
<code>requires-python</code> are kept as written.</p>

<h3>JSON to TOML: a package.json</h3>
<p>Pasting this JSON into the right panel:</p>

```json
{"name":"demo","version":"1.0.0","private":true,"scripts":{"build":"astro build","test":"node --test"},"workspaces":["packages/*"],"engines":{"node":">=22"}}
```

<p>gives:</p>

```toml
name = "demo"
version = "1.0.0"
private = true
workspaces = [ "packages/*" ]

[scripts]
build = "astro build"
test = "node --test"

[engines]
node = ">=22"
```

<p>
  Plain values are written first and nested objects follow as <code>[tables]</code>, because in TOML every key after a table header
  belongs to that table. Keys that are not bare words are quoted: <code>{'{"my key": 1, "a.b": 2}'}</code> becomes
  <code>{'"my key" = 1'}</code> and <code>{'"a.b" = 2'}</code>, so a dot inside a JSON key is not turned into nesting.
</p>

<h2>TOML vs JSON</h2>
<p>
  <strong>TOML</strong> (Tom's Obvious Minimal Language) is a configuration file format designed to be easy to read due to its obvious semantics.
  It is widely used in Rust projects (<code>Cargo.toml</code>), Hugo, and many other tools.
  <strong>JSON</strong> is the standard data interchange format for APIs and web services.
  This tool converts between them; the differences between the two type systems are listed under "What Changes in Conversion" below.
</p>

## What Changes in Conversion

TOML has types that JSON lacks, and the reverse. This input:

```toml
# build settings
title = "x"
created = 2026-09-29T10:00:00Z
day = 2026-09-29

[server]
port = 8080
```

converts to:

```json
{
  "title": "x",
  "created": "2026-09-29T10:00:00.000Z",
  "day": "2026-09-29",
  "server": {
    "port": 8080
  }
}
```

- **Comments are dropped.** JSON has no comments.
- **Dates and times become strings.** An offset date-time gains milliseconds (`.000Z`). Converting the JSON back gives a quoted string, not a TOML date.
- **Times finer than milliseconds stop the conversion to JSON.** The TOML parser keeps milliseconds and drops further digits, which [TOML 1.0](https://toml.io/en/v1.0.0#offset-date-time) allows a parser to do. `started = 2026-10-01T09:30:00.123456Z` in a `[build]` table gives `Not converted: JSON cannot hold these values without changing them: /build/started: 2026-10-01T09:30:00.123456Z has more than millisecond precision`. Trailing zeros, as in `.120000`, lose nothing and convert. Dates and times inside strings and comments are text and are not checked.
- **`inf` and `nan` stop the conversion to JSON.** JSON has no infinity or NaN, and `JSON.stringify` would write `null`. This TOML:

  ```toml
  ratio = inf

  [limits]
  max = nan
  ```

  gives `Not converted: JSON cannot hold these values without changing them: /ratio: inf has no JSON form (JSON.stringify would write null); /limits/max: nan has no JSON form (JSON.stringify would write null)`.
- **Integers outside ±(2^53 − 1) stop the conversion in both directions.** [TOML 1.0](https://toml.io/en/v1.0.0) allows 64-bit integers, but the TOML parser stops with `integer value cannot be represented losslessly` rather than round them. In JSON → TOML, `JSON.parse` would round them, so the field is listed instead; a number too large for a double, such as `1e400`, is listed too.
- **JSON `null` stops the conversion to TOML.** TOML has no null. This JSON:

  ```json
  {"user":{"id":9007199254740993,"nickname":null}}
  ```

  gives `Not converted: TOML cannot hold these values without changing them: /user/id: integer 9007199254740993 is outside ±(2^53 − 1), so JavaScript would round it; /user/nickname: null — TOML has no null`. Quote large IDs as strings and replace or remove nulls, then convert again.
- **A failed conversion clears the output panel** and disables its Copy button, so an earlier result is not copied by mistake.
- **`-0.0` keeps its sign both ways.** The JSON `{"offset":-0.0}` gives `offset = -0.0`, a TOML float, and TOML `offset = -0.0` gives `"offset": -0.0` (`JSON.stringify` alone would write `0`). The JSON integer `-0` gives `count = 0` for `{"count":-0}`: [TOML 1.0](https://toml.io/en/v1.0.0#integer) says `-0` and `+0` are the same integer as `0`.
- **JSON `1.0` becomes TOML `1`.** `JSON.parse` does not keep the difference between `1.0` and `1`, so a float that happens to be whole is written as a TOML integer. Write `1.5`-style values or fix the type by hand if your program checks it.
- **The JSON root must be an object.** `[1, 2]` gives `stringify can only be called with an object`, because a TOML document is always a table.
- **Redefinitions are errors.** TOML such as `a = 1` followed by `[a]` gives `trying to redefine an already defined table or value` with the line and a caret.

For the same data in YAML, use the [YAML ↔ TOML converter](/tools/yaml-toml/); to check a JSON file before converting it, use the [JSON formatter](/tools/json-formatter/).
