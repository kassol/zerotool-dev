<h2>TOML의 활용 사례</h2>
<p>Rust 프로젝트 설정(Cargo.toml), Python 패키지 설정(pyproject.toml), 정적 사이트 생성기 설정(Hugo, Zola) 등에서 널리 사용됩니다. 기존 JSON 설정을 TOML로 마이그레이션하거나 TOML 내용을 API에 전달할 때 변환이 필요합니다.</p>

## 변환하면서 바뀌는 것

TOML에는 JSON에 없는 타입이 있고, 그 반대도 있습니다. 다음 입력은

```toml
# build settings
title = "x"
created = 2026-09-29T10:00:00Z
day = 2026-09-29

[server]
port = 8080
```

이렇게 변환됩니다.

```json
{
  "title": "x",
  "created": "2026-09-29T10:00:00.000Z",
  "day": "2026-09-29",
  "server": {
    "port": 8080
  }
}
```

- **주석은 사라집니다.** JSON에는 주석이 없습니다.
- **날짜와 시간은 문자열이 됩니다.** 오프셋이 있는 날짜-시간에는 밀리초(`.000Z`)가 붙습니다. JSON을 다시 TOML로 바꾸면 TOML 날짜가 아니라 따옴표로 감싼 문자열이 됩니다.
- **밀리초보다 정밀한 시간이 있으면 JSON으로 변환하지 않습니다.** TOML 파서는 밀리초까지만 남기고 그 아래 자릿수를 버립니다([TOML 1.0](https://toml.io/en/v1.0.0#offset-date-time)은 파서에 이를 허용합니다). `[build]` 테이블의 `started = 2026-10-01T09:30:00.123456Z`는 `변환하지 않았습니다: JSON에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /build/started: 2026-10-01T09:30:00.123456Z — 밀리초보다 정밀합니다` 메시지를 냅니다. `.120000`처럼 끝에 붙은 0은 정보를 잃지 않으므로 변환합니다. 문자열과 주석 안의 날짜·시간은 텍스트이므로 검사하지 않습니다.
- **`inf`와 `nan`이 있으면 JSON으로 변환하지 않습니다.** JSON에는 무한대와 NaN이 없고 `JSON.stringify`는 `null`로 씁니다. 다음 TOML은

  ```toml
  ratio = inf

  [limits]
  max = nan
  ```

  `변환하지 않았습니다: JSON에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /ratio: inf — JSON으로 나타낼 수 없습니다(JSON.stringify는 null로 씁니다); /limits/max: nan — JSON으로 나타낼 수 없습니다(JSON.stringify는 null로 씁니다)` 메시지를 냅니다.
- **±(2^53 − 1)을 벗어나는 정수는 양방향 모두 변환하지 않습니다.** [TOML 1.0](https://toml.io/en/v1.0.0)은 64비트 정수를 허용하지만, TOML 파서는 반올림하지 않고 `integer value cannot be represented losslessly` 오류로 멈춥니다. JSON → TOML에서는 `JSON.parse`가 반올림하므로 필드를 표시하고 멈춥니다. `1e400`처럼 배정밀도 범위를 넘는 수도 표시합니다.
- **JSON의 `null`이 있으면 TOML로 변환하지 않습니다.** TOML에는 null이 없습니다. 다음 JSON은

  ```json
  {"user":{"id":9007199254740993,"nickname":null}}
  ```

  `변환하지 않았습니다: TOML에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /user/id: 정수 9007199254740993 — ±(2^53 − 1) 범위를 벗어나 JavaScript에서 반올림됩니다; /user/nickname: null — TOML에는 null이 없습니다` 메시지를 냅니다. 큰 ID는 문자열로 쓰고 null을 바꾸거나 지운 뒤 다시 변환하세요.
- **변환에 실패하면 출력 패널이 비워지고** 복사 버튼이 비활성화되어 이전 결과를 잘못 복사하지 않습니다.
- **`-0.0`은 양방향 모두 부호를 유지합니다.** JSON `{"offset":-0.0}`은 TOML 부동소수점 `offset = -0.0`이 되고, TOML `offset = -0.0`은 `"offset": -0.0`이 됩니다(`JSON.stringify`만 쓰면 `0`이 됩니다). JSON 정수 `-0`은 정수 0으로 씁니다. `{"count":-0}`은 `count = 0`이 됩니다. [TOML 1.0](https://toml.io/en/v1.0.0#integer)은 `-0`과 `+0`을 `0`과 같은 정수로 정합니다.
