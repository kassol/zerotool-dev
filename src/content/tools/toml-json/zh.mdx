<h2>转换示例</h2>

<h3>简单表格</h3>
<p>输入 TOML：</p>
<pre><code>[database]
host = "localhost"
port = 5432
enabled = true</code></pre>
<p>输出 JSON 包含嵌套的 database 对象，含 host、port 和 enabled 字段。</p>

<h3>表格数组</h3>
<p>TOML 表格数组（使用双方括号 <code>[[table]]</code> 语法）会转换为 JSON 对象数组。例如，两个 <code>[[fruits]]</code> 表格块转换后得到包含两个对象的 fruits 数组。</p>

<h2>TOML 与 JSON 对比</h2>
<p>
  <strong>TOML</strong>（Tom's Obvious Minimal Language）是一种以语义明确、易于阅读著称的配置文件格式，广泛用于 Rust 项目（<code>Cargo.toml</code>）、Hugo 等工具。
  <strong>JSON</strong> 是 API 和 Web 服务中最常用的数据交换格式。
  本工具在两者之间转换，两种类型系统的差异见下文「转换时会变的地方」。
</p>

## 转换时会变的地方

TOML 有 JSON 没有的类型，反过来也一样。下面的输入：

```toml
# build settings
title = "x"
created = 2026-09-29T10:00:00Z
day = 2026-09-29

[server]
port = 8080
```

转换结果是：

```json
{
  "title": "x",
  "created": "2026-09-29T10:00:00.000Z",
  "day": "2026-09-29",
  "server": {
    "port": 8080
  }
}
```

- **注释会丢失。** JSON 没有注释。
- **日期时间变成字符串。** 带时区偏移的日期时间会补上毫秒（`.000Z`）。再转回 TOML 时得到的是带引号的字符串，不再是 TOML 日期。
- **精度超过毫秒的时间会停止转 JSON。** TOML 解析器只保留到毫秒，后面的位数会被舍去（[TOML 1.0](https://toml.io/en/v1.0.0#offset-date-time) 允许解析器这样做）。`[build]` 表里的 `started = 2026-10-01T09:30:00.123456Z` 得到 `未转换：JSON 无法原样保存下列值：/build/started：2026-10-01T09:30:00.123456Z 的精度超过毫秒`。末尾补零（如 `.120000`）不丢信息，照常转换。字符串和注释里的日期时间是文本，不检查。
- **`inf` 和 `nan` 会停止转 JSON。** JSON 没有无穷大和 NaN，`JSON.stringify` 会写成 `null`。下面的 TOML：

  ```toml
  ratio = inf

  [limits]
  max = nan
  ```

  得到 `未转换：JSON 无法原样保存下列值：/ratio：inf 在 JSON 中没有写法（JSON.stringify 会写成 null）；/limits/max：nan 在 JSON 中没有写法（JSON.stringify 会写成 null）`。
- **超出 ±(2^53 − 1) 的整数在两个方向都会停止转换。** [TOML 1.0](https://toml.io/en/v1.0.0) 允许 64 位整数，但 TOML 解析器不会四舍五入，而是报错 `integer value cannot be represented losslessly`。JSON → TOML 时 `JSON.parse` 会把它们四舍五入，所以工具改为列出字段；`1e400` 这类超出双精度范围的数字也会列出。
- **JSON 的 `null` 会停止转 TOML。** TOML 没有 null。下面的 JSON：

  ```json
  {"user":{"id":9007199254740993,"nickname":null}}
  ```

  得到 `未转换：TOML 无法原样保存下列值：/user/id：整数 9007199254740993 超出 ±(2^53 − 1)，JavaScript 会把它四舍五入；/user/nickname：null，TOML 没有 null`。请把大 ID 写成字符串，替换或删除 null 后再转换。
- **转换失败时输出面板会清空**，复制按钮停用，不会误复制之前的结果。
- **`-0.0` 在两个方向都保留负号。** JSON `{"offset":-0.0}` 得到 TOML 浮点数 `offset = -0.0`，TOML `offset = -0.0` 得到 `"offset": -0.0`（只用 `JSON.stringify` 会写成 `0`）。JSON 整数 `-0` 写成整数零：`{"count":-0}` 得到 `count = 0`，[TOML 1.0](https://toml.io/en/v1.0.0#integer) 规定 `-0`、`+0` 与 `0` 是同一个整数。
