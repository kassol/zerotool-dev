## How to Use

1. Type or paste text in the **Text** box. The binary appears in the **Binary (UTF-8)** box as you type, one 8-bit group per byte.
2. Pick a **Separator** for the output: Space, None (one continuous string), Comma, or New line.
3. To go the other way, paste binary into the **Binary** box and click **Binary → Text** (or press Ctrl+Enter / ⌘+Enter in the box).
4. Read the status line under the boxes. It gives the counts, a note when something needs your attention, or the reason a conversion failed.
5. Use the **Copy** button above either box.

## Three Characters, Byte by Byte

The tool encodes text with UTF-8 ([RFC 3629](https://www.rfc-editor.org/rfc/rfc3629#section-3)) and writes each byte as 8 bits. These are the tool's own outputs:

| Input | Code point | UTF-8 bytes | Binary output |
|---|---|---|---|
| `A` | U+0041 | 41 | `01000001` |
| `中` | U+4E2D | E4 B8 AD | `11100100 10111000 10101101` |
| `😀` | U+1F600 | F0 9F 98 80 | `11110000 10011111 10011000 10000000` |

So "8 bits per character" is only true for ASCII. The first bits of each byte tell a decoder how long the character is: `0xxxxxxx` is a one-byte character, `1110xxxx` starts a three-byte character, `11110xxx` starts a four-byte one, and every `10xxxxxx` byte continues the character before it.

What looks like one character can be several code points. The family emoji 👨‍👩‍👧 is three emoji joined by two ZERO WIDTH JOINER characters (U+200D). The tool reports it as `1 character (5 code points) → 18 bytes of UTF-8`, and the output contains `11100010 10000000 10001101` twice, once for each joiner. An accented letter typed as `e` plus a combining acute accent (U+0301) gives `01100101 11001100 10000001`, while the precomposed `é` (U+00E9) gives `11000011 10101001`. Both look the same on screen. Characters are counted as grapheme clusters as defined in [Unicode UAX #29](https://www.unicode.org/reports/tr29/).

## Decoding Binary from Code and Homework

Binary copied from code often has no leading zeros. Python's [`bin()`](https://docs.python.org/3/library/functions.html#bin) returns `0b1001000` for 72, and JavaScript's `(72).toString(2)` returns `1001000`. This Python line gives 7-bit groups:

```python
' '.join(format(ord(c), 'b') for c in 'Zero')
# '1011010 1100101 1110010 1101111'
```

Paste that into the Binary box and the tool returns `Zero`, with the note that 4 groups were read with leading zeros. The `0b` form (`0b1001000 0b1101001`) decodes to `Hi` as well.

A group shorter than 8 bits counts as one byte only when no group is longer than 8 bits. If you paste a continuous stream that was wrapped at an odd place, such as `0100100001101001` followed by `01` on the next line, the tool stops at group 2 instead of turning `01` into a control character.

## What the Error Messages Mean

Binary → Text either shows the whole text or shows no text and one message. Each case below is an input you can paste:

| Input | Message (shortened) |
|---|---|
| `01001000 0110100x` | Character "x" at position 17 is not 0 or 1 |
| `010010000110100` | 15 bits is not a multiple of 8: the last byte has only 7 bits |
| `11100100 10111000` | Byte 1 starts a 3-byte UTF-8 character, but only 2 bytes of it are present |
| `10111000` | Byte 1 is a continuation byte (10xxxxxx) with no lead byte before it |
| `11101101 10100000 10000000` | Bytes 1–2 encode a UTF-16 surrogate, which UTF-8 does not allow |

The UTF-8 checks follow the byte ranges in RFC 3629 section 4: `C0`, `C1` and `F5`–`FF` never occur, overlong forms are rejected, and so are surrogates (U+D800–U+DFFF) and values above U+10FFFF. The test suite compares the checker with the browser's `TextDecoder` in fatal mode on 20,000 random byte strings, and the two agree on every one.

Two situations give text plus a note. If the result contains control characters, the status names the first one. `00000000 01000001` is `A` in UTF-16 big-endian, and here it decodes to U+0000 followed by `A`, which is almost never what you want. If the bytes start with `11101111 10111011 10111111` (a byte order mark), the tool keeps it as U+FEFF, while a plain `TextDecoder` removes it silently ([WHATWG Encoding, UTF-8 decode](https://encoding.spec.whatwg.org/#utf-8-decode)).

## The Same Conversion in Code

```javascript
const toBinary = (text) =>
  [...new TextEncoder().encode(text)].map((b) => b.toString(2).padStart(8, '0')).join(' ');
toBinary('Hi'); // "01001000 01101001"
```

```python
' '.join(f'{b:08b}' for b in 'Hi'.encode('utf-8'))  # '01001000 01101001'
```

## Limits

- **UTF-8 only.** The tool does not output UTF-16, Shift_JIS, GBK or EUC-KR. Bytes in those encodings usually fail the UTF-8 check. UTF-16 input can pass it and shows control characters with a warning.
- **Binary digits only.** Hex (`0x48`), octal and decimal are rejected. Separators are spaces, tabs, line breaks, commas and semicolons; a period or a dash is an error.
- **Binary → Text runs on click.** Text → Binary updates while you type. The other direction waits for the button or Ctrl+Enter, so half-typed bytes do not produce stray characters.
- **Unpaired surrogates.** A lone UTF-16 surrogate in the text cannot be encoded. It becomes U+FFFD (`11101111 10111111 10111101`), and the status says how many were replaced.
- **Size.** In Chromium on our test Mac, 87,500 characters of mixed Chinese, ASCII and emoji (175,000 bytes, about 1.57 million characters of spaced binary) convert in about 15 ms, and laying out the two boxes takes about 250 ms more. Decoding the same binary takes about 30 ms. The tool sets no size limit.
