<h2>生成内容包含</h2>
<ul>
  <li><strong>基础 SEO meta</strong>——<code>title</code>、<code>description</code>、<code>canonical</code>、<code>author</code>、<code>keywords</code>、<code>theme-color</code>、<code>viewport</code>、<code>robots</code>。</li>
  <li><strong>Open Graph</strong>——<code>og:type</code>、<code>og:title</code>、<code>og:description</code>、<code>og:url</code>、<code>og:site_name</code>、<code>og:image</code>（含 width / height / alt）、<code>og:locale</code>。</li>
  <li><strong>Twitter Card</strong>——<code>twitter:card</code>、<code>twitter:site</code>、<code>twitter:creator</code>、<code>twitter:title</code>、<code>twitter:description</code>、<code>twitter:image</code>。</li>
  <li><strong>Schema.org JSON-LD</strong>——最小的 <code>WebPage</code>、<code>Article</code>、<code>Product</code> 或 <code>Organization</code> 块（name / description / url / image）。</li>
</ul>

<h2>在微信里分享</h2>
<p>生成的 og 标签面向读取 Open Graph 的平台。在微信内置浏览器里自定义“分享给朋友”的卡片，微信开放文档《JS-SDK 使用说明》给出的步骤是：</p>
<ol>
  <li>登录微信公众平台，在“服务号设置”的“功能设置”里填写“JS接口安全域名”。文档写明：最多 5 个域名，不支持 IP 地址、端口号和短链域名，域名须通过 ICP 备案验证，新备案的域名 24 小时后才能配置。</li>
  <li>页面引入 <code>jweixin-1.6.0.js</code>，用 <code>wx.config</code> 注入签名配置。</li>
  <li>在 <code>wx.ready</code> 里调用 <code>wx.updateAppMessageShareData</code>，传入 <code>title</code>、<code>desc</code>、<code>link</code>、<code>imgUrl</code>；朋友圈用 <code>wx.updateTimelineShareData</code>。<code>link</code> 的域名或路径必须与 JS 接口安全域名一致。旧的 <code>wx.onMenuShareAppMessage</code> 等接口文档标注为即将废弃。</li>
</ol>
<p>本工具不生成这段 JS-SDK 代码，也不检查签名。上面测评文章的例子里，<code>og:title</code>、<code>og:description</code>、<code>og:image</code> 的值可以直接作为 title、desc、imgUrl 传进去，两边保持一致。</p>

<h2>限制</h2>
<ul>
  <li><strong>JSON-LD 只有最少的字段。</strong>只有 name、description、url、image，Article 另加 author。Google 的 <a href="https://developers.google.com/search/docs/appearance/structured-data/article">Article 文档</a>建议写 <code>headline</code>、<code>datePublished</code>；Product 要有 <code>offers</code>、<code>review</code> 或 <code>aggregateRating</code> 才可能出现产品富媒体结果。这些字段需要手工补，再用 Google 的富媒体搜索结果测试检查。</li>
  <li><strong>有的选项没有配套字段。</strong>Twitter 的 <code>player</code>、<code>app</code> 卡片需要 <code>twitter:player</code> 或 <code>twitter:app:&#42;</code> 标签，工具不生成；og:type 里的 <code>product</code> 不在 ogp.me 定义的类型中。工具也不生成 <code>article:published_time</code>、<code>og:image:type</code> 和 hreflang。</li>
  <li><strong>robots 总会输出。</strong><code>index, follow</code> 本来就是爬虫的默认行为，不改成 noindex 或 nofollow 时可以删掉这一行。</li>
  <li><strong>预览只是近似。</strong>各平台的卡片样式只是模拟。规范 URL 为空时，预览用站点名生成一个示例域名；站点名里没有英文字母或数字（比如“小王测评”）时显示 <code>example.com</code>。上线后请用平台自己的调试工具看真实卡片。</li>
  <li><strong>联网：</strong>标签内容留在浏览器里，但 Facebook、Twitter、Discord 预览会加载你填写的图片 URL，图片所在的服务器会看到这次请求。默认显示的 Google 预览不含图片。</li>
  <li><strong>Ctrl/⌘+L 只清文本。</strong>文本框（包括 og:locale 和主题色文本框）会被清空；URL、数字框、下拉选项和 viewport 复选框保留，head 按剩下的值重新生成。</li>
</ul>

<h2>把输出粘贴到哪里</h2>
<p>生成的 meta 区块放进 <code>&lt;head&gt;</code> 即可，建议靠前，放在 <code>&lt;meta charset&gt;</code> 之后、第三方脚本之前。爬虫不在意顺序，但把社交 meta 放在一起，以后检查起来方便。</p>
