<h2>What It Generates</h2>
<ul>
  <li><strong>Basic SEO meta</strong> — <code>title</code>, <code>description</code>, <code>canonical</code>, <code>author</code>, <code>keywords</code>, <code>theme-color</code>, <code>viewport</code>, <code>robots</code>.</li>
  <li><strong>Open Graph</strong> — <code>og:type</code>, <code>og:title</code>, <code>og:description</code>, <code>og:url</code>, <code>og:site_name</code>, <code>og:image</code> (with width / height / alt), <code>og:locale</code>.</li>
  <li><strong>Twitter Card</strong> — <code>twitter:card</code>, <code>twitter:site</code>, <code>twitter:creator</code>, <code>twitter:title</code>, <code>twitter:description</code>, <code>twitter:image</code>.</li>
  <li><strong>Schema.org JSON-LD</strong> — minimal <code>WebPage</code>, <code>Article</code>, <code>Product</code>, or <code>Organization</code> block (name / description / url / image).</li>
</ul>

<h2>Example: a Blog Post With JSON-LD</h2>
<p>Enter a title with quotes and an ampersand, a description with a <code>&lt;</code>, choose og:type <strong>article</strong> and Schema.org type <strong>Article</strong>, and fill in the author. To reproduce the block below, press Ctrl/⌘+L to clear the sample text, untick the viewport tag, and replace the two sample URLs:</p>

{/* mtg-check: {"title":"Build \"Notes\" & tips","description":"Five habits that keep a notes app useful (<10 minutes a day).","canonical":"https://example.com/blog/notes-tips/","siteName":"Example Blog","author":"Jane Doe","ogType":"article","ogLocale":"en_US","ogImage":"https://example.com/og/notes-tips.png","ogImageWidth":"1200","ogImageHeight":"630","schemaType":"Article"} */}
```html
<title>Build &quot;Notes&quot; &amp; tips</title>
<meta name="description" content="Five habits that keep a notes app useful (&lt;10 minutes a day).">
<link rel="canonical" href="https://example.com/blog/notes-tips/">
<meta name="author" content="Jane Doe">
<meta name="robots" content="index, follow">

<!-- Open Graph / Facebook -->
<meta property="og:type" content="article">
<meta property="og:title" content="Build &quot;Notes&quot; &amp; tips">
<meta property="og:description" content="Five habits that keep a notes app useful (&lt;10 minutes a day).">
<meta property="og:url" content="https://example.com/blog/notes-tips/">
<meta property="og:site_name" content="Example Blog">
<meta property="og:image" content="https://example.com/og/notes-tips.png">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:locale" content="en_US">

<!-- Twitter Card -->
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="Build &quot;Notes&quot; &amp; tips">
<meta name="twitter:description" content="Five habits that keep a notes app useful (&lt;10 minutes a day).">
<meta name="twitter:image" content="https://example.com/og/notes-tips.png">

<!-- Schema.org JSON-LD -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "name": "Build \"Notes\" & tips",
  "description": "Five habits that keep a notes app useful (\u003c10 minutes a day).",
  "url": "https://example.com/blog/notes-tips/",
  "image": "https://example.com/og/notes-tips.png",
  "author": {
    "@type": "Person",
    "name": "Jane Doe"
  }
}
</script>
```

<p>Quotes, ampersands and angle brackets are escaped in every attribute, so <code>og:title</code> becomes <code>{'content="Build &quot;Notes&quot; &amp; tips"'}</code>. The JSON-LD block gets <code>name</code>, <code>description</code>, <code>url</code>, <code>image</code> and an <code>author</code> object of type <code>Person</code>, and the <code>&lt;</code> in the description is written as <code>\u003c</code> so text such as a closing script tag cannot break the page you paste it into. A JSON parser reads <code>\u003c</code> back as <code>&lt;</code>.</p>

<h2>Limits</h2>
<ul>
  <li><strong>Minimal JSON-LD.</strong> The block has only name, description, url, image and (for Article) author. Google's Article guide recommends <code>headline</code> and <code>datePublished</code>, and a Product is eligible for product rich results only with <code>offers</code>, <code>review</code> or <code>aggregateRating</code>; add those by hand and check the page in Google's Rich Results Test.</li>
  <li><strong>Card and type options without their fields.</strong> The <code>player</code> and <code>app</code> card types need <code>twitter:player</code> or <code>twitter:app:&#42;</code> tags the tool does not write, and <code>product</code> is not one of the og:type values defined on ogp.me. There are no <code>article:published_time</code>, <code>og:image:type</code> or hreflang tags.</li>
  <li><strong>robots is always written.</strong> <code>index, follow</code> is what crawlers assume anyway; delete the line unless you switch to noindex or nofollow.</li>
  <li><strong>Counters are guides.</strong> The 60 and 160 character counters are rough limits; search results cut titles by pixel width, not a fixed character count.</li>
  <li><strong>Previews are approximations</strong> of each platform's card layout. When Canonical URL is empty, the preview invents a domain from the site name. To see the real card, share the URL or use the platform's own debugger after the page is live.</li>
  <li><strong>Network:</strong> your tags stay in the browser, but the Facebook, Twitter and Discord previews load the image URLs you enter, so those image hosts see a request from you. The Google preview, shown first, has no image.</li>
  <li><strong>Ctrl/⌘+L clears text only.</strong> Text fields (including og:locale and the theme color text) are emptied; URL and number fields, selections and the viewport checkbox stay, and the head is rebuilt from what is left.</li>
</ul>

<h2>Where to Paste the Output</h2>
<p>The generated block goes inside <code>&lt;head&gt;</code>, ideally near the top — after <code>&lt;meta charset&gt;</code> and before any third-party scripts. Order does not matter for crawlers, but keeping social meta together makes audits easy.</p>
