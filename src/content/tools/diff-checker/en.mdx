<h2>How to Use</h2>
<ol>
  <li>Paste your original text into the <strong>Original</strong> panel.</li>
  <li>Paste your modified text into the <strong>Modified</strong> panel.</li>
  <li>Click <strong>Compare</strong> to see the diff.</li>
  <li>Lines highlighted in <span style="color:#c0392b">red</span> were removed; lines in <span style="color:#057a55">green</span> were added.</li>
  <li>Use <strong>Swap</strong> to reverse the comparison direction.</li>
</ol>

<h2>About This Tool</h2>
<p>
  This diff checker compares line by line. It computes the longest common subsequence (LCS) of the two
  line lists: the lines kept in both texts are as many as possible, and everything else is a removal or an
  addition. <code>git diff</code> and GNU <code>diff</code> solve the same problem with Myers' algorithm
  (<a href="https://git-scm.com/docs/git-diff#Documentation/git-diff.txt---diff-algorithmpatienceminimalhistogrammyers" target="_blank" rel="noopener">git-diff <code>--diff-algorithm</code></a>),
  which needs far less memory. When several equally short diffs exist, the tools may choose different ones,
  so the order of <code>-</code> and <code>+</code> lines can differ from Git's output while describing the same change.
  It suits code, configuration files, log output, or any text where line-level changes matter.
</p>

## Reading the Output

The **Unified** view lists every line of both texts in one column. The first two number columns are the line numbers in the original and the modified text. A `-` marks a line that exists only in the original, a `+` marks a line that exists only in the modified text, and unmarked lines are the same in both. For example, comparing

```text
timeout = 30
retries = 3
```

with

```text
timeout = 60
retries = 3
```

shows `- timeout = 30`, then `+ timeout = 60`, then the unchanged `retries = 3`. The **Side-by-Side** view puts removed and added lines next to each other: in each block of changed lines, the first removed line sits next to the first added line, the second next to the second, and so on.

## Example: a Configuration Change

Original:

```yaml
server:
  port: 8080
  host: 0.0.0.0
logging:
  level: info
```

Modified:

```yaml
server:
  port: 9090
  host: 0.0.0.0
logging:
  level: debug
  file: app.log
```

The tool reports `+3 / -2` (three lines added, two removed) and shows, in the Unified view:

```diff
  server:
-   port: 8080
+   port: 9090
    host: 0.0.0.0
  logging:
-   level: info
+   level: debug
+   file: app.log
```

Each changed line appears as a removal followed by an addition. The new `file: app.log` line has no partner, so in the Side-by-Side view its left cell is empty.

## Example: Line Endings and Trailing Newlines

CR LF (Windows), LF and a lone CR all end a line, so the same text saved with different line endings compares as identical. A browser text box already turns pasted CR LF into LF (the HTML standard's "normalize newlines" step), and the tool splits text the same way. Other invisible differences still count: a trailing space, a tab instead of spaces, or a non-breaking space (U+00A0) instead of a normal one makes the line differ.

A final newline also counts. `a`, `b` compared with `a`, `b` plus a trailing line break gives `+1 / -0`: the extra line is an empty one at the end.

## Limits

- **Whole lines only.** A one-character change marks the whole line as removed and added; there is no word- or character-level highlighting.
- **No ignore options.** Whitespace and letter-case differences count as changes. `one`, `two` against `ONE`, `TWO` is two removals and two additions.
- **Side-by-Side pairs lines by position.** Within a block of changes, removed and added lines are paired in order, whether or not they are related. If a block removes three lines and adds one, the added line sits next to the first removed line and the other two have empty partners.
- **No context folding.** Unchanged lines are always shown in full, and the output has no `@@` hunk headers, so it is not a patch you can apply.
- **Large inputs are slow.** The algorithm keeps a table of every original line against every modified line. In a Node.js test, two 10,000-line files took about 1.3 seconds and 840 MB of memory, and larger inputs can stall the tab.

For large files, patches, or whitespace-insensitive comparison, use the command line: `diff -u a.txt b.txt` prints a unified patch, `diff -w` ignores whitespace, `git diff --no-index a.txt b.txt` works on files outside a repository, and `git diff --word-diff` highlights changed words.
