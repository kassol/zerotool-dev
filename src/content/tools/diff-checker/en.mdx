<h2>How to Use</h2>
<ol>
  <li>Paste your original text into the <strong>Original</strong> panel.</li>
  <li>Paste your modified text into the <strong>Modified</strong> panel.</li>
  <li>Click <strong>Compare</strong> to see the diff.</li>
  <li>Lines highlighted in <span style="color:#c0392b">red</span> were removed; lines in <span style="color:#057a55">green</span> were added.</li>
  <li>Use <strong>Swap</strong> to reverse the comparison direction.</li>
</ol>

<h2>About This Tool</h2>
<p>
  This diff checker performs line-by-line comparison using the Longest Common Subsequence (LCS) algorithm —
  the same principle used by <code>git diff</code> and Unix <code>diff</code>. It's ideal for comparing
  code, configuration files, log output, or any text where line-level changes matter.
</p>

## Reading the Output

The **Unified** view lists every line of both texts in one column. The first two number columns are the line numbers in the original and the modified text. A `-` marks a line that exists only in the original, a `+` marks a line that exists only in the modified text, and unmarked lines are the same in both. For example, comparing

```text
timeout = 30
retries = 3
```

with

```text
timeout = 60
retries = 3
```

shows `- timeout = 30`, then `+ timeout = 60`, then the unchanged `retries = 3`. The **Side-by-Side** view puts a removed line and the added line right after it on the same row.

## Limits

- **Whole lines only.** A one-character change marks the whole line as removed and added; there is no word- or character-level highlighting.
- **No ignore options.** Whitespace and letter-case differences count as changes.
- **No context folding.** Unchanged lines are always shown in full, and the output has no `@@` hunk headers, so it is not a patch you can apply.
- **Large inputs are slow.** The algorithm keeps a table of every original line against every modified line. In a Node.js test, two 10,000-line files took about 1.3 seconds and 840 MB of memory, and larger inputs can stall the tab.

For large files, patches, or whitespace-insensitive comparison, use the command line: `diff -u a.txt b.txt` prints a unified patch, `diff -w` ignores whitespace, `git diff --no-index a.txt b.txt` works on files outside a repository, and `git diff --word-diff` highlights changed words.
