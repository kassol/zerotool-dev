<h2>テキスト差分について</h2>
<p>差分チェックはコードレビュー、ドキュメントの変更追跡、設定ファイルの比較などで重宝します。gitのような版管理システムでも同様の機能が使われています。</p>

## 結果の読み方

「統合表示」は両方のテキストの全行を 1 列に並べます。先頭の 2 つの数字列は、元テキストと変更後テキストでの行番号です。`-` は元テキストにだけある行、`+` は変更後テキストにだけある行で、記号のない行は両方で同じです。たとえば

```text
timeout = 30
retries = 3
```

と

```text
timeout = 60
retries = 3
```

を比べると、`- timeout = 30`、`+ timeout = 60`、変わっていない `retries = 3` の順に表示されます。「並列表示」では、連続した変更の中で削除行と追加行を順番に組み合わせます（1 つ目の削除と 1 つ目の追加、2 つ目同士…、余った側は空欄）。CR LF（Windows）、LF、単独の CR はどれも改行として扱うので、改行コードだけが違うテキストは同一と判定されます。ブラウザのテキスト欄も貼り付けた CR LF を LF に変換します（HTML 標準の「改行の正規化」）。行末の空白、タブとスペース、ノーブレークスペース（U+00A0）などの見えない違いは変更として数えます。

## 制限事項

- **行単位の比較のみ。** 1 文字の変更でも行全体が削除と追加として表示され、単語・文字単位のハイライトはありません。
- **無視オプションはありません。** 空白や大文字小文字の違いも変更として扱います。
- **前後の行は折りたたみません。** 変わっていない行もすべて表示され、`@@` のハンク見出しもないため、パッチとしては使えません。
- **大きな入力は時間がかかりますが、ページは固まりません。** 比較は Web Worker で行い、「キャンセル」ですぐに止まります。全行の組み合わせ表は作らず、スコアを数行分だけ保持します。Node.js 22 で、10 行に 1 行を変えた 10,000 行どうしのファイルを比べると約 0.7 秒、メモリのピークは約 31 MB でした。以前の表を丸ごと作る実装では約 2.9 秒・946 MB でした。ブラウザーでは、バックグラウンドのスレッドの割り当て方によって Worker の時間が長くなることがあります。描画するのは 1 ページ 100 行だけです。

大きなファイル、パッチ、空白を無視した比較にはコマンドラインを使ってください。`diff -u a.txt b.txt` は unified 形式のパッチを出力し、`diff -w` は空白を無視し、`git diff --no-index a.txt b.txt` はリポジトリ外のファイルを比較でき、`git diff --word-diff` は変わった単語をハイライトします。
