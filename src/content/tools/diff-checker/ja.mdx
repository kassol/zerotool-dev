<h2>テキスト差分について</h2>
<p>
  2 つのテキストを行の並びとして比べ、両方に残る行が最も多くなるように差分を求めます。<code>git diff</code> や GNU <code>diff</code> は既定で Myers アルゴリズムを使い、同じ種類の最短の差分を求めます。同じ長さの差分が複数あるときは、- と + の並び順が Git と変わることがあります。設定ファイル、議事録、名簿、ログなど、行ごとに確認したいテキストに向いています。
</p>

## 結果の読み方

「統合表示」は両方のテキストの全行を 1 列に並べます。先頭の 2 つの数字列は、元テキストと変更後テキストでの行番号です。`-` は元テキストにだけある行、`+` は変更後テキストにだけある行で、記号のない行は両方で同じです。ステータス行には `+1 / -1` のように追加と削除の行数が出て、まったく同じときは「内容は同一です。」と表示されます。「並列表示」では、連続した変更の中で削除行と追加行を順番に組み合わせます（1 つ目の削除と 1 つ目の追加、2 つ目同士…、余った側は空欄）。

CR LF（Windows）、LF、単独の CR はどれも改行として扱うので、改行コードだけが違うテキストは同一と判定されます。ブラウザーのテキスト欄も貼り付けた CR LF を LF に変換します（HTML 標準の「改行の正規化」）。末尾に改行が 1 つ多いと、空の行が 1 行追加されたことになります。

## 例：名簿の表記ゆれ

架空の名簿を別の担当者が入力し直した例です。名前の間は半角スペースに、番地は全角の数字とハイフンになっています。

{/* dc-check */}
元テキスト：

```text
氏名：山田　花子
住所：大阪市北区梅田1-2-3
所属：営業部
```

変更後：

```text
氏名：山田 花子
住所：大阪市北区梅田１－２－３
所属：営業部
```

統合表示：

```text
- 氏名：山田　花子
- 住所：大阪市北区梅田1-2-3
+ 氏名：山田 花子
+ 住所：大阪市北区梅田１－２－３
  所属：営業部
```

ステータス行：

```text
+2 / -2 変更行のうち 1 組は空白か見えない文字だけが違います（行末の空白、タブ、U+00A0、U+3000、ゼロ幅文字）。
```

2 組のうち、空白だけが違うのは氏名の行です。住所の行は全角の「１」や「－」が別の文字として見えるので、組数には入りません。

## 濁点が分かれた文字

HFS+（Mac OS 拡張）のボリュームは、ファイル名を分解した形の Unicode で保存します（<a href="https://developer.apple.com/library/archive/qa/qa1173/_index.html" target="_blank" rel="noopener">Apple Technical Q&A QA1173</a>）。このとき「デ」は「テ」と結合用の濁点（U+3099）の 2 文字になります。そのボリュームから読み出したファイル名の一覧と、キーボードで入力した一覧を比べると、同じに見える行が変更として出ます。

{/* dc-check: {"a":"データ.csv\n報告書.xlsx","b":"テ\u3099ータ.csv\n報告書.xlsx","show":["status"]} */}
1 行目の「データ.csv」だけが分解形のとき、ステータス行は `+1 / -1 変更行のうち 1 組は Unicode の正規化形式（NFC / NFD）だけが違います。` です。差分としては残るので、比較の前にどちらかを NFC にそろえてください。

## 制限事項

- **行単位の比較のみ。** 1 文字の変更でも行全体が削除と追加として表示され、単語・文字単位のハイライトはありません。
- **無視オプションはありません。** 空白や大文字小文字の違いも変更として扱います。ステータス行は空白・見えない文字・正規化だけが違う行の組数を示すだけで、その行を隠しはしません。
- **並列表示は位置で組み合わせます。** 削除行と追加行の内容が関係しているかどうかは判定しません。
- **前後の行は折りたたみません。** 変わっていない行もすべて表示され、`@@` のハンク見出しもないため、パッチとしては使えません。
- **大きな入力は時間がかかりますが、ページは固まりません。** 比較は Web Worker で行い、「キャンセル」ですぐに止まります。全行の組み合わせ表は作らず、スコアを数行分だけ保持します。Node.js 22 で、10 行に 1 行を変えた 10,000 行どうしのファイルを比べると約 0.7 秒、メモリのピークは約 31 MB でした。以前の表を丸ごと作る実装では約 2.9 秒・946 MB でした。ブラウザーでは、バックグラウンドのスレッドの割り当て方によって Worker の時間が長くなることがあります。描画するのは 1 ページ 100 行だけです。

大きなファイル、パッチ、空白を無視した比較にはコマンドラインを使ってください。`diff -u a.txt b.txt` は unified 形式のパッチを出力し、`diff -w` は空白を無視し、`git diff --no-index a.txt b.txt` はリポジトリ外のファイルを比較でき、`git diff --word-diff` は変わった単語をハイライトします。
