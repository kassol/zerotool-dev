<h2>사용 방법</h2>
<ol>
  <li>왼쪽 패널에 JSON을 붙여넣거나 입력합니다. 실시간으로 유효성이 검사됩니다.</li>
  <li>필요에 따라 <strong>루트 클래스 이름</strong>을 설정합니다(기본값: <code>RootObject</code>).</li>
  <li>어노테이션 모드를 선택합니다: <strong>없음</strong>, <strong>Jackson</strong>, <strong>Gson</strong>, 또는 <strong>Lombok (@Data)</strong>.</li>
  <li><strong>Java 생성</strong>을 클릭하거나 실시간 변환 결과를 기다립니다.</li>
  <li><strong>복사</strong>를 클릭하여 출력을 클립보드에 복사합니다.</li>
</ol>

<h2>타입 매핑</h2>
<ul>
  <li><code>null</code> → <code>Object</code></li>
  <li>문자열 → <code>String</code></li>
  <li>정수 → <code>int</code> (int 범위를 넘는 값은 <code>long</code>)</li>
  <li>부동소수점 → <code>double</code></li>
  <li>불리언 → <code>boolean</code></li>
  <li>배열 → <code>List&lt;T&gt;</code></li>
  <li>중첩 객체 → 독립된 <code>public class</code></li>
</ul>

<h2>예시</h2>
<p>다음 JSON 입력 시:</p>
<pre><code>{`{"user": {"first_name": "Alice", "age": 30}, "tags": ["admin"]}`}</code></pre>
<p>Lombok 모드로 생성되는 출력:</p>
<pre><code>{`import java.util.List;\nimport lombok.Data;\n\n@Data\npublic class RootObject {\n    private User user;\n    private List<String> tags;\n}\n\n@Data\npublic class User {\n    private String firstName;\n    private int age;\n}`}</code></pre>

<h2>예시: 중첩 항목이 있는 주문 (Jackson 모드)</h2>

<p>입력:</p>

<pre><code>{`{"order_id": 9007, "customer": {"name": "Alice", "vip": true}, "items": [{"sku": "A-1", "qty": 2, "price": 9.5}, {"sku": "B-2", "qty": 1, "price": 20}], "note": null}`}</code></pre>

<p>출력(getter / setter 생략):</p>

<pre><code>{`import java.util.List;
import com.fasterxml.jackson.annotation.JsonProperty;

public class RootObject {
    @JsonProperty("order_id")
    private int orderId;
    private Customer customer;
    private List<ItemsItem> items;
    private Object note;
    // getters and setters omitted here
}

public class Customer {
    private String name;
    private boolean vip;
    // ...
}

public class ItemsItem {
    private String sku;
    private int qty;
    private double price;
    // ...
}`}</code></pre>

<p>이 출력은 한 파일로는 컴파일되지 않습니다. <code>{"public class"}</code>는 같은 이름의 파일에 있어야 하므로 <code>{"RootObject.java"}</code>, <code>{"Customer.java"}</code>, <code>{"ItemsItem.java"}</code>로 나눕니다. 나누면 「주석 없음」 모드 출력은 javac 21로 그대로 컴파일됩니다.</p>

<h2>생성 후 확인할 것</h2>

<ul>
  <li><code>{"price"}</code>는 <code>{"double"}</code>입니다. 첫 항목은 <code>{"9.5"}</code>, 둘째는 <code>{"20"}</code>이고 도구는 <code>{"int"}</code>와 <code>{"double"}</code>을 더 넓은 <code>{"double"}</code>로 합칩니다. 금액이면 <code>{"BigDecimal"}</code>로 바꾸세요.</li>
  <li>샘플의 <code>{"null"}</code>은 <code>{"Object"}</code>가 됩니다. 실제 타입으로 바꾸세요.</li>
  <li>int 범위를 넘는 정수(밀리초 타임스탬프 <code>{"1730000000000"}</code> 등)는 <code>{"long"}</code>이 됩니다. 샘플 값은 작아도 나중에 커질 ID는 직접 <code>{"long"}</code>으로 바꾸세요.</li>
  <li>Lombok 모드는 <code>{"@JsonProperty"}</code>를 붙이지 않아서 <code>{"order_id"}</code>가 <code>{"orderId"}</code>에 매핑되지 않습니다:</li>
</ul>

<pre><code>{`import java.util.List;
import lombok.Data;

@Data
public class RootObject {
    private int orderId;
    private Customer customer;
    private List<ItemsItem> items;
    private Object note;
}`}</code></pre>

<p>Lombok 모드에서는 <code>{"@JsonProperty"}</code>를 직접 붙이거나 Jackson에 <code>{"PropertyNamingStrategies.SNAKE_CASE"}</code>를 설정하세요. Gson 모드는 같은 목적으로 <code>{"@SerializedName"}</code>을 씁니다.</p>

<p>Jackson으로 읽기:</p>

<pre><code>{`ObjectMapper mapper = new ObjectMapper();
RootObject order = mapper.readValue(json, RootObject.class);`}</code></pre>

<p>Java 16 이상에서는 작은 불변 모델을 클래스 대신 record로 만들 수 있고, Jackson은 2.12부터 record를 읽습니다:</p>

<pre><code>{`public record Customer(String name, boolean vip) {}`}</code></pre>

<h2>예시: 같은 키의 다른 구조와 Java 이름이 될 수 없는 키 (Jackson 모드)</h2>

{/* jjp-check: {"json":"{\"billing\":{\"address\":{\"city\":\"Paris\"}},\"shipping\":{\"address\":{\"line1\":\"1 Main St\"}},\"class\":\"A\",\"2fa\":true,\"URL\":\"https://example.com\"}","mode":"jackson"} */}

<pre><code>{`{"billing": {"address": {"city": "Paris"}}, "shipping": {"address": {"line1": "1 Main St"}}, "class": "A", "2fa": true, "URL": "https://example.com"}`}</code></pre>

<p>출력(getter / setter 대부분 생략):</p>

<pre><code>{`import com.fasterxml.jackson.annotation.JsonProperty;

public class RootObject {
    private Billing billing;
    private Shipping shipping;
    @JsonProperty("class")
    private String classValue;
    @JsonProperty("2fa")
    private boolean t2fa;
    @JsonProperty("URL")
    private String uRL;

    @JsonProperty("URL")
    public String getURL() {
    // 나머지 getter / setter 생략
}

public class Address {
    private String city;
    // ...
}

public class ShippingAddress {
    private String line1;
    // ...
}`}</code></pre>

<ul>
  <li>두 <code>{"address"}</code>는 필드가 달라서 두 번째에 부모 이름을 앞에 붙입니다(<code>{"ShippingAddress"}</code>). 필드와 타입이 같은 객체는 클래스 하나를 함께 씁니다. 앞에 붙여도 이름이 겹치면 번호를 붙입니다.</li>
  <li>Java 키워드와 리터럴에는 <code>{"Value"}</code>를 붙이고(<code>{"class"}</code> → <code>{"classValue"}</code>), 숫자로 시작할 이름에는 <code>{"T"}</code>를 붙이고(<code>{"2fa"}</code> → <code>{"t2fa"}</code>), 같은 이름이 되는 키에는 번호를 붙입니다(<code>{"first-name"}</code>과 <code>{"first_name"}</code> → <code>{"firstName"}</code>과 <code>{"firstName2"}</code>). 원래 키는 어노테이션에 남습니다.</li>
  <li>Jackson은 <code>{"getURL()"}</code>을 <code>{"uRL"}</code>이 아니라 <code>{"url"}</code>로 읽습니다. getter와 setter에 어노테이션이 없으면 속성이 하나 더 생겨 <code>{"URL"}</code>을 읽을 때 오류가 납니다. Gson은 필드만 읽으므로 필요 없습니다.</li>
</ul>

<p>도구 테스트는 javac 21, Jackson 2.17.2, Gson 2.11.0으로 Jackson / Gson 출력을 각각 컴파일하고, 샘플을 읽었다가 다시 쓰면 원래 JSON과 같습니다. Lombok 1.18.34 출력도 모두 컴파일됩니다.</p>

<h2>제한</h2>
<ul>
  <li><strong>없음·Lombok 모드는 Java 이름만 있습니다.</strong> 이 두 모드에서 <code>{"classValue"}</code>·<code>{"t2fa"}</code>는 <code>{"class"}</code>·<code>{"2fa"}</code>에 매핑되지 않습니다. 키가 Java 이름이 될 수 없으면 Jackson이나 Gson 모드를 쓰세요.</li>
  <li><strong>Jackson은 빈 키를 쓸 수 없습니다.</strong> <code>{'@JsonProperty("")'}</code>는 '기본 이름을 쓴다'는 뜻이라 키 <code>{'""'}</code>에는 <code>{'@JsonAlias("")'}</code>와 주석을 출력합니다. Jackson은 <code>{'{"": 4}'}</code>를 읽지만 다시 쓰면 <code>{'{"t": 4}'}</code>가 됩니다. Gson 모드는 <code>{'@SerializedName("")'}</code>로 빈 키를 유지합니다.</li>
</ul>
