<h2>Markdownテーブルの構文</h2>

Markdownテーブルはヘッダー行・区切り行・データ行で構成され、パイプ文字（`|`）で列を区切ります。

```
| Name  | Age | City     |
| :---- | :-- | :------- |
| Alice | 30  | New York |
| Bob   | 25  | London   |
```

区切り行で配置を制御します：`:---` = 左揃え、`:---:` = 中央揃え、`---:` = 右揃え。

## 料金表を右揃えで作る

金額の列を右に寄せたい料金表です。桁区切りのカンマを含む金額は、引用符で囲んでおきます（例のプランと金額は架空のものです）。

{/* cm-check: {"align":"right"} */}

```csv
プラン,月額（円）,ストレージ
ライト,"1,980",100GB
スタンダード,"3,980",1TB
プレミアム,"7,980",
```

```markdown
| プラン    | 月額（円） | ストレージ |
| -------: | ------: | ------: |
| ライト    | 1,980 | 100GB |
| スタンダード | 3,980 | 1TB   |
| プレミアム  | 7,980 |       |
```

- 引用符は外れ、`1,980` のカンマはセルの中に残ります。引用符で囲まないと、`1` と `980` が別の列に分かれます。
- 配置は全列共通なので、プラン名も右揃えになります。金額の列だけ右揃えにしたいときは、コピー後に区切り行を `| :--- | ---: | :--- |` のように書き換えます。
- 最後の行はストレージが空なので、空のセルになります。
- 列の幅は文字数で数えて空白を足しています。全角文字は等幅フォントで 2 文字分の幅なので、ソース上では列がずれて見えますが、表示される表には影響しません。

## 英数字のデータと引用符

区切り文字を含む値や、セル内のパイプの扱いは次のとおりです（配置は「右揃え」）。

{/* cm-check: {"align":"right"} */}

```csv
product,price,units
Widget,9.99,150
"Gadget, large",24.99,42
Cmd|Ctrl+C,1,2
```

```markdown
| product       | price | units |
| --------------: | ------: | ------: |
| Widget        | 9.99  | 150   |
| Gadget, large | 24.99 | 42    |
| Cmd\|Ctrl+C   | 1     | 2     |
```

値の中の `|` は `\|` と書き出されるので、列の区切りになりません。区切り行はほかの行より幅が広くなりますが、Markdown のレンダラーは気にしないので表は正しく表示されます。

## 全角カンマに注意

IME をオンにしたまま入力すると、カンマが全角（，）になることがあります。全角カンマは区切り文字ではありません。

{/* cm-check: {"align":"left"} */}

```csv
品名，数量
ノート，3
```

```markdown
| 品名，数量 |
| :------ |
| ノート，3 |
```

行全体が 1 つのセルになりました。Excel や Google スプレッドシートからコピーしたテキストもタブ区切りなので、同じく 1 列になります。先に半角カンマへ置き換えるか、カンマ区切りの CSV として保存してから貼り付けてください。

## パイプと引用符

2 行目のパイプはすでにエスケープ済みで、3 行目はフィールドの途中にインチ記号があります。

{/* cm-check: {"align":"left"} */}

```csv
書き方,意味
a|b,a または b
a\|b,エスケープ済み
5" パイプ,インチ記号
```

```markdown
| 書き方    | 意味      |
| :------- | :-------- |
| a\|b   | a または b |
| a\|b   | エスケープ済み |
| 5" パイプ | インチ記号   |
```

ただの `|` にはバックスラッシュが付き、もともと `\|` だったものはそのままなので、どちらの行も `a|b` と表示され、セルは分かれません。`5` のあとの `"` はフィールドの先頭ではないので、文字としてセルに残ります。

## Qiita や Zenn で使う

GitHub と GitLab では、README、Issue、プルリクエスト、Wiki でこの表の書き方が表示されます（[GFM 仕様：表](https://github.github.com/gfm/#tables-extension-)）。[Qiita の Markdown 記法](https://qiita.com/Qiita/items/c686397e4a0f4f11683d)と [Zenn の Markdown 記法](https://zenn.dev/zenn/articles/markdown-guide)にも同じ形の表が載っています。表は拡張構文なので、拡張なしの CommonMark ではただのテキストになります。JSON が必要な場合は <a href="/ja/tools/csv-json/">CSV JSON 変換器</a>を使ってください。

## 制限事項

- **区切り文字は半角カンマだけ。** タブ・セミコロン・全角カンマは区切りになりません。地域によってはセミコロン区切りの CSV もあり、これも 1 列になります。
- **ヘッダーより長い行があれば列を足します。** 列数はいちばん長い行に合わせます。ヘッダーのない列は位置から `Column N`（4 列目なら `Column 4`）と名付け、ステータス行に表示します。項目が少ない行は空のセルで埋めます。
- **配置は全列共通。** 上の料金表のように、列ごとの配置はコピー後に区切り行で調整します。
- **セル内の改行はスペースになります。** Markdown の表のセルには改行を入れられません。HTML が使えるレンダラーなら手で `<br>` を書きます。
- **書式は変換しません。** セルの文字はそのまま出力されるので、`*` や `_` が Markdown の強調として解釈されることがあります。
- **パイプは [Markdown 表作成ツール](/ja/tools/markdown-table-generator/)と同じ規則でエスケープします。** 直前のバックスラッシュが偶数個のパイプにだけバックスラッシュを足すので、セルにもともと `\|` があれば `\|` のまま出力され、表示は `|` になります。バックスラッシュ自体を表示したいときは CSV に `\\|` と書きます。GitHub でも micromark 系のレンダラー（remark、MDX、Astro）でもセルは分かれません。
- **引用符として扱うのはフィールド先頭のダブルクォートだけです。** 引用符のないフィールドの途中にある `"` はただの文字で、`5" パイプ` はそのまま残ります。閉じられていない引用符があると変換を止め、引用符が始まる行をエラーで示します。
