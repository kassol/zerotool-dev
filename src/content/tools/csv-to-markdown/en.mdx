<h2>Markdown Table Syntax</h2>

A Markdown table consists of a header row, a separator row, and data rows. Pipe characters (`|`) delimit columns.

```
| Name  | Age | City     |
| :---- | :-- | :------- |
| Alice | 30  | New York |
| Bob   | 25  | London   |
```

The separator row controls alignment: `:---` = left, `:---:` = center, `---:` = right.

<h2>Tips</h2>
<ul>
  <li>Pipe characters (<code>|</code>) inside cell values are automatically escaped as <code>\|</code>.</li>
  <li>Newlines within quoted CSV fields are collapsed to a single space in the output.</li>
  <li>Use the <a href="/tools/csv-json/">CSV to JSON</a> tool if you need JSON output instead.</li>
</ul>

## Example

Input, with **Right** alignment:

```csv
product,price,units
Widget,9.99,150
"Gadget, large",24.99,42
Cmd|Ctrl+C,1,2
```

Output:

```markdown
| product       | price | units |
| --------------: | ------: | ------: |
| Widget        | 9.99  | 150   |
| Gadget, large | 24.99 | 42    |
| Cmd\|Ctrl+C   | 1     | 2     |
```

- The quotes around `"Gadget, large"` are removed and the comma stays in the cell.
- `|` inside a value is written as `\|`, so it does not start a new column.
- The separator row is wider than the other rows. Markdown renderers ignore this, and the table renders correctly.

## Example: Empty Cells and Center Alignment

With **Center** alignment, this input has a missing last field in two rows and a city name in Japanese:

```csv
id,city,score
1,東京,9.5
2,"Paris, FR",
3,Berlin
```

```markdown
| id  | city      | score |
| :---: | :---------: | :-----: |
| 1   | 東京        | 9.5   |
| 2   | Paris, FR |       |
| 3   | Berlin    |       |
```

Row 2 ends with a comma, so its score is an empty string; row 3 has only two fields and gets an empty cell. Both render as blank cells. The columns are padded by character count, so in a monospace editor the row with `東京` looks misaligned (each of those characters is two columns wide); the rendered table is not affected.

A file saved from Excel as "CSV UTF-8" starts with a byte order mark. The tool removes it, so the first header is `id`, not an invisible character followed by `id`. Line breaks inside quoted fields, including Windows `\r\n` ones, become single spaces.

## Where Markdown Tables Render

GitHub and GitLab render this table syntax in READMEs, issues, pull requests, and wikis ([GitHub Flavored Markdown spec, tables](https://github.github.com/gfm/#tables-extension-)). Tables are an extension: CommonMark without extensions shows the lines as plain text. Static site generators such as Docusaurus, MkDocs, and VitePress support GFM tables.

## Limits

- **Commas only.** Text copied from Excel or Google Sheets is tab-separated, and semicolon-separated CSV is common in some locales. Both become a single column. Save the sheet as CSV (comma) first.
- **Rows longer than the header get extra columns.** The table has as many columns as the longest row. Columns without a header are named `Column N` by position (`Column 4` for the fourth), and the status line lists them. A row with fewer fields gets empty cells.
- **One alignment for all columns.** To right-align only the number columns, edit the separator row after you copy, for example `| :--- | ---: | ---: |`.
- **Line breaks in cells become spaces.** Markdown table cells cannot contain line breaks; use `<br>` by hand if the renderer allows HTML.
- **No formatting.** Cell text is copied as is. Characters such as `*` and `_` can still be read as Markdown emphasis.
