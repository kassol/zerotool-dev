<h2>네이버 클라우드 플랫폼 서브넷의 사용 가능 IP 수</h2>
<p>
  이 도구는 전통적인 규칙대로 네트워크 주소와 브로드캐스트 주소 두 개만 뺍니다. 클라우드에서는 사업자가 몇 개를 더 예약합니다.
  <a href="https://guide.ncloud-docs.com/docs/vpc-subnetmanage-vpc">네이버 클라우드 플랫폼의 Subnet 관리 가이드</a>는
  "Network IP, Broadcast IP, 내부 관리를 위한 최초 5개의 IP는 가용 수량에서 제외되어, /24인 경우 249개, /25인 경우 121개, /26인 경우 57개의 IP 사용 가능"이라고 설명합니다.
  같은 크기를 이 도구에 넣으면 다음과 같습니다.
</p>
<table>
  <thead>
    <tr><th>입력</th><th>도구의 사용 가능한 호스트 수</th><th>NCP 가이드의 사용 가능 IP</th></tr>
  </thead>
  <tbody>
    {/* isc-page: {"in":"10.0.1.0/24","show":["hosts","broadcast"]} */}

    {/* isc-page: {"in":"10.0.1.0/25","show":["hosts","broadcast"]} */}

    {/* isc-page: {"in":"10.0.1.0/26","show":["hosts","broadcast"]} */}

<p>
  세 경우 모두 NCP 쪽이 정확히 5개 적습니다. 네트워크·브로드캐스트 주소는 양쪽이 같이 빼고, 내부 관리용 5개가 더 빠지기 때문입니다.
  서버 대수에 맞춰 서브넷 크기를 정할 때는 도구가 보여 주는 값에서 5를 빼서 계산하세요. 가이드는 어느 주소가 관리용인지는 적지 않으므로,
  정적 IP를 정할 때는 콘솔에서 실제로 할당 가능한 범위를 확인하는 편이 안전합니다.
</p>

<h2>VPN 대역 /22 확인하기</h2>
<p>
  사내 VPN 대역으로 <code>10.10.0.0/22</code>를 받았다면, 이 대역이 어디까지인지와 몇 대를 붙일 수 있는지를 바로 확인할 수 있습니다.
</p>
{/* isc-page: {"in":"10.10.2.15/22","show":["network","mask","broadcast","hosts","cidr"]} */}
<pre><code>{`입력: 10.10.2.15/22
네트워크 주소: 10.10.0.0
서브넷 마스크: 255.255.252.0
브로드캐스트 주소: 10.10.3.255
사용 가능한 호스트 수: 1,022
CIDR 표기법: 10.10.0.0/22`}</code></pre>
<p>
  <code>/22</code>는 <code>/24</code> 네 개(<code>10.10.0.x</code>부터 <code>10.10.3.x</code>까지)를 묶은 범위입니다. 대역 안의 아무 주소나 넣어도 같은 네트워크 주소와 정규화된 표기 <code>10.10.0.0/22</code>가 나옵니다.
  방화벽 규칙에 <code>10.10.2.15/22</code>처럼 호스트 비트가 남은 값을 넣으면 거부하는 장비가 많으므로, CIDR 표기법 칸의 값을 쓰세요.
</p>

<p>'복사'를 누르면 8개 항목이 '라벨: 값' 형태로 한 줄씩 클립보드에 들어갑니다.</p>
{/* isc-page: {"in":"10.0.1.77/26","copy":true} */}
```text
네트워크 주소: 10.0.1.64
브로드캐스트 주소: 10.0.1.127
서브넷 마스크: 255.255.255.192
와일드카드 마스크: 0.0.0.63
첫 번째 사용 가능한 호스트: 10.0.1.65
마지막 사용 가능한 호스트: 10.0.1.126
사용 가능한 호스트 수: 62
CIDR 표기법: 10.0.1.64/26
```

<h2>출력 필드 설명</h2>

| 필드 | 설명 |
|------|------|
| 네트워크 주소 | 서브넷의 첫 번째 주소 — 네트워크 자체를 식별 |
| 브로드캐스트 주소 | 마지막 주소 — 서브넷의 모든 호스트에 전송. /31과 /32에는 없어 「없음」으로 표시 |
| 서브넷 마스크 | 프리픽스의 점으로 구분된 십진수 형식(예: 255.255.255.0) |
| 와일드카드 마스크 | 서브넷 마스크의 비트 반전 |
| 첫 번째 사용 가능한 호스트 | 네트워크 주소 + 1. /31과 /32에서는 네트워크 주소 자체 |
| 마지막 사용 가능한 호스트 | 브로드캐스트 주소 − 1. /31과 /32에서는 블록의 마지막 주소 |
| 사용 가능한 호스트 수 | 총 주소 수 − 2(네트워크 + 브로드캐스트). /31은 2, /32는 1 |
| CIDR 표기법 | 표준 네트워크/프리픽스 형식 |

<h2>제한 사항</h2>
<ul>
  <li>주소는 0–255 사이의 십진수 4개여야 하고 앞에 0을 붙일 수 없습니다. <code>10.0.0.01</code>, <code>0x0a.0.0.1</code>, <code>10.1</code>은 "유효하지 않은 IPv4 주소입니다. 0–255 숫자 4개를 점으로 구분하고 앞에 0을 붙이지 마세요(예: 10.0.0.1)."라고 표시합니다.</li>
  <li>프리픽스는 0–32 정수입니다. <code>/33</code>, <code>/24x</code>, <code>/024</code>는 "CIDR 프리픽스는 0–32 사이의 정수여야 합니다(예: /24)."라고 표시합니다. 슬래시 뒤에 점 표기 마스크는 쓸 수 없으므로 <code>/255.255.252.0</code>은 <code>/22</code>로 바꿔 입력하세요.</li>
  <li>IPv4만 지원하며 IPv6 주소는 유효하지 않은 것으로 처리합니다.</li>
  <li>한 번에 서브넷 하나만 계산합니다. 블록 분할, 전체 주소 목록, 두 범위의 겹침 확인은 하지 않습니다.</li>
  <li>사용 가능한 호스트 수는 네트워크·브로드캐스트 주소만 뺀 값입니다(/31은 2, /32는 1, RFC 3021). 클라우드 사업자가 따로 예약하는 주소는 위의 NCP처럼 직접 빼야 합니다.</li>
</ul>
