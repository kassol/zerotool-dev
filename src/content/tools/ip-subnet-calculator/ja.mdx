<h2>基本情報技術者試験の過去問をツールで確かめる</h2>
<p>
  IPA が公開している<a href="https://www.ipa.go.jp/shiken/mondai-kaiotu/2016h28.html">平成28年度秋期 基本情報技術者試験</a>の午前 問33 は、同じサブネットに属するかを問う問題です。問題冊子の題文は次のとおりです。
</p>
<blockquote>
  <p>2 台の PC に IPv4 アドレスを割り振りたい。サブネットマスクが 255.255.255.240 のとき，両 PC の IPv4 アドレスが同一サブネットに所属する組合せはどれか。</p>
  <p>ア 192.168.1.14 と 192.168.1.17<br />イ 192.168.1.17 と 192.168.1.29<br />ウ 192.168.1.29 と 192.168.1.33<br />エ 192.168.1.33 と 192.168.1.49</p>
</blockquote>
<p>
  255.255.255.240 は <code>/28</code> です（スラッシュの後ろにマスクは書けないので、プレフィックスに直して入力します）。選択肢に出てくる 5 つのアドレスを <code>/28</code> で入れると、ネットワークアドレスは次のようになります。
</p>
<table>
  <thead>
    <tr><th>入力</th><th>ネットワークアドレス</th><th>ブロードキャストアドレス</th></tr>
  </thead>
  <tbody>
    {/* isc-page: {"in":"192.168.1.14/28","show":["network","broadcast"]} */}
    <tr><td><code>192.168.1.14/28</code></td><td><code>192.168.1.0</code></td><td><code>192.168.1.15</code></td></tr>
    {/* isc-page: {"in":"192.168.1.17/28","show":["network","broadcast"]} */}
    <tr><td><code>192.168.1.17/28</code></td><td><code>192.168.1.16</code></td><td><code>192.168.1.31</code></td></tr>
    {/* isc-page: {"in":"192.168.1.29/28","show":["network","broadcast"]} */}
    <tr><td><code>192.168.1.29/28</code></td><td><code>192.168.1.16</code></td><td><code>192.168.1.31</code></td></tr>

<p>
  ネットワークアドレスが一致するのは 192.168.1.17 と 192.168.1.29 の組だけなので、答えはイです。IPA の
  <a href="https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000g6fw-att/2016h28a_fe_am_ans.pdf">解答例</a>でも問33 の正解はイです。
  手計算なら、第 4 オクテットのマスク 240 から刻み幅は 256 − 240 = 16 で、サブネットは .0、.16、.32、.48 と 16 ごとに区切られます。17 と 29 はどちらも 16〜31 の範囲に入ります。
</p>

<h2>全角で入力しても計算できる</h2>
<p>
  日本語入力がオンのままだと、数字やピリオドが全角になったり、ピリオドのつもりが句点「。」になったりします。ツールはこれらを半角として読んでから検査するので、そのままでも結果が出ます。入力欄の文字は書き換えません。
</p>
{/* isc-page: {"in":"１９２．１６８．１．２９／２８","show":["network","cidr"]} */}
<pre><code>{`入力: １９２．１６８．１．２９／２８
ネットワークアドレス: 192.168.1.16
CIDR表記: 192.168.1.16/28`}</code></pre>
<p>
  ファイアウォールやクラウドの設定画面に貼るときは、全角が残った入力欄ではなく、半角で表示された結果をコピーしてください。読点「、」や全角カンマは使えず、「無効なIPv4アドレスです。」と表示します。
</p>

<h2>コピーした結果の形式</h2>
<p>「コピー」を押すと、8 項目が「ラベル: 値」の形で 1 行ずつクリップボードに入ります。上の過去問のアドレスなら次のとおりです。</p>
{/* isc-page: {"in":"192.168.1.17/28","copy":true} */}
```text
ネットワークアドレス: 192.168.1.16
ブロードキャストアドレス: 192.168.1.31
サブネットマスク: 255.255.255.240
ワイルドカードマスク: 0.0.0.15
最初の使用可能ホスト: 192.168.1.17
最後の使用可能ホスト: 192.168.1.30
使用可能ホスト数: 14
CIDR表記: 192.168.1.16/28
```

<h2>出力フィールドの説明</h2>

| フィールド | 説明 |
|-----------|------|
| ネットワークアドレス | サブネットの最初のアドレス（ネットワーク自体を識別） |
| ブロードキャストアドレス | 最後のアドレス（サブネット内の全ホストに送信）。/31 と /32 にはないため「なし」と表示 |
| サブネットマスク | プレフィックスのドット区切り10進数表現（例: 255.255.255.0） |
| ワイルドカードマスク | サブネットマスクのビット反転 |
| 最初の使用可能ホスト | ネットワークアドレス + 1。/31 と /32 ではネットワークアドレスそのもの |
| 最後の使用可能ホスト | ブロードキャストアドレス − 1。/31 と /32 ではブロックの最後のアドレス |
| 使用可能ホスト数 | 総アドレス数 − 2（ネットワーク + ブロードキャスト）。/31 は 2、/32 は 1 |
| CIDR表記 | 標準的なネットワーク/プレフィックス形式 |

<h2>制限事項</h2>
<ul>
  <li>アドレスは 0〜255 の 10 進数 4 つで、先頭に 0 は付けられません。<code>10.0.0.01</code>、<code>0x0a.0.0.1</code>、<code>10.1</code> は「無効なIPv4アドレスです。0〜255 の数字 4 つをドットで区切り、先頭に 0 を付けずに入力してください（例: 10.0.0.1）。」と表示します。</li>
  <li>プレフィックスは 0〜32 の整数です。<code>/33</code>、<code>/24x</code>、<code>/024</code> は「CIDRプレフィックスは 0〜32 の整数で指定してください（例: /24）。」と表示します。スラッシュの後ろにドット区切りのマスクは書けないので、<code>/255.255.255.240</code> は <code>/28</code> に直して入力します。</li>
  <li>IPv4 のみ対応し、IPv6 アドレスは無効として扱います。</li>
  <li>一度に計算するのは 1 つのサブネットです。ブロックの分割、全アドレスの一覧、2 つの範囲の重なりの確認はできません。</li>
  <li>使用可能ホスト数はネットワークアドレスとブロードキャストアドレスだけを引いた値です。/31 では 2（RFC 3021）、/32 では 1 を返します。クラウドの VPC などで事業者が別に予約するアドレスは差し引いていません。</li>
</ul>
