<h2>例子：把一个 /24 分成 4 个 /26</h2>
<p>
  办公室的 <code>192.168.10.0/24</code> 要拆给四个部门，每个部门一个 /26。工具一次只算一个子网，依次输入四个网段的起始地址（或网段里任意一个地址）即可：
</p>
<table>
  <thead>
    <tr><th>输入</th><th>网络地址</th><th>广播地址</th><th>可用范围</th><th>可用主机数</th></tr>
  </thead>
  <tbody>
    {/* isc-page: {"in":"192.168.10.0/26","show":["network","broadcast","first","last","hosts"]} */}
    <tr><td><code>192.168.10.0/26</code></td><td><code>192.168.10.0</code></td><td><code>192.168.10.63</code></td><td><code>192.168.10.1</code> – <code>192.168.10.62</code></td><td><code>62</code></td></tr>
    {/* isc-page: {"in":"192.168.10.64/26","show":["network","broadcast","first","last"]} */}
    <tr><td><code>192.168.10.64/26</code></td><td><code>192.168.10.64</code></td><td><code>192.168.10.127</code></td><td><code>192.168.10.65</code> – <code>192.168.10.126</code></td><td>62</td></tr>
    {/* isc-page: {"in":"192.168.10.128/26","show":["network","broadcast","first","last"]} */}
    <tr><td><code>192.168.10.128/26</code></td><td><code>192.168.10.128</code></td><td><code>192.168.10.191</code></td><td><code>192.168.10.129</code> – <code>192.168.10.190</code></td><td>62</td></tr>
    {/* isc-page: {"in":"192.168.10.200/26","show":["network","broadcast","first","last","cidr"]} */}
    <tr><td><code>192.168.10.200/26</code></td><td><code>192.168.10.192</code></td><td><code>192.168.10.255</code></td><td><code>192.168.10.193</code> – <code>192.168.10.254</code></td><td>62</td></tr>
  </tbody>
</table>
<p>
  最后一行输入的是网段中间的 <code>192.168.10.200</code>，工具清掉主机位后给出规范写法 <code>192.168.10.192/26</code>。
  每段 64 个地址，扣掉网络地址和广播地址后剩 62 个。四段首尾相接，正好覆盖整个 /24。
</p>

<h2>阿里云交换机的可用地址比工具少</h2>
<p>
  工具按传统规则只扣网络地址和广播地址。阿里云专有网络的说明《<a href="https://help.aliyun.com/zh/vpc/vpc-and-vswitch">专有网络与交换机</a>》写明：
  “针对 IPv4，每个交换机的第 1 个和最后 3 个 IP 地址为系统保留地址。”以 <code>172.16.1.0/24</code> 的交换机为例：
</p>
{/* isc-page: {"in":"172.16.1.0/24","show":["network","broadcast","first","last","hosts"]} */}
<pre><code>{`网络地址: 172.16.1.0
广播地址: 172.16.1.255
第一个可用主机: 172.16.1.1
最后一个可用主机: 172.16.1.254
可用主机数: 254`}</code></pre>
<p>
  阿里云保留的是 <code>172.16.1.0</code>、<code>172.16.1.253</code>、<code>172.16.1.254</code>、<code>172.16.1.255</code> 这 4 个，
  所以能分配给 ECS 的是 <code>172.16.1.1</code> 到 <code>172.16.1.252</code>，共 252 个，比工具的 254 少 2 个。
  工具显示的「最后一个可用主机」<code>172.16.1.254</code> 在阿里云上恰好是保留地址，规划静态 IP 时要避开。按这个规则，/26 的交换机能用 60 个，/28 能用 12 个。
</p>

<h2>中文输入法下输入地址</h2>
<p>
  开着中文输入法敲点号，常会打出句号「。」；全角模式下数字和斜杠也会变成全角。工具先把这些字符按半角读取，再按点分十进制规则检查，输入框里的文字保持原样：
</p>
{/* isc-page: {"in":"192。168。10。77/26","show":["network","cidr"]} */}
<pre><code>{`输入: 192。168。10。77/26
网络地址: 192.168.10.64
CIDR 表示法: 192.168.10.64/26`}</code></pre>
<p>
  其他标点（顿号、中文逗号）不会转换，会提示「无效的 IPv4 地址」。复制结果或填进防火墙、云控制台时，请使用工具给出的半角结果。
</p>

<h2>复制出来的结果</h2>
<p>「复制」把 8 项结果按「标签: 值」逐行写入剪贴板。/31 没有广播地址时，会写出原因：</p>
{/* isc-page: {"in":"10.0.0.9/31","copy":true} */}
```text
网络地址: 10.0.0.8
广播地址: 无（/31 点对点链路，RFC 3021）
子网掩码: 255.255.255.254
通配符掩码: 0.0.0.1
第一个可用主机: 10.0.0.8
最后一个可用主机: 10.0.0.9
可用主机数: 2
CIDR 表示法: 10.0.0.8/31
```

<h2>输出字段说明</h2>

| 字段 | 说明 |
|------|------|
| 网络地址 | 子网第一个地址，用于标识网络本身 |
| 广播地址 | 最后一个地址，发送给子网内所有主机；/31 与 /32 没有广播地址，显示「无」 |
| 子网掩码 | 前缀的点分十进制形式（如 255.255.255.0） |
| 通配符掩码 | 子网掩码的按位取反 |
| 第一个可用主机 | 网络地址 + 1；/31 与 /32 为网络地址本身 |
| 最后一个可用主机 | 广播地址 − 1；/31 与 /32 为网段最后一个地址 |
| 可用主机数 | 总地址数减 2（网络 + 广播）；/31 为 2，/32 为 1 |
| CIDR 表示法 | 规范的网络/前缀形式 |

<h2>限制</h2>
<ul>
  <li>地址必须是 4 个 0–255 的十进制数，不能有前导零。<code>10.0.0.01</code>、<code>0x0a.0.0.1</code>、<code>10.1</code> 会提示「无效的 IPv4 地址。请用点分隔的 4 个 0–255 的数字，不带前导零（如 10.0.0.1）。」</li>
  <li>前缀必须是 0–32 的整数。<code>/33</code>、<code>/24x</code>、<code>/024</code> 会提示「CIDR 前缀必须是 0–32 的整数（如 /24）。」斜杠后不能写点分掩码，<code>/255.255.255.0</code> 要改成 <code>/24</code>。</li>
  <li>只支持 IPv4，IPv6 地址按无效处理。</li>
  <li>一次只算一个子网：不会自动拆分网段、列出全部地址，也不检查两个网段是否重叠。</li>
  <li>可用主机数按传统规则只扣网络地址和广播地址，云平台额外保留的地址（如上文的阿里云交换机）需要自己再减。</li>
</ul>
