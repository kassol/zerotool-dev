<p>
  The first row is the usual question when you see an address in a log: <code>192.168.1.77</code> with a /26 mask belongs to the
  block that starts at <code>.64</code>, so <code>192.168.1.130</code> is in a different subnet and traffic between them goes through
  a router. The CIDR Notation field shows the corrected form, <code>192.168.1.64/26</code>, which is what most firewall and cloud
  consoles expect; many of them reject <code>192.168.1.77/26</code> because host bits are set.
</p>

<p>
  The second row is a typical cloud subnet. The calculator counts 4,094 usable hosts, but AWS reserves the first four and the last
  address of every VPC subnet, and Azure reserves five as well, so only 4,091 can be assigned there. Subtract those yourself when you
  size a cloud subnet.
</p>
<p>
  For /31 and /32 the calculator does not subtract a network and a broadcast address. A /31 is a point-to-point link with two usable
  addresses (RFC 3021), and a /32 is a single host, as used in route tables and allow-lists. Neither has a broadcast address, so the
  Broadcast Address field says None and gives the reason:
</p>

<h2>Output Fields Explained</h2>

| Field | Description |
|-------|-------------|
| Network Address | First address of the subnet — identifies the network itself |
| Broadcast Address | Last address — sent to all hosts in the subnet; none for /31 and /32 |
| Subnet Mask | Dotted-decimal form of the prefix (e.g. 255.255.255.0) |
| Wildcard Mask | Bitwise inverse of the subnet mask |
| First Usable Host | Network address + 1; the network address itself for /31 and /32 |
| Last Usable Host | Broadcast address − 1; the last address for /31 and /32 |
| Usable Hosts | Total addresses minus 2 (network + broadcast); 2 for /31 and 1 for /32 |
| CIDR Notation | Canonical network/prefix form |

<h2>Errors and Limitations</h2>
<ul>
  <li>Addresses must be four decimal numbers from 0 to 255 with no leading zeros. <code>10.0.0.01</code>, <code>0x0a.0.0.1</code> and
  <code>10.1</code> show “Invalid IPv4 address. Use four numbers from 0 to 255 separated by dots, with no leading zeros (e.g. 10.0.0.1).”
  This matches <code>inet_pton</code> and Node's <code>net.isIPv4</code>; it avoids guessing whether <code>010</code> means 10 or octal 8.</li>
  <li>Before that check, full-width digits, dots and slash (<code>１９２．１６８．１．７７／２６</code>) and the ideographic full stop (<code>192。168。1。77/26</code>) that an IME may type are read as ASCII. The text in the field is left as you typed it.</li>
  <li>The prefix must be a whole number from 0 to 32. <code>/33</code>, <code>/24x</code> and <code>/024</code> show “The CIDR prefix must be a whole number from 0 to 32 (e.g. /24).”</li>
  <li>Dotted masks are not accepted after the slash. Type <code>/26</code>, or look up the prefix for a mask in the table above.</li>
  <li>IPv4 only. IPv6 addresses are rejected as invalid.</li>
  <li>One subnet at a time: the tool does not split a block into smaller subnets, list every address, or check whether two ranges overlap.</li>
</ul>
