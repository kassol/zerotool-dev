<h2>示例：百度帮助中心“屏蔽百度、放行图片搜索”的写法怎么读</h2>
<p>百度帮助中心的「<a href="https://help.baidu.com/question?prod_id=99&class=476&id=2996">Baiduspider 常见问题解答</a>」列出了各产品使用的 user-agent：网页搜索为 <code>Baiduspider</code>，图片搜索为 <code>Baiduspider-image</code>，并给出“禁止所有来自百度的抓取，但允许图片搜索抓取 /image/ 目录”的写法。在工具里删除初始块，添加两个块，分别用“自定义...”填 <code>Baiduspider</code>（禁止 <code>/</code>）和 <code>Baiduspider-image</code>（允许 <code>/image/</code>），输出为：</p>

{/* rtg-tool: {"blocks":[{"custom":"Baiduspider","rules":[["Disallow","/"]]},{"custom":"Baiduspider-image","rules":[["Allow","/image/"]]}],"rfc":[{"ua":"Baiduspider","paths":[["/news/",false]]},{"ua":"Baiduspider-image","paths":[["/image/logo.png",true],["/news/",true]]},{"ua":"Googlebot","paths":[["/news/",true]]}]} */}

```text
User-agent: Baiduspider
Disallow: /

User-agent: Baiduspider-image
Allow: /image/
```

<p>按 <a href="https://www.rfc-editor.org/rfc/rfc9309">RFC 9309</a> 的规则读这个文件：爬虫按名字（不区分大小写）找到与自己匹配的组，只遵守这一组，组内没有匹配的规则时，网址视为允许。所以 <code>Baiduspider</code> 不能抓 <code>/news/</code>。<code>Baiduspider-image</code> 读自己的组，<code>/image/logo.png</code> 可以抓，而 <code>/news/</code> 没有规则匹配，同样是允许。文件里没有 <code>&#42;</code> 组，Googlebot 等其他爬虫不受任何限制。百度没有公开图片爬虫的解析代码，以上是按标准得出的读法。想让图片爬虫只抓 <code>/image/</code>，在它的组里再加一条“禁止 <code>/</code>”：</p>

{/* rtg-tool: {"blocks":[{"custom":"Baiduspider","rules":[["Disallow","/"]]},{"custom":"Baiduspider-image","rules":[["Disallow","/"],["Allow","/image/"]]}],"rfc":[{"ua":"Baiduspider-image","paths":[["/image/logo.png",true],["/news/",false]]}]} */}

```text
User-agent: Baiduspider
Disallow: /

User-agent: Baiduspider-image
Disallow: /
Allow: /image/
```

<p><code>Allow: /image/</code> 比 <code>Disallow: /</code> 长，RFC 9309 规定匹配字节最多的规则生效，与两行的先后无关，因此 <code>/image/</code> 下的文件仍可抓取，其余路径被禁止。同一页帮助还写明 <code>Baiduspider-cpro</code> 与 <code>Baiduspider-ads</code> 不遵守 robots 协议，以及已经建立的索引可能需要数月才会清除。</p>

<h2>示例：Sitemap 要写完整网址</h2>
<p>工具不检查 Sitemap 地址，填 <code>/sitemap.xml</code> 也会原样写出：</p>

{/* rtg-tool: {"blocks":[{"ua":"*","rules":[["Disallow","/search/"]]}],"sitemap":"/sitemap.xml","rfc":[{"ua":"Baiduspider","paths":[["/search/?q=%E6%89%8B%E6%9C%BA",false],["/product/1001.html",true]]}]} */}

```text
User-agent: *
Disallow: /search/

Sitemap: /sitemap.xml
```

<p><a href="https://www.sitemaps.org/protocol.html#submit_robots">Sitemaps 协议</a>要求在 robots.txt 里写网站地图的完整 URL，所以要填成 <code>https://www.example.cn/sitemap.xml</code> 这样带协议和主机名的地址。上面这个文件里，站内搜索结果 <code>/search/?q=手机</code> 被 <code>Disallow: /search/</code> 禁止，商品页 <code>/product/1001.html</code> 不受影响。</p>

{/* rtg-tool: {"blocks":[{"ua":"*","rules":[["Disallow","/search/"]]}],"sitemap":"https://www.example.cn/sitemap.xml"} */}

```text
User-agent: *
Disallow: /search/

Sitemap: https://www.example.cn/sitemap.xml
```

<p>写好后可以用百度搜索资源平台的 <a href="https://ziyuan.baidu.com/robots/index">Robots 工具</a>检测。该页面说明工具支持 48k 以内的文件内容，目录最长不超过 250 个字符。</p>

<h2>常见 robots.txt 配置</h2>
<ul>
  <li><strong>屏蔽所有爬虫：</strong><code>User-agent: &#42;</code> + <code>Disallow: /</code></li>
  <li><strong>允许所有爬虫：</strong><code>User-agent: &#42;</code> + <code>Disallow:</code>（留空）。工具里一个块没有任何规则时，就会写出这样的空 <code>Disallow:</code>。</li>
  <li><strong>屏蔽特定目录：</strong><code>Disallow: /admin/</code></li>
  <li><strong>只允许某一个爬虫：</strong>先用 <code>&#42;</code> 块禁止 <code>/</code>，再为该爬虫单独加一个不含规则的块</li>
</ul>

<h2>工具不做的事与 robots.txt 的边界</h2>
<ul>
  <li><strong>不校验：</strong>路径去掉两端空白后原样写出。RFC 9309 的路径以 <code>/</code> 开头，<code>admin/</code> 这样的值不是有效规则；空路径写成空规则。</li>
  <li><strong>只有一行 Sitemap：</strong>有多个网站地图时，复制这一行手动补上。不生成 <code>Crawl-delay</code> 等非标准指令。</li>
  <li><strong>通配符：</strong><code>&#42;</code> 和 <code>$</code> 属于 RFC 9309，可以直接写进路径，例如 <code>Disallow: /&#42;?sessionid=</code>，工具不检查写法。</li>
  <li><strong>禁止抓取不等于从搜索结果删除：</strong>其他页面链接到被禁止的网址时，它仍可能以无摘要的形式出现在结果中。要让页面不出现在结果里，应允许抓取并在页面上发送 <code>noindex</code>，可以用 <a href="/zh/tools/meta-tag-generator/">Meta 标签生成器</a>写出。</li>
  <li><strong>大小与错误：</strong>RFC 9309 要求爬虫至少解析文件的前 500 KiB。robots.txt 返回 4xx 时爬虫可以抓取全部内容；返回 5xx 或无法访问时，应视为全部禁止。</li>
  <li><strong>每个主机各一份：</strong>文件上传到网站根目录，使其可以通过 <code>https://你的域名/robots.txt</code> 访问。<code>example.cn</code> 上的规则管不到 <code>m.example.cn</code>，移动站或子域名要各放一份。</li>
</ul>
