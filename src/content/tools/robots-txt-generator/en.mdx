<h2>Example: a Typical Site File</h2>
<p>Keep the <code>&#42;</code> block, change its rule to Disallow <code>/admin/</code> and add Allow <code>/admin/public/</code>; add a second block with the custom name <code>GPTBot</code> and Disallow <code>/</code>; enter the sitemap URL. The output is:</p>

{/* rtg-tool: {"blocks":[{"ua":"*","rules":[["Disallow","/admin/"],["Allow","/admin/public/"]]},{"custom":"GPTBot","rules":[["Disallow","/"]]}],"sitemap":"https://example.com/sitemap.xml","rfc":[{"ua":"Googlebot","paths":[["/admin/public/help",true],["/admin/users",false]]},{"ua":"GPTBot","paths":[["/",false],["/blog/",false]]}]} */}

```text
User-agent: *
Disallow: /admin/
Allow: /admin/public/

User-agent: GPTBot
Disallow: /

Sitemap: https://example.com/sitemap.xml
```

<p>Under <a href="https://www.rfc-editor.org/rfc/rfc9309">RFC 9309</a> the longest matching path wins, whatever the line order, and when an Allow and a Disallow match with the same length the Allow should win. So <code>/admin/public/help</code> may be crawled, <code>/admin/users</code> may not, and GPTBot may fetch nothing. Scrapy's Protego parser returned exactly that. Python 3.12's <code>urllib.robotparser</code> did not: it applies the first matching line in file order and reported <code>/admin/public/help</code> as blocked. CPython rewrote the module for RFC 9309 in Python 3.13.14 and 3.14.5 (<a href="https://github.com/python/cpython/issues/138907">gh-138907</a>), and Python 3.14.7 allows that URL. If one of your own scripts uses it on an older Python, put the Allow line above the Disallow line; RFC-compliant crawlers read both orders the same way.</p>

<h2>Example: Allow One Crawler Only</h2>

{/* rtg-tool: {"blocks":[{"ua":"*","rules":[["Disallow","/"]]},{"ua":"Googlebot"}],"rfc":[{"ua":"Googlebot","paths":[["/products/",true]]},{"ua":"Bingbot","paths":[["/products/",false]]}]} */}

```text
User-agent: *
Disallow: /

User-agent: Googlebot
Disallow:
```

<p>Build it with two blocks: the default <code>&#42;</code> block with Disallow <code>/</code>, and a Googlebot block with no rules. A block without rules gets an empty <code>Disallow:</code> line, which allows everything. Googlebot reads only its own group, so the <code>&#42;</code> rule does not apply to it.</p>

<h2>Limits and Things robots.txt Does Not Do</h2>
<ul>
  <li><strong>No validation.</strong> Paths are trimmed and otherwise copied as typed. RFC 9309 paths start with <code>/</code>; a value such as <code>admin/</code> is not a valid rule. Empty paths are written as empty rules.</li>
  <li><strong>One Sitemap line.</strong> For several sitemaps, copy the line and add the others by hand. <code>Crawl-delay</code> and other non-standard lines are not generated; Google ignores <code>Crawl-delay</code>.</li>
  <li><strong>Wildcards</strong> <code>&#42;</code> and <code>$</code> are part of RFC 9309 and can be typed into a path, for example <code>Disallow: /&#42;?sessionid=</code>; the tool does not check them.</li>
  <li><strong>Blocking is not removal.</strong> A disallowed URL can still appear in search results without a description if other pages link to it. To keep a page out of results, let it be crawled and send <code>noindex</code>, which the <a href="/tools/meta-tag-generator/">meta tag generator</a> can write.</li>
  <li><strong>Size and errors.</strong> RFC 9309 asks crawlers to parse at least the first 500 KiB. If the file returns a 4xx status, crawlers may crawl everything; if it returns 5xx or cannot be reached, they should assume everything is disallowed.</li>
</ul>

<h2>Common robots.txt Patterns</h2>
<ul>
  <li><strong>Block all bots:</strong> <code>User-agent: &#42;</code> + <code>Disallow: /</code></li>
  <li><strong>Allow all bots:</strong> <code>User-agent: &#42;</code> + <code>Disallow:</code> (empty value)</li>
  <li><strong>Block a specific directory:</strong> <code>Disallow: /admin/</code></li>
  <li><strong>Allow Googlebot only:</strong> Block <code>&#42;</code>, then add a separate Googlebot block with <code>Disallow:</code></li>
</ul>
<p>
  After generating your file, upload it to your web server root so it is accessible at
  <code>https://yourdomain.com/robots.txt</code>. Each host and protocol needs its own file: rules at <code>example.com</code> do not cover <code>blog.example.com</code>.
</p>
