<h2>例：日本語 URL のページをクロールさせない</h2>
<p>お問い合わせフォームを <code>/お問い合わせ/</code> のような日本語のパスで公開している場合、「+ 拒否」のパスにそのまま日本語で入力できます。ツールは入力どおりに書き出します。</p>

{/* rtg-tool: {"blocks":[{"ua":"*","rules":[["Disallow","/お問い合わせ/"]]}],"sitemap":"https://example.jp/sitemap.xml","rfc":[{"ua":"Googlebot","paths":[["/%E3%81%8A%E5%95%8F%E3%81%84%E5%90%88%E3%82%8F%E3%81%9B/form",false],["/news/2026/",true]]}]} */}

```text
User-agent: *
Disallow: /お問い合わせ/

Sitemap: https://example.jp/sitemap.xml
```

<p>クローラーが実際に受け取る URL は <code>/%E3%81%8A%E5%95%8F%E3%81%84%E5%90%88%E3%82%8F%E3%81%9B/form</code> のようにパーセントエンコードされています。<a href="https://www.rfc-editor.org/rfc/rfc9309#section-2.2.2">RFC 9309 の 2.2.2 節</a>は、URL とルールのパスに含まれる ASCII 以外のバイトを、比較の前にどちらもパーセントエンコードするよう定めていて、例として <code>/foo/bar/ツ</code> と <code>/foo/bar/%E3%83%84</code> を挙げています。そのため、ファイルを UTF-8 で保存していれば、日本語のまま書いても、エンコード済みの形で書いても同じ URL に一致します。この規則で読むと、フォームの URL は拒否、<code>/news/2026/</code> は許可です。</p>

<h2>例：全角スラッシュが混ざったパス</h2>
<p>全角文字で書かれた資料からパスを写すと、半角の <code>/</code> ではなく全角の <code>／</code>（U+FF0F）が混ざることがあります。ツールはパスを検査しないので、全角のまま出力されます。</p>

{/* rtg-tool: {"blocks":[{"ua":"*","rules":[["Disallow","／members／"]]}]} */}

```text
User-agent: *
Disallow: ／members／
```

<p>RFC 9309 の構文では、パスは半角の <code>/</code> で始まる必要があります。<code>／members／</code> はこの形に当てはまらず、どのクローラーでも規則として読まれる保証はありません。半角に直したファイルなら、会員ページの下はすべて拒否されます。</p>

{/* rtg-tool: {"blocks":[{"ua":"*","rules":[["Disallow","/members/"]]}],"rfc":[{"ua":"Googlebot","paths":[["/members/login",false],["/member",true]]}]} */}

```text
User-agent: *
Disallow: /members/
```

<p>ルールは前方一致なので、<code>/members/login</code> は拒否されますが、末尾のスラッシュがない <code>/member</code> は一致せず許可のままです。</p>

<h2>日本の検索で読むのは主に Googlebot</h2>
<p>ヤフー株式会社は 2010 年 7 月、検索エンジンとして Google を採用すると発表しました（<a href="https://www.lycorp.co.jp/news/archive/Y/ja/ja20100727_A.pdf">プレスリリース</a>）。日本向けのサイトでは、<code>&#42;</code> のブロックに加えて Googlebot 用のブロックを作るかどうかが、Yahoo! 検索に出るページにも関係します。Googlebot 専用のブロックを作ると、Googlebot はそのブロックだけを読み、<code>&#42;</code> のルールは使いません。</p>

<h2>よく使われる robots.txt パターン</h2>
<ul>
  <li><strong>すべてのボットをブロック：</strong><code>User-agent: &#42;</code> + <code>Disallow: /</code></li>
  <li><strong>すべてのボットを許可：</strong><code>User-agent: &#42;</code> + <code>Disallow:</code>（空欄）。ルールを一つも入れないブロックは、この空の <code>Disallow:</code> を出力します。</li>
  <li><strong>特定ディレクトリをブロック：</strong><code>Disallow: /admin/</code></li>
  <li><strong>Googlebot のみ許可：</strong><code>&#42;</code> を <code>/</code> で拒否し、ルールのない Googlebot ブロックを追加する</li>
</ul>

<h2>ツールの制限と robots.txt でできないこと</h2>
<ul>
  <li><strong>検証しない：</strong>パスは前後の空白を除いてそのまま書き出します。<code>admin/</code> のように <code>/</code> で始まらない値は RFC 9309 の規則として正しくありません。空のパスは空のルールになります。</li>
  <li><strong>Sitemap は 1 行だけ：</strong>複数のサイトマップがある場合は、行をコピーして手で足します。<code>Crawl-delay</code> などの非標準の行は生成しません。</li>
  <li><strong>ワイルドカード：</strong><code>&#42;</code> と <code>$</code> は RFC 9309 の一部で、<code>Disallow: /&#42;?sessionid=</code> のようにパスに書けます。ツールは書き方を確認しません。</li>
  <li><strong>拒否は削除ではない：</strong>拒否した URL でも、ほかのページからリンクされていれば、説明文なしで検索結果に出ることがあります。結果から外したいページはクロールを許可し、<a href="/ja/tools/meta-tag-generator/">meta タグ生成ツール</a>で作る <code>noindex</code> を返します。</li>
  <li><strong>サイズとエラー：</strong>RFC 9309 は、クローラーが少なくとも先頭の 500 KiB を解析するよう求めています。robots.txt が 4xx を返すとクローラーはすべてを取得してよく、5xx を返すか接続できない場合はすべて拒否されたものとして扱います。</li>
  <li><strong>ホストごとに 1 つ：</strong>ファイルは <code>https://自分のドメイン/robots.txt</code> で開ける場所に置きます。<code>example.jp</code> のルールは <code>blog.example.jp</code> には効かないので、サブドメインごとに置いてください。</li>
</ul>
