<h2>예: 카페24 FAQ의 폴더 경로를 URL 경로로 바꾸기</h2>
<p>카페24 웹호스팅 FAQ「<a href="https://help.cafe24.com/faq/web-hosting/introduce/setup-management/traffic_exceeded_daily_bandwidth/">일일 전송량(트래픽)이 초과되었다고 나옵니다</a>」에는 특정 봇의 접근을 robots.txt로 막는 예시가 있습니다. 그중 “구글봇만 www/hompage 디렉토리 접근 차단” 예시를 생성기에 그대로 입력하면 다음과 같이 출력됩니다. 생성기는 경로를 검사하지 않습니다.</p>

{/* rtg-tool: {"blocks":[{"ua":"Googlebot","rules":[["Disallow","www/hompage"]]}]} */}

```text
User-agent: Googlebot
Disallow: www/hompage
```

<p><code>www</code>는 FTP에서 보이는 폴더 이름입니다. 카페24 웹호스팅은 메인 페이지 경로를 <code>/www/index.html</code>로 안내하므로(<a href="https://help.cafe24.com/faq/web-hosting/introduce/connection-error/site_not_loading_error_guide/">홈페이지 접속 오류 FAQ</a>), <code>www/hompage</code> 폴더는 웹에서 <code>/hompage/</code>로 열립니다. 또 <a href="https://www.rfc-editor.org/rfc/rfc9309">RFC 9309</a>의 문법에서 경로는 반드시 <code>/</code>로 시작하므로, <code>www/hompage</code>는 규칙으로 읽힌다는 보장이 없습니다. URL 경로로 고쳐 쓰면 다음과 같습니다.</p>

{/* rtg-tool: {"blocks":[{"ua":"Googlebot","rules":[["Disallow","/hompage/"]]}],"rfc":[{"ua":"Googlebot","paths":[["/hompage/index.html",false],["/",true]]},{"ua":"Yeti","paths":[["/hompage/index.html",true]]}]} */}

```text
User-agent: Googlebot
Disallow: /hompage/
```

<p>RFC 9309의 규칙으로 읽으면 Googlebot은 <code>/hompage/index.html</code>을 수집할 수 없고 첫 페이지 <code>/</code>는 수집할 수 있습니다. 파일에 <code>&#42;</code> 그룹이 없으니 네이버의 Yeti를 비롯한 다른 봇에는 아무 제한도 걸리지 않습니다.</p>

<h2>예: 구글은 허용하고 네이버는 차단하기</h2>
<p>같은 FAQ의 “구글은 허용, 네이버는 차단” 예시는 Googlebot 블록에 빈 <code>Disallow:</code>, Yeti 블록에 <code>Disallow:/</code>를 씁니다. 네이버 서치어드바이저의 <a href="https://searchadvisor.naver.com/guide/seo-basic-robots">robots.txt 설정하기</a>도 네이버 검색로봇(Yeti)이 robots.txt에 작성된 규칙을 준수한다고 밝히고 있습니다. 생성기에서는 규칙 없는 Googlebot 블록과, “직접 입력...”으로 <code>Yeti</code>를 넣고 <code>/</code>를 차단한 블록을 만듭니다.</p>

{/* rtg-tool: {"blocks":[{"ua":"Googlebot"},{"custom":"Yeti","rules":[["Disallow","/"]]}],"rfc":[{"ua":"Yeti","paths":[["/",false],["/board/list",false]]},{"ua":"Googlebot","paths":[["/board/list",true]]},{"ua":"Bingbot","paths":[["/board/list",true]]}]} */}

```text
User-agent: Googlebot
Disallow:

User-agent: Yeti
Disallow: /
```

<p>FAQ 예시와 달리 콜론 뒤에 공백이 하나 들어가지만, RFC 9309는 콜론 앞뒤의 공백을 허용하므로 뜻은 같습니다. Yeti는 모든 경로가 차단되고 Googlebot은 모두 허용됩니다. 이 파일에도 <code>&#42;</code> 그룹이 없어서 Bingbot 같은 다른 봇은 제한 없이 수집합니다. 같은 FAQ도 검색 로봇을 차단하면 포털 검색 노출이 제한될 수 있다고 안내합니다.</p>

<h2>자주 쓰는 robots.txt 패턴</h2>
<ul>
  <li><strong>모든 봇 차단:</strong> <code>User-agent: &#42;</code> + <code>Disallow: /</code></li>
  <li><strong>모든 봇 허용:</strong> <code>User-agent: &#42;</code> + <code>Disallow:</code> (값 비워 두기). 규칙이 하나도 없는 블록은 이 빈 <code>Disallow:</code>를 출력합니다.</li>
  <li><strong>특정 디렉터리 차단:</strong> <code>Disallow: /admin/</code></li>
  <li><strong>봇 하나만 허용:</strong> <code>&#42;</code> 블록에서 <code>/</code>를 차단하고, 허용할 봇의 블록은 규칙 없이 추가하기</li>
</ul>

<h2>생성기의 제한과 robots.txt의 한계</h2>
<ul>
  <li><strong>검증하지 않음:</strong> 경로는 앞뒤 공백만 지우고 그대로 씁니다. <code>admin/</code>처럼 <code>/</code>로 시작하지 않는 값은 RFC 9309의 올바른 규칙이 아닙니다. 빈 경로는 빈 규칙이 됩니다.</li>
  <li><strong>Sitemap은 한 줄:</strong> 사이트맵이 여러 개라면 줄을 복사해 직접 추가하세요. <code>Crawl-delay</code> 같은 비표준 줄은 만들지 않습니다.</li>
  <li><strong>와일드카드:</strong> <code>&#42;</code>와 <code>$</code>는 RFC 9309에 포함되어 <code>Disallow: /&#42;?sessionid=</code>처럼 경로에 쓸 수 있습니다. 생성기는 와일드카드 문법을 검사하지 않습니다.</li>
  <li><strong>차단은 삭제가 아님:</strong> 차단한 URL도 다른 페이지가 링크하면 설명 없이 검색 결과에 나올 수 있습니다. 결과에서 빼려면 수집을 허용하고 <a href="/ko/tools/meta-tag-generator/">메타 태그 생성기</a>로 만든 <code>noindex</code>를 보내세요.</li>
  <li><strong>크기와 오류:</strong> RFC 9309는 크롤러가 적어도 앞 500 KiB를 해석하도록 요구합니다. robots.txt가 4xx를 돌려주면 크롤러는 모든 것을 수집해도 되고, 5xx를 돌려주거나 연결할 수 없으면 전부 차단된 것으로 봅니다.</li>
  <li><strong>호스트마다 한 파일:</strong> 파일은 <code>https://내 도메인/robots.txt</code>로 열리는 곳에 둡니다. <code>example.co.kr</code>의 규칙은 <code>m.example.co.kr</code>에 적용되지 않으므로 서브도메인마다 따로 두세요.</li>
</ul>
