<h2>Nano ID vs UUID Comparison</h2>

| Feature | Nano ID (default) | UUID v4 |
|---|---|---|
| Length | 21 chars | 36 chars (with dashes) |
| Randomness | ~126 bits | 122 bits |
| URL-safe | ✓ Yes | ✓ Yes (hyphens are unreserved URL characters, [RFC 3986 §2.3](https://www.rfc-editor.org/rfc/rfc3986#section-2.3)) |
| Custom alphabet | ✓ Yes | ✗ No |
| Sortable | ✗ No | ✗ No |
| Timestamp-embedded | ✗ No | ✗ No |

<p>The last row uses a custom alphabet without <code>0</code>, <code>O</code>, <code>1</code> and <code>I</code>, a common choice for codes that people read aloud or type from paper, such as voucher or invite codes. A URL-safe ID can start with <code>-</code> or <code>{'_'}</code>, as the first row does. If the ID becomes a file name or a command-line argument, a leading <code>-</code> can be read as an option, so pick Alphanumeric there.</p>

<h2>Choosing the Size</h2>
<p>Each character carries log2(alphabet size) bits of randomness. The table shows the bits at the default size of 21 and the size needed to reach the 126 bits of a default Nano ID:</p>

| Alphabet | Bits at size 21 | Size for ≥ 126 bits |
|---|---|---|
| URL-safe (64) | 126.0 | 21 |
| Alphanumeric (62) | 125.0 | 22 |
| Lowercase hex (16) | 84.0 | 32 |
| Numbers only (10) | 69.8 | 38 |

{/* nid-check: {"alphabet":"url-safe","size":21,"p":0.01} */}
By the birthday bound, the default ID (`21 × log2(64) = 126.0` bits) reaches a 1% chance of any collision after about 1.3 × 10<sup>18</sup> IDs (`≈ 1.3 × 10^18`).

{/* nid-check: {"custom":"23456789ABCDEFGHJKLMNPQRSTUVWXYZ","size":8,"p":0.01} */}
Short IDs collide much sooner: an 8-character code from the 32-symbol alphabet `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` above has `8 × log2(32) = 40.0` bits and reaches a 1% chance after about 149,000 codes (`≈ 149,000`). Check uniqueness in the database for short codes, or use the <a href="/tools/uuid-generator/">UUID Generator</a> when IDs need a standard format.
<p>Random bytes come from <code>crypto.getRandomValues()</code>. For alphabets whose size is not a power of two, Nano ID masks each byte and discards values outside the alphabet instead of using a modulo, so every character is equally likely (see the <a href="https://github.com/ai/nanoid#custom-alphabet-or-size" target="_blank" rel="noopener">Nano ID README</a>).</p>

<h2>Limits</h2>
<ul>
  <li>Batch count is clamped to 1–100 and size to 1–128. An empty size, or 0, falls back to 21.</li>
  <li>Duplicate characters in a custom alphabet are removed; fewer than 2 distinct characters shows an error.</li>
  <li>Custom alphabets are read by code point: <code>😀😃🐱</code> is three symbols, and an ID of size 8 has eight of them (16 UTF-16 code units). The library's own <code>customAlphabet()</code> works per UTF-16 code unit and allows at most 256 symbols, so for custom alphabets the tool draws a 32-bit random value per symbol instead and discards values at or above the largest multiple of the alphabet size, which keeps every symbol equally likely. Combined characters such as flags or skin-tone emoji are two or more code points and become separate symbols.</li>
  <li>Nano IDs carry no timestamp and do not sort by creation time. For sortable keys, use the <a href="/tools/ulid-generator/">ULID Generator</a>.</li>
</ul>
