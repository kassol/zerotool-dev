<h2>Nano ID vs UUID 비교</h2>

| 기능 | Nano ID (기본) | UUID v4 |
|---|---|---|
| 길이 | 21자 | 36자 (하이픈 포함) |
| 무작위성 | 약 126비트 | 122비트 |
| URL 안전 | ✓ 예 | ✓ 예 (하이픈도 URL에서 그대로 쓸 수 있는 문자) |
| 커스텀 알파벳 | ✓ 예 | ✗ 아니오 |
| 정렬 가능 | ✗ 아니오 | ✗ 아니오 |
| 타임스탬프 내장 | ✗ 아니오 | ✗ 아니오 |

<h2>알파벳 참고</h2>

| 프리셋 | 문자 | 개수 |
|---|---|---|
| URL 안전 (기본) | `A-Za-z0-9_-` | 64 |
| 영숫자 | `A-Za-z0-9` | 62 |
| 숫자만 | `0-9` | 10 |
| 소문자 16진수 | `0-9a-f` | 16 |

## 한글로 만든 알파벳

ID는 매번 무작위라서 직접 생성한 결과는 아래 예와 다릅니다. 설정으로 정해지는 것은 글자 하나가 가지는 log2(알파벳 크기)비트의 무작위성과, 몇 개를 만들면 중복 확률이 1%에 이르는지(생일 문제 근사)입니다.

행사 입장 코드를 한글로 읽기 쉽게 만들고 싶다고 해 봅시다. 사용자 정의 알파벳에 `가나다라마바사아자차카타파하`를 넣고 크기를 8로 두면 다음과 같습니다.

{/* nid-check: {"custom":"가나다라마바사아자차카타파하","size":8,"p":0.01} */}
- 입력: `가나다라마바사아자차카타파하`, 기호 14개
- 무작위성: `8 × log2(14) = 30.5`비트
- 중복 확률이 1%에 이르는 개수: `≈ 5,450`

수천 장만 나눠 줘도 겹칠 가능성이 생기므로, 발급할 때 이미 나간 코드와 대조해야 합니다. 같은 8자리라도 URL 안전 알파벳(64자)을 쓰면 48비트가 되어 훨씬 여유가 있습니다. 한글은 UTF-8에서 한 글자에 3바이트이므로, 바이트 수로 길이를 제한한 DB 컬럼에서는 24바이트가 필요하다는 점도 확인하세요.

주문 번호처럼 외부에 보이는 ID를 12자로 줄이고 싶다면 URL 안전 알파벳으로 계산해 볼 수 있습니다.

{/* nid-check: {"alphabet":"url-safe","size":12,"p":0.01} */}
- 무작위성: `12 × log2(64) = 72.0`비트
- 중복 확률이 1%에 이르는 개수: `≈ 9.7 × 10^9`

## 자모로 분해된 한글을 붙여넣으면

사용자 정의 알파벳은 Unicode 코드 포인트 단위로 셉니다. 같은 '한글'이라도 완성형(NFC)이면 두 기호지만, 자모로 분해된 형태(NFD)로 복사된 문자열은 초성·중성·종성이 각각 하나의 기호가 됩니다.

{/* nid-check: {"custom":"한글","size":10,"p":0.01,"symbols":true} */}
- 입력: `한글` (화면에는 '한글'로 보이지만 NFD)
- 나뉜 기호 6개: `ᄒ ᅡ ᆫ ᄀ ᅳ ᆯ`
- 무작위성: `10 × log2(6) = 25.8`비트
- 중복 확률이 1%에 이르는 개수: `≈ 1,100`

이렇게 만든 ID에는 홀로 쓰인 자모가 섞여 글꼴에 따라 이상하게 보입니다. 다른 프로그램에서 복사한 한글이 예상보다 기호 수가 많다면 NFC로 정규화한 뒤 다시 붙여넣으세요. 이 도구는 정규화를 하지 않습니다.

중복을 지우고 나서 기호가 하나만 남으면 생성하지 않고 오류를 보여 줍니다.

{/* nid-check: {"custom":"하하하","size":8} */}
입력 `하하하`, 표시 `알파벳은 최소 2자 이상이어야 합니다`

## 제한

- 일괄 수는 1–100, 크기는 1–128 범위로 맞춥니다. 크기가 비어 있거나 0이면 21을 씁니다.
- 사용자 정의 알파벳의 중복 문자는 지워지고, 서로 다른 기호가 두 개보다 적으면 오류가 납니다.
- 사용자 정의 알파벳은 코드 포인트 단위로 읽습니다. `😀😃🐱`를 넣으면 기호 3개이고, 크기 8인 ID는 기호 8개(UTF-16 코드 단위 16개)입니다. 국기나 피부색이 붙은 이모지처럼 여러 코드 포인트로 된 문자는 각각 따로 기호가 됩니다.
- 프리셋은 Nano ID 3.3.11로 생성합니다. 사용자 정의 알파벳은 기호마다 32비트 난수 하나를 뽑고, 알파벳 크기의 가장 큰 배수 이상인 값은 버리므로 모든 기호가 같은 확률로 나옵니다.
- Nano ID에는 타임스탬프가 없어 생성 순서대로 정렬되지 않습니다. 정렬 가능한 키가 필요하면 [ULID 생성기](/ko/tools/ulid-generator/)를 쓰세요.
