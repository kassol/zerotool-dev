<h2>Nano ID vs UUID 对比</h2>

| 特性 | Nano ID（默认）| UUID v4 |
|---|---|---|
| 长度 | 21 字符 | 36 字符（含连字符）|
| 随机性 | 约 126 位 | 122 位 |
| URL 安全 | ✓ 是 | ✓ 是（连字符本身也是 URL 可直接使用的字符）|
| 自定义字符集 | ✓ 是 | ✗ 否 |
| 可排序 | ✗ 否 | ✗ 否 |
| 内嵌时间戳 | ✗ 否 | ✗ 否 |

| 预设 | 字符 | 数量 |
|---|---|---|
| URL 安全（默认）| `A-Za-z0-9_-` | 64 |

| 十六进制小写 | `0-9a-f` | 16 |

## 长度怎么定：取件码和短链接

ID 每次随机生成，你点出来的结果和下面不会一样；能算准的是由设置决定的部分：每个字符带 log2(字符集大小) 位随机性，生成到多少个时出现重复的概率达到 1%（按生日问题估算）。

像取件码那样只用 6 位数字：

{/* nid-check: {"alphabet":"numbers","size":6,"p":0.01} */}
- 随机性：`6 × log2(10) = 19.9` 位
- 生成约 142 个就有 1% 的概率出现两个相同的码：`≈ 142`

一百多个就可能撞号，所以这种短码不能只靠随机，发放前必须在数据库里查重，或者只在码仍有效的那段时间、那个范围内保证唯一。

给短链接用 7 位字母数字：

{/* nid-check: {"alphabet":"alphanumeric","size":7,"p":0.01} */}
- 随机性：`7 × log2(62) = 41.7` 位
- 1% 碰撞概率对应的数量：`≈ 266,000`

加到 8 位：

{/* nid-check: {"alphabet":"alphanumeric","size":8,"p":0.01} */}
- 随机性：`8 × log2(62) = 47.6` 位
- 1% 碰撞概率对应的数量：`≈ 2.1 × 10^6`

每多一位，可容纳的数量大约乘以 √62 ≈ 7.9。链接数量预计在几十万以上时，7 位已经不够从容，要么加长，要么在插入时检查唯一约束并在冲突时重试。默认的 21 位 URL 安全 ID 有约 126 位随机性，一般业务不必查重，但会让链接变长。

## 自定义字符集按码点计算

自定义字符集会按 Unicode 码点拆开并去掉重复，所以中文字符、emoji 都按一个符号算。比如用十个天干当字符集：

{/* nid-check: {"custom":"甲乙丙丁戊己庚辛壬癸","size":6,"symbols":true} */}
- 字符集 `甲乙丙丁戊己庚辛壬癸` 拆成 10 个符号：`甲 乙 丙 丁 戊 己 庚 辛 壬 癸`
- 长度 6 的随机性：`6 × log2(10) = 19.9` 位

结果和 6 位纯数字完全一样：随机性只看符号个数，不看是什么字。换成汉字只是更好认，并不更难猜。另外，一个汉字在 UTF-8 里占 3 个字节，存进按字节限制长度的字段时要留意。

去重后不足 2 个不同符号时，工具不生成，直接提示：

{/* nid-check: {"custom":"哈哈哈","size":8} */}
输入 `哈哈哈`，提示：`字符集至少需要 2 个字符`

## 限制

- 批量数量限制为 1–100，长度限制为 1–128；长度留空或为 0 时按 21 处理。
- 自定义字符集里的重复字符会被删掉；不同的符号少于 2 个时报错。
- 自定义字符集按码点读取：`😀😃🐱` 是 3 个符号，长度 8 的 ID 含 8 个这样的符号（16 个 UTF-16 码元）。国旗、带肤色的 emoji 这类组合字符由两个以上码点组成，会被拆成几个独立的符号。
- 预设字符集由 Nano ID 3.3.11 生成；自定义字符集由工具为每个符号取一个 32 位随机数，丢弃不小于字符集大小最大整数倍的值，避免取模偏差。
- Nano ID 不含时间戳，不能按创建时间排序。需要可排序的键时用 [ULID 生成器](/zh/tools/ulid-generator/)。
