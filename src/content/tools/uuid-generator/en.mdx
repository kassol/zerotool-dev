</p>

<h2>How Unlikely Is a Collision?</h2>
<p>
  With 122 random bits there are 2<sup>122</sup> (about 5.3 × 10<sup>36</sup>) possible values. By the birthday bound, you need about
  2.7 × 10<sup>18</sup> UUIDs before the chance of any two matching reaches 50%. At one billion UUIDs per second, that takes about 86 years.
  After 103 trillion UUIDs the chance is still about one in a billion. In practice, duplicates come from bugs such as a copied seed or a
  value reused by mistake, not from the random bits.
</p>

<h2>Choosing Between UUID Versions and Other IDs</h2>
<ul>
  <li><strong>v4 (this tool)</strong>: random, no information about when or where it was made. Good for public identifiers and tokens that must not reveal order.</li>
  <li><strong>v7</strong> (RFC 9562 section 5.7): 48-bit Unix millisecond timestamp, then random bits. The same section says implementations SHOULD use v7 instead of v1 and v6 where possible. The <a href="/tools/ulid-generator/">ULID Generator</a> makes a similar time-sorted 128-bit ID in 26 characters.</li>
  <li><strong>Shorter IDs</strong>: the <a href="/tools/nano-id-generator/">Nano ID Generator</a> makes 21-character URL-safe IDs with about the same amount of randomness.</li>
</ul>

<h2>Limitations</h2>
<ul>
  <li>Version 4 only. There are no options for uppercase, no hyphens, braces or URN form (<code>urn:uuid:…</code>); edit the copied text if your system needs one of these.</li>
  <li>At most 100 per batch.</li>
  <li><code>crypto.randomUUID()</code> is available in Chrome and Edge 92+, Firefox 95+ and Safari 15.4+ (MDN browser compatibility data). In older browsers the tool shows no UUID.</li>
  <li>The tool generates values; it does not validate or decode a UUID you paste.</li>
</ul>
