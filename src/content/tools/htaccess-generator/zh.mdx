<h2>各配置区域生成什么</h2>
<ul>
  <li><strong>强制 HTTPS：</strong>在 <code>%&#123;HTTPS&#125;</code> 为 <code>off</code> 时，用 RewriteRule 把请求 301 跳转到同一主机的 <code>https://</code> 地址，需要 <code>mod_rewrite</code>。规则包在 <code>&lt;IfModule mod_rewrite.c&gt;</code> 里，服务器没有加载该模块时这段不生效，也不会报错。</li>
  <li><strong>WWW 跳转：</strong>统一成带 <code>www.</code> 或不带 <code>www.</code> 的一种写法。跳转目标始终是 <code>https://</code>，即使关闭了“强制 HTTPS”也一样。</li>
  <li><strong>目录索引：</strong>请求目录时 Apache 依次查找的默认文件，默认值为 <code>index.php index.html index.htm</code>；输入框为空或只有空格时写成 <code>index.php index.html</code>。</li>
  <li><strong>浏览器缓存：</strong>用 <code>mod_expires</code> 为图片、CSS/JS 和字体发送 <code>Expires</code> 与 <code>Cache-Control: max-age</code>。每种 MIME 类型各写一行 <code>ExpiresByType</code>，Apache 返回的类型不在列表里时，该文件就没有缓存头。</li>
  <li><strong>安全：</strong>禁止目录浏览（<code>Options -Indexes</code>），用 <code>Require all denied</code> 拒绝直接访问 <code>.htaccess</code> 和 <code>.env</code>。可选的响应头有 <code>X-Content-Type-Options: nosniff</code>、<code>X-Frame-Options: SAMEORIGIN</code>、<code>Referrer-Policy: strict-origin-when-cross-origin</code>，以及按 <a href="https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html#x-xss-protection">OWASP HTTP Headers Cheat Sheet</a> 建议关闭旧版浏览器 XSS 过滤器的 <code>X-XSS-Protection: 0</code>，默认不勾选。</li>
  <li><strong>自定义跳转：</strong>来源路径和目标网址都填写后，生成一条 Apache <code>Redirect</code> 指令，状态码可选 301 或 302。</li>
</ul>

<h2>示例：默认选项的输出</h2>
<p>打开页面不做任何修改，输出如下（强制 HTTPS、目录索引、浏览器缓存，以及安全区域的前三项）。把它放进 Apache 2.4.67、目录设为 <code>AllowOverride All</code> 后用 HTTP 请求：<code>/</code> 返回 301；去掉 HTTPS 一段再测，<code>.ttf</code> 文件带 <code>Cache-Control: max-age=31536000</code>（1 年），<code>/.env</code>、<code>/.htaccess</code> 和没有首页文件的目录都返回 403。</p>

```apache
# Force HTTPS
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
</IfModule>

# Directory Index
DirectoryIndex index.php index.html index.htm

# Browser Caching
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/gif "access plus 1 year"
  ExpiresByType image/svg+xml "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"
  ExpiresByType text/javascript "access plus 1 month"
  ExpiresByType font/woff "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
  ExpiresByType font/ttf "access plus 1 year"
  ExpiresByType application/x-font-ttf "access plus 1 year"
  ExpiresByType application/vnd.ms-fontobject "access plus 1 year"
</IfModule>

# Security
Options -Indexes
<Files ".htaccess">
  Require all denied
</Files>
<Files ".env">
  Require all denied
</Files>
```

<p>字体同时列出 <code>font/ttf</code> 和 <code>application/x-font-ttf</code>：Apache 2.4 自带的 <code>mime.types</code> 把 <code>.ttf</code> 映射为 <code>font/ttf</code>，较旧的配置用的是带 <code>x-</code> 的名字，只写其中一个，另一种服务器上的 TTF 文件就拿不到缓存头。</p>

<h2>示例：在阿里云虚拟主机上把中文栏目迁到新地址</h2>
<p>先确认主机类型。阿里云的文档写明，Linux 普通版云虚拟主机的 Web 服务是 Apache，伪静态规则写在站点根目录 <code>/htdocs</code> 下的 <code>.htaccess</code> 里；增强版的 Web 服务是 Nginx 1.18，不支持通过 <code>.htaccess</code> 设置伪静态，要在控制台“高级环境设置 → NGINX设置”里写规则（<a href="https://help.aliyun.com/zh/cloud-web-hosting/use-cases/using-urlrewrite-configuration-cloud-hosting-pseudo-static-function">使用 URL Rewrite 配置伪静态</a>、<a href="https://help.aliyun.com/zh/cloud-web-hosting/user-guide/nginx-configuration-file">配置 Nginx 文件</a>）。控制台自带的 301 重定向在普通版上只支持网站首页（<a href="https://help.aliyun.com/zh/cloud-web-hosting/user-guide/configure-a-301-redirect-and-https-redirection">设置 301 重定向</a>），所以普通版上要跳转某个栏目，用 <code>.htaccess</code> 里的 <code>Redirect</code> 更直接。</p>
<p>假设旧站的“关于我们”页面路径是中文 <code>/关于我们</code>，要永久跳到 <code>https://example.cn/about/</code>，同时去掉 www。在工具里勾选“WWW 跳转”并选“去除 www”，再打开“自定义跳转”，来源路径填 <code>/关于我们</code>、目标网址填 <code>https://example.cn/about/</code>、类型选 301。输出中新增的两段是：</p>

<p>浏览器发出的请求路径是百分号编码的 <code>/%E5%85%B3%E4%BA%8E%E6%88%91%E4%BB%AC</code>。<a href="https://httpd.apache.org/docs/2.4/mod/mod_alias.html#redirect">Redirect 文档</a>说明来源路径按解码后的形式比较，所以 <code>.htaccess</code> 里直接写中文即可，前提是文件以 UTF-8 保存。在 Apache 2.4.67 中实测，这个请求得到 301，<code>Location</code> 为 <code>https://example.cn/about/</code>。<code>Redirect</code> 是前缀匹配，会把剩余部分接在目标后面：<code>/关于我们/team</code> 跳到了 <code>https://example.cn/about//team</code>，中间多了一个斜杠。来源和目标的结尾斜杠保持一致（都写或都不写）就能避免。</p>
<p>阿里云文档的操作步骤里，示例文件先以 <code>htaccess</code> 的名字通过 FTP 传到 <code>/htdocs</code>，再重命名为 <code>.htaccess</code>。文档还提醒 <code>.htaccess</code> 是隐藏文件，要在 FTP 客户端里打开显示隐藏文件才能看到；目录里已有 <code>.htaccess</code> 时，先下载到本地备份。</p>

<h2>限制与常见错误</h2>
<ul>
  <li><strong>500 Internal Server Error：</strong><code>.htaccess</code> 里的每条指令都要被该目录的 <a href="https://httpd.apache.org/docs/2.4/mod/core.html#allowoverride">AllowOverride</a> 允许。在 <code>AllowOverride FileInfo</code> 下，仅 <code>Options -Indexes</code> 一行就让整个目录返回 500。</li>
  <li><strong>所有页面都是 403：</strong><code>.htaccess</code> 中的 <code>RewriteRule</code> 需要 <code>Options FollowSymLinks</code> 或 <code>SymLinksIfOwnerMatch</code>，两者都关闭时，Apache 拒绝所有经过该规则的请求（错误日志 AH00670）。</li>
  <li><strong>CDN 或负载均衡后面无限跳转：</strong><code>%&#123;HTTPS&#125;</code> 描述的是 Apache 自己收到的连接。前面的代理终止 TLS、再用 HTTP 转给 Apache 时，这个变量永远是 <code>off</code>，强制 HTTPS 会一直跳转。这种情况在代理上强制 HTTPS，或改为判断代理设置的请求头。</li>
  <li><strong>强制 www 会作用到子域名：</strong>规则给所有不以 <code>www.</code> 开头的主机加前缀，<code>blog.example.cn</code> 会被跳到 <code>www.blog.example.cn</code>，IP 地址也会被加上。只有站点只用主域名时才适合开启。</li>
  <li><strong>只保护完全同名的文件：</strong><code>.env</code> 块只拦截名字正好是 <code>.env</code> 的文件，<code>.env.local</code>、<code>.env.production</code> 仍会被返回，这类文件应放在网站根目录之外。</li>
  <li><strong>来源路径必须以斜杠开头：</strong>Redirect 文档要求旧路径以 <code>/</code> 开头、不允许相对路径。<code>Redirect 301 old-page …</code> 在 Apache 2.4.67 中加载时不报错，但请求 <code>/old-page</code> 不会跳转。因此来源路径不以 <code>/</code> 开头时，工具不写出这条重定向，并在“复制”下方的状态行提示；其他规则照常可以复制。</li>
  <li><strong>路径中间不能有空格：</strong>来源路径或目标 URL 中间有空格时，<code>Redirect</code> 行会变成 4 个参数，Apache 2.4.67 对整个目录返回 500（错误日志写“Redirect takes one, two or three arguments”）。工具会提示并不写出这一行。目标 URL 里的空格写成 <code>%20</code>；来源路径确实含空格时，手动编辑文件并给路径加引号（<code>Redirect 301 "/old page" …</code> 在同一测试中可以跳转）。</li>
  <li>每次只生成一条自定义跳转，需要多条时复制 <code>Redirect</code> 行再修改。没有 Basic 认证、CORS、gzip/Brotli 压缩这些区域；需要密码保护目录时，可以用 <a href="/zh/tools/htpasswd-generator/">htpasswd 生成器</a>生成凭据文件。</li>
</ul>
