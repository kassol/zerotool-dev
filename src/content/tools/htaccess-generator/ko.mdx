<h2>생성기가 출력하는 규칙</h2>
<ul>
  <li><strong>HTTPS 강제:</strong> <code>%&#123;HTTPS&#125;</code>가 <code>off</code>일 때 같은 호스트의 <code>https://</code> 주소로 301 리디렉션하는 RewriteRule입니다. <code>mod_rewrite</code>가 필요하며, <code>&lt;IfModule mod_rewrite.c&gt;</code>로 감싸 두었기 때문에 모듈이 없는 서버에서는 오류 없이 무시됩니다.</li>
  <li><strong>WWW 리디렉션:</strong> 주소를 www가 붙은 형태나 뺀 형태 하나로 통일합니다. HTTPS 강제를 꺼 두어도 이동할 주소는 항상 <code>https://</code>입니다.</li>
  <li><strong>디렉터리 인덱스:</strong> 디렉터리 주소로 요청이 왔을 때 Apache가 차례로 찾는 파일입니다. 기본값은 <code>index.php index.html index.htm</code>이고, 입력란이 비어 있거나 공백뿐이면 <code>index.php index.html</code>로 출력됩니다. 파일 이름 사이의 전각 공백은 반각 공백으로 바꿔 씁니다. Apache는 반각 공백으로만 이름을 나누기 때문입니다.</li>
  <li><strong>브라우저 캐싱:</strong> <code>mod_expires</code>로 이미지, CSS/JavaScript, 글꼴에 <code>Expires</code>와 <code>Cache-Control: max-age</code>를 붙입니다. MIME 유형마다 <code>ExpiresByType</code>을 한 줄씩 쓰므로, 목록에 없는 유형으로 응답되는 파일에는 헤더가 붙지 않습니다.</li>
  <li><strong>보안:</strong> 디렉터리 목록을 끄고(<code>Options -Indexes</code>), <code>.htaccess</code>와 <code>.env</code>에 대한 직접 접근을 <code>Require all denied</code>로 막습니다. 보안 헤더(<code>X-Content-Type-Options: nosniff</code>, <code>X-Frame-Options: SAMEORIGIN</code>, <code>Referrer-Policy: strict-origin-when-cross-origin</code>, <code>X-XSS-Protection: 0</code>)는 기본으로 꺼져 있습니다. <code>X-XSS-Protection</code>을 <code>0</code>으로 두는 것은 <a href="https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html#x-xss-protection">OWASP HTTP Headers Cheat Sheet</a>의 권장값입니다.</li>
  <li><strong>사용자 정의 리디렉션:</strong> 원본 경로와 대상 URL을 모두 입력하면 <code>Redirect</code> 지시문 한 줄을 만듭니다. 상태는 301 또는 302 중에서 고릅니다.</li>
</ul>

<h2>예: 기본 설정 그대로의 출력</h2>
<p>페이지를 연 직후의 설정(HTTPS 강제, 디렉터리 인덱스, 브라우저 캐싱, 보안의 앞 세 항목)으로는 다음 파일이 나옵니다.</p>

{/* hta-check: {} */}

```apache
# Force HTTPS
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
</IfModule>

# Directory Index
DirectoryIndex index.php index.html index.htm

# Browser Caching
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/gif "access plus 1 year"
  ExpiresByType image/svg+xml "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"
  ExpiresByType text/javascript "access plus 1 month"
  ExpiresByType font/woff "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
  ExpiresByType font/ttf "access plus 1 year"
  ExpiresByType application/x-font-ttf "access plus 1 year"
  ExpiresByType application/vnd.ms-fontobject "access plus 1 year"
</IfModule>

# Security
Options -Indexes
<Files ".htaccess">
  Require all denied
</Files>
<Files ".env">
  Require all denied
</Files>
```

<p>Apache 2.4.67에서 <code>AllowOverride All</code>인 디렉터리에 두고 HTTP로 요청하면 <code>/</code>는 301, <code>/.env</code>와 <code>/.htaccess</code>는 403이었습니다. 글꼴에 <code>font/ttf</code>와 <code>application/x-font-ttf</code>가 함께 있는 까닭은 Apache 2.4에 들어 있는 <code>mime.types</code>가 <code>.ttf</code>를 <code>font/ttf</code>로 보내고, 오래된 설정은 <code>x-</code>가 붙은 이름을 쓰기 때문입니다.</p>

<h2>예: 카페24 웹호스팅의 기존 .htaccess에 덧붙일 때</h2>
<p>카페24 웹호스팅은 FTP의 <code>/www</code> 폴더가 홈페이지 최상위 폴더이고, 기본 메인 페이지 경로를 <code>/www/index.html</code> 또는 <code>/www/index.php</code>로 안내합니다(<a href="https://help.cafe24.com/faq/web-hosting/introduce/connection-error/site_not_loading_error_guide/">홈페이지 접속 오류 FAQ</a>). 같은 FAQ는 PHP 메모리 한도 같은 설정도 <code>/www/.htaccess</code>에 넣도록 안내하므로, 이미 파일이 있다면 내용을 덮어쓰지 말고 아래에 덧붙입니다. 파일 이름은 정확히 <code>.htaccess</code>여야 하며 <code>.htaccess.txt</code>로 저장하면 적용되지 않습니다(<a href="https://help.cafe24.com/faq/web-hosting/introduce/setup-management/block_unauthorized_link_htaccess/">무단 링크 방지 FAQ</a>).</p>
<p>예를 들어 <code>.env</code> 파일을 실수로 올렸을 때를 대비해 보안 항목에서 디렉터리 목록 차단과 <code>.env</code> 숨기기만 남기면 출력은 다음과 같습니다.</p>

{/* hta-check: {"https":false,"index":false,"cache":false,"security":{"ht":false}} */}

```apache
# Security
Options -Indexes
<Files ".env">
  Require all denied
</Files>
```

<p>주의할 점은 기존 파일의 문법입니다. 카페24의 무단 링크 방지 FAQ 예시는 Apache 2.2 문법인 <code>Order</code>, <code>Allow from</code>, <code>Deny from</code>을 씁니다. 그 예시의 일부(검색엔진 줄 생략) 아래에 위 출력을 붙인 파일로 Apache 2.4.67에서 확인했습니다.</p>

```apache
SetEnvIf Referer mydomain.com go_in
SetEnvIf Referer ^$ go_in

Order Deny,Allow
Allow from env=go_in
Deny from all

# Security
Options -Indexes
<Files ".env">
  Require all denied
</Files>
```

{/* hta-apache: {"override":"All","compat":true,"requests":[["/",200],["/.env",403]]} */}
{/* hta-apache: {"override":"All","requests":[["/",500]],"log":"Invalid command 'Order'"} */}

<p><code>mod_access_compat</code>을 불러온 서버에서는 Referer 없는 <code>/</code> 요청이 200, <code>/.env</code>는 403이었습니다. 이 모듈이 없으면 <code>Order</code> 줄 때문에 사이트 전체가 500이 되고, 오류 로그에 <code>Invalid command 'Order'</code>가 남습니다. 또 <a href="https://httpd.apache.org/docs/2.4/upgrading.html">Apache 2.4 업그레이드 문서</a>는 옛 지시문과 <code>Require</code>를 섞는 것이 기술적으로는 가능하지만 권장하지 않는다고 적고 있습니다. 새로 쓰는 규칙은 <code>Require</code>로 통일하고, 기존 <code>Order</code> 줄도 같은 뜻의 <code>Require</code>로 바꿔 두는 편이 안전합니다.</p>

<h2>제한과 자주 나는 오류</h2>
<ul>
  <li><strong>500 Internal Server Error:</strong> 모든 지시문은 해당 디렉터리의 <a href="https://httpd.apache.org/docs/2.4/mod/core.html#allowoverride">AllowOverride</a>가 허용해야 합니다. <code>AllowOverride FileInfo</code> 환경에서는 <code>Options -Indexes</code> 한 줄만으로 디렉터리 전체가 500이 되었습니다.</li>
  <li><strong>모든 페이지가 403:</strong> <code>.htaccess</code>의 <code>RewriteRule</code>에는 <code>Options FollowSymLinks</code>나 <code>SymLinksIfOwnerMatch</code>가 필요합니다. 둘 다 꺼져 있으면 규칙에 닿는 요청이 모두 거부됩니다(오류 로그 AH00670).</li>
  <li><strong>CDN이나 로드 밸런서 뒤에서 리디렉션이 끝나지 않음:</strong> <code>%&#123;HTTPS&#125;</code>는 Apache가 직접 받은 연결을 뜻합니다. 앞단 프록시가 TLS를 끝내고 Apache에는 HTTP로 넘기면 값이 항상 <code>off</code>여서 HTTPS 강제가 반복됩니다. 이때는 프록시에서 HTTPS로 보내거나 프록시가 붙이는 헤더를 조건으로 쓰세요.</li>
  <li><strong>www 강제는 서브도메인에도 적용:</strong> <code>www.</code>로 시작하지 않는 모든 호스트에 <code>www.</code>를 붙이므로 <code>blog.example.co.kr</code>은 <code>www.blog.example.co.kr</code>로, IP 주소에도 붙습니다.</li>
  <li><strong>이름이 정확히 같은 파일만 보호:</strong> <code>.env</code> 블록은 <code>.env.local</code>이나 <code>.env.production</code>을 막지 않습니다. 이런 파일은 웹 루트 밖에 두세요.</li>
  <li><strong>원본 경로는 슬래시로 시작:</strong> <a href="https://httpd.apache.org/docs/2.4/mod/mod_alias.html#redirect">Redirect</a> 문서에 따르면 원본 경로는 슬래시로 시작하는 경로이며 상대 경로는 쓸 수 없습니다. <code>Redirect 301 old-page …</code>는 Apache 2.4.67에서 오류 없이 읽혔지만 <code>/old-page</code> 요청은 리디렉션되지 않았습니다. 그래서 원본 경로가 <code>/</code>로 시작하지 않으면 생성기는 이 줄을 출력하지 않고, 복사 버튼 아래 상태 줄에 오류를 표시합니다. 다른 규칙은 그대로 복사할 수 있습니다.</li>
  <li><strong>경로 중간에 공백 금지:</strong> 원본 경로나 대상 URL 중간에 공백이 있으면 <code>Redirect</code> 줄의 인수가 4개가 되고, Apache 2.4.67에서는 디렉터리 전체가 500이 되었습니다(오류 로그 “Redirect takes one, two or three arguments”). 생성기는 오류를 표시하고 이 줄을 출력하지 않습니다. 대상 URL의 공백은 <code>%20</code>으로 쓰고, 공백이 든 원본 경로는 파일을 직접 고쳐 경로를 따옴표로 감싸세요(<code>Redirect 301 "/old page" …</code>는 같은 확인에서 리디렉션되었습니다).</li>
  <li>사용자 정의 리디렉션은 한 줄만 만듭니다. 여러 개가 필요하면 <code>Redirect</code> 줄을 복사해 고치세요. Basic 인증, CORS, gzip / Brotli 압축 항목은 없습니다. 비밀번호 파일은 <a href="/ko/tools/htpasswd-generator/">htpasswd 생성기</a>로 만들 수 있습니다.</li>
</ul>
