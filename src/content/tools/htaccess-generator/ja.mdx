<h2>出力される設定の中身</h2>
<ul>
  <li><strong>HTTPS 強制：</strong><code>%&#123;HTTPS&#125;</code> が <code>off</code> のとき、同じホストの <code>https://</code> へ 301 で転送する RewriteRule です。<code>mod_rewrite</code> が必要で、<code>&lt;IfModule mod_rewrite.c&gt;</code> で囲まれているため、モジュールがないサーバーではエラーにならずに無視されます。</li>
  <li><strong>WWW リダイレクト：</strong>「www を強制」か「www を削除」のどちらかに統一します。転送先は、HTTPS 強制をオフにしていても常に <code>https://</code> です。</li>
  <li><strong>ディレクトリインデックス：</strong>ディレクトリにアクセスされたとき Apache が順に探すファイルです。初期値は <code>index.php index.html index.htm</code> で、欄が空か空白だけのときは <code>index.php index.html</code> と出力されます。</li>
  <li><strong>ブラウザキャッシュ：</strong><code>mod_expires</code> で画像、CSS/JavaScript、フォントに <code>Expires</code> と <code>Cache-Control: max-age</code> を付けます。MIME タイプごとに <code>ExpiresByType</code> を 1 行ずつ書くので、Apache が一覧にないタイプで返したファイルにはヘッダーが付きません。</li>
  <li><strong>セキュリティ：</strong>ディレクトリ一覧を止め（<code>Options -Indexes</code>）、<code>.htaccess</code> と <code>.env</code> への直接アクセスを <code>Require all denied</code> で拒否します。ヘッダー（<code>X-Content-Type-Options: nosniff</code>、<code>X-Frame-Options: SAMEORIGIN</code>、<code>Referrer-Policy: strict-origin-when-cross-origin</code>、<code>X-XSS-Protection: 0</code>）は初期状態ではオフです。<code>X-XSS-Protection</code> を <code>0</code> にするのは <a href="https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html#x-xss-protection">OWASP HTTP Headers Cheat Sheet</a> の推奨です。</li>
  <li><strong>カスタムリダイレクト：</strong>リダイレクト元とリダイレクト先の両方を入力すると、<code>Redirect</code> ディレクティブを 1 行出力します。種類は 301 か 302 です。</li>
</ul>

<h2>例：初期状態のまま出力した場合</h2>
<p>ページを開いた直後の設定（HTTPS 強制、ディレクトリインデックス、ブラウザキャッシュ、セキュリティの最初の 3 項目）では、次のファイルが出力されます。</p>

{/* hta-check: {} */}

```apache
# Force HTTPS
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
</IfModule>

# Directory Index
DirectoryIndex index.php index.html index.htm

# Browser Caching
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/gif "access plus 1 year"
  ExpiresByType image/svg+xml "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"
  ExpiresByType text/javascript "access plus 1 month"
  ExpiresByType font/woff "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
  ExpiresByType font/ttf "access plus 1 year"
  ExpiresByType application/x-font-ttf "access plus 1 year"
  ExpiresByType application/vnd.ms-fontobject "access plus 1 year"
</IfModule>

# Security
Options -Indexes
<Files ".htaccess">
  Require all denied
</Files>
<Files ".env">
  Require all denied
</Files>
```

<p>Apache 2.4.67 で <code>AllowOverride All</code> のディレクトリに置いて HTTP でアクセスすると、<code>/</code> は 301 になり、<code>/.env</code> と <code>/.htaccess</code> は 403 でした。フォントに <code>font/ttf</code> と <code>application/x-font-ttf</code> の両方があるのは、Apache 2.4 同梱の <code>mime.types</code> が <code>.ttf</code> を <code>font/ttf</code> にしている一方、古い設定では <code>x-</code> 付きの名前が使われているためです。</p>

<h2>例：エックスサーバーで常時 SSL 化と www なしをまとめる</h2>
<p>エックスサーバーのマニュアル「<a href="https://www.xserver.ne.jp/manual/man_server_fullssl.php">Webサイトの常時SSL化</a>」によると、独自 SSL を設定しただけでは <code>https://</code> へ自動で転送されず、サーバーパネルの「.htaccess編集」で転送の記述を追記します。追記先は既存の設定を残した先頭が推奨されています。同じ転送をジェネレーターで作るなら、HTTPS 強制と「www を削除」だけをオンにします。</p>

{/* hta-check: {"https":true,"www":"remove","index":false,"cache":false,"security":false} */}

```apache
# Force HTTPS
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
</IfModule>

# Remove www
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
  RewriteRule ^(.*)$ https://%1%{REQUEST_URI} [L,R=301]
</IfModule>
```

{/* hta-apache: {"override":"All","requests":[["/",301,null,"https://www.example.jp/","www.example.jp"],["/news/",301,null,"https://example.jp/news/","example.jp"]]} */}

<p>マニュアルの記述は <code>RewriteCond %&#123;HTTPS&#125; !on</code> で、ジェネレーターは <code>off</code> と書きますが、意味は同じです。Apache 2.4.67 で HTTP の <code>http://www.example.jp/</code> を開くと、最初の 301 の転送先は <code>https://www.example.jp/</code> でした。規則は上から順に適用され、1 回目は HTTPS 強制だけが働くからです。転送先の HTTPS ページでは <code>%&#123;HTTPS&#125;</code> が <code>on</code> になり、今度は「www を削除」の規則で <code>https://example.jp/</code> へもう一度転送されます。往復は 2 回になりますが、最終的な URL は 1 つにそろいます。</p>
<p>サーバーパネルの「<a href="https://www.xserver.ne.jp/manual/man_server_htaccess.php">.htaccess編集</a>」が編集するのはドメインの <code>public_html/.htaccess</code> で、UTF-8 で保存されます。マニュアルにあるとおり、このファイルにはパネルの機能や WordPress が書き込んだ記述が入っていることがあるので、置き換えずに追記してください。</p>

<h2>例：キャッシュ期間をパネルより長くする</h2>
<p>エックスサーバーの「<a href="https://www.xserver.ne.jp/manual/man_server_expires.php">ブラウザキャッシュ設定</a>」は、各項目を最大 7 日間保持する値を指定する機能で、<code>.htaccess</code> で Expires ヘッダーを設定している場合はそちらが優先されます。CSS と JavaScript を 1 週間、画像を 3 か月、フォントを 1 年にしたい場合、ブラウザキャッシュだけをオンにして期間を選ぶと次のようになります。</p>

{/* hta-check: {"https":false,"index":false,"security":false,"cache":["3 months","1 week","1 year"]} */}

```apache
# Browser Caching
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/jpeg "access plus 3 months"
  ExpiresByType image/png "access plus 3 months"
  ExpiresByType image/gif "access plus 3 months"
  ExpiresByType image/svg+xml "access plus 3 months"
  ExpiresByType image/webp "access plus 3 months"
  ExpiresByType text/css "access plus 1 week"
  ExpiresByType application/javascript "access plus 1 week"
  ExpiresByType text/javascript "access plus 1 week"
  ExpiresByType font/woff "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
  ExpiresByType font/ttf "access plus 1 year"
  ExpiresByType application/x-font-ttf "access plus 1 year"
  ExpiresByType application/vnd.ms-fontobject "access plus 1 year"
</IfModule>
```

{/* hta-apache: {"override":"All","requests":[["/app.css",200,"max-age=604800"],["/a.ttf",200,"max-age=31536000"]]} */}

<p>Apache 2.4.67 では、CSS に <code>Cache-Control: max-age=604800</code>（7 日）、TTF に <code>max-age=31536000</code>（365 日）が付きました。CSS や JavaScript のファイル名にバージョンを付けていない場合、一度読み込んだブラウザーは、期限が切れるまで更新前のファイルを使い続けることがあります。</p>

<h2>制限とよくあるエラー</h2>
<ul>
  <li><strong>500 Internal Server Error：</strong>ディレクティブはすべて、そのディレクトリの <a href="https://httpd.apache.org/docs/2.4/mod/core.html#allowoverride">AllowOverride</a> で許可されている必要があります。<code>AllowOverride FileInfo</code> の環境では、<code>Options -Indexes</code> の 1 行だけでディレクトリ全体が 500 になりました。</li>
  <li><strong>すべてのページが 403：</strong><code>.htaccess</code> の <code>RewriteRule</code> には <code>Options FollowSymLinks</code> か <code>SymLinksIfOwnerMatch</code> が必要です。両方オフだと、規則に到達したリクエストはすべて拒否されます（エラーログ AH00670）。</li>
  <li><strong>CDN やロードバランサーの後ろで転送が止まらない：</strong><code>%&#123;HTTPS&#125;</code> は Apache 自身が受けた接続を表します。手前のプロキシが TLS を終端して Apache には HTTP で渡す構成では常に <code>off</code> になり、HTTPS 強制が繰り返されます。プロキシ側で HTTPS にするか、プロキシが付けるヘッダーを条件にしてください。</li>
  <li><strong>「www を強制」はサブドメインにも効く：</strong><code>www.</code> で始まらないホストすべてに <code>www.</code> を付けるので、<code>blog.example.jp</code> は <code>www.blog.example.jp</code> に、IP アドレスにも前置されます。</li>
  <li><strong>名前が完全一致するファイルだけを守る：</strong><code>.env</code> のブロックは <code>.env.local</code> や <code>.env.production</code> を守りません。こうしたファイルはドキュメントルートの外に置きます。</li>
  <li><strong>リダイレクト元は「/」から：</strong><a href="https://httpd.apache.org/docs/2.4/mod/mod_alias.html#redirect">Redirect</a> のリダイレクト元はスラッシュで始まるパスで、相対パスは使えません。<code>Redirect 301 old-page …</code> は Apache 2.4.67 でエラーにならずに読み込まれ、<code>/old-page</code> へのリクエストは転送されませんでした。そのため、リダイレクト元が <code>/</code> で始まらないときは、ジェネレーターはこの行を出力せず、「コピー」の下の状態表示でエラーを知らせます。ほかの規則はそのままコピーできます。</li>
  <li>カスタムリダイレクトは 1 件だけです。複数必要なら <code>Redirect</code> の行をコピーして書き換えます。Basic 認証、CORS、gzip / Brotli 圧縮の項目はありません。パスワードファイルは <a href="/ja/tools/htpasswd-generator/">htpasswd 生成ツール</a>で作れます。</li>
</ul>
