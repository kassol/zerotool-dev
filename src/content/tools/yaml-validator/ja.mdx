<h2>使い方</h2>
<ol>
  <li>YAMLの内容をテキストエリアに貼り付けます。</li>
  <li><strong>Validate</strong> ボタンをクリックします（または <kbd>Ctrl</kbd>+<kbd>Enter</kbd>）。</li>
  <li>YAMLが<strong>正しい</strong>場合、緑色の成功メッセージが表示され、解析済み構造がJSON形式で表示されます。</li>
  <li>YAMLが<strong>不正</strong>な場合、エラーボックスに理由・行番号・列番号と問題箇所のスニペットが表示されます。</li>
</ol>

<h2>エラー出力の見方</h2>

<p>バリデーション失敗時、エラーボックスには以下が含まれます：</p>
<ul>
  <li><strong>理由</strong> — 何が問題かの説明（例：<em>インデント不正</em>、<em>ストリームの予期しない終了</em>）。</li>
  <li><strong>行番号・列番号</strong> — 入力中のエラーの正確な位置。</li>
  <li><strong>スニペット</strong> — パーサーが示す前後のコンテキスト。多くの場合、問題の文字を指す <code>^</code> が含まれます。</li>
</ul>

<h2>よくあるYAML構文エラー</h2>
<ul>
  <li><strong>インデントの不統一</strong> — YAMLはネストにスペースのみを使用します（タブは禁止）。同じレベルで2スペースと4スペースを混在させると解析エラーになります。</li>
  <li><strong>キーの後のコロン欠如</strong> — <code>key value</code> は無効です。<code>key: value</code> と記述する必要があります。</li>
  <li><strong>特殊文字のクォートなし使用</strong> — 値に <code>:</code>・<code>#</code>・<code>[</code>・<code>]</code>・<code>{'{'}</code>・<code>{'}'}</code> などを含む場合は、クォートで囲むかエスケープする必要があります。</li>
  <li><strong>タブ文字</strong> — YAMLのインデントにタブは使用できません。すべてスペースに置き換えてください。</li>
  <li><strong>重複キー</strong> — 同じマッピングブロック内の重複キーは、YAML 1.2仕様では技術的に無効です。</li>
</ul>

<h2>例：正しいYAML</h2>

```yaml
server:
  host: localhost
  port: 8080
  tls: true

database:
  driver: postgres
  name: myapp
  credentials:
    user: admin
    password: "s3cr3t"

allowed_origins:
  - https://example.com
  - https://api.example.com
```

<h2>例：不正なYAML（インデントエラー）</h2>

```yaml
server:
  host: localhost
   port: 8080   # エラー：余分なスペースでインデントが不統一
```

<p>バリデーターは不整合が検出された行番号と列番号を報告するため、問題を素早く特定して修正できます。</p>

## 構文が正しくても構造が正しいとは限らない

バリデーターが報告するのは構文エラーです。解析できる YAML でも構造が意図と違うことがあるので、「解析結果」のプレビューを確認してください。次のファイルでは `carrot` のインデントが 2 つ足りません。

```yaml
fruits:
  - apple
vegetables:
- carrot
  - spinach
```

結果は「YAML は有効です」で、プレビューは `"vegetables": ["carrot - spinach"]` になります。次の行が `carrot` に連結され、1 つの文字列になっています。

## YAML 1.1 と 1.2 で値の解釈が違う

このツールは YAML 1.2 準拠の js-yaml 4.3.2 を使います。Python でよく使う PyYAML は YAML 1.1 準拠です。同じファイルでも結果が変わります。

| YAML | このツール（js-yaml 4.3.2） | PyYAML 6.0.3 `safe_load` |
|---|---|---|
| `debug: yes` | `"yes"`（文字列） | `True` |
| `country: NO` | `"NO"`（文字列） | `False` |
| `octal: 0777` | `777` | `511` |
| `time: 12:30` | `"12:30"`（文字列） | `750` |

YAML 1.1 のパーサーでも読まれるファイルでは、`"NO"`、`"yes"`、`"0777"` のような値を引用符で囲みます。

## よく出るエラーメッセージ

| 入力 | バリデーターのメッセージ |
|---|---|
| `message: Error: something went wrong` | bad indentation of a mapping entry（1:15）。値を引用符で囲む |
| `host:` の前にタブ | tab characters must not be used in indentation |
| 同じマッピングに `timeout` が 2 回 | duplicated mapping key |
| `server` のコロン抜け、次の行がインデント | end of the stream or a document separator is expected |

## 制限事項

- **複数ドキュメントは 1 つずつ検証します。** `---` で区切ったファイル（Deployment と Service を含む Kubernetes マニフェストなど）は js-yaml の `loadAll` で読み込みます。すべて有効ならプレビューはドキュメントごとに 1 要素の JSON 配列です。エラーがあると各ドキュメントを行範囲付きで並べ、有効かエラー内容かを示すので、壊れた Service があっても有効な Deployment は確認できます。
- **構文チェックのみ。** Kubernetes、GitHub Actions、Docker Compose のスキーマ検証や lint ルールは行いません。CI では [yamllint](https://github.com/adrienverge/yamllint)（`yamllint .`）を使います。
- **プレビューは JSON。** アンカーと `<<` マージキーは展開済みで、コメントは表示されません。
- **js-yaml の処理上限。** js-yaml 4.3.2 は、ネストが 100 階層を超える文書、マージキー（`<<`）で処理するマッピングとキーが合計 10,000 個を超える文書、1 つのマージキーに 100 個を超えるマッピングを並べた文書を止めます。エラーには「コレクションのネストが 100 階層を超えています（js-yaml の既定の上限）」のように上限と行・列が出ます。
