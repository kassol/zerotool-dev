<h2>JSONPath Syntax Reference (RFC 9535)</h2>
<ul>
  <li><code>{"$"}</code> — root of the document</li>
  <li><code>{".key"}</code>, <code>{"['key']"}</code>, <code>{"[\"key\"]"}</code> — member of an object</li>
  <li><code>{"[n]"}</code>, <code>{"[-1]"}</code> — array element; negative indexes count from the end</li>
  <li><code>{"[start:end:step]"}</code> — slice, for example <code>{"[0:2]"}</code>, <code>{"[1:]"}</code>, <code>{"[::-1]"}</code></li>
  <li><code>{"[0,2]"}</code>, <code>{"['title','price']"}</code> — several selectors in one bracket; results follow the order of the selectors</li>
  <li><code>{"[*]"}</code>, <code>{".*"}</code> — all array elements or object member values</li>
  <li><code>{"..key"}</code>, <code>{"..[0]"}</code>, <code>{"..*"}</code> — descendants at any depth</li>
  <li><code>{"[?@.price < 10]"}</code> — filter; also written <code>{"[?(@.price < 10)]"}</code></li>
  <li><code>{"[?@.isbn]"}</code>, <code>{"[?!@.isbn]"}</code> — members that exist / do not exist</li>
  <li><code>{"[?@.a.b == 'x' && @.c > $.min]"}</code> — nested paths, <code>{"&&"}</code> <code>{"||"}</code> <code>{"!"}</code>, and absolute $ paths inside a filter</li>
  <li><code>{"length()"}</code>, <code>{"count()"}</code>, <code>{"match()"}</code>, <code>{"search()"}</code>, <code>{"value()"}</code> — the five functions defined by RFC 9535</li>
</ul>

<h2>Limitations</h2>
<ul>
  <li>Syntax errors and syntax outside RFC 9535 are rejected with "Invalid or unsupported syntax" and the character position. Syntax outside RFC 9535 includes script expressions <code>{"[(...)]"}</code>, <code>{"=~"}</code>, <code>{"in"}</code> / <code>{"nin"}</code>, and extensions such as <code>{"~"}</code> for member names from other libraries.</li>
  <li><code>{"$.store.book.length"}</code> selects a member named <code>{"length"}</code>, which arrays do not have, so the result is empty. Use <code>{"length()"}</code> inside a filter, for example <code>{"$[?length(@.book) > 3]"}</code>.</li>
  <li>Results list the matched values. Normalized paths (such as <code>{"$['store']['book'][0]"}</code>) are not shown.</li>
  <li>Object members come back in the order JavaScript keeps them: names that are array indexes, such as <code>{'"2"'}</code> or <code>{'"10"'}</code>, first and in ascending order, then the other names in the order of your JSON (<a href="https://tc39.es/ecma262/#sec-ordinaryownpropertykeys" target="_blank" rel="noopener">ECMA-262 OrdinaryOwnPropertyKeys</a>). The pretty-printed Results use the same order. RFC 9535 §2.3.2.2 leaves the order open, so other implementations can differ.</li>
  <li>If an object has the same name twice, <code>{"JSON.parse"}</code> keeps the last value and the query never sees the first one.</li>
  <li>Member names are compared code point by code point, with no Unicode normalization (RFC 9535 §2.3.1.2 for name selectors; the tool compares strings in filters the same way): <code>{"é"}</code> typed as one character does not select a name stored as <code>{"e"}</code> plus a combining accent.</li>
  <li><code>{"match()"}</code> and <code>{"search()"}</code> run the pattern as a JavaScript regular expression with the <code>{"u"}</code> flag after changing <code>{"."}</code> to <code>{"[^\\n\\r]"}</code> (RFC 9485 §5.3). Patterns that JavaScript rejects give false; JavaScript-only syntax such as <code>{"\\d"}</code> or lookahead is accepted.</li>
  <li>Numbers are JavaScript numbers after <code>{"JSON.parse"}</code>. Integers above 2<sup>53</sup>, very long decimals, <code>{"-0"}</code> and numbers too large for a double change before they are compared and shown; the status line lists them (see the example below).</li>
  <li>The invalid-JSON message is the browser's own JavaScript parser message, so its wording depends on the browser.</li>
</ul>

<h2>Example: an ID Larger Than 2<sup>53</sup></h2>
<p>
  An order export that stores 64-bit IDs as JSON numbers looks fine in the input box, but a filter for one ID can match two orders:
</p>
{/* jpt-check: {"q":"$.orders[?@.id == 9007199254740993].total","json":"block","show":["compact","status"]} */}
```json
{"orders": [
  {"id": 9007199254740993, "total": 25.0},
  {"id": 9007199254740992, "total": 10}
]}
```
<p>
  <code>{"$.orders[?@.id == 9007199254740993].total"}</code> returns <code>{"[25,10]"}</code>, and the status line reads
</p>
```text
2 matches · Numbers that JavaScript cannot hold exactly (1): 9007199254740993 → 9007199254740992. Filters and Results use the JavaScript value.
```
<p>
  Both IDs become the same double, so the comparison cannot tell them apart; <code>{"25.0"}</code> is also shown as <code>{"25"}</code>, which is the same value and is not listed.
  RFC 8259 §6 says only integers in the range −(2<sup>53</sup>)+1 to 2<sup>53</sup>−1 are interoperable. Send such IDs as strings and compare them as strings: <code>{"[?@.id == '9007199254740993']"}</code>.
</p>

<p>
  When exactly one value matches, the Results panel shows that value on its own; with two or more, it shows a JSON array. Copy takes
  the panel as shown, so a single string is copied with its quotes. Results are pretty-printed with two-space indentation.
</p>

<h2>Other JSONPath Dialects</h2>
<p>
  Many tools say “JSONPath” but implement a different language. An expression that works here may need changes elsewhere, and the reverse:
</p>
<ul>
  <li><strong>kubectl</strong> uses JSONPath templates: the expression goes inside braces, the leading <code>{"$"}</code> is optional, and
  there are extra keywords such as <code>{"range"}</code> and <code>{"end"}</code>, as in <code>{"kubectl get pods -o jsonpath='{.items[*].metadata.name}'"}</code>.
  Paste only the part inside the braces here, with <code>{"$"}</code> added in front.</li>
  <li><strong>Jayway JsonPath</strong> (Java) and libraries based on Stefan Goessner's 2007 article accept script expressions, the
  <code>{"=~"}</code> regex operator and functions such as <code>{".length()"}</code> at the end of a path. This tool follows RFC 9535 and rejects them with the position of the problem.</li>
  <li><strong>AWS Step Functions</strong> accepts JsonPath in fields such as <code>{"InputPath"}</code>, but a reference path such as <code>{"ResultPath"}</code> must point to a single node and cannot use filters, wildcards or slices, which this tool accepts.</li>
</ul>
<p>
  To reshape JSON rather than only select from it, use the <a href="/tools/jq-playground/">jq Playground</a>; to check the document first, use the <a href="/tools/json-formatter/">JSON Formatter</a>.
</p>
