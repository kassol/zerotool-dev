  - question: "JSONPath란 무엇인가요?"
    answer: "JSONPath는 JSON을 위한 쿼리 언어로, XML의 XPath에 해당합니다. 경로 표현식을 사용하여 JSON 문서에서 노드를 선택합니다. RFC 9535(2024)로 표준화되었습니다. kubectl 출력 템플릿, AWS Step Functions, 여러 API 테스트 도구가 그 변형을 사용합니다."
  - question: "JSONPath 표현식에서 $는 무엇을 의미하나요?"
    answer: "$ 는 JSON 문서의 루트 요소를 가리킵니다. 유효한 JSONPath 표현식은 모두 $로 시작해야 합니다. 단독으로 사용하면 전체 문서를 선택하고, 이후에 선택자를 연결합니다(예: $.store.book[0].title)."
  - question: "배열의 모든 요소를 선택하려면 어떻게 하나요?"
    answer: "배열 키 뒤에 와일드카드 선택자 [*]를 사용합니다. 예를 들어 $.store.book[*]은 배열의 모든 book 객체를 반환합니다. 각 요소를 더 깊이 접근할 수도 있습니다: $.store.book[*].author는 모든 author 값을 반환합니다."
  - question: "필터 표현식은 어떻게 사용하나요?"
    answer: "필터는 [?표현식]으로 쓰고, @는 검사 중인 요소를 가리킵니다. RFC 9535에서는 괄호를 생략할 수 있어 $.store.book[?@.price < 10]과 $.store.book[?(@.price < 10)]은 같습니다. ==, !=, <, <=, >, >=로 비교하고, &&, ||, !로 조건을 조합하며, @.author.name 같은 중첩 경로, $로 시작하는 문서의 다른 값과의 비교, length(), count(), match(), search(), value() 함수를 쓸 수 있습니다."
  - question: "재귀 하강(..)이란 무엇인가요?"
    answer: ".. 연산자는 현재 노드의 모든 자손을 재귀적으로 검색합니다. 예를 들어 $..author는 중첩 깊이에 관계없이 JSON 트리 어디서든 모든 author 필드를 찾습니다."
  - question: "\"지원하지 않는 구문\"이 표시되는 이유는 무엇인가요?"

<h2>사용 방법</h2>
<ol>
  <li><strong>JSON 입력</strong> 패널에 JSON을 붙여넣거나 입력합니다(서점 샘플 데이터가 기본 로드됩니다).</li>
  <li><strong>JSONPath 표현식</strong> 필드에 표현식을 입력하거나 <strong>예시</strong> 버튼을 클릭합니다.</li>
  <li>결과가 구문 강조와 함께 <strong>결과</strong> 패널에 즉시 표시됩니다.</li>
  <li><strong>복사</strong>를 클릭하여 매칭된 출력을 클립보드에 복사합니다.</li>
</ol>

<h2>JSONPath 구문 참조 (RFC 9535)</h2>
<ul>
  <li><code>{"$"}</code> — 문서 루트</li>
  <li><code>{".key"}</code>, <code>{"['key']"}</code>, <code>{"[\"key\"]"}</code> — 객체 멤버</li>
  <li><code>{"[n]"}</code>, <code>{"[-1]"}</code> — 배열 요소. 음수 인덱스는 끝에서부터 셈</li>
  <li><code>{"[start:end:step]"}</code> — 슬라이스. 예: <code>{"[0:2]"}</code>, <code>{"[1:]"}</code>, <code>{"[::-1]"}</code></li>
  <li><code>{"[0,2]"}</code>, <code>{"['title','price']"}</code> — 대괄호 하나에 여러 선택자. 결과는 선택자 순서</li>
  <li><code>{"[*]"}</code>, <code>{".*"}</code> — 배열의 모든 요소 또는 객체의 모든 멤버 값</li>
  <li><code>{"..key"}</code>, <code>{"..[0]"}</code>, <code>{"..*"}</code> — 깊이에 관계없는 자손</li>
  <li><code>{"[?@.price < 10]"}</code> — 필터. <code>{"[?(@.price < 10)]"}</code>으로도 씀</li>
  <li><code>{"[?@.isbn]"}</code>, <code>{"[?!@.isbn]"}</code> — 멤버가 있음 / 없음</li>
  <li><code>{"[?@.a.b == 'x' && @.c > $.min]"}</code> — 필터 안의 중첩 경로, <code>{"&&"}</code> <code>{"||"}</code> <code>{"!"}</code>, $로 시작하는 절대 경로</li>
  <li><code>{"length()"}</code>, <code>{"count()"}</code>, <code>{"match()"}</code>, <code>{"search()"}</code>, <code>{"value()"}</code> — RFC 9535가 정의한 5개 함수</li>
</ul>

<h2>제한 사항</h2>
<ul>
  <li>RFC 9535에 없는 구문은 "지원하지 않는 구문"과 문자 위치를 표시합니다: 스크립트 표현식 <code>{"[(...)]"}</code>, <code>{"=~"}</code>, <code>{"in"}</code> / <code>{"nin"}</code>, 다른 라이브러리의 <code>{"~"}</code>(멤버 이름 가져오기) 같은 확장.</li>
  <li><code>{"$.store.book.length"}</code>는 <code>{"length"}</code>라는 이름의 멤버를 선택합니다. 배열에는 그런 멤버가 없으므로 결과가 비어 있습니다. 길이로 거르려면 필터 안에서 <code>{"length()"}</code>를 쓰세요(예: <code>{"$[?length(@.book) > 3]"}</code>).</li>
  <li>결과에는 매칭된 값만 나오고 정규화 경로(<code>{"$['store']['book'][0]"}</code> 등)는 표시하지 않습니다.</li>
  <li>객체 멤버는 JSON 텍스트에 적힌 순서대로 반환합니다. RFC 9535는 이 순서를 정하지 않으므로 다른 구현에서는 순서가 다를 수 있습니다.</li>
  <li><code>{"match()"}</code>와 <code>{"search()"}</code>는 <code>{"."}</code>을 <code>{"[^\\n\\r]"}</code>로 바꾼 뒤 <code>{"u"}</code> 플래그가 붙은 JavaScript 정규식으로 실행합니다(RFC 9485 §5.3). JavaScript가 거부하는 패턴은 false가 되고, <code>{"\\d"}</code>나 전방 탐색처럼 JavaScript에만 있는 구문도 받아들입니다.</li>
  <li>숫자는 <code>{"JSON.parse"}</code>로 JavaScript 숫자가 되므로 2<sup>53</sup>보다 큰 정수는 비교 전에 정밀도를 잃습니다.</li>
</ul>

<h2>주요 활용 사례</h2>
<p>
  JSONPath는 API 응답에서 데이터 추출, kubectl의 <code>{"-o jsonpath"}</code> 출력 템플릿,
  AWS Step Functions의 InputPath 같은 필드에서 쓰입니다.
  다만 각자 방언이 있어 kubectl은 식을 중괄호로 감싸고, Step Functions의 ResultPath에서는 필터를 쓸 수 없습니다. 이 도구는 RFC 9535에 따라 해석합니다.
  JSONPath 쿼리를 익히면 중첩된 JSON 구조를 다룰 때 시간을 크게 절약할 수 있습니다.
</p>
