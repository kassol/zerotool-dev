<h2>JSONPath 语法参考（RFC 9535）</h2>
<ul>
  <li><code>{"$"}</code> — 文档根节点</li>
  <li><code>{".key"}</code>、<code>{"['key']"}</code>、<code>{"[\"key\"]"}</code> — 对象成员</li>
  <li><code>{"[n]"}</code>、<code>{"[-1]"}</code> — 数组元素；负索引从末尾倒数</li>
  <li><code>{"[start:end:step]"}</code> — 切片，例如<code>{"[0:2]"}</code>、<code>{"[1:]"}</code>、<code>{"[::-1]"}</code></li>
  <li><code>{"[0,2]"}</code>、<code>{"['title','price']"}</code> — 一个方括号里放多个选择器，结果按选择器顺序排列</li>
  <li><code>{"[*]"}</code>、<code>{".*"}</code> — 全部数组元素或对象成员值</li>
  <li><code>{"..key"}</code>、<code>{"..[0]"}</code>、<code>{"..*"}</code> — 任意深度的后代</li>
  <li><code>{"[?@.price < 10]"}</code> — 过滤器；也可写成 <code>{"[?(@.price < 10)]"}</code></li>
  <li><code>{"[?@.isbn]"}</code>、<code>{"[?!@.isbn]"}</code> — 成员存在 / 不存在</li>
  <li><code>{"[?@.a.b == 'x' && @.c > $.min]"}</code> — 过滤器内的嵌套路径、<code>{"&&"}</code> <code>{"||"}</code> <code>{"!"}</code>、以 $ 开头的绝对路径</li>
  <li><code>{"length()"}</code>、<code>{"count()"}</code>、<code>{"match()"}</code>、<code>{"search()"}</code>、<code>{"value()"}</code> — RFC 9535 定义的 5 个函数</li>
</ul>

<h2>限制</h2>
<ul>
  <li>RFC 9535 之外的语法会显示「不支持的语法」和字符位置：脚本表达式 <code>{"[(...)]"}</code>、<code>{"=~"}</code>、<code>{"in"}</code> / <code>{"nin"}</code>，以及其他库用 <code>{"~"}</code> 取成员名之类的扩展。</li>
  <li><code>{"$.store.book.length"}</code> 选取名为 <code>{"length"}</code> 的成员，数组没有这个成员，所以结果为空。要按长度筛选，请在过滤器中用 <code>{"length()"}</code>，例如 <code>{"$[?length(@.book) > 3]"}</code>。</li>
  <li>结果只列出匹配的值，不显示规范化路径（如 <code>{"$['store']['book'][0]"}</code>）。</li>
  <li>对象成员按 JSON 文本中的顺序返回。RFC 9535 没有规定这个顺序，其他实现可能不同。</li>
  <li><code>{"match()"}</code> 与 <code>{"search()"}</code> 把 <code>{"."}</code> 换成 <code>{"[^\\n\\r]"}</code> 后，按带 <code>{"u"}</code> 标志的 JavaScript 正则执行（RFC 9485 §5.3）。JavaScript 不接受的模式结果为 false；<code>{"\\d"}</code>、先行断言等只有 JavaScript 支持的写法也会被接受。</li>
  <li>数字经 <code>{"JSON.parse"}</code> 转成 JavaScript 数字，大于 2<sup>53</sup> 的整数在比较前就已丢失精度。</li>
</ul>

<h2>常见使用场景</h2>
<p>
  JSONPath 常用于从 API 响应中提取数据、编写 kubectl 的 <code>{"-o jsonpath"}</code> 输出模板，以及 AWS Step Functions 的 InputPath 等字段。
  这些地方用的是各自的方言：kubectl 要求表达式写在大括号里，Step Functions 的 ResultPath 不能用过滤器；本工具按 RFC 9535 解析。
  熟练掌握 JSONPath 查询可以大幅提高处理嵌套 JSON 结构的效率。
</p>
