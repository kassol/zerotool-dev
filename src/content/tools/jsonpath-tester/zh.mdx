<h2>JSONPath 语法参考（RFC 9535）</h2>
<ul>
  <li><code>{"$"}</code> — 文档根节点</li>
  <li><code>{".key"}</code>、<code>{"['key']"}</code>、<code>{"[\"key\"]"}</code> — 对象成员</li>
  <li><code>{"[n]"}</code>、<code>{"[-1]"}</code> — 数组元素；负索引从末尾倒数</li>
  <li><code>{"[start:end:step]"}</code> — 切片，例如<code>{"[0:2]"}</code>、<code>{"[1:]"}</code>、<code>{"[::-1]"}</code></li>
  <li><code>{"[0,2]"}</code>、<code>{"['title','price']"}</code> — 一个方括号里放多个选择器，结果按选择器顺序排列</li>
  <li><code>{"[*]"}</code>、<code>{".*"}</code> — 全部数组元素或对象成员值</li>
  <li><code>{"..key"}</code>、<code>{"..[0]"}</code>、<code>{"..*"}</code> — 任意深度的后代</li>
  <li><code>{"[?@.price < 10]"}</code> — 过滤器；也可写成 <code>{"[?(@.price < 10)]"}</code></li>
  <li><code>{"[?@.isbn]"}</code>、<code>{"[?!@.isbn]"}</code> — 成员存在 / 不存在</li>
  <li><code>{"[?@.a.b == 'x' && @.c > $.min]"}</code> — 过滤器内的嵌套路径、<code>{"&&"}</code> <code>{"||"}</code> <code>{"!"}</code>、以 $ 开头的绝对路径</li>
  <li><code>{"length()"}</code>、<code>{"count()"}</code>、<code>{"match()"}</code>、<code>{"search()"}</code>、<code>{"value()"}</code> — RFC 9535 定义的 5 个函数</li>
</ul>

## 示例：中文键名的订单数据

键名可以直接用中文，点号写法 <code>{"$.订单"}</code> 与方括号写法 <code>{"$['订单']"}</code> 都能用（RFC 9535 允许 ASCII 以外的字符出现在点号后的名称里）。下面是一份虚构的订单数据，第 3 条的金额被后端写成了字符串：

{/* jpt-check: {"q":"$.订单[?@.状态 == '已发货'].编号","json":"block"} */}
```json
{"订单": [
  {"编号": "A1001", "商品": "机械键盘", "金额": 399, "状态": "已发货"},
  {"编号": "A1002", "商品": "USB-C 数据线", "金额": 29.9, "状态": "待付款"},
  {"编号": "A1003", "商品": "显示器支架", "金额": "159.00", "状态": "已发货"}
]}
```

<code>{"$.订单[?@.状态 == '已发货'].编号"}</code> 得到 <code>{'["A1001","A1003"]'}</code>。

{/* jpt-check: {"q":"$.订单[?@.金额 > 100].商品","json":"{\"订单\": [{\"编号\": \"A1001\", \"商品\": \"机械键盘\", \"金额\": 399, \"状态\": \"已发货\"}, {\"编号\": \"A1002\", \"商品\": \"USB-C 数据线\", \"金额\": 29.9, \"状态\": \"待付款\"}, {\"编号\": \"A1003\", \"商品\": \"显示器支架\", \"金额\": \"159.00\", \"状态\": \"已发货\"}]}"} */}
再用 <code>{"$.订单[?@.金额 > 100].商品"}</code> 找金额超过 100 的商品，结果只有 <code>{'["机械键盘"]'}</code>，显示器支架没有出现：它的金额是字符串 <code>{'"159.00"'}</code>，RFC 9535 §2.3.5.2.2 规定只有两边同为数字或同为字符串时 < 、> 才可能为真，工具不会提示。看到这种「少了一条」的结果，先检查字段类型。

## 中文输入法打出的符号

在中文标点状态下输入表达式时，<code>{"["}</code> 可能变成 <code>{"【"}</code>，<code>{"$"}</code> 可能变成 <code>{"￥"}</code>。这两类字符混进表达式后，读法不同：

{/* jpt-check: {"q":"￥.订单","json":"{\"订单\": []}","show":["status"]} */}
- 开头写成 <code>{"￥.订单"}</code> 时，状态行显示 <code>{"不支持的语法: 查询必须以 $ 开头（第 1 个字符）"}</code>。

{/* jpt-check: {"q":"$.订单【0】.商品","json":"{\"订单\": [{\"商品\": \"机械键盘\"}]}","show":["panel","status"]} */}
- 写在名称中间时不会报错。<code>{"$.订单【0】.商品"}</code> 会被读成名为「订单【0】」的成员，结果是 <code>{"未找到匹配项"}</code>，状态行提示 <code>{"表达式含全角字符（【 】）。JSONPath 把它们读作成员名的一部分，不当作 . [ ] * 或 $；请改用半角（ASCII）输入。"}</code> 改成半角的 <code>{"$.订单[0].商品"}</code> 即可。

## 对象成员的顺序

<code>{"$.地区.*"}</code> 这类通配查询按 JavaScript 保存对象成员的顺序返回：形如数组下标的名称（如 <code>{'"110000"'}</code>）排在前面并按数值升序，其余名称按 JSON 里的顺序排在后面。以地区代码为键的数据会被重新排序：

{/* jpt-check: {"q":"$.地区.*","json":"block"} */}
```json
{"地区": {"440000": "广东省", "110000": "北京市", "310000": "上海市"}}
```

结果是 <code>{'["北京市","上海市","广东省"]'}</code>，不是 JSON 里的顺序。RFC 9535 没有规定对象成员的顺序，其他实现可能给出不同的顺序；需要固定顺序时请把数据改成数组。

<h2>限制</h2>
<ul>
  <li>RFC 9535 之外的语法会显示「不支持的语法」和字符位置：脚本表达式 <code>{"[(...)]"}</code>、<code>{"=~"}</code>、<code>{"in"}</code> / <code>{"nin"}</code>，以及其他库用 <code>{"~"}</code> 取成员名之类的扩展。</li>
  <li><code>{"$.store.book.length"}</code> 选取名为 <code>{"length"}</code> 的成员，数组没有这个成员，所以结果为空。要按长度筛选，请在过滤器中用 <code>{"length()"}</code>，例如 <code>{"$[?length(@.book) > 3]"}</code>。</li>
  <li>结果只列出匹配的值，不显示规范化路径（如 <code>{"$['store']['book'][0]"}</code>）。</li>
  <li>同一对象里出现两个同名键时，<code>{"JSON.parse"}</code> 只保留后一个值，查询看不到前一个。</li>
  <li>名称按码点逐个比较，不做 Unicode 规范化（RFC 9535 §2.3.1.2）。</li>
  <li><code>{"match()"}</code> 与 <code>{"search()"}</code> 把 <code>{"."}</code> 换成 <code>{"[^\\n\\r]"}</code> 后，按带 <code>{"u"}</code> 标志的 JavaScript 正则执行（RFC 9485 §5.3）。JavaScript 不接受的模式结果为 false；<code>{"\\d"}</code>、先行断言等只有 JavaScript 支持的写法也会被接受。</li>
  <li>数字经 <code>{"JSON.parse"}</code> 转成 JavaScript 数字。超过 2<sup>53</sup> 的整数、位数过多的小数、<code>{"-0"}</code> 以及超出双精度范围的数会在比较和显示前改变，状态行会列出这些数字，例如 <code>{"9007199254740993 → 9007199254740992"}</code>。按 RFC 8259 §6，只有 −(2<sup>53</sup>)+1 到 2<sup>53</sup>−1 之间的整数能在各实现间通用，雪花 ID 这类长整数请以字符串传递。</li>
  <li>JSON 格式错误时显示的是浏览器 JavaScript 解析器的原始信息，措辞因浏览器而异。</li>
</ul>

<h2>与其他 JSONPath 方言的区别</h2>
<p>
  kubectl 的 <code>{"-o jsonpath"}</code> 模板把表达式写在大括号里，开头的 <code>{"$"}</code> 可以省略；粘贴到这里时只取大括号里的部分，并在前面补上 <code>{"$"}</code>。
  Java 的 Jayway JsonPath 接受脚本表达式、<code>{"=~"}</code> 和路径末尾的 <code>{".length()"}</code>，本工具按 RFC 9535 解析，会报错并指出位置。
  只想筛选数据时用本工具即可；要改写 JSON 的结构，请用 <a href="/zh/tools/jq-playground/">jq Playground</a>。
</p>
