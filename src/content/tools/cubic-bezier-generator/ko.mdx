<h2>커스텀 cubic-bezier가 필요한 순간</h2>

<p>linear / ease / ease-in / ease-out / ease-in-out 다섯 키워드로 일상적인 경우는 대부분 충분합니다. 다음과 같을 때는 커스텀 cubic-bezier가 필요합니다.</p>
<ul>
  <li>디자인 시스템에 모션 곡선이 정해져 있을 때 — Material Design 2 표준 곡선 <code>(0.4, 0, 0.2, 1)</code>, Material 3의 <code>(0.2, 0, 0, 1)</code>, Tailwind의 <code>ease-in-out</code>, 아래 예시의 KRDS 컴포넌트 값.</li>
  <li>지나침이나 예비 동작이 필요할 때 — 모달 팝업, 드로어 드래그, 버튼 누름 피드백.</li>
  <li>Figma나 After Effects의 타이밍 곡선을 실제 코드에서 같은 숫자로 쓰고 싶을 때.</li>
</ul>

<h2>한눈에 곡선 읽기</h2>

<p>X축은 정규화된 시간(시작 0, 끝 1), Y축은 애니메이션 진행도입니다. 대각선 그대로면 linear입니다. 곡선이 대각선 아래로 처지면 천천히 출발해 끝에서 따라잡고(ease-in 느낌), 위로 부풀면 빠르게 출발해 점점 느려집니다(ease-out 느낌). 아래에서 위로 S자를 그리면 ease-in-out입니다. 0 아래로 내려가거나 1을 넘으면 "스프링" 같은 움직임이 생기는데, 장식적인 UI에는 어울리지만 기능 흐름에서는 리듬을 끊을 수 있습니다.</p>

<h2>KRDS 컴포넌트의 곡선 확인하기</h2>

<p>대한민국 디지털 정부를 위한 디자인 시스템 KRDS(Korea Responsive Design System)는 npm 패키지 <a href="https://www.npmjs.com/package/krds-uiux/v/1.1.0" target="_blank" rel="noopener">krds-uiux</a>로 배포됩니다. 1.1.0 버전의 SCSS에서 스위치(<code>resources/scss/component/_switch.scss</code>)는 <code>transition: .4s cubic-bezier(.4, .0, .23, 1)</code>을, 아코디언(<code>_accordion.scss</code>)의 접힌 상태 규칙은 <code>transition: all .5s cubic-bezier(0, 1, 0, 1)</code>을 씁니다. 아래 코드 블록은 편집기의 실제 출력이고, <code>x → y</code> 줄은 시간이 x만큼 지났을 때 미리보기가 쓰는 진행도(소수 셋째 자리)입니다.</p>

<h3>스위치: Material 2 표준과 거의 같은 곡선</h3>

<p>숫자 입력에 <code>0.4</code>, <code>0</code>, <code>0.23</code>, <code>1</code>을 넣습니다.</p>

{/* cbg-check: {"p":["0.4","0","0.23","1"],"x":["0.25","0.5","0.75"]} */}

```css
transition-timing-function: cubic-bezier(0.4, 0, 0.23, 1);
```

```
x = 0.25 → y = 0.223
x = 0.5 → y = 0.758
x = 0.75 → y = 0.956
```

<p>프리셋의 Material 2 표준을 누르면 다음과 같습니다.</p>

{/* cbg-check: {"preset":"0.4,0,0.2,1","x":["0.25","0.5","0.75"]} */}

```css
transition-timing-function: cubic-bezier(0.4, 0, 0.2, 1);
```

```
x = 0.25 → y = 0.237
x = 0.5 → y = 0.776
x = 0.75 → y = 0.959
```

<p>같은 시점의 차이는 2%포인트 이내라서 0.4초 동안에는 거의 구분되지 않습니다. KRDS 화면에 Material 2 표준 곡선을 쓰는 다른 컴포넌트를 섞어도 움직임이 크게 어긋나지 않는다는 뜻입니다.</p>

<h3>아코디언: 처음 25밀리초에 74.8%</h3>

{/* cbg-check: {"p":["0","1","0","1"],"x":["0.05","0.1","0.2"]} */}

```css
transition-timing-function: cubic-bezier(0, 1, 0, 1);
```

```
x = 0.05 → y = 0.748
x = 0.1 → y = 0.846
x = 0.2 → y = 0.928
```

<p>CSS 트랜지션은 바뀐 뒤의 스타일에 적힌 값을 씁니다(<a href="https://www.w3.org/TR/css-transitions-1/#starting" target="_blank" rel="noopener">CSS Transitions Level 1 §3</a>의 after-change style). 이 곡선은 <code>.active</code>가 없는 상태의 규칙에 있으므로 아코디언이 닫힐 때 쓰입니다. 0.5초 중 처음 5%인 25밀리초에 <code>max-height</code> 변화의 74.8%가 끝나니, 사용자에게는 거의 바로 닫히는 것처럼 보입니다. 열릴 때는 <code>.active</code> 규칙의 <code>1.5s ease-in-out</code>이 쓰입니다.</p>

<h2>제한 사항</h2>

<ul>
  <li>값은 소수 셋째 자리까지 유지합니다. 드래그로 생긴 더 세밀한 값은 숫자 입력과 복사 결과에서 셋째 자리로 반올림합니다.</li>
  <li>y는 −2~2로 제한됩니다. 미리보기에 그 범위만큼의 여백만 있기 때문입니다. CSS는 y에 어떤 값이든 받으므로, 범위를 넘는 값을 입력하면 경곗값으로 복사되고 상태 표시줄에 안내가 나옵니다. 더 큰 값은 CSS에 직접 쓰세요.</li>
  <li>x에 0~1을 벗어난 값을 넣으면 범위 안으로 맞추고 안내를 표시합니다. 그런 값을 CSS에 그대로 쓰면 선언 전체가 무효가 됩니다.</li>
  <li><code>cubic-bezier()</code>만 만듭니다. <code>steps()</code>나 여러 점을 쓰는 <code>linear()</code> 함수는 만들 수 없으므로 여러 번 튀는 바운스는 표현할 수 없습니다.</li>
  <li>미리보기 시간(100~10,000밀리초)과 반복은 미리보기에만 쓰이고 복사한 코드에는 들어가지 않습니다. <code>transition-duration</code>은 따로 쓰세요.</li>
  <li>Tailwind 탭은 v3의 <code>tailwind.config.js</code> 형식이며 키 이름은 <code>custom</code>으로 고정입니다. v4에서는 <code>@config</code>나 <code>--ease-*</code> 테마 변수를 쓰세요.</li>
</ul>

<h2>개인정보 처리</h2>

<p>곡선 계산, 애니메이션 미리보기, 복사는 브라우저 안에서 처리됩니다. 컨트롤 포인트, 시간, 출력 형식은 이 기기의 localStorage에 저장되며 초기화하면 지워집니다. 페이지는 Google Analytics를 불러오지만, 복사에 성공했을 때 도구 이름과 형식(<code>copy_css</code> 등)만 기록하고 숫자는 기록하지 않습니다.</p>
