<h2>When to reach for a custom cubic-bezier</h2>

<p>CSS Easing Functions Level 1 defines <code>linear</code>, four cubic-bezier keywords (<code>ease</code>, <code>ease-in</code>, <code>ease-out</code>, <code>ease-in-out</code>) and two step keywords (<code>step-start</code>, <code>step-end</code>), which jump instead of following a curve. This editor makes <code>cubic-bezier()</code> curves only; it has presets for <code>linear</code> and the four cubic-bezier keywords, and none for the step keywords. The keywords cover the everyday cases. You need a custom cubic-bezier when:</p>
<ul>
  <li>Your design system has a defined motion language — Material Design 2's standard curve <code>(0.4, 0, 0.2, 1)</code>, Material 3's <code>(0.2, 0, 0, 1)</code>, or Tailwind's <code>ease-in-out</code>.</li>
  <li>The animation should overshoot or anticipate — modal pop-ins, drawer drags, button press feedback.</li>
  <li>You want to match a Figma or After Effects timing curve so the prototype and the production build use the same numbers.</li>
</ul>

<h2>Reading the curve at a glance</h2>

<p>The X axis is normalized time (0 at the start, 1 at the end). The Y axis is animation progress. A diagonal line means linear. A curve that sags below the diagonal starts slowly and catches up at the end (ease-in feel). A curve that bulges above starts fast and slows down (ease-out feel). An S-shape, below then above, is ease-in-out. When the curve dips below 0 or above 1, you get the "spring" effect — useful for playful UI but distracting in functional flows.</p>

<h2>Worked examples</h2>

<p>Each example below was produced by the editor itself: the output block is what Copy puts on the clipboard, and the <code>x → y</code> lines are the progress the preview uses at that moment of the animation, rounded to three decimals.</p>

<h3>The Back preset, copied as SCSS</h3>

<p>Click <strong>Back (overshoot)</strong> and choose the SCSS tab:</p>

{/* cbg-check: {"preset":"0.68,-0.55,0.265,1.55","format":"scss","x":["0.1","0.2","0.5","0.8"]} */}

```scss
$ease-custom: cubic-bezier(0.68, -0.55, 0.265, 1.55);
```

```
x = 0.1 → y = -0.066
x = 0.2 → y = -0.093
x = 0.5 → y = 0.607
x = 0.8 → y = 1.092
```

<p>For the first fifth of the duration the element moves backwards (y below 0), and near the end it passes its target by about 9% before it settles at 1.</p>

<h3>Material 2 standard against Material 3 standard</h3>

<p>Both are called "standard", but they move at different speeds. Click <strong>Material 2 Std</strong>:</p>

{/* cbg-check: {"preset":"0.4,0,0.2,1","x":["0.25","0.5"]} */}

```css
transition-timing-function: cubic-bezier(0.4, 0, 0.2, 1);
```

```
x = 0.25 → y = 0.237
x = 0.5 → y = 0.776
```

<p>Then click <strong>Material 3 Std</strong>:</p>

{/* cbg-check: {"preset":"0.2,0,0,1","x":["0.25","0.5"]} */}

```css
transition-timing-function: cubic-bezier(0.2, 0, 0, 1);
```

```
x = 0.25 → y = 0.607
x = 0.5 → y = 0.878
```

<p>A quarter of the way through the duration, the Material 3 curve has covered 60.7% of the distance and the Material 2 curve 23.7%. If you update an app from Material 2 to Material 3, the same 300 ms transition will look faster at the start.</p>

<h3>A Tailwind theme value</h3>

<p>The Tailwind CSS v4 documentation uses <code>cubic-bezier(0.3, 0, 0, 1)</code> as an example theme value. Type <code>0.3</code>, <code>0</code>, <code>0</code>, <code>1</code> into the fields and choose the Tailwind tab:</p>

{/* cbg-check: {"p":["0.3","0","0","1"],"format":"tailwind"} */}

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      transitionTimingFunction: {
        'custom': 'cubic-bezier(0.3, 0, 0, 1)',
      },
    },
  },
};
```

<p>This is the v3 JavaScript configuration. In a v4 project, either load the file with <code>@config "./tailwind.config.js";</code> or write the value as a theme variable, <code>{'@theme { --ease-custom: cubic-bezier(0.3, 0, 0, 1); }'}</code>; both give the class <code>ease-custom</code>.</p>

<h2>Limits</h2>

<ul>
  <li>Values keep at most three decimals. Dragging gives finer numbers, which are rounded to three in the fields and in the copied output.</li>
  <li>Y is limited to −2–2, because the preview has room for that range only. CSS itself accepts any y value; a token such as <code>cubic-bezier(0.55, 2.05, 0.65, 0.75)</code> is copied as <code>2</code> and the editor shows a message. Write larger values into your CSS by hand.</li>
  <li>An x value typed outside 0–1 is clamped and a message appears; CSS would reject the whole declaration.</li>
  <li>The editor makes only <code>cubic-bezier()</code>. It does not make <code>steps()</code> or the <code>linear()</code> function with several points, so it cannot draw a bounce with more than one rebound.</li>
  <li>The preview duration (100–10,000 ms) and Loop only control the preview; they are not part of the copied code. Add your own <code>transition-duration</code>.</li>
  <li>The Tailwind tab prints the v3 <code>tailwind.config.js</code> format with the key <code>custom</code>; in v4 use <code>@config</code> or a <code>--ease-*</code> theme variable, as shown above.</li>
</ul>
