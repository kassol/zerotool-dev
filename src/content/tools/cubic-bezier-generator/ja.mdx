<h2>カスタム cubic-bezier が必要な場面</h2>

<p>CSS Easing Functions Level 1 のキーワードは、<code>linear</code>、ベジェ曲線の 4 つ（<code>ease</code>、<code>ease-in</code>、<code>ease-out</code>、<code>ease-in-out</code>）、それに曲線ではなく段階的に切り替わる <code>step-start</code>・<code>step-end</code> です。このエディタが作るのは <code>cubic-bezier()</code> の曲線だけで、プリセットには <code>linear</code> とベジェ曲線の 4 つのキーワードがあり、step 系はありません。これらのキーワードで十分なことも多いですが、次のようなときはカスタム曲線が必要です。</p>
<ul>
  <li>デザインシステムでモーションが決まっている — Material Design 2 の標準曲線 <code>(0.4, 0, 0.2, 1)</code>、Material 3 の <code>(0.2, 0, 0, 1)</code>、Tailwind の <code>ease-in-out</code>、下の例の Spindle など。</li>
  <li>オーバーシュートや予備動作がほしい — モーダルのポップイン、ドロワーのドラッグ、ボタンを押したときの反応。</li>
  <li>Figma や After Effects のタイミング曲線と、本番のコードで同じ数値を使いたい。</li>
</ul>

<h2>曲線の読み方</h2>

<p>X 軸は正規化された時間（開始 0、終了 1）、Y 軸はアニメーションの進み具合です。対角線そのままなら linear。対角線より下にたわむ曲線はゆっくり始まって終盤で追いつき（ease-in 寄り）、上に膨らむ曲線は出だしが速くだんだん遅くなります（ease-out 寄り）。下から上へ S 字を描けば ease-in-out です。0 を下回ったり 1 を超えたりすると「バネ」のような動きになり、装飾的な UI には合いますが、操作の流れの中では邪魔になることもあります。</p>

<h2>Spindle のイージングを試す</h2>

<p>Ameba のデザインシステム Spindle は、デザイントークンを npm パッケージ <a href="https://www.npmjs.com/package/@openameba/spindle-tokens/v/1.10.0" target="_blank" rel="noopener">@openameba/spindle-tokens</a> として公開しています。バージョン 1.10.0 の <code>dist/css/spindle-tokens.css</code> には 4 つのイージングがあります。以下のコードブロックはエディタの実際の出力で、<code>x → y</code> の行は、時間が x まで進んだときにプレビューが使う進み具合（小数第 3 位まで）です。</p>

<h3>--animation-easing-ease-out：最初の 1 割でほぼ半分</h3>

<p>数値欄に <code>0</code>、<code>0</code>、<code>0</code>、<code>1</code> と入力します。</p>

{/* cbg-check: {"p":["0","0","0","1"],"x":["0.1","0.25"]} */}

```css
transition-timing-function: cubic-bezier(0, 0, 0, 1);
```

```
x = 0.1 → y = 0.446
x = 0.25 → y = 0.691
```

<p>CSS の <code>ease-out</code> キーワード（プリセットの Ease-Out）と比べてみます。</p>

{/* cbg-check: {"preset":"0,0,0.58,1","x":["0.1","0.25"]} */}

```css
transition-timing-function: cubic-bezier(0, 0, 0.58, 1);
```

```
x = 0.1 → y = 0.161
x = 0.25 → y = 0.378
```

<p>同じ「ease-out」という名前でも、Spindle の曲線は時間の 1 割で 44.6% 進み、CSS のキーワードは 16.1% です。トークン名だけを見て CSS のキーワードに置き換えると、動きの印象が変わります。</p>

<h3>--animation-easing-ease-out-bounce：このエディタで扱えない値</h3>

{/* cbg-check: {"p":["0.55","2.05","0.65","0.75"],"warn":"y","x":["0.5"]} */}

<p>このトークンの値は <code>cubic-bezier(0.55, 2.05, 0.65, 0.75)</code> で、P1.y が 2 を超えています。数値欄に <code>0.55</code>、<code>2.05</code>、<code>0.65</code>、<code>0.75</code> と入力すると、ステータス欄に「このエディタでは P1.y / P2.y を −2〜2 に制限しています。自動的にクランプしました。」と表示され、出力は次のようになります。</p>

```css
transition-timing-function: cubic-bezier(0.55, 2, 0.65, 0.75);
```

```
x = 0.5 → y = 1.149
```

<p>コピーされるのは 2.05 ではなく、上限の 2 に収めた（クランプした）曲線です。CSS 自体は y にどんな値でも受け付けるので、このトークンを使うときはコピーした後で 2 を 2.05 に戻すか、トークンの値をそのまま CSS に書いてください。</p>

<p>時間は逆行しないので、2 つの制御点の x は 0〜1 の範囲に収める必要があり、エディタが自動で制限します。y はこの範囲を超えてもよく、Back プリセットのオーバーシュートはそれで生まれます。</p>

<h2>制限</h2>

<ul>
  <li>数値は小数第 3 位まで保持します。ドラッグで得られる細かい値は、数値欄でもコピーでも第 3 位に丸めます。</li>
  <li>y は −2〜2 に制限します。プレビューにその範囲の余白しかないためです。CSS は y にどんな値でも受け付けるので、Spindle の bounce のように 2 を超える値は、上の例のように手で書き直してください。</li>
  <li>x に 0〜1 の範囲外を入力すると範囲内に収め、メッセージを表示します。範囲外の値を CSS に書くと、宣言全体が無効になります。</li>
  <li>生成できるのは <code>cubic-bezier()</code> だけです。<code>steps()</code> や複数の点を持つ <code>linear()</code> 関数は作れないので、何度も弾むバウンスは表現できません。</li>
  <li>プレビュー時間（100〜10,000 ミリ秒）とループはプレビュー専用で、コピーするコードには入りません。<code>transition-duration</code> は別に書いてください。</li>
  <li>Tailwind タブは v3 の <code>tailwind.config.js</code> 形式で、キー名は <code>custom</code> 固定です。v4 では <code>@config</code> か <code>--ease-*</code> テーマ変数を使います。</li>
</ul>

<h2>プライバシー</h2>

<p>曲線の計算、アニメーションのプレビュー、コピーはブラウザの中で行います。制御点、時間、出力形式はこの端末の localStorage に保存し、リセットで消えます。ページは Google Analytics を読み込みますが、コピーに成功したときに記録するのはツール名と形式（<code>copy_css</code> など）だけで、数値は記録しません。</p>
