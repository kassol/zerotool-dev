<h2>How to Use</h2>
<ol>
  <li>Set the <strong>Length</strong> slider or type a number from 4 to 128. A new password appears as soon as the value changes.</li>
  <li>Tick the character sets the target system accepts: uppercase, lowercase, digits, symbols. At least one must stay selected.</li>
  <li>Tick <strong>Exclude ambiguous</strong> if the password will be read aloud or typed from paper; it removes <code>0 O l 1 I</code>.</li>
  <li>Read the meter: it shows the entropy in bits for the current settings and a label from Very Weak to Very Strong.</li>
  <li>Click the copy icon, or click <strong>Generate</strong> for another password. <strong>Generate 10</strong> fills the box below with ten passwords, one per line.</li>
</ol>

<h2>How the Strength Number Is Calculated</h2>
<p>
  The meter does not guess how "complex" a password looks. Because every character is drawn uniformly
  from the selected set, the number of possible passwords is <em>set size</em> raised to <em>length</em>,
  and the entropy in bits is <code>length × log2(set size)</code>. The labels are fixed bands:
  under 40 bits Very Weak, 40–59 Weak, 60–79 Fair, 80–99 Strong, 100 and above Very Strong.
</p>

</p>

<h2>Example Output</h2>
<p>One run with the default settings (all four sets, 20 characters) printed:</p>
<p><code>{'_Q;.Q{4(W$WiO=@^[@O!'}</code> — Very Strong (129 bits)</p>
<p>With <strong>Exclude ambiguous</strong> on and length 16 it printed <code>{'p#mzk<#nEyeXu#UU'}</code> (102 bits), and with only lowercase and digits at length 12 it printed <code>gbkh5k0nlo2r</code> (62 bits). Your results will differ on every click; that is the point.</p>
<p>
  Notice the first example repeats <code>@</code>, <code>Q</code> and <code>O</code>. Repeats are normal in a
  random string and do not lower the entropy; a generator that avoided them would actually have fewer possible outputs.
</p>

<h2>Limits</h2>
<ul>
  <li><strong>Length 4 to 128.</strong> Values outside the range are clamped. NIST SP 800-63B asks sites to accept at least 64 characters, but many still cap length lower; check before pasting a 128-character password.</li>
  <li><strong>No "one of each" guarantee.</strong> Characters are drawn independently, so a password can lack a digit or a symbol. With all four sets, a 20-character password has no digit about 9% of the time and a 12-character one about 24% of the time. Sites that enforce such rules will reject it; generate again.</li>
  <li><strong>Fixed symbol list.</strong> 26 ASCII symbols are used; <code>{'" \' / \\ ` ~'}</code> and space are never included, and there is no field for a custom set or for removing single symbols.</li>
  <li><strong>No passphrases.</strong> The tool makes character passwords only, not word-list passphrases (Diceware-style).</li>
  <li><strong>bcrypt truncates.</strong> If the password will be hashed with bcrypt, only the first 72 bytes count; a 128-character password gives no extra protection there. To produce a bcrypt hash, use the <a href="/tools/bcrypt-generator/">bcrypt generator</a>.</li>
  <li><strong>Nothing is kept.</strong> The batch box and the output are cleared when the page reloads. Copy the password into a password manager before leaving.</li>
</ul>

<h2>What the Standards Say About Password Rules</h2>
<p>
  <a href="https://pages.nist.gov/800-63-4/sp800-63b.html">NIST SP 800-63B</a> requires at least 15 characters for a
  password used as a single factor (8 when it is part of multi-factor login), says services should accept all printing ASCII
  characters and spaces, and forbids composition rules such as "must contain a symbol" and forced periodic changes. A long,
  random password from this page satisfies any length rule; the symbol option exists mainly for older sites that still demand one.
</p>

<h2>Password Security Tips</h2>
<ul>
  <li>Use a unique password for every account. A password manager makes this practical.</li>
  <li>Enable two-factor authentication wherever possible, regardless of password strength. The <a href="/tools/totp-generator/">TOTP generator</a> shows how authenticator codes are derived.</li>
  <li>Never use personal information (birthdays, names) in passwords — even partially.</li>
</ul>
