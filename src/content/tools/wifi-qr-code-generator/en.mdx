## How to Make a WiFi QR Code

1. Type the **network name (SSID)** exactly as it appears in the Wi-Fi list, including capital letters and spaces. The counter on the right shows its length in bytes.
2. Type the **password**. The eye button shows it, so you can check it against the router setting.
3. Pick the **security**: WPA / WPA2 / WPA3 for most routers, WPA3 only, WEP for very old routers, or No password. Tick **Hidden network** if the router does not broadcast the name.
4. The code redraws as you type. Read the warnings under it, then press **Download PNG** or **Download SVG**.
5. Scan the result with a phone before you print it, or check the image with the [QR Code Reader](/tools/qr-code-decoder/).
6. For a counter, a door or a guest room, fill in **Printable card** and download the card or print it.

## What the Code Contains

A Wi-Fi QR code holds one line of text that starts with `WIFI:`. The format comes from the ZXing project's [Barcode Contents](https://github.com/zxing/zxing/wiki/Barcode-Contents#wi-fi-network-config-android-ios-11) page, and the Wi-Fi Alliance later wrote it into section 7 of the [WPA3 Specification v3.5](https://www.wi-fi.org/system/files/WPA3%20Specification%20v3.5.pdf) as the WIFI URI. The tool writes the fields in the order of that specification:

| Field | Written as | Meaning |
|---|---|---|
| `T` | `WPA`, `WEP` or `nopass` | Security type. The WPA3 specification sets `WPA` for every password network, WPA2 and WPA3 alike. |
| `R` | `1` (WPA3 only) | Transition Disable bitmap, bit 0 = WPA3-Personal: phones that support it will not fall back to WPA2 on this network. |
| `S` | the name | SSID, escaped. |
| `H` | `true` | Hidden network, so the phone also probes for a name that is not broadcast. |
| `P` | the password | Escaped; left out for an open network. |

ZXing escapes five characters with a backslash: `\`, `;`, `,`, `"` and `:`. Android's parser in the AOSP source ([WifiUriParser](https://android.googlesource.com/platform/packages/modules/Wifi/+/refs/heads/main/framework/java/android/net/wifi/WifiUriParser.java)) removes those backslashes again. When Android shares a network from Settings, it writes the same format (AOSP `WifiNetworkConfig.getQrCode()`).

## Examples

{/* wqg-check: {"ssid":"Guest-WiFi","password":"welcome-2026","payload":"WIFI:T:WPA;S:Guest-WiFi;P:welcome-2026;;","warnings":[],"version":3} */}
**A guest network.** Name `Guest-WiFi`, password `welcome-2026`, WPA. The tool writes `WIFI:T:WPA;S:Guest-WiFi;P:welcome-2026;;` and reports version 3 (29 × 29 modules) at level M. With the default 1024 px setting, the PNG is 999 × 999 px: 37 modules including the 4-module quiet zone, 27 px each.

{/* wqg-check: {"ssid":"Cafe;Guest","password":"p@ss:w,d","payload":"WIFI:T:WPA;S:Cafe\\;Guest;P:p@ss\\:w\\,d;;","warnings":["wEscape","wEscape"]} */}
**Punctuation.** Name `Cafe;Guest`, password `p@ss:w,d`. The string becomes `WIFI:T:WPA;S:Cafe\;Guest;P:p@ss\:w\,d;;`. Without the backslash, a phone reads the name as `Cafe`, because `;` ends a field. The tool also notes that a reader following only the WPA3 specification would not remove the backslashes: the specification percent-encodes `;` instead, and Android does not decode percent signs.

{/* wqg-check: {"ssid":"Home","password":"correct horse","security":"WPA3","payload":"WIFI:T:WPA;R:1;S:Home;P:correct horse;;","warnings":[]} */}
**WPA3 only.** Name `Home`, password `correct horse`, WPA3 only: `WIFI:T:WPA;R:1;S:Home;P:correct horse;;`, the same string as example 2 in section 7.3 of the specification. The 8–63 character check is skipped, because WPA3's SAE handshake accepts any password.

{/* wqg-check: {"ssid":"Bistro 5G","password":"1234567","warnings":["wWpaLength"]} */}
**A password that cannot be right.** `1234567` on a WPA network gets a warning: a WPA2 passphrase is 8 to 63 printable ASCII characters, or the key itself as 64 hex digits (the limits in [hostapd's sample configuration](https://w1.fi/cgit/hostap/plain/hostapd/hostapd.conf)). The code is still drawn, in case the router runs WPA3 only.

{/* wqg-check: {"ssid":"咖啡店二楼访客无线网络","password":"kafei2026","warnings":["wSsidBytes","wSsidUtf8"],"bytes":33} */}
**A name that is too long.** `咖啡店二楼访客无线网络` is 11 characters but 33 bytes in UTF-8. An SSID is at most 32 bytes (IEEE 802.11), so no router broadcasts that name, and the tool says so instead of drawing a code that can never connect.

## Which Phones Read It

- **Android.** On Android, Settings › Network & internet › Internet › your network › Share shows the network as a QR code ([Google help](https://support.google.com/android/answer/9075847)). Samsung's [connection guide](https://www.samsung.com/us/support/answer/ANS10002546/) has a QR code icon on the Wi-Fi screen for scanning one. The AOSP parser accepts `WPA`, `SAE`, `WEP` and `nopass`, reads `R:1`, and rejects a password network with no `P` field.
- **iPhone.** Apple's iPhone User Guide ([Find and share your Wi-Fi password](https://support.apple.com/guide/iphone/find-and-share-your-wi-fi-password-iph96e6aa9bb/ios)) has a Show Network QR Code button in the Passwords app that others scan to join. Apple does not publish which `WIFI:` fields the Camera reads, and we have not tested an iPhone for this page.
- **Other brands.** We found no Xiaomi or Huawei documentation of the fields they accept. Test with the phones your guests use.

## The Printable Card

The card is 100 mm wide. Its height grows with long names and passwords, which wrap and are never cut. The PNG is 1200 px wide, about 305 dpi, and each module is a whole number of pixels. The SVG keeps its 100 mm size when printed. Names and passwords use a monospaced font, and spaces in a password print as `␣`. Untick **Print the password on the card** to print the code and name only.

A printed password belongs to a guest network. Anyone who photographs the card can read the password with any QR reader, so keep the network your own devices use off the card.

## How It Differs from Other Generators

We ran the same inputs through other generators on 2026-10-01:

- [qifi.org](https://qifi.org/) runs in the browser and escapes correctly. With the name `咖啡店二楼访客无线网络`, it writes one byte per character, the low byte of each UTF-16 unit, so zxing-cpp read the name back as `紡洛|ｿ｢狒Qﾜ`. It gave no length warning.
- [GenQRCode](https://genqrcode.com/generator/wifi) sends the password in a JSON request to its `/preview` endpoint before it shows the preview.

This tool keeps the name in UTF-8, escapes it the way Android's parser expects, checks the 32-byte and password limits before drawing, and uploads nothing.

## Limits

- No WPA2-Enterprise (802.1X) fields. ZXing lists `E`, `A`, `I` and `PH2` for them, the WPA3 specification does not define them, and phones that support them differ.
- No SAE-PK public key (`K`) or SAE password identifier (`I`).
- Hex-looking names such as `CAFE1234` are written as typed. ZXing's old Android app read an all-hex SSID as raw bytes and suggested quotes, but the current branch of Android's WifiUriParser keeps the quotes as part of the name.
- The quiet zone is fixed at 4 modules, the minimum ISO/IEC 18004 requires. For a code for a link or text, use the [QR Code Generator](/tools/qr-code-generator/). For a strong password to print, use the [Password Generator](/tools/password-generator/).
