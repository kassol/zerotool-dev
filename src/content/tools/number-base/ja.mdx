## 例 1：IME の全角入力のまま変換する

日本語入力をオンにしたまま数字を打つと `２５５` のような全角になります。多くの変換ツールはここで「正しい数値ではありません」と止まりますが、このツールは半角として読み取り、「全角文字は半角として読み取りました。」と表示します。

{/* nb: {"in": "１０１１", "base": 2, "out": 10, "expect": "11"} */}
{/* nb: {"in": "ＦＦ", "base": 16, "out": 10, "expect": "255"} */}

- 2進数 `１０１１` → 10進数 `11`
- 16進数 `ＦＦ` → 10進数 `255`

全角の `－` や数学記号の `−`（U+2212）もマイナスとして扱います。

## 例 2：Excel の DEC2BIN で足りないとき

Excel の [DEC2BIN 関数](https://support.microsoft.com/ja-jp/office/dec2bin-%E9%96%A2%E6%95%B0-0f63dd0e-5d1a-42d8-b511-5bf5c6d43838)は −512〜511 の範囲しか扱えず、範囲外は `#NUM!` になります。負の数は 10 ビットの 2の補数で返るので、`=DEC2BIN(-10)` は `1111110110` です。[BASE 関数](https://support.microsoft.com/ja-jp/office/base-%E9%96%A2%E6%95%B0-2ef61411-aee9-4f29-a811-1c42456c6342)は 2〜36 進数に対応しますが、数値は 0 以上 2^53 未満の整数に限られ、小数は切り捨てられます。

このツールでは 10進数 `-10` の 2の補数を 16 ビットで表示すると次のようになります。

{/* nb: {"in": "-10", "base": 10, "twos": 16, "expect": "1111111111110110"} */}

`1111111111110110` の下位 10 ビットが Excel の `1111110110` と一致します。DEC2BIN が `#NUM!` を返す 1000 も、そのまま `1111101000` になります。

{/* nb: {"in": "1000", "base": 10, "out": 2, "expect": "1111101000"} */}

## 例 3：chmod の 8進数を 2進数で見る

Linux のパーミッション `755` は 8進数です。基数を 8 にして `755` を入力すると、2進数は `111101101` になります。3 桁ずつ区切ると `111 101 101`、つまり rwx r-x r-x です。

{/* nb: {"in": "755", "base": 8, "out": 2, "expect": "111101101"} */}

8進数 1 桁は 2進数 3 桁、16進数 1 桁は 2進数 4 桁にちょうど対応します。桁区切りを「1111 0000」にすると、2進数が 4 桁ずつ区切られ、16進数との対応を目で追いやすくなります。

パーミッションを記号から組み立てるなら [Chmod 計算機](/ja/tools/chmod-calculator/)が便利です。

## 例 4：0.1 が 2進数で割り切れない理由

10進数 `0.1` は 2進数で `0.0(0011)`、16進数で `0.1(9)` になります。括弧内の数字が永遠に繰り返す循環小数です。0.1 = 1/10 の分母に 5 が含まれるため、2 の累乗では割り切れません。JavaScript の数値は IEEE 754 倍精度浮動小数点数（[MDN](https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Global_Objects/Number)）なので 0.1 を近似値で持ち、`0.1 + 0.2` が `0.3` になりません。

{/* nb: {"in": "0.1", "base": 10, "out": 2, "expect": "0.0(0011)"} */}

このツールは分数のまま正確に計算し、四捨五入しません。循環部分が 64 桁を超える場合は先頭 64 桁で切って … を付けます。

## 入力できる書き方

| 入力 | 読み取り方 |
|---|---|
| `1111_0000`、`1111 0000`、`1111'0000` | 数字の間の区切りは無視 |
| `1,234,567` | 10進数の 3 桁区切りとしてだけ読む |
| `0x1F`、`0o17`、`0b101` | 基数と一致する接頭辞は外す。10進数を選んでいるときは接頭辞で基数を判断 |
| `#FF5733` | 16進数ではカラーコードとして読む |
| `２５５`、`ＦＦ`、`－５` | 全角は半角として読む |

それ以外の文字があると変換を止め、位置を示します。2進数で `10102` と入力すると「5 文字目の「2」は2進数の数字ではありません（使える文字：0–1）。」と表示します。

{/* nb: {"in": "10102", "base": 2, "error": "invalidDigit"} */}

## ほかのツールとの違い

Bing で「進数変換」の上位に出る [hogehoge.tk の相互変換ツール](https://hogehoge.tk/tool/number.html)に、2026-10-01 に同じ値を入力しました。`9007199254740993` のような大きな整数は正しく変換されます。一方、全角の `２５５` は「正しい数値ではありません。」、`0x1F` と `1111_0000` は使える文字の案内、`0.1` は「小数は入力できません。」、`-10` は「符号あり」に切り替えるよう求めるアラートになり、どの文字が問題かは示されません。このツールではこれらをすべて変換し、変換できない入力には文字の位置を示します。

## 制限事項

- 対応する基数は 2〜36（数字 0–9 と英字 A–Z）で、Python の `int()` や JavaScript の `toString()` と同じ範囲です。58 進数・62 進数・Base64 の文字表は扱いません。
- 1 つの数は 20,000 桁まで。
- `0.0(0011)` の括弧は読むための表記で、入力欄には貼り戻せません。
- 浮動小数点数の IEEE 754 のビット構成（符号・指数・仮数）は表示しません。
- 2の補数は整数だけで、ビット数は 8・16・32・64・128 から選びます。

文字列を 2進数にするなら[バイナリ変換（テキスト ⇔ 2進数）](/ja/tools/text-to-binary/)や [ASCII 変換器](/ja/tools/ascii-converter/)、サブネットマスクの 2進数表記は [IPサブネット計算機](/ja/tools/ip-subnet-calculator/)を使ってください。
