## 使用方法

1. 在「输入进制」里选二进制、八进制、十进制、十六进制，或 3 到 36 之间的其他进制。
2. 输入或粘贴数字。十进制、二进制、十六进制、八进制四行随输入更新，第五行可以换成任意进制（默认 36 进制）。
3. 看输入框下方的提示：按哪种进制读取、需要几个二进制位；输入有误时写明第几个字符出了什么问题。
4. 每行都有「复制」按钮。结果下方可以设置数位分组（`1111_0000` 或 `1111 0000`）、加 `0b` / `0o` / `0x` 前缀、字母小写，以及 8、16、32、64、128 位补码。
5. 展开「显示计算过程」，查看按权展开和除基取余的每一步。

## 示例一：补码与 Java、JavaScript 的差别

-10 写成二进制，各语言的结果不同。JavaScript 的 `(-10).toString(2)` 返回 `-1010`，是「负号 + 绝对值」；Java 的 [`Integer.toBinaryString(-10)`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Integer.html#toBinaryString(int)) 返回 32 位补码 `11111111111111111111111111110110`。本工具两种都给：

{/* nb: {"in": "-10", "base": 10, "out": 2, "expect": "-1010"} */}
{/* nb: {"in": "-10", "base": 10, "twos": 8, "expect": "11110110"} */}

- 二进制行：`-1010`
- 选 8 位补码：`11110110`（十六进制 `F6`），提示「无符号 246，有符号 -10」

8 位有符号数的范围是 -128 到 127，无符号是 0 到 255。补码行接受两者的并集；-129 会提示超出 8 位范围。

## 示例二：把 Modbus 寄存器读成负数

[Modbus 协议规范](https://modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf)里保持寄存器是 16 位字。很多温度变送器把带符号的读数按 16 位补码存放（以设备手册为准）。抓包看到寄存器值 `FF38`：选十六进制、补码选 16 位、勾选「按有符号数读取输入」，得到：

{/* nb: {"in": "FF38", "base": 16, "signed": 16, "out": 10, "expect": "-200"} */}

十进制 `-200`。手册若写「单位 0.1 ℃」，就是 -20.0 ℃。不勾选时同一个值读作 65336。

## 示例三：雪花 ID 到前端变了

数据库里的 BIGINT 主键（如雪花算法生成的 ID）超过 2^53 − 1 时，JavaScript 的 `Number` 存不下（[MDN](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER)）。`JSON.parse('{"id":1234567890123456789}').id` 得到 `1234567890123456800`，后三位已经变了。本工具按 BigInt 逐位解析：

{/* nb: {"in": "1234567890123456789", "base": 10, "out": 16, "expect": "112210F47DE98115"} */}

十六进制 `112210F47DE98115`，选 64 位补码可以看到完整的 64 位二进制。这也是很多后端把长整型 ID 序列化成字符串的原因。

## 示例四：0.1 为什么不精确

十进制 `0.1` 转二进制得到 `0.0(0011)`，转十六进制得到 `0.1(9)`，括号里的数字无限循环。JavaScript 的数字是 IEEE 754 双精度浮点数，只能存 0.1 的近似值，所以 `0.1 + 0.2` 不等于 `0.3`。分母能整除新进制某次幂的小数才会结束，例如 `0.625` 是二进制 `0.101`。

{/* nb: {"in": "0.1", "base": 10, "out": 16, "expect": "0.1(9)"} */}
{/* nb: {"in": "0.625", "base": 10, "out": 2, "expect": "0.101"} */}

本工具用精确分数计算，不四舍五入；循环节超过 64 位时只显示前 64 位并加 …。

## 能粘贴什么

| 输入 | 处理方式 |
|---|---|
| `1111_0000`、`1111 0000` | 数字之间的下划线、空格、撇号忽略 |
| `1,234,567` | 只在十进制里按千位分隔读取 |
| `0x1F`、`0o17`、`0b101` | 前缀与输入进制一致时去掉；选十进制时按前缀判断进制 |
| `２５５`、`ＦＦ`、`－５` | 全角字符按半角读取 |
| `#FF5733` | 十六进制下读作 CSS 颜色值 |

其他字符会停止转换并指出位置，例如二进制下输入 `1012`，提示「第 4 个字符「2」不是 2 进制的数字（可用：0–1）」。

{/* nb: {"in": "1012", "base": 2, "error": "invalidDigit"} */}

## 与常见在线工具的差别

2026-10-01 我们在 [tool.lu 进制转换](https://tool.lu/hexconvert/)（cn.bing.com「进制转换」第一位）输入同样的内容。大整数 `9007199254740993` 结果正确，但以下输入没有报错、直接给了别的数：

| 输入 | tool.lu 结果 | 本工具 |
|---|---|---|
| 十进制 `1,000` | 9000 | 1000 |
| 十进制全角 `２５５` | -111 | 255 |
| 二进制 `1012` | 9 | 提示第 4 个字符不是二进制数字 |
| 二进制 `1111_0000` | 464 | 240 |
| 十六进制 `0x1F` | -225 | 31 |

小数 `0.1` 在 tool.lu 没有输出。

## 限制

- 支持 2 到 36 进制，数字为 0–9 和 A–Z，与 Python `int()`、JavaScript `toString()` 的范围相同。不支持 58、62 进制和 Base64 字母表。
- 每个数最多 20,000 位。
- `0.0(0011)` 里的括号只用于阅读，不能再粘贴回输入框。
- 不显示浮点数的 IEEE 754 位布局（符号位、阶码、尾数）。
- 补码只用于整数，位宽为 8、16、32、64、128 位。

处理文字而不是数字时，请用[二进制翻译器](/zh/tools/text-to-binary/)或 [ASCII 转换器](/zh/tools/ascii-converter/)；八进制权限位见 [Chmod 权限计算器](/zh/tools/chmod-calculator/)，子网掩码的二进制形式见 [IP 子网计算器](/zh/tools/ip-subnet-calculator/)。
