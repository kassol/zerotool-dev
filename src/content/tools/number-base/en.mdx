## Example: a 64-bit ID That JavaScript Cannot Hold

Discord IDs are 64-bit "snowflakes", and the [Discord API reference](https://discord.com/developers/docs/reference#snowflakes) says they are sent as strings "to prevent integer overflows in some languages". The documentation's sample ID is `175928847299117063`. With Decimal selected and Two's complement set to 64-bit:

{/* nb: {"in": "175928847299117063", "base": 10, "out": 16, "expect": "271065AC1020007"} */}
{/* nb: {"in": "175928847299117063", "base": 10, "twos": 64, "expect": "0000001001110001000001100101101011000001000000100000000000000111"} */}

- Hex: `271065AC1020007`
- 64-bit binary: `0000001001110001000001100101101011000001000000100000000000000111`

The first 42 bits hold the time. Paste them back with Binary selected:

{/* nb: {"in": "000000100111000100000110010110101100000100", "base": 2, "out": 10, "expect": "41944705796"} */}

The result is `41944705796` milliseconds after the Discord epoch, the same number as in the documentation's diagram. The ID itself is larger than `Number.MAX_SAFE_INTEGER` (2^53 − 1, [MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER)), so `parseInt('175928847299117063')` returns `175928847299117060`. This tool parses every digit with BigInt and keeps all 18.

## Example: Negative Numbers and Two's Complement

Different tools write −10 in binary in different ways. JavaScript's `(-10).toString(2)` gives `-1010`: a minus sign in front of the magnitude. Java's [`Integer.toBinaryString(-10)`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Integer.html#toBinaryString(int)) gives the 32-bit pattern, because Java stores an `int` in two's complement. This tool shows both:

{/* nb: {"in": "-10", "base": 10, "out": 2, "expect": "-1010"} */}
{/* nb: {"in": "-10", "base": 10, "twos": 8, "expect": "11110110"} */}
{/* nb: {"in": "-10", "base": 10, "twos": 32, "field": "hex", "expect": "FFFFFFF6"} */}

- Binary row: `-1010`
- 8-bit row: `11110110` (hex `F6`), with the note "unsigned 246, signed −10"
- 32-bit hex row: `FFFFFFF6`

{/* nb: {"in": "FFFFFFF6", "base": 16, "signed": 32, "out": 10, "expect": "-10"} */}

To read a pattern from a register dump or a hex editor, type it, pick the width and tick **Read input as signed**. `FFFFFFF6` with 32 bits reads as `-10`. A value outside the width, such as −129 for 8 bits, is reported with the range −128 to 255 (the signed and unsigned ranges together).

## Example: Fractions That Never End

`0.1` in decimal becomes `0.0(0011)` in binary and `0.1(9)` in hex. The digits in parentheses repeat forever. That is why a JavaScript `Number`, which is an IEEE 754 double ([MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number#number_encoding)), cannot hold 0.1 exactly and `0.1 + 0.2` is not `0.3`. Fractions whose denominator divides a power of the new base do end: `0.625` is `0.101` in binary and `0.A` in hex.

{/* nb: {"in": "0.1", "base": 10, "out": 2, "expect": "0.0(0011)"} */}
{/* nb: {"in": "0.1", "base": 10, "out": 16, "expect": "0.1(9)"} */}
{/* nb: {"in": "0.625", "base": 10, "out": 2, "expect": "0.101"} */}

The tool does the arithmetic on exact fractions, so it never rounds. If the repeating block is longer than 64 digits, it shows the first 64 digits and an ellipsis.

## What You Can Paste

| Input | Read as |
|---|---|
| `1111_0000`, `1111 0000`, `1111'0000` | Separators between digits are ignored (Python, Java and C++14 styles) |
| `1,234,567` | Thousands commas in base 10 only |
| `0x1F`, `0o17`, `0b101` | The prefix is dropped when it matches the input base. With Decimal selected, the prefix picks the base |
| `#FF5733` | A CSS color in base 16 |
| `２５５`, `ＦＦ`, `−42` | Full-width characters and the Unicode minus sign are read as ASCII |
| `-0xff` | A sign before the prefix |

{/* nb: {"in": "-0xff", "base": 10, "out": 10, "expect": "-255"} */}

With Decimal selected, `-0xff` is read as hexadecimal because of its prefix, and the decimal row shows `-255`.

Anything else stops the conversion and names the character and its position, for example `"2" at position 5 is not a base-2 digit (allowed: 0–1)` for `10102`. JavaScript's [`parseInt('10102', 2)`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/parseInt) returns 10 instead: it stops at the first bad digit without an error.

{/* nb: {"in": "10102", "base": 2, "error": "invalidDigit"} */}

## How This Differs From RapidTables

[RapidTables](https://www.rapidtables.com/convert/number/decimal-to-binary.html) is the first Bing result for "binary to decimal". We gave both tools the same inputs on 2026-10-01. RapidTables handles large integers correctly (`9007199254740993` → hex `20000000000001`). These cases differ:

- Decimal `0.1` → RapidTables gives `0.0001100110011001101` and `0.1999999999999999999A`, cut and rounded without a mark. This tool gives `0.0(0011)` and `0.1(9)`.
- Decimal `-10` → RapidTables picks a 16-bit two's complement on its own. Here you choose the width.
- `1111_0000`, `２５５` and `1,000` → RapidTables shows "Illegal input!" without saying which character. This tool converts them.

## Limits

- Bases 2 to 36 with the digits 0–9 and A–Z, the same range as Python's `int()` and JavaScript's `toString()`. Base 58, base 62 and Base64 alphabets are not supported.
- Up to 20,000 digits. Python's `int()` stops at 4,300 decimal digits by default ([Python docs](https://docs.python.org/3/library/stdtypes.html#int-max-str-digits)), so a very long result from here may need `sys.set_int_max_str_digits()` there.
- The parentheses in `0.0(0011)` are notation for reading. No input box, including this one, accepts them back.
- The tool converts exact numbers. It does not show the IEEE 754 bit layout of a float (sign, exponent, mantissa).
- Two's complement needs an integer and one of the five widths. Excel-style 10-bit or 40-bit patterns appear as the low bits of the 16-bit or 64-bit row.
