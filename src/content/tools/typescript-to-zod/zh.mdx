<h2>支持的 TypeScript 特性</h2>
<ul>
  <li><strong>基础类型</strong>：<code>string</code>、<code>number</code>、<code>boolean</code>、<code>null</code>、<code>undefined</code>、<code>any</code>、<code>unknown</code>、<code>void</code>、<code>never</code>、<code>bigint</code>、<code>symbol</code></li>
  <li><strong>可选属性</strong>：<code>prop?: type</code> → <code>.optional()</code></li>
  <li><strong>联合类型</strong>：<code>A | B</code> → <code>z.union([A, B])</code></li>
  <li><strong>字符串枚举</strong>：<code>"a" | "b" | "c"</code> → <code>z.enum(["a", "b", "c"])</code></li>
  <li><strong>数组</strong>：<code>T[]</code> / <code>Array&lt;T&gt;</code> → <code>z.array(T)</code></li>
  <li><strong>嵌套对象</strong>：内联对象类型 → <code>z.object(&#123;&#125;)</code></li>
  <li><strong>交叉引用</strong>：命名类型间相互引用 → Schema 常量</li>
  <li><strong>readonly</strong>：接受 <code>readonly</code> 修饰符，转换时去掉；需要只读的推断类型时自行加 <code>.readonly()</code></li>
  <li><strong>工具类型</strong>：<code>Partial&lt;T&gt;</code>、<code>Record&lt;K, V&gt;</code>、<code>Promise&lt;T&gt;</code></li>
  <li><strong>交叉类型</strong>：<code>A &amp; B</code> → <code>z.intersection(A, B)</code></li>
  <li><strong>元组</strong>：<code>[A, B]</code> → <code>z.tuple([A, B])</code></li>
  <li><strong>字面量类型</strong>：<code>"value"</code>、<code>42</code>、<code>true</code> → <code>z.literal()</code></li>
  <li><strong><code>extends</code></strong>：<code>{"interface Admin extends Base"}</code> → <code>{"BaseSchema.extend({ ... })"}</code>，第二个父类型追加 <code>{".extend(OtherSchema.shape)"}</code>；父类型不是对象 schema（如交叉类型别名）时写成 <code>{"z.intersection(BaseSchema, z.object({ ... }))"}</code>。未在输入中声明的父类型生成普通 <code>z.object()</code> 并加注释。</li>
  <li><strong>索引签名</strong>：与其他属性并存的 <code>{"[key: string]: V"}</code> → <code>{".catchall(V)"}</code>（校验并保留多出来的键）；只有索引签名时 → <code>{"z.record(z.string(), V)"}</code>。键总是 <code>z.string()</code>，因为解析出的 JSON 对象的键都是字符串。</li>
  <li><strong><code>enum</code> 声明</strong>：字符串枚举 → 取值的 <code>z.enum()</code>；数字或混合成员（从 0 或上一个数字自动递增）→ <code>z.literal()</code> 的 <code>z.union()</code>。<code>const enum</code>、<code>declare enum</code> 同样处理；含 <code>{"1 << 2"}</code> 这类计算值的枚举整体写成 <code>z.unknown()</code> 并加注释。</li>
  <li><strong>声明顺序与递归</strong>：不论输入顺序，被依赖的 schema 先输出。形成环的引用写成 <code>{"z.lazy(() => NameSchema)"}</code>，环上的每个类型照原文写出并加 <code>{"z.ZodType<Name>"}</code> 标注（Zod 文档里递归类型的写法）。输出已用 TypeScript 5.9 严格模式编译，并在 Zod 3.25 与 Zod 4 下加载验证。</li>
</ul>

<h2>示例</h2>
<p>给定以下 TypeScript 输入：</p>
<pre><code>{`interface Address {
  street: string;
  city: string;
  zipCode?: string;
}

export interface User {
  id: number;
  name: string;
  role: "admin" | "user" | "guest";
  age?: number;
  isActive: boolean;
  tags: string[];
  address: Address;
}

export type Status = "active" | "inactive" | "pending";`}</code></pre>
<p>工具生成：</p>
<pre><code>{`import { z } from "zod";

export const AddressSchema = z.object({
  street: z.string(),
  city: z.string(),
  zipCode: z.string().optional(),
});
export type Address = z.infer<typeof AddressSchema>;

export const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  role: z.enum(["admin", "user", "guest"]),
  age: z.number().optional(),
  isActive: z.boolean(),
  tags: z.array(z.string()),
  address: AddressSchema,
});
export type User = z.infer<typeof UserSchema>;

export const StatusSchema = z.enum(["active", "inactive", "pending"]);
export type Status = z.infer<typeof StatusSchema>;`}</code></pre>

<h2>示例：注册表单</h2>

<p>输入：</p>

<pre><code>{`interface SignupForm {
  email: string;
  password: string;
  nickname?: string;
  referrer: string | null;
  age?: number | undefined;
  plan: "free" | "pro";
}`}</code></pre>

<p>输出：</p>

<pre><code>{`import { z } from "zod";

export const SignupFormSchema = z.object({
  email: z.string(),
  password: z.string(),
  nickname: z.string().optional(),
  referrer: z.union([z.string(), z.null()]),
  age: z.union([z.number(), z.undefined()]).optional(),
  plan: z.enum(["free", "pro"]),
});
export type SignupForm = z.infer<typeof SignupFormSchema>;`}</code></pre>

<p>用 zod 3.25 拿生成的 schema 校验三份数据：</p>

<pre><code>{`SignupFormSchema.safeParse({ email: "not-an-email", password: "1", referrer: null, plan: "pro" })
// success: true  (types match; no format rules yet)

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", plan: "free" })
// referrer: Invalid input  (string | null is required, it cannot be missing)

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", referrer: "ad", plan: "team" })
// plan: Invalid enum value. Expected 'free' | 'pro', received 'team'`}</code></pre>

<h2>null、undefined 与可选</h2>

<ul>
  <li><code>{"prop?: T"}</code> 变成 <code>{".optional()"}</code>：这个键可以不存在。</li>
  <li><code>{"T | null"}</code> 变成 <code>{"z.union([T, z.null()])"}</code>，等价于 <code>{"T.nullable()"}</code>：键必须存在，值可以是 <code>{"null"}</code>。缺少 <code>{"referrer"}</code> 的数据会校验失败。</li>
  <li>可选且可为 null（<code>{"prop?: T | null"}</code>）需要两者兼有；如果 API 就是这么返回的，手动写成 <code>{".nullish()"}</code>。</li>
</ul>

<h2>补上 TypeScript 表达不了的规则</h2>

<p>TypeScript 类型没有格式和范围，所以上面第一份数据带着无效邮箱和一位密码也通过了。生成后补上约束：</p>

<pre><code>{`export const SignupFormSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  nickname: z.string().max(20).optional(),
  referrer: z.string().nullable(),
  age: z.number().int().min(13).optional(),
  plan: z.enum(["free", "pro"]),
});`}</code></pre>

<p>之后把生成的 <code>{"z.infer"}</code> 类型当作唯一来源，删掉原来的 interface，两者就不会逐渐不一致。</p>
