<h2>支持的 TypeScript 特性</h2>
<ul>
  <li><strong>基础类型</strong>：<code>string</code>、<code>number</code>、<code>boolean</code>、<code>null</code>、<code>undefined</code>、<code>any</code>、<code>unknown</code>、<code>void</code>、<code>never</code>、<code>bigint</code>、<code>symbol</code></li>
  <li><strong>可选属性</strong>：<code>prop?: type</code> → <code>.optional()</code></li>
  <li><strong>联合类型</strong>：<code>A | B</code> → <code>z.union([A, B])</code></li>
  <li><strong>字符串枚举</strong>：<code>"a" | "b" | "c"</code> → <code>z.enum(["a", "b", "c"])</code></li>
  <li><strong>数组</strong>：<code>T[]</code> / <code>Array&lt;T&gt;</code> → <code>z.array(T)</code></li>
  <li><strong>嵌套对象</strong>：内联对象类型 → <code>z.object(&#123;&#125;)</code></li>
  <li><strong>交叉引用</strong>：命名类型间相互引用 → Schema 常量</li>
  <li><strong>readonly</strong>：接受 <code>readonly</code> 修饰符，转换时去掉；需要只读的推断类型时自行加 <code>.readonly()</code></li>
  <li><strong>工具类型</strong>：<code>Partial&lt;T&gt;</code>、<code>Record&lt;K, V&gt;</code>、<code>Promise&lt;T&gt;</code></li>
  <li><strong>交叉类型</strong>：<code>A &amp; B</code> → <code>z.intersection(A, B)</code></li>
  <li><strong>元组</strong>：<code>[A, B]</code> → <code>z.tuple([A, B])</code></li>
  <li><strong>字面量类型</strong>：<code>"value"</code>、<code>42</code>、<code>true</code> → <code>z.literal()</code></li>
  <li><strong><code>extends</code></strong>：<code>{"interface Admin extends Base"}</code> → <code>{"BaseSchema.extend({ ... })"}</code>，第二个父类型追加 <code>{".extend(OtherSchema.shape)"}</code>；父类型不是对象 schema（如交叉类型别名）时写成 <code>{"z.intersection(BaseSchema, z.object({ ... }))"}</code>。未在输入中声明的父类型生成普通 <code>z.object()</code> 并加注释。</li>
  <li><strong>索引签名</strong>：与其他属性并存的 <code>{"[key: string]: V"}</code> → <code>{".catchall(V)"}</code>（校验并保留多出来的键）；只有索引签名时 → <code>{"z.record(z.string(), V)"}</code>。键总是 <code>z.string()</code>，因为解析出的 JSON 对象的键都是字符串。</li>
  <li><strong><code>enum</code> 声明</strong>：字符串枚举 → 取值的 <code>z.enum()</code>；数字或混合成员（从 0 或上一个数字自动递增）→ <code>z.literal()</code> 的 <code>z.union()</code>。<code>const enum</code>、<code>declare enum</code> 同样处理；含 <code>{"1 << 2"}</code> 这类计算值的枚举整体写成 <code>z.unknown()</code> 并加注释。</li>
  <li><strong>声明顺序与递归</strong>：不论输入顺序，被依赖的 schema 先输出。形成环的引用写成 <code>{"z.lazy(() => NameSchema)"}</code>，环上的每个类型照原文写出并加 <code>{"z.ZodType<Name>"}</code> 标注（Zod 文档里递归类型的写法）。输出已用 TypeScript 5.9 严格模式编译，并在 Zod 3.25 与 Zod 4 下加载验证。</li>
</ul>

<h2>示例</h2>
<p>给定以下 TypeScript 输入：</p>
<pre><code>{`interface Address {
  street: string;
  city: string;
  zipCode?: string;
}

export interface User {
  id: number;
  name: string;
  role: "admin" | "user" | "guest";
  age?: number;
  isActive: boolean;
  tags: string[];
  address: Address;
}

export type Status = "active" | "inactive" | "pending";`}</code></pre>
<p>工具生成：</p>
<pre><code>{`import { z } from "zod";

export const AddressSchema = z.object({
  street: z.string(),
  city: z.string(),
  zipCode: z.string().optional(),
});
export type Address = z.infer<typeof AddressSchema>;

export const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  role: z.enum(["admin", "user", "guest"]),
  age: z.number().optional(),
  isActive: z.boolean(),
  tags: z.array(z.string()),
  address: AddressSchema,
});
export type User = z.infer<typeof UserSchema>;

export const StatusSchema = z.enum(["active", "inactive", "pending"]);
export type Status = z.infer<typeof StatusSchema>;`}</code></pre>

<h2>示例：微信支付回调通知</h2>

<p>微信支付「支付成功回调通知」文档（更新时间 2024.12.27）列出了回调报文的通知参数：<code>event_type</code> 在支付成功时为 <code>TRANSACTION.SUCCESS</code>，<code>resource_type</code> 固定为 <code>encrypt-resource</code>，<code>resource</code> 里的 <code>algorithm</code> 目前为 <code>AEAD_AES_256_GCM</code>，<code>associated_data</code> 选填。按这张表写成 interface，固定值用字面量类型：</p>

{/* ttz-check: {"schema": "WechatPayNotifySchema", "accepts": [{"id": "EV-2018022511223320873", "create_time": "2015-05-20T13:29:35+08:00", "resource_type": "encrypt-resource", "event_type": "TRANSACTION.SUCCESS", "summary": "支付成功", "resource": {"original_type": "transaction", "algorithm": "AEAD_AES_256_GCM", "ciphertext": "", "associated_data": "", "nonce": ""}}, {"id": "EV-1", "create_time": "2026-10-08T10:00:00+08:00", "resource_type": "encrypt-resource", "event_type": "TRANSACTION.SUCCESS", "summary": "支付成功", "resource": {"original_type": "transaction", "algorithm": "AEAD_AES_256_GCM", "ciphertext": "", "nonce": ""}}], "rejects": [{"id": "EV-2018022511223320873", "create_time": "2015-05-20T13:29:35+08:00", "resource_type": "encrypt-resource", "event_type": "TRANSACTION.SUCCESS", "summary": "支付成功"}, {"id": "EV-2018022511223320873", "create_time": "2015-05-20T13:29:35+08:00", "resource_type": "plain", "event_type": "TRANSACTION.SUCCESS", "summary": "支付成功", "resource": {"original_type": "transaction", "algorithm": "AEAD_AES_256_GCM", "ciphertext": "", "nonce": ""}}]} */}

<pre><code>{`interface WechatPayNotify {
  id: string;
  create_time: string;
  event_type: "TRANSACTION.SUCCESS";
  resource_type: "encrypt-resource";
  summary: string;
  resource: {
    original_type: "transaction";
    algorithm: "AEAD_AES_256_GCM";
    ciphertext: string;
    associated_data?: string;
    nonce: string;
  };
}`}</code></pre>

<p>工具输出：</p>

<pre><code>{`import { z } from "zod";

export const WechatPayNotifySchema = z.object({
  id: z.string(),
  create_time: z.string(),
  event_type: z.literal("TRANSACTION.SUCCESS"),
  resource_type: z.literal("encrypt-resource"),
  summary: z.string(),
  resource: z.object({
      original_type: z.literal("transaction"),
      algorithm: z.literal("AEAD_AES_256_GCM"),
      ciphertext: z.string(),
      associated_data: z.string().optional(),
      nonce: z.string(),
    }),
});
export type WechatPayNotify = z.infer<typeof WechatPayNotifySchema>;`}</code></pre>

<p>单个字符串字面量生成 <code>z.literal()</code>，两个以上才合成 <code>z.enum()</code>。文档里的示例报文能通过这个 schema，去掉 <code>associated_data</code> 也能通过；缺少 <code>resource</code>，或 <code>resource_type</code> 不是 <code>encrypt-resource</code> 的报文会失败。嵌套对象的属性比常见写法多缩进两格，这是工具的输出格式，不影响运行，可以交给 Prettier 重新排版。</p>

<p>这个 schema 只检查通知的外层结构。<code>ciphertext</code> 解密后才是订单信息，那部分 JSON 需要另写一个 interface 再生成。验签必须在解析之前用原始报文完成，<code>parse()</code> 返回的对象会去掉 schema 里没有的键，不能拿来重新拼验签串。</p>

<h2>示例：注册表单</h2>

{/* ttz-check: {"schema": "SignupFormSchema", "accepts": [{"email": "not-an-email", "password": "1", "referrer": null, "plan": "pro"}], "rejects": [{"email": "a@example.com", "password": "x", "plan": "free"}, {"email": "a@example.com", "password": "x", "referrer": "ad", "plan": "team"}]} */}

<p>输入：</p>

<pre><code>{`interface SignupForm {
  email: string;
  password: string;
  nickname?: string;
  referrer: string | null;
  age?: number | undefined;
  plan: "free" | "pro";
}`}</code></pre>

<p>输出：</p>

<pre><code>{`import { z } from "zod";

export const SignupFormSchema = z.object({
  email: z.string(),
  password: z.string(),
  nickname: z.string().optional(),
  referrer: z.union([z.string(), z.null()]),
  age: z.union([z.number(), z.undefined()]).optional(),
  plan: z.enum(["free", "pro"]),
});
export type SignupForm = z.infer<typeof SignupFormSchema>;`}</code></pre>

<p>用 zod 3.25 拿生成的 schema 校验三份数据：</p>

<pre><code>{`SignupFormSchema.safeParse({ email: "not-an-email", password: "1", referrer: null, plan: "pro" })
// success: true  （类型都对；还没有格式规则）

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", plan: "free" })
// referrer: Invalid input  （string | null 必须有这个键，不能缺）

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", referrer: "ad", plan: "team" })
// plan: Invalid enum value. Expected 'free' | 'pro', received 'team'`}</code></pre>

<h2>null、undefined 与可选</h2>

<ul>
  <li><code>{"prop?: T"}</code> 变成 <code>{".optional()"}</code>：这个键可以不存在。</li>
  <li><code>{"T | null"}</code> 变成 <code>{"z.union([T, z.null()])"}</code>，等价于 <code>{"T.nullable()"}</code>：键必须存在，值可以是 <code>{"null"}</code>。缺少 <code>{"referrer"}</code> 的数据会校验失败。</li>
  <li><code>{"prop?: T | null"}</code> 变成 <code>{"z.union([T, z.null()]).optional()"}</code>：键可以不存在，值也可以是 <code>{"null"}</code>，与 <code>{"T.nullish()"}</code> 相同。</li>
</ul>

<h2>中文名称与全角冒号</h2>

<p>属性名和类型名按 TypeScript 的标识符规则读取，可以直接写中文。中文输入法打出的全角冒号 <code>：</code> 在字符串字面量之外按半角 <code>:</code> 读取。下面这段 interface 里，<code>备注</code> 没加引号，<code>amount</code> 后面是全角冒号：</p>

{/* ttz-check: {"schema": "OrderSchema", "accepts": [{"id": "A1", "amount": 99, "备注": "尽快发货", "收货人": "张三"}], "rejects": [{"id": "A1", "amount": 99, "收货人": "张三"}, {"id": "A1", "amount": "99", "备注": "", "收货人": "张三"}]} */}

<pre><code>{`interface Order {
  id: string;
  amount：number;
  备注: string;
  "收货人": string;
}`}</code></pre>

<pre><code>{`import { z } from "zod";

export const OrderSchema = z.object({
  id: z.string(),
  amount: z.number(),
  备注: z.string(),
  "收货人": z.string(),
});
export type Order = z.infer<typeof OrderSchema>;`}</code></pre>

<p>四个属性都在：<code>amount</code> 是 <code>z.number()</code>，<code>备注</code> 原样作为属性名，加了引号的 <code>"收货人"</code> 保留引号。只把冒号当作例外处理，是因为对整段输入做 NFKC 会连字符串字面量类型一起改掉（<code>{'"ＡＢ"'}</code> 会变成 <code>{'"AB"'}</code>）。类型名同样可以是中文，<code>{"interface 订单"}</code> 生成 <code>订单Schema</code>。</p>

{/* ttz-error: {"message": "第 3 行第 3 列：“amount”后面缺少冒号“:”。"} */}

<p>漏写冒号时会报错并给出位置，不再跳过这个属性。输入：</p>

<pre><code>{`interface 订单 {
  id: string;
  amount number;
}`}</code></pre>

<p>状态栏显示 <code>{'解析错误：第 3 行第 3 列：“amount”后面缺少冒号“:”。'}</code>，输出清空。列号按字符计，一个汉字算一列。其他语法错误的正文仍是英文，只给出解析器没料到的第一个记号：缺少右花括号的 <code>{"interface A { a: string"}</code> 报 <code>{'Expected "}" got ""'}</code>，只有 <code>const</code> 语句的输入提示「未找到 interface 或 type 声明。」。</p>

<h2>补上 TypeScript 表达不了的规则</h2>

<p>TypeScript 类型没有格式和范围，所以上面第一份数据带着无效邮箱和一位密码也通过了。生成后补上约束：</p>

<pre><code>{`export const SignupFormSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  nickname: z.string().max(20).optional(),
  referrer: z.string().nullable(),
  age: z.number().int().min(13).optional(),
  plan: z.enum(["free", "pro"]),
});`}</code></pre>

<p>之后把生成的 <code>{"z.infer"}</code> 类型当作唯一来源，删掉原来的 interface，两者就不会逐渐不一致。</p>

<h2>限制</h2>

<p>工具用自带的小型解析器读取声明，没有调用 TypeScript 编译器，不会跨文件解析类型，也不做类型检查。使用前请核对以下几处：</p>

<ul>
  <li><strong>未声明的名字变成 <code>z.unknown()</code>。</strong>输入里没有声明的类型（包括 <code>Date</code> 和从别处 import 的类型）写成 <code>{"z.unknown() /* Name */"}</code>，请换成 <code>z.date()</code> 或对应的 schema。父类型没有声明时生成普通 <code>z.object()</code>，并加注释 <code>{"/* extends Name: not declared in the input */"}</code>。</li>
  <li><strong>enum 按值复制。</strong>schema 检查的是枚举的值（<code>"RED"</code>、<code>0</code>），不是运行时的枚举对象；如果项目里能 import 这个 enum，用 <code>z.nativeEnum(Color)</code>（Zod 3）或 <code>z.enum(Color)</code>（Zod 4）效果相同。</li>
  <li><strong>索引签名的键</strong>总是 <code>z.string()</code>；与 <code>.catchall()</code> 并用时，声明过的属性也要符合自己的 schema。</li>
  <li><strong>字面量键的 Record</strong>，如 <code>{'Record<"read" | "write", boolean>'}</code>，生成 <code>{'z.record(z.enum(["read", "write"]), z.boolean())'}</code>。Zod 4 要求两个键都在，与 TypeScript 一致；Zod 3 只有一个键也通过。</li>
  <li><strong>名字里的 Unicode 转义不会解码。</strong><code>{"\\u0061: string"}</code> 生成名为 <code>u0061</code> 的属性，不是 <code>a</code>。</li>
  <li><strong>只有冒号按全角读取。</strong>全角问号等其他符号仍按未知字符跳过：<code>{"age？: number"}</code> 生成必填的 <code>{"age: z.number()"}</code>，不会变成可选。</li>
  <li><strong>不转换：</strong>泛型参数、class、方法、get / set 访问器、调用签名与构造签名（跳过）、映射类型与条件类型、<code>keyof</code>、<code>typeof</code>，模板字面量类型写成 <code>z.string()</code>。</li>
</ul>
