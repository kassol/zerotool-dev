<h2>지원하는 TypeScript 기능</h2>
<ul>
  <li><strong>기본 타입</strong>: <code>string</code>, <code>number</code>, <code>boolean</code>, <code>null</code>, <code>undefined</code>, <code>any</code>, <code>unknown</code>, <code>void</code>, <code>never</code>, <code>bigint</code>, <code>symbol</code></li>
  <li><strong>선택적 속성</strong>: <code>prop?: type</code> → <code>.optional()</code></li>
  <li><strong>유니언 타입</strong>: <code>A | B</code> → <code>z.union([A, B])</code></li>
  <li><strong>문자열 열거형</strong>: <code>"a" | "b" | "c"</code> → <code>z.enum(["a", "b", "c"])</code></li>
  <li><strong>배열</strong>: <code>T[]</code> / <code>Array&lt;T&gt;</code> → <code>z.array(T)</code></li>
  <li><strong>중첩 객체</strong>: 인라인 객체 타입 → <code>z.object(&#123;&#125;)</code></li>
  <li><strong>상호 참조</strong>: 선언된 타입 간의 참조 → Schema 상수</li>
  <li><strong>readonly</strong>: <code>readonly</code> 수식어를 허용하며, 변환 시 제거(읽기 전용 타입이 필요하면 <code>.readonly()</code>를 직접 추가)</li>
  <li><strong>유틸리티 타입</strong>: <code>Partial&lt;T&gt;</code>, <code>Record&lt;K, V&gt;</code>, <code>Promise&lt;T&gt;</code></li>
  <li><strong>교차 타입</strong>: <code>A &amp; B</code> → <code>z.intersection(A, B)</code></li>
  <li><strong>튜플</strong>: <code>[A, B]</code> → <code>z.tuple([A, B])</code></li>
  <li><strong>리터럴 타입</strong>: <code>"value"</code>, <code>42</code>, <code>true</code> → <code>z.literal()</code></li>
  <li><strong><code>extends</code></strong>: <code>{"interface Admin extends Base"}</code> → <code>{"BaseSchema.extend({ ... })"}</code>. 두 번째 상위 타입은 <code>{".extend(OtherSchema.shape)"}</code>를 덧붙입니다. 상위 타입이 객체 스키마가 아니면(교차 타입 별칭 등) <code>{"z.intersection(BaseSchema, z.object({ ... }))"}</code>가 됩니다. 입력에 선언되지 않은 상위 타입은 일반 <code>z.object()</code>에 주석을 붙입니다.</li>
  <li><strong>인덱스 시그니처</strong>: 다른 속성과 함께 있는 <code>{"[key: string]: V"}</code> → <code>{".catchall(V)"}</code>(추가 키를 검사하고 유지), 인덱스 시그니처만 있으면 <code>{"z.record(z.string(), V)"}</code>. 파싱한 JSON 객체의 키는 모두 문자열이므로 키는 항상 <code>z.string()</code>입니다.</li>
  <li><strong><code>enum</code> 선언</strong>: 문자열 enum → 값의 <code>z.enum()</code>, 숫자 또는 혼합 멤버(0 또는 직전 숫자부터 자동 증가) → <code>z.literal()</code>의 <code>z.union()</code>. <code>const enum</code>, <code>declare enum</code>도 같습니다. <code>{"1 << 2"}</code> 같은 계산 값이 있는 enum은 전체를 <code>z.unknown()</code>으로 쓰고 주석을 붙입니다.</li>
  <li><strong>선언 순서와 재귀</strong>: 입력 순서와 관계없이 의존하는 스키마를 먼저 출력합니다. 순환을 닫는 참조는 <code>{"z.lazy(() => NameSchema)"}</code>가 되고, 순환에 속한 타입은 원래 선언을 그대로 쓰고 <code>{"z.ZodType<Name>"}</code> 타입 주석을 붙입니다(Zod 문서의 재귀 타입 작성법). 출력은 TypeScript 5.9 strict 모드로 컴파일하고 Zod 3.25와 Zod 4에서 불러와 확인했습니다.</li>
</ul>

<h2>예시</h2>
<p>다음 TypeScript를 입력하면:</p>
<pre><code>{`interface Address {
  street: string;
  city: string;
  zipCode?: string;
}

export interface User {
  id: number;
  name: string;
  role: "admin" | "user" | "guest";
  age?: number;
  isActive: boolean;
  tags: string[];
  address: Address;
}

export type Status = "active" | "inactive" | "pending";`}</code></pre>
<p>다음과 같이 생성됩니다:</p>
<pre><code>{`import { z } from "zod";

export const AddressSchema = z.object({
  street: z.string(),
  city: z.string(),
  zipCode: z.string().optional(),
});
export type Address = z.infer<typeof AddressSchema>;

export const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  role: z.enum(["admin", "user", "guest"]),
  age: z.number().optional(),
  isActive: z.boolean(),
  tags: z.array(z.string()),
  address: AddressSchema,
});
export type User = z.infer<typeof UserSchema>;

export const StatusSchema = z.enum(["active", "inactive", "pending"]);
export type Status = z.infer<typeof StatusSchema>;`}</code></pre>

<h2>토스페이먼츠 Payment 객체로 확인하기</h2>

<p>토스페이먼츠 코어 API 문서의 Payment 객체에서 <code>status</code>는 <code>READY</code>, <code>IN_PROGRESS</code>, <code>WAITING_FOR_DEPOSIT</code>, <code>DONE</code>, <code>CANCELED</code>, <code>PARTIAL_CANCELED</code>, <code>ABORTED</code>, <code>EXPIRED</code> 중 하나이고, <code>method</code>와 <code>approvedAt</code>은 <code>nullable · string</code>으로 표시돼 있습니다. 문서의 필드 일부를 그대로 옮겨 적으면:</p>

{/* ttz-check: {"schema": "PaymentSchema", "accepts": [{"paymentKey": "tgen_20261008000000Ab1c2", "orderId": "order-20261008-0001", "orderName": "생수 외 1건", "method": null, "totalAmount": 15000, "status": "READY", "requestedAt": "2026-10-08T10:00:00+09:00", "approvedAt": null, "currency": "KRW"}], "rejects": [{"paymentKey": "tgen_20261008000000Ab1c2", "orderId": "order-20261008-0001", "orderName": "생수 외 1건", "method": "카드", "totalAmount": 15000, "status": "PAID", "requestedAt": "2026-10-08T10:00:00+09:00", "approvedAt": "2026-10-08T10:01:00+09:00"}, {"paymentKey": "tgen_20261008000000Ab1c2", "orderId": "order-20261008-0001", "orderName": "생수 외 1건", "method": null, "totalAmount": 15000, "status": "READY", "requestedAt": "2026-10-08T10:00:00+09:00"}], "drops": ["currency"]} */}

<pre><code>{`type PaymentStatus =
  | "READY"
  | "IN_PROGRESS"
  | "WAITING_FOR_DEPOSIT"
  | "DONE"
  | "CANCELED"
  | "PARTIAL_CANCELED"
  | "ABORTED"
  | "EXPIRED";

interface Payment {
  paymentKey: string;
  orderId: string;
  orderName: string;
  method: string | null;
  totalAmount: number;
  status: PaymentStatus;
  requestedAt: string;
  approvedAt: string | null;
}`}</code></pre>

<pre><code>{`import { z } from "zod";

export const PaymentStatusSchema = z.enum(["READY", "IN_PROGRESS", "WAITING_FOR_DEPOSIT", "DONE", "CANCELED", "PARTIAL_CANCELED", "ABORTED", "EXPIRED"]);
export type PaymentStatus = z.infer<typeof PaymentStatusSchema>;

export const PaymentSchema = z.object({
  paymentKey: z.string(),
  orderId: z.string(),
  orderName: z.string(),
  method: z.union([z.string(), z.null()]),
  totalAmount: z.number(),
  status: PaymentStatusSchema,
  requestedAt: z.string(),
  approvedAt: z.union([z.string(), z.null()]),
});
export type Payment = z.infer<typeof PaymentSchema>;`}</code></pre>

<p>여러 줄에 걸친 유니언도 맨 앞의 <code>|</code>를 읽고 여덟 값을 하나의 <code>z.enum()</code>으로 묶습니다. 결제 대기 상태처럼 <code>method</code>와 <code>approvedAt</code>이 <code>null</code>인 데이터는 통과하고, <code>status</code>가 목록에 없는 <code>PAID</code>이면 실패합니다. <code>approvedAt</code> 키 자체가 빠진 데이터도 실패하는데, 문서의 nullable은 값이 <code>null</code>일 수 있다는 뜻이고 <code>string | null</code>은 키가 있어야 하기 때문입니다.</p>

<p>Payment 객체에는 <code>currency</code>, <code>mId</code> 등 여기 적지 않은 필드가 더 있습니다. Zod는 스키마에 없는 키를 기본적으로 지우므로 검증은 통과하지만 <code>parse()</code> 결과에서는 빠집니다. 문서에 적힌 <code>orderId</code> 길이(6자 이상 64자 이하) 같은 제약은 타입에 없으니 <code>{".min(6).max(64)"}</code>처럼 직접 추가하세요. 값은 이 페이지용 예시입니다.</p>

<h2>null, undefined, optional의 차이</h2>

<ul>
  <li><code>{"prop?: T"}</code>는 <code>{".optional()"}</code>이 됩니다. 키가 없어도 됩니다.</li>
  <li><code>{"T | null"}</code>은 <code>{"z.union([T, z.null()])"}</code>, 즉 <code>{"T.nullable()"}</code>과 같습니다. 키는 반드시 있어야 하고 값은 <code>{"null"}</code>일 수 있습니다. <code>{"referrer"}</code>가 없는 데이터는 실패합니다.</li>
  <li><code>{"prop?: T | null"}</code>은 <code>{"z.union([T, z.null()]).optional()"}</code>이 됩니다. 키가 없어도 되고 값이 <code>{"null"}</code>이어도 되므로 <code>{"T.nullish()"}</code>와 같습니다.</li>
</ul>

<h2>한글 속성 이름</h2>

<p>이 도구의 토크나이저는 이름으로 영문자, 숫자, <code>_</code>, <code>$</code>만 읽고 나머지 문자는 오류 없이 건너뜁니다. 따옴표 없는 한글 키가 있는 다음 interface에서는:</p>

{/* ttz-check: {"schema": "MemberSchema", "accepts": [{"id": "m1", "이름": "홍길동", "닉네임": "길동"}], "rejects": [{"id": "m1"}], "drops": ["이름"]} */}

<pre><code>{`interface Member {
  id: string;
  이름: string;
  "닉네임": string;
}`}</code></pre>

<pre><code>{`import { z } from "zod";

  "닉네임": z.string(),
});
export type Member = z.infer<typeof MemberSchema>;`}</code></pre>

<p><code>이름</code>이 출력에서 사라지고, 상태 표시는 그대로 "스키마 1개를 생성했습니다."입니다. <code>이름</code>이 들어 있는 데이터도 검증은 통과하지만 결과 객체에서는 지워집니다. 따옴표로 감싼 <code>"닉네임"</code>은 그대로 남으니 한글 키는 모두 따옴표로 감싸세요.</p>

{/* ttz-error: {"message": "Expected identifier, got \"{\""} */}

<p>타입 이름이 한글이면 파싱 오류가 납니다. 입력:</p>

<pre><code>{`interface 회원 { id: string }`}</code></pre>

<p>상태 표시에 <code>{'파싱 오류: Expected identifier, got "{"'}</code>가 나오고 출력은 지워집니다. 오류 본문은 영어이며 파서가 예상하지 못한 첫 토큰만 알려 줍니다. 닫는 중괄호가 없는 <code>{"interface A { a: string"}</code>는 <code>{'Expected "}" got ""'}</code>, <code>const</code> 문만 있는 입력은 "interface 또는 type 선언을 찾을 수 없습니다."가 됩니다.</p>

<h2>TypeScript로 표현할 수 없는 규칙 추가</h2>

<p>TypeScript 타입에는 형식과 범위가 없어서 위의 첫 데이터는 잘못된 이메일과 한 글자 비밀번호로도 통과합니다. 생성 후 제약을 추가하세요:</p>

<pre><code>{`export const SignupFormSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  nickname: z.string().max(20).optional(),
  referrer: z.string().nullable(),
  age: z.number().int().min(13).optional(),
  plan: z.enum(["free", "pro"]),
});`}</code></pre>

<p>생성한 <code>{"z.infer"}</code> 타입을 유일한 정의로 두고 원래 interface를 지우면 둘이 어긋나지 않습니다.</p>

<h2>제한 사항</h2>

<p>선언은 TypeScript 컴파일러가 아니라 자체 소형 파서로 읽기 때문에 다른 파일의 타입을 해석하지 않고 타입 검사도 하지 않습니다. 사용하기 전에 다음을 확인하세요.</p>

<ul>
  <li><strong>선언되지 않은 이름은 <code>z.unknown()</code>이 됩니다.</strong> <code>Date</code>나 import한 타입처럼 입력에 선언이 없는 타입은 <code>{"z.unknown() /* Name */"}</code>로 출력되니 <code>z.date()</code>나 해당 스키마로 바꾸세요. 선언되지 않은 상위 타입은 일반 <code>z.object()</code>에 주석 <code>{"/* extends Name: not declared in the input */"}</code>을 붙입니다.</li>
  <li><strong>enum은 값을 복사합니다.</strong> 스키마는 enum의 값(<code>"RED"</code>, <code>0</code>)을 검사하며 런타임 enum 객체를 쓰지 않습니다. enum을 import할 수 있다면 <code>z.nativeEnum(Color)</code>(Zod 3)나 <code>z.enum(Color)</code>(Zod 4)도 같은 결과입니다.</li>
  <li><strong>인덱스 시그니처의 키</strong>는 항상 <code>z.string()</code>입니다. <code>.catchall()</code>과 함께 쓰면 선언된 속성도 자기 스키마에 맞아야 합니다.</li>
  <li><strong>리터럴 키의 Record</strong>(<code>{'Record<"read" | "write", boolean>'}</code>)는 <code>{'z.record(z.enum(["read", "write"]), z.boolean())'}</code>가 됩니다. Zod 4는 TypeScript처럼 두 키를 모두 요구하고, Zod 3는 하나만 있어도 통과시킵니다.</li>
  <li><strong>이름은 영문자만 읽습니다.</strong> 한글뿐 아니라 악센트가 있는 라틴 문자도 중간에 잘립니다. <code>{"prénom: string"}</code>은 <code>{"nom: z.string()"}</code>이 됩니다.</li>
  <li><strong>변환하지 않는 것:</strong> 제네릭 타입 매개변수, class, 메서드(건너뜀), 매핑된 타입과 조건부 타입, <code>keyof</code>, <code>typeof</code>. 템플릿 리터럴 타입은 <code>z.string()</code>이 됩니다.</li>
</ul>
