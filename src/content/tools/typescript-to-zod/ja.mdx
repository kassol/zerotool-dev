<h2>対応TypeScript機能</h2>
<ul>
  <li><strong>基本型</strong>：<code>string</code>、<code>number</code>、<code>boolean</code>、<code>null</code>、<code>undefined</code>、<code>any</code>、<code>unknown</code>、<code>void</code>、<code>never</code>、<code>bigint</code>、<code>symbol</code></li>
  <li><strong>省略可能プロパティ</strong>：<code>prop?: type</code> → <code>.optional()</code></li>
  <li><strong>Union型</strong>：<code>A | B</code> → <code>z.union([A, B])</code></li>
  <li><strong>文字列enum</strong>：<code>"a" | "b" | "c"</code> → <code>z.enum(["a", "b", "c"])</code></li>
  <li><strong>配列</strong>：<code>T[]</code> / <code>Array&lt;T&gt;</code> → <code>z.array(T)</code></li>
  <li><strong>ネストオブジェクト</strong>：インラインオブジェクト型 → <code>z.object(&#123;&#125;)</code></li>
  <li><strong>相互参照</strong>：宣言済み型間の参照 → Schemaの定数</li>
  <li><strong>readonly</strong>：<code>readonly</code>修飾子を受け入れ、変換時に取り除きます（読み取り専用の型が必要なら <code>.readonly()</code> を追加）</li>
  <li><strong>ユーティリティ型</strong>：<code>Partial&lt;T&gt;</code>、<code>Record&lt;K, V&gt;</code>、<code>Promise&lt;T&gt;</code></li>
  <li><strong>交差型</strong>：<code>A &amp; B</code> → <code>z.intersection(A, B)</code></li>
  <li><strong>タプル</strong>：<code>[A, B]</code> → <code>z.tuple([A, B])</code></li>
  <li><strong>リテラル型</strong>：<code>"value"</code>、<code>42</code>、<code>true</code> → <code>z.literal()</code></li>
  <li><strong><code>extends</code></strong>：<code>{"interface Admin extends Base"}</code> → <code>{"BaseSchema.extend({ ... })"}</code>。2 つ目の基底型は <code>{".extend(OtherSchema.shape)"}</code> を追加します。基底型がオブジェクトのスキーマでない場合（交差型の別名など）は <code>{"z.intersection(BaseSchema, z.object({ ... }))"}</code> です。入力にない基底型は通常の <code>z.object()</code> にコメントを付けます。</li>
  <li><strong>インデックスシグネチャ</strong>：他のプロパティと並ぶ <code>{"[key: string]: V"}</code> → <code>{".catchall(V)"}</code>（余分なキーを検証して残す）。インデックスシグネチャだけなら <code>{"z.record(z.string(), V)"}</code>。JSON を解析したオブジェクトのキーは文字列なので、キーは常に <code>z.string()</code> です。</li>
  <li><strong><code>enum</code> 宣言</strong>：文字列 enum → 値の <code>z.enum()</code>。数値や混在のメンバー（0 または直前の数値から自動採番）→ <code>z.literal()</code> の <code>z.union()</code>。<code>const enum</code>、<code>declare enum</code> も同じです。<code>{"1 << 2"}</code> のような計算値を含む enum は全体を <code>z.unknown()</code> にしてコメントを付けます。</li>
  <li><strong>宣言順と再帰</strong>：入力の順序に関係なく、依存先のスキーマから出力します。循環を閉じる参照は <code>{"z.lazy(() => NameSchema)"}</code> になり、循環に含まれる型は元の宣言を書き出して <code>{"z.ZodType<Name>"}</code> の型注釈を付けます（Zod のドキュメントにある再帰型の書き方）。出力は TypeScript 5.9 の strict モードでコンパイルし、Zod 3.25 と Zod 4 で読み込んで確認しています。</li>
</ul>

<h2>サンプル</h2>
<p>以下のTypeScriptを入力すると：</p>
<pre><code>{`interface Address {
  street: string;
  city: string;
  zipCode?: string;
}

export interface User {
  id: number;
  name: string;
  role: "admin" | "user" | "guest";
  age?: number;
  isActive: boolean;
  tags: string[];
  address: Address;
}

export type Status = "active" | "inactive" | "pending";`}</code></pre>
<p>このように生成されます：</p>
<pre><code>{`import { z } from "zod";

export const AddressSchema = z.object({
  street: z.string(),
  city: z.string(),
  zipCode: z.string().optional(),
});
export type Address = z.infer<typeof AddressSchema>;

export const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  role: z.enum(["admin", "user", "guest"]),
  age: z.number().optional(),
  isActive: z.boolean(),
  tags: z.array(z.string()),
  address: AddressSchema,
});
export type User = z.infer<typeof UserSchema>;

export const StatusSchema = z.enum(["active", "inactive", "pending"]);
export type Status = z.infer<typeof StatusSchema>;`}</code></pre>

<h2>例：LINE Messaging API の Webhook イベント</h2>

<p>LINE が公開している OpenAPI 定義（line/line-openapi の <code>webhook.yml</code>）では、すべての Webhook イベントに <code>type</code>、<code>timestamp</code>、<code>mode</code>、<code>webhookEventId</code>、<code>deliveryContext</code> が必須で、<code>mode</code> は <code>active</code> か <code>standby</code>、<code>deliveryContext.isRedelivery</code> は真偽値です。メッセージイベントはこれに <code>replyToken</code> と <code>message</code> を加え、テキストメッセージでは <code>id</code>、<code>text</code>、<code>quoteToken</code> が必須です。共通部分を基底の interface にして <code>extends</code> で書くと、次のようになります。</p>

{/* ttz-check: {"schema": "TextMessageEventSchema", "accepts": [{"type": "message", "timestamp": 1759885200000, "mode": "active", "webhookEventId": "01K70M3Q8ZABCDEFGHJKMNPQRS", "deliveryContext": {"isRedelivery": false}, "replyToken": "r-0001", "source": {"type": "user", "userId": "U0001"}, "message": {"type": "text", "id": "100001", "text": "予約したいです", "quoteToken": "q-0001", "markAsReadToken": "m-0001"}}], "drops": ["message.markAsReadToken"], "rejects": [{"type": "message", "timestamp": 1759885200000, "mode": "paused", "webhookEventId": "01K70M3Q8ZABCDEFGHJKMNPQRS", "deliveryContext": {"isRedelivery": false}, "message": {"type": "text", "id": "100001", "text": "予約したいです", "quoteToken": "q-0001"}}, {"type": "follow", "timestamp": 1759885200000, "mode": "active", "webhookEventId": "01K70M3Q8ZABCDEFGHJKMNPQRS", "deliveryContext": {"isRedelivery": false}, "message": {"type": "text", "id": "100001", "text": "予約したいです", "quoteToken": "q-0001"}}]} */}

<pre><code>{`type EventMode = "active" | "standby";

interface DeliveryContext {
  isRedelivery: boolean;
}

interface WebhookEvent {
  type: string;
  timestamp: number;
  mode: EventMode;
  webhookEventId: string;
  deliveryContext: DeliveryContext;
}

interface TextMessageEvent extends WebhookEvent {
  type: "message";
  replyToken?: string;
  source?: { type: "user"; userId?: string };
  message: { type: "text"; id: string; text: string; quoteToken: string };
}`}</code></pre>

<p>生成結果：</p>

<pre><code>{`import { z } from "zod";

export const EventModeSchema = z.enum(["active", "standby"]);
export type EventMode = z.infer<typeof EventModeSchema>;

export const DeliveryContextSchema = z.object({
  isRedelivery: z.boolean(),
});
export type DeliveryContext = z.infer<typeof DeliveryContextSchema>;

export const WebhookEventSchema = z.object({
  type: z.string(),
  timestamp: z.number(),
  mode: EventModeSchema,
  webhookEventId: z.string(),
  deliveryContext: DeliveryContextSchema,
});
export type WebhookEvent = z.infer<typeof WebhookEventSchema>;

export const TextMessageEventSchema = WebhookEventSchema.extend({
  type: z.literal("message"),
  replyToken: z.string().optional(),
  source: z.object({
      type: z.literal("user"),
      userId: z.string().optional(),
    }).optional(),
  message: z.object({
      type: z.literal("text"),
      id: z.string(),
      text: z.string(),
      quoteToken: z.string(),
    }),
});
export type TextMessageEvent = z.infer<typeof TextMessageEventSchema>;`}</code></pre>

<p>宣言の順番を入れ替えても、依存先の <code>EventModeSchema</code> から順に出力されます。<code>.extend()</code> は同じキーを上書きするため、<code>type</code> は基底の <code>z.string()</code> ではなく <code>z.literal("message")</code> で検証されます。<code>mode</code> が <code>paused</code> のデータや <code>type</code> が <code>follow</code> のデータは失敗します。</p>

<p>上の interface に書かなかった <code>markAsReadToken</code>（webhook.yml では省略可能なプロパティ）を含むメッセージも検証は通りますが、Zod はスキーマにないキーを既定で取り除くため、<code>parse()</code> の結果からは消えます。パース後のオブジェクトは受け取ったボディと同じではないので、元のデータが必要な処理には生のボディを使ってください。値（ID やトークン）はこのページ用の例です。</p>

<h2>例：会員登録フォーム</h2>

{/* ttz-check: {"schema": "SignupFormSchema", "accepts": [{"email": "not-an-email", "password": "1", "referrer": null, "plan": "pro"}], "rejects": [{"email": "a@example.com", "password": "x", "plan": "free"}, {"email": "a@example.com", "password": "x", "referrer": "ad", "plan": "team"}]} */}

<p>入力：</p>

<pre><code>{`interface SignupForm {
  email: string;
  password: string;
  nickname?: string;
  referrer: string | null;
  age?: number | undefined;
  plan: "free" | "pro";
}`}</code></pre>

<p>出力：</p>

<pre><code>{`import { z } from "zod";

export const SignupFormSchema = z.object({
  email: z.string(),
  password: z.string(),
  nickname: z.string().optional(),
  referrer: z.union([z.string(), z.null()]),
  age: z.union([z.number(), z.undefined()]).optional(),
  plan: z.enum(["free", "pro"]),
});
export type SignupForm = z.infer<typeof SignupFormSchema>;`}</code></pre>

<p>生成したスキーマで zod 3.25 を使い 3 つのデータを検証した結果：</p>

<pre><code>{`SignupFormSchema.safeParse({ email: "not-an-email", password: "1", referrer: null, plan: "pro" })

<h2>null・undefined・省略可能の違い</h2>

<ul>
  <li><code>{"prop?: T"}</code> は <code>{".optional()"}</code> になります。キーがなくてもかまいません。</li>
  <li><code>{"T | null"}</code> は <code>{"z.union([T, z.null()])"}</code>、つまり <code>{"T.nullable()"}</code> と同じです。キーは必須で、値に <code>{"null"}</code> を許します。<code>{"referrer"}</code> のないデータは失敗します。</li>
  <li><code>{"prop?: T | null"}</code> は <code>{"z.union([T, z.null()]).optional()"}</code> になります。キーがなくても値が <code>{"null"}</code> でもよく、<code>{"T.nullish()"}</code> と同じ意味です。</li>
</ul>

<h2>日本語の名前と全角コロン</h2>

<p>プロパティ名と型名は TypeScript の識別子の規則で読むので、日本語をそのまま書けます。IME で入力した全角コロン <code>：</code> は、文字列リテラルの外では半角の <code>:</code> として読みます。クォートなしの <code>氏名</code> と、全角コロンを含む次の interface では：</p>

{/* ttz-check: {"schema": "MemberSchema", "accepts": [{"id": "m1", "氏名": "山田太郎", "フリガナ": "ヤマダタロウ", "age": 30}], "rejects": [{"id": "m1", "フリガナ": "ヤマダタロウ", "age": 30}, {"id": "m1", "氏名": "山田太郎", "フリガナ": "ヤマダタロウ", "age": "30"}]} */}

<pre><code>{`interface Member {
  id: string;
  氏名: string;
  "フリガナ": string;
  age：number;
}`}</code></pre>

<pre><code>{`import { z } from "zod";

export const MemberSchema = z.object({
  id: z.string(),
  氏名: z.string(),
  "フリガナ": z.string(),
  age: z.number(),
});
export type Member = z.infer<typeof MemberSchema>;`}</code></pre>

<p>4 項目すべてが残り、<code>氏名</code> はそのままプロパティ名に、クォートで囲んだ <code>"フリガナ"</code> はクォート付きで出力されます。入力全体を NFKC で正規化しないのは、文字列リテラル型まで変わってしまうためです（<code>{'"ﾎｯｶｲﾄﾞｳ"'}</code> が <code>{'"ホッカイドウ"'}</code> になります）。型名も日本語で書け、<code>{"interface 会員"}</code> は <code>会員Schema</code> になります。</p>

{/* ttz-error: {"message": "3 行 3 列：「氏名」の後に「:」がありません。"} */}

<p>コロンを書き忘れると、そのプロパティを読み飛ばさず、位置付きのエラーになります。入力：</p>

<pre><code>{`interface 会員 {
  id: string;
  氏名 string;
}`}</code></pre>

<p>ステータスには <code>{'解析エラー：3 行 3 列：「氏名」の後に「:」がありません。'}</code> と表示され、出力は消えます。列は文字単位で数えます。その他の構文エラーは英語のままで、パーサーが予期しなかった最初のトークンだけを示します。閉じ括弧のない <code>{"interface A { a: string"}</code> は <code>{'Expected "}" got ""'}</code>、<code>const</code> 文だけの入力は「interface または type 宣言が見つかりません。」です。</p>

<h2>TypeScript では書けないルールを足す</h2>

<p>TypeScript の型には形式や範囲がないため、上の 1 件目は不正なメールアドレスと 1 文字のパスワードでも通ります。生成後に制約を足します：</p>

<pre><code>{`export const SignupFormSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  nickname: z.string().max(20).optional(),
  referrer: z.string().nullable(),
  age: z.number().int().min(13).optional(),
  plan: z.enum(["free", "pro"]),
});`}</code></pre>

<p>生成した <code>{"z.infer"}</code> の型を唯一の定義にして元の interface は消すと、両者がずれていくことを防げます。</p>

<h2>制限事項</h2>

<p>宣言の読み取りには TypeScript コンパイラではなく独自の小さなパーサーを使うため、別ファイルの型は解決せず、型チェックもしません。使う前に次の点を確認してください。</p>

<ul>
  <li><strong>宣言のない名前は <code>z.unknown()</code> になります。</strong><code>Date</code> や import した型など、入力で宣言していない型は <code>{"z.unknown() /* Name */"}</code> と出力されます。<code>z.date()</code> や対応するスキーマに置き換えてください。宣言のない基底型は通常の <code>z.object()</code> にコメント <code>{"/* extends Name: not declared in the input */"}</code> を付けます。</li>
  <li><strong>enum は値をコピーします。</strong>スキーマが検証するのは enum の値（<code>"RED"</code>、<code>0</code>）で、実行時の enum オブジェクトではありません。enum を import できるなら <code>z.nativeEnum(Color)</code>（Zod 3）や <code>z.enum(Color)</code>（Zod 4）でも同じです。</li>
  <li><strong>インデックスシグネチャのキー</strong>は常に <code>z.string()</code> です。<code>.catchall()</code> と併用すると、宣言済みのプロパティも自身のスキーマに合う必要があります。</li>
  <li><strong>リテラルキーの Record</strong>（<code>{'Record<"read" | "write", boolean>'}</code>）は <code>{'z.record(z.enum(["read", "write"]), z.boolean())'}</code> になります。Zod 4 は TypeScript と同じく両方のキーを要求し、Zod 3 は片方だけでも通します。</li>
  <li><strong>名前の Unicode エスケープは解釈しません。</strong><code>{"\\u0061: string"}</code> は <code>a</code> ではなく <code>u0061</code> というプロパティになります。</li>
  <li><strong>全角で読むのはコロンだけです。</strong>全角の疑問符などは未知の文字として読み飛ばすため、<code>{"age？: number"}</code> は省略可能にならず <code>{"age: z.number()"}</code> になります。</li>
  <li><strong>変換しないもの：</strong>ジェネリックの型パラメーター、class、メソッド（読み飛ばし）、Mapped Types と Conditional Types、<code>keyof</code>、<code>typeof</code>。テンプレートリテラル型は <code>z.string()</code> になります。</li>
</ul>
