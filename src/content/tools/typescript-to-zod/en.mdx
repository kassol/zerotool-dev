<h2>How to Use</h2>
<ol>
  <li>Paste your TypeScript <code>interface</code> or <code>type</code> declarations into the left panel.</li>
  <li>The tool validates and converts in real time (300 ms debounce after typing stops).</li>
  <li>Click <strong>Generate Zod Schema</strong> to force a conversion.</li>
  <li>Click <strong>Copy</strong> to copy the Zod output to your clipboard.</li>
  <li>Paste the result into your project — the output already includes the <code>import</code> statement and <code>export type</code> inference lines.</li>
</ol>

<h2>Supported TypeScript Features</h2>
<ul>
  <li><strong>Basic types</strong>: <code>string</code>, <code>number</code>, <code>boolean</code>, <code>null</code>, <code>undefined</code>, <code>any</code>, <code>unknown</code>, <code>void</code>, <code>never</code>, <code>bigint</code>, <code>symbol</code></li>
  <li><strong>Optional properties</strong>: <code>prop?: type</code> → <code>.optional()</code></li>
  <li><strong>Union types</strong>: <code>A | B</code> → <code>z.union([A, B])</code></li>
  <li><strong>String enums</strong>: <code>"a" | "b" | "c"</code> → <code>z.enum(["a", "b", "c"])</code></li>
  <li><strong>Arrays</strong>: <code>T[]</code> / <code>Array&lt;T&gt;</code> → <code>z.array(T)</code></li>
  <li><strong>Nested objects</strong>: inline object types → <code>z.object(&#123;&#125;)</code></li>
  <li><strong>Cross-references</strong>: named types reference each other → Schema constants</li>
  <li><strong>Readonly</strong>: the <code>readonly</code> modifier is accepted and dropped; add <code>.readonly()</code> yourself if the inferred type should be read-only</li>
  <li><strong>Utility types</strong>: <code>Partial&lt;T&gt;</code> → <code>.partial()</code>, <code>Record&lt;K, V&gt;</code> → <code>z.record(K, V)</code>, <code>Promise&lt;T&gt;</code> → <code>z.promise(T)</code>; <code>Required&lt;T&gt;</code> is passed through unchanged</li>
  <li><strong>Intersection types</strong>: <code>A &amp; B</code> → <code>z.intersection(A, B)</code></li>
  <li><strong>Tuples</strong>: <code>[A, B]</code> → <code>z.tuple([A, B])</code></li>
  <li><strong>Literal types</strong>: <code>"value"</code>, <code>42</code>, <code>true</code> → <code>z.literal()</code></li>
</ul>

<h2>Example</h2>
<p>Given this TypeScript input:</p>
<pre><code>{`interface Address {
  street: string;
  city: string;
  zipCode?: string;
}

export interface User {
  id: number;
  name: string;
  role: "admin" | "user" | "guest";
  age?: number;
  isActive: boolean;
  tags: string[];
  address: Address;
}

export type Status = "active" | "inactive" | "pending";`}</code></pre>
<p>The tool generates:</p>
<pre><code>{`import { z } from "zod";

export const AddressSchema = z.object({
  street: z.string(),
  city: z.string(),
  zipCode: z.string().optional(),
});
export type Address = z.infer<typeof AddressSchema>;

export const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  role: z.enum(["admin", "user", "guest"]),
  age: z.number().optional(),
  isActive: z.boolean(),
  tags: z.array(z.string()),
  address: AddressSchema,
});
export type User = z.infer<typeof UserSchema>;

export const StatusSchema = z.enum(["active", "inactive", "pending"]);
export type Status = z.infer<typeof StatusSchema>;`}</code></pre>

<h2>Example: A Signup Form</h2>

<p>Input:</p>

<pre><code>{`interface SignupForm {
  email: string;
  password: string;
  nickname?: string;
  referrer: string | null;
  age?: number | undefined;
  plan: "free" | "pro";
}`}</code></pre>

<p>Output:</p>

<pre><code>{`import { z } from "zod";

export const SignupFormSchema = z.object({
  email: z.string(),
  password: z.string(),
  nickname: z.string().optional(),
  referrer: z.union([z.string(), z.null()]),
  age: z.union([z.number(), z.undefined()]).optional(),
  plan: z.enum(["free", "pro"]),
});
export type SignupForm = z.infer<typeof SignupFormSchema>;`}</code></pre>

<p>Running the generated schema with zod 3.25 on three payloads:</p>

<pre><code>{`SignupFormSchema.safeParse({ email: "not-an-email", password: "1", referrer: null, plan: "pro" })
// success: true  (types match; no format rules yet)

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", plan: "free" })
// referrer: Invalid input  (string | null is required, it cannot be missing)

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", referrer: "ad", plan: "team" })
// plan: Invalid enum value. Expected 'free' | 'pro', received 'team'`}</code></pre>

<h2>null, undefined and Optional</h2>

<ul>
  <li><code>{"prop?: T"}</code> becomes <code>{".optional()"}</code>: the key may be missing.</li>
  <li><code>{"T | null"}</code> becomes <code>{"z.union([T, z.null()])"}</code> — the same as <code>{"T.nullable()"}</code>: the key must be present, and its value may be <code>{"null"}</code>. A payload without <code>{"referrer"}</code> fails.</li>
  <li><code>{"T | null"}</code> on an optional property (<code>{"prop?: T | null"}</code>) needs both; write <code>{".nullish()"}</code> by hand if that is what the API sends.</li>
</ul>

<h2>Adding the Rules TypeScript Cannot Express</h2>

<p>TypeScript types have no formats or ranges, so the first payload above passes with an invalid email and a one-character password. Add refinements after generating:</p>

<pre><code>{`export const SignupFormSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  nickname: z.string().max(20).optional(),
  referrer: z.string().nullable(),
  age: z.number().int().min(13).optional(),
  plan: z.enum(["free", "pro"]),
});`}</code></pre>

<p>Keep the generated <code>{"z.infer"}</code> type as the single source of truth and delete the original interface, so the two cannot drift apart.</p>

<h2>Errors</h2>

<p>The status line shows <strong>Parse error:</strong> followed by the first token the parser did not expect. A missing closing brace in <code>{"interface A { a: string"}</code> gives <code>{'Expected "}" got ""'}</code>, and <code>{"type = string"}</code> gives <code>{'Expected identifier, got "="'}</code>. Input with no <code>interface</code> or <code>type</code> declaration, such as a file of <code>const</code> statements, gives “No interface or type declarations found.”</p>

<h2>Limitations</h2>

<p>The tool reads declarations with its own small parser rather than the TypeScript compiler, so it does not resolve types from other files and does not type-check. Check the output for these cases before you use it:</p>

<ul>
  <li><strong>Declaration order.</strong> Schemas are written in the order of the input, as <code>const</code> declarations. If <code>Order</code> uses <code>Customer</code> and <code>Customer</code> is declared later, loading the module throws <code>ReferenceError: Cannot access 'CustomerSchema' before initialization</code>. Put the dependencies first. A recursive type such as <code>{"children: Category[]"}</code> fails the same way; rewrite that field with <code>z.lazy(() =&gt; CategorySchema)</code> and an explicit type annotation, as the Zod 3 documentation shows for recursive types (Zod 4 also accepts a getter).</li>
  <li><strong><code>extends</code> is skipped.</strong> <code>{"interface Admin extends Base"}</code> produces only the fields written inside <code>Admin</code>. Change the output to <code>{"BaseSchema.extend({ ... })"}</code>.</li>
  <li><strong>Index signatures are skipped.</strong> <code>{"[key: string]: unknown"}</code> adds nothing to the object; use <code>.catchall()</code> or <code>z.record()</code> by hand.</li>
  <li><strong>Unknown names become <code>z.unknown()</code>.</strong> Any type not declared in the input, including <code>Date</code>, imported types and TypeScript <code>enum</code> declarations (which are skipped), is written as <code>{"z.unknown() /* Name */"}</code>. Replace it with <code>z.date()</code>, <code>z.nativeEnum()</code> (Zod 3) or <code>z.enum()</code> (Zod 4), or the imported schema.</li>
  <li><strong>Records with literal keys</strong> such as <code>{'Record<"read" | "write", boolean>'}</code> become <code>{'z.record(z.enum(["read", "write"]), z.boolean())'}</code>. Zod 4 then requires both keys, as TypeScript does; Zod 3 accepts an object with only one of them.</li>
  <li><strong>Not converted:</strong> generic parameters, classes, methods (skipped), mapped and conditional types, <code>keyof</code>, <code>typeof</code> and template literal types (written as <code>z.string()</code>).</li>
</ul>

<p>For JSON you already have, the <a href="/tools/json-to-zod/">JSON to Zod</a> tool infers a schema from sample data instead of from types.</p>
