<h2>Supported TypeScript Features</h2>
<ul>
  <li><strong>Basic types</strong>: <code>string</code>, <code>number</code>, <code>boolean</code>, <code>null</code>, <code>undefined</code>, <code>any</code>, <code>unknown</code>, <code>void</code>, <code>never</code>, <code>bigint</code>, <code>symbol</code></li>
  <li><strong>Optional properties</strong>: <code>prop?: type</code> → <code>.optional()</code></li>
  <li><strong>Union types</strong>: <code>A | B</code> → <code>z.union([A, B])</code></li>
  <li><strong>String enums</strong>: <code>"a" | "b" | "c"</code> → <code>z.enum(["a", "b", "c"])</code></li>
  <li><strong>Arrays</strong>: <code>T[]</code> / <code>Array&lt;T&gt;</code> → <code>z.array(T)</code></li>
  <li><strong>Nested objects</strong>: inline object types → <code>z.object(&#123;&#125;)</code></li>
  <li><strong>Cross-references</strong>: named types reference each other → Schema constants</li>
  <li><strong>Readonly</strong>: the <code>readonly</code> modifier is accepted and dropped; add <code>.readonly()</code> yourself if the inferred type should be read-only</li>
  <li><strong>Utility types</strong>: <code>Partial&lt;T&gt;</code> → <code>.partial()</code>, <code>Record&lt;K, V&gt;</code> → <code>z.record(K, V)</code>, <code>Promise&lt;T&gt;</code> → <code>z.promise(T)</code>; <code>Required&lt;T&gt;</code> is passed through unchanged</li>
  <li><strong>Intersection types</strong>: <code>A &amp; B</code> → <code>z.intersection(A, B)</code></li>
  <li><strong>Tuples</strong>: <code>[A, B]</code> → <code>z.tuple([A, B])</code></li>
  <li><strong>Literal types</strong>: <code>"value"</code>, <code>42</code>, <code>true</code> → <code>z.literal()</code></li>
  <li><strong><code>extends</code></strong>: <code>{"interface Admin extends Base"}</code> → <code>{"BaseSchema.extend({ ... })"}</code>; a second base adds <code>{".extend(OtherSchema.shape)"}</code>. If a base is not an object schema (an intersection alias, for example), the result is <code>{"z.intersection(BaseSchema, z.object({ ... }))"}</code>.</li>
  <li><strong>Index signatures</strong>: <code>{"[key: string]: V"}</code> next to other properties → <code>{".catchall(V)"}</code>, which checks and keeps the extra keys; on its own → <code>{"z.record(z.string(), V)"}</code>.</li>
  <li><strong><code>enum</code> declarations</strong>: a string enum → <code>z.enum()</code> of its values; numeric or mixed members (auto-numbered from 0 or from the last number) → <code>z.union()</code> of <code>z.literal()</code> values. <code>const enum</code> and <code>declare enum</code> are read the same way.</li>
  <li><strong>Declaration order and recursion</strong>: schemas are written dependencies first, whatever the input order. A reference that closes a cycle becomes <code>{"z.lazy(() => NameSchema)"}</code>, and each type in the cycle is written out with an explicit <code>{"z.ZodType<Name>"}</code> annotation, as the Zod documentation shows for recursive types.</li>
</ul>

<h2>Example: Recursion, extends and an Index Signature</h2>

{/* ttz-check: {"schema": "MenuSchema", "accepts": [{"id": "m", "root": {"name": "r", "children": [{"name": "c", "children": []}]}, "extra": 1}], "rejects": [{"root": {"name": "r", "children": []}}, {"id": "m", "root": {"name": "r", "children": [{"name": "c"}]}}]} */}

<p>Input, with <code>Category</code> declared after the type that uses it:</p>

<pre><code>{`interface Menu extends Base { root: Category; [key: string]: unknown }
interface Base { id: string }
interface Category { name: string; children: Category[] }`}</code></pre>

<p>Output (checked with the TypeScript 5.9 compiler in strict mode and loaded with Zod 3.25 and Zod 4):</p>

<pre><code>{`import { z } from "zod";

export const BaseSchema = z.object({
  id: z.string(),
});
export type Base = z.infer<typeof BaseSchema>;

export interface Category { name: string; children: Category[] }
export const CategorySchema: z.ZodType<Category> = z.object({
  name: z.string(),
  children: z.array(z.lazy(() => CategorySchema)),
});

export const MenuSchema = BaseSchema.extend({
  root: CategorySchema,
}).catchall(z.unknown());
export type Menu = z.infer<typeof MenuSchema>;`}</code></pre>

<h2>Example</h2>
<p>Given this TypeScript input:</p>
<pre><code>{`interface Address {
  street: string;
  city: string;
  zipCode?: string;
}

export interface User {
  id: number;
  name: string;
  role: "admin" | "user" | "guest";
  age?: number;
  isActive: boolean;
  tags: string[];
  address: Address;
}

export type Status = "active" | "inactive" | "pending";`}</code></pre>
<p>The tool generates:</p>
<pre><code>{`import { z } from "zod";

export const AddressSchema = z.object({
  street: z.string(),
  city: z.string(),
  zipCode: z.string().optional(),
});
export type Address = z.infer<typeof AddressSchema>;

export const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  role: z.enum(["admin", "user", "guest"]),
  age: z.number().optional(),
  isActive: z.boolean(),
  tags: z.array(z.string()),
  address: AddressSchema,
});
export type User = z.infer<typeof UserSchema>;

export const StatusSchema = z.enum(["active", "inactive", "pending"]);
export type Status = z.infer<typeof StatusSchema>;`}</code></pre>

<h2>Example: A Signup Form</h2>

{/* ttz-check: {"schema": "SignupFormSchema", "accepts": [{"email": "not-an-email", "password": "1", "referrer": null, "plan": "pro"}], "rejects": [{"email": "a@example.com", "password": "x", "plan": "free"}, {"email": "a@example.com", "password": "x", "referrer": "ad", "plan": "team"}]} */}

<p>Input:</p>

<pre><code>{`interface SignupForm {
  email: string;
  password: string;
  nickname?: string;
  referrer: string | null;
  age?: number | undefined;
  plan: "free" | "pro";
}`}</code></pre>

<p>Output:</p>

<pre><code>{`import { z } from "zod";

export const SignupFormSchema = z.object({
  email: z.string(),
  password: z.string(),
  nickname: z.string().optional(),
  referrer: z.union([z.string(), z.null()]),
  age: z.union([z.number(), z.undefined()]).optional(),
  plan: z.enum(["free", "pro"]),
});
export type SignupForm = z.infer<typeof SignupFormSchema>;`}</code></pre>

<p>Running the generated schema with zod 3.25 on three payloads:</p>

<pre><code>{`SignupFormSchema.safeParse({ email: "not-an-email", password: "1", referrer: null, plan: "pro" })
// success: true  (types match; no format rules yet)

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", plan: "free" })
// referrer: Invalid input  (string | null is required, it cannot be missing)

SignupFormSchema.safeParse({ email: "a@example.com", password: "x", referrer: "ad", plan: "team" })
// plan: Invalid enum value. Expected 'free' | 'pro', received 'team'`}</code></pre>

<h2>null, undefined and Optional</h2>

<ul>
  <li><code>{"prop?: T"}</code> becomes <code>{".optional()"}</code>: the key may be missing.</li>
  <li><code>{"T | null"}</code> becomes <code>{"z.union([T, z.null()])"}</code> — the same as <code>{"T.nullable()"}</code>: the key must be present, and its value may be <code>{"null"}</code>. A payload without <code>{"referrer"}</code> fails.</li>
  <li><code>{"prop?: T | null"}</code> becomes <code>{"z.union([T, z.null()]).optional()"}</code>: the key may be missing or <code>{"null"}</code>, the same as <code>{"T.nullish()"}</code>.</li>
</ul>

<h2>Adding the Rules TypeScript Cannot Express</h2>

<p>TypeScript types have no formats or ranges, so the first payload above passes with an invalid email and a one-character password. Add refinements after generating:</p>

<pre><code>{`export const SignupFormSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  nickname: z.string().max(20).optional(),
  referrer: z.string().nullable(),
  age: z.number().int().min(13).optional(),
  plan: z.enum(["free", "pro"]),
});`}</code></pre>

<p>Keep the generated <code>{"z.infer"}</code> type as the single source of truth and delete the original interface, so the two cannot drift apart.</p>

<h2>Errors</h2>

<p>The status line shows <strong>Parse error:</strong> followed by the first token the parser did not expect. A missing closing brace in <code>{"interface A { a: string"}</code> gives <code>{'Expected "}" got ""'}</code>, and <code>{"type = string"}</code> gives <code>{'Expected identifier, got "="'}</code>. Input with no <code>interface</code> or <code>type</code> declaration, such as a file of <code>const</code> statements, gives “No interface or type declarations found.”</p>

<h2>Limitations</h2>

<p>The tool reads declarations with its own small parser rather than the TypeScript compiler, so it does not resolve types from other files and does not type-check. Check the output for these cases before you use it:</p>

<ul>
  <li><strong>Unknown names become <code>z.unknown()</code>.</strong> Any type not declared in the input, including <code>Date</code> and imported types, is written as <code>{"z.unknown() /* Name */"}</code>. Replace it with <code>z.date()</code> or the imported schema. A base type that is not declared gives a plain <code>z.object()</code> with the comment <code>{"/* extends Name: not declared in the input */"}</code>.</li>
  <li><strong>Enums are copied as values.</strong> The schema checks the enum's values (<code>"RED"</code>, <code>0</code>), not the runtime enum object; if you import the enum, <code>z.nativeEnum(Color)</code> (Zod 3) or <code>z.enum(Color)</code> (Zod 4) does the same. Members with computed values such as <code>{"1 << 2"}</code> make the whole enum <code>{"z.unknown() /* enum E: computed member A */"}</code>.</li>
  <li><strong>Index signature keys</strong> are always <code>z.string()</code>, because every key of a parsed JSON object is a string; <code>{"[id: number]: V"}</code> is converted the same way. With <code>.catchall()</code>, a declared property must also match its own schema.</li>
  <li><strong>Records with literal keys</strong> such as <code>{'Record<"read" | "write", boolean>'}</code> become <code>{'z.record(z.enum(["read", "write"]), z.boolean())'}</code>. Zod 4 then requires both keys, as TypeScript does; Zod 3 accepts an object with only one of them.</li>
  <li><strong>Names use ASCII letters only.</strong> The tokenizer reads A–Z, a–z, digits, <code>_</code> and <code>$</code> in a name and skips every other character without an error. <code>{"prénom: string"}</code> becomes <code>{"nom: z.string()"}</code>, <code>{"interface Café"}</code> gives <code>CafSchema</code>, and a property written only in other letters, such as <code>{"名前: string"}</code>, is dropped. Quote such keys (<code>{'"prénom": string'}</code>); a quoted key is kept as written. A full-width colon <code>：</code> also drops the property.</li>
  <li><strong>Not converted:</strong> generic parameters (a recursive generic type also needs its written-out type fixed by hand), classes, methods (skipped), mapped and conditional types, <code>keyof</code>, <code>typeof</code> and template literal types (written as <code>z.string()</code>).</li>
</ul>
