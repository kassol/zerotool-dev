<h2>テキストケース変換について</h2>
<p>プログラミングでは変数名・関数名・定数名にそれぞれ異なる命名規則が使われます。このツールは 1 つの入力から 9 形式を同時に表示するので、目的の行をコピーするだけで書き換えられます。</p>
<ul>
  <li><strong>camelCase</strong>：JavaScript変数、オブジェクトプロパティに使用</li>
  <li><strong>PascalCase</strong>：クラス名、コンポーネント名に使用</li>
  <li><strong>snake_case</strong>：Python変数、データベース列名に使用</li>
  <li><strong>kebab-case</strong>：CSSクラス名、URLスラッグに使用</li>
  <li><strong>CONSTANT_CASE</strong>：定数、環境変数に使用</li>
</ul>

## 例：Qiita API のフィールド名を JavaScript の名前にする

Qiita API v2 の記事（Item）のレスポンスでは、`likes_count`、`rendered_body`、`page_views_count` のようにアンダースコア区切りのフィールド名が使われています（[Qiita API v2 ドキュメント](https://qiita.com/api/v2/docs)）。JavaScript 側で同じ値を受け取る変数を作るときは、フィールド名を 1 つずつ貼り付けて camelCase の行を見ます。

{/* tc-check: {"input":"likes_count","camel":"likesCount"} */}

- `likes_count` → camelCase `likesCount`

{/* tc-check: {"input":"rendered_body","camel":"renderedBody","pascal":"RenderedBody"} */}

- `rendered_body` → camelCase `renderedBody`、PascalCase `RenderedBody`

{/* tc-check: {"input":"page_views_count","camel":"pageViewsCount","constant":"PAGE_VIEWS_COUNT"} */}

- `page_views_count` → camelCase `pageViewsCount`。定数名にするなら CONSTANT_CASE の `PAGE_VIEWS_COUNT`

変換結果はあくまで新しい名前です。API に送るときや受け取ったデータを読むときは、元のフィールド名（`likes_count` など）のまま扱ってください。

## 例：全角英字と全角スペースが混ざった名前

日本語の文書から項目名をコピーすると、全角英字や全角スペースが混ざっていることがあります。このツールは全角英字も英字として大文字・小文字を判定しますが、半角には直しません。

{/* tc-check: {"input":"ｕｓｅｒ　ｎａｍｅ","camel":"ｕｓｅｒＮａｍｅ","snake":"ｕｓｅｒ_ｎａｍｅ"} */}

- `ｕｓｅｒ　ｎａｍｅ`（全角英字と全角スペース）→ camelCase `ｕｓｅｒＮａｍｅ`、snake_case `ｕｓｅｒ_ｎａｍｅ`。全角スペースは区切りになりますが、英字は全角のままです。

{/* tc-check: {"input":"ユーザーID","kebab":"ユーザーid","constant":"ユーザーID"} */}

- `ユーザーID` → kebab-case `ユーザーid`、CONSTANT_CASE `ユーザーID`。カタカナの直後の大文字は新しい単語の始まりとして扱われないため、「ユーザー」と「ID」は 1 語のままです。間に半角スペースを入れれば分かれます。

ソースコードの識別子にする場合は、全角英字を半角にしてから貼り付けてください。

<h2>単語の分け方</h2>
<p>camelCase、PascalCase、kebab-case、snake_case、CONSTANT_CASE は、まず入力を単語に分けます。規則は <a href="https://github.com/blakeembrey/change-case" rel="noopener">change-case</a> ライブラリの <code>split</code>（<code>separateNumbers</code> 有効）と同じです。</p>
<ul>
  <li>小文字または数字の後に大文字が来たら区切る：<code>userLoginCount</code> → user、Login、Count</li>
  <li>大文字の連続の後に新しい単語が続く場合、最後の大文字の前で区切る：<code>XMLHttpRequest</code> → XML、Http、Request</li>
  <li>文字と数字の間で区切る：<code>base64Encode</code> → base、64、Encode</li>
  <li>スペース・句読点・記号はすべて区切りとして扱う：<code>user-login_count</code> → user、login、count</li>
</ul>
<p>区切る前にアポストロフィを取り除きます（lodash と同じ）。<code>don't stop</code> → <code>dontStop</code>。どの文字体系の文字もアクセント記号も残ります：<code>café au lait</code> → <code>caféAuLait</code>、<code>Привет мир</code> → <code>приветМир</code>。各言語のスタイルガイドが略語や数字をどう扱うかは、<a href="/ja/blog/text-case-guide/">キャメルケースの解説記事</a>で比較しています。</p>

<h2>制限事項</h2>
<ul>
  <li>Title Case と Sentence case は元のスペースと句読点を保ち、変数名を分割しません：<code>userLoginCount</code> → <code>Userlogincount</code>。Title Case は of や the などの短い語も先頭を大文字にします。</li>
  <li>Sentence case は入力全体で最初に現れる文字 1 つだけを大文字にし、残りをすべて小文字にします。先頭のスペース・引用符・かっこ・記号は飛ばします。かなや漢字も「文字」に数えますが大文字がないため、日本語で始まる入力ではどこも大文字になりません。最初に現れる文字または数字が数字の場合も大文字にしません：<code>2FA CODE</code> → <code>2fa code</code>（下の例）。</li>
  <li>camelCase と PascalCase では略語の大文字は保たれません：<code>parseHTML</code> → <code>parseHtml</code>。</li>
  <li>大文字・小文字の変換はブラウザ既定の Unicode 規則で、言語ごとの規則は使いません：<code>ß</code> は CONSTANT_CASE で <code>SS</code> になり、トルコ語の点付き・点なし i は特別扱いしません。</li>
  <li>絵文字は 5 つの命名形式では区切りとして消えます。UPPER CASE、lower case、Title Case、Sentence case では残ります。</li>
</ul>

{/* tc-check: {"input":"(draft) release notes","sentence":"(Draft) release notes","title":"(Draft) Release Notes"} */}

例：`(draft) release notes` は先頭の丸かっこを飛ばすので、Sentence case の結果は `(Draft) release notes` です。Title Case では `(Draft) Release Notes` になります。

{/* tc-check: {"input":"2FA CODE","sentence":"2fa code"} */}

例：`2FA CODE` は数字で始まるため、Sentence case の結果は `2fa code` で、大文字になる文字はありません。
