<h2>텍스트 케이스 변환에 대하여</h2>
<p>프로그래밍에서는 변수명·함수명·상수명에 각각 다른 명명 규칙이 사용됩니다. 이 도구는 입력 하나로 9가지 형식을 한꺼번에 보여 주므로, 필요한 행만 복사하면 됩니다.</p>
<ul>
  <li><strong>camelCase</strong>: JavaScript 변수, 객체 속성에 사용</li>
  <li><strong>PascalCase</strong>: 클래스명, 컴포넌트명에 사용</li>
  <li><strong>snake_case</strong>: Python 변수, 데이터베이스 열 이름에 사용</li>
  <li><strong>kebab-case</strong>: CSS 클래스명, URL 슬러그에 사용</li>
  <li><strong>CONSTANT_CASE</strong>: 상수, 환경 변수에 사용</li>
</ul>

## 예시: 카카오 로컬 API 응답 필드를 JavaScript 이름으로

카카오 로컬 API의 ‘키워드로 장소 검색’ 응답은 `place_name`(장소명, 업체명), `road_address_name`(전체 도로명 주소), `category_group_code`처럼 밑줄로 나눈 필드 이름을 씁니다([카카오 로컬 API 개발 가이드](https://developers.kakao.com/docs/latest/ko/local/dev-guide)). 프런트엔드에서 같은 값을 담을 변수나 props 이름을 정할 때 필드 이름을 하나씩 붙여 넣고 camelCase 행을 보면 됩니다.

{/* tc-check: {"input":"place_name","camel":"placeName"} */}

- `place_name` → camelCase `placeName`

{/* tc-check: {"input":"road_address_name","camel":"roadAddressName","pascal":"RoadAddressName"} */}

- `road_address_name` → camelCase `roadAddressName`, PascalCase `RoadAddressName`

{/* tc-check: {"input":"is_end","camel":"isEnd","constant":"IS_END"} */}

- 응답의 `meta`에 있는 `is_end` → camelCase `isEnd`, CONSTANT_CASE `IS_END`

여기서 만든 이름은 코드 안에서 쓰는 새 이름일 뿐입니다. 응답 JSON을 읽을 때는 원래 필드 이름(`place_name` 등)으로 접근해야 합니다.

## 예시: 한글과 영문이 섞인 이름

기획서나 엑셀 시트에는 ‘회원ID’, ‘주문번호 order_no’처럼 한글과 영문이 섞인 항목명이 자주 나옵니다. 한글은 대소문자가 없어 모든 형식에서 그대로 남고, 공백이나 기호가 있는 곳에서만 단어가 나뉩니다.

{/* tc-check: {"input":"회원ID","kebab":"회원id","constant":"회원ID"} */}

- `회원ID` → kebab-case `회원id`, CONSTANT_CASE `회원ID`. 한글 바로 뒤의 대문자는 새 단어의 시작으로 보지 않아 하나의 단어가 됩니다.

{/* tc-check: {"input":"회원 ID","snake":"회원_id","camel":"회원Id"} */}

- `회원 ID`(사이에 공백) → snake_case `회원_id`, camelCase `회원Id`

{/* tc-check: {"input":"주문번호 order_no","camel":"주문번호OrderNo","kebab":"주문번호-order-no"} */}

- `주문번호 order_no` → camelCase `주문번호OrderNo`, kebab-case `주문번호-order-no`

이 도구는 한글을 로마자나 영어로 옮기지 않습니다. 코드에 넣을 이름은 영문으로 바꾼 뒤 변환하세요.

<h2>단어를 나누는 규칙</h2>
<p>camelCase, PascalCase, kebab-case, snake_case, CONSTANT_CASE는 먼저 입력을 단어로 나눕니다. 규칙은 <a href="https://github.com/blakeembrey/change-case" rel="noopener">change-case</a> 라이브러리의 <code>split</code>(<code>separateNumbers</code> 사용)과 같습니다.</p>
<ul>
  <li>소문자나 숫자 뒤에 대문자가 오면 나눕니다: <code>userLoginCount</code> → user, Login, Count</li>
  <li>대문자가 이어지다 새 단어가 시작되면 마지막 대문자 앞에서 나눕니다: <code>XMLHttpRequest</code> → XML, Http, Request</li>
  <li>문자와 숫자 사이에서 나눕니다: <code>base64Encode</code> → base, 64, Encode</li>
  <li>공백, 문장 부호, 기호는 모두 구분자로 봅니다: <code>user-login_count</code> → user, login, count</li>
</ul>
<p>나누기 전에 아포스트로피를 지웁니다(lodash와 같음). <code>don't stop</code> → <code>dontStop</code>. 모든 문자 체계의 글자와 악센트는 그대로 남습니다: <code>café au lait</code> → <code>caféAuLait</code>, <code>Привет мир</code> → <code>приветМир</code>.</p>

<h2>제한 사항</h2>
<ul>
  <li>Title Case와 Sentence case는 원문의 공백과 문장 부호를 유지하고 변수명을 나누지 않습니다: <code>userLoginCount</code> → <code>Userlogincount</code>. Title Case는 of, the 같은 짧은 단어도 첫 글자를 대문자로 바꿉니다.</li>
  <li>Sentence case는 입력 전체의 첫 글자 하나만 대문자로 바꾸고 나머지는 모두 소문자로 바꿉니다. 첫 글자가 따옴표나 공백이면 아무 글자도 대문자가 되지 않습니다(아래 예시).</li>
  <li>camelCase와 PascalCase에서는 약어의 대문자가 유지되지 않습니다: <code>parseHTML</code> → <code>parseHtml</code>.</li>
  <li>대소문자 변환은 브라우저 기본 Unicode 규칙을 따르며 언어별 규칙은 쓰지 않습니다: <code>ß</code>는 CONSTANT_CASE에서 <code>SS</code>가 되고, 터키어의 점 있는 i / 점 없는 i는 따로 처리하지 않습니다.</li>
  <li>이모지는 다섯 가지 이름 형식에서는 구분자로 취급되어 사라지고, 대문자·소문자·Title Case·Sentence case에서는 남습니다.</li>
  <li>전각 영문(<code>ｕｓｅｒ</code> 등)은 모든 형식에서 전각 그대로 나옵니다. ASCII 이름이 필요하면 먼저 반각으로 바꾸세요.</li>
</ul>

{/* tc-check: {"input":"\"hello\" she said","sentence":"\"hello\" she said","upper":"\"HELLO\" SHE SAID"} */}

예: `"hello" she said`는 첫 글자가 따옴표라서 Sentence case 결과도 `"hello" she said` 그대로입니다. UPPER CASE는 `"HELLO" SHE SAID`가 됩니다.
