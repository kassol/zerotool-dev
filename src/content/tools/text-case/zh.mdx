## 示例：把数据库列名改成 Java 属性名

后端项目里，MySQL 表的列名多用下划线，Java 实体类的属性用驼峰。MyBatis 的配置文档把 `mapUnderscoreToCamelCase` 设置描述为「是否开启驼峰命名自动映射，即从经典数据库列名 A_COLUMN 映射到经典 Java 属性名 aColumn」，默认值为 false。没开这个设置、要在 `resultMap` 里逐个写属性名时，可以把列名一个一个粘进来，看 camelCase 一行：

{/* tc-check: {"input":"create_time","camel":"createTime","pascal":"CreateTime"} */}

- `create_time` → camelCase `createTime`，PascalCase `CreateTime`

{/* tc-check: {"input":"is_deleted","camel":"isDeleted","constant":"IS_DELETED"} */}

- `is_deleted` → camelCase `isDeleted`；CONSTANT_CASE 一行是 `IS_DELETED`，可直接当常量名

{/* tc-check: {"input":"user_id, create_time","camel":"userIdCreateTime"} */}

注意不要把整行列名一起粘进来：`user_id, create_time` 的逗号和空格也是分隔符，camelCase 会得到一个合在一起的 `userIdCreateTime`。换行同样是分隔符，所以每行一个列名的列表也会合成一个名字；多个列名只能逐个粘贴转换。

## 示例：中英文混排的名字

产品文档里常见「用户ID」「订单号 order_no」这类写法。工具对汉字的处理是：汉字没有大小写，九种格式里都原样保留；汉字和英文之间有空格或标点时才断开。

{/* tc-check: {"input":"用户ID","kebab":"用户id","constant":"用户ID"} */}

- `用户ID` → kebab-case `用户id`，CONSTANT_CASE `用户ID`。汉字后紧跟的大写字母不算新词的开头，所以「用户」和「ID」被当成一个词。

{/* tc-check: {"input":"用户 ID","kebab":"用户-id","snake":"用户_id"} */}

- `用户 ID`（中间加一个空格）→ kebab-case `用户-id`，snake_case `用户_id`。

{/* tc-check: {"input":"订单号 order_no","camel":"订单号OrderNo","snake":"订单号_order_no"} */}

- `订单号 order_no` → camelCase `订单号OrderNo`，snake_case `订单号_order_no`。

真正要放进代码的名字，通常还是改成全英文。这个工具不做中文到拼音或英文的转换。

<h2>拆词规则</h2>
<p>camelCase、PascalCase、kebab-case、snake_case、CONSTANT_CASE 先把输入拆成单词，规则与 <a href="https://github.com/blakeembrey/change-case" rel="noopener">change-case</a> 库开启 <code>separateNumbers</code> 的 <code>split</code> 相同：</p>
<ul>
  <li>小写字母或数字后跟大写字母处断开：<code>userLoginCount</code> → user、Login、Count。</li>
  <li>连续大写后接新单词时，在最后一个大写字母前断开：<code>XMLHttpRequest</code> → XML、Http、Request。</li>
  <li>字母与数字之间断开：<code>base64Encode</code> → base、64、Encode。</li>
  <li>空格、标点、符号一律当作分隔符：<code>user-login_count</code> → user、login、count。</li>
</ul>
<p>拆词前先去掉撇号（同 lodash），<code>don't stop</code> → <code>dontStop</code>。各种文字的字母和重音都保留：<code>café au lait</code> → <code>caféAuLait</code>，<code>Привет мир</code> → <code>приветМир</code>。各语言变量名、类名、常量名惯用哪种格式，可以看<a href="/zh/blog/text-case-guide/">命名风格转换指南</a>里的速查表。</p>

<h2>限制</h2>
<ul>
  <li>Title Case 和 Sentence case 保留原文的空格与标点，不拆变量名：<code>userLoginCount</code> → <code>Userlogincount</code>。Title Case 把每个单词首字母大写，of、the 这类短词也一样。</li>
  <li>Sentence case 只把整段输入的第一个字符变成大写，其余全部小写；第一个字符是引号或空格时，什么都不会变成大写（见下例）。</li>
  <li>camelCase 与 PascalCase 不保留缩写的全大写：<code>parseHTML</code> → <code>parseHtml</code>。</li>
  <li>大小写转换用浏览器默认的 Unicode 规则，不按语言区域处理：<code>ß</code> 在 CONSTANT_CASE 中变成 <code>SS</code>，土耳其语的带点 / 不带点 i 不做特殊处理。</li>
  <li>中文、日文、韩文没有大小写，原样输出；它们之间的空格与标点会变成分隔符。</li>
  <li>表情符号在五种命名格式里被当作分隔符删掉，在大写、小写、Title Case、Sentence case 里保留。</li>
  <li>中文输入法打出的全角字母（如 <code>ｕｓｅｒ</code>）在所有格式里仍是全角。结果必须是 ASCII 时，先把全角字母换成半角再转换。</li>
</ul>

{/* tc-check: {"input":"\"hello\" she said","sentence":"\"hello\" she said"} */}

例：`"hello" she said` 第一个字符是引号，Sentence case 的结果仍是 `"hello" she said`，首字母没有大写。
