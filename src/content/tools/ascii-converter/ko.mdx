## 변환 예시

아래 결과는 이 도구의 변환 함수로 계산했으며, 상태 메시지도 페이지에 표시되는 문구와 같습니다.

{/* ac-check: {"text":"한글","fmt":"hex","status":true} */}
### 한글을 코드로

텍스트에 `한글`을 넣고 16진수를 선택한 뒤 텍스트 → ASCII를 누르면 다음과 같습니다.

```text
0xD55C 0xAE00
```

상태 메시지는 `2개 문자를 변환했습니다.`입니다. 한글 음절은 ASCII 범위 밖이므로 Unicode 코드 포인트(U+D55C, U+AE00)가 그대로 나옵니다. 10진수로 바꾸고 다시 누르면 `54620 44544`가 됩니다.

{/* ac-check: {"codes":"54620 44544"} */}
### 코드를 한글로

`54620 44544`를 ASCII / Unicode 코드에 넣고 ASCII → 텍스트를 누르면 `한글`로 돌아옵니다. 10진수와 16진수를 섞어 `54620 0xAE00`처럼 써도 됩니다.

{/* ac-check: {"codes":"0xD55C,0xAE00 ０xAE00","error":true} */}
### 전각 문자가 섞였을 때

한글 입력 상태에서 전각으로 바뀐 숫자가 끼어들면 그 항목에서 변환이 멈춥니다. `0xD55C,0xAE00 ０xAE00`을 넣으면 상태 메시지는 다음과 같습니다.

```text
Error: Invalid code: ０xAE00
```

앞의 두 항목이 올바르더라도 아무것도 변환되지 않습니다. 오류에 표시된 항목을 반각으로 고친 뒤 다시 누르세요.

## ₩ 와 백슬래시

당시 Microsoft에서 일하던 Michael Kaplan이 MSDN 블로그에 쓴 글 「[When is a backslash not a backslash?](http://archives.miloush.net/michkap/archive/2005/09/17/469941.html)」(보관본)에 따르면, 한국어 코드 페이지 949에서 0x5C는 원화 기호이고, 시스템 로캘이 한국어인 Windows의 글꼴은 U+005C를 원화 기호 모양으로 표시합니다. 그래서 경로가 `C:₩Program Files` 처럼 보여도 실제 문자는 백슬래시입니다.

{/* ac-check: {"text":"\\5,000","fmt":"dec"} */}
진짜 백슬래시로 시작하는 `\5,000`은 첫 코드가 92입니다.

```text
92 53 44 48 48 48
```

{/* ac-check: {"text":"₩5,000","fmt":"dec"} */}
원화 기호 U+20A9를 쓴 `₩5,000`은 첫 코드가 8361입니다.

```text
8361 53 44 48 48 48
```

전각 원화 기호 ￦는 65510으로 또 다른 문자입니다. 프로그램에서 이스케이프 문자나 경로 구분자로 동작하는 것은 92뿐이므로, 복사한 문자열이 기대대로 동작하지 않을 때 어느 문자인지 먼저 확인해 보세요.

## 자모로 나뉜 한글

같은 「한」도 완성형 음절 하나(U+D55C)로 저장될 수 있고, 초성·중성·종성 세 개로 나뉘어 저장될 수도 있습니다. Apple의 기술 문서 [QA1173](https://developer.apple.com/library/archive/qa/qa1173/_index.html)은 macOS의 HFS Plus 볼륨이 파일 이름을 분해형 Unicode로 저장한다고 설명합니다.

{/* ac-check: {"text":"\u1112\u1161\u11ab","fmt":"hex"} */}
화면에서는 똑같이 보이는 분해형 <code>{'\u1112\u1161\u11AB'}</code>를 16진수로 변환하면 코드가 세 개 나옵니다.

```text
0x1112 0x1161 0x11AB
```

파일 이름을 비교하거나 검색할 때 글자 수가 맞지 않는다면 이런 차이를 의심해 볼 수 있습니다.

## 줄바꿈과 탭

줄바꿈과 탭도 숫자로 출력됩니다. Windows 텍스트의 줄바꿈은 보통 `13 10`(CR LF), macOS와 Linux는 `10`(LF)이며 탭은 `9`입니다. 반대 방향에서 `10`을 넣으면 텍스트 창에 실제 줄바꿈이 들어갑니다.

## 제한

- 텍스트 → ASCII는 Unicode 코드 포인트 단위로 처리합니다. 피부색을 지정한 👍🏽처럼 여러 코드 포인트로 된 이모지는 `128077 127997` 두 개의 코드가 됩니다.
- 출력은 코드 포인트이며 EUC-KR이나 UTF-8 바이트가 아닙니다. 「한」은 54620(U+D55C)으로 표시되지만 EUC-KR에서는 `C7 D1` 2바이트입니다. 바이트를 보려면 [이진수 변환기 (텍스트 ↔ 2진수)](/ko/tools/text-to-binary/)을 사용하세요.
- ASCII → 텍스트는 0~1114111(`0x10FFFF`)을 받습니다. 55296~57343(`0xD800`~`0xDFFF`)은 서로게이트라서 문자가 아니며 `Code point out of range`가 표시됩니다.
- `72abc`, `1.5`, `0b102`처럼 해당 진수의 숫자로만 이루어지지 않은 코드는 `Invalid code`가 되며, 고칠 때까지 아무것도 변환하지 않습니다.
- 두 가지 오류 메시지는 모든 언어 페이지에서 영어로 표시됩니다. 변환에 성공했을 때의 개수 메시지는 페이지 언어로 표시됩니다.

## ASCII란

ASCII(American Standard Code for Information Interchange)는 영문자·숫자·기호·제어 문자 128개에 0~127 번호를 붙인 7비트 문자 코드입니다. UTF-8은 0~127 문자를 ASCII와 같은 값의 1바이트로 나타내므로([RFC 3629](https://www.rfc-editor.org/rfc/rfc3629#section-1)) 영문과 숫자만 있는 ASCII 파일은 그대로 UTF-8로 읽힙니다.
