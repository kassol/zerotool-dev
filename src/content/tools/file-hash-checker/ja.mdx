## JAIST ミラーの Ubuntu WSL イメージを照合する

北陸先端科学技術大学院大学（JAIST）のミラーは Ubuntu の公式ファイルをそのまま配布しています。2026 年 10 月 1 日に確認したところ、JAIST の `ubuntu-releases/24.04/SHA256SUMS` は [releases.ubuntu.com の SHA256SUMS](https://releases.ubuntu.com/24.04/SHA256SUMS) とバイト単位で同じで、9 行ありました。各行は次の形です。

```text
bb415d824822c4b878125729af451a5d18fb13d1cf5cbed9a7393ad64ac6039e *ubuntu-24.04.5-wsl-amd64.wsl
```

ファイル名の前の `*` はバイナリーモードの印で、GNU coreutils の[出力形式](https://www.gnu.org/software/coreutils/manual/html_node/cksum-output-modes.html)の一部です。WSL 用イメージ `ubuntu-24.04.5-wsl-amd64.wsl`（388,975,696 バイト）をドロップし、9 行を貼り付けると、カードに「✓ 一致」と「一覧の ubuntu-24.04.5-wsl-amd64.wsl の SHA-256 と一致します（8 行目）。」が出ます。残り 8 行は選んでいないファイルとして件数だけ表示され、エラーにはなりません。

## Firefox 日本語版を SHA512SUMS で確かめる

Mozilla はリリースごとに全言語・全プラットフォームの値を 1 つのファイルにまとめています。Firefox 157.0 の [SHA512SUMS](https://archive.mozilla.org/pub/firefox/releases/157.0/SHA512SUMS) は 4,921 行で、日本語版 Windows インストーラーは `win64/ja/Firefox Setup 157.0.exe`、韓国語版は `win64/ko/Firefox Setup 157.0.exe` と、ファイル名が同じでフォルダーだけが違います。

ダウンロードした `Firefox Setup 157.0.exe`（93,612,392 バイト）をドロップし、SHA512SUMS を「チェックサムファイルを開く」で読み込みます。ファイル名に SHA512 が含まれるので、128 桁の値は SHA-512 として扱われ、SHA-512 にも自動でチェックが入ります。同じ名前の候補が複数あるときは、値が一致する行を採ります。結果は「一覧の win64/ja/Firefox Setup 157.0.exe の SHA-512 と一致します（4715 行目）。」でした。フォルダーを持たない 1 ファイルを、正しい言語の行に結び付けられています。

## 貼り付けられる形式

Windows の `certutil -hashfile ファイル SHA256` の出力（説明の行・ハッシュの行・完了メッセージ）や、PowerShell の [`Get-FileHash`](https://learn.microsoft.com/ja-jp/powershell/module/microsoft.powershell.utility/get-filehash)（既定は SHA256、大文字の16進数）の表は、そのまま貼り付けられます。ほかに `shasum --tag` や OpenSSL の `SHA256 (ファイル名) = 値`、npm の `package-lock.json` にある `sha512-…`（[SRI](https://www.w3.org/TR/SRI/) 形式の Base64）、Docker の `sha256:…`、SFV の CRC32 も読みます。全角の英数字や途中の空白、大文字・小文字の違いは問題になりません。

値に誤りがあれば行番号付きで知らせます。末尾に `x` が付いた SHA-256 なら「1 行目：65 文字目の「x」は16進数（0–9、a–f）ではありません。」、SHA3 と書かれた値なら「対応していません」と表示し、一部が一致したからといって「一致」にはしません。このツールの旧版は空白を除いた貼り付け文字列の中に計算結果が含まれていれば一致としていたため、余分な文字があっても「一致」と出ていました。

## 大きなファイルの扱い

ブラウザー標準の Web Crypto はデータ全体を一度に渡す仕組みです。旧版はファイル全体をメモリに読み込んでいたので、1 GB でタブのメモリが約 2 GB 増え、MD5 も選ぶと 12 秒間操作できず、3 GB では「ファイルを読み込めませんでした」で止まっていました。現在は [hash-wasm](https://github.com/Daninet/hash-wasm) を使い、ワーカー内で 1 MB ずつ計算します。2026 年 10 月 1 日、Apple M1 Max のデスクトップ版 Chromium で、1 GB の SHA-256 は 4.3 秒、メモリの増加は約 100 MB でした。4,080,486,400 バイトの Ubuntu 24.04.5 サーバー版 ISO も、公式 SHA256SUMS と一致しました。

## 他のツールとの違い

2026 年 10 月 1 日、デスクトップ版 Chromium で同じファイルを使い、開発者ツールで通信を確認しました。どのツールもファイルを送信していません。

| ツール | 0 バイトのファイル | 3 GB のファイル | 2 行の一覧（ハッシュを入れ替え） |
|---|---|---|---|
| このツール | 正しい値 | 正しい値 | 2 件とも「不一致」 |
| BrowserTools.jp ファイルハッシュ値計算・照合ツール | 正しい値 | 120 秒後も結果なし、エラー表示なし | 入力欄が 1 行で、何も強調されない |
| emn178 Online Tools | 結果なし | 正しい値（83 秒） | 照合欄なし |
| PiliApp（kr.piliapp.com） | 正しい値 | 150 秒後も結果なし、エラー表示なし | 2 件とも「일치」（一致） |

BrowserTools.jp は 1 GB なら 4 種類のハッシュをまとめて出せますが、3 GB では何も表示されません。PiliApp は値だけで照合するため、ファイル名とハッシュの組み合わせが間違った一覧でも一致と表示します。

## 制限

- 対応は SHA-256・SHA-1・SHA-384・SHA-512・MD5・CRC32 です。SHA-224・SHA3・BLAKE2（Arch Linux の `b2sums.txt` など）・BLAKE3 は計算しません。
- 一度に追加できるのは 1,000 ファイルまで、チェックサム一覧は 1 MB までです。
- GPG 署名は検証しません。一覧そのものの正しさは [Ubuntu の手順](https://ubuntu.com/tutorials/how-to-verify-ubuntu)のように署名で確かめてください。
- MD5・SHA-1 は意図的な衝突を作れます（SHA-1 の例は [SHAttered](https://shattered.io/)）。CRC32 は偶発的な破損の検出用です。
- 「フォルダーを選択」ボタンは画面幅が狭いときは表示しません。フォルダーのドロップはドラッグ＆ドロップできるブラウザーで使えます。
- 文字列のハッシュ値は[ハッシュジェネレーター](/ja/tools/hash-generator/)、鍵付きのハッシュは [HMAC ジェネレーター](/ja/tools/hmac-generator/)で計算できます。
