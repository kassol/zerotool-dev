## 카카오 미러에서 받은 Ubuntu 서버 ISO 확인

국내에서는 Ubuntu를 카카오 미러(mirror.kakao.com)에서 많이 받습니다. 2026년 10월 1일 확인한 결과, [카카오 미러의 SHA256SUMS](https://mirror.kakao.com/ubuntu-releases/24.04/SHA256SUMS)는 [releases.ubuntu.com의 원본](https://releases.ubuntu.com/24.04/SHA256SUMS)과 바이트 단위로 같았고 9줄이었습니다.

`ubuntu-24.04.5-live-server-amd64.iso`(4,080,486,400바이트, 약 3.8 GB)와 WSL용 `ubuntu-24.04.5-wsl-amd64.wsl`을 함께 끌어다 놓고 9줄을 붙여 넣으면 다음과 같이 나옵니다.

```text
ubuntu-24.04.5-live-server-amd64.iso   3.8 GB   ✓ 일치
SHA-256  97f3d7ffb032c3eb3b23d2c8be9cc76e60c2c1f2c0146ba5ba9fe01cafae0fd8
목록에 있는 ubuntu-24.04.5-live-server-amd64.iso의 SHA-256 값과 일치합니다(7번째 줄).
```

아래 요약은 '일치 2개 · 불일치 0개'와 '목록에 있는 7개 파일을 선택하지 않았습니다'입니다. 선택하지 않은 줄은 오류로 치지 않습니다. 파일 전체를 메모리에 올리던 이 도구의 예전 버전은 3 GB 파일에서 '파일을 읽을 수 없습니다'라는 오류로 멈췄습니다. 지금은 워커가 [hash-wasm](https://github.com/Daninet/hash-wasm)으로 1 MB씩 읽어 계산하므로, 탭의 메모리는 100 MB 정도만 늘어납니다.

## Firefox 한국어판 설치 파일 확인

Mozilla는 버전마다 모든 언어와 플랫폼의 해시를 파일 하나에 모아 둡니다. Firefox 157.0의 [SHA256SUMS](https://archive.mozilla.org/pub/firefox/releases/157.0/SHA256SUMS)에서 한국어판 Windows 설치 파일은 `win64/ko/Firefox Setup 157.0.exe` 줄에 있고, 일본어판(`win64/ja/…`)과 파일 이름이 같습니다.

받은 `Firefox Setup 157.0.exe`(93,450,968바이트)를 끌어다 놓고 SHA256SUMS를 '체크섬 파일 열기'로 읽으면, 같은 이름의 후보 가운데 값이 맞는 `win64/ko/Firefox Setup 157.0.exe` 줄과 짝지어 '일치'로 표시합니다. SHA-256은 `7086a2caf747f5bba9d900dd2125ad16411080fd676d9758b1d84050879cdcf8`입니다. [SHA512SUMS](https://archive.mozilla.org/pub/firefox/releases/157.0/SHA512SUMS)를 읽으면 파일 이름의 SHA512를 보고 SHA-512 계산을 자동으로 켭니다.

## 값을 잘못 붙여 넣었을 때

일부만 맞는다고 '일치'로 처리하지 않고, 어디가 틀렸는지 줄 번호와 함께 알려 줍니다.

| 붙여 넣은 값 | 표시 |
|---|---|
| SHA-256 끝에 `x`가 붙음 | 1번째 줄: 65번째 글자 "x"는 16진수(0–9, a–f)가 아닙니다. |
| 마지막 한 글자가 빠짐 | 1번째 줄: 16진수 63자리는 지원하는 해시 길이(…)가 아닙니다. |
| `SHA3-256 (x) = …` | 1번째 줄: SHA3는 지원하지 않습니다. |

예전 버전은 공백을 지운 붙여 넣기 내용 안에 계산 결과가 들어 있기만 하면 일치로 봤기 때문에, 글자가 하나 더 붙어 있어도 '일치'라고 나왔습니다.

Windows의 `certutil -hashfile 파일 SHA256` 출력과 PowerShell [`Get-FileHash`](https://learn.microsoft.com/ko-kr/powershell/module/microsoft.powershell.utility/get-filehash) 표(기본 SHA256, 대문자 16진수)는 그대로 붙여 넣어도 됩니다. `shasum --tag`, OpenSSL의 `SHA256 (파일) = 값`, npm `package-lock.json`의 `sha512-…`([SRI](https://www.w3.org/TR/SRI/) 형식 Base64), Docker의 `sha256:…`, SFV의 CRC32도 읽습니다.

## 다른 도구와 비교

2026년 10월 1일 데스크톱 Chromium에서 같은 파일로 시험하고 개발자 도구로 네트워크 요청을 확인했습니다. 아래 도구는 모두 파일을 업로드하지 않았습니다.

| 도구 | 0바이트 파일 | 3 GB 파일 | 해시를 서로 바꿔 적은 2줄 목록 |
|---|---|---|---|
| 이 도구 | 올바른 값 | 올바른 값 | 두 파일 모두 '불일치' |
| PiliApp SHA 파일 해시값 확인 | 올바른 값 | 150초 뒤에도 결과·오류 표시 없음 | 두 파일 모두 '일치' |
| emn178 Online Tools | 결과 없음 | 올바른 값(83초) | 대조 기능 없음 |
| BrowserTools.jp | 올바른 값 | 120초 뒤에도 결과·오류 표시 없음 | 한 줄 입력이라 강조 없음 |

PiliApp은 '파일 크기 제한 없음'이라고 안내하지만 3 GB 파일에서는 아무것도 표시하지 않았습니다. 또 파일 이름은 보지 않고 값만 비교하기 때문에, 해시가 엇갈려 적힌 목록에서도 두 파일을 '일치'로 표시했습니다.

## 한계

- SHA-256, SHA-1, SHA-384, SHA-512, MD5, CRC32를 지원합니다. SHA-224, SHA3, BLAKE2(Arch Linux `b2sums.txt` 등), BLAKE3는 계산하지 않습니다.
- 한 번에 1,000개 파일까지, 체크섬 목록은 1 MB까지 읽습니다.
- GPG 서명은 검증하지 않습니다. 목록 자체가 배포처 것인지는 [Ubuntu 안내](https://ubuntu.com/tutorials/how-to-verify-ubuntu)처럼 서명으로 확인하세요.
- MD5와 SHA-1은 일부러 충돌을 만들 수 있습니다(SHA-1 사례: [SHAttered](https://shattered.io/)). CRC32는 우연한 손상 확인용입니다.
- '폴더 선택' 버튼은 좁은 화면에서 숨깁니다. 폴더 끌어다 놓기는 드래그 앤 드롭이 되는 브라우저에서 쓸 수 있습니다.
- 문자열의 해시는 [해시 생성기](/ko/tools/hash-generator/), 키를 쓰는 해시는 [HMAC 생성기](/ko/tools/hmac-generator/)를 쓰세요.
