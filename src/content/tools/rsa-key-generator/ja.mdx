<h2>セキュリティに関する注意</h2>
<ul>
  <li><strong>秘密鍵は厳重に保管</strong>してください。秘密鍵を持つ人は誰でもメッセージを復号したり署名を偽造できます。</li>
  <li>共有するのは<strong>公開鍵</strong>だけにしてください——公開鍵は公開されることを前提に設計されています。</li>
  <li>このツールはテスト・開発用途に適しています。本番環境では専用の鍵管理サービス（AWS KMS、HashiCorp Vaultなど）を使ってください。</li>
</ul>

## 出力の形式

**PEM** では、公開鍵は SubjectPublicKeyInfo（`-----BEGIN PUBLIC KEY-----`）、秘密鍵は暗号化なしの PKCS#8（`-----BEGIN PRIVATE KEY-----`）で出力されます。OpenSSL 3.6 はどちらもそのまま読めます（`Private-Key: (2048 bit, 2 primes)`）。PKCS#1（`-----BEGIN RSA PRIVATE KEY-----`）しか受け付けない古いソフトウェアでは変換が必要です。コマンドは下にあります。

**JWK**（[RFC 7517](https://www.rfc-editor.org/rfc/rfc7517)）はブラウザの Web Crypto API がエクスポートする形式です。RSA-OAEP なら `"alg": "RSA-OAEP-256"` と `"key_ops": ["encrypt"]`、RSASSA-PKCS1-v1_5 なら `"alg": "RS256"` と `"key_ops": ["verify"]` になります。出力に `kid` と `use` はありません。次の LINE の例で、実際の出力を全項目見られます。

## 例：LINE のアサーション署名キーを作る

Messaging API のチャネルアクセストークン v2.1 を発行するには、JWT に署名するアサーション署名キーが必要です。LINE Developers の「[チャネルアクセストークンv2.1を発行する](https://developers.line.biz/ja/docs/messaging-api/generate-json-web-token/)」は、公開鍵の条件として、`kty` が `RSA`、鍵長 2048 ビット、`alg` が `RS256`、`use` が `sig` か `key_ops` が `["verify"]` のどちらかを挙げ、`kid` があると登録時にエラーになると書いています。

このツールでは 2048 ビット、RSASSA-PKCS1-v1_5、JWK を選びます。公開鍵の出力は次のとおりです。モジュラス `n` は毎回変わるので、長さだけを書いています。

{/* rkg-check: {"size":2048,"algo":"RSASSA-PKCS1-v1_5","format":"jwk","part":"public","mask":"<{n} 文字>","nLength":342} */}
```json
{
  "alg": "RS256",
  "e": "AQAB",
  "ext": true,
  "key_ops": [
    "verify"
  ],
  "kty": "RSA",
  "n": "<342 文字>"
}
```

`key_ops` が `["verify"]` で `kid` がないので、条件を満たします。`n` は 2048 ビット（256 バイト）を base64url にしたもので、いつも `342` 文字です。`ext` は Web Crypto API が付ける項目で、同じドキュメントにある Chrome のコンソールで生成する例の出力にも入っています。

この公開鍵を LINE Developers コンソールの［チャネル基本設定］タブ、アサーション署名キーの［公開鍵を登録する］に貼り付けると `kid` が発行されます。JWT の署名には秘密鍵の JWK（`d`・`p`・`q` などを含む方）を使い、ヘッダーにはその `kid` を入れます。秘密鍵はサーバー側だけに置き、コンソールには貼らないでください。

## 公開鍵を最後までコピーできたか確かめる

フォームに PEM の公開鍵を貼り付けるとき、末尾が欠けていないかは長さと両端で確かめられます。乱数で決まるのは中ほどのモジュラスだけで、前後のバイトは鍵長で決まっています。

{/* rkg-check: {"size":2048,"algo":"RSA-OAEP","format":"pem","part":"public","header":"-----BEGIN PUBLIC KEY-----","footer":"-----END PUBLIC KEY-----","oneLine":392,"lines":7,"lastLine":8,"start":"MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA","end":"IDAQAB"} */}
2048 ビットの公開鍵は、`-----BEGIN PUBLIC KEY-----` と `-----END PUBLIC KEY-----` の間が `7` 行です。64 文字の行が 6 行続き、最後の行は `8` 文字で、合計 `392` 文字になります。先頭は `MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA`、末尾は公開指数 65537 を含む `IDAQAB` で、アルゴリズムの選択に関係なく同じです。

## OpenSSH と OpenSSL で使う

次のコマンドは、ダウンロードしたファイルに対して macOS の OpenSSH と OpenSSL 3.6.1 で実行して確認しました。秘密鍵ファイルを他人が読める状態だと `ssh-keygen` は拒否する（「Permissions 0644 … are too open」）ので、先に権限を絞ります：

```bash
chmod 600 private-key.pem

# OpenSSH public key for ~/.ssh/authorized_keys
ssh-keygen -y -f private-key.pem
ssh-keygen -i -m PKCS8 -f public-key.pem      # same result from the public key

# PKCS#1 ("BEGIN RSA PRIVATE KEY") for older software
openssl rsa -in private-key.pem -traditional -out private-key-pkcs1.pem

# Inspect the key
openssl pkey -in private-key.pem -noout -text
```

## 鍵長とアルゴリズムの選び方

| 鍵長 | セキュリティ強度（[NIST SP 800-57 Part 1 Rev. 5](https://csrc.nist.gov/pubs/sp/800/57/pt1/r5/final) 表 2） |
|---|---|
| 1024 ビット | 80 ビット、使用不可 |
| 2048 ビット | 112 ビット |
| 3072 ビット | 128 ビット（このツールにはなし） |
| 4096 ビット | 128 と 192 ビットの間 |

アルゴリズムの設定は、ブラウザが鍵に許す用途と JWK の記載を決めます。**RSA-OAEP**（SHA-256）は暗号化用、**RSASSA-PKCS1-v1_5**（SHA-256、JWT の `RS256`）は署名用です。PEM ファイルにはアルゴリズムの情報がないため、OpenSSL では同じ PEM 鍵をどちらの用途にも使えます。LINE のように鍵長が 2048 ビットと決まっている場合は、4096 ビットを選ばないでください。

## 制限

- 鍵長は 2048 と 4096 のみで、公開指数は常に 65537（`AQAB`）です。
- 秘密鍵の PEM はパスフレーズで暗号化されません。保護された場所に保存するか、`openssl pkcs8 -topk8 -in private-key.pem -out encrypted.pem` で暗号化してください。
- OpenSSH 形式の秘密鍵、証明書、CSR は出力しません。`ssh-keygen` と `openssl req` を使ってください。
- JWK に `kid` や `use` を付ける機能はありません。必要なら出力した JSON に手で追加します（LINE のアサーション署名キーには `kid` を付けません）。`use` を付ける場合は `key_ops` を削除してください。[RFC 7517 の 4.3 節](https://www.rfc-editor.org/rfc/rfc7517#section-4.3)は `use` と `key_ops` を同時に使わないよう求めています（SHOULD NOT）。
- 4096 ビットは 2048 ビットより明らかに時間がかかります。ページは `crypto.subtle.generateKey` が返す Promise を待つだけで、Chromium はこの処理を「WebCrypto」という別スレッドで実行するため（[ソースコード](https://chromium.googlesource.com/chromium/src/+/main/components/webcrypto/webcrypto_impl.cc)）、待っている間も画面は固まりません。
- クリアボタンはありません。ツール内で Ctrl または Command + L を押すと両方の結果が消えます。
