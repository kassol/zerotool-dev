  <li><strong>공개 키</strong>만 공유하세요 — 공개 키는 공개되도록 설계되었습니다.</li>

## 출력 형식

**PEM**은 공개 키를 SubjectPublicKeyInfo(`-----BEGIN PUBLIC KEY-----`), 개인 키를 암호화하지 않은 PKCS#8(`-----BEGIN PRIVATE KEY-----`)로 출력합니다. OpenSSL 3.6은 둘 다 바로 읽습니다(`Private-Key: (2048 bit, 2 primes)`). PKCS#1(`-----BEGIN RSA PRIVATE KEY-----`)만 받는 오래된 소프트웨어는 변환이 필요합니다. 명령은 아래에 있습니다.

**JWK**([RFC 7517](https://www.rfc-editor.org/rfc/rfc7517))는 브라우저 Web Crypto API가 내보내는 형식입니다. RSA-OAEP를 고르면 `"alg": "RSA-OAEP-256"`과 `"key_ops": ["encrypt"]`, RSASSA-PKCS1-v1_5를 고르면 `"alg": "RS256"`과 `"key_ops": ["verify"]`가 됩니다. 출력에는 `kid`와 `use`가 없습니다.

## 예시: 카카오 로그인 공개키와 비교하기

카카오 로그인의 OpenID Connect는 ID 토큰 서명에 쓴 공개키 목록을 `https://kauth.kakao.com/.well-known/jwks.json`에서 JWK 배열로 제공합니다([REST API 문서의 ‘OIDC: 공개키 목록 조회’](https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api#oidc-find-public-key)). 문서에 나온 필드는 `kid`, `kty`(`RSA` 고정), `alg`, `use`(`sig` 고정), `n`, `e`입니다. 자체 서비스에서 RS256 서명 JWT를 발급하고 같은 방식으로 공개 키를 내보내려는 경우, 이 도구에서 2048비트, RSASSA-PKCS1-v1_5, JWK를 고르면 공개 키는 다음과 같습니다. 모듈러스 `n`은 매번 달라지므로 길이만 적었습니다.

{/* rkg-check: {"size":2048,"algo":"RSASSA-PKCS1-v1_5","format":"jwk","part":"public","mask":"<{n}자>","nLength":342} */}
```json
{
  "alg": "RS256",
  "e": "AQAB",
  "ext": true,
  "key_ops": [
    "verify"
  ],
  "kty": "RSA",
  "n": "<342자>"
}
```

`n`은 2048비트(256바이트)를 base64url로 쓴 값이라 항상 `342`자입니다. 2026년 10월 9일에 카카오의 공개키 목록을 조회했을 때 두 키 모두 `n`이 342자, `e`가 `AQAB`였으니 크기와 지수는 같습니다. 차이는 필드 구성입니다. 이 도구의 출력에는 `kid`와 `use`가 없고, Web Crypto API가 붙이는 `ext`와 `key_ops`가 있습니다. JWKS로 공개하려면 `kid`를 정해 넣고 `use`를 `sig`로 추가하세요. JWT 헤더의 `kid`로 검증 측이 어떤 키를 쓸지 고릅니다.

## 예시: 4096비트 키를 SSH에 쓰기

{/* rkg-check: {"size":4096,"algo":"RSASSA-PKCS1-v1_5","format":"pem","part":"public","oneLine":736,"sshPrefix":"ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAACAQ","sshLength":724,"fpLength":43,"keygenTail":"no comment (RSA)"} */}
4096비트 공개 키 PEM은 Base64 부분이 `736`자입니다. `ssh-keygen -i -m PKCS8 -f public-key.pem`으로 바꾸면 `ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAACAQ`로 시작하는 `724`자짜리 한 줄이 나오고, 끝에 주석은 붙지 않습니다. 이 줄을 `~/.ssh/authorized_keys`에 넣으면 됩니다. 파일로 저장해 지문을 보면 키 크기, `SHA256:` 뒤 `43`자, `no comment (RSA)` 순서로 나옵니다.

```
$ ssh-keygen -l -f public-key.pub
4096 SHA256:… no comment (RSA)
```

2048비트 키라면 같은 줄이 `ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQ`로 시작하고 380자입니다. 앞부분은 키 종류와 지수, 모듈러스 길이를 담고 있어서 키 크기마다 정해져 있고, 그 뒤가 매번 달라지는 모듈러스입니다. 붙여 넣은 줄이 이보다 짧으면 복사하다가 잘린 것입니다.

## OpenSSH와 OpenSSL에서 쓰기

아래 명령은 내려받은 파일로 macOS의 OpenSSH와 OpenSSL 3.6.1에서 실행해 확인했습니다. 다른 사용자가 읽을 수 있는 개인 키 파일은 `ssh-keygen`이 거부하므로("Permissions 0644 … are too open") 먼저 권한을 줄이세요:

```bash
chmod 600 private-key.pem

# OpenSSH public key for ~/.ssh/authorized_keys
ssh-keygen -y -f private-key.pem
ssh-keygen -i -m PKCS8 -f public-key.pem      # same result from the public key

# PKCS#1 ("BEGIN RSA PRIVATE KEY") for older software
openssl rsa -in private-key.pem -traditional -out private-key-pkcs1.pem

# Inspect the key
openssl pkey -in private-key.pem -noout -text
```

## 키 길이와 알고리즘 고르기

| 키 길이 | 보안 강도([NIST SP 800-57 Part 1 Rev. 5](https://csrc.nist.gov/pubs/sp/800/57/pt1/r5/final) 표 2) |
|---|---|
| 1024비트 | 80비트, 사용 불가 |
| 2048비트 | 112비트 |
| 3072비트 | 128비트(이 도구에는 없음) |
| 4096비트 | 128과 192비트 사이 |

알고리즘 설정은 브라우저가 키에 허용하는 용도와 JWK의 내용을 정합니다. **RSA-OAEP**(SHA-256)는 암호화용, **RSASSA-PKCS1-v1_5**(SHA-256, JWT의 `RS256`)는 서명용입니다. PEM 파일에는 알고리즘 정보가 없으므로 OpenSSL에서는 같은 PEM 키를 두 용도에 모두 쓸 수 있습니다.

## 제한 사항

- 키 길이는 2048과 4096뿐이며 공개 지수는 항상 65537(`AQAB`)입니다.
- 개인 키 PEM은 암호로 보호되지 않습니다. 보호된 위치에 저장하거나 `openssl pkcs8 -topk8 -in private-key.pem -out encrypted.pem`으로 암호화하세요.
- OpenSSH 형식 개인 키, 인증서, CSR은 출력하지 않습니다. `ssh-keygen`과 `openssl req`를 쓰세요.
- JWK에 `kid`나 `use`를 넣는 기능은 없습니다. 필요하면 출력된 JSON에 직접 추가하세요.
- 4096비트는 2048비트보다 눈에 띄게 오래 걸립니다. 페이지는 `crypto.subtle.generateKey`가 돌려주는 Promise를 기다리기만 하고, Chromium은 이 연산을 ‘WebCrypto’라는 별도 스레드에서 실행하므로([소스 코드](https://chromium.googlesource.com/chromium/src/+/main/components/webcrypto/webcrypto_impl.cc)) 기다리는 동안 화면이 멈추지 않습니다.
- 지우기 버튼은 없습니다. 도구 안에서 Ctrl 또는 Command + L을 누르면 두 결과가 모두 지워집니다.
