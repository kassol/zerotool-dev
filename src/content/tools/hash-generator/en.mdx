<h2>Which Hash Should I Use?</h2>
<ul>
  <li><strong>MD5:</strong> Legacy checksums and non-security file verification only.</li>
  <li><strong>SHA-1:</strong> Not safe for security uses, because collisions can be produced. Git still uses SHA-1 for object names by default.</li>
  <li><strong>SHA-256:</strong> The current standard for general cryptographic hashing, digital signatures, and TLS.</li>
  <li><strong>SHA-512:</strong> Larger output and security margin; whether it is faster or slower than SHA-256 depends on the CPU.</li>
</ul>
<p>
  <strong>Never use MD5 or SHA-1 for password hashing.</strong> Use a slow hash function
  like bcrypt, scrypt, or Argon2 for passwords.
</p>

## Non-ASCII Text and Encodings

{/* hash-check: {"in":"你好","algos":["md5","sha256"],"bytes":true} */}

The two characters `你好` are six bytes in UTF-8 (`e4 bd a0 e5 a5 bd`), and the tool gives MD5 `7eca689f0d3389d9dea66ae112e5cfd7` and SHA-256 `670d9743542cae3ea7ebe36af56bd53648b0a1126162e78d81a32934a711302e`. {/* hash-check: {"hex":"c4e3bac3","enc":"gbk","text":"你好","algos":["md5"],"bytes":true} */}A program that stores the same text in GBK hashes four different bytes (`c4 e3 ba c3`) and gets MD5 `b94ae3c6d892b29cf48d9bea819b27b9`. When two systems disagree about the hash of text that looks identical, compare the bytes before suspecting the hash. Common causes:

- a different encoding (GBK, Shift_JIS, UTF-16);
- a byte order mark at the start of a file: `hello` saved as UTF-8 with BOM hashes to SHA-256 `7489ebbcc2a00056ddaaaac190bce473e5c03696ea1bd8ed83cf59a174283862`;
- Windows line endings (`\r\n`) instead of `\n`;
- characters that look the same but are different code points, such as a composed `é` and `e` plus a combining accent.

## Why Git's SHA-1 Is Different

`git hash-object` does not hash the file content alone. It hashes a header, the word `blob`, a space, the size in bytes and a NUL byte, followed by the content. For a file containing `hello` and a line feed, Git reports `ce013625030ba8dba906f756967f9e9ca394464a`, while the SHA-1 of the same six bytes is `f572d396fae9206628714fb2ce00f72e94f2258f`. This tool computes the second kind of value. Git repositories still use SHA-1 object names by default; SHA-256 repositories are an opt-in format.

## Hashing Files

This page hashes text only. To hash a file without uploading it, use the [File Hash Checker](/tools/file-hash-checker/), or run one of these commands:

```bash
sha256sum archive.tar.gz                            # Linux
shasum -a 256 archive.tar.gz                        # macOS
certutil -hashfile archive.tar.gz SHA256            # Windows cmd
Get-FileHash archive.tar.gz -Algorithm SHA256       # PowerShell
```

## Passwords Need a Slow Hash

MD5, SHA-1, and the SHA-2 family are designed to be fast, which lets an attacker test guesses quickly. Store passwords with Argon2id, scrypt, or bcrypt, as the [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) recommends.

## Limits

- Text only, encoded as UTF-8 before hashing. The same characters in another encoding (for example GBK or Shift_JIS) produce different hashes.
- Empty input is not hashed. For reference, the SHA-256 of an empty string is `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`.
- Output is lowercase hexadecimal only. There is no Base64 output, which some systems expect (for example the `sha256-…` values in Subresource Integrity).
- No secret key. A hash of a message plus a password is not a message authentication code; use the [HMAC Generator](/tools/hmac-generator/) for signed webhooks and API requests.
- SHA-3, BLAKE2 and CRC32 are not offered here. The [File Hash Checker](/tools/file-hash-checker/) adds CRC32 for files.
