<h2>해시 알고리즘 고르기</h2>
<p>해시는 길이와 상관없이 데이터를 고정 길이 값으로 바꾸는 단방향 함수이며, 값에서 원래 데이터를 되살릴 수 없습니다. 이 도구는 아래 다섯 가지를 한 번에 계산합니다.</p>
<ul>
  <li><strong>MD5</strong>(128비트): 오래된 체크섬과 맞춰 볼 때만 씁니다. 보안 용도에는 쓰지 않습니다.</li>
  <li><strong>SHA-1</strong>(160비트): 충돌을 만들 수 있어 보안 용도에 맞지 않습니다. Git은 지금도 객체 이름에 SHA-1을 씁니다.</li>
  <li><strong>SHA-256</strong>(256비트): 위변조 검증, 서명 등 일반적인 용도의 기본값입니다.</li>
  <li><strong>SHA-384</strong>(384비트): SHA-512와 같은 절차에 초기값만 바꾸고 출력을 384비트로 자른 것입니다.</li>
  <li><strong>SHA-512</strong>(512비트): 출력이 길고 보안 여유가 큽니다. SHA-256보다 빠른지는 CPU에 따라 다릅니다.</li>
</ul>

## 결과 확인하기

{/* hash-check: {"in":"hello","algos":["md5","sha1","sha256"]} */}

`hello` 다섯 글자를 해시하면 다음과 같습니다.

| 알고리즘 | 결과 |
|---|---|
| MD5 | `5d41402abc4b2a76b9719d911017c592` |
| SHA-1 | `aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d` |
| SHA-256 | `2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824` |

{/* hash-check: {"in":"hello\n","algos":["sha256"]} */}

터미널 결과가 다르면 보이지 않는 줄바꿈을 의심하세요. `echo "hello" | sha256sum`은 `hello`에 줄바꿈 하나를 붙여 해시하므로 `5891b5b522d5df086d0ff0b110fbd9d21bb4fc7163af34d08286a2e846f6be03`을 출력하고, `printf 'hello' | sha256sum`은 표와 같습니다.

## 한글은 NFC와 NFD에 따라 값이 다릅니다

화면에는 똑같이 「한글」로 보여도, 완성형 음절 두 개(NFC)로 저장될 수도 있고 초성·중성·종성 자모 여섯 개(NFD)로 저장될 수도 있습니다. Apple의 기술 문서 [QA1173](https://developer.apple.com/library/archive/qa/qa1173/_index.html)에 따르면 macOS의 HFS Plus(Mac OS 확장) 볼륨은 파일 이름을 분해된 형태로 저장합니다. Mac에서 복사한 파일 이름을 해시로 맞춰 볼 때 자주 생기는 차이입니다.

{/* hash-check: {"in":"한글","algos":["sha256"],"bytes":true} */}

NFC 「한글」은 `ed 95 9c ea b8 80`의 6바이트이고, SHA-256은 `bd87f9bb68b67d2fa1cb82b6751820e946d5b1316d25d5fd96512fb4be44a2a8`입니다.

{/* hash-check: {"in":"\u1112\u1161\u11ab\u1100\u1173\u11af","algos":["sha256"],"bytes":true} */}

NFD 「한글」은 자모 여섯 개, `e1 84 92 e1 85 a1 e1 86 ab e1 84 80 e1 85 b3 e1 86 af`의 18바이트가 되어 SHA-256이 `cf0273800fe12c2b4d3fd3c95d0bc94b6c64718221fb6d6e785153070f8decd9`로 바뀝니다. 이 도구는 입력을 정규화하지 않으므로, 양쪽 시스템에서 먼저 같은 형태(보통 NFC)로 맞춘 뒤 비교하세요.

## EUC-KR로 저장된 텍스트

{/* hash-check: {"hex":"c7d1b1db","enc":"euc-kr","text":"한글","algos":["md5"],"bytes":true} */}

같은 「한글」을 EUC-KR로 저장한 파일이나 오래된 시스템에서는 바이트가 `c7 d1 b1 db`의 4바이트가 되고 MD5는 `fd2a2a55c7fc6b96d3aad609c7d84118`입니다. 이 도구는 EUC-KR로 계산할 수 없습니다. 값이 맞지 않을 때는 알고리즘을 의심하기 전에 양쪽이 해시에 넣은 바이트를 출력해 비교하세요.

## 파일 해시

이 페이지는 텍스트만 해시합니다. 파일을 업로드하지 않고 해시를 구하려면 [파일 해시값 확인 도구](/ko/tools/file-hash-checker/)를 쓰거나 다음 명령을 실행하세요.

```bash
sha256sum archive.tar.gz                            # Linux
shasum -a 256 archive.tar.gz                        # macOS
certutil -hashfile archive.tar.gz SHA256            # Windows cmd
Get-FileHash archive.tar.gz -Algorithm SHA256       # PowerShell
```

## 비밀번호에는 느린 해시를

MD5, SHA-1, SHA-2 계열은 빠르게 계산되도록 설계되어 공격자가 추측을 빠르게 시도할 수 있습니다. 비밀번호는 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)가 권장하는 Argon2id, scrypt, bcrypt로 저장하세요.

## 제한 사항

- 텍스트만 지원하며, 해시 전에 UTF-8로 인코딩합니다. 같은 글자라도 EUC-KR 같은 다른 인코딩이면 해시 값이 다릅니다.
- 입력을 정규화하지 않습니다. NFC와 NFD 한글은 서로 다른 값이 나옵니다.
- 입력이 비어 있으면 계산하지 않습니다. 참고로 빈 문자열의 SHA-256은 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`입니다.
- 출력은 소문자 16진수뿐이며 Base64는 지원하지 않습니다.
- 비밀 키를 쓰지 않습니다. 메시지와 비밀번호를 이어 붙여 해시해도 메시지 인증 코드가 되지 않으므로, 키가 있는 서명에는 [HMAC 생성기 · 웹훅 서명 검증](/ko/tools/hmac-generator/)을 쓰세요.
- SHA-3, BLAKE2, CRC32는 지원하지 않습니다.
- 짝이 없는 서로게이트(이모지의 반쪽)는 인코딩할 때 U+FFFD로 바꾼 뒤 계산합니다.
- 입력을 수정해도 자동으로 다시 계산하지 않으니 해시 생성을 다시 누르세요.
