<h2>アルゴリズムの選び方</h2>
<p>ハッシュは任意の長さのデータから固定長の値を作る一方向の関数で、値から元のデータには戻せません。このツールは次の 5 種類を同時に出力します。</p>
<ul>
  <li><strong>MD5</strong>（128ビット）：古いチェックサムとの照合用。セキュリティ目的には使いません。</li>
  <li><strong>SHA-1</strong>（160ビット）：衝突を作れるため安全用途には不向き。Git は今もオブジェクト名に SHA-1 を使います。</li>
  <li><strong>SHA-256</strong>（256ビット）：改ざん検知や署名など、一般的な用途の標準。</li>
  <li><strong>SHA-384</strong>（384ビット）：SHA-512 と同じ計算で出力を短くしたもの。</li>
  <li><strong>SHA-512</strong>（512ビット）：出力が長く安全余裕が大きい。SHA-256 より速いかどうかは CPU 次第です。</li>
</ul>

## 結果を確かめる

{/* hash-check: {"in":"hello","algos":["md5","sha1","sha256"]} */}

`hello` の 5 文字をハッシュ化すると次のとおりです。

| アルゴリズム | 出力 |
|---|---|
| MD5 | `5d41402abc4b2a76b9719d911017c592` |
| SHA-1 | `aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d` |
| SHA-256 | `2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824` |

{/* hash-check: {"in":"hello\n","algos":["sha256"]} */}

ターミナルの結果と違う場合は、見えない改行を疑ってください。`echo "hello" | sha256sum` は `hello` に改行を足したものをハッシュ化し、`5891b5b522d5df086d0ff0b110fbd9d21bb4fc7163af34d08286a2e846f6be03` を出力します。`printf 'hello' | sha256sum` なら表と一致します。

## 日本語は UTF-8 で計算します

{/* hash-check: {"in":"こんにちは","algos":["md5","sha256"],"bytes":true} */}

`こんにちは` は UTF-8 では 1 文字 3 バイト、合計 15 バイト（`e3 81 93 e3 82 93 e3 81 ab e3 81 a1 e3 81 af`）です。このツールの結果は MD5 `c0e89a293bd36c7a768e4e9d2c5475a8`、SHA-256 `125aeadf27b0459b8760c13a3d80912dfa8a81a68261906f60d87f4a0268646c` になります。

{/* hash-check: {"hex":"82b182f182c982bf82cd","enc":"shift_jis","text":"こんにちは","algos":["md5"],"bytes":true} */}

同じ 5 文字を Shift_JIS で保存したファイルや、Shift_JIS 前提の古いシステムでは、バイト列が 1 文字 2 バイトの `82 b1 82 f1 82 c9 82 bf 82 cd` になり、MD5 は `2316c3ccdb7049dc4b38bb8453e3f538` です。このツールは Shift_JIS では計算できません。社内システムと値が合わないときは、まず相手がどの文字コードでバイト列を作っているかを確認してください。

## 全角スペースが 1 つ入っただけで別の値

IME がオンのままスペースキーを押すと、全角スペース（U+3000）が入ります。画面では見分けにくいのに、ハッシュはまったく変わります。

{/* hash-check: {"in":"東京都","algos":["sha256"],"bytes":true} */}

`東京都` は `e6 9d b1 e4 ba ac e9 83 bd` の 9 バイトで、SHA-256 は `ce76fe655d41af062f0ef4f53a509f84df667596a54921a88ac27c11a1a02db7` です。

{/* hash-check: {"in":"東京都　","algos":["sha256"],"bytes":true} */}

末尾に全角スペースが付いた `東京都　` は `e6 9d b1 e4 ba ac e9 83 bd e3 80 80` の 12 バイトになり、SHA-256 は `b2725f8020074e38f58a24e04994e7ee2f25daf1b4754231e34f0e0e9112e741` です。このツールは前後の空白を削らないので、住所や氏名をハッシュで照合するときは、両方のシステムで空白の扱い（削るか、半角にそろえるか）を決めてから比べてください。

## ファイルのハッシュ

このページはテキスト専用です。ファイルをアップロードせずにハッシュを計算するには [ファイルハッシュ値確認ツール](/ja/tools/file-hash-checker/) を使うか、次のコマンドを実行してください。

```bash
sha256sum archive.tar.gz                            # Linux
shasum -a 256 archive.tar.gz                        # macOS
certutil -hashfile archive.tar.gz SHA256            # Windows cmd
Get-FileHash archive.tar.gz -Algorithm SHA256       # PowerShell
```

## パスワードには遅いハッシュを

MD5、SHA-1、SHA-2 系は高速に計算できるよう設計されているため、攻撃者は推測を素早く試せます。パスワードの保存には [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) が推奨する Argon2id、scrypt、bcrypt を使ってください。

## 制限事項

- テキストのみ対応し、UTF-8 に変換してからハッシュ化します。同じ文字でも Shift_JIS など別の文字コードではハッシュ値が変わります。
- 入力が空のときは計算しません。参考までに、空文字列の SHA-256 は `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` です。
- 出力は小文字の 16 進数のみで、Base64 は出せません。
- 秘密鍵は使いません。メッセージとパスワードをつなげてハッシュ化しても認証コードにはならないので、鍵付きの署名には [HMAC 計算・署名検証ツール](/ja/tools/hmac-generator/) を使ってください。
- SHA-3、BLAKE2、CRC32 には対応していません。
- 対になっていないサロゲート（絵文字の片割れ）は、エンコード時に U+FFFD に置き換えてから計算します。
- 入力を編集しても自動では再計算しません。もう一度「ハッシュを生成」を押してください。
