<h2>Unixタイムスタンプについて</h2>
<p>Unixタイムスタンプはプログラミング・データベース・APIで時刻を扱う標準的な方法です。タイムゾーンを気にせず絶対時刻を表現でき、日時の計算や比較が簡単です。</p>
<p>ログ解析、APIレスポンスのデバッグ、データベースのタイムスタンプ確認などに便利です。</p>

## 変換例

単位が「単位を自動判定」のとき、小数点より前の桁数で判定します。12 桁以下は秒、13〜15 桁はミリ秒、16〜18 桁はマイクロ秒、19 桁以上はナノ秒です。現在時刻ならそれぞれ 10・13・16・19 桁です。どの単位で読んだかはステータス欄に表示され、違う場合は一覧から単位を選べます。

{/* tsc-check: {"in": ["1700000000", "1700000000123", "2147483647", "1700000000123456", "1700000000123456789"]} */}

| 入力 | 判定 | ISO 8601（UTC） |
|---|---|---|
| `1700000000` | 秒 | `2023-11-14T22:13:20.000Z` |
| `1700000000123` | ミリ秒 | `2023-11-14T22:13:20.123Z` |
| `2147483647` | 秒 | `2038-01-19T03:14:07.000Z` |
| `1700000000123456` | マイクロ秒 | `2023-11-14T22:13:20.123Z` |
| `1700000000123456789` | ナノ秒 | `2023-11-14T22:13:20.123Z` |

`2147483647` は符号付き 32 ビット整数の最大値で、2038 年問題はこの時点で起きます。最後の 2 行はマイクロ秒（Python `time.time_ns() // 1000` など）とナノ秒（Go `time.Now().UnixNano()`、`date +%s%N`）のタイムスタンプです。JavaScript の日付はミリ秒単位なので、ミリ秒未満の桁は切り捨てます。ナノ秒の値は 2<sup>53</sup> を超えるため、大きな整数として読み、精度を落としません。

## LINE の Webhook と日本時間

以下は PC のタイムゾーンが日本（Asia/Tokyo）のときの結果で、ローカルの行がそのまま日本時間になります。

{/* tsc-check: {"in": "1692251666727", "tz": "Asia/Tokyo", "show": ["iso", "local"], "label": true, "status": true} */}

LINE Messaging API の Webhook イベントにある `timestamp` は、[Messaging API リファレンス](https://developers.line.biz/ja/reference/messaging-api/nojs)によると、イベントの発生時刻を UNIX 時間（ミリ秒）で表した値です。再送された Webhook でも、再送の時刻ではなく発生時刻が入ります。[メッセージ（Webhook）を受信する](https://developers.line.biz/ja/docs/messaging-api/receiving-messages/)の例にある `1692251666727` を貼り付けると、13 桁なのでステータス欄に「ミリ秒として読み取りました（13 桁）。違う場合は単位を選んでください。」と出て、ISO 8601 は `2023-08-17T05:54:26.727Z`、「Local (UTC+09:00)」の行は `2023-08-17 14:54:26` になります。再送で到着の順番が入れ替わったときは、この値で前後関係を確かめられます。

{/* tsc-check: {"in": "１６９２２５１６６６７２７", "tz": "Asia/Tokyo", "show": ["iso"], "status": true} */}

全角で書かれた `１６９２２５１６６６７２７` も半角として読み、同じ「ミリ秒として読み取りました（13 桁）。違う場合は単位を選んでください。」の表示と `2023-08-17T05:54:26.727Z` になります。入力欄の文字は書き換えません。

### 1948〜1951 年の夏時刻

{/* tsc-check: {"in": "-647049600", "tz": "Asia/Tokyo", "show": ["iso", "local"], "label": true} */}

[夏時刻法](https://www.shugiin.go.jp/internet/itdb_housei.nsf/html/houritsu/00219480428029.htm)（昭和23年法律第29号）は、夏の期間に「中央標準時より一時間進めた時刻（夏時刻）」を用いると定めていました。ブラウザのタイムゾーンデータ（[IANA tz](https://github.com/eggert/tz/blob/main/asia) の Rule Japan）にもこの期間が入っているため、`-647049600`（`1949-07-01T00:00:00.000Z`）は、PC が日本時間なら「Local (UTC+10:00)」の行で `1949-07-01 10:00:00` と表示されます。古い記録を照合するときは、ISO 8601 の行を基準にしてください。

## コードで変換する

```bash
date +%s                      # current timestamp (Linux, macOS)
date -u -d @1700000000        # GNU date (Linux)
date -u -r 1700000000         # BSD date (macOS)
```

```javascript
Math.floor(Date.now() / 1000)          // current timestamp in seconds
new Date(1700000000 * 1000).toISOString()  // "2023-11-14T22:13:20.000Z"
```

```python
import time, datetime
int(time.time())                                                  # current timestamp
datetime.datetime.fromtimestamp(1700000000, datetime.timezone.utc)  # 2023-11-14 22:13:20+00:00
```

## 制限事項

{/* tsc-check: {"cases": [{"in": "1e10", "error": true}, {"in": "8640000000000000", "unit": "ms"}, {"in": "8640000000000001", "unit": "ms", "error": true}]} */}

- **自動判定は桁数だけで行います。** 2001-09-09 より前のミリ秒値は 12 桁なので秒として、13 桁以上の秒値（西暦 33658 年以降）はミリ秒として読みます。この場合は単位を選んでください。
- **数字だけを受け付けます。** 指数（`1e10`）、16 進数、桁区切りはエラーになり、ステータス欄に `無効なタイムスタンプです。数字を入力してください（符号と小数点を使えます）。日付は「日付 → タイムスタンプ」で選びます。` と表示します。小数部は入力でき、全角の数字は半角として読みます。
- **「日付 → タイムスタンプ」はローカルのタイムゾーンを使います。** 日付ピッカーの値はブラウザのタイムゾーンで解釈されるため、同じ値でもタイムゾーン設定の違う PC では別のタイムスタンプになります。
- **うるう秒は数えません。** Unix 時間はうるう秒を無視し、JavaScript の `Date` も同じです。
- **範囲があります。** JavaScript の日付で表せるのはエポックの前後 ±8,640,000,000,000,000 ミリ秒です。単位をミリ秒にすると `8640000000000000` は `+275760-09-13T00:00:00.000Z` になり、1 ミリ秒増やすと「タイムスタンプが範囲外です。」と表示します。
