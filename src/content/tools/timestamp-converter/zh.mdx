<h2>关于 Unix 时间戳</h2>
<p>
  Unix 纪元始于 1970-01-01 00:00:00 UTC。每一个时刻都以相对于该起点的整数偏移量来存储。
  大多数系统使用秒；JavaScript 使用毫秒。
</p>
<p>
  32 位有符号时间戳将在 2038 年 1 月 19 日溢出（即 <em>2038 年问题</em>）。
  现代 64 位系统不受影响。
</p>

## 示例

单位选「自动判断单位」时，工具数小数点前的位数：12 位以内按秒，13–15 位按毫秒，16–18 位按微秒，19 位及以上按纳秒。当前时刻的时间戳分别是 10、13、16、19 位。状态栏会写明按哪种单位读取，判断不对时可在列表里选择单位。

{/* tsc-check: {"in": ["1700000000", "1700000000123", "2147483647", "1700000000123456", "1700000000123456789"]} */}

| 输入 | 识别为 | ISO 8601（UTC） |
|---|---|---|
| `1700000000` | 秒 | `2023-11-14T22:13:20.000Z` |
| `1700000000123` | 毫秒 | `2023-11-14T22:13:20.123Z` |
| `2147483647` | 秒 | `2038-01-19T03:14:07.000Z` |
| `1700000000123456` | 微秒 | `2023-11-14T22:13:20.123Z` |
| `1700000000123456789` | 纳秒 | `2023-11-14T22:13:20.123Z` |

`2147483647` 是有符号 32 位整数的最大值，2038 年问题就从这一刻开始。最后两行是微秒时间戳（如 Python `time.time_ns() // 1000`）和纳秒时间戳（如 Go `time.Now().UnixNano()`、`date +%s%N`）。JavaScript 的日期只精确到毫秒，毫秒以下的位数会被舍去；纳秒值超过 2<sup>53</sup>，工具按大整数读取，不丢精度。

## 钉钉、飞书接口里的时间戳

飞书和钉钉机器人的签名都要带 timestamp，但单位不同。下面的结果按电脑时区为中国（Asia/Shanghai）时算出，「本地」一行就是北京时间。

{/* tsc-check: {"in": "1599360473", "tz": "Asia/Shanghai", "show": ["iso", "local"], "label": true, "status": true} */}

**飞书：10 位，单位是秒。** 飞书《[自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)》要求签名校验用的 timestamp 与当前时间相差不超过 1 小时，单位是秒，文档举的例子是 `1599360473`。把它粘贴进来，状态行写「按秒读取（10 位）。如有误，请选择单位。」，ISO 8601 一行是 `2020-09-06T02:47:53.000Z`，「Local (UTC+08:00)」一行是 `2020-09-06 10:47:53`。

{/* tsc-check: {"in": "1577262236757", "tz": "Asia/Shanghai", "show": ["iso", "local"], "status": true} */}

**钉钉：13 位，单位是毫秒。** 钉钉《[企业内部机器人群聊校验合法请求](https://open.dingtalk.com/document/robots/verify-valid-requests-for-intra-enterprise-robot-group-chat)》写明，请求头里的 timestamp 是毫秒，与系统当前时间相差 1 小时以上即视为非法请求，示例值是 `1577262236757`。工具按毫秒读取，状态行写「按毫秒读取（13 位）。如有误，请选择单位。」，结果是 `2019-12-25T08:23:56.757Z`，北京时间 `2019-12-25 16:23:56`。签名校验失败时，可以先把收到的时间戳贴进来，看看它离现在有多远。

{/* tsc-check: {"in": "１５９９３６０４７３", "tz": "Asia/Shanghai", "show": ["iso"]} */}

全角的 `１５９９３６０４７３` 也按半角读取，结果同样是 `2020-09-06T02:47:53.000Z`，输入框里的文字保持原样。

### 1986–1991 年的夏令时

{/* tsc-check: {"in": "583718400", "tz": "Asia/Shanghai", "show": ["iso", "local"], "label": true} */}

浏览器的时区数据来自 [IANA 时区库](https://github.com/eggert/tz/blob/main/asia)，其中 Asia/Shanghai 的 PRC 规则收录了这几年的夏令时。电脑时区为中国时，`583718400` 的 ISO 8601 一行是 `1988-07-01T00:00:00.000Z`，「Local (UTC+09:00)」一行是 `1988-07-01 09:00:00`，比平时多 1 小时。核对这几年的老数据时，以 ISO 8601 一行为准。

## 用代码转换

```bash
date +%s                      # current timestamp (Linux, macOS)
date -u -d @1700000000        # GNU date (Linux)
date -u -r 1700000000         # BSD date (macOS)
```

```javascript
Math.floor(Date.now() / 1000)          // current timestamp in seconds
new Date(1700000000 * 1000).toISOString()  // "2023-11-14T22:13:20.000Z"
```

```python
import time, datetime
int(time.time())                                                  # current timestamp
datetime.datetime.fromtimestamp(1700000000, datetime.timezone.utc)  # 2023-11-14 22:13:20+00:00
```

## 限制

{/* tsc-check: {"cases": [{"in": "1e10", "error": true}, {"in": "8640000000000000", "unit": "ms"}, {"in": "8640000000000001", "unit": "ms", "error": true}]} */}

- **自动判断只看位数。** 2001-09-09 之前的毫秒值只有 12 位，会按秒读取；13 位及以上的秒值（公元 33658 年之后）会按毫秒读取。这两种情况请手动选择单位。
- **只接受数字。** 指数（`1e10`）、十六进制和千位分隔符会报错，状态行显示 `无效的时间戳。请输入数字，可带正负号和小数点；日期请在「日期 → 时间戳」中选择。` 小数部分可以输入，全角数字按半角读取。
- **「日期 → 时间戳」使用本地时区。** 日期选择器里的时间按浏览器所在时区解读，同一个选择值在不同时区的电脑上会得到不同的时间戳。
- **不计闰秒。** Unix 时间不计闰秒，JavaScript 的 `Date` 也一样。
- **范围。** JavaScript 日期只能表示纪元前后 ±8,640,000,000,000,000 毫秒。单位选毫秒时，`8640000000000000` 得到 `+275760-09-13T00:00:00.000Z`，再加 1 毫秒显示「时间戳超出范围。」
