## 出力されるコード

出力はそのまま `.ts` ファイルに貼れるコードです。1 行目が `import { z } from "zod";`、続いて `const 名前Schema = …;`、最後に `export type 名前 = z.infer<typeof 名前Schema>;` が並びます。スキーマ定数には `export` が付かないので、ほかのモジュールから使う場合は自分で付けます。名前は「ルートスキーマ名」から作られ、空欄なら `Root` です。ルートスキーマ名は先頭を大文字にし、ECMAScript の識別子のルールで整えます。日本語を含む各言語の文字、数字、`$`、`_` は残るので、`天気` は `天気Schema` になります。それ以外の文字は取り除かれて次の文字が大文字になり（`user profile` は `UserProfileSchema`）、識別子の先頭に使えない名前には `T` が付きます（`2fa` は `T2faSchema`）。何も残らない場合は `Root` です。

## 例：気象庁の天気概況 JSON

気象庁サイトの天気予報ページが読み込んでいる天気概況の JSON（`https://www.jma.go.jp/bosai/forecast/data/overview_forecast/130000.json`、東京都）を 2026 年 10 月 8 日に取得し、そのまま貼りました。ルート名は `Overview` です。

{/* jtz-check: {"root":"Overview"} */}

```json
{"publishingOffice":"気象庁","reportDatetime":"2026-10-08T16:35:00+09:00","targetArea":"東京都","headlineText":"","text":"　日本海の高気圧が本州付近に張り出しています。\n\n　東京地方は、晴れています。\n\n　８日は、高気圧に覆われる見込みです。このため、晴れるでしょう。\n\n　９日は、引き続き高気圧に覆われる見込みです。このため、晴れるでしょう。"}
```

出力：

```ts
import { z } from "zod";

const OverviewSchema = z.object({
  publishingOffice: z.string(),
  reportDatetime: z.string(),
  targetArea: z.string(),
  headlineText: z.string(),
  text: z.string(),
});

export type Overview = z.infer<typeof OverviewSchema>;
```

すべて `z.string()` になります。空文字列の `headlineText` も、全角スペースや改行を含む `text` も、ツールから見れば同じ文字列です。日時の `reportDatetime` を厳密にチェックしたいときは、Zod 4 なら `z.iso.datetime({ offset: true })`、Zod 3 なら `z.string().datetime({ offset: true })` に書き換えます。`offset: true` を付けないと、`+09:00` 付きの値は不正として拒否されます。

## 例：郵便番号検索 API の成功時とエラー時

[zipcloud の郵便番号検索 API](https://zipcloud.ibsnet.co.jp/doc/api) は、成功すると `results` に住所の配列を返し、エラーのときは `message` に文字列、`results` に `null` を入れて返します（ドキュメントの「エラー発生時のサンプル」）。成功時だけから作ったスキーマはエラー時のレスポンスを拒否するので、2 つのサンプル（成功時は 1 件に省略）を配列に入れて貼ります。ルート名は `ZipcloudResponse` です。

{/* jtz-check: {"root":"ZipcloudResponse"} */}

```json
[{"message":null,"results":[{"address1":"北海道","address2":"美唄市","address3":"上美唄町協和","kana1":"ﾎｯｶｲﾄﾞｳ","kana2":"ﾋﾞﾊﾞｲｼ","kana3":"ｶﾐﾋﾞﾊﾞｲﾁｮｳｷｮｳﾜ","prefcode":"1","zipcode":"0790177"}],"status":200},{"message":"必須パラメータが指定されていません。","results":null,"status":400}]
```

出力：

```ts
import { z } from "zod";

const ZipcloudResponseSchema = z.array(z.object({
    message: z.union([z.null(), z.string()]),
    results: z.union([z.array(z.object({
        address1: z.string(),
        address2: z.string(),
        address3: z.string(),
        kana1: z.string(),
        kana2: z.string(),
        kana3: z.string(),
        prefcode: z.string(),
        zipcode: z.string(),
      })), z.null()]),
    status: z.number().int(),
  }));

export type ZipcloudResponse = z.infer<typeof ZipcloudResponseSchema>;
```

`message` と `results` が `null` を含む union になり、両方のレスポンスが通ります。ルートが配列なので、出力全体は `z.array(…)` です。API のレスポンス 1 件を検証するには、`z.array(` と最後の `)` を外して中の `z.object(…)` だけを使います。`zipcode` は先頭の 0 を保つために文字列のままにしておきます。

## 使う前に直すところ

| 生成結果 | 問題 | 修正（Zod 4） |
|---|---|---|
| `email: z.string()` | どんな文字列も通る | `z.email()`（Zod 3 は `z.string().email()`） |
| `qty: z.number().int()` | 常に整数のときだけ正しい。`10.5` は `Invalid input: expected int, received number` で失敗する | 価格は `z.number()` にし、`.min(0)` を足す |
| `message: z.union([z.null(), z.string()])` | 意味は合っているが読みにくい | `z.string().nullable()` |
| `status: z.number().int()` | どんな整数も通る | `z.union([z.literal(200), z.literal(400), z.literal(500)])` |
| サンプルにあったフィールド | API が省略することがあっても必須になる | `.optional()` を付ける |

失敗したら処理を止めたい場所（起動時の設定読み込みなど）では `.parse()` を使います。`ZodError` を投げます。API レスポンスやユーザー入力には `.safeParse()` を使います。`{ success: false, error }` を返すので、エラーを自分で処理できます。

## 制限事項

- **型は貼ったサンプルだけから決まります。** 空の配列は `z.array(z.unknown())`、空のオブジェクトは `z.record(z.string(), z.unknown())` になります。
- **`null` は `z.null()` になります。** `.nullable()` は付きません。
- **型が混ざった配列は union になります。** `[{"a": 1}, 2]` のような配列は `z.array(z.union([z.number().int(), z.object({ a: z.number().int() })]))` になります。同じ配列のオブジェクトは 1 つの `z.object` にまとまります。
- **整数と小数が同じキーにあると union になります。** `z.union([z.number(), z.number().int()])` は `z.number()` にまとめられます。
- **大きな整数。** 入力は `JSON.parse` で読むので、9007199254740991 を超える整数はスキーマを作る前に桁が変わります。
- **文字列の形式や範囲は付きません。** メール、URL、日付、UUID はすべて `z.string()` です。
- **ネストが非常に深い JSON。** ブラウザのコールスタックを超えることがあり、その場合はステータスにエラーを表示し、前のスキーマを消去してコピーを無効にします。
- {/* jtz-error: {"input":"{\"天気\":　\"晴れ\"}"} */}**入力は有効な JSON である必要があります。** 無効なときは出力が消えてコピーが無効になり、ステータスにエラーの行と列、考えられる原因が表示されます。行と列は入力したままのテキストで数えます。IME で入力した全角スペースが値の前に入った `{"天気":　"晴れ"}` は `無効なJSON：1 行 7 列目、全角文字 　 があります。JSON の記号と空白は半角です。` になります。全角の `：` や `“”` も同じように位置が示されます。
