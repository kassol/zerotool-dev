## 예시: 카카오 로컬 API 응답 두 개의 meta

[카카오 로컬 API 개발 가이드](https://developers.kakao.com/docs/latest/ko/local/dev-guide)의 응답 예제를 보면, ‘키워드로 장소 검색’의 `meta.same_name`은 객체이고 ‘카테고리로 장소 검색’에서는 `null`입니다. 키워드 검색 응답 하나로 만든 스키마는 카테고리 검색 응답을 거부합니다. 두 예제의 `meta`를 배열에 넣어 붙여 넣고 루트 이름을 `Meta`로 지정하면:

{/* jtz-check: {"root":"Meta"} */}

```json
[
  {"same_name": {"region": [], "keyword": "카카오프렌즈", "selected_region": ""}, "pageable_count": 14, "total_count": 14, "is_end": true},
  {"same_name": null, "pageable_count": 11, "total_count": 11, "is_end": true}
]
```

출력:

```ts
import { z } from "zod";

const MetaSchema = z.array(z.object({
    same_name: z.union([z.object({
        region: z.array(z.unknown()),
        keyword: z.string(),
        selected_region: z.string(),
      }), z.null()]),
    pageable_count: z.number().int(),
    total_count: z.number().int(),
    is_end: z.boolean(),
  }));

export type Meta = z.infer<typeof MetaSchema>;
```

`same_name`이 객체와 `z.null()`의 union이 되어 두 응답의 `meta`를 모두 통과시킵니다. 루트가 배열이므로 출력 전체가 `z.array(…)`로 감싸여 있습니다. 응답 하나의 `meta`를 검사하려면 안쪽의 `z.object(…)`만 꺼내 씁니다. 그 밖에 손볼 곳은 두 가지입니다.

- `region`은 예제에서 빈 배열이라 `z.array(z.unknown())`이 되었습니다. 문서의 타입은 String[]이므로 `z.array(z.string())`으로 고칩니다.
- `z.union([z.object(…), z.null()])`은 `z.object(…).nullable()`과 같은 뜻이므로 바꿔 쓰면 읽기 쉽습니다.

## 예시: 한글 키와 엄격 모드

사내 시스템이나 엑셀에서 변환한 회원 데이터처럼 한글 키를 쓰는 JSON도 그대로 처리됩니다. 루트 이름을 `Member`로 하고 ‘엄격 모드(추가 키 불허)’를 켜면:

{/* jtz-check: {"root":"Member","strict":true} */}

```json
{"이름":"홍길동","연락처":{"휴대전화":"010-1234-5678","이메일":"hong@example.com"},"관심분야":["개발","디자인"]}
```

출력:

```ts
import { z } from "zod";

const MemberSchema = z.object({
  "이름": z.string(),
  "연락처": z.object({
    "휴대전화": z.string(),
    "이메일": z.string(),
  }).strict(),
  "관심분야": z.array(z.string()),
}).strict();

export type Member = z.infer<typeof MemberSchema>;
```

한글 키는 따옴표로 감싸 출력되며 JavaScript 객체 키로 유효합니다. 중첩된 `연락처`에도 `.strict()`가 붙으므로 `"집전화"` 같은 키가 더 들어오면 검사에 실패합니다. 휴대전화 번호는 앞자리 0을 지키도록 문자열로 둡니다.

루트 이름은 첫 글자를 대문자로 바꾼 뒤 ECMAScript 식별자 규칙으로 정리합니다. 한글을 포함한 각 언어의 문자, 숫자, `$`, `_`는 남으므로 `회원`은 `회원Schema`가 됩니다. 그 밖의 문자는 지우고 다음 글자를 대문자로 바꾸며(`user profile`은 `UserProfileSchema`), 식별자 첫 글자로 쓸 수 없는 이름은 앞에 `T`를 붙입니다(`2fa`는 `T2faSchema`). 남는 글자가 없으면 `Root`를 씁니다.

## 출력 코드의 구성

출력은 그대로 `.ts` 파일에 붙여 넣을 수 있는 코드입니다. 첫 줄은 `import { z } from "zod";`, 다음은 `const 이름Schema = …;`, 마지막은 `export type 이름 = z.infer<typeof 이름Schema>;`입니다. 스키마 상수에는 `export`가 없으므로 다른 모듈에서 쓰려면 직접 붙이세요.

## 생성된 스키마 다듬기

| 생성 결과 | 문제 | 수정(Zod 4) |
|---|---|---|
| `"이메일": z.string()` | 어떤 문자열이든 통과 | `z.email()`(Zod 3은 `z.string().email()`) |
| `qty: z.number().int()` | 항상 정수일 때만 맞음. `10.5`는 `Invalid input: expected int, received number`로 실패 | 가격은 `z.number()`로 바꾸고 `.min(0)` 추가 |
| `metadata: z.null()` | `null`만 통과 | `z.string().nullable()` |
| 샘플에 있던 필드 | API가 생략할 때가 있어도 필수가 됨 | `.optional()` 추가 |

실패하면 실행을 멈춰야 하는 곳(시작할 때 설정 읽기 등)에는 `.parse()`를 씁니다. `ZodError`를 던집니다. API 응답과 사용자 입력에는 `.safeParse()`를 씁니다. `{ success: false, error }`를 돌려주므로 오류를 직접 처리할 수 있습니다.

## 제한 사항

- **타입은 붙여 넣은 샘플에서만 정해집니다.** 빈 배열은 `z.array(z.unknown())`, 빈 객체는 `z.record(z.string(), z.unknown())`이 됩니다.
- **`null`은 `z.null()`이 됩니다.** `.nullable()`은 붙지 않습니다.
- **타입이 섞인 배열은 union이 됩니다.** `[{"a": 1}, 2]` 같은 배열은 `z.array(z.union([z.number().int(), z.object({ a: z.number().int() })]))`가 됩니다. 같은 배열의 객체는 하나의 `z.object`로 합쳐집니다.
- **정수와 소수가 한 키에 섞이면 union이 됩니다.** `z.union([z.number(), z.number().int()])`는 `z.number()`로 줄일 수 있습니다.
- **큰 정수.** 입력을 `JSON.parse`로 읽으므로 9007199254740991보다 큰 정수는 스키마를 만들기 전에 자릿수가 바뀝니다.
- **문자열 형식과 범위는 붙지 않습니다.** 이메일, URL, 날짜, UUID는 모두 `z.string()`입니다.
- **중첩이 아주 깊은 JSON.** 브라우저의 호출 스택을 넘을 수 있으며, 이때 상태 표시에 오류가 나오고 이전 스키마는 지워지며 복사 버튼은 비활성화됩니다.
- **입력은 유효한 JSON이어야 합니다.** 잘못되면 출력이 지워지고, ‘잘못된 JSON:’ 뒤에 브라우저 파서의 메시지(Chrome에서는 영어)가 표시됩니다.
