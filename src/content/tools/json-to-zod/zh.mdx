## 输出是什么样子

输出是一段可以直接粘进 `.ts` 文件的代码：第一行 `import { z } from "zod";`，中间是 `const 名称Schema = …;`，最后是 `export type 名称 = z.infer<typeof 名称Schema>;`。schema 常量没有 `export`，别的模块要用时自己加上。名称取自「根 Schema 名称」，留空时用 `Root`。

## 示例：中文键名的订单

低代码平台或报表导出的 JSON 常用中文键名。根名称填 `Order`：

{/* jtz-check: {"root":"Order"} */}

```json
{"订单号":"A-1001","收货地址":{"省份":"浙江省","城市":"杭州市"},"商品列表":[{"名称":"龙井茶","数量":2,"单价":128.5},{"名称":"茶具","数量":1,"单价":299,"备注":"礼盒装"}]}
```

输出：

```ts
import { z } from "zod";

const OrderSchema = z.object({
  "订单号": z.string(),
  "收货地址": z.object({
    "省份": z.string(),
    "城市": z.string(),
  }),
  "商品列表": z.array(z.object({
    "名称": z.string(),
    "数量": z.number().int(),
    "单价": z.union([z.number(), z.number().int()]),
    "备注": z.string().optional(),
  })),
});

export type Order = z.infer<typeof OrderSchema>;
```

三处值得注意：

- 中文键名一律加引号，这是合法的 JavaScript 对象键。
- `单价` 在第一件商品是 `128.5`、第二件是 `299`，生成器把两种数字都列进 `z.union`。这个 union 等价于 `z.number()`，直接改成 `z.number()` 更清楚。如果样本里的价格碰巧都是整数，就只会得到 `z.number().int()`，以后遇到 `128.5` 会校验失败，所以价格字段要手动检查。
- `备注` 只在第二件商品里出现，所以加了 `.optional()`。

根名称按 ECMAScript 标识符规则处理，首字母变成大写：中文等各国文字的字母、数字以及 `$`、`_` 都保留，`用户` 得到 `用户Schema`；其他字符被去掉、后一个字母变成大写，`user profile` 得到 `UserProfileSchema`；不能作为开头的加前缀 `T`，`2fa` 得到 `T2faSchema`。什么都不剩时用 `Root`。

## 示例：后端返回的 19 位 ID

很多 Java 后端用 MyBatis-Plus 的 `IdType.ASSIGN_ID` 生成主键。按 [MyBatis-Plus 注解文档](https://baomidou.com/reference/annotation/)，它默认用雪花算法，适用于 Long、Integer、String 类型的主键。主键是 Long 时，接口返回的 JSON 里会是一个很长的数字。根名称填 `UserResult`：

{/* jtz-check: {"root":"UserResult","rejects":{"v4":["data","id"]}} */}

```json
{"code":200,"msg":"操作成功","data":{"id":1830000000000000001,"userName":"张三","remark":null}}
```

输出：

```ts
import { z } from "zod";

const UserResultSchema = z.object({
  code: z.number().int(),
  msg: z.string(),
  data: z.object({
    id: z.number().int(),
    userName: z.string(),
    remark: z.null(),
  }),
});

export type UserResult = z.infer<typeof UserResultSchema>;
```

`1830000000000000001` 大于 `Number.MAX_SAFE_INTEGER`（9007199254740991，见 [MDN](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER)），`JSON.parse` 读出来是 `1830000000000000000`，生成器和你的前端拿到的都是这个已经变了的值。用这份 schema 去校验这份样本，两个版本的结果不同：Zod 3 的 `z.number().int()` 放行，错误的 ID 一路传下去；Zod 4 的 `z.number().int()` 只接受安全范围内的整数，报 `Too big: expected int to be <9007199254740991`。两种结果都说明数字类型装不下这个 ID，应让后端把它输出成字符串，schema 改为 `z.string().regex(/^\d+$/)`。

`remark` 样本里是 `null`，生成 `z.null()`，只接受 `null`。按接口文档改成 `z.string().nullable()`。

## 生成后怎么改

| 生成结果 | 问题 | 改为（Zod 4） |
|---|---|---|
| `email: z.string()` | 任意字符串都能通过 | `z.email()`（Zod 3：`z.string().email()`） |
| `数量: z.number().int()` | 只有一定是整数时才对，`10.5` 会报 `Invalid input: expected int, received number` | 价格类字段用 `z.number()`，再加 `.min(0)` |
| `remark: z.null()` | 只有 `null` 能通过 | `z.string().nullable()` |
| `status: z.string()` | 任意字符串都能通过 | `z.enum(["active", "inactive"])` |
| 样本里出现过的字段 | 一律必填，即使接口有时不返回 | 加 `.optional()` |

失败就应该停止运行的地方（如启动时读配置）用 `.parse()`，它会抛出 `ZodError`；接口响应和用户输入用 `.safeParse()`，它返回 `{ success: false, error }`，由你自己处理错误。

## 限制

- **类型只来自一份样本。** 空数组生成 `z.array(z.unknown())`，空对象生成 `z.record(z.string(), z.unknown())`。
- **`null` 生成 `z.null()`。** 不会自动加 `.nullable()`。在对象数组里，某个键在第一项是 `null`、第二项是字符串时，生成 `z.union([z.null(), z.string()])`。
- **混合数组生成 union。** `[{"a": 1}, 2]` 这样的数组，不论在根上还是在对象内部，都生成 `z.array(z.union([z.number().int(), z.object({ a: z.number().int() })]))`。同一数组里的对象合并成一个 `z.object`，所以 union 里只有一个对象成员。
- **同一个键既有整数又有小数时生成 union。** `z.union([z.number(), z.number().int()])` 可以直接改成 `z.number()`。
- **大整数。** 输入用 `JSON.parse` 读取，大于 9007199254740991 的整数在生成 schema 之前就已经变了。
- **没有字符串格式与范围。** 邮箱、URL、日期、UUID 都是 `z.string()`。
- **嵌套极深时可能超出浏览器的调用栈。** 这时状态栏显示错误，之前的 schema 被清空，「复制」按钮停用。
- **输入必须是合法 JSON。** 无效时输出被清空，状态栏在「JSON 格式错误：」后面显示浏览器自带的解析错误（Chrome 里是英文）。中文输入法带进来的全角引号 `“”` 和全角冒号 `：` 也会报错。
