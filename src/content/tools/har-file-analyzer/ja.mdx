<h2>使い方</h2>
<ol>
  <li>ブラウザ DevTools の Network パネルからセッションを <strong>.har</strong> として書き出します。</li>
  <li>ファイルをドロップゾーンにドラッグ（またはクリックして選択）。解析はブラウザ内で完了します。</li>
  <li><strong>概要</strong>（統計）／<strong>ウォーターフォール</strong>（タイミング）／<strong>詳細</strong>（ヘッダー・Cookie・ボディ）／<strong>フィルタとエクスポート</strong>（切り出しダウンロード）を切り替えます。</li>
  <li>ウォーターフォール任意行のクリックで該当リクエストの詳細にジャンプします。</li>
  <li><strong>リセット</strong>でメモリ上の HAR を消去できます。</li>
</ol>

<h2>ウォーターフォールのフェーズ</h2>
<p>ウォーターフォールは HAR 1.2 <code>timings</code> を 6 セグメントで描画します：</p>
<ul>
  <li><strong>キュー / Stalled</strong> — <code>blocked</code></li>
  <li><strong>DNS 解決</strong> — <code>dns</code></li>
  <li><strong>初期接続</strong> — <code>connect</code>（HAR 1.2 では <code>ssl</code> も含まれる）</li>
  <li><strong>送信</strong> — <code>send</code></li>
  <li><strong>待機 (TTFB)</strong> — <code>wait</code></li>
  <li><strong>受信</strong> — <code>receive</code></li>
</ul>

<h2>プライバシー</h2>
<p>HAR には Authorization / Cookie / レスポンスボディなど機微な情報が含まれます。クラウドアナライザへの送信はリスクが高いです。ZeroTool は <code>FileReader</code> + <code>JSON.parse</code> でブラウザ内処理し、アップロードもリロード越しの永続化も行いません。</p>

<h2>例：cURL でリクエストを再送する</h2>
<p>HTTP/2 で <code>{'{"note":"costs $5"}'}</code> を POST した Chrome の HAR エントリでは、詳細ビューの cURL タブに次が表示されます。</p>

```bash
curl -X "POST" "https://api.example.com/v1/orders" -H ":authority: api.example.com" -H "content-type: application/json" -H "cookie: session=abc123" --data-raw "{\"note\":\"costs $5\"}"
```

<p>実行前にコマンドを確認してください。値はダブルクォートで囲まれているため、POSIX シェルが <code>$5</code> を展開し、サーバーには <code>{'{"note":"costs "}'}</code> が届きます（curl 8.7.1、ローカルサーバーで確認）。ボディに <code>$</code>、バッククォート、<code>{'\\'}</code> が含まれるときは、その前後をシングルクォートに変えてください。<code>:authority</code> などの HTTP/2 疑似ヘッダーは HAR からそのままコピーされます。curl 8.7.1 はこれらを送信しないので害はありませんが、削除しても構いません。</p>

<h2>制限</h2>
<ul>
  <li>50 MB を超えるファイルは「ファイルが大きすぎます」として読み込みません。</li>
  <li><code>log.entries</code> 配列を持つ JSON である必要があります。それ以外の JSON では「この JSON は HAR アーカイブではありません — log.entries がありません。」と表示されます。</li>
  <li>Cookie やトークンは削除しません。HAR が機密データ付きで書き出されている場合、詳細ビュー、書き出した .har のサブセット、「全件を cURL でコピー」にはファイル内のすべてのヘッダー（<code>Cookie</code> や <code>Authorization</code> を含む）が入ります。Chrome の既定の sanitized 書き出しでは、この 3 つのヘッダーは最初から含まれません。</li>
  <li><code>-1</code> のタイミング値は、そのリクエストでその段階が発生しなかったことを示し（再利用した接続には DNS と接続時間がないなど）、N/A と表示されます。</li>
</ul>
