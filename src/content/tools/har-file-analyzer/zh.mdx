<h2>使用方法</h2>
<ol>
  <li>打开浏览器 DevTools，进入 Network 面板，将会话导出为 <strong>.har</strong> 文件。</li>
  <li>将文件拖到拖拽区（或点击选择）。解析过程在你的浏览器内完成。</li>
  <li>在 <strong>概览</strong>（统计）、<strong>瀑布</strong>（时序）、<strong>详情</strong>（Header / Cookie / Body）、<strong>筛选与导出</strong>（裁切下载）之间切换。</li>
  <li>点击任意瀑布行可直接跳到该请求的详情视图。</li>
  <li>点击 <strong>重置</strong> 清除内存中的 HAR 数据。</li>
</ol>

<h2>瀑布阶段</h2>
<p>瀑布按 HAR 1.2 <code>timings</code> 字段分 6 段绘制：</p>
<ul>
  <li><strong>排队 / Stalled</strong> — <code>blocked</code></li>
  <li><strong>DNS 解析</strong> — <code>dns</code></li>
  <li><strong>建立连接</strong> — <code>connect</code>（按 HAR 1.2 已包含 <code>ssl</code>）</li>
  <li><strong>请求发送</strong> — <code>send</code></li>
  <li><strong>等待（TTFB）</strong> — <code>wait</code></li>
  <li><strong>内容下载</strong> — <code>receive</code></li>
</ul>

<h2>隐私</h2>
<p>HAR 文件经常包含 Authorization、Cookie、响应体等敏感信息，上传到云端分析器有风险。ZeroTool 使用 <code>FileReader</code> + <code>JSON.parse</code> 在浏览器中完成解析，不上传、不持久化，刷新即清空。</p>

<h2>示例：用 cURL 重放请求</h2>
<p>对一条通过 HTTP/2 发送 <code>{'{"note":"costs $5"}'}</code> 的 Chrome HAR 记录，「详情」里的 cURL 标签生成：</p>

```bash
curl -X "POST" "https://api.example.com/v1/orders" -H ":authority: api.example.com" -H "content-type: application/json" -H "cookie: session=abc123" --data-raw "{\"note\":\"costs $5\"}"
```

<p>运行前先检查命令。各个值用双引号包裹，POSIX shell 会展开 <code>$5</code>，服务器收到的是 <code>{'{"note":"costs "}'}</code>（curl 8.7.1，对本地服务器实测）。请求体含 <code>$</code>、反引号或 <code>{'\\'}</code> 时，把它两侧的引号改成单引号。<code>:authority</code> 这类 HTTP/2 伪头部是从 HAR 原样复制的；curl 8.7.1 不会发送它们，没有影响，也可以删掉。</p>

<h2>限制</h2>
<ul>
  <li>超过 50 MB 的文件会被拒绝，提示文件过大。</li>
  <li>文件必须是带 <code>log.entries</code> 数组的 JSON，否则提示「该 JSON 不是 HAR 归档 —— 缺少 log.entries。」</li>
  <li>工具不会删除 Cookie 或令牌。如果 HAR 是带敏感数据导出的，「详情」、导出的 .har 子集和「全部复制为 cURL」都会包含文件里的全部请求头，包括 <code>Cookie</code> 和 <code>Authorization</code>。Chrome 默认的 sanitized 导出已不含这三个请求头。</li>
  <li>取值为 <code>-1</code> 的时序字段表示该请求没有这个阶段（例如复用连接时没有 DNS 和连接时间），显示为 N/A。</li>
</ul>
