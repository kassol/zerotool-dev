## How to use

1. Type in the grid. **Enter** moves to the cell below (and adds a row at the end), **Shift+Enter** starts a new line inside the cell.
2. To bring in data, paste cells from Excel, Google Sheets or a web page into any cell, or open **Import data** and paste CSV, TSV, JSON, an HTML table or an existing Markdown table. The format is detected; you can set it by hand.
3. Choose each column's alignment in the row above the headers. *Default* writes `---`, *Left* `:---`, *Center* `:---:`, *Right* `---:`.
4. Use the toolbar on the selected cell: insert or delete rows and columns, move a column, sort by the column, transpose, undo.
5. **Copy Markdown** (or **Download .md**). **Preview** shows how a GFM renderer draws the table.

## Example: a range copied from Excel

A sales sheet with an empty top-left cell, a note that spans two lines in one cell, and an empty last cell. Pasted into the first header cell, with column Q1 set to *Right*:

{/* mdt-check: {"import": {"format": "tsv", "text": "\tQ1\tQ2\nNorth\t1,200\t\"Delayed:\nsupplier\"\nSouth\t980\t"}, "align": ["none", "right", "none"]} */}
```markdown
|       |    Q1 | Q2                   |
| ----- | ----: | -------------------- |
| North | 1,200 | Delayed:<br>supplier |
| South |   980 |                      |
```

The empty first cell keeps its column, so *Q1* stays above *1,200*. The line break inside the cell becomes `<br>`, because a real line break would end the row ([GFM spec, section 4.10](https://github.github.com/gfm/#tables-extension-)).

## Example: text that looks like Markdown

Cells are Markdown by default, so `**bold**`, `` `code` `` and links work. Data from a spreadsheet often contains `*` and `_` that are not meant as formatting. With **Cell text: Markdown** this CSV

```text
pattern,matches
*.md,every Markdown file
_draft_,files named _draft_
a|b,a or b
```

{/* mdt-check: {"import": {"format": "csv", "text": "pattern,matches\n*.md,every Markdown file\n_draft_,files named _draft_\na|b,a or b"}} */}
```markdown
| pattern | matches             |
| ------- | ------------------- |
| *.md    | every Markdown file |
| _draft_ | files named _draft_ |
| a\|b    | a or b              |
```

renders *draft* in italics, and the note under the output says how many cells change when rendered. **Cell text: Plain text** escapes them:

{/* mdt-check: {"import": {"format": "csv", "text": "pattern,matches\n*.md,every Markdown file\n_draft_,files named _draft_\na|b,a or b"}, "opts": {"plain": true}} */}
```markdown
| pattern   | matches               |
| --------- | --------------------- |
| \*.md     | every Markdown file   |
| \_draft\_ | files named \_draft\_ |
| a\|b      | a or b                |
```

Underscores inside a word (`snake_case`) are left alone, since they cannot start emphasis. `&copy;` gets a backslash only when it would turn into ©.

## Example: tidying an existing table

**Import data → Markdown table** reads a table the way GitHub does and writes it back aligned. Code spans keep their escaped pipe:

```markdown
|Option|Default|Notes|
|-|:-:|-|
|`--depth`|1|Use `--depth 0` for \| full history|
|`--quiet`|off|
```

{/* mdt-check: {"import": {"format": "markdown", "text": "|Option|Default|Notes|\n|-|:-:|-|\n|`--depth`|1|Use `--depth 0` for \\| full history|\n|`--quiet`|off|"}} */}
```markdown
| Option    | Default | Notes                               |
| --------- | :-----: | ----------------------------------- |
| `--depth` |    1    | Use `--depth 0` for \| full history |
| `--quiet` |   off   |                                     |
```

The short last row gets an empty cell. A row with more cells than the header is kept as extra columns and reported, because GitHub would hide those cells.

## Escaping and line breaks, checked on real renderers

The test script for this tool ([source](https://github.com/kassol/zerotool-dev/blob/master/scripts/test-markdown-table-generator.mjs)) renders the output with micromark and compares it with HTML recorded on 2026-10-02 from the GitHub and Gitee Markdown APIs, Zenn's renderer (zenn-markdown-html 0.5.4) and Qiita's (qiita_marker 0.23.9.0):

```text
In a cell            GitHub, Gitee, Qiita, Zenn     micromark (remark, MDX, Astro)
a\|b                 a|b                            a|b
`a\|b`               code a|b                       code a|b
`a|b`                cell ends after `a             cell ends after `a
x\\|y                one cell: x|y                  two cells: x\ and y
line 1<br>line 2     line break                     line break when HTML is allowed
**注意：**ここ       not bold                       not bold
```

The tool never writes `\\|`: a backslash followed by a pipe becomes `\\\|`, which all five read as `\|`. The last row is a CommonMark rule, not a table rule: `**` next to full-width punctuation such as `：` does not open emphasis, so in CJK text put the bold markers around whole words or add a space.

## Columns that line up with CJK text

**Aligned columns** pads every cell to the widest cell in its column, measured in display columns: Chinese, Japanese and Korean characters and emoji count as 2, combining marks as 0 ([Unicode UAX #11](https://www.unicode.org/reports/tr11/), data from EastAsianWidth 18.0.0). The width rules are the same as string-width 8.1.0, which markdownlint uses for [rule MD060](https://github.com/DavidAnson/markdownlint/blob/main/doc/md060.md); the tests run MD055, MD056, MD058 and MD060 on 200 random tables in both layouts.

{/* mdt-check: {"table": {"headers": ["Office", "Name", "Staff"], "rows": [["Head office", "本社", "120"], ["Busan", "부산 지점", "8"]], "align": ["none", "none", "right"]}} */}
```markdown
| Office      | Name      | Staff |
| ----------- | --------- | ----: |
| Head office | 本社      |   120 |
| Busan       | 부산 지점 |     8 |
```

Characters such as ○, ×, ① and → are *ambiguous* in UAX #11: one column in Western fonts, two in most Chinese, Japanese and Korean fonts. Turn on the ambiguous-width option if your editor shows them wide.

## How it compares

Tested on 2026-10-02 with the same Excel-style data (empty top-left cell, a two-line cell, `a|b`, `5*3*2`, `東京`):

- **tablesgenerator.com** posts the *Paste table data* text to its server, drops the empty first cell (every header moves one column left) and splits the two-line cell into two rows.
- **tableconvert.com** (Excel source) also drops the empty first cell, so data rows have one cell more than the header, and leaves `a|b` unescaped.
- **tabletomarkdown.com** keeps the columns and escapes `|` and `*`, but not `_`.
- All three pad by character count, so the cell with `東京` comes out two columns too wide in a monospace font.

## Limits

- No merged cells: GFM has no colspan or rowspan. Merged cells from HTML are split; the text goes into the first cell.
- Cells hold inline Markdown only: no lists, block quotes or code blocks.
- Leading and trailing spaces in a cell are dropped (GFM trims them) and tabs become spaces.
- The grid shows the first 1,000 rows; the Markdown output has all rows.
- Import reads the first Markdown table in the text and the first `<table>` in HTML.
