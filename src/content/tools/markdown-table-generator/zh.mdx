## 使用方法

1. 在网格里直接输入。**Enter** 跳到下一行的同一列（在最后一行会新增一行），**Shift+Enter** 在单元格内换行。
2. 已有数据时，在 Excel、WPS 表格或网页里复制一片单元格，粘贴到任意单元格；也可以打开「导入数据」，粘贴 CSV、TSV、JSON、HTML 表格或现成的 Markdown 表格，格式会自动识别。
3. 在表头上方那一行选择每列的对齐方式：默认写 `---`，左对齐 `:---`，居中 `:---:`，右对齐 `---:`。
4. 工具栏作用于当前单元格：插入或删除行和列、左右移动列、按该列排序、行列互换、撤销。
5. 点「复制 Markdown」或「下载 .md」。「预览」按 GFM 渲染出表格，可以先检查一遍。

## 示例：从电子表格复制季度数据

左上角是空单元格，一个单元格里有两行备注，最后一格为空。粘贴到第一个表头单元格，并把「一季度」设为右对齐：

{/* mdt-check: {"import": {"format": "tsv", "text": "\t一季度\t二季度\n华东\t1,200\t\"延迟：\n供应商缺货\"\n华南\t980\t"}, "align": ["none", "right", "none"]} */}
```markdown
|      | 一季度 | 二季度               |
| ---- | -----: | -------------------- |
| 华东 |  1,200 | 延迟：<br>供应商缺货 |
| 华南 |    980 |                      |
```

空的第一格保留了自己的列，「一季度」仍在「1,200」上方。单元格里的换行写成 `<br>`，因为真正的换行会结束这一行（[GFM 规范 4.10 节](https://github.github.com/gfm/#tables-extension-)）。

## 示例：全角竖线写的表格

如果手写表格时竖线和横线打成了全角的 `｜` `－`（例如开着全角标点输入），GFM 不会识别：它只认半角 `|`，这样的表格在 GitHub、Gitee 上显示为一段普通文字（本工具测试脚本记录了两家 API 的实际返回）。把它粘贴到「导入数据」：

```text
｜接口｜方法｜说明｜
｜－－－｜：－－：｜－－－｜
｜/users｜GET｜用户列表｜
｜/users/{id}｜DELETE｜删除用户｜
```

工具按半角读取并在状态栏说明，输出：

{/* mdt-check: {"import": {"format": "markdown", "text": "｜接口｜方法｜说明｜\n｜－－－｜：－－：｜－－－｜\n｜/users｜GET｜用户列表｜\n｜/users/{id}｜DELETE｜删除用户｜"}} */}
```markdown
| 接口        |  方法  | 说明     |
| ----------- | :----: | -------- |
| /users      |  GET   | 用户列表 |
| /users/{id} | DELETE | 删除用户 |
```

只有分隔行里的全角横线和冒号会改成半角，单元格里的「：」原样保留。

## 示例：数据库字段表里的下划线

单元格默认按 Markdown 处理，`**加粗**`、`` `代码` `` 和链接都能用。字段名里的 `_` 和 `*` 却不该变成格式。把「单元格内容」设为纯文本：

{/* mdt-check: {"import": {"format": "csv", "text": "字段,类型,说明\nuser_id,bigint,主键\n_deleted,bool,软删除标记\ntags,varchar,用 | 分隔"}, "opts": {"plain": true}} */}
```markdown
| 字段      | 类型    | 说明       |
| --------- | ------- | ---------- |
| user_id   | bigint  | 主键       |
| \_deleted | bool    | 软删除标记 |
| tags      | varchar | 用 \| 分隔 |
```

`user_id` 中间的下划线不会触发斜体，所以不加反斜杠；开头的 `_deleted` 会加。选 Markdown 模式时，输出下方会提示有几个单元格渲染后和原文不同。

## Gitee、GitHub 与 micromark 的差异

测试脚本把输出交给 micromark 渲染，并与 2026-10-02 从 GitHub、Gitee 的 Markdown API 以及 Zenn、Qiita 的渲染器取回的 HTML 逐格对比：

```text
单元格里写        GitHub / Gitee / Qiita / Zenn    micromark（remark、MDX、Astro）
a\|b              a|b                              a|b
x\\|y             一个单元格 x|y                   两个单元格 x\ 和 y
`a|b`             在 `a 处结束单元格                同左
行一<br>行二      换行                             允许 HTML 时换行
**注意：**这里    不加粗                           不加粗
```

工具不会写出 `\\|`。最后一行是 CommonMark 的规则：`**` 紧挨着全角标点「：」时不能开始或结束强调，写成 `**注意**：这里` 即可加粗。

## 中文列为什么能对齐

「列对齐」排版按显示宽度补空格：汉字、假名、谚文、全角符号和 emoji 计 2 列，组合符号计 0 列，依据 [Unicode UAX #11](https://www.unicode.org/reports/tr11/) 与 EastAsianWidth 18.0.0 数据。计算规则与 markdownlint 的 [MD060](https://github.com/DavidAnson/markdownlint/blob/main/doc/md060.md) 所用的 string-width 8.1.0 一致，测试脚本用 MD055、MD056、MD058、MD060 检查了 200 个随机表格的两种排版。○ × ① → 这类字符在 UAX #11 里属于宽度不定（在东亚旧字符集里是全角）。如果编辑器把它们显示为 2 列，勾选对应选项。

## 与同类工具对比

2026-10-02 用同一组数据（左上角空单元格、两行单元格、`a|b`、`5*3*2`、`东京`）测试：

- tableconvert.com（中文版在 Bing「markdown表格生成」排第一）从 Excel 读取时丢掉左上角的空单元格，表头因此少一列，数据行多出的单元格在 GitHub 上不显示；`a|b` 没有转义。
- tablesgenerator.com 的「Paste table data」把文本以表单 POST 提交到它的服务器，同样丢掉空单元格，并把两行单元格拆成两行。
- 两者都按字符数补空格，`东京` 所在的格在等宽字体里多出两列宽，对不齐。

## 限制

- 不支持合并单元格：GFM 没有 colspan / rowspan，HTML 里的合并单元格会拆开，文字放在第一格。
- 单元格里只能写行内 Markdown，不能放列表、引用或代码块。
- 单元格首尾空格会被 GFM 去掉，制表符写成空格。
- 网格只显示前 1,000 行，Markdown 输出包含全部行。
- 导入时只读取文本里的第一个 Markdown 表格、HTML 里的第一个 `<table>`。

只需单向转换 CSV 时用 [CSV 转 Markdown 表格](/zh/tools/csv-to-markdown/)；整页 HTML 转换用 [HTML 转 Markdown](/zh/tools/html-to-markdown/)；想看表格在全文里的效果，用 [Markdown 预览](/zh/tools/markdown-preview/)。
