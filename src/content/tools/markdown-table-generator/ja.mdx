## 例：○×の対応表

料金プランの比較表は ○ と × をよく使います。スプレッドシートからコピーしたセルを貼り付け、プラン列を中央揃えにすると次のようになります。

{/* mdt-check: {"import": {"format": "tsv", "text": "機能\t無料版\t有料版\n共有リンク\t○\t○\nSSO\t×\t○\n容量\t5GB\t1TB"}, "align": ["none", "center", "center"]} */}
```markdown
| 機能       | 無料版 | 有料版 |
| ---------- | :----: | :----: |
| 共有リンク |   ○    |   ○    |
| SSO        |   ×    |   ○    |
| 容量       |  5GB   |  1TB   |
```

○ と × は [Unicode UAX #11](https://www.unicode.org/reports/tr11/) で幅が「曖昧」（Ambiguous）な文字です。欧文の環境では半角、日本語の旧来の文字コード（Shift_JIS など）では全角として扱われてきました。エディターで ○ が全角幅に見えるなら「幅が曖昧な文字を全角として数える」をオンにします。

{/* mdt-check: {"import": {"format": "tsv", "text": "機能\t無料版\t有料版\n共有リンク\t○\t○\nSSO\t×\t○\n容量\t5GB\t1TB"}, "align": ["none", "center", "center"], "opts": {"ambiguousWide": true}} */}
```markdown
| 機能       | 無料版 | 有料版 |
| ---------- | :----: | :----: |
| 共有リンク |   ○   |   ○   |
| SSO        |   ×   |   ○   |
| 容量       |  5GB   |  1TB   |
```

どちらの出力も表示結果は同じです。違うのはソースの見た目だけです。

## 例：全角の縦棒で書かれた表

全角入力のまま手で書いた表では、`｜` や `ー` が全角になっていることがあります。GFM が区切りとして扱うのは半角の `|` だけなので、GitHub、Qiita、Zenn ではただの文章として表示されます（このツールのテストで各レンダラーの出力を記録しています）。「データ取り込み」に貼り付けると半角に読み替えます。

```text
｜項目｜内容｜
｜ーー｜ーー｜
｜締切｜10月31日｜
```

{/* mdt-check: {"import": {"format": "markdown", "text": "｜項目｜内容｜\n｜ーー｜ーー｜\n｜締切｜10月31日｜"}} */}
```markdown
| 項目 | 内容     |
| ---- | -------- |
| 締切 | 10月31日 |
```

区切り行の全角ハイフンや長音記号、全角コロンだけを半角にし、セルの中の全角文字はそのままです。

## Qiita と Zenn での表示

表の書き方は [Qiita のチートシート](https://qiita.com/Qiita/items/c686397e4a0f4f11683d) と [Zenn の Markdown ガイド](https://zenn.dev/zenn/articles/markdown-guide) にあります。2026-10-02 に Qiita のレンダラー（qiita_marker 0.23.9.0）と Zenn のレンダラー（zenn-markdown-html 0.5.4）、GitHub と Gitee の API でこのツールの出力を描画し、セルの文字を比べました。

- `\|` と書いたパイプは、Qiita、Zenn、GitHub、micromark のどれでもセル内の `|` になります。
- `<br>` はどれでも改行です（micromark は HTML を許可したとき）。
- `x\\|y` は Qiita・Zenn・GitHub では 1 セル、micromark では 2 セルです。ツールはこの形を出力しません。
- `**注意：**ここ` はどれでも太字になりません。CommonMark では `**` が全角の句読点「：」に接していると強調が閉じないためです。`**注意**：ここ` と書けば太字になります。

## 日本語の列をそろえる仕組み

「列をそろえる」では、各セルを列の最大幅まで表示幅でスペース埋めします。漢字・かな・全角英数字・絵文字は 2 桁、結合文字は 0 桁で、データは EastAsianWidth 18.0.0 です。計算方法は markdownlint の [MD060](https://github.com/DavidAnson/markdownlint/blob/main/doc/md060.md) が使う string-width 8.1.0 と同じで、テストでは 200 個のランダムな表の両レイアウトに MD055・MD056・MD058・MD060 をかけています。

## 他のツールとの比較

2026-10-02、同じデータ（左上が空のセル、2 行のセル、`a|b`、`5*3*2`、`東京`）で試しました。

- NotePM の Markdown 表作成ツール（Bing「markdown 表 作成」で 3 位）は空セルの位置を保ち、日本語の幅も考えて列をそろえますが、`a|b` をエスケープしないため、その行は GitHub で 1 セル多くなり `b` が表示されません。
- tableconvert.com（Excel から変換）は左上の空セルを落とし、見出しが 1 列ずれます。`a|b` もそのままです。
- tablesgenerator.com の「Paste table data」は貼り付けたテキストをフォームで自社サーバーへ POST し、2 行のセルを 2 つの行に分けてしまいます。

## 制限

- 結合セルは作れません。GFM に colspan / rowspan はなく、HTML の結合セルは分割して先頭のセルに文字を入れます。
- セルに書けるのはインラインの Markdown だけです。箇条書き・引用・コードブロックは入りません。
- セルの先頭と末尾の空白は GFM が削除し、タブはスペースにします。
- グリッドに表示するのは先頭 1,000 行で、Markdown 出力にはすべての行が入ります。
- 取り込むのはテキスト内の最初の Markdown テーブル、HTML 内の最初の `<table>` です。

CSV を一方向に変換するだけなら [CSV → Markdown テーブル](/ja/tools/csv-to-markdown/)、ページ全体なら [HTML → Markdown 変換器](/ja/tools/html-to-markdown/)、文書の中での見え方は [Markdown プレビュー](/ja/tools/markdown-preview/) で確認できます。
