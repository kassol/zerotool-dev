<h2>What is a .gitignore file?</h2>
<p>
  A <code>.gitignore</code> file lists patterns Git should ignore — typically build artifacts, OS metadata, IDE caches, dependency directories, and secrets. Patterns follow gitignore glob syntax (<code>*.log</code>, <code>build/</code>, <code>!keep-this.log</code>) and apply per directory. Every Git repository should ship one to keep clones reproducible and prevent leaking environment-specific noise.
</p>

<h2>How merging works</h2>
<p>
  Selected templates are sorted alphabetically and concatenated. For each template we emit a <code>### Name.gitignore</code> header so you can trace which rules came from where. Identical rule lines across templates are dropped after the first appearance, but comments and blank lines are kept verbatim. Custom rules go last under <code>### Custom additions</code>. The output starts with a small attribution header pointing back to ZeroTool and the github/gitignore source — remove it freely if you prefer a clean file.
</p>

<h2>Why a curated bundle</h2>
<p>
  Crawling github/gitignore at request time would add network latency and rate-limit exposure. We snapshot the repository at build time, dedupe IDs, and ship the result as a single TypeScript module — predictable, auditable, and zero runtime dependencies. Refreshing pulls a new snapshot from upstream and replaces the bundle in one commit.
</p>

<h2>Syntax Pitfalls, Checked with Git</h2>
<p>With this <code>.gitignore</code>, <code>git check-ignore -v</code> (Git 2.56) reports:</p>

```text
logs/
!logs/keep.log
docs/*.pdf
build/
/secret.txt
```

<ul>
  <li><code>logs/keep.log</code> is still ignored by <code>logs/</code>. Git does not look inside an excluded directory, so the negation never applies (<a href="https://git-scm.com/docs/gitignore" target="_blank" rel="noopener">gitignore documentation</a>). Write <code>{'logs/*'}</code> instead of <code>logs/</code> if you need the exception.</li>
  <li><code>{'docs/*.pdf'}</code> ignores <code>docs/a.pdf</code> but not <code>docs/notes/old.pdf</code>: a slash in the middle anchors the pattern to the directory of the <code>.gitignore</code> file, and <code>{'*'}</code> does not cross <code>/</code>.</li>
  <li><code>build/</code> matches <code>build/</code> and <code>src/build/</code> at any depth, but only directories.</li>
  <li><code>/secret.txt</code> matches the root file only; <code>src/secret.txt</code> is not ignored.</li>
</ul>

<h2>Files That Are Already Tracked</h2>
<p>A new rule does not untrack files Git already tracks. Remove them from the index and commit; the files stay on disk:</p>

```bash
git rm -r --cached node_modules/
git commit -m "Stop tracking node_modules"
```

<p>This does not remove the files from earlier commits. If a secret was committed, rotate it; rewriting history (for example with <code>git filter-repo</code>) needs a force-push and fresh clones.</p>

<h2>Limits</h2>
<ul>
  <li>The bundle has 237 templates: 162 from the root of github/gitignore (languages and frameworks) and 75 from <code>Global/</code> (editors, operating systems, tools). Templates under <code>community/</code> are not included.</li>
  <li>The templates are a snapshot taken when the bundle was last refreshed. Changes merged upstream after that appear only after the next refresh.</li>
  <li>Deduplication removes repeated identical lines across the whole file. It does not merge equivalent patterns such as <code>{'node_modules'}</code> and <code>{'node_modules/'}</code>.</li>
</ul>
