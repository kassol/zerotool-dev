<h2>使い方</h2>
<ol>
  <li>GraphQL query、mutation、subscription、SDL スキーマを入力欄に貼り付けるか、<strong>サンプルを読み込む</strong> から例を起点にしてください。</li>
  <li><strong>整形</strong> で美化、<strong>圧縮</strong> で短縮、<strong>検証</strong> で構文のみ確認できます。</li>
  <li>インデントは 2 または 4 スペースを切り替え可能。デフォルト 2 は graphql-js のネイティブ出力と同じです。</li>
  <li><strong>コピー</strong> や <strong>.graphql をダウンロード</strong> で結果を持ち帰り。<kbd>Cmd/Ctrl + Enter</kbd> でキーボードから整形できます。</li>
</ol>

<h2>実例</h2>

<h3>整形前</h3>

```graphql
query GetUser($id:ID!,$withPosts:Boolean!){user(id:$id){id name email posts @include(if:$withPosts){...PostSummary}}} fragment PostSummary on Post{id title publishedAt}
```

<h3>整形後</h3>

```graphql
query GetUser($id: ID!, $withPosts: Boolean!) {
  user(id: $id) {
    id
    name
    email
    posts @include(if: $withPosts) {
      ...PostSummary
    }
  }
}

fragment PostSummary on Post {
  id
  title
  publishedAt
}
```

<h3>SDL スキーマ</h3>

```graphql
type Post {
  id: ID!
  title: String!
  publishedAt: DateTime
  author: User!
}

type Query {
  post(id: ID!): Post
  posts(authorId: ID, limit: Int = 20): [Post!]!
}
```

<h2>なぜ GraphQL を整形するのか</h2>
<p>一貫した GraphQL の整形は、コードレビュー、スキーマ diff、<code>.graphql</code> ファイルの保管に直結します。永続化クエリを使えない環境では minify によって通信量を減らせます。整形されたクエリは PR 上で読みやすく、クエリを単体で検証すると、閉じかっこの不足や閉じていない文字列といった構文エラーを送信前に見つけられます。存在しない fragment 名は構文エラーではないため、スキーマを使った検証が必要です。</p>

<h2>内部の仕組み</h2>
<p>本ツールはブラウザ内で <code>graphql-js</code>（GraphQL Foundation 管理の公式リファレンス実装）を動かします。<code>parse()</code> がテキストから AST を構築し、最初の構文エラーを行・列で報告。<code>print()</code> が AST を規範的な GraphQL に再シリアライズ。<code>stripIgnoredCharacters()</code> が spec で ignored とされるトークンをすべて除去して圧縮版を返します。ネットワーク往復ゼロ、データは端末内に留まります。</p>

<h2>圧縮とエラーの例</h2>
<p>上の「整形前」のクエリで<strong>圧縮</strong>を押すと、次のようになります（graphql-js 16.14 の <code>stripIgnoredCharacters</code>）。</p>

```graphql
query GetUser($id:ID!$withPosts:Boolean!){user(id:$id){id name email posts@include(if:$withPosts){...PostSummary}}}fragment PostSummary on Post{id title publishedAt}
```

<p>GraphQL ではカンマは無視されるトークンなので、空白と一緒に削除されます。閉じ波かっこが 1 つ足りない <code>query &#123; user(id: 1) &#123; id name &#125;</code> は <code>解析エラー: Syntax Error: Expected Name, found &lt;EOF&gt;. (行 1, 列 32)</code> と表示され、パーサーが入力の終わりに達した位置を指します。</p>

<h2>制限</h2>
<ul>
  <li><strong>整形するとコメントが消えます。</strong>graphql-js の <code>print()</code> は構文木から文字列を作り直し、<code># コメント</code>は構文木に含まれません。圧縮でもコメントは削除されます。コメントが必要なら元のファイルを残してください。</li>
  <li>検証は構文だけです。<code>&#123; user(id: $id) &#123; id &#125; &#125;</code> は <code>$id</code> が宣言されていなくても通ります。変数やフィールドの確認にはスキーマが必要です。</li>
  <li>報告される構文エラーは最初の 1 件だけです。</li>
  <li>4 スペースのオプションが広げるのは入れ子によるインデントだけです。<code>"""</code> のブロック文字列は開始行が新しいインデントに移り、中の文字はそこからの相対的なインデントを保ちます。GraphQL の仕様はブロック文字列の共通インデントだけを取り除くため、中の行まで広げると説明文が変わってしまうからです。graphql-js の出力は 2 スペースで、他のツールも 2 スペースになります。</li>
  <li>入力の上限は 10,485,760 文字です。</li>
</ul>
