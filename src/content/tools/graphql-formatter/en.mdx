<h2>Worked Examples</h2>

<h3>Before formatting</h3>

```graphql
query GetUser($id:ID!,$withPosts:Boolean!){user(id:$id){id name email posts @include(if:$withPosts){...PostSummary}}} fragment PostSummary on Post{id title publishedAt}
```

<h3>After formatting</h3>

```graphql
query GetUser($id: ID!, $withPosts: Boolean!) {
  user(id: $id) {
    id
    name
    email
    posts @include(if: $withPosts) {
      ...PostSummary
    }
  }
}

fragment PostSummary on Post {
  id
  title
  publishedAt
}
```

<h3>SDL schema</h3>

```graphql
type Post {
  id: ID!
  title: String!
  publishedAt: DateTime
  author: User!
}

type Query {
  post(id: ID!): Post
  posts(authorId: ID, limit: Int = 20): [Post!]!

```

<h2>Why Format GraphQL?</h2>
<p>Consistent GraphQL formatting matters for code review, schema diffs, and storing operations in <code>.graphql</code> files. Minified queries shrink wire payloads when you cannot rely on persisted queries; pretty-printed queries are easier to scan in PRs. Validating a query in isolation catches syntax mistakes such as a missing brace or an unclosed string before you send it; an undefined fragment name is not a syntax error and needs schema-aware validation.</p>

<h2>Behind the Scenes</h2>
<p>This tool runs <code>graphql-js</code> (the reference implementation maintained by The GraphQL Foundation) entirely inside your browser. <code>parse()</code> builds an AST from your text and reports the first syntax error with line and column. <code>print()</code> serializes the AST back to canonical GraphQL. <code>stripIgnoredCharacters()</code> removes every token the spec marks as ignored — that is the minified form. Nothing is sent anywhere, and there is no server round-trip.</p>

<h2>Minify and Error Examples</h2>
<p><strong>Minify</strong> on the "before" query above returns (graphql-js 16.14 <code>stripIgnoredCharacters</code>):</p>

```graphql
query GetUser($id:ID!$withPosts:Boolean!){user(id:$id){id name email posts@include(if:$withPosts){...PostSummary}}}fragment PostSummary on Post{id title publishedAt}
```

<p>Commas are ignored tokens in GraphQL, so they are removed along with the whitespace. A missing closing brace in <code>query &#123; user(id: 1) &#123; id name &#125;</code> is reported as <code>Parse error: Syntax Error: Expected Name, found &lt;EOF&gt;. (line 1, column 32)</code>, pointing at the end of the input where the parser ran out of text.</p>

<h2>Aliases, Variables, and Comments</h2>
<p>This query asks for two users with different aliases. Choose 4 spaces and click <strong>Format</strong> to separate the nested selections. The output keeps <code>primary</code>, <code>secondary</code>, the quoted IDs, the variable default, and the <code>@include</code> directive. The leading comment disappears. Keep a copy of the original query when that comment contains useful context. <strong>Minify</strong> keeps the same operation and selections while removing the comment and spacing between tokens where the parser permits it.</p>

<h3>Input</h3>

```graphql
# Fetch two labels
query Labels($show: Boolean! = true) { primary: user(id: "a") { name } secondary: user(id: "b") @include(if: $show) { name } }
```

<h3>Four-space output</h3>

```graphql
query Labels($show: Boolean! = true) {
    primary: user(id: "a") {
        name
    }
    secondary: user(id: "b") @include(if: $show) {
        name
    }
}
```

<h3>Minified output</h3>

```graphql
query Labels($show:Boolean!=true){primary:user(id:"a"){name}secondary:user(id:"b")@include(if:$show){name}}
```

<h2>Keep Indented Description Text</h2>
<p>A description can contain its own indentation. In this SDL example, the note starts two spaces further in than the preceding sentence. Formatting with 4 spaces moves the field and the description delimiters to the wider structural indentation. The note still starts two spaces further in than the sentence. Parsing the formatted result gives the same description text as the input, including that newline and the two spaces before the note.</p>

<h3>Input</h3>

```graphql
type Query {
  """
  Returns a label.
    Keep this note indented.
  """
  label: String
}
```

<h3>Four-space output</h3>

```graphql
type Query {
    """
    Returns a label.
      Keep this note indented.
    """
    label: String
}
```

<h2>Limits</h2>
<ul>
  <li><strong>Format drops comments.</strong> graphql-js <code>print()</code> rebuilds the text from the syntax tree, and <code># comments</code> are not part of the tree. Minify removes them too. Keep the original file if its comments matter.</li>
  <li>Validation is syntax only. <code>&#123; user(id: $id) &#123; id &#125; &#125;</code> passes even though <code>$id</code> is never declared; checking variables and fields needs the schema.</li>
  <li>Only the first syntax error is reported.</li>
  <li>The 4-space option widens only the indentation that comes from nesting. Inside a <code>"""</code> block string, the opening line moves to the new indentation and the text keeps its own indentation relative to it, because the GraphQL spec removes only the common indentation of a block string; widening the inner lines would change the description text. graphql-js prints with 2 spaces, so 2 spaces is the output other tools produce.</li>
  <li>Input is limited to 10,485,760 characters.</li>
</ul>
