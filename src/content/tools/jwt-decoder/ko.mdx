<h2>예시: 카카오 로그인 ID 토큰 확인하기</h2>
<p>카카오 로그인에서 OpenID Connect를 켜면 액세스 토큰과 함께 ID 토큰을 받을 수 있습니다. <a href="https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api" target="_blank" rel="noopener">카카오 로그인 REST API 문서</a>에 따르면 ID 토큰 페이로드에는 <code>iss</code>(<code>https://kauth.kakao.com</code>으로 고정), <code>aud</code>(앱 키), <code>sub</code>(회원번호), <code>iat</code>, <code>exp</code>, <code>auth_time</code>과, 동의한 경우 <code>nickname</code> 등이 들어갑니다.</p>
<p>아래 토큰은 같은 문서의 「ID 토큰 정보 조회」 응답 예시에 있는 회원번호와 시각을 쓰고, 닉네임 「홍길동」과 가짜 앱 키를 넣어 만든 것입니다. 실제 카카오 ID 토큰은 헤더의 <code>alg</code>가 <code>RS256</code>으로 고정이고 카카오의 키로 서명되지만, 이 예시는 누구나 다시 만들 수 있도록 데모용 비밀 키 <code>zerotool-demo-secret-ko</code>로 HS256 서명했습니다. 디코딩 결과는 서명 방식과 관계없이 같은 방법으로 읽힙니다.</p>
{/* jwtd-check: {"header":{"alg":"HS256","typ":"JWT"},"payload":{"iss":"https://kauth.kakao.com","aud":"demo-app-key","sub":"166959","iat":1647183250,"exp":1647190450,"auth_time":1647183250,"nickname":"홍길동"},"secret":"zerotool-demo-secret-ko","show":["token","payload","hints"]} */}


<p>Payload 영역에는 다음 JSON이 표시됩니다. 「복사」를 눌러도 날짜 주석 없이 같은 내용이 복사됩니다.</p>

```json
{
  "iss": "https://kauth.kakao.com",
  "aud": "demo-app-key",
  "sub": "166959",
  "iat": 1647183250,
  "exp": 1647190450,
  "auth_time": 1647183250,
  "nickname": "홍길동"
}
```

<p><code>iat</code> 옆에는 <code>Sun, 13 Mar 2022 14:54:10 GMT</code>, <code>exp</code> 옆에는 <code>Sun, 13 Mar 2022 16:54:10 GMT — EXPIRED</code>가 표시됩니다. 한국 시간으로는 2022년 3월 13일 23:54:10에 발급되어 3월 14일 01:54:10에 만료된 토큰이고, 두 값의 차이는 7200초, 곧 2시간입니다. <code>auth_time</code>은 날짜 주석 대상이 아니라서 숫자만 보입니다. 날짜가 붙는 키는 <code>exp</code>, <code>iat</code>, <code>nbf</code> 세 개뿐입니다.</p>
<p>카카오 문서는 ID 토큰 정보 조회 API(<code>https://kauth.kakao.com/oauth/tokeninfo</code>)를 디버깅용 참고 정보를 돌려주는 API로 설명하고, 서비스는 ID 토큰의 유효성을 먼저 검증한 뒤 토큰의 사용자 정보를 활용하라고 안내합니다. 서명 검증에 쓰는 공개키는 공개키 목록(<code>https://kauth.kakao.com/.well-known/jwks.json</code>)에서 받습니다. 이 도구의 디코딩 결과는 그 검증을 대신하지 않습니다.</p>

<h2>붙여넣을 때 자주 생기는 오류</h2>
{/* jwtd-check: {"header":{"alg":"HS256","typ":"JWT"},"payload":{"iss":"https://kauth.kakao.com","aud":"demo-app-key","sub":"166959","iat":1647183250,"exp":1647190450,"auth_time":1647183250,"nickname":"홍길동"},"secret":"zerotool-demo-secret-ko","prefix":"\"","suffix":"\"","show":["status"]} */}
<p>토큰 요청 API 응답은 <code>{`"id_token": "eyJ..."`}</code> 형태의 JSON입니다. 값을 복사하면서 양쪽 큰따옴표까지 함께 붙여넣으면 상태 표시줄에 <code>Base64URL 디코드에 실패했습니다.</code>가 나타납니다. 따옴표를 빼고 <code>eyJ</code>로 시작하는 부분만 붙여넣으세요. 앞에 <code>Bearer </code>가 붙어 있을 때도 같은 오류가 납니다.</p>
{/* jwtd-check: {"token":"eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxNjY5NTkifQ","show":["status"]} */}
<p>긴 토큰이 화면에서 줄바꿈되어 마지막 서명 부분을 빠뜨리기도 합니다. <code>eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxNjY5NTkifQ</code>처럼 두 부분만 넣으면 <code>유효하지 않은 JWT: 3개 파트가 필요합니다. 실제: 2.</code>가 표시됩니다. 위 두 경우는 300밀리초 후 자동 디코딩도 동작하지 않으므로, 오류 내용을 보려면 「디코드」를 눌러야 합니다.</p>

<h2>제한</h2>
<ul>
  <li>날짜를 표시하는 것은 값이 숫자(초)인 <code>exp</code>, <code>iat</code>, <code>nbf</code>뿐이며, 중첩된 객체의 같은 이름 필드에도 붙습니다. 원래 숫자는 그대로 보여 주고 날짜 주석은 초 단위까지만 표시합니다. 밀리초 값을 넣으면 수만 년 뒤의 날짜가 나옵니다.</li>
  <li>「valid」, 「EXPIRED」, 서명 영역의 「not verified」, 「(unable to parse)」는 모든 언어 페이지에서 영어로 표시됩니다.</li>
  <li>디코딩은 되지만 JSON이 아닌 부분은 「(unable to parse)」로 표시됩니다.</li>
  <li>암호화된 JWE는 다섯 부분으로 이루어져 키 없이는 읽을 수 없습니다(<a href="https://www.rfc-editor.org/rfc/rfc7516#section-3" target="_blank" rel="noopener">RFC 7516 §3</a>).</li>
  <li>서명은 검증하지 않습니다. 서버에서는 발급자의 키로 서명을 검증한 뒤 <code>exp</code>, <code>nbf</code>, <code>iss</code>, <code>aud</code>를 확인해야 합니다(<a href="https://www.rfc-editor.org/rfc/rfc8725#section-3" target="_blank" rel="noopener">RFC 8725 §3</a>).</li>
  <li>토큰은 어디에도 저장하지 않습니다. JWT는 로그인 자격 증명인 경우가 많아, 이 페이지는 분석·광고 스크립트를 불러오지 않습니다.</li>
</ul>

<h2>JWT에 대하여</h2>
<p>JWT는 웹 애플리케이션의 인증·인가에 널리 쓰입니다. 사용자가 로그인하면 서버가 JWT를 발급하고, 클라이언트는 이후 요청에서 JWT를 Authorization 헤더에 넣어 보냅니다. 디버깅 중에 토큰 안의 사용자 ID, 역할, 만료 시각을 확인하고 싶을 때 이 도구를 씁니다. 원하는 클레임으로 테스트 토큰을 만들려면 <a href="/ko/tools/jwt-generator/">JWT 생성기 / 서명 도구</a>를 사용하세요.</p>
