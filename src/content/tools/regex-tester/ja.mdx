## 実際の動作例

`g` をオンにしたときのテスターの結果です。

| 正規表現 | テスト文字列 | マッチ |
|---|---|---|
| `[ぁ-んァ-ヶー一-龠]+` | `注文番号は12345です` | `注文番号は`、`です` |
| `<.+>` | `<a>foo</a>` | `<a>foo</a>`（最長一致：最初の `<` から最後の `>` まで） |
| `<.+?>` | `<a>foo</a>` | `<a>`、`</a>`（最短一致） |
| `(?<=\$)\d+` | `cost $42` | `42`（後読み） |
| `^(?<ts>\S+)\s+(?<level>\w+)\s+(?<msg>.+)$` | `2026-04-07T14:23:01 ERROR connection refused` | 1 件。グループは `2026-04-07T14:23:01`、`ERROR`、`connection refused` |

正規表現が確認するのは形式だけです。`^\d{4}-(?:0[1-9]|1[0-2])-(?:0[1-9]|[12]\d|3[01])$` は `2026-02-31` も通すので、日付は日付ライブラリで解析してください。

## 結果の読み方

状態行にマッチの総数が出て、その下の一覧に 1 件ずつ、マッチした文字列と位置が並びます。キャプチャグループは番号付きで字下げして表示されます。金額を抜き出す例では、先読み `(?=円)` が「円」を含めずに数字だけを返します。

{/* rgx-check: {"p":"\\d[\\d,]*(?=円)","f":"g","s":"税込1,980円（本体1,800円）"} */}

```text
2 件マッチしました。
マッチ 1: 1,980 (位置 2)
マッチ 2: 1,800 (位置 11)
```

位置は UTF-16 のコード単位で数えます。ひらがな・漢字・全角括弧はどれも 1 単位なので、2 件目は「税込1,980円（本体」の 11 文字のあとから始まります。絵文字や「𠮷」のような U+FFFF を超える文字は 2 単位になり、そのあとの位置が 1 文字につき 2 ずつ増えます。

## 日本語のテキストで気をつけること

**全角で入力された数字。** 郵便番号を 1 行ずつ検査するとき（`g` と `m` をオン）、IME の全角モードで入った 2 行目と、ハイフンだけ全角の「－」（U+FF0D）になった 3 行目は通りません。

{/* rgx-check: {"p":"^\\d{3}-\\d{4}$","f":"gm","s":"150-0002\n１５０-０００２\n150－0002"} */}

```text
1 件マッチしました。
マッチ 1: 150-0002 (位置 0)
```

全角も受け付けるなら、検査の前に `String.prototype.normalize('NFKC')` で半角にそろえるのが簡単です。郵便番号の正規表現は形式を見るだけで、その番号が実在するかは確認しません。

**漢字の範囲指定。** よく使われる `[一-龠]` は「々」（U+3005）や、U+FFFF を超える「𠮷」を含みません。このツールには `u` フラグがないため、「𠮷」は 2 つのコード単位に分かれ、範囲で表せません。

{/* rgx-check: {"p":"[一-龠]+","f":"g","s":"𠮷野家 佐々木"} */}

```text
3 件マッチしました。
マッチ 1: 野家 (位置 2)
マッチ 2: 佐 (位置 5)
マッチ 3: 木 (位置 7)
```

ひらがな・カタカナの範囲の漏れ（「ゔ」「ヷ」、長音符「ー」）や、`u` フラグ付きの `\p{scx=Hira}` などの書き方は、[正規表現 早見表](/ja/blog/regex-cheat-sheet/)で JavaScript・Python・PCRE2・Go の結果と並べて確認できます。

## よくある間違い

- **メタ文字のエスケープ漏れ。** `.` `*` `+` `?` `(` `)` `[` `]` `{` `}` `^` `$` `|` `\` は特別な意味を持ちます。ピリオドそのものには `\.` と書きます。
- **複数行テキストの `^` と `$`。** `m` をオフにすると、テキスト全体の先頭と末尾にしか一致しません。
- **`\w` は ASCII だけ。** `café 東京` に `\w+` を使うと `caf` だけが一致し、漢字には一致しません。日本語の単語の前後でも `\b` は働かないので、「東京」を探すなら `\b` を付けずに `東京` と書きます。
- **量指定子の入れ子。** `(a+)+$` は一致に近い文字列で長時間かかることがあります。ネイティブ JavaScript RegExp を Worker で実行し、全体の上限は 2 秒です。「キャンセル」で停止できます。時間切れやキャンセルでは完全な結果は出ません。入力を変えると前の処理を停止します。

## 制限事項

- **JavaScript の構文だけです。** Python の `(?P<name>...)` は「Invalid group」になるので `(?<name>...)` と書きます。Go（RE2）、PCRE、Java 向けの正規表現は動作が異なることがあります。パターンが無効なときは「無効な正規表現：」のあとにブラウザーのエラー文をそのまま表示し、多くは英語です。
- **フラグは 4 つ。** 使えるのは `g`、`i`、`m`、`s` だけです。`u` がないため `\p{L}` は文字列 `p{L}` として扱われ、`y`、`d`、`v` も使えません。
- **グループは番号で表示されます。** 名前付きグループもグループ 1、グループ 2 と表示されます。
- **件数は全体、表示は上限付き。** 完了した処理では全マッチを数えます。ハイライトは先頭 100,000 UTF-16 単位と最大 1,000 件までです。一覧は先頭 100 件と各マッチの 20 グループまで、各値は 1,000 単位、合計 100,000 単位までです。短縮した値には `…` を付けます。Worker 対応が必要です。
- **置換はできません。** テスターはマッチを探すだけで、`replace()` は実行しません。
