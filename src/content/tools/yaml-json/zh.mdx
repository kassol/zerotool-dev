<h2>转换示例</h2>

<h3>简单对象</h3>
<p>输入 YAML：</p>

```yaml
name: Alice

active: true
```

<p>输出 JSON 包含 name、age 和 active 字段。</p>

<h3>嵌套结构与数组</h3>


<p>输出 JSON 包含嵌套的 server 对象，含 features 数组。</p>

<h2>YAML 与 JSON 对比</h2>
<p>
  <strong>YAML</strong>（YAML Ain't Markup Language）是一种人类友好的数据序列化格式，广泛用于配置文件（Docker Compose、Kubernetes、Ansible、GitHub Actions）。
  <strong>JSON</strong>（JavaScript Object Notation）是 API 和 Web 服务中最常用的数据交换格式。
  两者可以表示相同的数据结构——本工具在两者之间转换，注释、锚点和部分标量值会在转换中改变，见下文「类型会变的值」。
</p>

## 类型会变的值

本工具使用 js-yaml 4.3.2 的默认 schema：[YAML 1.2](https://yaml.org/spec/1.2.2/) core schema，加上时间戳、`<<` 合并键和 `!!binary`、`!!set`、`!!omap`、`!!pairs` 标签。下列输入的转换结果如下：

| YAML | JSON | 说明 |
|---|---|---|
| `country: NO` | `"NO"` | 字符串。PyYAML 等 YAML 1.1 解析器会读成 `false` |
| `enabled: yes` | `"yes"` | 同上；布尔值请写 `true` |
| `version: 1.10` | `1.1` | 按数字解析；版本号请加引号 |
| `mode: 0755` | `755` | YAML 1.2 里前导 0 不表示八进制；请写 `0o755` |
| `zip: 01234` | `1234` | 前导 0 丢失；这类编码请加引号 |
| `date: 2026-09-29` | `"2026-09-29T00:00:00.000Z"` | 日期变成完整的 UTC 时间戳 |
| `at: 2026-10-01T09:30:00+09:00` | `"2026-10-01T00:30:00.000Z"` | 偏移换成 UTC。JSON 没有日期类型，输出 UTC 的 ISO 8601 文本：时刻相同，但原来写的 `+09:00` 不保留 |
| `zero: -0.0` | `-0.0` | 负零保留负号（只用 `JSON.stringify` 会写成 `0`） |
| `empty:` | `null` | 没有值的键是 null |
| `roles: !!set {admin, editor}` | `{"admin":null,"editor":null}` | js-yaml 把 set 读成值为 null 的映射 |
| `steps: !!pairs [run: build, run: test]` | `[["run","build"],["run","test"]]` | pairs 变成 [键, 值] 数组，重复的键保留 |
| `2026-01-01: New Year` | `{"2026-01-01":"New Year"}` | 作键的日期保留原文；JSON 的键都是字符串 |

## 限制

- **一次只转换一个文档。** 含 `---` 分隔的输入会报错 `expected a single document in the stream, but found more`。
- **JSON 或 YAML 无法保存的值会停止转换。** YAML 的 `.inf`、`-.inf`、`.nan`，以及任一方向超出 ±(2^53 − 1) 的整数，在转换中会改变（`JSON.stringify` 写成 `null`，`JSON.parse` 和 js-yaml 会把大整数四舍五入）。状态栏按 JSON Pointer 列出每个字段。下面的 YAML：

  ```yaml
  size: .inf
  id: 9007199254740993
  ```

  得到 `未转换：JSON 无法原样保存下列值：/size：inf 在 JSON 中没有写法（JSON.stringify 会写成 null）；/id：整数 9007199254740993 超出 ±(2^53 − 1)，JavaScript 会把它四舍五入`。`1e400` 这类超出双精度范围的 JSON 数字同样列出。大 ID 请加引号。输出面板会清空，复制按钮停用，直到输入可以转换。
- **日期必须存在，时间只保留到毫秒。** js-yaml 用 `Date.UTC` 构造日期，会把 `2026-02-31` 顺延成 3 月 3 日，并且只保留到毫秒。这类时间戳会停止转换。下面的 YAML：

  ```yaml
  due: 2026-02-31
  at: 2026-10-01T09:30:00.123456Z
  ```

  得到 `未转换：JSON 无法原样保存下列值：/due：2026-02-31 不是有效的日期或时间；/at：2026-10-01T09:30:00.123456Z 的精度超过毫秒`。本意是文本的值请加引号（`due: "2026-02-31"`）。有效的日期时间按上表转换成 UTC。
- **`!!binary` 数据同样会停止转换。** js-yaml 把它读成字节，而 JSON 没有二进制类型（`JSON.stringify` 会写成以字节序号为键的对象）。`photo: !!binary aGVsbG8=` 得到 `未转换：JSON 无法原样保存下列值：/photo：!!binary 二进制值，JSON 没有二进制类型`。去掉 `!!binary` 标签，Base64 文本就作为字符串转换。`!!binary` 作键时同样停止：js-yaml 会把这个键写成字节值（下例为 `107,49`）。PyYAML 6.0.3 就这样写 `bytes` 类型的键，`yaml.dump({b'k1': 1})` 输出：

  ```yaml
  ? !!binary |
    azE=
  : 1
  ```

  工具给出 `未转换：JSON 无法原样保存下列值：（根）：!!binary 键 azE=，JSON 的键只能是文本`。`m: {<<: !!binary aGk=}` 这样用 `<<` 合并 `!!binary` 数据时，同样以 `/m：!!binary aGk=，<< 只能合并映射` 停止。
- **js-yaml 的处理上限。** js-yaml 4.3.2 遇到嵌套超过 100 层、合并键（`<<`）累计处理的映射和键超过 10,000 个、一个合并键列出超过 100 个映射的文档会停止，例如 `无效 YAML: 集合嵌套超过 100 层（js-yaml 默认上限） (1:103)`。
- **重复的键会报错**（`duplicated mapping key`），不会静默覆盖。
- **注释和锚点不保留。** 锚点和 `<<` 合并键会展开成普通的副本。
- **JSON 整数 `-0` 写成 `0`。** `{"count":-0,"offset":-0.0}` 得到 `count: 0` 和 `offset: -0.0`：[YAML 1.2](https://yaml.org/spec/1.2.2/#1032-tag-resolution) 把 `-0` 读作整数零，`-0.0` 仍是负的浮点零。
- **JSON → YAML 时会给有歧义的字符串加引号**，例如 `'1.10'`、`'yes'`、`'NO'`，再读回来仍是字符串。
