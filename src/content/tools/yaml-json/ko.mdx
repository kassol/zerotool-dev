<h2>YAML과 JSON의 구분 사용</h2>
<p>YAML은 Docker Compose, Kubernetes, GitHub Actions, Ansible, Helm Charts 등의 설정 파일에 널리 사용됩니다. JSON은 REST API, 웹 브라우저, 프로그램 간 데이터 교환에 적합합니다. 두 형식 간 변환이 필요한 상황에서 활용하십시오.</p>

## 타입이 바뀌는 값

이 도구는 js-yaml 4.3.2의 기본 스키마를 씁니다. [YAML 1.2](https://yaml.org/spec/1.2.2/) core schema에 타임스탬프, `<<` 병합 키, `!!binary`·`!!set`·`!!omap`·`!!pairs` 태그를 더한 것입니다. 다음 입력은 이렇게 변환됩니다.

| YAML | JSON | 설명 |
|---|---|---|
| `country: NO` | `"NO"` | 문자열. PyYAML 같은 YAML 1.1 파서는 `false`로 읽음 |
| `enabled: yes` | `"yes"` | 위와 같음. 불리언은 `true`로 쓰기 |
| `version: 1.10` | `1.1` | 숫자로 해석됨. 버전 문자열은 따옴표로 감싸기 |
| `mode: 0755` | `755` | YAML 1.2에서 앞의 0은 8진수가 아님. `0o755`로 쓰기 |
| `zip: 01234` | `1234` | 앞의 0이 사라짐. 이런 코드는 따옴표로 감싸기 |
| `date: 2026-09-29` | `"2026-09-29T00:00:00.000Z"` | 날짜가 UTC 타임스탬프 전체로 바뀜 |
| `at: 2026-10-01T09:30:00+09:00` | `"2026-10-01T00:30:00.000Z"` | 오프셋이 UTC로 바뀜. JSON에는 날짜 타입이 없어 UTC ISO 8601 문자열이 됨. 시각은 같지만 원래 쓴 `+09:00`은 남지 않음 |
| `zero: -0.0` | `-0.0` | 음수 0은 부호를 유지함(`JSON.stringify`만 쓰면 `0`) |
| `empty:` | `null` | 값이 없는 키는 null |
| `roles: !!set {admin, editor}` | `{"admin":null,"editor":null}` | js-yaml은 set을 값이 null인 매핑으로 읽음 |
| `steps: !!pairs [run: build, run: test]` | `[["run","build"],["run","test"]]` | pairs는 [키, 값] 배열이 되며 중복 키도 남음 |
| `2026-01-01: New Year` | `{"2026-01-01":"New Year"}` | 키로 쓴 날짜는 쓴 그대로의 문자열이 됨. JSON의 키는 문자열 |

## 제한 사항

- **한 번에 문서 하나만 변환합니다.** `---`로 구분된 입력은 `expected a single document in the stream, but found more` 오류가 납니다.
- **JSON이나 YAML로 나타낼 수 없는 값이 있으면 변환하지 않습니다.** YAML의 `.inf`, `-.inf`, `.nan`과 양방향 모두 ±(2^53 − 1)을 벗어나는 정수는 변환 중 값이 바뀝니다(`JSON.stringify`는 `null`로 쓰고, `JSON.parse`와 js-yaml은 큰 정수를 반올림합니다). 상태 줄에 각 필드를 JSON Pointer로 표시합니다. 다음 YAML은

  ```yaml
  size: .inf
  id: 9007199254740993
  ```

  `변환하지 않았습니다: JSON에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /size: inf — JSON으로 나타낼 수 없습니다(JSON.stringify는 null로 씁니다); /id: 정수 9007199254740993 — ±(2^53 − 1) 범위를 벗어나 JavaScript에서 반올림됩니다` 메시지를 냅니다. `1e400`처럼 배정밀도 범위를 넘는 JSON 숫자도 같은 방식으로 표시합니다. 큰 ID는 따옴표로 감싸세요. 변환할 수 있는 입력이 될 때까지 출력 패널은 비워지고 복사 버튼은 비활성화됩니다.
- **없는 날짜와 밀리초보다 정밀한 시간은 변환하지 않습니다.** js-yaml은 `Date.UTC`로 날짜를 만들기 때문에 `2026-02-31`을 3월 3일로 넘기고, 시간은 밀리초까지만 남깁니다. 이런 타임스탬프가 있으면 변환을 멈춥니다. 다음 YAML은

  ```yaml
  due: 2026-02-31
  at: 2026-10-01T09:30:00.123456Z
  ```

  `변환하지 않았습니다: JSON에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /due: 2026-02-31 — 올바른 날짜나 시각이 아닙니다; /at: 2026-10-01T09:30:00.123456Z — 밀리초보다 정밀합니다` 메시지를 냅니다. 텍스트로 쓰려는 값은 따옴표로 감싸세요(`due: "2026-02-31"`). 올바른 날짜와 시간은 위 표처럼 UTC로 변환됩니다.
- **`!!binary` 데이터도 변환하지 않습니다.** js-yaml은 이를 바이트로 읽지만 JSON에는 바이너리 자료형이 없습니다(`JSON.stringify`는 바이트 번호를 키로 하는 객체로 씁니다). `photo: !!binary aGVsbG8=`는 `변환하지 않았습니다: JSON에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /photo: !!binary 값 — JSON에는 바이너리 자료형이 없습니다` 메시지를 냅니다. `!!binary` 태그를 빼면 Base64 텍스트가 문자열로 변환됩니다. `!!binary`를 키로 쓴 경우에도 변환하지 않습니다. js-yaml은 이 키를 바이트 값 목록(아래 예에서는 `107,49`)으로 바꿉니다. PyYAML 6.0.3은 `bytes` 키를 이렇게 쓰며, `yaml.dump({b'k1': 1})`의 출력은 다음과 같습니다.

  ```yaml
  ? !!binary |
    azE=
  : 1
  ```

  도구는 `변환하지 않았습니다: JSON에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: (루트): !!binary 키 azE= — JSON의 키는 문자열만 쓸 수 있습니다` 메시지를 냅니다. `m: {<<: !!binary aGk=}`처럼 `<<`로 `!!binary` 데이터를 병합해도 `/m: !!binary aGk= — <<로는 매핑만 병합할 수 있습니다`로 멈춥니다.
- **js-yaml 처리 한도.** js-yaml 4.3.2는 중첩이 100단계를 넘거나, 병합 키(`<<`)가 처리하는 매핑과 키가 모두 10,000개를 넘거나, 병합 키 하나에 매핑을 100개 넘게 나열한 문서에서 멈춥니다. 예: `유효하지 않은 YAML: 컬렉션 중첩이 100단계를 넘습니다(js-yaml 기본 한도) (1:103)`.
- **중복 키는 오류입니다**(`duplicated mapping key`). 조용히 덮어쓰지 않습니다.
- **주석과 앵커는 남지 않습니다.** 앵커와 `<<` 병합 키는 펼쳐져 일반 복사본이 됩니다.
- **JSON 정수 `-0`은 `0`이 됩니다.** `{"count":-0,"offset":-0.0}`은 `count: 0`과 `offset: -0.0`이 됩니다. [YAML 1.2](https://yaml.org/spec/1.2.2/#1032-tag-resolution)는 `-0`을 정수 0으로 읽고, `-0.0`은 음의 부동소수점 0으로 남습니다.
- **JSON → YAML에서는 모호한 문자열에 따옴표를 붙입니다**(`'1.10'`, `'yes'`, `'NO'` 등). 다시 읽어도 문자열로 남습니다.
