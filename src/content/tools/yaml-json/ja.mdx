<h2>YAMLとJSONの使い分け</h2>
<p>YAMLはDocker Compose、Kubernetes、GitHub Actions、Ansible、Helm Chartsなどの設定ファイルで広く使われています。JSONはREST API、Webブラウザ、プログラム間のデータ交換に適しています。両形式の変換が必要な場面で活用してください。</p>

## 型が変わる値

このツールは js-yaml 4.3.2 の既定のスキーマを使います。[YAML 1.2](https://yaml.org/spec/1.2.2/) の core schema に、タイムスタンプ、`<<` マージキー、`!!binary`・`!!set`・`!!omap`・`!!pairs` タグを加えたものです。次の入力はこう変換されます。

| YAML | JSON | 補足 |
|---|---|---|
| `country: NO` | `"NO"` | 文字列。PyYAML など YAML 1.1 のパーサーは `false` と読む |
| `enabled: yes` | `"yes"` | 同上。真偽値なら `true` と書く |
| `version: 1.10` | `1.1` | 数値として解析される。バージョン番号は引用符で囲む |
| `mode: 0755` | `755` | YAML 1.2 では先頭の 0 は 8 進数を意味しない。`0o755` と書く |
| `zip: 01234` | `1234` | 先頭の 0 が消える。この種のコードは引用符で囲む |
| `date: 2026-09-29` | `"2026-09-29T00:00:00.000Z"` | 日付は UTC のタイムスタンプになる |
| `at: 2026-10-01T09:30:00+09:00` | `"2026-10-01T00:30:00.000Z"` | オフセットは UTC に換算される。JSON に日付型はないので UTC の ISO 8601 文字列になる。時刻は同じだが、書かれていた `+09:00` は残らない |
| `zero: -0.0` | `-0.0` | 負のゼロは符号を保つ（`JSON.stringify` だけでは `0` になる） |
| `empty:` | `null` | 値のないキーは null |
| `roles: !!set {admin, editor}` | `{"admin":null,"editor":null}` | js-yaml はセットを値が null のマッピングとして読む |
| `steps: !!pairs [run: build, run: test]` | `[["run","build"],["run","test"]]` | pairs は [キー, 値] の配列になり、重複したキーも残る |
| `2026-01-01: New Year` | `{"2026-01-01":"New Year"}` | キーに使った日付は書いたとおりの文字列になる。JSON のキーは文字列 |

## 制限事項

- **変換できる文書は 1 つだけです。** `---` で区切られた入力は `expected a single document in the stream, but found more` というエラーになります。
- **JSON や YAML で表せない値があると変換しません。** YAML の `.inf`・`-.inf`・`.nan` と、どちらの方向でも ±(2^53 − 1) を超える整数は、変換で値が変わります（`JSON.stringify` は `null` と書き、`JSON.parse` と js-yaml は大きな整数を丸めます）。ステータス行に各フィールドを JSON Pointer で示します。次の YAML は

  ```yaml
  size: .inf
  id: 9007199254740993
  ```

  `変換していません：JSON では次の値を変えずに表せません：/size：inf は JSON で表せません（JSON.stringify は null と書きます）；/id：整数 9007199254740993 は ±(2^53 − 1) を超えるため、JavaScript では丸められます` になります。`1e400` のように倍精度の範囲を超える JSON の数値も同じように示します。大きな ID は引用符で囲んでください。変換できる入力になるまで、出力パネルは空になりコピーボタンは無効です。
- **存在しない日付とミリ秒より細かい時刻は変換しません。** js-yaml は `Date.UTC` で日付を作るため `2026-02-31` を 3 月 3 日に繰り越し、時刻はミリ秒までしか残しません。こうしたタイムスタンプがあると変換を止めます。次の YAML は

  ```yaml
  due: 2026-02-31
  at: 2026-10-01T09:30:00.123456Z
  ```

  `変換していません：JSON では次の値を変えずに表せません：/due：2026-02-31 は有効な日付・時刻ではありません；/at：2026-10-01T09:30:00.123456Z はミリ秒より細かい精度を持っています` になります。テキストとして扱いたい値は引用符で囲んでください（`due: "2026-02-31"`）。有効な日付・時刻は上の表のとおり UTC に変換します。
- **`!!binary` のデータも変換しません。** js-yaml はこれをバイト列として読みますが、JSON にはバイナリ型がありません（`JSON.stringify` はバイトの番号をキーにしたオブジェクトを書きます）。`photo: !!binary aGVsbG8=` は `変換していません：JSON では次の値を変えずに表せません：/photo：!!binary の値 — JSON にはバイナリ型がありません` になります。`!!binary` タグを外すと、Base64 のテキストが文字列として変換されます。
- **js-yaml の処理上限。** js-yaml 4.3.2 は、ネストが 100 階層を超える文書、マージキー（`<<`）で処理するマッピングとキーが合計 10,000 個を超える文書、1 つのマージキーに 100 個を超えるマッピングを並べた文書を止めます。例：`無効な YAML: コレクションのネストが 100 階層を超えています（js-yaml の既定の上限） (1:103)`。
- **重複したキーはエラーになります**（`duplicated mapping key`）。黙って上書きはしません。
- **コメントとアンカーは残りません。** アンカーと `<<` のマージキーは展開されて普通のコピーになります。
- **JSON の整数 `-0` は `0` になります。** `{"count":-0,"offset":-0.0}` は `count: 0` と `offset: -0.0` になります。[YAML 1.2](https://yaml.org/spec/1.2.2/#1032-tag-resolution) は `-0` を整数のゼロとして読み、`-0.0` は負の浮動小数点ゼロのままです。
- **JSON → YAML では曖昧な文字列を引用符で囲みます**（`'1.10'`、`'yes'`、`'NO'` など）。読み直しても文字列のままです。
