<h2>使い方</h2>
<ol>
  <li><strong>YAML → JSON</strong>：YAMLを入力欄に貼り付け、<strong>変換</strong>をクリックします。</li>
  <li><strong>JSON → YAML</strong>：JSONを入力欄に貼り付け、<strong>変換</strong>をクリックします。</li>
  <li>結果を<strong>コピー</strong>します。</li>
</ol>

<h2>YAMLとJSONの使い分け</h2>
<p>YAMLはDocker Compose、Kubernetes、GitHub Actions、Ansible、Helm Chartsなどの設定ファイルで広く使われています。JSONはREST API、Webブラウザ、プログラム間のデータ交換に適しています。両形式の変換が必要な場面で活用してください。</p>

## 型が変わる値

このツールは js-yaml 4.1 を使い、[YAML 1.2](https://yaml.org/spec/1.2.2/) の core schema とタイムスタンプに従います。次の入力はこう変換されます。

| YAML | JSON | 補足 |
|---|---|---|
| `country: NO` | `"NO"` | 文字列。PyYAML など YAML 1.1 のパーサーは `false` と読む |
| `enabled: yes` | `"yes"` | 同上。真偽値なら `true` と書く |
| `version: 1.10` | `1.1` | 数値として解析される。バージョン番号は引用符で囲む |
| `mode: 0755` | `755` | YAML 1.2 では先頭の 0 は 8 進数を意味しない。`0o755` と書く |
| `zip: 01234` | `1234` | 先頭の 0 が消える。この種のコードは引用符で囲む |
| `date: 2026-09-29` | `"2026-09-29T00:00:00.000Z"` | 日付は UTC のタイムスタンプになる |
| `empty:` | `null` | 値のないキーは null |

## 制限事項

- **変換できる文書は 1 つだけです。** `---` で区切られた入力は `expected a single document in the stream, but found more` というエラーになります。
- **重複したキーはエラーになります**（`duplicated mapping key`）。黙って上書きはしません。
- **コメントとアンカーは残りません。** アンカーと `<<` のマージキーは展開されて普通のコピーになります。
- **JSON → YAML では曖昧な文字列を引用符で囲みます**（`'1.10'`、`'yes'`、`'NO'` など）。読み直しても文字列のままです。
