<h2>实例：重置若依（RuoYi）的管理员密码</h2>

<p>若依前后端分离版（<a href="https://github.com/yangzongzhuan/RuoYi-Vue" target="_blank" rel="noopener">RuoYi-Vue</a>）用 Spring Security 的 <code>BCryptPasswordEncoder</code> 加密密码（<code>SecurityUtils.encryptPassword</code>）。初始化脚本 <code>sql/ry_20260417.sql</code> 里，admin 和 ry 两个账号的 <code>password</code> 字段都是下面这个值，README 写明演示账号是 admin / admin123。把它粘贴到「校验」页，输入 <code>admin123</code>，结果是「匹配」：</p>

{/* bcg-check: {"hash":"$2a$10$7JB720yubVSZvUI0rEqK/.VqGOZTH.ulu33dHOiBE8ByOhJIrdAu2","pw":"admin123","result":"match","notes":"lib_$2a$"} */}
```
$2a$10$7JB720yubVSZvUI0rEqK/.VqGOZTH.ulu33dHOiBE8ByOhJIrdAu2
```

<p>上线前要换掉这个默认密码时，在「生成」页输入新密码，前缀选 <code>$2a$</code>、成本选 10（和若依自己生成的一致），把结果写回数据库：</p>

```sql
UPDATE sys_user SET password = '把生成的哈希粘贴在这里' WHERE user_name = 'admin';
```

<p>改完再用「校验」页核对一次新密码和哈希，确认没有复制漏字符。</p>

<h2>实例：粘贴来的值不是标准格式</h2>

<p>从不同地方复制出来的哈希常常带着「外壳」。Spring Security 的 <code>DelegatingPasswordEncoder</code> 会在前面加 <code>{"{bcrypt}"}</code>；Spring Security 7.1.1 用 <code>PasswordEncoderFactories.createDelegatingPasswordEncoder()</code> 生成的一个值如下（密码 <code>Ruoyi@2026</code>），本页会去掉 <code>{"{bcrypt}"}</code> 再校验：</p>

{/* bcg-check: {"hash":"{bcrypt}$2a$10$Syj8x8XixpYEkWocxvjgbuqT3xOMxpG.utD30HGZwQBzRMIxVnroC","pw":"Ruoyi@2026","result":"match","notes":"spring,lib_$2a$"} */}
```
{bcrypt}$2a$10$Syj8x8XixpYEkWocxvjgbuqT3xOMxpG.utD30HGZwQBzRMIxVnroC
```

<p>同样会处理的还有：前后的引号和空格、htpasswd 行开头的 <code>用户名:</code>、Docker Compose 里写成 <code>$$</code> 的美元符号、Django 的 <code>bcrypt$</code> 与 <code>bcrypt_sha256$</code>（后者先对密码做 SHA-256）。哈希本身坏了时会指出位置，例如少了最后一个字符会提示「应有 60 个字符，这里只有 59 个」：</p>

{/* bcg-check: {"hash":"$2a$10$7JB720yubVSZvUI0rEqK/.VqGOZTH.ulu33dHOiBE8ByOhJIrdAu","error":"short@59"} */}
```
$2a$10$7JB720yubVSZvUI0rEqK/.VqGOZTH.ulu33dHOiBE8ByOhJIrdAu
```

<h2>选哪个前缀</h2>

<p>对 UTF-8 密码来说，<code>$2a$</code>、<code>$2b$</code>、<code>$2y$</code> 的算法相同：<code>$2y$</code> 标记修复 CVE-2011-2483 之后的 crypt_blowfish 结果，<code>$2b$</code> 是 OpenBSD 2014 年改用的标记，crypt_blowfish 1.3 对 <code>$2b$</code> 的处理与 <code>$2y$</code>「完全相同」（<a href="https://www.openwall.com/crypt/" target="_blank" rel="noopener">Openwall</a>）。真正的差别在于各个库认不认。2026-10-02 我们用同一批哈希逐个测试：</p>

{/* bcg-compat */}

| 库 | 版本 | $2a$ | $2b$ | $2y$ | 超过 72 字节时生成 | 默认写出 |
|---|---|---|---|---|---|---|
| PHP `password_verify` {/* php */} | 8.4.26 | ✓ | ✓ | ✓ | ✂ 截断 | `$2y$12$` |
| Laravel `Hash::check` {/* laravel */} | 13.34.0 | ⚠ 抛异常 | ⚠ 抛异常 | ✓ | ✂ 截断 | `$2y$12$` |
| Python `bcrypt` {/* python-bcrypt-5 */} | 5.0.0 | ✓ | ✓ | ✓ | ✗ 报错 | `$2b$12$` |
| Python `bcrypt` {/* python-bcrypt-4 */} | 4.2.0 | ✓ | ✓ | ✓ | ✂ 截断 | `$2b$12$` |
| Node.js `bcrypt` {/* node-bcrypt */} | 6.0.0 | ✓ | ✓ | ✗ false | ✂ 截断 | `$2b$10$` |
| Node.js `bcryptjs` {/* bcryptjs-3 */} | 3.0.3 | ✓ | ✓ | ✓ | ✂ 截断 | `$2b$10$` |
| Go `x/crypto/bcrypt` {/* go */} | 0.57.0 | ✓ | ✓ | ✓ | ✗ 报错 | `$2a$10$` |
| Spring Security {/* spring-7 */} | 7.1.1 | ✓ | ✓ | ✓ | ✗ 报错 | `$2a$10$` |
| Spring Security {/* spring-6 */} | 6.5.11 | ✓ | ✓ | ✓ | ✗ 报错 | `$2a$10$` |
| Symfony {/* symfony */} | 8.1.0 | ✓ | ✓ | ✓ | 先做 SHA-512 | `$2y$13$` |

<p>Laravel 的框架配置默认 <code>HASH_VERIFY</code> 为 true，PHP 的 <code>password_get_info()</code> 只把 <code>$2y$</code> 认作 bcrypt，所以 <code>$2a$</code>、<code>$2b$</code> 会抛 <code>This password does not use the Bcrypt algorithm.</code>。结论：给 PHP / Laravel 用 <code>$2y$</code>，给 Node.js 用 <code>$2b$</code>，Java、Go、Python 三种都行。只改前缀，哈希依然有效，「校验」页会直接列出另外两种写法。</p>

<h2>72 字节与中文密码</h2>

<p>bcrypt 最多读密码的前 72 个字节。UTF-8 里一个汉字通常占 3 个字节，所以 24 个汉字就到上限：</p>

{/* bcg-check: {"password":"我家的猫叫小橘子它今年三岁了最喜欢在阳台上晒太阳","bytes":72,"issues":""} */}
```
我家的猫叫小橘子它今年三岁了最喜欢在阳台上晒太阳
```

<p>这句正好 72 字节，再多一个字就不起作用。超过上限时各库的做法不同：PHP、Node.js bcrypt、bcryptjs 悄悄截断；Python bcrypt 5、Go、Spring Security 6.3 及以上直接报错（我们测到 6.2.8 仍截断）。本页会提示最后一个被计入的字，并在校验结果里注明「只比较了前 72 字节」。</p>

<h2>成本怎么选</h2>

<p>成本是 2 的指数：成本 12 做 2<sup>12</sup> = 4,096 轮密钥设置，比成本 11 慢一倍。<a href="https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html" target="_blank" rel="noopener">OWASP 密码存储速查表</a>要求至少 10，并把 bcrypt 定为「只在没有 Argon2 和 scrypt 的旧系统里使用」；新项目优先 Argon2id。本页显示的耗时是浏览器里 JavaScript 实现的速度，服务器上的原生库通常更快，最终以登录服务器上的实测为准。</p>

<h2>与其他在线工具的区别</h2>

<p>2026-10-02 用同一组输入测试了 cn.bing.com 搜「bcrypt 在线」排在前面的 xyutil.com 和 33tool.com：两者都在浏览器里计算，只生成 <code>$2a$</code>；73 字节的密码对比前 72 字节的哈希，两者都显示匹配且不提示；含 <code>!</code> 的哈希两者都只说「不匹配」，不指出格式错误。本页可选前缀，并说明不匹配的具体原因。</p>

<h2>限制</h2>

<ul>
  <li>计算用 bcryptjs 2.4.3。成本最高可选 31，但在浏览器里要算几天，可随时点「取消」。</li>
  <li><code>$2x$</code>（旧 crypt_blowfish 缺陷产生的哈希）只在密码全是 ASCII 时按 <code>$2a$</code> 校验。</li>
  <li>密码按输入的字符原样转成 UTF-8，不做 Unicode 规范化。</li>
  <li>只支持 bcrypt，Argon2、scrypt、SHA-crypt 等会被识别出名称但不校验。生成 Apache / Nginx 用的文件请用 <a href="/zh/tools/htpasswd-generator/">htpasswd 生成器</a>，生成随机密码请用<a href="/zh/tools/password-generator/">密码生成器</a>。</li>
</ul>
