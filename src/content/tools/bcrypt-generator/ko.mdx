<h2>예시: Spring Security의 {"{bcrypt}"} 저장값</h2>

<p>Spring Security 7.1.1의 <code>PasswordEncoderFactories.createDelegatingPasswordEncoder()</code>로 <code>우리집강아지2026</code>을 인코딩하면 다음 값이 나옵니다(2026-10-02 실행). 이 값을 그대로 붙여 넣으면 이 페이지는 앞의 <code>{"{bcrypt}"}</code>를 떼고 검증해 「일치」를 보여 줍니다.</p>

{/* bcg-check: {"hash":"{bcrypt}$2a$10$YNfXOCtLgUC6YN84nk7njuohGwEWGbk2NRKH27SD9weV1Hw3LxWz.","pw":"우리집강아지2026","result":"match","notes":"spring,lib_$2a$"} */}
```
{bcrypt}$2a$10$YNfXOCtLgUC6YN84nk7njuohGwEWGbk2NRKH27SD9weV1Hw3LxWz.
```

<p>반대로 이 페이지에서 만든 <code>$2a$</code> 해시를 <code>{"{bcrypt}"}</code> 없이 DB에 넣으면, <code>DelegatingPasswordEncoder</code>는 로그인할 때 <code>IllegalArgumentException: Given that there is no default password encoder configured, each password must have a password encoding prefix.</code>를 던집니다(6.5.11과 7.1.1에서 확인). <code>BCryptPasswordEncoder</code>를 직접 빈으로 등록한 프로젝트라면 접두사 없이 넣어야 합니다. 어느 쪽인지는 <code>SecurityConfig</code>의 <code>PasswordEncoder</code> 빈을 보면 알 수 있습니다.</p>

<h2>예시: 복사하다 망가진 해시</h2>

<p>로그나 메신저에서 복사한 해시는 끝이 잘리거나 다른 문자가 섞이기 쉽습니다. 이 페이지는 몇 번째 문자가 문제인지 알려 줍니다. 아래 값은 41번째 문자가 bcrypt 문자가 아닌 <code>!</code>입니다.</p>

{/* bcg-check: {"hash":"$2a$10$YNfXOCtLgUC6YN84nk7njuohGwEWGbk2N!KH27SD9weV1Hw3LxWz.","error":"char@41"} */}
```
$2a$10$YNfXOCtLgUC6YN84nk7njuohGwEWGbk2N!KH27SD9weV1Hw3LxWz.
```

<p>마지막 문자의 패딩 비트가 0이 아닌 해시도 따로 알려 줍니다. 이런 해시는 Python bcrypt가 「Invalid salt」를 내고 PHP·Node.js·Spring은 비밀번호가 맞아도 불일치로 판정하므로, 이 페이지는 정규 형식을 계산해 함께 보여 줍니다.</p>

<h2>접두사별 호환성</h2>

<p>UTF-8 비밀번호라면 <code>$2a$</code>, <code>$2b$</code>, <code>$2y$</code>는 같은 알고리즘입니다. <code>$2y$</code>는 crypt_blowfish가 8비트 문자 버그(CVE-2011-2483)를 고친 뒤의 표시, <code>$2b$</code>는 OpenBSD가 2014년에 바꾼 표시이고, crypt_blowfish 1.3은 <code>$2b$</code>를 <code>$2y$</code>와 「정확히 같게」 처리합니다(<a href="https://www.openwall.com/crypt/" target="_blank" rel="noopener">Openwall</a>). 차이는 라이브러리가 받아들이느냐이며, 2026-10-02에 같은 해시로 확인한 결과는 다음과 같습니다.</p>

{/* bcg-compat */}

| 라이브러리 | 버전 | $2a$ | $2b$ | $2y$ | 72바이트 초과 생성 | 기본 출력 |
|---|---|---|---|---|---|---|
| Spring Security {/* spring-7 */} | 7.1.1 | ✓ | ✓ | ✓ | ✗ 오류 | `$2a$10$` |
| Spring Security {/* spring-6 */} | 6.5.11 | ✓ | ✓ | ✓ | ✗ 오류 | `$2a$10$` |
| Go `x/crypto/bcrypt` {/* go */} | 0.57.0 | ✓ | ✓ | ✓ | ✗ 오류 | `$2a$10$` |
| Node.js `bcrypt` {/* node-bcrypt */} | 6.0.0 | ✓ | ✓ | ✗ false | ✂ 잘라 냄 | `$2b$10$` |
| Node.js `bcryptjs` {/* bcryptjs-3 */} | 3.0.3 | ✓ | ✓ | ✓ | ✂ 잘라 냄 | `$2b$10$` |
| Python `bcrypt` {/* python-bcrypt-5 */} | 5.0.0 | ✓ | ✓ | ✓ | ✗ 오류 | `$2b$12$` |
| Python `bcrypt` {/* python-bcrypt-4 */} | 4.2.0 | ✓ | ✓ | ✓ | ✂ 잘라 냄 | `$2b$12$` |
| PHP `password_verify` {/* php */} | 8.4.26 | ✓ | ✓ | ✓ | ✂ 잘라 냄 | `$2y$12$` |
| Laravel `Hash::check` {/* laravel */} | 13.34.0 | ⚠ 예외 | ⚠ 예외 | ✓ | ✂ 잘라 냄 | `$2y$12$` |
| Symfony {/* symfony */} | 8.1.0 | ✓ | ✓ | ✓ | SHA-512 먼저 | `$2y$13$` |

<p>Java·Go·Python은 셋 다 괜찮고, PHP 계열은 <code>$2y$</code>, Node.js는 <code>$2b$</code>를 쓰면 됩니다. 접두사만 바꿔도 해시는 그대로 유효하며, 「검증」 탭이 다른 두 형식을 바로 보여 줍니다.</p>

<h2>한글 비밀번호와 72바이트</h2>

<p>bcrypt는 비밀번호의 앞 72바이트만 읽습니다. 한글 음절은 UTF-8로 한 글자에 3바이트라 24자면 한도에 닿습니다. 아래 25자는 75바이트여서, 이 페이지는 「…고올해로다섯살이되었습니」 뒤는 무시된다고 경고합니다.</p>

{/* bcg-check: {"password":"우리집강아지이름은초코이고올해로다섯살이되었습니다","bytes":75,"issues":"over72","tail":"…고올해로다섯살이되었습니"} */}
```
우리집강아지이름은초코이고올해로다섯살이되었습니다
```

<p>마지막 「다」를 다른 글자로 바꿔도 결과는 「일치」입니다. 라이브러리마다 처리도 다릅니다. 우리가 확인한 Spring Security는 6.2.8까지는 잘라 내고, 6.3.10부터는 <code>encode()</code>에서 <code>password cannot be more than 72 bytes</code>를 던집니다. 그래서 오래된 버전에서 만든 긴 비밀번호의 해시는 6.3 이후에도 <code>matches()</code>로는 통과하지만, 같은 비밀번호로 다시 인코딩하려 하면 예외가 납니다.</p>

<h2>비용 정하기</h2>

<p>비용은 2의 지수입니다. 비용 12는 키 설정을 2<sup>12</sup> = 4,096번 반복하며 11보다 두 배 오래 걸립니다. <a href="https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html" target="_blank" rel="noopener">OWASP Password Storage Cheat Sheet</a>는 최소 10을 요구하고, bcrypt는 「Argon2와 scrypt를 쓸 수 없는 레거시 시스템에서만」 쓰라고 합니다. 새로 만드는 시스템이라면 Argon2id를 먼저 검토하세요. Spring Security에서는 <code>new BCryptPasswordEncoder(12)</code>처럼 생성자로 비용을 정합니다. 이 페이지의 소요 시간은 브라우저의 JavaScript 구현 기준이므로 서버에서 다시 재어 보세요.</p>

<h2>다른 도구와 다른 점</h2>

<p>2026-10-02에 Bing에서 「bcrypt 생성기」 상위에 나오는 Go Tools 한국어판을 같은 입력으로 시험했습니다. 계산은 브라우저의 Web Worker에서 하고 접두사도 고를 수 있지만, 73바이트 비밀번호를 앞 72바이트의 해시와 비교하자 경고 없이 「일치」였고, <code>!</code>가 들어간 해시에는 「검증할 bcrypt 해시를 입력하세요」라고만 나왔으며, <code>$2x$</code> 해시에서는 「생성 중…」에서 멈췄습니다. 같은 날 확인한 MiniWebtool 일본어판은 비밀번호를 폼으로 서버에 POST했습니다. 이 페이지는 통신하지 않고, 불일치의 원인을 구체적으로 알려 줍니다.</p>

<h2>제한</h2>

<ul>
  <li>계산은 bcryptjs 2.4.3으로 합니다. 비용 31까지 고를 수 있지만 브라우저에서는 며칠이 걸리므로 「취소」로 멈출 수 있습니다.</li>
  <li><code>$2x$</code>(옛 crypt_blowfish 버그로 만든 해시)는 비밀번호가 모두 ASCII일 때만 <code>$2a$</code>로 검증합니다.</li>
  <li>입력한 글자를 그대로 UTF-8로 바꾸며 유니코드 정규화는 하지 않습니다.</li>
  <li>bcrypt 전용입니다. Argon2·scrypt·SHA-crypt 등은 이름만 알려 주고 검증하지 않습니다. Apache·Nginx용 파일은 <a href="/ko/tools/htpasswd-generator/">htpasswd 생성기</a>, 무작위 비밀번호는 <a href="/ko/tools/password-generator/">비밀번호 생성기</a>로 만들 수 있습니다.</li>
</ul>
