<h2>Examples</h2>

<p><strong>A Spring Security value.</strong> The Spring Security reference (<a href="https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html" target="_blank" rel="noopener">Password Storage</a>) stores the password <code>password</code> like this. The <strong>Example</strong> button fills it in:</p>

{/* bcg-check: {"hash":"{bcrypt}$2a$10$dXJ3SW6G7P50lGmMkkmwe.20cQQubK3.HZWzG3YB1tlRy.fqvM/BG","pw":"password","result":"match","notes":"spring,lib_$2a$"} */}
```
{bcrypt}$2a$10$dXJ3SW6G7P50lGmMkkmwe.20cQQubK3.HZWzG3YB1tlRy.fqvM/BG
```

<p>The page strips the <code>{"{bcrypt}"}</code> id that <code>DelegatingPasswordEncoder</code> adds and reports a match.</p>

<p><strong>A PHP hash for a Node.js service.</strong> PHP 8.4 <code>password_hash("correct horse battery staple", PASSWORD_BCRYPT)</code> returned this on 2026-10-02:</p>

{/* bcg-check: {"hash":"$2y$12$wz5da1i8Rk.FgE0MhaU3Jev51XAHhPzMRebBW4kXVqBbDO8acchn2","pw":"correct horse battery staple","result":"match","notes":"lib_$2y$"} */}
```
$2y$12$wz5da1i8Rk.FgE0MhaU3Jev51XAHhPzMRebBW4kXVqBbDO8acchn2
```

<p>In the same test, <code>bcrypt.compareSync()</code> from the Node.js <code>bcrypt</code> package 6.0.0 returned <code>false</code> for every <code>$2y$</code> hash. The Check tab shows the hash with a <code>$2b$</code> prefix, <code>$2b$12$wz5da1i8Rk.FgE0MhaU3Jev51XAHhPzMRebBW4kXVqBbDO8acchn2</code>, which that package accepts.</p>

<p><strong>A Docker Compose label.</strong> Compose reads <code>$</code> as the start of a variable, so a literal dollar sign is written <code>$$</code> (<a href="https://docs.docker.com/reference/compose-file/interpolation/" target="_blank" rel="noopener">Compose interpolation</a>). A basic-auth user list copied from such a file looks like this:</p>

{/* bcg-check: {"hash":"admin:$$2y$$12$$SVhOQ29BkxG9DYgTkPXqMuE4ZzjTo93.uW11Jps7hP09jZzVT7LZq","pw":"ramen-daisuki-2026","result":"match","notes":"htpasswd,dollar,lib_$2y$"} */}
```
admin:$$2y$$12$$SVhOQ29BkxG9DYgTkPXqMuE4ZzjTo93.uW11Jps7hP09jZzVT7LZq
```

<p>The page takes the part after <code>admin:</code> and turns <code>$$</code> back into <code>$</code>.</p>

<p><strong>A damaged hash.</strong> A hash missing its last character is reported as 59 of 60 characters, and a character outside the bcrypt alphabet by its position, here character 41:</p>

{/* bcg-check: {"hash":"$2b$05$.vOjLibWYVoJlI08x8Bv.em8Qy7cOWg3j!TZvJxhB4iON3pFKvtu.","error":"char@41"} */}
```
$2b$05$.vOjLibWYVoJlI08x8Bv.em8Qy7cOWg3j!TZvJxhB4iON3pFKvtu.
```

<h2>Which prefix: $2a$, $2b$ or $2y$</h2>

<p>All three run the same algorithm on UTF-8 passwords. The labels mark bug fixes: <code>$2y$</code> marks hashes from crypt_blowfish after the 8-bit bug CVE-2011-2483 was fixed, and <code>$2b$</code> marks OpenBSD hashes after a 2014 password-length fix; crypt_blowfish 1.3 treats <code>$2b$</code> “exactly the same” as <code>$2y$</code> (<a href="https://www.openwall.com/crypt/" target="_blank" rel="noopener">Openwall crypt_blowfish</a>). What matters today is which label a library accepts; we ran the same hashes through each on 2026-10-02:</p>

{/* bcg-compat */}

| Library | Version | $2a$ | $2b$ | $2y$ | Hashing over 72 bytes | Writes |
|---|---|---|---|---|---|---|
| PHP `password_verify` {/* php */} | 8.4.26 | ✓ | ✓ | ✓ | ✂ cuts | `$2y$12$` |
| Laravel `Hash::check` {/* laravel */} | 13.34.0 | ⚠ throws | ⚠ throws | ✓ | ✂ cuts | `$2y$12$` |
| Symfony `NativePasswordHasher` {/* symfony */} | 8.1.0 | ✓ | ✓ | ✓ | SHA-512 first | `$2y$13$` |
| Python `bcrypt` {/* python-bcrypt-5 */} | 5.0.0 | ✓ | ✓ | ✓ | ✗ error | `$2b$12$` |
| Python `bcrypt` {/* python-bcrypt-4 */} | 4.2.0 | ✓ | ✓ | ✓ | ✂ cuts | `$2b$12$` |
| Node.js `bcrypt` {/* node-bcrypt */} | 6.0.0 | ✓ | ✓ | ✗ false | ✂ cuts | `$2b$10$` |
| Node.js `bcryptjs` {/* bcryptjs-3 */} | 3.0.3 | ✓ | ✓ | ✓ | ✂ cuts | `$2b$10$` |
| Go `x/crypto/bcrypt` {/* go */} | 0.57.0 | ✓ | ✓ | ✓ | ✗ error | `$2a$10$` |
| Spring Security {/* spring-7 */} | 7.1.1 | ✓ | ✓ | ✓ | ✗ error | `$2a$10$` |
| Spring Security {/* spring-6 */} | 6.5.11 | ✓ | ✓ | ✓ | ✗ error | `$2a$10$` |

<p>“✓” means the right password matched. Laravel throws <code>RuntimeException: This password does not use the Bcrypt algorithm.</code> because its framework config sets <code>HASH_VERIFY</code> to true and PHP's <code>password_get_info()</code> only names <code>$2y$</code> hashes “bcrypt” (<a href="https://laravel.com/docs/12.x/hashing#hash-algorithm-verification" target="_blank" rel="noopener">Laravel docs</a>). So write <code>$2y$</code> for PHP, <code>$2b$</code> for Node.js, and any of the three for Python, Go or Java. Changing only the prefix keeps a hash valid, which the Check tab does for you.</p>

<h2>The 72-byte limit</h2>

<p>bcrypt reads at most 72 bytes of the password. Bytes, not characters, count: an ASCII letter is one byte, most Chinese, Japanese and Korean characters three. A 24-character Chinese password already fills the limit. The libraries above split three ways: PHP, Node.js and bcryptjs cut silently, Python bcrypt 5, Go and Spring Security 6.3 or later refuse to hash, and Symfony hashes longer passwords with SHA-512 first. This sentence-long password shows the warning:</p>

{/* bcg-check: {"password":"my dog's name is Biscuit and he was born in Portland, Oregon in the spring of 2019","bytes":82,"issues":"over72","tail":"… in the spri"} */}
```
my dog's name is Biscuit and he was born in Portland, Oregon in the spring of 2019
```

<p>It is 82 bytes, so everything after “… in the spri” has no effect, and “…spring of 2020” checks as a match too. A NUL character is another trap: PHP's <code>password_hash()</code> refuses it and <code>password_verify()</code> stops reading at it, while this page, Python, Node.js, Go and Spring include it.</p>

<h2>Choosing the cost</h2>

<p>Cost is a base-2 exponent: cost 12 runs 2<sup>12</sup> = 4,096 rounds of key setup, twice the work of cost 11. OWASP asks for “a minimum of 10”. Defaults differ: PHP raised <code>password_hash()</code> from 10 to 12 in 8.4 (<a href="https://wiki.php.net/rfc/bcrypt_cost_2023" target="_blank" rel="noopener">RFC</a>), Laravel and Python use 12, Node.js bcrypt, Go and Spring use 10. The estimate here is for a JavaScript bcrypt in this browser; time the cost on the server that will check logins.</p>

<h2>When bcrypt is the wrong choice</h2>

<p>The <a href="https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html" target="_blank" rel="noopener">OWASP Password Storage Cheat Sheet</a> recommends Argon2id (19 MiB of memory, 2 iterations), then scrypt, and says bcrypt “should only be used for password storage in legacy systems where Argon2 and scrypt are not available”. If you need passwords over 72 bytes with bcrypt, it describes <code>bcrypt(base64(hmac-sha384(password, pepper)))</code> and calls plain <code>bcrypt(base64(sha512(password)))</code> “a dangerous practice”, because a leaked SHA-512 hash can then be tested directly. For API tokens a keyed <a href="/tools/hmac-generator/">HMAC</a> is the usual tool, and checksums belong in the <a href="/tools/hash-generator/">hash generator</a>.</p>

<h2>Limits</h2>

<ul>
  <li>The page uses bcryptjs 2.4.3. A cost of 31 is accepted but would take days in a browser; cancel a long run with <strong>Cancel</strong>.</li>
  <li><code>$2x$</code> hashes, made by the old crypt_blowfish bug, are checked as <code>$2a$</code> when the password is all ASCII; for other passwords the page says it cannot reproduce the bug.</li>
  <li>Passwords are hashed as UTF-8 without Unicode normalization, so the same text typed with another input method may differ in bytes.</li>
  <li>Only bcrypt is supported. Argon2, scrypt, SHA-crypt and phpass hashes are recognized and named, not checked. For Apache and Nginx files use the <a href="/tools/htpasswd-generator/">htpasswd generator</a>; for a random password use the <a href="/tools/password-generator/">password generator</a>.</li>
</ul>
