<h2>使い方</h2>

<ol>
  <li>「生成」タブでパスワードを入力します。入力欄の下に文字数と UTF-8 のバイト数が出て、72 バイトを超えると警告します。</li>
  <li>ハッシュを照合する側のライブラリーに合わせてプレフィックスを選び（下の表を参照）、コストを選びます。そのコストがこのブラウザーで何秒かかるかが表示されます。</li>
  <li>「ハッシュを生成」を押すと、プレフィックス・コスト・22 文字のソルト・31 文字のハッシュ値に分けて表示され、コピーできます。</li>
  <li>手元のハッシュを確かめるときは「検証」タブにハッシュを貼り付け、パスワードを入れて「パスワードを検証」を押します。結果は「一致」か「不一致」で、別のプレフィックスに変えた同じハッシュも表示します。</li>
</ol>

<h2>例：Node.js のユーザーを Laravel に移すと例外になる</h2>

<p>Node.js の <code>bcrypt</code> 6.0.0 で <code>sakura-2026</code> をハッシュ化すると <code>$2b$</code> で始まる値になります（2026-10-02 に作成）。これをそのまま Laravel 13 の users テーブルに入れて <code>Hash::check()</code> にかけると、<code>RuntimeException: This password does not use the Bcrypt algorithm.</code> が投げられました。</p>

{/* bcg-check: {"hash":"$2b$10$dr1dD/1ObGWVj9/VD5K4Levz1e6tjkJQ2IsrpOaXacIoYkknmfKoq","pw":"sakura-2026","result":"match","notes":"lib_$2b$"} */}
```
$2b$10$dr1dD/1ObGWVj9/VD5K4Levz1e6tjkJQ2IsrpOaXacIoYkknmfKoq
```

<p>原因は Laravel の「ハッシュアルゴリズムの検証」です。<code>HASH_VERIFY</code> が true（既定）のとき、PHP の <code>password_get_info()</code> が <code>bcrypt</code> と判定したハッシュしか受け付けず、この関数が bcrypt と認めるのは <code>$2y$</code> だけです（<a href="https://readouble.com/laravel/12.x/ja/hashing.html" target="_blank" rel="noopener">Laravel 12.x ハッシュ</a>）。このツールの「検証」タブは上の値を「一致」と判定したうえで、<code>$2y$10$dr1dD/1ObGWVj9/VD5K4Levz1e6tjkJQ2IsrpOaXacIoYkknmfKoq</code> を表示します。接頭辞を書き換えたこの値なら、同じ Laravel で <code>true</code> が返りました。<code>.env</code> に <code>HASH_VERIFY=false</code> を書く方法もありますが、アルゴリズムの取り違えを検出する仕組みを止めることになります。</p>

<p>逆向き、つまり Laravel の <code>Hash::make('sakura-2026')</code> が出力した次の値を Node.js の <code>bcrypt.compareSync()</code> に渡すと <code>false</code> になります。この場合は <code>$2b$</code> に書き換えます。</p>

{/* bcg-check: {"hash":"$2y$12$IFeiEsY7tOL6S.EkDs8m1.JTzRFijXd15g3jHqCEYshCcNuewc6kS","pw":"sakura-2026","result":"match","notes":"lib_$2y$"} */}
```
$2y$12$IFeiEsY7tOL6S.EkDs8m1.JTzRFijXd15g3jHqCEYshCcNuewc6kS
```

<h2>ライブラリーごとの受け付け方</h2>

<p>UTF-8 のパスワードなら <code>$2a$</code>・<code>$2b$</code>・<code>$2y$</code> は同じアルゴリズムです。<code>$2y$</code> は crypt_blowfish が 8 ビット文字のバグ（CVE-2011-2483）を直したあとの印、<code>$2b$</code> は OpenBSD が 2014 年に導入した印で、crypt_blowfish 1.3 は <code>$2b$</code> を <code>$2y$</code> と「まったく同じ」に扱います（<a href="https://www.openwall.com/crypt/" target="_blank" rel="noopener">Openwall</a>）。差が出るのは受け付けるかどうかで、2026-10-02 に同じハッシュを各ライブラリーで照合した結果は次のとおりです。</p>

{/* bcg-compat */}

| ライブラリー | バージョン | $2a$ | $2b$ | $2y$ | 72 バイト超の生成 | 出力 |
|---|---|---|---|---|---|---|
| Laravel `Hash::check` {/* laravel */} | 13.34.0 | ⚠ 例外 | ⚠ 例外 | ✓ | ✂ 切り捨て | `$2y$12$` |
| PHP `password_verify` {/* php */} | 8.4.26 | ✓ | ✓ | ✓ | ✂ 切り捨て | `$2y$12$` |
| Symfony {/* symfony */} | 8.1.0 | ✓ | ✓ | ✓ | 先に SHA-512 | `$2y$13$` |
| Node.js `bcrypt` {/* node-bcrypt */} | 6.0.0 | ✓ | ✓ | ✗ false | ✂ 切り捨て | `$2b$10$` |
| Node.js `bcryptjs` {/* bcryptjs-3 */} | 3.0.3 | ✓ | ✓ | ✓ | ✂ 切り捨て | `$2b$10$` |
| Python `bcrypt` {/* python-bcrypt-5 */} | 5.0.0 | ✓ | ✓ | ✓ | ✗ エラー | `$2b$12$` |
| Python `bcrypt` {/* python-bcrypt-4 */} | 4.2.0 | ✓ | ✓ | ✓ | ✂ 切り捨て | `$2b$12$` |
| Go `x/crypto/bcrypt` {/* go */} | 0.57.0 | ✓ | ✓ | ✓ | ✗ エラー | `$2a$10$` |
| Spring Security {/* spring-7 */} | 7.1.1 | ✓ | ✓ | ✓ | ✗ エラー | `$2a$10$` |
| Spring Security {/* spring-6 */} | 6.5.11 | ✓ | ✓ | ✓ | ✗ エラー | `$2a$10$` |

<p>PHP 系には <code>$2y$</code>、Node.js には <code>$2b$</code>、Python・Go・Java ならどれでも構いません。プレフィックスだけを変えてもハッシュは有効なままです。</p>

<h2>日本語パスワードと 72 バイト</h2>

<p>bcrypt が読むのはパスワードの先頭 72 バイトだけです。ひらがな・カタカナ・漢字は UTF-8 で 1 文字 3 バイトなので、24 文字で上限に達します。次の 25 文字は 75 バイトあり、このツールは「…富士山がとてもきれいだっ」より後ろは無視されると警告します。</p>

{/* bcg-check: {"password":"東京スカイツリーから見た富士山がとてもきれいだった","bytes":75,"issues":"over72","tail":"…富士山がとてもきれいだっ"} */}
```
東京スカイツリーから見た富士山がとてもきれいだった
```

<p>最後の「た」を「よ」に変えても照合結果は「一致」のままです。ライブラリーの扱いも分かれ、PHP・Laravel・Node.js は黙って切り捨て、Python bcrypt 5・Go・Spring Security 6.3 以降は生成を拒否します。全角英数字も 1 文字 3 バイトなので、IME が全角のまま入力したパスワードは見た目より早く上限に届き、半角で入れた同じ文字列とは別のパスワードになります。</p>

<h2>コストの決め方</h2>

<p>コストは 2 の指数で、コスト 12 は鍵の準備を 2<sup>12</sup> = 4,096 回繰り返し、11 の 2 倍の時間がかかります。<a href="https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html" target="_blank" rel="noopener">OWASP Password Storage Cheat Sheet</a> は 10 以上を求め、bcrypt は「Argon2 も scrypt も使えないレガシーシステムに限る」としています。新しく作るなら Argon2id が第一候補です。Laravel の既定値 12 は <code>.env</code> の <code>BCRYPT_ROUNDS</code> で変えられます。このページの所要時間はブラウザーの JavaScript 実装の値なので、最終的にはサーバーで測ってください。</p>

<h2>ほかのツールとの違い</h2>

<p>2026-10-02 に、Bing で「bcrypt ハッシュ 生成」の上位に出る MiniWebtool の日本語版を確かめたところ、パスワードはフォームでサーバーに POST されていました（リクエストに <code>password=correct horse battery staple</code> が含まれていました）。英語圏で上位の bcrypt-generator.com はブラウザー内で計算しますが、出力は <code>$2a$</code> だけで、73 バイトのパスワードと先頭 72 バイトのハッシュを警告なしに「一致」とし、<code>!</code> を含むハッシュも「不一致」とだけ表示しました。このページは通信せず、プレフィックスを選べ、不一致の理由を示します。</p>

<h2>制限</h2>

<ul>
  <li>計算には bcryptjs 2.4.3 を使います。コスト 31 も選べますが、ブラウザーでは数日かかります。「キャンセル」でいつでも止められます。</li>
  <li><code>$2x$</code>（旧 crypt_blowfish のバグで作られたハッシュ）は、パスワードがすべて ASCII のときだけ <code>$2a$</code> として照合します。</li>
  <li>入力した文字をそのまま UTF-8 にし、Unicode の正規化はしません。</li>
  <li>bcrypt 専用です。Argon2・scrypt・SHA-crypt などは名前を表示するだけで照合しません。Apache や Nginx 用のファイルは <a href="/ja/tools/htpasswd-generator/">htpasswd 生成ツール</a>、ランダムなパスワードは<a href="/ja/tools/password-generator/">パスワードジェネレーター</a>で作れます。</li>
</ul>
