## How to Use

1. Enter the **Username** and **Password**, or press **Random** for a 20-character password.
2. Choose a **Format**. The note below the button says which Apache and Nginx builds read it.
3. For bcrypt, pick the **cost**; for SHA-512 or SHA-256 crypt, the **rounds** (htpasswd default 5,000).
4. Press **Generate line** and copy the result into the htpasswd file as one line. The matching `htpasswd` command is shown under it.

Problems are listed before anything is hashed: a `:` in the username, a name that starts with `#`, spaces at either end, a password longer than bcrypt reads. **Several users at once** turns `user:password` lines into a file. **Check or edit an htpasswd file** tests a password against a line you already have, and adds, updates or removes a user the way `htpasswd -b` does.

## Which Format Your Server Reads

Apache's [Password Formats](https://httpd.apache.org/docs/2.4/misc/password_encryptions.html) page lists bcrypt (`$2y$`), APR1 MD5 (`$apr1$`), SHA-1 (`{SHA}`), CRYPT and plain text. The [htpasswd manual](https://httpd.apache.org/docs/2.4/programs/htpasswd.html) adds SHA-256 and SHA-512 crypt (`-2`, `-5`). Nginx's [auth_basic_user_file](https://nginx.org/en/docs/http/ngx_http_auth_basic_module.html) handles `$apr1$`, `{SHA}`, `{SSHA}` and `{PLAIN}` itself and hands everything else to the system `crypt()`. Apache does the same for anything except `$2a$`, `$2y$`, `$apr1$` and `{SHA}` (`apr_password_validate` in APR's `apr_passwd.c`).

So bcrypt in Nginx depends on the operating system. We loaded lines from this tool into real servers on 2026-10-01 and called `curl -u` against them:

| Format | Apache 2.4.68 (Debian 13) | Apache 2.4.67 (macOS htpasswd -v) | Nginx 1.29.8 (Debian 13, Alpine 3.23) |
|---|---|---|---|
| bcrypt `$2y$` / `$2a$` | yes | yes | yes |
| SHA-512 / SHA-256 crypt | yes | no | yes |
| APR1 `$apr1$` | yes | yes | yes |
| SHA-1 `{SHA}` | yes | yes | yes |
| CRYPT (DES) | yes | yes | yes |
| Plain text | no | no | no |
| `{PLAIN}` | no | no | yes |

The system `crypt()` decides the Nginx column on other systems: on CentOS 7.9 (glibc 2.17) and Ubuntu 18.04 it rejected all bcrypt hashes but accepted SHA-512 and SHA-256 crypt; Ubuntu 20.04, 22.04, 24.04, Debian 11 and AlmaLinux 9 accepted bcrypt. If a bcrypt line keeps failing on such a system while the password is right, switch to SHA-512 crypt.

## Checking and Editing an Existing File

Paste a file and every user line gets its format and a note. For this file:

```text
# staging
deploy:$2y$10$B5ZE66PBlA9fW9mqo.EoquP8tf/AH7r2EEtgXBIZ2ceg5y2fU/0ry
 ops:{SHA}QTP3Zyeatz4Ck0oFIxA2hCGcmlg=
deploy:$apr1$WCk.8Wc2$rEoqVyFbdWIWrm6GZy8dK.
qa:secret
```

- Line 3 starts with a space: Apache strips it and reads the user `ops`, Nginx reads ` ops`. It is also unsalted SHA-1.
- Line 4 repeats `deploy`. Apache (`mod_authn_file`) and Nginx stop at the first match, so line 2 is the one that counts.
- Line 5 is plain text, which Linux Apache and Nginx both reject.

**Add or update user** follows `htpasswd -b`: every line of that user is replaced where it stands, comments and blank lines stay, a new user goes to the end, and the file keeps its line endings. **Remove user** deletes every line of the user, like `htpasswd -D`. The textarea then holds the new file; copy or download it.

## Usernames and Passwords the Servers Read Differently

- **Colon.** The colon separates name and hash, and htpasswd exits with code 6 for a name that contains one. Several online generators simply write `a:b:$apr1$…`, which Apache reads as user `a`.
- **`#` at the start.** Apache and Nginx treat the line as a comment; the user can never log in.
- **Non-ASCII text.** Servers compare bytes. This tool hashes UTF-8, so a client has to send UTF-8 as well; `curl -u` from a UTF-8 terminal did, and both servers accepted a Japanese password.
- **Length.** bcrypt reads 72 bytes of the password, so a 25-character Chinese or Japanese password (75 bytes) is cut; the tool warns before hashing. CRYPT reads 8 bytes. htpasswd refuses passwords over 255 bytes.

## How It Differs from Other Online htpasswd Generators

Tested on 2026-10-01 in desktop Chromium, recording the page's network requests:

- **web2generators.com** (first on Bing for "htpasswd generator") sends the username and password to its server in a POST request and returns an APR1 line. For the username `a:b` it returns `a:b:$apr1$…`.
- **htpasswd.utils.com** hashes in the browser and its bcrypt, APR1 and SHA-1 output verified with htpasswd. It also writes `a:b:…` for `a:b`, and offers `{SHA256}` and `{SHA512}` options that neither Apache 2.4 nor Nginx 1.29 accepted when we tried them.

None of the generators we tested checks a password against an existing line. This one does, flags the lines Apache and Nginx read differently, and lists which servers read each format.

## Limits

- Formats are the seven that Apache's htpasswd writes, plus `$2a$` and `{PLAIN}`. Checking also reads `$1$` MD5 crypt and `{SSHA}`; yescrypt (`$y$`), scrypt and `$2x$` are recognised but cannot be checked in the browser.
- bcrypt cost is 4–17 (the APR limit); SHA-2 rounds are 1,000–1,000,000 here. At cost 17 bcrypt takes many seconds in a browser.
- The file editor works on text; it does not write to your server.
- Digest authentication files (`htdigest`) use another format and are not supported.
