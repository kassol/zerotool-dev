## レンタルサーバーで Basic 認証を掛ける

Apache のサーバーなら、公開ディレクトリに次の `.htaccess` を置き、生成した行を書いた `.htpasswd` を指定します。`AuthUserFile` はサーバー上の絶対パスで書きます。

```apache
AuthType Basic
AuthName "Staging"
AuthUserFile /home/example/.htpasswd
Require valid-user
```

`.htpasswd` はブラウザから取得できない場所に置きます。[htpasswd のマニュアル](https://httpd.apache.org/docs/2.4/programs/htpasswd.html) にも、パスワードファイルを Web サーバーの URI 空間に置かないようにと書かれています。

ユーザー `staging`、パスワード `Sakura-2026` で生成した例です（ソルトはランダムなので、実際の結果は毎回変わります）。

{/* htpw-check: {"line": "staging:$2y$10$8AntxzBrzybDEh8RYEl9SeY.6kqHt4ywkI7TqIKJdB/jvcjypDxmG", "password": "Sakura-2026"} */}
{/* htpw-check: {"line": "staging:$6$yYcQBn5mlXKhcSLx$bc5EQxE5nTj.DZSc7PSfzZdkSKCG6kJDK5gCylmUSt1BO8Cw/zvPZU58KvVdoHrkvz7yIvFDQAKG6h7WfsiTD/", "password": "Sakura-2026"} */}

```text
staging:$2y$10$8AntxzBrzybDEh8RYEl9SeY.6kqHt4ywkI7TqIKJdB/jvcjypDxmG
staging:$6$yYcQBn5mlXKhcSLx$bc5EQxE5nTj.DZSc7PSfzZdkSKCG6kJDK5gCylmUSt1BO8Cw/zvPZU58KvVdoHrkvz7yIvFDQAKG6h7WfsiTD/
```

どちらも Apache 付属の `htpasswd -vb .htpasswd staging Sakura-2026` で `Password for user staging correct.` と表示されました（SHA-512 の行は `httpd:2.4` コンテナー内の htpasswd で確認。macOS の htpasswd は SHA-2 crypt を作れないため）。

## 形式と対応サーバー

Apache の [Password Formats](https://httpd.apache.org/docs/2.4/misc/password_encryptions.html) が挙げるのは bcrypt（`$2y$`）、APR1 MD5（`$apr1$`）、SHA-1（`{SHA}`）、CRYPT、平文の 5 つで、htpasswd は SHA-256 / SHA-512 crypt（`-2`、`-5`）も作れます。[Nginx の auth_basic_user_file](https://nginx.org/en/docs/http/ngx_http_auth_basic_module.html) は `$apr1$`、`{SHA}`、`{SSHA}`、`{PLAIN}` を自分で処理し、それ以外は OS の `crypt()` に渡します。

このツールで作った行を Nginx 1.29.8（Debian 13 と Alpine 3.23 のイメージ）と Apache 2.4.68 に読ませ、2026-10-01 に `curl -u` でログインを試した結果です。

| 形式 | Apache 2.4.68（Linux） | Nginx 1.29.8 |
|---|---|---|
| bcrypt `$2y$` / `$2a$` | 可 | 可（OS の crypt() 次第） |
| SHA-512 / SHA-256 crypt | 可（macOS・Windows は不可） | 可 |
| APR1 `$apr1$` | 可 | 可 |
| SHA-1 `{SHA}`・CRYPT | 可（安全でない） | 可（安全でない） |
| 平文 | 不可（Windows・NetWare のみ） | 不可 |
| `{PLAIN}` | 不可 | 可 |

「OS の crypt() 次第」の部分は、Docker イメージで確かめました。Ubuntu 18.04 と CentOS 7.9 の `crypt()` は bcrypt を受け付けず、Ubuntu 20.04 以降、Debian 11 以降、AlmaLinux 9 は受け付けました。SHA-512 crypt はどれでも通りました。古い VPS の Nginx に Basic 認証を掛けるなら SHA-512 crypt を選ぶのが確実です。

## 全角文字が混ざったとき

IME がオンのまま入力すると、パスワードに全角文字が入ります。ツールは UTF-8 でハッシュ化し、「UTF-8 の 21 バイトとしてハッシュ化します」のように表示します。

{/* htpw-check: {"line": "staging:$2y$10$aGvQqvoclFaLSOzptcNXjup6OTrhv6cP19/GrZ9V4ikE/Xy.muPRK", "password": "さくら２０２６"} */}
{/* htpw-check: {"line": "staging:$2y$10$aGvQqvoclFaLSOzptcNXjup6OTrhv6cP19/GrZ9V4ikE/Xy.muPRK", "password": "さくら2026", "ok": false} */}
{/* htpw-check: {"passwordCheck": "さくら２０２６", "format": "bcrypt-2y", "codes": "info:passNonAscii", "bytes": 21} */}

```text
staging:$2y$10$aGvQqvoclFaLSOzptcNXjup6OTrhv6cP19/GrZ9V4ikE/Xy.muPRK
```

この行は `さくら２０２６`（全角数字）から作ったもので、ブラウザのログイン画面で半角の `さくら2026` を入れても通りません。**htpasswd ファイルの確認・編集** にこの行を貼り、パスワード欄に両方を順に入れて **パスワードを照合** すると、一致・不一致がすぐに分かります。bcrypt が読むのは先頭 72 バイトまでで、ひらがな・漢字は 1 文字 3 バイトなので、25 文字以上になるとツールが警告します。

## 既存の .htpasswd を確認する

貼り付けたファイルは 1 行ずつ形式と注意点を表示します。実際のサーバーで確かめた、読み方が分かれる例です。

- 同じユーザーが 2 行あるとき、Apache も Nginx も最初の行だけを使います。後ろの行を書き換えても効きません。
- 行頭に空白があると、Apache は空白を取り除いたユーザー名で、Nginx は空白付きで読みます。
- ハッシュの後ろに空白があると、Apache は取り除き、Nginx は比較に含めるため毎回ログインに失敗します。
- 「#」で始まる行はどちらもコメントとして扱います。

**ユーザーを追加・更新** は `htpasswd -b` と同じく、同名の行をその場で置き換え、コメントと空行を残し、新しいユーザーを末尾に足します。改行コード（LF / CRLF）も元のままです。**ユーザーを削除** は `htpasswd -D` と同じく、そのユーザーの行をすべて消します。

## 他のオンライン生成ツールとの違い

2026-10-01 にデスクトップ版 Chromium で試し、ページの通信を記録しました。

- **株式会社ルフト「htpasswdファイル生成(作成)」**（Bing で「htpasswd 生成」1 位）は、ID とパスワードをフォームでサーバーに POST し、サーバー側で作った bcrypt `$2y$10$` の行を返します。日本語のパスワードでは「半角英数記号を入れてください。」と表示して生成せず、ID に `a:b` を入れると `a:b:$2y$10$…` を返しました。
- **web2generators.com**（英語の検索 1 位）もユーザー名とパスワードをサーバーに POST し、出力は MD5 だけです。

このツールはブラウザの中だけで計算し、既存の行でパスワードを照合でき、Apache と Nginx で読み方が分かれる行を指摘します。

## 制限

- 生成できるのは Apache の htpasswd が作る 7 形式と `$2a$`、`{PLAIN}` です。照合では `$1$`（MD5 crypt）と `{SSHA}` も読めます。yescrypt（`$y$`）、scrypt、`$2x$` は判別だけで、照合はできません。
- bcrypt のコストは 4〜17（APR の上限）、SHA-2 のラウンド数はこのツールでは 1000〜1000000 です。コスト 17 はブラウザで数秒以上かかります。
- ファイル編集はテキスト上の操作で、サーバーには書き込みません。
- Digest 認証用の `htdigest` ファイルは形式が違うため扱いません。
