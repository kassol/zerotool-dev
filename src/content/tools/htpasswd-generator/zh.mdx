## 先确认服务器能读哪种格式

Apache 的 [Password Formats](https://httpd.apache.org/docs/2.4/misc/password_encryptions.html) 列出 bcrypt（`$2y$`）、APR1 MD5（`$apr1$`）、SHA-1（`{SHA}`）、CRYPT 和明文，[htpasswd 手册](https://httpd.apache.org/docs/2.4/programs/htpasswd.html) 另有 SHA-256、SHA-512 crypt（`-2`、`-5`）。[Nginx 的 auth_basic_user_file](https://nginx.org/en/docs/http/ngx_http_auth_basic_module.html) 自己处理 `$apr1$`、`{SHA}`、`{SSHA}`、`{PLAIN}`，其余交给系统 `crypt()`；Apache 除 `$2a$`、`$2y$`、`$apr1$`、`{SHA}` 外同样交给 `crypt()`（APR `apr_passwd.c` 的 `apr_password_validate`）。

所以 Nginx 能不能用 bcrypt 取决于操作系统。2026-10-01 我们用 Docker 镜像里的系统 `crypt()` 逐一验证：

| 系统 | bcrypt `$2y$` | SHA-512 / SHA-256 crypt | CRYPT |
|---|---|---|---|
| CentOS 7.9（glibc 2.17） | 不支持 | 支持 | 支持 |
| Ubuntu 18.04 | 不支持 | 支持 | 支持 |
| Ubuntu 20.04 / 22.04 / 24.04 | 支持 | 支持 | 支持 |
| Debian 11 / 12 / 13 | 支持 | 支持 | 支持 |
| AlmaLinux 9.8 | 支持 | 支持 | 支持 |

再把本工具生成的行放进 Nginx 1.29.8（Debian 13 与 Alpine 3.23 镜像）和 Apache 2.4.68，用 `curl -u` 登录：bcrypt、SHA-512、SHA-256、APR1、SHA-1、CRYPT 全部通过；无前缀的明文两边都失败，`{PLAIN}` 只有 Nginx 接受。国内不少服务器还在跑 CentOS 7，在这类机器上给 Nginx 配 Basic 认证，选 **SHA-512 crypt** 最稳妥：轮数可调，又不依赖系统的 bcrypt 支持。

## 示例：同一个密码的三种写法

用户 `admin`，密码 `春眠不觉晓-2026`（盐是随机的，你生成的结果会不同）：

{/* htpw-check: {"line": "admin:$6$c/1gv6vIDsCOui.D$x6wo6Gy9VzP7dl8C1I8ww19k3JPp4wVtCfcGgQh7PaB/J8wmiMajLV8c9Eyu8rrLadpr.fhNXIrpidWD4Xtx10", "password": "春眠不觉晓-2026"} */}
{/* htpw-check: {"line": "admin:$apr1$XZpeiq1G$KCu7/cf7Tz6ysV42CPgYZ1", "password": "春眠不觉晓-2026"} */}
{/* htpw-check: {"passwordCheck": "春眠不觉晓-2026", "format": "bcrypt-2y", "codes": "info:passNonAscii", "bytes": 20} */}

```text
admin:$2y$10$3LD7z4FEQ30ifzeHhZ87EOQCSf5leTn8lq.xcZedcGbgPvlZ7G1oe
admin:$6$c/1gv6vIDsCOui.D$x6wo6Gy9VzP7dl8C1I8ww19k3JPp4wVtCfcGgQh7PaB/J8wmiMajLV8c9Eyu8rrLadpr.fhNXIrpidWD4Xtx10
admin:$apr1$XZpeiq1G$KCu7/cf7Tz6ysV42CPgYZ1
```

三行都通过 Apache 的 `htpasswd -vb 文件 admin 春眠不觉晓-2026` 校验（输出 `Password for user admin correct.`）；SHA-512 那一行在 `httpd:2.4` 容器里校验，因为 macOS 的 htpasswd 不支持 SHA-2 crypt。这个密码含 5 个汉字，按 UTF-8 共 20 字节，工具会提示「按 UTF-8 的 20 字节哈希」。

再换一个 30 个汉字的长密码选 bcrypt，工具会提示：

{/* htpw-check: {"passwordCheck": "白日依山尽黄河入海流欲穷千里目更上一层楼春眠不觉晓处处闻啼", "format": "bcrypt-2y", "codes": "info:passNonAscii,warn:bcrypt72"} */}

> bcrypt 只取前 72 字节；这个密码有 90 字节，后面的部分不起作用。

也就是说，只要前 24 个汉字相同，后面写什么都能登录。需要长中文口令时改用 SHA-512 crypt，它没有这个限制。

## 检查已有文件

把文件粘贴进 **检查或编辑 htpasswd 文件**，每个用户行都会标出格式和提示，例如：

```text
# 测试环境
admin:$2y$10$3LD7z4FEQ30ifzeHhZ87EOQCSf5leTn8lq.xcZedcGbgPvlZ7G1oe
admin:$apr1$XZpeiq1G$KCu7/cf7Tz6ysV42CPgYZ1
test:$apr1$XZpeiq1G$KCu7/cf7Tz6ysV42CPgYZ1  
```

- 第 3 行与第 2 行同名。实测 Apache 和 Nginx 都只用第一条匹配的行，第 3 行改了也不生效。
- 第 4 行哈希后面有两个空格：Apache 读行时去掉，Nginx 把空格算进哈希，每次登录都失败。

填好用户名、密码后点 **验证密码**，会告诉你密码与哪一行匹配；**增加或更新用户** 与 `htpasswd -b` 一致：同名的每一行原地替换，注释和空行保留，新用户追加到末尾，换行符（LF 或 CRLF）不变；**删除用户** 与 `htpasswd -D` 一致，删掉该用户的所有行。处理后的内容直接写回文本框，可复制或下载。

## 用户名的几个坑

- 用户名不能含 `:`：冒号是用户名和哈希的分隔符，htpasswd 遇到这种名字直接退出（退出码 6）。不少在线生成器照样输出 `a:b:$apr1$…`，Apache 会把它读成用户 `a`。
- 以 `#` 开头的行在 Apache 和 Nginx 里都是注释，这个用户永远登录不了。
- 首尾空格：Apache 会去掉行首空格，Nginx 不会，两边看到的用户名不一样。
- 中文用户名可以用，但服务器按字节比较，客户端必须按 UTF-8 发送。

## 与其他在线 htpasswd 生成器的区别

2026-10-01 用桌面版 Chromium 实测，并记录页面发出的网络请求：

- **在线工具大全 lddgo.net**（cn.bing.com 搜「htpasswd 在线生成」第一）点击生成时，把用户名、密码和算法以 JSON 发到 `/api/Htpasswd`，在服务器端计算。用户名填 `a:b` 照样输出 `a:b:$apr1$…`。
- **web2generators.com**（Bing 英文结果第一）同样把用户名和密码 POST 到自己的服务器，只有 MD5。

本工具只在浏览器里计算；能用已有的行验证密码，能指出 Apache 与 Nginx 读法不同的行，并写明每种格式哪些服务器能读。

## 限制

- 生成的格式是 Apache htpasswd 能写的 7 种，加上 `$2a$` 和 `{PLAIN}`。验证时另外支持 `$1$` MD5 crypt 和 `{SSHA}`；yescrypt（`$y$`）、scrypt、`$2x$` 只能识别，不能在浏览器里验证。
- bcrypt 强度 4–17（APR 的上限），SHA-2 轮数这里限 1000–1000000。强度 17 在浏览器里要算很多秒。
- 文件编辑只处理文本，不会写到服务器上。
- Digest 认证的 `htdigest` 文件是另一种格式，不支持。
