## 사용 방법

1. **사용자 이름**과 **비밀번호**를 입력합니다. **무작위**를 누르면 20자 비밀번호를 만듭니다.
2. **형식**을 고릅니다. 버튼 아래에 그 형식을 읽는 Apache·Nginx가 표시됩니다.
3. bcrypt는 **비용**, SHA-512·SHA-256 crypt는 **라운드 수**(htpasswd 기본 5000)를 정합니다.
4. **생성**을 누르고 결과를 htpasswd 파일에 한 줄로 붙여 넣습니다. 같은 형식을 만드는 `htpasswd` 명령도 함께 보여 주므로 서버에서 다시 만들 수도 있습니다.

해시하기 전에 사용자 이름의 `:`, 맨 앞의 `#`, 앞뒤 공백, bcrypt가 다 읽지 못하는 긴 비밀번호를 먼저 알려 줍니다. **여러 사용자 한 번에 생성**은 `user:password` 여러 줄을 파일로 만들고, **htpasswd 파일 확인·편집**은 가진 줄로 비밀번호를 확인하고 `htpasswd -b`와 같은 규칙으로 사용자를 추가·변경·삭제합니다.

## Ubuntu 서버의 Nginx에 Basic 인증 걸기

Nginx 설정은 다음과 같습니다.

```nginx
location /admin/ {
    auth_basic           "Restricted";
    auth_basic_user_file /etc/nginx/.htpasswd;
}
```

[Nginx 문서](https://nginx.org/en/docs/http/ngx_http_auth_basic_module.html)에 따르면 Nginx는 `$apr1$`, `{SHA}`, `{SSHA}`, `{PLAIN}`만 직접 처리하고 나머지는 운영체제의 `crypt()`에 넘깁니다. 그래서 bcrypt가 되는지는 배포판에 달려 있습니다. 2026-10-01 Docker 이미지의 시스템 `crypt()`로 확인한 결과입니다.

| 배포판 | bcrypt | SHA-512·SHA-256 crypt |
|---|---|---|
| Ubuntu 18.04 | 안 됨 | 됨 |
| Ubuntu 20.04 / 22.04 / 24.04 | 됨 | 됨 |
| Debian 11 / 12 / 13 | 됨 | 됨 |
| CentOS 7.9 (glibc 2.17) | 안 됨 | 됨 |
| AlmaLinux 9.8 | 됨 | 됨 |

아직 Ubuntu 18.04를 쓰는 서버라면 bcrypt 줄은 비밀번호가 맞아도 통과하지 않습니다. 이때는 **SHA-512 crypt**를 고르세요. 이 도구로 만든 줄을 실제 Nginx 1.29.8(Debian 13, Alpine 3.23 이미지)과 Apache 2.4.68에 넣고 `curl -u`로 로그인한 결과, bcrypt·SHA-512·SHA-256·APR1·SHA-1·CRYPT는 모두 통과했고, 접두사 없는 평문은 둘 다 실패했으며 `{PLAIN}`은 Nginx만 받았습니다.

## 예시: 한글이 들어간 비밀번호

사용자 `dev`, 비밀번호 `비밀번호-2026`으로 만든 줄입니다(솔트가 무작위라 직접 만든 결과는 다릅니다).


세 줄 모두 Apache htpasswd의 `htpasswd -vb .htpasswd dev 비밀번호-2026`에서 `Password for user dev correct.`가 나왔습니다(SHA-512 줄은 `httpd:2.4` 컨테이너 안의 htpasswd로 확인. macOS htpasswd는 SHA-2 crypt를 지원하지 않습니다). 한글 4자는 UTF-8로 12바이트라 이 비밀번호는 17바이트이고, 도구는 "UTF-8 17바이트로 해시합니다"라고 표시합니다. 서버는 바이트를 비교하므로, 다른 인코딩(EUC-KR 등)으로 보내는 클라이언트에서는 맞는 비밀번호도 실패합니다.

## 형식별 정리

- **bcrypt `$2y$`**: Apache htpasswd `-B`와 같은 출력. Apache 2.4는 모든 플랫폼에서, Nginx는 위 표처럼 OS에 따라 읽습니다. 비용 4~17.
- **SHA-512 / SHA-256 crypt**: htpasswd `-5`, `-2`와 같은 출력. Linux의 Apache와 Nginx는 읽지만 macOS·Windows의 Apache는 못 읽습니다.
- **APR1 `$apr1$`**: htpasswd 기본값. Apache와 Nginx가 직접 구현해 어디서나 동작하지만, 1000회 고정 MD5이고 비용 설정이 없습니다.
- **SHA-1 `{SHA}`, CRYPT, 평문**: [Apache 문서](https://httpd.apache.org/docs/2.4/misc/password_encryptions.html)가 안전하지 않다고 적는 형식입니다. CRYPT는 앞 8자만, 평문은 Windows·NetWare의 Apache에서만 쓰입니다.

## 기존 파일 확인과 편집

파일을 붙여 넣으면 줄마다 형식과 주의점을 보여 줍니다. 실제 서버에서 확인한, 두 서버가 다르게 읽는 경우입니다.

- 같은 사용자가 두 줄이면 Apache와 Nginx 모두 첫 줄만 씁니다.
- 줄 앞에 공백이 있으면 Apache는 공백을 지운 이름으로, Nginx는 공백 포함 이름으로 읽습니다.
- 해시 뒤에 공백이 있으면 Apache는 지우고 Nginx는 비교에 포함해 매번 로그인이 실패합니다.
- 사용자 이름에 `:`가 있으면 htpasswd는 종료 코드 6으로 거부합니다. 이 도구도 생성하지 않습니다.

**사용자 추가·변경**은 `htpasswd -b`처럼 같은 이름의 줄을 제자리에서 바꾸고, 주석과 빈 줄을 그대로 두고, 새 사용자는 끝에 붙입니다. 줄바꿈 방식(LF·CRLF)도 유지합니다. **사용자 삭제**는 `htpasswd -D`처럼 그 사용자의 줄을 모두 지웁니다.

## 다른 온라인 생성기와의 차이

2026-10-01 데스크톱 Chromium에서 페이지의 네트워크 요청을 기록하며 시험했습니다.

- **다이나믹랩스 htpasswd 생성기**(Bing "htpasswd 생성" 1위)는 브라우저 안에서 계산하고, 콜론이나 공백이 든 사용자 이름을 막습니다. 다만 형식은 `{SHA}`와 `{SHA256}` 두 가지뿐이고, 페이지에 bcrypt는 "브라우저에서는 생성 불가"라고 적혀 있습니다. `{SHA256}` 줄은 Apache 2.4.68과 Nginx 1.29.8 모두에서 로그인이 실패했습니다.
- **web2generators.com**(영어 검색 1위)은 사용자 이름과 비밀번호를 자기 서버로 POST하고 MD5만 만듭니다.

이 도구는 브라우저에서 bcrypt와 SHA-512 crypt를 만들고, 기존 줄로 비밀번호를 확인하며, 두 서버가 다르게 읽는 줄을 짚어 줍니다.

## 제한 사항

- 생성 형식은 Apache htpasswd가 만드는 7가지와 `$2a$`, `{PLAIN}`입니다. 확인할 때는 `$1$`(MD5 crypt)와 `{SSHA}`도 읽습니다. yescrypt(`$y$`), scrypt, `$2x$`는 알아보기만 하고 확인하지 못합니다.
- bcrypt 비용은 4~17(APR 상한), SHA-2 라운드 수는 이 도구에서 1000~1000000입니다. 비용 17은 브라우저에서 몇 초 이상 걸립니다.
- 파일 편집은 텍스트에만 적용되며 서버에 쓰지 않습니다.
- Digest 인증용 `htdigest` 파일은 형식이 달라 지원하지 않습니다.
