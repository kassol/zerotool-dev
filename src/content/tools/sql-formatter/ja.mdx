<h2>SQLフォーマットについて</h2>
<p>整形されたSQLは読みやすく、コードレビューやデバッグが容易になります。また、ORMが生成した圧縮されたSQLを読む際に整形ツールは非常に役立ちます。一方、ログやAPIパラメータとして渡す場合は圧縮形式が適しています。</p>

## 整形の例

整形前：

```sql
select u.id, u.name, o.total from users u join orders o on u.id = o.user_id where o.total > 100 and u.active = 1 order by o.total desc limit 10;
```

整形後（既定の設定）：

```sql
SELECT
  u.id,
  u.name,
  o.total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.total > 100
  AND u.active = 1
ORDER BY o.total DESC
LIMIT 10;
```

## サブクエリの例

既定の設定（2 スペースインデント、キーワード大文字）での実際の出力です。括弧内のサブクエリは 1 段深くインデントされます。

```sql
select * from users where id in (select user_id from orders where total > 100);
```

```sql
SELECT
  *
FROM users
WHERE id IN (
  SELECT
    user_id
  FROM orders
  WHERE total > 100
);
```

## CTE の例

`WITH ... AS (...)` の中身はサブクエリと同じようにインデントされます。`SUM(total)` のような関数呼び出しは 1 行に収まり、`ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` のようなウィンドウ関数も同様です。

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## 制限事項

- **方言は汎用の 1 種類のみで、構文チェックはしません。** MySQL・PostgreSQL・SQL Server などのモードはなく、誤った SQL もエラーなしで整形されます。
- **`CASE` は 1 行のままです。** `CASE WHEN ... THEN ... END` は `WHEN` ごとに改行されません。
- **圧縮するとコメントが消え**、閉じ括弧の後の空白もなくなります（例：`SELECT COUNT(*)FROM events`）。
