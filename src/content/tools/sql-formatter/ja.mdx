## 日本語のカラム名は引用符で囲む

PostgreSQL のマニュアルは、引用符なしの識別子にラテン文字以外の文字（non-Latin letters）も使えると説明しています（[PostgreSQL: Lexical Structure](https://www.postgresql.org/docs/current/sql-syntax-lexical.html)）。そのため `社員番号` のような名前は、引用符なしでもそのまま実行できます。このツールのトークナイザーは ASCII の英字・数字・`_`・`$` だけを名前として読むので、日本語の部分は1文字ずつ区切られます。

{/* sqlf-check: {"op":"format"} */}
```sql
select 社員番号, 氏名 from 社員 where 部署 = '営業部';
```

```sql
SELECT
  社 員 番 号,
  氏 名
FROM 社 員
WHERE 部 署 = '営業部';
```

文字列 `'営業部'` はそのままですが、名前が区切られたので、もう同じ SQL ではありません。SQLite 3.49.1（sql.js）で試すと、{/* sqlf-sqlite: {"sql":"select 社員番号, 氏名 from 社員 where 部署 = '営業部';"} */}元の文は実行でき、{/* sqlf-sqlite: {"sql":"SELECT\n  社 員 番 号,\n  氏 名\nFROM 社 員\nWHERE 部 署 = '営業部';","error":"near \"番\": syntax error"} */}整形後の文は `near "番": syntax error` で止まります。名前を二重引用符で囲めば、ひとまとまりのまま整形されます。

{/* sqlf-check: {"op":"format"} */}
```sql
select "社員番号", "氏名" from "社員" where "部署" = '営業部' order by "社員番号";
```

```sql
SELECT
  "社員番号",
  "氏名"
FROM "社員"
WHERE "部署" = '営業部'
ORDER BY "社員番号";
```

## 全角スペースは半角スペースに変わる

日本語入力をオンにしたまま SQL を打つと、語の区切りに全角スペース（U+3000）が入ることがあります。トークナイザーは全角スペースも空白として扱うので、整形すると語の間は半角スペースや改行になります。文字列の中の全角スペースは変わりません。

{/* sqlf-check: {"op":"format"} */}
```sql
SELECT　"氏名"　FROM　"社員"　WHERE　"部署"　=　'営業　第一部';
```

```sql
SELECT
  "氏名"
FROM "社員"
WHERE "部署" = '営業　第一部';
```

SQLite 3.49.1 では、{/* sqlf-sqlite: {"sql":"SELECT　\"氏名\"　FROM　\"社員\"　WHERE　\"部署\"　=　'営業　第一部';","error":"near \"SELECT　\": syntax error"} */}元の文は `near "SELECT　": syntax error` になり、{/* sqlf-sqlite: {"sql":"SELECT\n  \"氏名\"\nFROM \"社員\"\nWHERE \"部署\" = '営業　第一部';"} */}整形後の文は実行できます。ただし、これは整形の副作用です。ほかの SQL クライアントでも同じように動くとは限らないので、全角スペースはエディターの検索で見つけて直すのが確実です。

## 小文字とスペース4個で整形する

チームのコーディング規約に合わせて、キーワードを小文字、インデントをスペース4個にした例です。二重引用符で囲んだ名前と文字列は、大文字・小文字の設定の影響を受けません。

{/* sqlf-check: {"op":"format","indent":"4","upper":false} */}
```sql
SELECT "部署", COUNT(*) AS "人数" FROM "社員" GROUP BY "部署" HAVING COUNT(*) >= 3;
```

```sql
select
    "部署",
    count(*) as "人数"
from "社員"
group by "部署"
having count(*) >= 3;
```

`COUNT` は小文字の `count` になります。大文字・小文字を切り替えるのは、決まった 54 語のキーワードだけです（`COUNT`、`SUM`、`AVG`、`MIN`、`MAX` の集計関数を含む）。`now()` のようなほかの関数名は入力のままです。

## サブクエリの例

既定の設定（2 スペースインデント、キーワード大文字）での実際の出力です。括弧内のサブクエリは 1 段深くインデントされます。

```sql
select * from users where id in (select user_id from orders where total > 100);
```

```sql
SELECT
  *
FROM users
WHERE id IN (
  SELECT
    user_id
  FROM orders
  WHERE total > 100
);
```

## 制限事項

- **方言は汎用の 1 種類のみで、構文チェックはしません。** MySQL・PostgreSQL・SQL Server などのモードはなく、誤った SQL もエラーなしで整形されます。
- **引用符のない日本語の名前は1文字ずつ区切られます。** 上の例のとおりです。アクセント付きの英字も同じです。
- **文字列中のバックスラッシュエスケープを認識しません。** MySQL は `NO_BACKSLASH_ESCAPES` が無効なとき、文字列中の `\'` を引用符1文字として読みます（[MySQL 8.4 String Literals](https://dev.mysql.com/doc/refman/8.4/en/string-literals.html)）。このツールはその引用符で文字列を終えるため、{/* sqlf-check: {"op":"minify","in":"select * from users where note = 'It\\'s'"} */}`select * from users where note = 'It\'s'` が `SELECT * FROM users WHERE note = 'It\' s '` になり、文字列の中身が変わります。`'It''s'` のように引用符を2つ重ねて書けば、そのまま残ります。
- **ほかの方言の書き方には空白が入ります。** {/* sqlf-check: {"op":"minify","in":"select * from t where id = $1 and name = N'山田'"} */}`select * from t where id = $1 and name = N'山田'` は `SELECT * FROM t WHERE id = $ 1 AND name = N '山田'` になり、PostgreSQL のパラメーター `$1` と SQL Server の `N'...'` が分かれます。
- **`CASE` は 1 行のままです。** `CASE WHEN ... THEN ... END` は `WHEN` ごとに改行されません。
- **圧縮するとコメントが消え**、閉じ括弧の後の空白もなくなります（例：`SELECT COUNT(*)FROM events`）。圧縮ではキーワードが常に大文字になり、大文字・小文字の設定は使われません。
