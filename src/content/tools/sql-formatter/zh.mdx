<h2>格式化示例</h2>
<h3>格式化前</h3>

```sql
select u.id, u.name, o.total from users u join orders o on u.id = o.user_id where o.total > 100 and u.active = 1 order by o.total desc limit 10;
```

<h3>格式化后</h3>

```sql
SELECT
  u.id,
  u.name,
  o.total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.total > 100
  AND u.active = 1
ORDER BY o.total DESC
LIMIT 10;
```

<h2>为什么要格式化 SQL？</h2>
<p>格式化的 SQL 更易于阅读、审查和调试。一致的格式有助于团队维护编码标准，使包含多个 JOIN 和子查询的复杂查询更易于管理。</p>

## 子查询示例

以下是默认选项（2 空格缩进、关键字大写）的实际输出。括号里的子查询会多缩进一级：

```sql
select * from users where id in (select user_id from orders where total > 100);
```

```sql
SELECT
  *
FROM users
WHERE id IN (
  SELECT
    user_id
  FROM orders
  WHERE total > 100
);
```

## CTE 示例

`WITH ... AS (...)` 的主体按子查询缩进。`SUM(total)` 这样的函数调用保持在一行，`ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` 这样的窗口函数也一样：

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## 限制

- **只有一种通用方言，不做语法校验。** 没有 MySQL、PostgreSQL、SQL Server 等模式，错误的 SQL 也会照样格式化，不报错。
- **`CASE` 保持在一行。** `CASE WHEN ... THEN ... END` 不会按 `WHEN` 拆行。
- **压缩会删掉注释**，也会去掉右括号后的空格，例如 `SELECT COUNT(*)FROM events`。
