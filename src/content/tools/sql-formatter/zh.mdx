<h2>示例：中文别名和中文表名</h2>

MySQL 允许不加引号的名字使用 U+0080 到 U+FFFF 的字符（[MySQL 8.4 参考手册：Schema Object Names](https://dev.mysql.com/doc/refman/8.4/en/identifiers.html)），所以 `as 用户名` 这样的中文别名在 MySQL 里可以直接执行。本工具把连续的 Unicode 字母、数字、`_`、`$` 读作一个名字，未加引号的中文名会整体保留，只有关键字改变大小写：

{/* sqlf-check: {"op":"format"} */}
```sql
select name as 用户名, count(*) as 订单数 from orders group by name;
```

```sql
SELECT
  name AS 用户名,
  COUNT(*) AS 订单数
FROM orders
GROUP BY name;
```

在 SQLite 3.49.1（sql.js）里实测，{/* sqlf-sqlite: {"sql":"select name as 用户名, count(*) as 订单数 from orders group by name;"} */}原句和{/* sqlf-sqlite: {"sql":"SELECT\n  name AS 用户名,\n  COUNT(*) AS 订单数\nFROM orders\nGROUP BY name;"} */}格式化后的句子都能执行，返回的行相同。表名、列名都是中文时也一样：

{/* sqlf-check: {"op":"format"} */}
```sql
select 收货人, sum(实付金额) as 合计 from 订单 where 状态 = '已支付' group by 收货人 order by 合计 desc;
```

```sql
SELECT
  收货人,
  SUM(实付金额) AS 合计
FROM 订单
WHERE 状态 = '已支付'
GROUP BY 收货人
ORDER BY 合计 DESC;
```

用反引号（MySQL）或双引号（标准 SQL、PostgreSQL）括起来的名字同样原样保留：

{/* sqlf-check: {"op":"format"} */}
```sql
select `收货人`, sum(`实付金额`) as `合计` from `订单` where `状态` = '已支付' group by `收货人` order by `合计` desc;
```

```sql
SELECT
  `收货人`,
  SUM(`实付金额`) AS `合计`
FROM `订单`
WHERE `状态` = '已支付'
GROUP BY `收货人`
ORDER BY `合计` DESC;
```

<h2>示例：压缩成一行写进日志</h2>

排查问题时，常要把一条多行 SQL 贴进日志检索框或配置项。“压缩”会把整条语句放到一行，并删掉注释：`--` 注释会吞掉同一行后面的所有内容，留在一行里会让后半句失效。

{/* sqlf-check: {"op":"minify"} */}
```sql
select id, `收货人` from `订单`
where `状态` = '待发货' -- 每日对账
  and created_at >= '2026-10-01';
```

```sql
SELECT id, `收货人` FROM `订单` WHERE `状态` = '待发货' AND created_at >= '2026-10-01';
```

引号里的中文和日期字符串保持原样。关键字的大小写与格式化一样，跟随“关键字大写”选项。

## 子查询示例

以下是默认选项（2 空格缩进、关键字大写）的实际输出。括号里的子查询会多缩进一级：

```sql
select * from users where id in (select user_id from orders where total > 100);
```

```sql
SELECT
  *
FROM users
WHERE id IN (
  SELECT
    user_id
  FROM orders
  WHERE total > 100
);
```

## CTE 示例

`WITH ... AS (...)` 的主体按子查询缩进。`SUM(total)` 这样的函数调用保持在一行，`ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` 这样的窗口函数也一样：

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## 限制

- **只有一种通用方言，不做语法校验。** 没有 MySQL、PostgreSQL、SQL Server 等模式，错误的 SQL 也会照样格式化，不报错。
- **字符串里的反斜杠按两种读法之一处理。** MySQL 在未开启 `NO_BACKSLASH_ESCAPES` 时把字符串里的 `\'` 当作转义的单引号（[MySQL 8.4 String Literals](https://dev.mysql.com/doc/refman/8.4/en/string-literals.html)）；PostgreSQL 在默认的 `standard_conforming_strings = on` 下（[PostgreSQL: Lexical Structure](https://www.postgresql.org/docs/current/sql-syntax-lexical.html)）和 SQLite（[SQLite: Literal Values](https://www.sqlite.org/lang_expr.html)）把反斜杠当普通字符。本工具在按 MySQL 读法能让每个字符串都闭合时用 MySQL 读法，否则用标准读法：{/* sqlf-check: {"op":"minify","in":"select * from users where note = 'It\\'s'"} */}`select * from users where note = 'It\'s'` 压缩后仍是 `SELECT * FROM users WHERE note = 'It\'s'`，单独的 `'C:\'` 也仍是一个字符串。字符串内容总是原样复制，读法只决定字符串在哪里结束。
- **`CASE` 保持在一行。** `CASE WHEN ... THEN ... END` 不会按 `WHEN` 拆行。
- **压缩会删掉 `-- ` 和 `/* */` 注释**（`#` 注释和不带空格的 `--x` 保留并换行），也会去掉右括号后的空格，例如 `SELECT COUNT(*)FROM events`。
