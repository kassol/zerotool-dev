<h2>How to Use</h2>
<ol>
  <li>Paste your SQL query into the input area.</li>
  <li>Click <strong>Format</strong> to beautify or <strong>Minify</strong> to compress.</li>
  <li>Adjust indent size and keyword casing with the options.</li>
  <li>Click <strong>Copy</strong> to copy the formatted result.</li>
</ol>

<h2>Worked Examples</h2>
<h3>Before formatting</h3>

```sql
select u.id, u.name, o.total from users u join orders o on u.id = o.user_id where o.total > 100 and u.active = 1 order by o.total desc limit 10;
```

<h3>After formatting</h3>

```sql
SELECT
  u.id,
  u.name,
  o.total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.total > 100
  AND u.active = 1
ORDER BY o.total DESC
LIMIT 10;
```

<h2>Why Format SQL?</h2>
<p>Formatted SQL is easier to read, review, and debug. Consistent formatting helps teams maintain coding standards and makes complex queries with multiple JOINs and subqueries much more manageable.</p>

## Subquery Example

Output with the default options (2-space indent, uppercase keywords). A subquery in parentheses is indented one level deeper:

```sql
select * from users where id in (select user_id from orders where total > 100);
```

```sql
SELECT
  *
FROM users
WHERE id IN (
  SELECT
    user_id
  FROM orders
  WHERE total > 100
);
```

## CTE Example

The body of a `WITH ... AS (...)` block is indented like a subquery. Function calls such as `SUM(total)` stay on one line, and so does a window function such as `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)`:

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## Limits

- **One generic dialect, no validation.** There is no MySQL, PostgreSQL, or SQL Server mode, and invalid SQL is formatted without an error.
- **`CASE` stays on one line.** `CASE WHEN ... THEN ... END` is not broken into `WHEN` lines.
- **Minify removes comments** and the space after a closing parenthesis, for example `SELECT COUNT(*)FROM events`.
