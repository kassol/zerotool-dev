<h2>Worked Examples</h2>
{/* sqlf-check: {"op":"format"} */}
<h3>Before formatting</h3>

```sql
select u.id, u.name, o.total from users u join orders o on u.id = o.user_id where o.total > 100 and u.active = 1 order by o.total desc limit 10;
```

<h3>After formatting</h3>

```sql
SELECT
  u.id,
  u.name,
  o.total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.total > 100
  AND u.active = 1
ORDER BY o.total DESC
LIMIT 10;
```

## Aggregates and Comments

`GROUP BY`, `HAVING` and `ORDER BY` each start a new line at the same level as `FROM`. Comments stay where they were, at the end of the line they belonged to:

{/* sqlf-check: {"op":"format"} */}

```sql
select status, count(*) as n -- per status
from orders /* this year */ where created_at >= '2026-01-01' group by status having count(*) > 5 order by n desc;
```

```sql
SELECT
  status,
  COUNT(*) AS n -- per status
FROM orders /* this year */
WHERE created_at >= '2026-01-01'
GROUP BY status
HAVING COUNT(*) > 5
ORDER BY n DESC;
```

Several statements separated by `;` are formatted one after another, each starting on a new line.

## Minify

**Minify** puts the whole query on one line, for example to paste it into a log search, a shell variable or a JSON string. Comments are dropped, because a `--` comment would swallow everything after it on a single line. Minifying the formatted aggregate query above gives:

```sql
SELECT status, COUNT(*)AS n FROM orders WHERE created_at >= '2026-01-01' GROUP BY status HAVING COUNT(*)> 5 ORDER BY n DESC;
```

The missing space in `COUNT(*)AS` looks odd but does not change the query; SQLite 3 runs this line as written. Format adds the space back.

## Write Statements

`INSERT`, `UPDATE` and `DELETE` are handled, but with less layout than `SELECT`:

```sql
UPDATE orders
SET status = 'shipped', shipped_at = now()
WHERE id = 42;
```

```sql
INSERT INTO users(name, email)
VALUES('Ann', 'ann@example.com'),('Bo', 'bo@example.com');
```

The column list after `SET` stays on one line, and all `VALUES` rows go on one line, with the space before each `(` removed. For a long multi-row insert, add the line breaks by hand.

## Keyword Case

With the uppercase option on, the formatter capitalizes a fixed list of 54 words: clause keywords such as `SELECT`, `LEFT`, `HAVING`, `UNION`, `CASE`, `EXISTS`, plus the five aggregate functions `COUNT`, `SUM`, `AVG`, `MIN` and `MAX`. Other function names (`now()`, `coalesce()`, `date_trunc()`) and data types are left as typed. With the option off, the same keywords are converted to lower case, so `Select Id From Users` becomes `select Id from Users`. Unquoted names, including names with accented or non-Latin letters such as `café` or `社員番号`, are never changed, and quoted names (`"Order Id"`, `` `name` ``) and string literals, including doubled quotes as in `'it''s here'`, are copied as written.

Names with other letters are kept whole as well. {/* sqlf-check: {"op":"minify","in":"select café, naïve from t"} */}`select café, naïve from t` minifies to `SELECT café, naïve FROM t`.

## Subquery Example

Output with the default options (2-space indent, uppercase keywords). A subquery in parentheses is indented one level deeper:

```sql
select * from users where id in (select user_id from orders where total > 100);
```

```sql
SELECT
  *
FROM users
WHERE id IN (
  SELECT
    user_id
  FROM orders
  WHERE total > 100
);
```

## CTE Example

The body of a `WITH ... AS (...)` block is indented like a subquery. Function calls such as `SUM(total)` stay on one line, and so does a window function such as `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)`:

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## Limits

- **One generic dialect, no validation.** There is no MySQL, PostgreSQL, or SQL Server mode, and invalid SQL is formatted without an error.
- **Backslashes in strings follow one of two readings.** MySQL reads `\'` inside a string as an escaped quote unless the `NO_BACKSLASH_ESCAPES` SQL mode is on ([MySQL 8.4 String Literals](https://dev.mysql.com/doc/refman/8.4/en/string-literals.html)); PostgreSQL with its default `standard_conforming_strings = on` ([PostgreSQL: Lexical Structure](https://www.postgresql.org/docs/current/sql-syntax-lexical.html)) and SQLite ([SQLite: Literal Values](https://www.sqlite.org/lang_expr.html)) treat a backslash as an ordinary character. The tool uses the MySQL reading when it closes every quoted string, and the standard reading otherwise. So {/* sqlf-check: {"op":"minify","in":"select * from users where note = 'It\\'s'"} */}`select * from users where note = 'It\'s'` stays `SELECT * FROM users WHERE note = 'It\'s'`, and a lone `'C:\'` stays one string. Strings are always copied as written; the reading only decides where each string ends.
- **Other dialect tokens get extra spaces.** {/* sqlf-check: {"op":"minify","in":"select [order id] from t where id = $1 and name = N'Zoë'"} */}`select [order id] from t where id = $1 and name = N'Zoë'` becomes `SELECT [ ORDER id ] FROM t WHERE id = $ 1 AND name = N 'Zoë'`: the SQL Server brackets are split and the keyword inside them is uppercased, and the PostgreSQL parameter `$1` and the `N'...'` prefix are separated.
- **`CASE` stays on one line.** `CASE WHEN ... THEN ... END` is not broken into `WHEN` lines.
- **Write statements are only lightly formatted.** See the `INSERT` and `UPDATE` examples above; `CREATE TABLE` column definitions also stay on one line.
- **Minify removes comments** and the space after a closing parenthesis, for example `SELECT COUNT(*)FROM events`.
- **Minify always writes keywords in uppercase,** whether or not the uppercase option is checked.
