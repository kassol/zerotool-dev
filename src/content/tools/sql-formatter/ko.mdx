## Oracle ROWNUM 페이징 쿼리 정렬하기

Oracle의 `ROWNUM`은 쿼리가 행을 고른 순서대로 1, 2, 3…을 매기는 의사 컬럼(pseudocolumn)이고, `ORDER BY`보다 먼저 매겨지기 때문에 정렬한 결과에 번호를 붙이려면 서브쿼리 안에서 먼저 정렬해야 합니다([Oracle Database SQL Language Reference: ROWNUM Pseudocolumn](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/ROWNUM-Pseudocolumn.html)). 아래처럼 게시판 목록의 11~20번째 글을 가져오는 쿼리는 세 겹으로 중첩되어, 한 줄로 쓰면 괄호의 짝을 찾기 어렵습니다.

{/* sqlf-check: {"op":"format"} */}
```sql
select * from (select rownum as rn, b.* from (select * from board order by reg_date desc) b where rownum <= 20) where rn > 10;
```

```sql
SELECT
  *
FROM (
  SELECT
    rownum AS rn,
    b.*
  FROM (
    SELECT
      *
    FROM board
    ORDER BY reg_date DESC
  ) b
  WHERE rownum <= 20
)
WHERE rn > 10;
```

서브쿼리마다 한 단계씩 들여쓰고, 닫는 괄호는 여는 괄호가 있던 줄의 들여쓰기로 돌아갑니다. `rownum`은 키워드 목록에 없으므로 입력한 대로 소문자로 남습니다. `rn > 10` 대신 `rn between 11 and 20`이라고 쓰면, `BETWEEN` 뒤의 `AND`도 조건을 잇는 `AND`처럼 새 줄에서 시작합니다. 의미는 같지만 줄 모양이 어색해 보일 수 있습니다.

## 한글 컬럼명은 따옴표로 감싸기

PostgreSQL은 따옴표 없는 식별자에 비라틴 문자도 쓸 수 있다고 설명합니다([PostgreSQL: Lexical Structure](https://www.postgresql.org/docs/current/sql-syntax-lexical.html)). 그래서 `가입일` 같은 한글 컬럼명은 따옴표 없이도 실행됩니다. 하지만 이 도구는 ASCII 영문자·숫자·`_`·`$`만 이름으로 읽으므로, 한글은 한 글자씩 떨어집니다.

{/* sqlf-check: {"op":"format"} */}
```sql
select 이름, 가입일 from 회원 where 등급 = 'VIP';
```

```sql
SELECT
  이 름,
  가 입 일
FROM 회 원
WHERE 등 급 = 'VIP';
```

SQLite 3.49.1(sql.js)에서 확인하면 {/* sqlf-sqlite: {"sql":"select 이름, 가입일 from 회원 where 등급 = 'VIP';"} */}원래 문장은 실행되고, {/* sqlf-sqlite: {"sql":"SELECT\n  이 름,\n  가 입 일\nFROM 회 원\nWHERE 등 급 = 'VIP';","error":"near \"일\": syntax error"} */}서식을 지정한 문장은 `near "일": syntax error`로 멈춥니다. `이 름`처럼 두 글자인 이름은 구문 오류가 아니라 “`이` 컬럼에 `름`이라는 별칭”으로 읽힙니다. {/* sqlf-sqlite: {"sql":"SELECT 이 름 FROM 회원;","error":"no such column: 이"} */}이 부분만 실행하면 `no such column: 이`가 나오고, 마침 `이`라는 컬럼이 있는 테이블이라면 오류 없이 다른 값을 돌려줍니다. 한글 이름은 큰따옴표로 감싸 두면 한 덩어리로 정렬됩니다.

{/* sqlf-check: {"op":"format"} */}
```sql
select "이름", "가입일" from "회원" where "등급" = 'VIP';
```

```sql
SELECT
  "이름",
  "가입일"
FROM "회원"
WHERE "등급" = 'VIP';
```

## 키워드 소문자, 탭 들여쓰기

“키워드 대문자”를 끄고 들여쓰기를 탭으로 바꾼 예입니다. 이 설정은 “서식 지정”을 누를 때 적용됩니다.

{/* sqlf-check: {"op":"format","indent":"tab","upper":false} */}
```sql
SELECT "등급", COUNT(*) AS cnt FROM "회원" GROUP BY "등급";
```

```sql
select
	"등급",
	count(*) as cnt
from "회원"
group by "등급";
```

`COUNT`도 소문자가 됩니다. 대소문자를 바꾸는 대상은 고정된 54개 키워드(집계 함수 `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` 포함)뿐이고, 큰따옴표로 감싼 이름은 그대로입니다.

## CTE 예시

`WITH ... AS (...)`의 본문은 서브쿼리처럼 들여씁니다. `SUM(total)` 같은 함수 호출은 한 줄에 들어가며, `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` 같은 윈도 함수도 마찬가지입니다.

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## 제한 사항

- **방언은 범용 1종류뿐이며 문법 검사를 하지 않습니다.** MySQL·PostgreSQL·SQL Server 등의 모드가 없고, 잘못된 SQL도 오류 없이 서식이 지정됩니다.
- **따옴표 없는 한글 이름은 한 글자씩 떨어집니다.** 위 예시와 같습니다. 악센트가 붙은 영문자도 마찬가지입니다.
- **문자열 안의 백슬래시 이스케이프를 인식하지 않습니다.** MySQL은 `NO_BACKSLASH_ESCAPES`가 꺼져 있으면 문자열 안의 `\'`를 작은따옴표 한 글자로 읽습니다([MySQL 8.4 String Literals](https://dev.mysql.com/doc/refman/8.4/en/string-literals.html)). 이 도구는 그 따옴표에서 문자열을 끝내므로 {/* sqlf-check: {"op":"minify","in":"select * from users where note = 'It\\'s'"} */}`select * from users where note = 'It\'s'`가 `SELECT * FROM users WHERE note = 'It\' s '`로 바뀌어 문자열 내용이 달라집니다. `'It''s'`처럼 작은따옴표를 두 번 쓰면 그대로 남습니다.
- **다른 방언 문법에는 공백이 들어갑니다.** PostgreSQL의 `$1`은 `$ 1`이 됩니다.
- **`CASE`는 한 줄로 유지됩니다.** `CASE WHEN ... THEN ... END`는 `WHEN`마다 줄바꿈되지 않습니다.
- **최소화하면 주석이 제거되고**, 닫는 괄호 뒤의 공백도 없어집니다(예: `SELECT COUNT(*)FROM events`). 최소화 결과의 키워드는 “키워드 대문자” 설정과 상관없이 항상 대문자입니다.
