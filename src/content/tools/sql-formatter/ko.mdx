## Oracle ROWNUM 페이징 쿼리 정렬하기

Oracle의 `ROWNUM`은 쿼리가 행을 고른 순서대로 1, 2, 3…을 매기는 의사 컬럼(pseudocolumn)이고, `ORDER BY`보다 먼저 매겨지기 때문에 정렬한 결과에 번호를 붙이려면 서브쿼리 안에서 먼저 정렬해야 합니다([Oracle Database SQL Language Reference: ROWNUM Pseudocolumn](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/ROWNUM-Pseudocolumn.html)). 아래처럼 게시판 목록의 11~20번째 글을 가져오는 쿼리는 세 겹으로 중첩되어, 한 줄로 쓰면 괄호의 짝을 찾기 어렵습니다.

{/* sqlf-check: {"op":"format"} */}
```sql
select * from (select rownum as rn, b.* from (select * from board order by reg_date desc) b where rownum <= 20) where rn > 10;
```

```sql
SELECT
  *
FROM (
  SELECT
    rownum AS rn,
    b.*
  FROM (
    SELECT
      *
    FROM board
    ORDER BY reg_date DESC
  ) b
  WHERE rownum <= 20
)
WHERE rn > 10;
```

서브쿼리마다 한 단계씩 들여쓰고, 닫는 괄호는 여는 괄호가 있던 줄의 들여쓰기로 돌아갑니다. `rownum`은 키워드 목록에 없으므로 입력한 대로 소문자로 남습니다. `rn > 10` 대신 `rn between 11 and 20`이라고 쓰면, `BETWEEN` 뒤의 `AND`도 조건을 잇는 `AND`처럼 새 줄에서 시작합니다. 의미는 같지만 줄 모양이 어색해 보일 수 있습니다.

## 한글 컬럼명 그대로 정렬하기

PostgreSQL은 따옴표 없는 식별자에 비라틴 문자도 쓸 수 있다고 설명합니다([PostgreSQL: Lexical Structure](https://www.postgresql.org/docs/current/sql-syntax-lexical.html)). 그래서 `가입일` 같은 한글 컬럼명은 따옴표 없이도 실행됩니다. 이 도구는 이어진 유니코드 문자·숫자·`_`·`$`를 한 이름으로 읽기 때문에 한글 이름도 떨어지지 않고 그대로 남습니다.

{/* sqlf-check: {"op":"format"} */}
```sql
select 이름, 가입일 from 회원 where 등급 = 'VIP';
```

```sql
SELECT
  이름,
  가입일
FROM 회원
WHERE 등급 = 'VIP';
```

`이름`처럼 두 글자인 이름도 한 덩어리로 남으므로, “`이` 컬럼에 `름`이라는 별칭”으로 잘못 읽힐 일이 없습니다. SQLite 3.49.1(sql.js)에서 확인하면 {/* sqlf-sqlite: {"sql":"select 이름, 가입일 from 회원 where 등급 = 'VIP';"} */}원래 문장과 {/* sqlf-sqlite: {"sql":"SELECT\n  이름,\n  가입일\nFROM 회원\nWHERE 등급 = 'VIP';"} */}서식을 지정한 문장이 모두 실행되고 같은 행을 돌려줍니다. 큰따옴표로 감싼 한글 이름도 그대로 정렬됩니다.

{/* sqlf-check: {"op":"format"} */}
```sql
select "이름", "가입일" from "회원" where "등급" = 'VIP';
```

```sql
SELECT
  "이름",
  "가입일"
FROM "회원"
WHERE "등급" = 'VIP';
```

## 키워드 소문자, 탭 들여쓰기

“키워드 대문자”를 끄고 들여쓰기를 탭으로 바꾼 예입니다. 이 설정은 “서식 지정”을 누를 때 적용됩니다.

{/* sqlf-check: {"op":"format","indent":"tab","upper":false} */}
```sql
SELECT "등급", COUNT(*) AS cnt FROM "회원" GROUP BY "등급";
```

```sql
select
	"등급",
	count(*) as cnt
from "회원"
group by "등급";
```

`COUNT`도 소문자가 됩니다. 대소문자를 바꾸는 대상은 고정된 54개 키워드(집계 함수 `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` 포함)뿐이고, 큰따옴표로 감싼 이름은 그대로입니다.

## CTE 예시

`WITH ... AS (...)`의 본문은 서브쿼리처럼 들여씁니다. `SUM(total)` 같은 함수 호출은 한 줄에 들어가며, `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` 같은 윈도 함수도 마찬가지입니다.

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## 제한 사항

- **방언은 범용 1종류뿐이며 문법 검사를 하지 않습니다.** MySQL·PostgreSQL·SQL Server 등의 모드가 없고, 잘못된 SQL도 오류 없이 서식이 지정됩니다.
- **문자열 안의 백슬래시는 두 가지 읽기 방식 중 하나로 처리합니다.** MySQL은 `NO_BACKSLASH_ESCAPES`가 꺼져 있으면 문자열 안의 `\'`를 이스케이프된 작은따옴표로 읽습니다([MySQL 8.4 String Literals](https://dev.mysql.com/doc/refman/8.4/en/string-literals.html)). 기본값 `standard_conforming_strings = on`인 PostgreSQL([PostgreSQL: Lexical Structure](https://www.postgresql.org/docs/current/sql-syntax-lexical.html))과 SQLite([SQLite: Literal Values](https://www.sqlite.org/lang_expr.html))에서 백슬래시는 일반 문자입니다. 이 도구는 MySQL 방식으로 읽었을 때 모든 문자열이 닫히면 그 방식을, 닫히지 않으면 표준 방식을 씁니다. {/* sqlf-check: {"op":"minify","in":"select * from users where note = 'It\\'s'"} */}`select * from users where note = 'It\'s'`는 최소화한 뒤에도 `SELECT * FROM users WHERE note = 'It\'s'`이고, 단독으로 쓴 `'C:\'`도 한 문자열로 남습니다. 문자열 내용은 항상 그대로 복사하며, 읽기 방식은 문자열이 끝나는 위치만 정합니다.
- **`CASE`는 한 줄로 유지됩니다.** `CASE WHEN ... THEN ... END`는 `WHEN`마다 줄바꿈되지 않습니다.
- **최소화하면 `-- `와 `/* */` 주석이 제거되고**(`/*! … */`와 `/*+ … */`는 그대로 두고, `#` 주석과 공백 없는 `--x`는 남기고 줄을 바꿉니다), 닫는 괄호 뒤의 공백도 없어집니다(예: `SELECT COUNT(*)FROM events`).
