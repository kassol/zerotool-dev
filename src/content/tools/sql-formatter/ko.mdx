<h2>SQL 포매팅에 대하여</h2>
<p>정렬된 SQL은 읽기 쉽고 코드 리뷰나 디버깅이 용이해집니다. 또한 ORM이 생성한 압축된 SQL을 읽을 때 정렬 도구가 매우 유용합니다. 반면 로그나 API 파라미터로 전달할 때는 압축 형식이 적합합니다.</p>

## 정렬 예시

정렬 전:

```sql
select u.id, u.name, o.total from users u join orders o on u.id = o.user_id where o.total > 100 and u.active = 1 order by o.total desc limit 10;
```

정렬 후(기본 옵션):

```sql
SELECT
  u.id,
  u.name,
  o.total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.total > 100
  AND u.active = 1
ORDER BY o.total DESC
LIMIT 10;
```

## 서브쿼리 예시

기본 옵션(공백 2칸 들여쓰기, 키워드 대문자)으로 실제 출력한 결과입니다. 괄호 안의 서브쿼리는 한 단계 더 들여씁니다.

```sql
select * from users where id in (select user_id from orders where total > 100);
```

```sql
SELECT
  *
FROM users
WHERE id IN (
  SELECT
    user_id
  FROM orders
  WHERE total > 100
);
```

## CTE 예시

`WITH ... AS (...)`의 본문은 서브쿼리처럼 들여씁니다. `SUM(total)` 같은 함수 호출은 한 줄에 남고, `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` 같은 윈도 함수도 마찬가지입니다.

```sql
with recent as (select user_id, sum(total) as spent from orders group by user_id) select u.name, r.spent from users u join recent r on r.user_id = u.id order by r.spent desc;
```

```sql
WITH recent AS (
  SELECT
    user_id,
    SUM(total) AS spent
  FROM orders
  GROUP BY user_id
)
SELECT
  u.name,
  r.spent
FROM users u
JOIN recent r ON r.user_id = u.id
ORDER BY r.spent DESC;
```

## 제한 사항

- **범용 방언 하나뿐이며 문법 검사를 하지 않습니다.** MySQL, PostgreSQL, SQL Server 모드가 없고, 잘못된 SQL도 오류 없이 정렬합니다.
- **`CASE`는 한 줄로 남습니다.** `CASE WHEN ... THEN ... END`를 `WHEN`마다 줄바꿈하지 않습니다.
- **최소화하면 주석이 사라지고** 닫는 괄호 뒤 공백도 없어집니다(예: `SELECT COUNT(*)FROM events`).
