<h2>示例</h2>

{/* efp-check: {"status":"有效 6 个，警告 2 个。","rows":[[2,"ok","DB_HOST",""],[3,"ok","DB_PORT",""],[4,"ok","DB_NAME",""],[5,"ok","DB_PASSWORD",""],[7,"warn","API_KEY","值为空"],[8,"ok","STRIPE_KEY",""],[10,"ok","APP_ENV",""],[11,"warn","APP_ENV","键重复"]]} */}
```
# 数据库配置
DB_HOST=localhost
DB_PORT=5432
DB_NAME=myapp
DB_PASSWORD="s3cr3t"
# API 密钥
API_KEY=
STRIPE_KEY=your-stripe-key
# 重复键示例
APP_ENV=development
APP_ENV=production
```

<p>解析器去掉 <code>DB_PASSWORD</code> 的引号，把 <code>API_KEY</code> 标为“值为空”，第二个 <code>APP_ENV</code> 标为“键重复”，状态行显示“有效 6 个，警告 2 个。”。导出的 <code>env.json</code> 中 <code>APP_ENV</code> 取最后的值：</p>

```json
{
  "DB_HOST": "localhost",
  "DB_PORT": "5432",
  "DB_NAME": "myapp",
  "DB_PASSWORD": "s3cr3t",
  "API_KEY": "",
  "STRIPE_KEY": "your-stripe-key",
  "APP_ENV": "production"
}
```

<h2>冒号、空格与其他键名</h2>
<p>dotenv 也接受类似 YAML 的 <code>KEY: value</code>，但冒号后必须有空格。dotenv 会跳过的行在表格中显示为错误，不进入导出；dotenv 接受但写法少见的键显示警告，照常导出：</p>

{/* efp-check: {"status":"有效 2 个，警告 1 个，错误 2 个。","rows":[[1,"ok","SITE_NAME",""],[2,"ok","API_BASE",""],[3,"error","","键名不符合常见规则"],[4,"warn","feature.flag","键名不符合常见规则"],[5,"error","","应写成 KEY=value，或 KEY: value（冒号后有空格，前面没有空格）"]],"node":{"CDN HOST":"static.example.cn","feature.flag":"on"}} */}
```
SITE_NAME: 示例商城
export API_BASE: https://api.example.cn/v1
CDN HOST=static.example.cn
feature.flag=on
PORT:8080
```

```json
{
  "SITE_NAME": "示例商城",
  "API_BASE": "https://api.example.cn/v1",
  "feature.flag": "on"
}
```

<p>
  状态行显示“有效 2 个，警告 1 个，错误 2 个。”。第 3 行键名中有空格，dotenv 的键名规则 <code>{'[\\w.-]+'}</code> 不允许，所以是错误；第 5 行冒号后没有空格。
  Node.js 自带的解析器（<code>--env-file</code>、<code>util.parseEnv()</code>）规则不同：Node.js 22.23.3 读这段文本时保留 <code>CDN HOST</code> 和 <code>feature.flag</code>，三行冒号写法全部忽略。
</p>

<p>名为 <code>__proto__</code> 的键是导出与 <code>dotenv.parse()</code> 唯一不同的地方，dotenv 会丢掉这个键：</p>

{/* efp-check: {"status":"有效 2 个。","toolOnly":["__proto__"]} */}
```
__proto__=keep
A=1
```

```json
{
  "__proto__": "keep",
  "A": "1"
}
```

<h2>全角符号与中文值</h2>
<p>从聊天记录、中文文档或表格里复制配置时，等号和冒号有时是全角的 <code>＝</code>、<code>：</code>。dotenv 只把半角 <code>=</code> 和半角冒号加空格当作分隔符，所以这样的行整行被跳过。下面这段里第 2、3 行就是这种情况：</p>

{/* efp-check: {"status":"有效 3 个，错误 2 个。","rows":[[1,"ok","APP_NAME",""],[2,"error","","全角的 ＝ 和 ： 不是分隔符，请改成半角 =，或半角冒号加空格"],[3,"error","","全角的 ＝ 和 ： 不是分隔符，请改成半角 =，或半角冒号加空格"],[4,"ok","SMS_SIGN",""],[5,"ok","NOTICE",""]],"node":{"APP_NAME":"示例商城","NOTICE":"今晚 22:00 维护","SMS_SIGN":"【示例商城】"}} */}
```
APP_NAME=示例商城
DB_HOST＝127.0.0.1
REDIS_PORT：6379
SMS_SIGN=【示例商城】
NOTICE=今晚 22:00 维护 # 运维通知
```

```json
{
  "APP_NAME": "示例商城",
  "SMS_SIGN": "【示例商城】",
  "NOTICE": "今晚 22:00 维护"
}
```

<p>
  状态行显示“有效 3 个，错误 2 个。”，第 2、3 行的备注都是“全角的 ＝ 和 ： 不是分隔符，请改成半角 =，或半角冒号加空格”：行里只有全角的 <code>＝</code>、<code>：</code>，没有半角分隔符。改成半角之后再解析即可。
  中文值不需要加引号：<code>【示例商城】</code> 原样保留；<code>NOTICE</code> 里 <code>#</code> 前面有空格，dotenv 把 <code># 运维通知</code> 当作注释去掉，值是 <code>今晚 22:00 维护</code>，这一行没有备注。
  如果 <code>#</code> 是值的一部分（例如 <code>工单#1024</code>），要给整个值加上引号，否则 <code>#</code> 之后会被截掉。
</p>

<h2>常见 .env 问题检测</h2>
<ul>
  <li><strong>缺少 = 号</strong>——该行既没有 <code>=</code> 也没有冒号，无法解析为键值对。</li>
  <li><strong>冒号写法不对</strong>——<code>PORT:8080</code>、<code>PORT : 8080</code> 会被 dotenv 跳过，写成 <code>PORT=8080</code> 或 <code>PORT: 8080</code>。</li>
  <li><strong>空值</strong>——键存在但值为空，可能导致运行时错误。</li>
  <li><strong>重复键</strong>——同一键出现多次，dotenv 取最后一个值，其他加载器不一定如此。</li>
  <li><strong>键名不符合常见规则</strong>——键名最好以字母或下划线开头，只含字母、数字和下划线。含 <code>.</code>、<code>-</code> 或以数字开头的键 dotenv 仍会加载（警告）；含空格等其他字符的键不会加载（错误）。</li>
  <li><strong>未加引号的值里有 #</strong>——dotenv 从这里开始算注释，所以 <code>COLOR=#fff</code> 是空值，<code>URL=https://example.com/#top</code> 会丢掉 <code>#top</code>。给值加上引号。规则见 <a href="https://github.com/motdotla/dotenv#what-rules-does-the-parsing-engine-follow">dotenv 解析规则</a>。</li>
</ul>

<h2>限制</h2>
<ul>
  <li><strong>不展开变量。</strong><code>{'${HOME}/data'}</code> 原样保留；dotenv-expand、Docker Compose 和部分框架会展开这类引用。</li>
  <li><strong>只按 dotenv 的规则。</strong>Node.js <code>--env-file</code>、Docker Compose 的 <code>{'env_file'}</code>、Python 的 python-dotenv 和 shell 的 <code>source</code> 对引号、冒号、<code>export</code> 和 <code>#</code> 各有处理方式，请以实际使用的加载器为准。</li>
  <li><strong>值以明文显示。</strong>表格不会遮盖密钥，共享屏幕时注意；需要分享文件时，先用 <a href="/zh/tools/secret-redactor/">API Key 脱敏工具</a>替换值。</li>
  <li><strong>只导出 JSON。</strong>不能导出 YAML、shell 的 <code>export</code> 行或 Kubernetes Secret，下载的文件名固定为 <code>env.json</code>。</li>
</ul>
