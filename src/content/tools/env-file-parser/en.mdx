<h2>Example</h2>
<p>This input uses made-up values and covers the cases the parser treats specially:</p>

```
# Database config
DB_HOST=localhost
DB_PORT=5432 # default port
DB_PASSWORD="s3cr3t#1"
API_KEY=
APP_ENV=development
APP_ENV=production
export NODE_ENV=production
COLOR=#fff
PRIVATE_KEY="-----BEGIN KEY-----
abc
-----END KEY-----"
GREETING="Hello\nWorld"
SINGLE='Hello\nWorld'
my-key=1
BROKEN LINE
```

<h2>Colons, Spaces and Other Keys</h2>
<p>
  dotenv also reads <code>KEY: value</code>, as in YAML, but only with a space after the colon. A line that dotenv skips is an error in
  the table and is left out of <strong>Export JSON</strong>; a key that dotenv accepts but that is unusual gets a warning and stays in the
  export:
</p>

{/* efp-check: {"status":"2 valid, 1 warning, 2 errors.","rows":[[1,"ok","DB_HOST",""],[2,"ok","REDIS_URL",""],[3,"error","","Non-standard key name"],[4,"warn","my.key","Non-standard key name"],[5,"error","","Use KEY=value, or KEY: value with a space after the colon and none before it"]],"node":{"MY KEY":"1","my.key":"2"}} */}
```
DB_HOST: db.internal
export REDIS_URL: redis://cache:6379/0
MY KEY=1
my.key=2
PORT:8080
```

```json
{
  "DB_HOST": "db.internal",
  "REDIS_URL": "redis://cache:6379/0",
  "my.key": "2"
}
```

<p>
  The status line reads "2 valid, 1 warning, 2 errors." Line 3 (<code>MY KEY=1</code>) shows <em>Non-standard key name</em> as an error
  because dotenv's key pattern <code>{'[\\w.-]+'}</code> has no space. Line 5 shows <em>Use KEY=value, or KEY: value with a space after the colon and
  none before it</em>. Node.js has its own parser (<code>--env-file</code>, <code>util.parseEnv()</code>), and Node.js 22.23.3 reads this text
  differently: it keeps <code>MY KEY</code> and <code>my.key</code> and ignores all three colon lines.
</p>

<p>A key named <code>__proto__</code> is the one place where the export differs from <code>dotenv.parse()</code>, which drops that key:</p>

{/* efp-check: {"status":"2 valid.","toolOnly":["__proto__"]} */}
```
__proto__=keep
A=1
```

```json
{
  "__proto__": "keep",
  "A": "1"
}
```

<h2>Limits</h2>
<ul>
  <li><strong>No variable expansion.</strong> <code>{'${HOME}/data'}</code> stays as written. dotenv-expand, Docker Compose and some frameworks expand such references, so the value your app sees can differ.</li>
  <li><strong>dotenv rules only.</strong> Other loaders differ: Node.js <code>--env-file</code> (see above), Docker Compose's <code>{'env_file'}</code>, Python's python-dotenv and shell <code>source</code> treat quotes, colons, <code>export</code> and <code>#</code> in their own ways. Check the loader you actually use when a value contains quotes or <code>#</code>, or when a line uses a colon.</li>
  <li><strong>Values are shown in clear text.</strong> The table does not mask secrets, so mind screen sharing; nothing is stored or sent. To share a file safely, replace the values with the <a href="/tools/secret-redactor/">secret redactor</a> first.</li>
  <li><strong>JSON only.</strong> There is no export to YAML, shell <code>export</code> lines or a Kubernetes Secret; the downloaded file is always named <code>env.json</code>.</li>
</ul>

<h2>Common .env Pitfalls Detected</h2>
<ul>
  <li><strong>Missing = sign</strong> — the line has neither <code>=</code> nor a colon, so it cannot be parsed as a key-value pair.</li>
  <li><strong>Colon without a space</strong> — <code>PORT:8080</code> and <code>PORT : 8080</code> are skipped by dotenv; write <code>PORT=8080</code> or <code>PORT: 8080</code>.</li>
  <li><strong>Empty value</strong> — the key exists but the value is blank; may cause runtime errors depending on your app.</li>
  <li><strong>Duplicate key</strong> — the same key appears more than once; dotenv uses the last value, other loaders may not.</li>
  <li><strong>Non-standard key name</strong> — keys should start with a letter or underscore and contain only letters, digits, and underscores. Keys with <code>.</code> or <code>-</code> or a leading digit still load in dotenv (warning); keys with a space or other characters do not (error).</li>
  <li><strong># in an unquoted value</strong> — dotenv starts a comment there, so <code>COLOR=#fff</code> is empty and <code>URL=https://example.com/#top</code> loses <code>#top</code>. Put the value in quotes. Rules: <a href="https://github.com/motdotla/dotenv#what-rules-does-the-parsing-engine-follow">dotenv parsing rules</a>.</li>
</ul>
