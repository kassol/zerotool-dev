<h2>How to Use</h2>
<ol>
  <li>Paste your <code>.env</code> file contents into the text area.</li>
  <li>Click <strong>Parse</strong> to visualize all key-value pairs in a table.</li>
  <li>Review the <strong>Notes</strong> column — warnings highlight empty values, duplicate keys, or non-standard names; errors flag lines that can't be parsed.</li>
  <li>Click <strong>Export JSON</strong> to download the parsed data as a <code>env.json</code> file.</li>
</ol>

<h2>Example</h2>
<p>This input uses made-up values and covers the cases the parser treats specially:</p>

```
# Database config
DB_HOST=localhost
DB_PORT=5432 # default port
DB_PASSWORD="s3cr3t#1"
API_KEY=
APP_ENV=development
APP_ENV=production
export NODE_ENV=production
COLOR=#fff
PRIVATE_KEY="-----BEGIN KEY-----
abc
-----END KEY-----"
GREETING="Hello\nWorld"
SINGLE='Hello\nWorld'
my-key=1
BROKEN LINE
```

<h2>Limits</h2>
<ul>
  <li><strong>No variable expansion.</strong> <code>{'${HOME}/data'}</code> stays as written. dotenv-expand, Docker Compose and some frameworks expand such references, so the value your app sees can differ.</li>
  <li><strong>dotenv rules only.</strong> Other loaders differ: Docker Compose's <code>{'env_file'}</code>, Python's python-dotenv and shell <code>source</code> treat quotes, <code>export</code> and <code>#</code> in their own ways. Check the loader you actually use when a value contains quotes or <code>#</code>.</li>
  <li><strong>Values are shown in clear text.</strong> The table does not mask secrets, so mind screen sharing; nothing is stored or sent. To share a file safely, replace the values with the <a href="/tools/secret-redactor/">secret redactor</a> first.</li>
  <li><strong>Messages are in English</strong> (notes and the status line) on every language version of this page.</li>
  <li><strong>JSON only.</strong> There is no export to YAML, shell <code>export</code> lines or a Kubernetes Secret; the downloaded file is always named <code>env.json</code>.</li>
</ul>

<h2>Common .env Pitfalls Detected</h2>
<ul>
  <li><strong>Missing = sign</strong> — the line cannot be parsed as a key-value pair.</li>
  <li><strong>Empty value</strong> — the key exists but the value is blank; may cause runtime errors depending on your app.</li>
  <li><strong>Duplicate key</strong> — the same key appears more than once; behavior depends on which dotenv library is used (first or last wins).</li>
  <li><strong>Non-standard key name</strong> — keys should start with a letter or underscore and contain only letters, digits, and underscores.</li>
  <li><strong># in an unquoted value</strong> — dotenv starts a comment there, so <code>COLOR=#fff</code> is empty and <code>URL=https://example.com/#top</code> loses <code>#top</code>. Put the value in quotes. Rules: <a href="https://github.com/motdotla/dotenv#what-rules-does-the-parsing-engine-follow">dotenv parsing rules</a>.</li>
</ul>
