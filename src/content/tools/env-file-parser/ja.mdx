<h2>入力例</h2>

{/* efp-check: {"status":"有効 6 件、警告 2 件。","rows":[[2,"ok","DB_HOST",""],[3,"ok","DB_PORT",""],[4,"ok","DB_NAME",""],[5,"ok","DB_PASSWORD",""],[7,"warn","API_KEY","値が空です"],[8,"ok","STRIPE_KEY",""],[10,"ok","APP_ENV",""],[11,"warn","APP_ENV","キーが重複しています"]]} */}
```
# データベース設定
DB_HOST=localhost
DB_PORT=5432
DB_NAME=myapp
DB_PASSWORD="s3cr3t"
# API キー
API_KEY=
STRIPE_KEY=your-stripe-key
# 重複キーの例
APP_ENV=development
APP_ENV=production
```

<p>パーサーは <code>DB_PASSWORD</code> の引用符を外し、<code>API_KEY</code> に「値が空です」、2 つ目の <code>APP_ENV</code> に「キーが重複しています」を表示し、ステータスは「有効 6 件、警告 2 件。」になります。エクスポートした <code>env.json</code> の <code>APP_ENV</code> は最後の値です。</p>

```json
{
  "DB_HOST": "localhost",
  "DB_PORT": "5432",
  "DB_NAME": "myapp",
  "DB_PASSWORD": "s3cr3t",
  "API_KEY": "",
  "STRIPE_KEY": "your-stripe-key",
  "APP_ENV": "production"
}
```

<h2>コロン・空白・そのほかのキー名</h2>
<p>dotenv は YAML 風の <code>KEY: value</code> も読みますが、コロンの後に空白が必要です。dotenv が読み飛ばす行はテーブルでエラーになりエクスポートされません。dotenv が受け付けるものの珍しいキーは警告になり、エクスポートされます。</p>

{/* efp-check: {"status":"有効 2 件、警告 1 件、エラー 2 件。","rows":[[1,"ok","APP_NAME",""],[2,"ok","API_URL",""],[3,"error","","一般的でないキー名"],[4,"warn","mail.from","一般的でないキー名"],[5,"error","","KEY=value、または KEY: value（コロンの後に空白、前には空白なし）と書いてください"]],"node":{"SMTP HOST":"smtp.example.jp","mail.from":"info@example.jp"}} */}
```
APP_NAME: 予約システム
export API_URL: https://api.example.jp/v2
SMTP HOST=smtp.example.jp
mail.from=info@example.jp
PORT:8080
```

```json
{
  "APP_NAME": "予約システム",
  "API_URL": "https://api.example.jp/v2",
  "mail.from": "info@example.jp"
}
```

<p>
  ステータスは「有効 2 件、警告 1 件、エラー 2 件。」です。3 行目はキーに空白があり、dotenv のキーのパターン <code>{'[\\w.-]+'}</code> に合わないのでエラー、5 行目はコロンの後に空白がありません。キーに全角スペース（U+3000）が入った場合も同じくエラーになります。
  Node.js 自身のパーサー（<code>--env-file</code>、<code>util.parseEnv()</code>）はルールが異なり、Node.js 22.23.3 ではこのテキストから <code>SMTP HOST</code> と <code>mail.from</code> を読み、コロンの 3 行はすべて無視します。
</p>

<p><code>__proto__</code> という名前のキーだけは、エクスポートが <code>dotenv.parse()</code> と異なります。dotenv はこのキーを取り除きます。</p>

{/* efp-check: {"status":"有効 2 件。","toolOnly":["__proto__"]} */}
```
__proto__=keep
A=1
```

```json
{
  "__proto__": "keep",
  "A": "1"
}
```

<h2>全角の ＝ と全角スペース</h2>
<p>日本語の資料やチャットから設定をコピーすると、<code>＝</code> が全角になっていたり、値に全角スペースが入っていたりします。次の例では 2 行目の <code>＝</code> が全角で、3 行目の値の末尾に全角スペースがあります。</p>

{/* efp-check: {"status":"有効 3 件、エラー 1 件。","rows":[[1,"ok","SHOP_NAME",""],[2,"error","","= がありません"],[3,"ok","MAIL_FROM_NAME",""],[4,"ok","COUPON_CODE",""]],"node":{"COUPON_CODE":"ＳＡＬＥ２０２６","MAIL_FROM_NAME":"山田　太郎　","SHOP_NAME":"山田商店"}} */}
```
SHOP_NAME=山田商店
SMTP_HOST＝smtp.example.jp
MAIL_FROM_NAME=山田　太郎　
COUPON_CODE=ＳＡＬＥ２０２６
```

```json
{
  "SHOP_NAME": "山田商店",
  "MAIL_FROM_NAME": "山田　太郎",
  "COUPON_CODE": "ＳＡＬＥ２０２６"
}
```

<p>
  ステータスは「有効 3 件、エラー 1 件。」です。2 行目には半角の <code>=</code> がないので dotenv は読み飛ばし、備考は「= がありません」になります。
  <code>MAIL_FROM_NAME</code> の名前の間の全角スペースは残りますが、末尾の全角スペースは半角スペースと同じく取り除かれ、<code>山田　太郎</code> になります。
  全角英数字の <code>ＳＡＬＥ２０２６</code> も変換されずにそのまま出力されるので、半角のクーポンコードと照合するアプリでは一致しません。
  Node.js 22.23.3 の <code>util.parseEnv()</code> はこの末尾の全角スペースを取り除かず、<code>山田　太郎　</code> を返します。dotenv と Node.js の <code>--env-file</code> を併用している場合は、値の端に全角スペースを残さないでください。
</p>

<h2>検出される一般的な .env の問題</h2>
<ul>
  <li><strong>= 記号がない</strong>——<code>=</code> もコロンもなく、キーと値のペアとして解析できない行。</li>
  <li><strong>コロンの書き方</strong>——<code>PORT:8080</code> や <code>PORT : 8080</code> は dotenv が読み飛ばします。<code>PORT=8080</code> か <code>PORT: 8080</code> と書いてください。</li>
  <li><strong>空の値</strong>——キーは存在するが値が空。アプリによっては実行時エラーになる可能性があります。</li>
  <li><strong>重複キー</strong>——同じキーが複数回出現。dotenv は最後の値を使いますが、ほかのローダーも同じとは限りません。</li>
  <li><strong>一般的でないキー名</strong>——キー名は英字かアンダースコアで始め、英数字とアンダースコアだけにするのが無難です。<code>.</code>・<code>-</code> を含むキーや数字で始まるキーは dotenv でも読み込まれます（警告）。空白などを含むキーは読み込まれません（エラー）。</li>
  <li><strong>引用符なしの値に # がある</strong>——dotenv はそこからコメントとみなすので、<code>COLOR=#fff</code> は空になり、<code>URL=https://example.com/#top</code> は <code>#top</code> が消えます。値を引用符で囲んでください。ルールは <a href="https://github.com/motdotla/dotenv#what-rules-does-the-parsing-engine-follow">dotenv の解析ルール</a>を参照。</li>
</ul>

<h2>制限</h2>
<ul>
  <li><strong>変数は展開しません。</strong><code>{'${HOME}/data'}</code> はそのまま残ります。dotenv-expand、Docker Compose、一部のフレームワークはこうした参照を展開します。</li>
  <li><strong>dotenv のルールだけです。</strong>Node.js の <code>--env-file</code>、Docker Compose の <code>{'env_file'}</code>、Python の python-dotenv、シェルの <code>source</code> は、引用符・コロン・<code>export</code>・<code>#</code> の扱いがそれぞれ異なります。実際に使うローダーで確認してください。</li>
  <li><strong>値は平文で表示されます。</strong>テーブルはシークレットを隠さないので画面共有に注意してください。ファイルを共有する前に <a href="/ja/tools/secret-redactor/">APIキーマスキング</a>で値を置き換えられます。</li>
  <li><strong>出力は JSON だけです。</strong>YAML、シェルの <code>export</code> 行、Kubernetes Secret には出力できず、ダウンロードするファイル名は常に <code>env.json</code> です。</li>
</ul>
