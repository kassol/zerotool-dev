{/* efp-check: {"status":"유효 6개, 경고 2개.","rows":[[2,"ok","DB_HOST",""],[3,"ok","DB_PORT",""],[4,"ok","DB_NAME",""],[5,"ok","DB_PASSWORD",""],[7,"warn","API_KEY","값이 비어 있습니다"],[8,"ok","STRIPE_KEY",""],[10,"ok","APP_ENV",""],[11,"warn","APP_ENV","중복된 키"]]} */}
```
# 데이터베이스 설정
DB_HOST=localhost
DB_PORT=5432
DB_NAME=myapp
DB_PASSWORD="s3cr3t"
# API 키
API_KEY=
STRIPE_KEY=your-stripe-key
# 중복 키 예시
APP_ENV=development
APP_ENV=production
```

<p>파서는 <code>DB_PASSWORD</code>의 따옴표를 제거하고, <code>API_KEY</code>에 "값이 비어 있습니다", 두 번째 <code>APP_ENV</code>에 "중복된 키"를 표시하며, 상태 줄은 "유효 6개, 경고 2개."입니다. 내보낸 <code>env.json</code>의 <code>APP_ENV</code>는 마지막 값입니다.</p>

```json
{
  "DB_HOST": "localhost",
  "DB_PORT": "5432",
  "DB_NAME": "myapp",
  "DB_PASSWORD": "s3cr3t",
  "API_KEY": "",
  "STRIPE_KEY": "your-stripe-key",
  "APP_ENV": "production"
}
```

<h2>콜론, 공백, 그 밖의 키 이름</h2>
<p>dotenv는 YAML처럼 <code>KEY: value</code>도 읽지만 콜론 뒤에 공백이 있어야 합니다. dotenv가 건너뛰는 줄은 테이블에서 오류가 되고 내보내지지 않습니다. dotenv가 받는 드문 키는 경고가 붙고 내보내기에 포함됩니다.</p>

{/* efp-check: {"status":"유효 2개, 경고 1개, 오류 2개.","rows":[[1,"ok","SERVICE_NAME",""],[2,"ok","API_URL",""],[3,"error","","일반적이지 않은 키 이름"],[4,"warn","kakao.rest-key","일반적이지 않은 키 이름"],[5,"error","","KEY=value 또는 KEY: value(콜론 뒤에 공백, 앞에는 공백 없음)로 쓰세요"]],"node":{"DB HOST":"db.internal","kakao.rest-key":"your-rest-api-key"}} */}
```
SERVICE_NAME: 예약 서비스
export API_URL: https://api.example.kr/v1
DB HOST=db.internal
kakao.rest-key=your-rest-api-key
PORT:8080
```

```json
{
  "SERVICE_NAME": "예약 서비스",
  "API_URL": "https://api.example.kr/v1",
  "kakao.rest-key": "your-rest-api-key"
}
```

<p>
  상태 줄은 "유효 2개, 경고 1개, 오류 2개."입니다. 3번째 줄은 키에 공백이 있어 dotenv의 키 패턴 <code>{'[\\w.-]+'}</code>에 맞지 않으므로 오류이고, 5번째 줄은 콜론 뒤에 공백이 없습니다.
  Node.js 자체 파서(<code>--env-file</code>, <code>util.parseEnv()</code>)는 규칙이 달라, Node.js 22.23.3은 이 텍스트에서 <code>DB HOST</code>와 <code>kakao.rest-key</code>를 읽고 콜론이 있는 세 줄은 모두 무시합니다.
</p>

<p><code>__proto__</code>라는 키만 내보내기 결과가 <code>dotenv.parse()</code>와 다릅니다. dotenv는 이 키를 버립니다.</p>

{/* efp-check: {"status":"유효 2개.","toolOnly":["__proto__"]} */}
```
__proto__=keep
A=1
```

```json
{
  "__proto__": "keep",
  "A": "1"
}
```

<h2>한글 값과 # 기호</h2>
<p>공지 제목이나 서비스 이름처럼 한글 값은 따옴표 없이 써도 됩니다. 문제가 되는 것은 값 안의 <code>#</code>입니다. 다음 예에서 2번째 줄과 3번째 줄은 같은 문구를 따옴표 없이, 그리고 따옴표로 감싸서 쓴 것입니다.</p>

{/* efp-check: {"status":"유효 3개, 경고 1개.","rows":[[1,"ok","SERVICE_NAME",""],[2,"warn","NOTICE_TITLE","# 뒤는 주석입니다. 남기려면 값을 따옴표로 감싸세요"],[3,"ok","NOTICE_BODY",""],[4,"ok","SUPPORT_TEL",""]],"node":{"NOTICE_BODY":"점검 공지#1","NOTICE_TITLE":"점검 공지","SERVICE_NAME":"예약 서비스","SUPPORT_TEL":"1588-0000"}} */}
```
SERVICE_NAME=예약 서비스
NOTICE_TITLE=점검 공지#1
NOTICE_BODY="점검 공지#1"
SUPPORT_TEL=1588-0000 # 대표번호
```

```json
{
  "SERVICE_NAME": "예약 서비스",
  "NOTICE_TITLE": "점검 공지",
  "NOTICE_BODY": "점검 공지#1",
  "SUPPORT_TEL": "1588-0000"
}
```

<p>
  상태 줄은 "유효 3개, 경고 1개."입니다. <code>SERVICE_NAME</code>은 단어 사이 공백까지 그대로 남습니다.
  <code>NOTICE_TITLE</code>은 <code>#</code> 앞에 공백이 없는데도 dotenv가 <code>#1</code>을 주석으로 보고 <code>점검 공지</code>만 남기며, 메모 열에 "# 뒤는 주석입니다. 남기려면 값을 따옴표로 감싸세요"가 표시됩니다.
  따옴표로 감싼 <code>NOTICE_BODY</code>는 <code>점검 공지#1</code>이 그대로 남습니다. <code>SUPPORT_TEL</code>처럼 공백 뒤에 붙인 <code># 대표번호</code>는 의도한 주석이라 경고 없이 잘립니다.
  Node.js 22.23.3의 <code>util.parseEnv()</code>도 이 네 줄은 같은 값으로 읽습니다.
</p>

<h2>감지되는 일반적인 .env 오류</h2>
<ul>
  <li><strong>등호 누락</strong> — <code>=</code>도 콜론도 없어 키-값 쌍으로 파싱할 수 없는 줄.</li>
  <li><strong>콜론 표기</strong> — <code>PORT:8080</code>, <code>PORT : 8080</code>은 dotenv가 건너뜁니다. <code>PORT=8080</code> 또는 <code>PORT: 8080</code>으로 쓰세요.</li>
  <li><strong>빈 값</strong> — 키는 있지만 값이 비어 있음. 앱에 따라 런타임 오류가 발생할 수 있습니다.</li>
  <li><strong>중복 키</strong> — 동일한 키가 두 번 이상 등장. dotenv는 마지막 값을 쓰지만 다른 로더도 그렇다는 보장은 없습니다.</li>
  <li><strong>일반적이지 않은 키 이름</strong> — 키 이름은 영문자나 밑줄로 시작하고 영문자, 숫자, 밑줄만 쓰는 것이 안전합니다. <code>.</code>, <code>-</code>가 있거나 숫자로 시작하는 키도 dotenv는 읽습니다(경고). 공백 등이 있는 키는 읽지 않습니다(오류).</li>
  <li><strong>따옴표 없는 값 속 #</strong> — dotenv는 거기서부터 주석으로 보므로 <code>COLOR=#fff</code>는 빈 값이 되고 <code>URL=https://example.com/#top</code>은 <code>#top</code>이 사라집니다. 값을 따옴표로 감싸세요. 규칙은 <a href="https://github.com/motdotla/dotenv#what-rules-does-the-parsing-engine-follow">dotenv 파싱 규칙</a> 참고.</li>
</ul>

<h2>제한</h2>
<ul>
  <li><strong>변수를 펼치지 않습니다.</strong> <code>{'${HOME}/data'}</code>는 그대로 남습니다. dotenv-expand, Docker Compose, 일부 프레임워크는 이런 참조를 펼칩니다.</li>
  <li><strong>dotenv 규칙만 따릅니다.</strong> Node.js <code>--env-file</code>, Docker Compose의 <code>{'env_file'}</code>, Python의 python-dotenv, 셸의 <code>source</code>는 따옴표·콜론·<code>export</code>·<code>#</code>를 각자 다르게 처리합니다. 실제로 쓰는 로더로 확인하세요.</li>
  <li><strong>값은 평문으로 표시됩니다.</strong> 테이블은 시크릿을 가리지 않으므로 화면 공유에 주의하세요. 파일을 공유하기 전에 <a href="/ko/tools/secret-redactor/">API 키 마스킹 도구</a>로 값을 바꿀 수 있습니다.</li>
  <li><strong>JSON으로만 내보냅니다.</strong> YAML, 셸 <code>export</code> 줄, Kubernetes Secret으로는 내보낼 수 없으며 내려받는 파일 이름은 항상 <code>env.json</code>입니다.</li>
</ul>
