<h2>值的写法</h2>
<ul>
  <li>空字段输出 <code>NULL</code>。</li>
  <li>非空单元格全是普通数字（<code>42</code>、<code>-7</code>、<code>19.90</code>）的列不加引号。普通数字指没有前导零、没有 <code>+</code>、没有指数、最多 15 位数字。</li>
  <li>其他列一律输出带引号的字符串，其中的数字也加引号，所以 <code>02134</code>、<code>1e5</code>、19 位订单号都保持原文。</li>
  <li>所有方言都把单引号写成两个（<code>O''Brien</code>）。MySQL 还会把反斜杠加倍：MySQL 默认的 SQL 模式把字符串里的 <code>\n</code> 读成换行（<a href="https://dev.mysql.com/doc/refman/8.4/en/string-literals.html" target="_blank" rel="noopener">MySQL 8.4 Reference Manual, String Literals</a>，表 11.1）。PostgreSQL 在 <code>standard_conforming_strings</code> 开启时（9.1 起的默认值，<a href="https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-STRINGS" target="_blank" rel="noopener">PostgreSQL 4.1.2.1</a>）和 SQLite 都把反斜杠原样保存。</li>
  <li>超出表头的单元格会补上 <code>column_3</code>、<code>column_4</code> 等列，并在状态栏列出。较短的行用 <code>NULL</code> 补齐。</li>
</ul>

<h2>示例：电商订单导出到 MySQL</h2>

<p>后台导出的订单表常有这几列：19 位订单号、收货人、11 位手机号、金额、备注。选 MySQL、勾选“添加 CREATE TABLE”，表名填 <code>订单</code>：</p>

{/* sql: {"dialect":"mysql","table":"订单","mode":"batch","createTable":true} */}

<pre><code>{`订单号,收货人,手机号,金额,备注
1830000000000000001,张伟,13800138000,199.00,
1830000000000000002,李娜,13912345678,58.5,"放快递柜，谢谢"`}</code></pre>

<pre><code>{`CREATE TABLE \`订单\` (\`订单号\` TEXT, \`收货人\` TEXT, \`手机号\` BIGINT, \`金额\` DOUBLE, \`备注\` TEXT);
INSERT INTO \`订单\` (\`订单号\`, \`收货人\`, \`手机号\`, \`金额\`, \`备注\`) VALUES
  ('1830000000000000001', '张伟', 13800138000, 199.00, NULL),
  ('1830000000000000002', '李娜', 13912345678, 58.5, '放快递柜，谢谢');`}</code></pre>

<p>逐列看：</p>
<ul>
  <li><strong>订单号</strong>有 19 位，超过 15 位，整列按字符串写出，建表类型为 <code>TEXT</code>。两个订单号都原样保留，不会被舍入成同一个数。</li>
  <li><strong>手机号</strong>是 11 位、没有前导零的整数，被当作普通数字：不加引号，建表类型是 <code>BIGINT</code>（超过 2,147,483,647）。手机号不参与计算，执行前可以把这一列改成 <code>VARCHAR(11)</code>。</li>
  <li><strong>金额</strong>里的 <code>199.00</code> 原样写进 SQL。<code>DOUBLE</code> 列不记录小数位数，金额建议改用 <code>DECIMAL(10,2)</code>。</li>
  <li><strong>备注</strong>为空的那一行写成 <code>NULL</code>；全角逗号“，”不是分隔符，原样留在字符串里。</li>
</ul>
<p>中文表名和列名放在反引号里即可：MySQL 8.4 手册规定，加引号的标识符可以使用 BMP（基本多文种平面）中除 U+0000 以外的全部字符，BMP 之外的字符（如 emoji）不允许（<a href="https://dev.mysql.com/doc/refman/8.4/en/identifiers.html" target="_blank" rel="noopener">Schema Object Names</a>）。</p>

<h2>示例：引号、前导零与空字段</h2>

<p>输入（SQLite，批量模式，表名 <code>customers</code>）：</p>

{/* sql: {"dialect":"sqlite","table":"customers","mode":"batch"} */}

<pre><code>{`id,name,zip,note
1,"O'Brien, Pat",02134,
2,Lee,10001,"path C:\\new"`}</code></pre>

<pre><code>{`INSERT INTO "customers" ("id", "name", "zip", "note") VALUES
  (1, 'O''Brien, Pat', '02134', NULL),
  (2, 'Lee', '10001', 'path C:\\new');`}</code></pre>

<p>带引号的 <code>"O'Brien, Pat"</code> 保留了逗号，空的 <code>note</code> 成为 <code>NULL</code>。<code>02134</code> 让 zip 列成为文本列，所以 <code>10001</code> 也加了引号。同样的输入选 MySQL 时，反斜杠写成两个，存进去的仍是 <code>path C:\new</code>；如果服务器的 <code>sql_mode</code> 含 <code>NO_BACKSLASH_ESCAPES</code>，反斜杠就是普通字符，这时请改用 PostgreSQL 或 SQLite 的输出。</p>

<h2>上传 GBK 编码的 CSV 会怎样</h2>

<p>“上传 CSV”只读取 UTF-8。下面这个文件的内容是表头 <code>订单号,收货人</code> 加一行数据，但用 GBK 编码保存，开头两个字节是 <code>B6 A9</code>（“订”）。上传后“CSV 输入”不变，状态栏显示：</p>

{/* cts-file: {"hex":"b6a9b5a5bac52ccad5bbf5c8cb0a313833303030303030303030303030303030312cd5c5ceb0","encoding":"gbk","text":"订单号,收货人\n1830000000000000001,张伟"} */}

<pre><code>{`未载入文件：第 0 个字节（从 0 开始计）不是有效的 UTF-8，文件用的是其他编码（GBK、Big5 或 Windows-1252？）。“CSV 输入”未改动。请另存为 UTF-8（Excel 选“CSV UTF-8”）后再载入。`}</code></pre>

<p>这些字节如果硬按 UTF-8 读，每个汉字都会变成替换字符 U+FFFD（显示为 �），生成的 SQL 列名全是乱码，却不会有任何提示。所以工具在载入前先检查字节，遇到 GBK、Big5、UTF-16 或二进制文件就停下，并给出出错的字节位置。</p>

<h2>示例：CREATE TABLE</h2>

<p>勾选<strong>添加 CREATE TABLE</strong> 后，列类型按值选择：整数为 <code>INTEGER</code>（MySQL 为 <code>INT</code>，超过 2,147,483,647 为 <code>BIGINT</code>），带小数点的数字为 <code>DOUBLE PRECISION</code>（MySQL 为 <code>DOUBLE</code>，SQLite 为 <code>REAL</code>），其余为 <code>TEXT</code>。PostgreSQL：</p>

{/* sql: {"dialect":"postgresql","table":"orders","mode":"batch","createTable":true} */}

<pre><code>{`order_id,amount,paid_at
1001,19.90,2026-09-30
1002,5,`}</code></pre>

<pre><code>{`CREATE TABLE "orders" ("order_id" INTEGER, "amount" DOUBLE PRECISION, "paid_at" TEXT);
INSERT INTO "orders" ("order_id", "amount", "paid_at") VALUES
  (1001, 19.90, '2026-09-30'),
  (1002, 5, NULL);`}</code></pre>

<p>日期按字符串处理，<code>paid_at</code> 这类列请改成 <code>DATE</code> 或 <code>TIMESTAMP</code>。工具不添加主键与约束。</p>

<h2>示例：单元格比表头多</h2>

{/* sql: {"dialect":"sqlite","table":"stock","mode":"individual"} */}

<pre><code>{`sku,qty
A-1,3,fragile
B-2,5`}</code></pre>

<pre><code>{`INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('A-1', 3, 'fragile');
INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('B-2', 5, NULL);`}</code></pre>

<p>状态栏会报告补上的 <code>column_3</code>，需要正式列名时在表头行里改名即可。</p>

<h2>示例：重名表头与字段里的引号</h2>

<p>从表格软件复制的表头可能有重名，最后一格也可能是空的。每一列仍会得到自己的名字（SQLite，勾选“添加 CREATE TABLE”，表名 <code>stock</code>）：</p>

{/* sql: {"dialect":"sqlite","table":"stock","mode":"batch","createTable":true} */}

<pre><code>{`商品,数量,数量,
键盘,3,4,已打包
鼠标,5,,`}</code></pre>

<pre><code>{`CREATE TABLE "stock" ("商品" TEXT, "数量" INTEGER, "数量_2" INTEGER, "column_4" TEXT);
INSERT INTO "stock" ("商品", "数量", "数量_2", "column_4") VALUES
  ('键盘', 3, 4, '已打包'),
  ('鼠标', 5, NULL, NULL);`}</code></pre>

{/* cts-status: {"csv":"商品,数量,数量,\n键盘,3,4,已打包\n鼠标,5,,"} */}

<p>状态栏列出改过的名字：</p>

<pre><code>{`表头有重名或空名，已改名：数量 → 数量_2, "" → column_4。`}</code></pre>

<p>第二个“数量”改成 <code>数量_2</code>，空着的第 4 个表头按位置改成 <code>column_4</code>。比较名字时不区分大小写，<code>Name</code> 和 <code>name</code> 也算重名：MySQL 的列名不区分大小写（<a href="https://dev.mysql.com/doc/refman/8.4/en/identifier-case-sensitivity.html" target="_blank" rel="noopener">MySQL 8.4, Identifier Case Sensitivity</a>），SQLite 也不接受同一张表里同时有 <code>"Name"</code> 和 <code>"name"</code>。PostgreSQL 加引号的列名区分大小写，但工具按同一规则改名，三种方言输出的列名相同。新名字不会占用表头里已有的名字：<code>a,a,a_2</code> 得到 <code>a</code>、<code>a_3</code>、<code>a_2</code>。</p>

{/* sql: {"dialect":"sqlite","table":"stock","mode":"batch","createTable":true} */}

<pre><code>{`商品,尺寸
显示器,27" 宽屏`}</code></pre>

<pre><code>{`CREATE TABLE "stock" ("商品" TEXT, "尺寸" TEXT);
INSERT INTO "stock" ("商品", "尺寸") VALUES
  ('显示器', '27" 宽屏');`}</code></pre>

<p>只有字段开头的双引号才开启引号字段。没加引号的字段中间出现的引号（如表示英寸的 <code>{'27"'}</code>）按普通字符保留。引号字段始终没有闭合时，转换会停下：</p>

{/* cts-status: {"csv":"sku,note\nA-1,\"fragile\nB-2,ok"} */}

<pre><code>{`sku,note
A-1,"fragile
B-2,ok`}</code></pre>

<pre><code>{`第 2 行开始的引号字段没有闭合。请补上结尾的 "，或删掉开头的 "。`}</code></pre>

<p>行号按“CSV 输入”里的行数计算，开头的空行也算在内。补好引号之前，SQL 输出保持为空。</p>

<h2>限制</h2>
<ul>
  <li>分隔符只支持半角逗号，第一行总是表头。分号或制表符分隔的文件需要先转换。</li>
  <li>类型只根据文本判断，日期、布尔值和 <code>1e5</code> 都按字符串处理；全角数字（如 <code>１２</code>）也是字符串。</li>
  <li>表名和列名作为单个标识符加引号，<code>public.users</code> 会成为一个含点号的名字。</li>
  <li>重名表头（不区分大小写）依次改成 <code>_2</code>、<code>_3</code>，空表头改成 <code>column_N</code>，状态栏会列出；其余名字原样使用，包括其中的空格。MySQL 的列名不能以空格结尾。</li>
  <li>引号字段没有闭合时，转换停下并给出起始行号；未加引号的字段中间的引号按普通字符保留。</li>
  <li>输入只去掉 BOM、开头的空行和末尾的换行，表头与单元格首尾的空格原样保留。</li>
  <li>大文件在浏览器标签页中一次性转换；上百万行请用数据库自带的批量导入（<code>LOAD DATA</code>、<code>COPY</code>、<code>.import</code>）。</li>
</ul>
