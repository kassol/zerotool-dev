<h2>値の書き方</h2>
<ul>
  <li>空のフィールドは <code>NULL</code> になります。</li>
  <li>空でないセルがすべて普通の数値（<code>42</code>、<code>-7</code>、<code>19.90</code>）の列は引用符なしで出力します。普通の数値とは、先頭のゼロ・<code>+</code>・指数がなく、15 桁以内のものです。</li>
  <li>それ以外の列は数値も含めてすべて引用符付きの文字列にするので、<code>02134</code>、<code>1e5</code>、20 桁のカード番号も元の文字のまま残ります。</li>
  <li>単一引用符はどの方言でも 2 つ重ねます（<code>O''Brien</code>）。MySQL ではバックスラッシュも 2 つにします。MySQL の既定の SQL モードは文字列中の <code>\n</code> を改行として読むためです（<a href="https://dev.mysql.com/doc/refman/8.4/en/string-literals.html" target="_blank" rel="noopener">MySQL 8.4 Reference Manual, String Literals</a>、表 11.1）。<code>standard_conforming_strings</code> が有効な PostgreSQL（9.1 以降の既定、<a href="https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-STRINGS" target="_blank" rel="noopener">PostgreSQL 4.1.2.1</a>）と SQLite は、バックスラッシュをそのまま保存します。</li>
  <li>ヘッダーより多いセルには <code>column_3</code>、<code>column_4</code> などの列を追加し、ステータス行に表示します。短い行は <code>NULL</code> で埋めます。</li>
</ul>

<h2>例：郵便番号と全角数字が混ざった在庫表（PostgreSQL）</h2>

<p>住所は zipcloud「<a href="https://zipcloud.ibsnet.co.jp/doc/api" target="_blank" rel="noopener">郵便番号検索API</a>」のレスポンスサンプル（郵便番号 <code>0790177</code>）のものです。在庫数の 1 行目は、IME の全角モードのまま入力した <code>１２</code> になっています。PostgreSQL、「CREATE TABLE を追加」あり、テーブル名 <code>店舗在庫</code> で変換します。</p>

{/* sql: {"dialect":"postgresql","table":"店舗在庫","mode":"batch","createTable":true} */}

<pre><code>{`郵便番号,住所,在庫数
0790177,北海道美唄市上美唄町協和,１２
0790177,北海道美唄市上美唄町南,3`}</code></pre>

<pre><code>{`CREATE TABLE "店舗在庫" ("郵便番号" TEXT, "住所" TEXT, "在庫数" TEXT);
INSERT INTO "店舗在庫" ("郵便番号", "住所", "在庫数") VALUES
  ('0790177', '北海道美唄市上美唄町協和', '１２'),
  ('0790177', '北海道美唄市上美唄町南', '3');`}</code></pre>

<ul>
  <li>郵便番号は先頭が 0 なので文字列のままで、<code>0790177</code> の 0 は消えません。</li>
  <li>全角の <code>１２</code> は普通の数値ではありません。そのため在庫数の列全体が文字列になり、半角の <code>3</code> も <code>'3'</code> と書かれ、型も <code>TEXT</code> です。数値の列にしたいときは、変換前に全角数字を半角に直してください。</li>
  <li>日本語のテーブル名と列名は二重引用符で囲んで使えます。PostgreSQL の文書では、引用符付きの識別子にはコード 0 の文字以外のすべての文字を使えます（<a href="https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-IDENTIFIERS" target="_blank" rel="noopener">PostgreSQL 4.1.1 Identifiers and Key Words</a>）。</li>
</ul>

<h2>例：引用符・先頭のゼロ・空のフィールド</h2>

<p>入力（SQLite、バッチモード、テーブル名 <code>customers</code>）：</p>

{/* sql: {"dialect":"sqlite","table":"customers","mode":"batch"} */}

<pre><code>{`id,name,zip,note
1,"O'Brien, Pat",02134,
2,Lee,10001,"path C:\\new"`}</code></pre>

<pre><code>{`INSERT INTO "customers" ("id", "name", "zip", "note") VALUES
  (1, 'O''Brien, Pat', '02134', NULL),
  (2, 'Lee', '10001', 'path C:\\new');`}</code></pre>

<p>引用符付きの <code>"O'Brien, Pat"</code> はカンマを含んだまま、空の <code>note</code> は <code>NULL</code> になります。同じ入力で MySQL を選ぶとバックスラッシュが 2 つになり、保存される値は <code>path C:\new</code> のままです。</p>

{/* sql: {"dialect":"mysql","table":"customers","mode":"batch"} */}

<pre><code>{`id,name,zip,note
1,"O'Brien, Pat",02134,
2,Lee,10001,"path C:\\new"`}</code></pre>

<pre><code>{`INSERT INTO \`customers\` (\`id\`, \`name\`, \`zip\`, \`note\`) VALUES
  (1, 'O''Brien, Pat', '02134', NULL),
  (2, 'Lee', '10001', 'path C:\\\\new');`}</code></pre>

<p>サーバーの <code>sql_mode</code> に <code>NO_BACKSLASH_ESCAPES</code> が入っている場合、バックスラッシュは普通の文字です。そのサーバーには PostgreSQL か SQLite の出力を使ってください。</p>

<h2>Shift_JIS の CSV をアップロードしたとき</h2>

<p>次のファイルは中身が <code>id,氏名</code> と 1 行のデータですが、Shift_JIS で保存されています。「氏」は <code>8E 81</code> の 2 バイトで、先頭の <code>id,</code> の後、3 バイト目（0 から数えて）にあります。アップロードしても「CSV 入力」は変わらず、ステータスには次のように表示されます。</p>

{/* cts-file: {"hex":"69642c8e8196bc0a312c8e529363","encoding":"shift_jis","text":"id,氏名\n1,山田"} */}

<pre><code>{`ファイルを読み込みませんでした：3 バイト目（0 から数えて）が UTF-8 として正しくないため、別の文字コード（Shift_JIS など）のファイルです。「CSV 入力」は変わっていません。UTF-8 で保存し直して（Excel では「CSV UTF-8」）から読み込んでください。`}</code></pre>

<p>このバイト列をそのまま UTF-8 として読むと、日本語は置換文字 U+FFFD（� と表示）に変わり、列名が文字化けした SQL が警告なしにできてしまいます。そこで読み込む前にバイトを確認し、Shift_JIS、UTF-16、バイナリのファイルは止めて、問題のバイトの位置を示します。</p>

<h2>例：CREATE TABLE</h2>

<p><strong>CREATE TABLE を追加</strong>を選ぶと、列の型を値から決めます。整数は <code>INTEGER</code>（MySQL は <code>INT</code>、2,147,483,647 を超えると <code>BIGINT</code>）、小数点を含む数値は <code>DOUBLE PRECISION</code>（MySQL は <code>DOUBLE</code>、SQLite は <code>REAL</code>）、それ以外は <code>TEXT</code> です。PostgreSQL の例：</p>

{/* sql: {"dialect":"postgresql","table":"orders","mode":"batch","createTable":true} */}

<pre><code>{`order_id,amount,paid_at
1001,19.90,2026-09-30
1002,5,`}</code></pre>

<pre><code>{`CREATE TABLE "orders" ("order_id" INTEGER, "amount" DOUBLE PRECISION, "paid_at" TEXT);
INSERT INTO "orders" ("order_id", "amount", "paid_at") VALUES
  (1001, 19.90, '2026-09-30'),
  (1002, 5, NULL);`}</code></pre>

<p>型が重要な場合は実行前に直してください。金額は <code>NUMERIC</code> / <code>DECIMAL</code>、<code>paid_at</code> のような日付は <code>DATE</code> や <code>TIMESTAMP</code> が適しています。主キーや制約は付けません。</p>

<h2>例：ヘッダーよりセルが多い行</h2>

{/* sql: {"dialect":"sqlite","table":"stock","mode":"individual"} */}

<pre><code>{`sku,qty
A-1,3,fragile
B-2,5`}</code></pre>

<pre><code>{`INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('A-1', 3, 'fragile');
INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('B-2', 5, NULL);`}</code></pre>

<p>追加した <code>column_3</code> はステータス行に表示されます。正式な列名にしたい場合はヘッダー行で名前を付けてください。</p>

<h2>制限事項</h2>
<ul>
  <li>区切り文字は半角カンマだけで、1 行目は常にヘッダーです。セミコロンやタブ区切りのファイルは先に変換してください。</li>
  <li>型は文字列から推測するだけです。日付、真偽値、<code>1e5</code>、全角数字は文字列として扱います。</li>
  <li>テーブル名と列名は 1 つの識別子として囲むので、<code>public.users</code> はドットを含む 1 つの名前になります。</li>
  <li>ヘッダーの名前はそのまま使います。同じ名前の列が 2 つあると、データベースが受け付けない SQL になります（SQLite では <code>duplicate column name</code>）。空のヘッダーセルは空の名前 <code>{'""'}</code> になります。MySQL の列名は末尾を空白にできません。</li>
  <li>引用符で囲んでいないフィールドの途中に二重引用符（例：<code>{'5" pipe'}</code>）があると、そこから引用符付きフィールドとして読みます。閉じられない引用符があると、残りのすべてが 1 つの値に入ります。どちらもエラーにならないので、出力の行数がファイルと同じか確認してください。</li>
  <li>入力全体の先頭と末尾の空白・改行は取り除くため、最初のヘッダーの先頭や最後のセルの末尾にある空白は残りません。</li>
  <li>大きなファイルもブラウザーのタブ内で一度に変換します。数百万行ならデータベースの一括読み込み（<code>LOAD DATA</code>、<code>COPY</code>、<code>.import</code>）を使ってください。</li>
</ul>
