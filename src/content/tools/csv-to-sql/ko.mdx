<h2>값을 쓰는 방식</h2>
<ul>
  <li>빈 필드는 <code>NULL</code>이 됩니다.</li>
  <li>비어 있지 않은 셀이 모두 일반 숫자(<code>42</code>, <code>-7</code>, <code>19.90</code>)인 열은 따옴표 없이 씁니다. 일반 숫자는 앞자리 0, <code>+</code>, 지수가 없고 15자리 이하인 숫자입니다.</li>
  <li>그 밖의 열은 숫자까지 모두 따옴표로 감싼 문자열로 쓰므로 <code>02134</code>, <code>1e5</code>, 20자리 카드 번호도 원래 글자 그대로 남습니다. 대상 열이 숫자 타입이면 MySQL, PostgreSQL, SQLite 모두 따옴표로 감싼 숫자를 변환해 저장합니다.</li>
  <li>작은따옴표는 모든 방언에서 두 개로 씁니다(<code>O''Brien</code>). MySQL에서는 백슬래시도 두 개로 씁니다. MySQL 기본 SQL 모드는 문자열 안의 <code>\n</code>을 줄바꿈으로 읽기 때문입니다(<a href="https://dev.mysql.com/doc/refman/8.4/en/string-literals.html" target="_blank" rel="noopener">MySQL 8.4 Reference Manual, String Literals</a>, 표 11.1). <code>standard_conforming_strings</code>가 켜진 PostgreSQL(9.1부터 기본값, <a href="https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-STRINGS" target="_blank" rel="noopener">PostgreSQL 4.1.2.1</a>)과 SQLite는 백슬래시를 그대로 저장합니다.</li>
  <li>헤더보다 많은 셀에는 <code>column_3</code>, <code>column_4</code> 같은 열을 추가하고 상태 표시줄에 알려 줍니다. 짧은 행은 <code>NULL</code>로 채웁니다.</li>
</ul>

<h2>예시: 따옴표, 앞자리 0, 빈 필드</h2>

<p>입력(SQLite, 배치 모드, 테이블명 <code>customers</code>):</p>

{/* sql: {"dialect":"sqlite","table":"customers","mode":"batch"} */}

<pre><code>{`id,name,zip,note
1,"O'Brien, Pat",02134,
2,Lee,10001,"path C:\\new"`}</code></pre>

<pre><code>{`INSERT INTO "customers" ("id", "name", "zip", "note") VALUES
  (1, 'O''Brien, Pat', '02134', NULL),
  (2, 'Lee', '10001', 'path C:\\new');`}</code></pre>

<p>따옴표로 감싼 <code>"O'Brien, Pat"</code>은 쉼표를 유지하고, 빈 <code>note</code>는 <code>NULL</code>이 됩니다. <code>02134</code> 때문에 zip 열은 문자열 열이 되어 <code>10001</code>도 따옴표로 감쌉니다. SQLite 3에서 실행하면 <code>SELECT zip FROM customers</code>가 <code>02134</code>와 <code>10001</code>을 돌려줍니다.</p>

<p>같은 입력에서 MySQL을 고르면 백슬래시가 두 개가 되어 저장되는 값은 그대로 <code>path C:\new</code>입니다.</p>

{/* sql: {"dialect":"mysql","table":"customers","mode":"batch"} */}

<pre><code>{`id,name,zip,note
1,"O'Brien, Pat",02134,
2,Lee,10001,"path C:\\new"`}</code></pre>

<pre><code>{`INSERT INTO \`customers\` (\`id\`, \`name\`, \`zip\`, \`note\`) VALUES
  (1, 'O''Brien, Pat', '02134', NULL),
  (2, 'Lee', '10001', 'path C:\\\\new');`}</code></pre>

<p>서버의 <code>sql_mode</code>에 <code>NO_BACKSLASH_ESCAPES</code>가 있으면 백슬래시는 일반 문자입니다. 그런 서버에는 PostgreSQL이나 SQLite 출력을 쓰세요.</p>

<h2>예시: CREATE TABLE</h2>

<p><strong>CREATE TABLE 추가</strong>를 켜면 값에 따라 열 타입을 정합니다. 정수는 <code>INTEGER</code>(MySQL은 <code>INT</code>, 2,147,483,647을 넘으면 <code>BIGINT</code>), 소수점이 있는 숫자는 <code>DOUBLE PRECISION</code>(MySQL은 <code>DOUBLE</code>, SQLite는 <code>REAL</code>), 나머지는 <code>TEXT</code>입니다. PostgreSQL 예:</p>

{/* sql: {"dialect":"postgresql","table":"orders","mode":"batch","createTable":true} */}

<pre><code>{`order_id,amount,paid_at
1001,19.90,2026-09-30
1002,5,`}</code></pre>

<pre><code>{`CREATE TABLE "orders" ("order_id" INTEGER, "amount" DOUBLE PRECISION, "paid_at" TEXT);
INSERT INTO "orders" ("order_id", "amount", "paid_at") VALUES
  (1001, 19.90, '2026-09-30'),
  (1002, 5, NULL);`}</code></pre>

<p>타입이 중요하면 실행 전에 고치세요. 금액은 <code>NUMERIC</code> / <code>DECIMAL</code>, <code>paid_at</code> 같은 날짜는 <code>DATE</code>나 <code>TIMESTAMP</code>가 맞습니다. 기본 키와 제약 조건은 붙이지 않습니다.</p>

<h2>예시: 헤더보다 셀이 많은 행</h2>

{/* sql: {"dialect":"sqlite","table":"stock","mode":"individual"} */}

<pre><code>{`sku,qty
A-1,3,fragile
B-2,5`}</code></pre>

<pre><code>{`INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('A-1', 3, 'fragile');
INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('B-2', 5, NULL);`}</code></pre>

<p>추가된 <code>column_3</code>은 상태 표시줄에 나옵니다. 정식 이름이 필요하면 헤더 행에서 이름을 붙이세요.</p>

<h2>제한 사항</h2>
<ul>
  <li>구분자는 쉼표만 지원하며 첫 행은 항상 헤더입니다. 세미콜론이나 탭으로 구분된 파일은 먼저 변환하세요.</li>
  <li>타입은 글자만 보고 추측합니다. 날짜, 불리언, <code>1e5</code>는 문자열로 처리합니다.</li>
  <li>테이블명과 열 이름은 하나의 식별자로 감싸므로 <code>public.users</code>는 점이 들어간 이름 하나가 됩니다.</li>
  <li>큰 파일도 브라우저 탭에서 한 번에 변환합니다. 수백만 행이라면 데이터베이스의 대량 적재 기능(<code>LOAD DATA</code>, <code>COPY</code>, <code>.import</code>)을 쓰세요.</li>
</ul>
