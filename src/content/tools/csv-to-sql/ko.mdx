<h2>값을 쓰는 방식</h2>
<ul>
  <li>빈 필드는 <code>NULL</code>이 됩니다.</li>
  <li>비어 있지 않은 셀이 모두 일반 숫자(<code>42</code>, <code>-7</code>, <code>19.90</code>)인 열은 따옴표 없이 씁니다. 일반 숫자는 앞자리 0, <code>+</code>, 지수가 없고 15자리 이하인 숫자입니다.</li>
  <li>그 밖의 열은 숫자까지 모두 따옴표로 감싼 문자열로 쓰므로 <code>02134</code>, <code>1e5</code>, 20자리 카드 번호도 원래 글자 그대로 남습니다.</li>
  <li>작은따옴표는 모든 방언에서 두 개로 씁니다(<code>O''Brien</code>). MySQL에서는 백슬래시도 두 개로 씁니다. MySQL 기본 SQL 모드는 문자열 안의 <code>\n</code>을 줄바꿈으로 읽기 때문입니다(<a href="https://dev.mysql.com/doc/refman/8.4/en/string-literals.html" target="_blank" rel="noopener">MySQL 8.4 Reference Manual, String Literals</a>, 표 11.1). <code>standard_conforming_strings</code>가 켜진 PostgreSQL(9.1부터 기본값, <a href="https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-STRINGS" target="_blank" rel="noopener">PostgreSQL 4.1.2.1</a>)과 SQLite는 백슬래시를 그대로 저장합니다.</li>
  <li>헤더보다 많은 셀에는 <code>column_3</code>, <code>column_4</code> 같은 열을 추가하고 상태 표시줄에 알려 줍니다. 짧은 행은 <code>NULL</code>로 채웁니다.</li>
</ul>

<h2>예시: 회원 목록을 SQLite로</h2>

<p>회원 관리 화면에서 내려받은 목록이라고 가정한 예입니다. 휴대폰 번호는 하이픈 없이 <code>010</code>으로 시작하고, 포인트에는 천 단위 쉼표가 들어 있어 따옴표로 감싸 있습니다. SQLite, 개별 INSERT, CREATE TABLE 추가, 테이블명 <code>회원</code>으로 변환합니다.</p>

{/* sql: {"dialect":"sqlite","table":"회원","mode":"individual","createTable":true} */}

<pre><code>{`이름,휴대폰,가입일,포인트
김민수,01012345678,2026-03-02,"1,250"
이서연,01098765432,2026-03-05,300`}</code></pre>

<pre><code>{`CREATE TABLE "회원" ("이름" TEXT, "휴대폰" TEXT, "가입일" TEXT, "포인트" TEXT);
INSERT INTO "회원" ("이름", "휴대폰", "가입일", "포인트") VALUES ('김민수', '01012345678', '2026-03-02', '1,250');
INSERT INTO "회원" ("이름", "휴대폰", "가입일", "포인트") VALUES ('이서연', '01098765432', '2026-03-05', '300');`}</code></pre>

<ul>
  <li>휴대폰 번호는 앞자리가 0이라 문자열로 남고, <code>010</code>의 0이 사라지지 않습니다.</li>
  <li><code>"1,250"</code>은 따옴표 안의 쉼표라서 한 칸으로 읽지만 일반 숫자는 아닙니다. 그래서 포인트 열 전체가 문자열이 되어 <code>300</code>도 <code>'300'</code>으로 쓰고 자료형은 <code>TEXT</code>입니다. 포인트를 숫자 열로 만들려면 변환 전에 CSV에서 천 단위 쉼표를 빼세요.</li>
  <li>가입일도 문자열입니다. SQLite에는 날짜·시간 전용 저장 클래스가 없으므로(<a href="https://www.sqlite.org/datatype3.html#date_and_time_datatype" target="_blank" rel="noopener">Datatypes In SQLite, 2.2</a>) 그대로 두거나, MySQL·PostgreSQL이라면 <code>DATE</code>로 바꾸세요.</li>
  <li>한글 테이블명과 열 이름은 큰따옴표 안에서 그대로 쓸 수 있습니다. MySQL은 백틱으로 감싸며, 따옴표로 감싼 식별자에 기본 다국어 평면(BMP)의 문자를 U+0000을 빼고 모두 쓸 수 있습니다(<a href="https://dev.mysql.com/doc/refman/8.4/en/identifiers.html" target="_blank" rel="noopener">MySQL 8.4 Reference Manual, Schema Object Names</a>).</li>
</ul>

<h2>예시: 따옴표, 앞자리 0, 빈 필드</h2>

<p>입력(SQLite, 배치 모드, 테이블명 <code>customers</code>):</p>

{/* sql: {"dialect":"sqlite","table":"customers","mode":"batch"} */}

<pre><code>{`id,name,zip,note
1,"O'Brien, Pat",02134,
2,Lee,10001,"path C:\\new"`}</code></pre>

<pre><code>{`INSERT INTO "customers" ("id", "name", "zip", "note") VALUES
  (1, 'O''Brien, Pat', '02134', NULL),
  (2, 'Lee', '10001', 'path C:\\new');`}</code></pre>

<p>따옴표로 감싼 <code>"O'Brien, Pat"</code>은 쉼표를 유지하고, 빈 <code>note</code>는 <code>NULL</code>이 됩니다. 같은 입력에서 MySQL을 고르면 백슬래시를 두 개로 써서 저장되는 값은 그대로 <code>path C:\new</code>입니다. 서버의 <code>sql_mode</code>에 <code>NO_BACKSLASH_ESCAPES</code>가 있으면 백슬래시는 일반 문자이므로, 그런 서버에는 PostgreSQL이나 SQLite 출력을 쓰세요.</p>

<h2>EUC-KR로 저장한 CSV를 올리면</h2>

<p>다음 파일의 내용은 <code>id,이름</code>과 데이터 한 행이지만 EUC-KR로 저장되어 있습니다. ‘이’는 <code>C0 CC</code> 두 바이트이고, 앞의 <code>id,</code> 다음인 3번째 바이트(0부터 셈)에서 시작합니다. 업로드해도 CSV 입력은 바뀌지 않고 상태 표시줄에 이렇게 나옵니다.</p>

{/* cts-file: {"hex":"69642cc0ccb8a70a312cb1e8b9cebcf6","encoding":"euc-kr","text":"id,이름\n1,김민수"} */}

<pre><code>{`파일을 불러오지 않았습니다: 3번째 바이트(0부터 셈)가 올바른 UTF-8이 아니어서 다른 인코딩(EUC-KR, CP949 등)의 파일입니다. CSV 입력은 바뀌지 않았습니다. UTF-8로 다시 저장한 뒤(Excel에서는 ‘CSV UTF-8’) 불러오세요.`}</code></pre>

<p>이 바이트를 UTF-8로 억지로 읽으면 한글이 대체 문자 U+FFFD(�로 표시)로 바뀌고, 열 이름이 깨진 SQL이 아무 경고 없이 만들어집니다. 그래서 불러오기 전에 바이트를 검사하고 EUC-KR, UTF-16, 바이너리 파일이면 멈춘 뒤 문제가 된 바이트 위치를 알려 줍니다.</p>

<h2>예시: CREATE TABLE</h2>

<p><strong>CREATE TABLE 추가</strong>를 켜면 값에 따라 열 타입을 정합니다. 정수는 <code>INTEGER</code>(MySQL은 <code>INT</code>, 2,147,483,647을 넘으면 <code>BIGINT</code>), 소수점이 있는 숫자는 <code>DOUBLE PRECISION</code>(MySQL은 <code>DOUBLE</code>, SQLite는 <code>REAL</code>), 나머지는 <code>TEXT</code>입니다. PostgreSQL 예:</p>

{/* sql: {"dialect":"postgresql","table":"orders","mode":"batch","createTable":true} */}

<pre><code>{`order_id,amount,paid_at
1001,19.90,2026-09-30
1002,5,`}</code></pre>

<pre><code>{`CREATE TABLE "orders" ("order_id" INTEGER, "amount" DOUBLE PRECISION, "paid_at" TEXT);
INSERT INTO "orders" ("order_id", "amount", "paid_at") VALUES
  (1001, 19.90, '2026-09-30'),
  (1002, 5, NULL);`}</code></pre>

<p>타입이 중요하면 실행 전에 고치세요. 금액은 <code>NUMERIC</code> / <code>DECIMAL</code>, <code>paid_at</code> 같은 날짜는 <code>DATE</code>나 <code>TIMESTAMP</code>가 맞습니다. 기본 키와 제약 조건은 붙이지 않습니다.</p>

<h2>예시: 헤더보다 셀이 많은 행</h2>

{/* sql: {"dialect":"sqlite","table":"stock","mode":"individual"} */}

<pre><code>{`sku,qty
A-1,3,fragile
B-2,5`}</code></pre>

<pre><code>{`INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('A-1', 3, 'fragile');
INSERT INTO "stock" ("sku", "qty", "column_3") VALUES ('B-2', 5, NULL);`}</code></pre>

<p>추가된 <code>column_3</code>은 상태 표시줄에 나옵니다. 정식 이름이 필요하면 헤더 행에서 이름을 붙이세요.</p>

<h2>제한 사항</h2>
<ul>
  <li>구분자는 반각 쉼표만 지원하며 첫 행은 항상 헤더입니다. 세미콜론이나 탭으로 구분된 파일은 먼저 변환하세요.</li>
  <li>타입은 글자만 보고 추측합니다. 날짜, 불리언, <code>1e5</code>, 천 단위 쉼표가 있는 숫자는 문자열로 처리합니다.</li>
  <li>테이블명과 열 이름은 하나의 식별자로 감싸므로 <code>public.users</code>는 점이 들어간 이름 하나가 됩니다.</li>
  <li>헤더 이름은 쓴 그대로 사용합니다. 같은 이름의 열이 두 개 있으면 데이터베이스가 거부하는 SQL이 됩니다(SQLite에서는 <code>duplicate column name</code>). 빈 헤더 칸은 빈 이름 <code>{'""'}</code>이 됩니다. MySQL의 열 이름은 공백으로 끝날 수 없습니다.</li>
  <li>따옴표로 감싸지 않은 필드 중간에 큰따옴표(예: <code>{'5" pipe'}</code>)가 있으면 거기서부터 따옴표 필드로 읽습니다. 닫히지 않는 따옴표가 있으면 나머지 내용 전체가 값 하나로 들어갑니다. 두 경우 모두 오류가 나지 않으므로 출력 행 수가 파일과 같은지 확인하세요.</li>
  <li>입력 전체의 맨 앞과 맨 뒤 공백·줄바꿈은 지우므로 첫 헤더 앞이나 마지막 셀 뒤의 공백은 남지 않습니다.</li>
  <li>큰 파일도 브라우저 탭에서 한 번에 변환합니다. 수백만 행이라면 데이터베이스의 대량 적재 기능(<code>LOAD DATA</code>, <code>COPY</code>, <code>.import</code>)을 쓰세요.</li>
</ul>
