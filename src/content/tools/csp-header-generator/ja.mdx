<h2>Strict CSP のスタート構成</h2>
<p>Strict プリセットは web.dev で解説されている nonce ベースの <a href="https://web.dev/articles/strict-csp" target="_blank" rel="noopener">strict CSP</a> に沿っています。HTTP ヘッダータブの出力は次のとおりです。</p>
<pre><code>{`Content-Security-Policy: default-src 'self'; script-src 'nonce-{RANDOM}' 'strict-dynamic'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests`}</code></pre>
<p><code>{"'nonce-{RANDOM}'"}</code> はプレースホルダーで、そのままでは使えません。サーバーはレスポンスごとに 128 ビット以上の新しいランダム値に置き換え、同じ値をレンダリングする各 <code>&lt;script&gt;</code> の <code>nonce="…"</code> に書き込む必要があります。ポリシーにプレースホルダーが残っている間、ツールは警告を表示します。固定の nonce を静的な設定に貼り付けないでください。一度見た人なら誰でも、注入したスクリプトで使い回せます。</p>
<p>以前のこのプリセットは <code>'self'</code> を使っていましたが、プレースホルダーに置き換えました。<code>'strict-dynamic'</code> があると、CSP Level 3 は一致する nonce かハッシュがない限り HTML パーサーが挿入したスクリプトをすべてブロックし、<code>'self'</code> やホストソースを確認しなくなります（<a href="https://www.w3.org/TR/CSP3/#strict-dynamic-usage" target="_blank" rel="noopener">CSP3 §8.2</a>）。そのため <code>script-src 'self' 'strict-dynamic'</code> だけでは、現行の Chrome・Firefox・Safari でスクリプトが 1 つも実行されません。ツールはこの組み合わせに警告を出すようになりました。nonce を設定できない静的ビルドのサイトでは、プレースホルダーを削除してハッシュ計算機で各インラインスクリプトのハッシュを追加するか、「中程度」プリセットから始めてください。</p>
<p><strong>Express (helmet)</strong> タブはレスポンスごとの処理まで出力します。<code>crypto.randomBytes(16).toString('base64')</code> を <code>res.locals.cspNonce</code> に入れるミドルウェアを追加し、<code>script-src</code> に関数を渡します。<a href="https://github.com/helmetjs/helmet#readme" target="_blank" rel="noopener">helmet の README</a> にある書き方です。テンプレート側では、この値を各 script タグに出力してください。<strong>Nginx</strong> タブはプレースホルダーを残してコメントを付けます。Nginx はアプリケーションが出力する HTML に同じ nonce を書き込めないためです。</p>

<h2>よくある落とし穴</h2>
<ul>
  <li><strong><code>'none'</code> は単独でしか効きません。</strong> 他のソースと並べると <code>'none'</code> は効果がなく、他のソースは許可されます。</li>
  <li><strong>HTTP ヘッダー専用のディレクティブがあります。</strong> <a href="https://www.w3.org/TR/CSP3/#meta-element" target="_blank" rel="noopener">CSP3 §3.3</a> では <code>&lt;meta&gt;</code> 内の <code>frame-ancestors</code>・<code>report-uri</code>・<code>sandbox</code> は無視され、Report-Only もありません。ツールは <code>&lt;meta&gt;</code> タブからこれらを除き、警告を出します。</li>
  <li><strong><code>'strict-dynamic'</code> には nonce かハッシュが必要です。</strong> ないとページ上のスクリプトがすべてブロックされます。ツールが警告します。</li>
  <li><strong>hash / nonce があると <code>'unsafe-inline'</code> は無効化されます。</strong> モダンブラウザは安全側を優先します。</li>
  <li><strong><code>default-src</code> は必ず定義すること。</strong> 未指定の fetch 系ディレクティブは <code>default-src</code> をフォールバックします。これがないと将来追加されたディレクティブにフォールバックが効きません。</li>
  <li><strong>カスタムホストにセミコロンは入れられません。</strong> セミコロンはポリシー全体を切ってしまいます。</li>
</ul>

<h2>Hash と Nonce の使い分け</h2>
<p><strong>静的なインライン内容</strong>（解析タグ、クリティカル CSS、SSR で出力される共通スクリプト）は hash を使います。静的 HTML やエッジキャッシュとも相性がよく、リクエストごとの値を必要としません。</p>
<p><strong>動的にレンダリングされる内容</strong>は nonce です。サーバーがヘッダーに <code>'nonce-XYZ'</code> を埋め込み、レンダリングする全 <code>&lt;script nonce="XYZ"&gt;</code> に同じ値を付与します。<code>'strict-dynamic'</code> と組み合わせれば、信頼されたスクリプトの子スクリプトも自動的に信頼され、巨大なホスト許可リストを保守する必要がなくなります。</p>

<h2>デプロイ早見表</h2>
<ul>
  <li><strong>Nginx</strong>：Nginx タブの内容を <code>server</code> ブロックに貼って reload。<code>always</code> はエラー応答にもヘッダーを付けます。</li>
  <li><strong>Apache</strong>：<code>.htaccess</code> や <code>httpd.conf</code> に <code>Header always set Content-Security-Policy "..."</code>。</li>
  <li><strong>Express / Node</strong>：helmet スニペットを貼り付け、<code>useDefaults</code> を必ず <code>false</code> にして自分のポリシーが helmet デフォルトと暗黙にマージされないようにします。</li>
  <li><strong>Cloudflare Pages / Vercel / Netlify</strong>：HTTP ヘッダー欄をそれぞれのヘッダー設定（<code>_headers</code>、<code>vercel.json</code>、<code>netlify.toml</code>）に貼ります。</li>
</ul>
