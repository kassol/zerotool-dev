<h2>Strict CSP starter</h2>
<p>The Strict preset follows the nonce-based <a href="https://web.dev/articles/strict-csp" target="_blank" rel="noopener">strict CSP</a> described on web.dev. The HTTP header tab shows:</p>
{/* csp-tool: {"preset":"strict","format":"header","warn":["warnNoncePlaceholder"]} */}
<pre><code>{`Content-Security-Policy: default-src 'self'; script-src 'nonce-{RANDOM}' 'strict-dynamic'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests`}</code></pre>
<p><code>{"'nonce-{RANDOM}'"}</code> is a placeholder, not a value. Your server must replace it with a new random value of at least 128 bits on every response, and write the same value into <code>nonce="…"</code> on each <code>&lt;script&gt;</code> it renders. The tool shows a warning while the placeholder is in the policy. Do not paste one fixed nonce into a static config: anyone who sees it once can reuse it in an injected script.</p>
<p>The placeholder replaces the <code>'self'</code> that earlier versions of this preset used. With <code>'strict-dynamic'</code>, CSP Level 3 blocks every script that the HTML parser inserts unless it has a matching nonce or hash, and it stops checking <code>'self'</code> and host sources (<a href="https://www.w3.org/TR/CSP3/#strict-dynamic-usage" target="_blank" rel="noopener">CSP3 §8.2</a>). So <code>script-src 'self' 'strict-dynamic'</code> on its own runs no script at all in current Chrome, Firefox and Safari, and the tool now warns about that combination. If your site is a static build that cannot set a nonce, remove the placeholder and add a hash for each inline script with the hash calculator, or start from the Moderate preset.</p>
<p>The <strong>Express (helmet)</strong> tab does the per-response part for you: it adds a middleware that stores <code>crypto.randomBytes(16).toString('base64')</code> in <code>res.locals.cspNonce</code> and passes <code>script-src</code> a function, which is the pattern in the <a href="https://github.com/helmetjs/helmet#readme" target="_blank" rel="noopener">helmet README</a>. Your templates still have to print that value on each script tag. The <strong>Nginx</strong> tab keeps the placeholder and adds a comment, because Nginx cannot put the same nonce into the HTML your application renders.</p>

<h2>Two policies built with the tool</h2>
<p><strong>A static site with one inline tag snippet.</strong> Start from Moderate, type <code>https://www.googletagmanager.com</code> into the <code>script-src</code> box, then paste the inline snippet into the hash calculator. The hash only matches if you paste exactly what sits between <code>&lt;script&gt;</code> and <code>&lt;/script&gt;</code>; this example assumes the tag contains these four lines with no leading line break:</p>
<pre><code>{`window.dataLayer = window.dataLayer || [];
function gtag(){dataLayer.push(arguments);}
gtag('js', new Date());
gtag('config', 'G-XXXXXXXXXX');`}</code></pre>
{/* csp-tool: {"preset":"moderate","sources":{"script-src":["https://www.googletagmanager.com"]},"hash":{"text":"window.dataLayer = window.dataLayer || [];\nfunction gtag(){dataLayer.push(arguments);}\ngtag('js', new Date());\ngtag('config', 'G-XXXXXXXXXX');"},"format":"header"} */}
<p>Compute &amp; add puts the SHA-256 hash into <code>script-src</code>, and the HTTP header tab shows:</p>
<pre><code>{`Content-Security-Policy: default-src 'self'; script-src 'self' https://www.googletagmanager.com 'sha256-vRtfVazNcneseB+qTMBbAh7HwesbIvuZpPyFnLearUI='; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'self'; upgrade-insecure-requests`}</code></pre>
<p>Moderate keeps <code>'unsafe-inline'</code> in <code>style-src</code> only, so the tool shows no warning for <code>script-src</code>. Indent the snippet differently, or change the measurement ID, and the hash no longer matches: compute it again from the final HTML.</p>
<p><strong>Watching before enforcing.</strong> Keep Strict, switch Mode to Report-Only, add the <code>report-uri</code> directive and type <code>/csp-reports</code> into it:</p>
{/* csp-tool: {"preset":"strict","mode":"report-only","add":["report-uri"],"sources":{"report-uri":["/csp-reports"]},"format":"header","warn":["warnUpgradeReportOnly"]} */}
<pre><code>{`Content-Security-Policy-Report-Only: default-src 'self'; script-src 'nonce-{RANDOM}' 'strict-dynamic'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; report-uri /csp-reports; upgrade-insecure-requests`}</code></pre>
<p>The browser now reports violations to <code>/csp-reports</code> and blocks nothing. The output still ends with <code>upgrade-insecure-requests</code>, but the <a href="https://www.w3.org/TR/upgrade-insecure-requests/#delivery" target="_blank" rel="noopener">Upgrade Insecure Requests</a> specification (§3.1) says this directive is ignored in a Report-Only header, and the tool shows a note saying so below the output. It starts to upgrade requests when you switch to Enforce.</p>

<h2>Common pitfalls</h2>
<ul>
  <li><strong><code>'none'</code> only works alone.</strong> If you list another source next to it, <code>'none'</code> has no effect and the other sources are allowed.</li>
  <li><strong>Some directives are HTTP only.</strong> <a href="https://www.w3.org/TR/CSP3/#meta-element" target="_blank" rel="noopener">CSP3 §3.3</a> ignores <code>frame-ancestors</code>, <code>report-uri</code> and <code>sandbox</code> in <code>&lt;meta&gt;</code>, and Report-Only mode does not exist there. The tool leaves these out of the <code>&lt;meta&gt;</code> tab and warns you.</li>
  <li><strong><code>'strict-dynamic'</code> needs a nonce or hash.</strong> Without one it blocks every script on the page; the tool flags this.</li>
  <li><strong>Hashes and nonces void <code>'unsafe-inline'</code>.</strong> Modern browsers fall back to the safer of the two when both are present.</li>
  <li><strong>Always set <code>default-src</code>.</strong> Missing fetch directives fall back to <code>default-src</code>; without it the browser applies no fallback for new directives added later.</li>
  <li><strong>Custom hosts cannot contain semicolons.</strong> A semicolon would terminate the policy and corrupt every directive after it.</li>
</ul>

<h2>Hashes vs. nonces</h2>
<p>Use <strong>hashes</strong> for static inline content that ships with the page — analytics snippets, critical CSS, server-rendered helpers. Hashes work for static HTML and edge-cached responses because they do not need any per-request value.</p>
<p>Use <strong>nonces</strong> for dynamic content rendered per request. The server emits a <code>Content-Security-Policy</code> header containing <code>'nonce-XYZ'</code> and stamps the same value on every <code>&lt;script nonce="XYZ"&gt;</code> it renders. Pair nonces with <code>'strict-dynamic'</code> so descendant scripts inherit trust without you maintaining a host allow-list.</p>

<h2>Deployment cheat sheet</h2>
<ul>
  <li><strong>Nginx</strong>: copy the Nginx tab into your <code>server</code> block and reload — the <code>always</code> flag forces the header on error responses too.</li>
  <li><strong>Apache</strong>: use <code>Header always set Content-Security-Policy "..."</code> in <code>.htaccess</code> or <code>httpd.conf</code>.</li>
  <li><strong>Express / Node</strong>: paste the helmet snippet. It sets <code>useDefaults: false</code>; keep it, or helmet adds its own default directives to your policy.</li>
  <li><strong>Cloudflare Pages / Vercel / Netlify</strong>: paste the HTTP header form into your platform's headers config (<code>_headers</code>, <code>vercel.json</code>, <code>netlify.toml</code>).</li>
</ul>

<h2>Limits</h2>
<ul>
  <li><strong>It builds a policy; it does not test one.</strong> The tool does not fetch your page, read an existing header or know which hosts a third-party script loads later. Use Report-Only and the reports to find what is missing.</li>
  <li><strong>Source checks are small.</strong> A semicolon is rejected and spaces split a value into several sources. CSP Level 3 (<a href="https://www.w3.org/TR/CSP3/#framework-directive-source-list" target="_blank" rel="noopener">§2.3.1</a>) allows only ASCII letters, digits and hyphens in a host, so a non-ASCII host is converted to punycode and the status line shows the result. Other typos, such as <code>https//cdn.example.com</code>, go into the policy as typed. Values that are not hosts are not converted: a <code>trusted-types</code> policy name must use only the characters that <a href="https://www.w3.org/TR/trusted-types/#trusted-types-csp-directive" target="_blank" rel="noopener">Trusted Types §4.2.2</a> allows, and <code>sandbox</code> tokens and <code>report-to</code> names must be ASCII; otherwise the value is refused.</li>
  <li><strong>Hashes are exact.</strong> The browser hashes the UTF-8 bytes of the script or style text (<a href="https://www.w3.org/TR/CSP3/#match-element-to-source-list" target="_blank" rel="noopener">CSP3 §6.7.3.3</a>), so one extra space or line break gives a different hash. The calculator hashes the UTF-8 bytes of what you paste.</li>
  <li><strong>Nonces need your server.</strong> The tool writes the <code>{"'nonce-{RANDOM}'"}</code> placeholder. Only the Express tab creates a new value per response; header, meta and Nginx output must be filled in by your application.</li>
  <li><strong>Retired directives.</strong> <code>prefetch-src</code> and <code>navigate-to</code> are not defined in the CSP3 Working Draft of 16 September 2026, so the tool no longer offers them; if a policy saved earlier contains them, they are removed when the page loads and the status line names them once. The <code>block-all-mixed-content</code> switch is still there, but <a href="https://www.w3.org/TR/mixed-content/#strict-checking" target="_blank" rel="noopener">Mixed Content §6.1</a> calls the directive obsolete because mixed content that cannot be upgraded is now blocked anyway, and the tool shows a note when the switch is on.</li>
  <li><strong>The policy is kept in this browser.</strong> See the privacy question below: the policy is saved in local storage and Ctrl/⌘+L does not delete it.</li>
</ul>
