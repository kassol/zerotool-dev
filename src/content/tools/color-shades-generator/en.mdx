<h2>Using Shades in Design Systems</h2>
<p>A 10-step shade scale is ideal for:</p>
<ul>
  <li><strong>Primary / accent colors:</strong> use 500 as the main brand color, lighter shades for backgrounds and hover states, darker shades for text and borders</li>
  <li><strong>State feedback:</strong> use 50–100 for tinted alert backgrounds, 700–900 for text on those backgrounds</li>
  <li><strong>Dark mode:</strong> swap scale direction — use 900 as the background and 50 as text</li>
  <li><strong>Component variants:</strong> a button's default, hover, and active states can be 500, 600, and 700 respectively</li>
</ul>

<h2>HSL Color Model Explained</h2>
<ul>
  <li><strong>Hue (H):</strong> the color angle on the color wheel, 0–360°. Red is 0°, green is 120°, blue is 240°.</li>
  <li><strong>Saturation (S):</strong> the intensity of the color. 0% is grey, 100% is fully vivid.</li>
  <li><strong>Lightness (L):</strong> 0% is black, 50% is the "pure" color, 100% is white.</li>
</ul>

## What the Generator Does With Your Color

The tool converts the base color to HSL, rounds hue and saturation to whole numbers, and keeps them. Lightness does not come from your color: every step uses a fixed value, from 96% at 50 to 10% at 900. Your exact base color therefore appears in the scale only if its lightness happens to be one of those values.

In the Output Format example above, the default color `#3b82f6` is `hsl(217, 91%, 60%)`. Its 60% lightness falls between 300 (68%) and 400 (55%), so `#3B82F6` itself is not in the list, and 500 is the darker `#0A56D1`. If you need the brand color at a fixed step, replace that step by hand after copying.

## Contrast Depends on the Hue

The same step has very different contrast for different hues, because HSL lightness is not perceived lightness. WCAG 2.2 asks for [4.5:1 for normal text and 3:1 for large text](https://www.w3.org/TR/WCAG22/#contrast-minimum). Contrast ratios of the generated steps against white text or background (`#FFFFFF`), computed with the WCAG formula:

| Step | Blue `#3b82f6` | Green `#16a34a` |
|---|---|---|
| 400 | 4.29 | 1.69 |
| 500 | 6.43 | 2.38 |
| 600 | 9.11 | 3.93 |
| 700 | 12.03 | 6.20 |
| 800 | 15.45 | 10.14 |

For blue, 500 already passes 4.5:1 on white; for green, you need 700. Check each text and background pair with the [Color Contrast Checker](/tools/color-contrast-checker/) instead of reusing one step number for every hue.

## Using the Output in Tailwind CSS

The copied variables are named `--color-50` … `--color-900`. Tailwind CSS v4 creates utilities from theme variables in `@theme`, so rename them with a color name:

```css
@import "tailwindcss";

@theme {
  --color-brand-50: #ECF3FE;
  --color-brand-500: #0A56D1;
  --color-brand-900: #021431;
}
```

This gives you `bg-brand-500`, `text-brand-900` and so on ([Tailwind CSS: Theme variables](https://tailwindcss.com/docs/theme)). In Tailwind v3, put the same values under `theme.extend.colors.brand` in `tailwind.config.js`.

## Limits

- **10 steps, 50–900.** Tailwind's own palette has 11 steps and adds 950 ([Tailwind CSS: Colors](https://tailwindcss.com/docs/colors)); the generator has no 950.
- **Fixed lightness values**, so the base color's own lightness is ignored (see above), and very light or very dark inputs give the same lightness range as any other color.
- **HSL, not a perceptual space.** Tailwind v4 defines its palette in OKLCH; the steps here are not perceptually even across hues.
- **Input is `#RRGGBB` only.** Three-digit hex (`#39f`), `rgb()` and `hsl()` are not accepted; the color picker always gives six digits.
- **Variable names are fixed** to `--color-{step}`.
