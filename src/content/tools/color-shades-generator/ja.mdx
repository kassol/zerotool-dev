## スケールの作り方

入力した色を OKLCH（Oklab 空間の明度・彩度・色相。[CSS Color 4 §9.2](https://www.w3.org/TR/css-color-4/#ok-lab)）に変換し、[Tailwind CSS のデフォルトパレット](https://tailwindcss.com/docs/colors)と同じ 50〜950 の 11 段階を作ります。

- **明度**：Tailwind v4 のパレットのうち、500 の色相が入力に近い 2 つを色相で補間した明度の並びを使います。Tailwind の黄色はどの段階でも青より明るく、色相ごとに並びが違うためです。グレーやグレーに近い色は、9 つのニュートラルパレットの中央値を使います。並び全体を伸縮させて、入力した色の明度をちょうど通るようにします。
- **彩度**：同じパレットの曲線にならい、50 で低く、400〜600 付近でいちばん高く、950 に向かって下がります。
- **色相**：入力した値のまま変えません（「色相シフト」を設定した場合を除く）。
- **sRGB の外に出る段階**：明度と色相を保って彩度だけを下げます（[CSS Color 4 §14](https://www.w3.org/TR/css-color-4/#gamut-mapping)）。

入力した色は 1 バイトも変えずにその段階へ入ります。「自動」では 50 から 950 まで明度も WCAG の相対輝度も段階ごとに下がるので、番号が小さいほど必ず明るい色です。

## 例：デジタル庁デザインシステムの Blue-500 から作る

[デジタル庁デザインシステム](https://design.digital.go.jp/dads/foundations/color/)は、プライマリーカラーに「主要な背景色とのコントラスト比が少なくとも 4.5:1 以上」を求めています。npm パッケージ `@digital-go-jp/design-tokens` 2.0.1 のプリミティブカラー Blue-500 は `#4979f5` です。これをベースカラーにすると次のスケールになります。

{/* csg-scale: {"input":"#4979f5"} */}

| 段階 | HEX | 白文字 |
|---|---|---|
| 50 | `#f0f4fe` | 1.10 |
| 100 | `#dfe8fc` | 1.22 |
| 200 | `#c6d7fb` | 1.44 |
| 300 | `#a0bdfc` | 1.87 |
| 400 | `#6f99f9` | 2.76 |
| 500 | `#4979f5` | 3.93 |
| 600 | `#2c5cea` | 5.48 |
| 700 | `#204ad2` | 7.06 |
| 800 | `#1c3fa8` | 9.02 |
| 900 | `#1e3983` | 10.66 |
| 950 | `#14244e` | 15.08 |

`#4979f5` 自体は白背景に対して 3.93:1 なので、白背景のサイトでプライマリーにするなら 4.5:1 を超える 600（`#2c5cea`、5.48:1）以降を選びます。同じパッケージの Blue は 50〜1200 の 13 段階で、Blue-600 の `#3460fb` は 4.98:1 です。段階の数も明度も違うので、このツールの出力をそのまま置き換えに使うことはできません。

デジタル庁デザインシステムのグレーは段階番号がコントラストの境目を示しています。カラーパレットのページによれば、Gray-420 が白に対して 3:1、Gray-536 が 4.5:1 を確保できる色です。トークン値はそれぞれ `#949494`（このツールの計算で 3.03:1）と `#767676`（4.54:1）です。Tailwind 式の 50〜950 にはこういう意味がないため、カードの数値で確かめます。

## 書き出し：oklch() の CSS 変数

書き出し形式を「CSS 変数」、値を「OKLCH」、名前を `key` にすると、次のように出力されます。

{/* csg: {"input":"#4979f5","export":"css","values":"oklch","name":"key"} */}
```css
:root {
  /* base: key-500 */
  --key-50: oklch(96.7% 0.01404 268.49);
  --key-100: oklch(93.02% 0.02883 266.37);
  --key-200: oklch(87.8% 0.05321 265.29);
  --key-300: oklch(80% 0.0954 265.21);
  --key-400: oklch(69.54% 0.14892 264.94);
  --key-500: oklch(60.94% 0.19319 265.17);
  --key-600: oklch(53.42% 0.22056 265.11);
  --key-700: oklch(47.62% 0.21362 265.24);
  --key-800: oklch(41.53% 0.17329 265.16);
  --key-900: oklch(37.09% 0.12901 265.36);
  --key-950: oklch(27.31% 0.08029 265.66);
}
```

彩度を小数点以下 5 桁まで出しているのは、読み戻したときに必ず同じ 8 ビットの色に戻るようにするためです（4 桁だと約 400 色に 1 色が 1 段ずれます）。回帰テストでは、CSS を PostCSS、Tailwind v4 を Tailwind 4.3.3 のコンパイラ、SCSS を Dart Sass 1.105、JSON を `JSON.parse` で読み、すべての値がカードの色と一致することを確認しています。

## コントラスト比はカードの数値で確認

Tailwind は色相によって明度を変えていて、このツールもそれに従います。そのため同じ段階でも色相によってコントラスト比が違います。

{/* csg-contrast: {"inputs":["#4979f5","#e4007f"]} */}

| 段階 | 青 `#4979f5` | マゼンタ `#e4007f` |
|---|---|---|
| 500 | 3.93 | 3.52 |
| 600 | 5.48 | 4.56 |
| 700 | 7.06 | 5.98 |

基準は WCAG 2.2 の[本文 4.5:1、大きな文字 3:1](https://www.w3.org/TR/WCAG22/#contrast-minimum)です。文字色と背景色の組み合わせごとの確認は[カラーコントラストチェッカー](/ja/tools/color-contrast-checker/)でできます。

## ほかの生成ツールとの比較

2026-10-01 に `#1a73e8` で試した結果です。

- **uicolors.app** は 700 に入れ、明るい段階の色相を空色側へ約 24 度ずらしました。CSS・SCSS の書き出しと OKLCH・HSL・RGB の値は有料プランです。
- **tints.dev** は既定で 500 に入れます。書き出した `oklch()` では 50 の色相が 500 より約 18 度大きく、明るい段階が紫寄りになります。
- **このツール**は明度がいちばん近い 600 に入れ、各段階の色相のずれは 2 度以内でした。書き出しはすべて無料です。

## 制限

- **出力は sRGB のみ**です。Display P3 は出力しません。Tailwind v4 のパレットには sRGB の外の色があり、P3 対応の画面ではここで出す HEX より鮮やかに見えます。
- **段階は 50〜950 の 11 段階で固定**です。デジタル庁デザインシステムのような 13 段階や、独自の段階名は作れません。
- **位置を固定すると段階が重なることがあります**。白を 500 に固定すると 100〜500 がすべて白になり、ステータス行に重なった段階を表示します。
- **入力形式**は 3・4・6・8 桁の HEX、`rgb()`、`hsl()`、`oklch()` です。透明度は無視します。`blue` のような色名、`lab()`、`color()` は読み取りません。
- **Tailwind v3 と oklch()**：Tailwind CSS 3.4.19 では `bg-key-500` は使えますが、`bg-key-500/50` のような不透明度指定は oklch() の値に対して何も出力されません（2026-10-01 確認）。v3 では HEX・RGB・HSL を選んでください。
- **コントラスト比は WCAG 2.2** で、純白・純黒に対する値だけです。APCA や、段階どうしのコントラストは計算しません。

1 色ずつの形式変換は[カラーコンバーター](/ja/tools/color-converter/)、デザイントークン全体の作成は [CSS 変数ジェネレーター](/ja/tools/css-variables-generator/)が使えます。
