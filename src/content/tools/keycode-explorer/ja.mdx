<h2>event.key vs event.code vs keyCode</h2>
<p>
  フロントエンドのキーボードバグの多くはこの3つの混在が原因。リファレンス対応表：
</p>

| プロパティ | レイアウト依存 | 推奨 | QWERTY で A を押した時の値 |
|---|---|---|---|
| event.key | あり（現在のレイアウト反映） | 推奨——セマンティック判定 | "a" または Shift で "A" |
| event.code | なし（物理位置） | 推奨——ゲーム・ショートカット | "KeyA" |
| keyCode | なし | 非推奨 | 65 |
| which | なし | 非推奨 | 65 |
| charCode | なし | 非推奨——keydown 時は常に 0 | 0 |

<h2>よくある用途</h2>
<ul>
  <li><strong>キーボードハンドラのデバッグ</strong>——実際の event.key を if 条件に貼ってタイポを直す。</li>
  <li><strong>ゲームコントロール構築</strong>——event.code を使えば AZERTY でも WASD が機能する。</li>
  <li><strong>コマンドパレット実装</strong>——event.key と e.ctrlKey / e.metaKey を組み合わせる。</li>
  <li><strong>レガシーコード監査</strong>——keyCode / which を読み、旧ハンドラを event.key に移行する。</li>
  <li><strong>IME 入力中の判定</strong>——e.isComposing = true は IME 変換中。単一キーハンドラは早期 return すべき。</li>
</ul>

<h2>preventDefault の挙動</h2>
<p>
  キャプチャパッドは Tab、Space、Backspace、矢印キー、F1-F12 のみ <code>preventDefault()</code> を呼び出す——
  ブラウザがナビゲーション・ページ操作で消費するキー。Ctrl+W / Cmd+Q などのシステムショートカットは
  傍受せずブラウザのデフォルト動作を維持する。
</p>

<h2>キーボード配列と IME</h2>
<p>
  <code>event.code</code> は物理キーを US キーボード上の位置で名付けます。<a href="https://www.w3.org/TR/uievents-code/" target="_blank" rel="noopener">UI Events KeyboardEvent code Values</a> 仕様では、<code>"KeyQ"</code> は US キーボードで q、フランス語 AZERTY キーボードで a と刻印されたキーです。AZERTY で a を打つと <code>key: "a"</code>、<code>code: "KeyQ"</code> になります。キーの位置に意味があるショートカット（WASD 移動）は <code>code</code>、入力される文字に意味があるショートカット（Ctrl+Z で元に戻す）は <code>key</code> で判定してください。
</p>
<p>
  JIS 配列（106/109 キーボード）には US 配列にないキーがあり、<code>"IntlYen"</code>（¥）、<code>"IntlRo"</code>（ろ）、<code>"NonConvert"</code>（無変換）、<code>"Convert"</code>（変換）、<code>"KanaMode"</code>（カタカナ/ひらがな/ローマ字）です。パッド上で押すと、ブラウザーが返す値を確認できます。
</p>
<p>
  IME で変換中は、<a href="https://www.w3.org/TR/uievents/#determine-keydown-keyup-keyCode" target="_blank" rel="noopener">UI Events</a> の規定により keydown の <code>keyCode</code> が 229 になり、<code>isComposing</code> が <code>true</code> になります。Enter を処理する前に <code>isComposing</code> を確認しないと、変換を確定する Enter でフォームも送信されてしまいます。
</p>

<h2>制限</h2>
<ul>
  <li>スマートフォンやタブレットのソフトキーボードは、完全な keydown ではなく入力した文字を持つ <code>input</code> イベントを送るのが普通です。パッドの下の代替入力欄はその文字を <code>key</code> として表示し、<code>code</code>・<code>keyCode</code>・<code>which</code>・<code>charCode</code> は空欄にします。input イベントはどのキーを押したかを伝えないためです。</li>
  <li>Ctrl+W や Cmd+Q などはブラウザーと OS が処理するため、ページには届きません。</li>
</ul>
