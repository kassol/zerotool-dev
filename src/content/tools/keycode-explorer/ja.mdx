<h2>event.key vs event.code vs keyCode</h2>
<p>
  フロントエンドのキーボード関連のバグの多くは、この 3 つを混同することから起きます。対応表は次のとおりです。
</p>

| プロパティ | レイアウト依存 | 推奨 | QWERTY で A を押した時の値 |
|---|---|---|---|
| event.key | あり（現在のレイアウト反映） | 推奨——意味で判定 | "a" または Shift で "A" |
| event.code | なし（物理位置） | 推奨——ゲーム・ショートカット | "KeyA" |
| keyCode | なし | 非推奨 | 65 |
| which | なし | 非推奨 | 65 |
| charCode | なし | 非推奨——keydown では 0 | 0 |

<h2>JIS 配列のキーで試す</h2>

<p>以下のコードブロックは、指定したキーをパッドで押したときにツールが表示する値です。「イベントプロパティ」の一部の行と、「コピー可能な JS スニペット」を載せています。</p>

<h3>半角/全角キーの code は "Backquote"</h3>

<p><a href="https://www.w3.org/TR/uievents-code/" target="_blank" rel="noopener">UI Events KeyboardEvent code Values</a> 仕様は、<code>"Backquote"</code> を US キーボードの <code>{'`~'}</code> キーとし、日本語キーボードでは半角/全角/漢字キーがこれにあたると書いています。</p>

{/* kce-check: {"event":{"key":"Unidentified","code":"Backquote"}} */}

```
event.code  "Backquote"
```

<p>つまり、<code>code === 'Backquote'</code> で判定するショートカット（US 配列の <code>{'`'}</code> キーを想定したもの）は、JIS 配列では半角/全角キーに当たります。JIS 配列の利用者を想定するなら、入力される文字（<code>event.key</code>）で判定するか、別のキーを割り当ててください。</p>

<h3>Mac の「かな」キーは "Lang1"</h3>

<p>同じ仕様では、Mac の日本語キーボードの「かな」キーが <code>"Lang1"</code>、「英数」キーが <code>"Lang2"</code> です。韓国語キーボードの 한/영 キーと 한자 キーも同じ <code>"Lang1"</code>・<code>"Lang2"</code> なので、<code>code</code> だけでは日本語用か韓国語用かは区別できません。</p>

{/* kce-check: {"event":{"key":"Unidentified","code":"Lang1"}} */}

```
event.code  "Lang1"
```

<h3>Enter で送信するフォーム</h3>

<p>Enter をパッドで押すと、次の値とスニペットになります。</p>

{/* kce-check: {"event":{"key":"Enter","code":"Enter","keyCode":13,"which":13}} */}

```
event.key   "Enter"
event.code  "Enter"
keyCode     13
```

```js
document.addEventListener('keydown', (e) => {
  if (e.key === 'Enter') {
    // your handler
  }
});
```

<h2>変換中の Enter に注意する</h2>

<p><a href="https://support.microsoft.com/ja-jp/windows/hardware/input-devices/microsoft-japanese-ime" target="_blank" rel="noopener">Microsoft 日本語 IME</a> のサポートページは、候補ウィンドウにフォーカスがある状態で Enter キーを押すと、フォーカスされている候補を選ぶと説明しています。つまり、その Enter は変換を確定するためのもので、フォームを送信するためのものではありません。上のスニペットは <code>event.key</code> と修飾キーしか見ないので、入力欄で使うなら次のように 1 行足してください。</p>

```js
input.addEventListener('keydown', (e) => {
  if (e.isComposing || e.keyCode === 229) return;
  if (e.key === 'Enter') {
    // 送信
  }
});
```

<p>変換中は <code>isComposing</code> が <code>true</code> です。<a href="https://www.w3.org/TR/uievents/#determine-keydown-keyup-keyCode" target="_blank" rel="noopener">UI Events</a> の非規範的な旧キーコードの節には、IME がキー入力を処理しているときの keydown では <code>keyCode</code> に 229 を返すとあります。キャプチャパッドはテキスト入力欄ではないので、ここで IME が変換を始めるかどうかは環境しだいです。この 1 行の効果は、自分の入力欄で IME をオンにして確かめてください。</p>

<h2>よくある用途</h2>
<ul>
  <li><strong>キーボードハンドラーのデバッグ</strong>——実際の event.key を if 条件に貼って、つづりの誤りを直す。</li>
  <li><strong>ゲームの操作</strong>——event.code を使えば AZERTY でも WASD が同じ位置で使える。</li>
  <li><strong>コマンドパレット</strong>——event.key と e.ctrlKey / e.metaKey を組み合わせる。</li>
  <li><strong>古いコードの確認</strong>——keyCode / which を読み、古いハンドラーを event.key に移す。</li>
</ul>

<h2>preventDefault の挙動</h2>
<p>
  キャプチャパッドが <code>preventDefault()</code> を呼ぶのは Tab、Space、Backspace、矢印キー、F1-F12 だけです。どれもブラウザーが移動やページ操作に使うキーです。
  Ctrl+W / Cmd+Q などのシステムショートカットは止めず、ブラウザーの既定動作のままです。
</p>

<h2>キーボード配列と IME</h2>
<p>
  <code>event.code</code> は物理キーを US キーボード上の位置で名付けます。同じ仕様では、<code>"KeyQ"</code> は US キーボードで q、フランス語 AZERTY キーボードで a と刻印されたキーです。キーの位置に意味があるショートカット（WASD 移動）は <code>code</code>、入力される文字に意味があるショートカット（Ctrl+Z で元に戻す）は <code>key</code> で判定してください。
</p>
<p>
  JIS 配列（106/109 キーボード）には US 配列にないキーがあり、<code>"IntlYen"</code>（¥）、<code>"IntlRo"</code>（ろ）、<code>"NonConvert"</code>（無変換）、<code>"Convert"</code>（変換）、<code>"KanaMode"</code>（カタカナ/ひらがな/ローマ字）です。パッドで押すと、ブラウザーが返す値を確認できます。
</p>

<h2>制限</h2>
<ul>
  <li>スマートフォンやタブレットのソフトウェアキーボードは、完全な keydown ではなく入力した文字を持つ <code>input</code> イベントを送るのが普通です。パッドの下の代替入力欄はその文字を <code>key</code> として表示し、<code>code</code>・<code>keyCode</code>・<code>which</code>・<code>charCode</code> は空欄にします。input イベントはどのキーを押したかを伝えないためです。IME で変換中は途中の input イベントを無視し、<code>compositionend</code> の時点で確定文字列を読み取ります。これは模擬した変換イベント（日本語・韓国語・中国語ピンイン）とデスクトップの Chromium の IME エミュレーションで確認したもので、Android の実機では試していません。</li>
  <li>Ctrl+W や Cmd+Q などはブラウザーと OS が処理するため、ページには届きません。</li>
  <li>キャプチャパッドはテキスト入力欄ではないので、IME がここで変換を始めるかどうかは環境によります。<code>keyCode</code> 229 が表示されないこともあります。</li>
  <li>スニペットは <code>event.key</code> と押されていた修飾キーだけで判定し、<code>event.code</code> も <code>isComposing</code> も見ません。</li>
  <li>捕捉するのは keydown だけで、keyup と keypress は表示しません。「最近のキー」は直近 8 回分です。</li>
</ul>
