<h2>event.key vs event.code vs keyCode</h2>
<p>
  프론트엔드 키보드 버그의 대부분은 이 세 가지 속성을 혼용한 데서 비롯됩니다. 참조표:
</p>

| 속성 | 레이아웃 영향 | 권장 여부 | QWERTY에서 A 누를 때 값 |
|---|---|---|---|
| event.key | 있음(현재 레이아웃 반영) | 권장 — 시맨틱 판정 | "a" 또는 Shift 시 "A" |
| event.code | 없음(물리 위치) | 권장 — 게임 / 단축키 바인딩 | "KeyA" |
| keyCode | 없음 | 비권장 — 폐지됨 | 65 |
| which | 없음 | 비권장 — 폐지됨 | 65 |
| charCode | 없음 | 비권장 — keydown 시 항상 0 | 0 |

<h2>주요 사용 사례</h2>
<ul>
  <li><strong>키보드 핸들러 디버깅</strong> — 실제 event.key 값을 if 조건에 붙여 오타를 잡습니다.</li>
  <li><strong>게임 컨트롤 구현</strong> — event.code를 사용하면 AZERTY 레이아웃에서도 WASD가 작동합니다.</li>
  <li><strong>커맨드 팔레트 단축키</strong> — event.key를 e.ctrlKey / e.metaKey와 조합합니다.</li>
  <li><strong>레거시 코드 감사</strong> — keyCode / which를 읽어 옛 핸들러를 event.key로 이전합니다.</li>
  <li><strong>IME 입력 상태 판별</strong> — e.isComposing = true는 한글/일본어 IME가 조합 중임을 의미하므로 단일 키 핸들러는 즉시 종료해야 합니다.</li>
</ul>

<h2>preventDefault 동작</h2>
<p>
  캡처 패드는 Tab, Space, Backspace, 화살표 키, F1-F12에 대해서만 <code>preventDefault()</code>를 호출합니다 —
  브라우저가 네비게이션/페이지 동작으로 소비하는 키들입니다. Ctrl+W / Cmd+Q 같은 시스템 단축키는
  가로채지 않으며 브라우저 기본 동작이 유지됩니다.
</p>

<h2>키보드 배열과 입력기</h2>
<p>
  <code>event.code</code>는 물리 키를 US 키보드에서의 위치로 이름 붙입니다. <a href="https://www.w3.org/TR/uievents-code/" target="_blank" rel="noopener">UI Events KeyboardEvent code Values</a> 명세에 따르면 <code>"KeyQ"</code>는 US 키보드에서 q, 프랑스어 AZERTY 키보드에서 a가 새겨진 키입니다. 그래서 AZERTY에서 a를 치면 <code>key: "a"</code>, <code>code: "KeyQ"</code>가 됩니다. 키 위치가 중요한 단축키(WASD 이동)는 <code>code</code>로, 입력되는 글자가 중요한 단축키(Ctrl+Z 실행 취소)는 <code>key</code>로 판단하세요.
</p>
<p>
  한국어 키보드에는 US 배열에 없는 <code>"Lang1"</code>(한/영)과 <code>"Lang2"</code>(한자) 키가 있습니다. 패드에서 눌러 브라우저가 보내는 값을 확인할 수 있습니다.
</p>
<p>
  입력기가 글자를 조합하는 동안에는 <a href="https://www.w3.org/TR/uievents/#determine-keydown-keyup-keyCode" target="_blank" rel="noopener">UI Events</a> 규정에 따라 keydown의 <code>keyCode</code>가 229이고 <code>isComposing</code>이 <code>true</code>입니다. Enter를 처리하기 전에 <code>isComposing</code>을 확인하지 않으면, 한글 조합 중 누른 Enter로 폼이 제출될 수 있습니다.
</p>

<h2>제한</h2>
<ul>
  <li>휴대폰과 태블릿의 소프트 키보드는 보통 완전한 keydown 대신 입력한 글자가 담긴 <code>input</code> 이벤트를 보냅니다. 패드 아래 대체 입력란은 그 글자를 <code>key</code>로 보여 주고 <code>code</code>, <code>keyCode</code>, <code>which</code>, <code>charCode</code>는 비워 둡니다. input 이벤트는 어떤 키를 눌렀는지 알려 주지 않기 때문입니다.</li>
  <li>Ctrl+W, Cmd+Q 같은 단축키는 브라우저와 운영체제가 처리하므로 페이지에 전달되지 않습니다.</li>
</ul>
