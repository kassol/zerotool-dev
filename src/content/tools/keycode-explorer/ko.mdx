<h2>event.key vs event.code vs keyCode</h2>
<p>
  프런트엔드 키보드 버그의 대부분은 이 세 가지 속성을 섞어 쓰는 데서 생깁니다. 참조표:
</p>

| 속성 | 레이아웃 영향 | 권장 여부 | QWERTY에서 A 누를 때 값 |
|---|---|---|---|
| event.key | 있음(현재 레이아웃 반영) | 권장 — 의미로 판정 | "a" 또는 Shift 시 "A" |
| event.code | 없음(물리 위치) | 권장 — 게임 / 단축키 바인딩 | "KeyA" |
| keyCode | 없음 | 비권장 — 더 이상 권장되지 않음 | 65 |
| which | 없음 | 비권장 — 더 이상 권장되지 않음 | 65 |
| charCode | 없음 | 비권장 — keydown에서는 0 | 0 |

<h2>한국어 키보드에서 확인할 값</h2>

<p>아래 코드 블록은 해당 키를 패드에서 눌렀을 때 도구가 보여 주는 값입니다. ‘이벤트 속성’의 일부 줄과 ‘복사 가능한 JS 스니펫’을 실었습니다.</p>

<h3>한/영 키와 한자 키</h3>

<p><a href="https://www.w3.org/TR/uievents-code/" target="_blank" rel="noopener">UI Events KeyboardEvent code Values</a> 명세에 따르면 한국어 키보드의 한/영 키는 <code>"Lang1"</code>, 한자 키는 <code>"Lang2"</code>입니다. 같은 표에서 Mac 일본어 키보드의 かな 키와 英数 키도 각각 <code>"Lang1"</code>, <code>"Lang2"</code>이므로, <code>code</code>만으로는 한국어 키인지 일본어 키인지 구분할 수 없습니다.</p>

{/* kce-check: {"event":{"key":"Unidentified","code":"Lang1"}} */}

```
event.code  "Lang1"
```

{/* kce-check: {"event":{"key":"Unidentified","code":"Lang2"}} */}

```
event.code  "Lang2"
```

<p>key 값으로는 <a href="https://www.w3.org/TR/uievents-key/" target="_blank" rel="noopener">UI Events KeyboardEvent key Values</a> 명세에 한글/영문 전환용 <code>"HangulMode"</code>와 한자용 <code>"HanjaMode"</code>가 정의되어 있습니다. 실제로 어떤 값이 오는지는 운영체제와 브라우저에 따라 다를 수 있으니 패드에서 직접 눌러 보세요.</p>

<h3>채팅 입력창의 Shift+Enter</h3>

<p>Enter로 보내고 Shift+Enter로 줄을 바꾸는 입력창을 만들 때, 패드에서 Shift+Enter를 누르면 다음과 같습니다.</p>

{/* kce-check: {"event":{"key":"Enter","code":"Enter","keyCode":13,"which":13,"shiftKey":true}} */}

```
event.key   "Enter"
event.code  "Enter"
keyCode     13
```

```js
document.addEventListener('keydown', (e) => {
  if (e.key === 'Enter' && e.shiftKey) {
    // your handler
  }
});
```

<h2>한글 조합 중의 Enter</h2>

<p>한글을 입력하는 동안 마지막 글자는 조합 중 상태이고, 그동안 <code>isComposing</code>은 <code>true</code>입니다. <a href="https://www.w3.org/TR/uievents/#determine-keydown-keyup-keyCode" target="_blank" rel="noopener">UI Events</a>의 비규범적인 예전 키 코드 절에는 입력기가 키 입력을 처리하는 keydown에서 <code>keyCode</code>로 229를 돌려준다고 적혀 있습니다. 위의 스니펫은 <code>event.key</code>와 수정자 키만 보므로, 입력란에 쓸 때는 한 줄을 더 넣으세요.</p>

```js
input.addEventListener('keydown', (e) => {
  if (e.isComposing || e.keyCode === 229) return;
  if (e.key === 'Enter' && !e.shiftKey) {
    // 전송
  }
});
```

<p>캡처 패드는 텍스트 입력란이 아니어서 여기서 입력기가 조합을 시작하는지는 환경에 따라 다르고, 229가 보이지 않을 수 있습니다. 이 한 줄의 효과는 직접 만든 입력란에서 한글 입력기를 켜고 확인하세요.</p>

<h2>주요 사용 사례</h2>
<ul>
  <li><strong>키보드 핸들러 디버깅</strong> — 실제 event.key 값을 if 조건에 붙여 오타를 잡습니다.</li>
  <li><strong>게임 컨트롤 구현</strong> — event.code를 쓰면 AZERTY 배열에서도 WASD가 같은 자리에서 작동합니다.</li>
  <li><strong>커맨드 팔레트 단축키</strong> — event.key를 e.ctrlKey / e.metaKey와 조합합니다.</li>
  <li><strong>레거시 코드 점검</strong> — keyCode / which를 읽어 예전 핸들러를 event.key로 옮깁니다.</li>
</ul>

<h2>preventDefault 동작</h2>
<p>
  캡처 패드는 Tab, Space, Backspace, 화살표 키, F1-F12에 대해서만 <code>preventDefault()</code>를 호출합니다.
  모두 브라우저가 이동이나 페이지 동작에 쓰는 키입니다. Ctrl+W / Cmd+Q 같은 시스템 단축키는
  가로채지 않으며 브라우저 기본 동작이 유지됩니다.
</p>

<h2>키보드 배열</h2>
<p>
  <code>event.code</code>는 물리 키를 US 키보드에서의 위치로 이름 붙입니다. 같은 명세에 따르면 <code>"KeyQ"</code>는 US 키보드에서 q, 프랑스어 AZERTY 키보드에서 a가 새겨진 키입니다. 그래서 AZERTY에서 a를 치면 <code>key: "a"</code>, <code>code: "KeyQ"</code>가 됩니다. 키 위치가 중요한 단축키(WASD 이동)는 <code>code</code>로, 입력되는 글자가 중요한 단축키(Ctrl+Z 실행 취소)는 <code>key</code>로 판단하세요.
</p>

<h2>제한</h2>
<ul>
  <li>휴대폰과 태블릿의 소프트 키보드는 보통 완전한 keydown 대신 입력한 글자가 담긴 <code>input</code> 이벤트를 보냅니다. 패드 아래 대체 입력란은 그 글자를 <code>key</code>로 보여 주고 <code>code</code>, <code>keyCode</code>, <code>which</code>, <code>charCode</code>는 비워 둡니다. input 이벤트는 어떤 키를 눌렀는지 알려 주지 않기 때문입니다. 입력기가 조합하는 동안에는 중간 input 이벤트를 무시하고 <code>compositionend</code> 시점에 확정된 글자를 읽습니다. 이는 모의 조합 이벤트(일본어, 한국어, 중국어 병음)와 데스크톱 Chromium의 입력기 에뮬레이션으로 확인했으며 안드로이드 실기기에서는 테스트하지 않았습니다.</li>
  <li>Ctrl+W, Cmd+Q 같은 단축키는 브라우저와 운영체제가 처리하므로 페이지에 전달되지 않습니다.</li>
  <li>캡처 패드는 텍스트 입력란이 아니므로 입력기가 여기서 조합을 시작하는지는 환경에 따라 다릅니다. <code>keyCode</code> 229가 보이지 않을 수 있습니다.</li>
  <li>스니펫은 <code>event.key</code>와 눌려 있던 수정자 키만으로 판정하며 <code>event.code</code>와 <code>isComposing</code>은 보지 않습니다.</li>
  <li>keydown만 캡처하며 keyup과 keypress는 보여 주지 않습니다. ‘최근 키’는 최근 8회만 보관합니다.</li>
</ul>
