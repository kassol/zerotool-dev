<h2>ステータスコードのカテゴリ</h2>
<ul>
  <li><strong>1xx 情報：</strong>暫定レスポンス——リクエスト受信済み、まだ処理中。</li>
  <li><strong>2xx 成功：</strong>リクエストが受信・理解・受理された。</li>
  <li><strong>3xx リダイレクト：</strong>リクエストを完了するために追加操作が必要。</li>
  <li><strong>4xx クライアントエラー：</strong>リクエストに誤りがあるか実行不可能。</li>
  <li><strong>5xx サーバーエラー：</strong>正常なリクエストの処理に失敗した。</li>
</ul>

## LINE Messaging API のエラーと照らし合わせる

LINE Messaging API のリファレンスには、API が返すステータスコードの一覧があります（[共通仕様「ステータスコード」](https://developers.line.biz/ja/reference/messaging-api/#status-codes)）。ボットのログに出たコードを本ツールで引くと、英語の一般的な意味と LINE 独自の意味の両方を確認できます。

**409 Conflict。** LINE では、同じリトライキー（`X-Line-Retry-Key`）のリクエストがすでに受理済みであることを表します。LINE のドキュメント「[失敗したAPIリクエストを再試行する](https://developers.line.biz/ja/docs/messaging-api/retrying-api-request/)」では、409 を受け取ったら再試行しない（すでに受理されている）とされています。本ツールで `conflict` と検索すると次のとおりです。

{/* hsc-check: {"q":"conflict"} */}
```text
409 Conflict
```

**413 Payload Too Large。** LINE ではリクエストが上限の 2MB を超えたときに返ります。LINE のリファレンスは旧名の Payload Too Large で書いていますが、本ツールは IANA レジストリと RFC 9110 の現在の名前 Content Too Large で表示します。説明文に旧名も入れているので、`payload` でも見つかります。

{/* hsc-check: {"q":"payload"} */}
```text
413 Content Too Large
```

**429 Too Many Requests。** レート制限や同時処理数の上限に加えて、無料メッセージ通数や追加メッセージ数の上限目安を超えた場合にも返ります。待てば解消するとは限らないので、レスポンス本文の `message` も確認してください。

日本語入力がオンのままだと、数字が全角になることがあります。検索前に全角の英数字を半角にそろえる（Unicode の NFKC 正規化）ので、全角の `４０９` でもそのまま見つかります。

{/* hsc-check: {"q":"４０９"} */}
```text
409 Conflict
```

## API で返すステータスコードの選び方

| 状況 | コード |
|---|---|
| `GET` でリソースを返す | 200 |
| `POST` でリソースを作成した | 201（`Location` ヘッダー付き） |
| 成功したがボディがない（`DELETE` など） | 204 |
| ボディが JSON として不正、または構文エラー | 400 |
| トークンがない、またはトークンが無効 | 401 |
| トークンは有効だが権限がない | 403 |
| リソースが存在しない | 404 |
| 重複（登録済みのメールアドレスなど） | 409 |
| ボディは解析できるが業務ルールに違反（終了日が開始日より前） | 422 |
| レート制限を超えた | 429 |
| 想定外の例外 | 500 |

**401 か 403 か。** 401 はサーバーが相手を識別できていない状態で、401 を返すサーバーは `WWW-Authenticate` ヘッダーも送らなければなりません（[RFC 9110 §15.5.2](https://www.rfc-editor.org/rfc/rfc9110#section-15.5.2)）。403 は相手を識別したうえで操作を許可しない状態です。リソースの存在自体を知られたくない場合は、403 の代わりに 404 を返せます（[§15.5.4](https://www.rfc-editor.org/rfc/rfc9110#section-15.5.4)）。

**リダイレクトとメソッド。** 歴史的な理由から、ブラウザーは 301 と 302 をたどるときに `POST` を `GET` に変えることがあります（[§15.4.2](https://www.rfc-editor.org/rfc/rfc9110#section-15.4.2)）。307 と 308 はメソッドとボディを保持しなければなりません。フォームの `POST` を `POST` のまま転送したいときは 307 か 308 を使います。

## コードとセットで返すヘッダー

| コード | ヘッダー | 規定 |
|---|---|---|
| 201 | `Location: /api/users/456` | 作成したリソースを指す |
| 401 | `WWW-Authenticate: Bearer realm="api"` | 必須 |
| 405 | `Allow: GET, POST` | 必須（[§15.5.6](https://www.rfc-editor.org/rfc/rfc9110#section-15.5.6)） |
| 429、503 | `Retry-After: 60` | 任意。秒数か HTTP 日付（[RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585#section-4)） |
| 304 | — | ボディなし。クライアントはキャッシュを使う |

## JavaScript での扱い方

`fetch()` は 4xx や 5xx では reject しません。reject するのはネットワークエラーのときだけなので、`res.ok`（200〜299 で true）か `res.status` を確認します。

```javascript
const res = await fetch('/api/orders', { method: 'POST', body });
if (res.status === 401) return redirectToLogin();
if (res.status === 429) {
  const wait = Number(res.headers.get('Retry-After') ?? 60);
  return retryAfter(wait);
}
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const order = await res.json();
```

## 制限事項

{/* hsc-iana */}
- **IANA レジストリの 64 コードをすべて収録。** 一覧は [IANA HTTP Status Code Registry](https://www.iana.org/assignments/http-status-codes/)（最終更新 2025-09-15）とコード単位で一致し、名前もレジストリの表記です。104 は 2026-11-13 に期限が切れる仮登録、305 Use Proxy は非推奨、306 と 418 は (Unused)、510 は OBSOLETED（廃止）と表示されます。nginx の 499 や Cloudflare の 520〜526 のような特定製品だけのコードは、レジストリにも一覧にもありません。
- **旧名称でも検索できます。** [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#section-15.5) で 413 は Content Too Large、422 は Unprocessable Content に改名されました。説明文に旧名称の Payload Too Large と Unprocessable Entity を残しているので、どちらの名前でも見つかります。418 はエイプリルフールの RFC 2324 が「I'm a teapot」に使ったため、RFC 9110 15.5.19 節が予約扱いにしています。説明文にもその旨を書いています。
- **説明は英語のみ。** どの言語のページでも名称と説明は英語です。数字だけの検索はその数字で始まるコードを探し（`20` なら 200〜208）、名称や説明文の中の数字は見ません。それ以外の検索は名称と英語の説明文に一致するものを探すので、「リダイレクト」では何も出ません。英語で検索してください。ただし `redirect` で見つかるのは 307 と 308 だけで、301 と 302 の説明文は `moved` という語を使っています。全角の英数字は検索前に半角にそろえます（NFKC 正規化）。
