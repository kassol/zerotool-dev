<h2>Supported Flags</h2>
<ul>
  <li><code>--name NAME</code> — Service name</li>
  <li><code>-p / --publish HOST:CONTAINER</code> — Port mappings</li>
  <li><code>-v / --volume HOST:CONTAINER[:mode]</code> — Volume mounts</li>
  <li><code>-e / --env KEY=VALUE</code> — Environment variables</li>
  <li><code>--network NETWORK</code> — Network</li>
  <li><code>--restart POLICY</code> — Restart policy (no, always, unless-stopped, on-failure)</li>
  <li><code>--cap-add CAP</code> — Capability additions</li>
  <li><code>--memory MEM</code> — Memory limit (e.g. 512m, 1g)</li>
  <li><code>--cpus N</code> — CPU limit</li>
</ul>

## Example: A PostgreSQL Container

Input:

```bash
docker run -d \
  --name postgres \
  -e POSTGRES_DB=myapp \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=secret \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql/data \
  --restart unless-stopped \
  postgres:16-alpine
```

Output:

```yaml
services:
  postgres:
    image: "postgres:16-alpine"
    ports:
      - "5432:5432"
    volumes:
      - "pgdata:/var/lib/postgresql/data"
    environment:
      - "POSTGRES_DB=myapp"
      - "POSTGRES_USER=admin"
      - "POSTGRES_PASSWORD=secret"
    restart: unless-stopped
```

The converter does not write the top-level `volumes:` block. Compose rejects a service that uses an undeclared named volume (`pgdata` here), so add this before you run `docker compose up -d`:

```yaml
volumes:
  pgdata:
```

`-d` is dropped because you detach with `docker compose up -d`. `--name` becomes the service key; add `container_name:` yourself if scripts depend on the exact container name.

## Example: Ports, Limits, and an Existing Network

```bash
docker run --rm -it --network app-net -p 127.0.0.1:8080:80/tcp \
  --restart on-failure:3 --memory 512m --cpus 1.5 --cap-add NET_ADMIN \
  ghcr.io/acme/web:1.2 npm start
```

```yaml
services:
  acme_web:
    image: "ghcr.io/acme/web:1.2"
    ports:
      - "127.0.0.1:8080:80/tcp"
    networks:
      - app-net
    restart: "on-failure:3"
    cap_add:
      - NET_ADMIN
    deploy:
      resources:
        limits:
          memory: 512m
          cpus: '1.5'
    command: ["npm", "start"]

networks:
  app-net:
    external: true
```

With no `--name`, the service key comes from the image (`ghcr.io/acme/web:1.2` → `acme_web`). `--rm`, `-i`, `-t`, and `-it` are dropped. `--network` becomes an external network, so it must already exist (`docker network create app-net`).

## Flag Mapping

| docker run | docker-compose.yml |
|---|---|
| `-p`, `--publish` | `ports:` (quoted; host IP and `/udp` kept) |
| `-v`, `--volume` | `volumes:` |
| `-e`, `--env` | `environment:` as `KEY=VALUE` items; a bare `KEY` is kept |
| `--network` | `networks:` plus a top-level `external: true` network |
| `--restart` | `restart:` |
| `--cap-add` | `cap_add:` |
| `--memory`, `-m`, `--cpus` | `deploy.resources.limits` |
| `--name` | service key |
| `-d`, `--rm`, `-i`, `-t`, `-it` | dropped |
| image and the arguments after it | `image:` and `command:` (JSON array) |

The `--flag=value` form works for the flags in this table.

## Flags to Add by Hand

Any other flag that takes a value is misread: the converter takes its value as the image name and turns everything after it into `command`. For example, `docker run -d --name web --entrypoint /bin/sh -u 1000 -w /app nginx -c "echo hello"` comes out as `image: /bin/sh`. Remove these flags before converting, then add the Compose keys yourself ([Compose file reference](https://docs.docker.com/reference/compose-file/services/)):

| docker run | Compose key |
|---|---|
| `--env-file .env` | `env_file: [".env"]` |
| `--entrypoint /bin/sh` | `entrypoint: /bin/sh` |
| `-u`, `--user 1000:1000` | `user: "1000:1000"` |
| `-w`, `--workdir /app` | `working_dir: /app` |
| `--network-alias api` | `networks: { app-net: { aliases: [api] } }` |
| `--health-cmd "curl -f http://localhost/"` | `healthcheck: { test: ["CMD-SHELL", "curl -f http://localhost/"] }` |
| `--add-host`, `-l` | `extra_hosts:`, `labels:` |

## Limits

- One `docker run` command per conversion. For several containers, convert each one and put the service blocks under a single `services:` key.
- Named volumes are not declared at the top level; add them as shown above.
- Flags outside the mapping table that take a value break the parse, as described above.
- The command must start with `docker run` (or just `run`). `docker container run` and `podman run` show "Not a valid docker run command".
