<h2>주요 사용 사례</h2>
<ul>
  <li><strong>마이그레이션:</strong> 일회성 docker run 명령어를 재현 가능한 compose 구성으로 변환.</li>
  <li><strong>문서화:</strong> README의 run 명령어를 팀용 compose 형식으로 변환.</li>
  <li><strong>멀티 서비스:</strong> 각 서비스 블록을 생성하여 하나의 compose 파일로 통합.</li>
  <li><strong>CI/CD:</strong> docker run 쉘 스크립트를 선언적 compose 파일로 대체.</li>
</ul>

## 예시: PostgreSQL 컨테이너

입력:

```bash
docker run -d \
  --name postgres \
  -e POSTGRES_DB=myapp \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=secret \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql/data \
  --restart unless-stopped \
  postgres:16-alpine
```

출력:

```yaml
services:
  postgres:
    image: "postgres:16-alpine"
    ports:
      - "5432:5432"
    volumes:
      - "pgdata:/var/lib/postgresql/data"
    environment:
      - "POSTGRES_DB=myapp"
      - "POSTGRES_USER=admin"
      - "POSTGRES_PASSWORD=secret"
    restart: unless-stopped

volumes:
  pgdata:
```

`pgdata`는 이름 있는 볼륨이라 최상위 [`volumes:`](https://docs.docker.com/reference/compose-file/volumes/)에 선언합니다. 이 부분이 없으면 Compose가 파일을 거부하며, `docker compose config`는 `service "postgres" refers to undefined volume pgdata`를 출력합니다. `-d`는 `docker compose up -d`로 백그라운드 실행하므로 뺍니다. `--name`은 서비스 이름이 됩니다. 정확한 컨테이너 이름에 의존하는 스크립트가 있으면 `container_name:`을 직접 추가하세요.

## 예시: 포트, 리소스 제한, 기존 네트워크

```bash
docker run --rm -it --network app-net -p 127.0.0.1:8080:80/tcp \
  --restart on-failure:3 --memory 512m --cpus 1.5 --cap-add NET_ADMIN \
  ghcr.io/acme/web:1.2 npm start
```

```yaml
services:
  acme_web:
    image: "ghcr.io/acme/web:1.2"
    ports:
      - "127.0.0.1:8080:80/tcp"
    networks:
      - app-net
    restart: "on-failure:3"
    cap_add:
      - NET_ADMIN
    stdin_open: true
    tty: true
    deploy:
      resources:
        limits:
          memory: 512m
          cpus: "1.5"
    command: ["npm", "start"]

networks:
  app-net:
    external: true
```

`--name`이 없으면 서비스 이름은 이미지에서 정해집니다(`ghcr.io/acme/web:1.2` → `acme_web`). `-it`는 짧은 옵션 `-i`와 `-t`를 합친 것으로 각각 `stdin_open`, `tty`가 됩니다. `--rm`은 뺍니다. `--network`는 외부 네트워크가 되므로 미리 만들어 두어야 합니다(`docker network create app-net`). `--network host`, `none`, `bridge`, `container:이름`은 `network_mode:`가 됩니다.

## 예시: Compose 키가 없는 옵션

```bash
docker run -d --name web --env-file .env --entrypoint /bin/sh -u 1000:1000 -w /app --gpus all nginx:1.27 -c "nginx -g 'daemon off;'"
```

```yaml
# Not converted: --gpus all
services:
  web:
    image: "nginx:1.27"
    entrypoint: ["/bin/sh"]
    env_file:
      - .env
    user: "1000:1000"
    working_dir: /app
    command: ["-c", "nginx -g 'daemon off;'"]
```

`docker run`의 `--entrypoint`는 실행 파일 하나만 받으므로 항목 하나짜리 목록이 됩니다. 이미지 뒤의 인수는 `command`입니다. `--gpus`는 1:1 대응하는 Compose 키가 없어(GPU는 `deploy.resources.reservations.devices`에 씀) 값을 읽어 이미지 이름을 바르게 유지하고, 첫 줄 주석과 상태 표시줄에 표시합니다.

위 출력은 모두 `docker compose config`(Docker Compose 5.1)를 통과합니다. 도구의 테스트가 각 예시에 이 검사를 실행합니다.

## 플래그 대응표

| docker run | docker-compose.yml |
|---|---|
| `-p`, `--publish` | `ports:` |
| `-v`, `--volume` | `volumes:`; named volumes also in the top-level `volumes:` |
| `-e`, `--env`, `--env-file` | `environment:`, `env_file:` |
| `--network` | `networks:` plus a top-level `external: true` network; `host`, `none`, `bridge`, `container:…` become `network_mode:` |
| `--entrypoint` | `entrypoint:` (one-item list) |
| `-u`, `-w`, `-h`, `--domainname` | `user:`, `working_dir:`, `hostname:`, `domainname:` |
| `--restart`, `--pull`, `--platform` | `restart:`, `pull_policy:`, `platform:` |
| `-l`, `--label`, `--annotation` | `labels:`, `annotations:` |
| `--add-host`, `--dns`, `--dns-option`, `--dns-search`, `--link`, `--expose` | `extra_hosts:`, `dns:`, `dns_opt:`, `dns_search:`, `links:`, `expose:` |
| `--cap-add`, `--cap-drop`, `--privileged`, `--security-opt`, `--device` | `cap_add:`, `cap_drop:`, `privileged:`, `security_opt:`, `devices:` |
| `--init`, `--read-only`, `-i`, `-t` | `init:`, `read_only:`, `stdin_open:`, `tty:` |
| `--tmpfs`, `--volumes-from`, `--shm-size`, `--sysctl` | `tmpfs:`, `volumes_from:`, `shm_size:`, `sysctls:` |
| `--memory`, `-m`, `--cpus` | `deploy.resources.limits` |
| `--memory-reservation`, `--memory-swap`, `--cpu-shares`, `--cpuset-cpus`, `--pids-limit` | `mem_reservation:`, `memswap_limit:`, `cpu_shares:`, `cpuset:`, `pids_limit:` |
| `--pid`, `--ipc`, `--uts`, `--userns`, `--cgroupns`, `--stop-signal` | `pid:`, `ipc:`, `uts:`, `userns_mode:`, `cgroup:`, `stop_signal:` |
| `--name` | service key |
| `-d`, `--rm`, `-q`, `--detach-keys` | dropped |
| image and the arguments after it | `image:` and `command:` (JSON array) |

옵션은 `--flag value`, `--flag=value`, `-p 80:80`, `-p80:80`처럼 쓸 수 있고, Docker CLI와 같이 묶어 쓸 수도 있습니다(`-dit`, `-dp 80:80`).

## 직접 추가해야 하는 옵션

다음 옵션은 읽지만 변환하지 않습니다. Compose 키의 구조가 다르기 때문입니다([services 레퍼런스](https://docs.docker.com/reference/compose-file/services/)):

| docker run | Compose key |
|---|---|
| `--health-cmd "curl -f http://localhost/"` and the other `--health-*` | `healthcheck: { test: ["CMD-SHELL", "curl -f http://localhost/"] }` |
| `--log-driver`, `--log-opt` | `logging: { driver: …, options: { … } }` |
| `--network-alias api`, `--ip` | `networks: { app-net: { aliases: [api], ipv4_address: … } }` |
| `--mount` | the long syntax of `volumes:` (`type`, `source`, `target`) |
| `--gpus` | `deploy.resources.reservations.devices` |
| `--ulimit nofile=1024:2048` | `ulimits: { nofile: { soft: 1024, hard: 2048 } }` |
| `--stop-timeout 30` | `stop_grace_period: 30s` |

## 제한 사항

- 한 번에 `docker run` 명령어 하나를 변환합니다. 여러 컨테이너는 각각 변환한 뒤 서비스 블록을 하나의 `services:` 아래에 합치세요.
- `docker run`과 `docker container run`을 인식하며 `podman run`은 인식하지 않습니다.
- `$(...)`, `$VAR`, `&&` 같은 셸 문법은 글자 그대로 남습니다. 변수는 변환 전에 펼치거나, 결과에서 Compose [변수 보간](https://docs.docker.com/reference/compose-file/interpolation/)을 쓰세요.
- `./data` 같은 상대 바인드 경로는 Compose에서는 compose 파일이 있는 디렉터리, `docker run`에서는 현재 디렉터리를 기준으로 합니다.
