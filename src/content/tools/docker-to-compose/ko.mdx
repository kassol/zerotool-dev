<h2>사용 방법</h2>
<ol>
  <li>왼쪽 패널에 <strong>docker run 명령어</strong>를 붙여넣습니다 (또는 <strong>예시</strong> 클릭).</li>
  <li><strong>변환</strong>을 클릭합니다.</li>
  <li>오른쪽 패널에서 생성된 <strong>docker-compose.yml</strong>을 확인합니다.</li>
  <li><strong>복사</strong>를 클릭하여 <code>docker-compose.yml</code>로 저장합니다.</li>
</ol>

<h2>지원 플래그</h2>
<ul>
  <li><code>--name NAME</code> — 서비스 이름</li>
  <li><code>-p / --publish HOST:CONTAINER</code> — 포트 매핑</li>
  <li><code>-v / --volume HOST:CONTAINER[:mode]</code> — 볼륨 마운트</li>
  <li><code>-e / --env KEY=VALUE</code> — 환경변수</li>
  <li><code>--network NETWORK</code> — 네트워크</li>
  <li><code>--restart POLICY</code> — 재시작 정책 (no, always, unless-stopped, on-failure)</li>
  <li><code>--cap-add CAP</code> — 리눅스 권한 추가</li>
  <li><code>--memory MEM</code> — 메모리 제한 (예: 512m, 1g)</li>
  <li><code>--cpus N</code> — CPU 제한</li>
</ul>

<h2>주요 사용 사례</h2>
<ul>
  <li><strong>마이그레이션:</strong> 일회성 docker run 명령어를 재현 가능한 compose 구성으로 변환.</li>
  <li><strong>문서화:</strong> README의 run 명령어를 팀용 compose 형식으로 변환.</li>
  <li><strong>멀티 서비스:</strong> 각 서비스 블록을 생성하여 하나의 compose 파일로 통합.</li>
  <li><strong>CI/CD:</strong> docker run 쉘 스크립트를 선언적 compose 파일로 대체.</li>
</ul>

## 예시: PostgreSQL 컨테이너

입력:

```bash
docker run -d \
  --name postgres \
  -e POSTGRES_DB=myapp \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=secret \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql/data \
  --restart unless-stopped \
  postgres:16-alpine
```

출력:

```yaml
services:
  postgres:
    image: "postgres:16-alpine"
    ports:
      - "5432:5432"
    volumes:
      - "pgdata:/var/lib/postgresql/data"
    environment:
      - "POSTGRES_DB=myapp"
      - "POSTGRES_USER=admin"
      - "POSTGRES_PASSWORD=secret"
    restart: unless-stopped
```

변환기는 최상위 `volumes:` 블록을 쓰지 않습니다. 선언되지 않은 이름 있는 볼륨(여기서는 `pgdata`)을 쓰는 서비스는 Compose가 거부하므로 `docker compose up -d` 전에 추가하세요:

```yaml
volumes:
  pgdata:
```

`-d`는 제거됩니다. Compose에서는 `docker compose up -d`로 백그라운드 실행하기 때문입니다. `--name`은 서비스 이름이 됩니다. 스크립트가 정확한 컨테이너 이름에 의존한다면 `container_name:`을 직접 추가하세요.

## 예시: 포트, 리소스 제한, 기존 네트워크

```bash
docker run --rm -it --network app-net -p 127.0.0.1:8080:80/tcp \
  --restart on-failure:3 --memory 512m --cpus 1.5 --cap-add NET_ADMIN \
  ghcr.io/acme/web:1.2 npm start
```

```yaml
services:
  acme_web:
    image: "ghcr.io/acme/web:1.2"
    ports:
      - "127.0.0.1:8080:80/tcp"
    networks:
      - app-net
    restart: "on-failure:3"
    cap_add:
      - NET_ADMIN
    deploy:
      resources:
        limits:
          memory: 512m
          cpus: '1.5'
    command: ["npm", "start"]

networks:
  app-net:
    external: true
```

`--name`이 없으면 서비스 이름은 이미지에서 만들어집니다(`ghcr.io/acme/web:1.2` → `acme_web`). `--rm`, `-i`, `-t`, `-it`는 제거됩니다. `--network`는 외부 네트워크가 되므로 미리 만들어 두어야 합니다(`docker network create app-net`).

## 플래그 대응표

| docker run | docker-compose.yml |
|---|---|
| `-p`, `--publish` | `ports:` (따옴표 포함, 호스트 IP와 `/udp` 유지) |
| `-v`, `--volume` | `volumes:` |
| `-e`, `--env` | `environment:`에 `KEY=VALUE` 항목으로 출력, `KEY`만 있어도 그대로 유지 |
| `--network` | `networks:`와 최상위 `external: true` 네트워크 |
| `--restart` | `restart:` |
| `--cap-add` | `cap_add:` |
| `--memory`, `-m`, `--cpus` | `deploy.resources.limits` |
| `--name` | 서비스 이름 |
| `-d`, `--rm`, `-i`, `-t`, `-it` | 제거 |
| 이미지와 그 뒤의 인수 | `image:`와 `command:`(JSON 배열) |

표의 플래그는 `--flag=value` 형식도 지원합니다.

## 직접 추가해야 하는 플래그

표에 없고 값을 받는 플래그는 잘못 해석됩니다. 그 값이 이미지 이름으로 쓰이고 뒤에 오는 내용은 모두 `command`가 됩니다. 예를 들어 `docker run -d --name web --entrypoint /bin/sh -u 1000 -w /app nginx -c "echo hello"`는 `image: /bin/sh`가 됩니다. 변환 전에 이런 플래그를 빼고, 대응하는 Compose 키를 직접 작성하세요([Compose 파일 레퍼런스](https://docs.docker.com/reference/compose-file/services/)):

| docker run | Compose 키 |
|---|---|
| `--env-file .env` | `env_file: [".env"]` |
| `--entrypoint /bin/sh` | `entrypoint: /bin/sh` |
| `-u`, `--user 1000:1000` | `user: "1000:1000"` |
| `-w`, `--workdir /app` | `working_dir: /app` |
| `--network-alias api` | `networks: { app-net: { aliases: [api] } }` |
| `--health-cmd "curl -f http://localhost/"` | `healthcheck: { test: ["CMD-SHELL", "curl -f http://localhost/"] }` |
| `--add-host`, `-l` | `extra_hosts:`, `labels:` |

## 제한 사항

- 한 번에 `docker run` 명령 하나만 변환합니다. 컨테이너가 여러 개라면 각각 변환한 뒤 서비스 블록을 하나의 `services:` 아래에 모으세요.
- 이름 있는 볼륨은 최상위에 선언되지 않으므로 위와 같이 추가하세요.
- 표에 없고 값을 받는 플래그가 있으면 파싱이 깨집니다(위 참조).
- 명령은 `docker run`(또는 `run`)으로 시작해야 합니다. `docker container run`, `podman run`은 "잘못된 docker run 명령어"라고 표시됩니다.
