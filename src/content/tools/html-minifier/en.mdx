<h2>How to Use</h2>
<ol>
  <li>Paste your HTML — a fragment or a full document with doctype — into the input panel.</li>
  <li>Click <strong>Minify</strong> to strip comments and collapse whitespace, or <strong>Beautify</strong> to re-indent the markup.</li>
  <li>For Beautify, choose 2 spaces, 4 spaces, or Tab from the indent dropdown.</li>
  <li>The status bar shows the savings after a minify (e.g. <code>12.4 KB → 8.1 KB (−34.6%)</code>).</li>
  <li>Click <strong>Copy</strong> on the output panel to grab the result.</li>
</ol>

<h2>Worked Examples</h2>
<h3>Before minify</h3>

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <!-- page metadata -->
    <title>Hello</title>
  </head>
  <body>
    <h1>Hello World</h1>
    <p>Some <strong>bold</strong> text.</p>
  </body>
</html>
```

<h3>After minify</h3>

```html
<!doctype html><html lang="en"><head>  <title>Hello</title> </head> <body> <h1>Hello World</h1> <p>Some <strong>bold</strong> text.</p> </body></html>
```

<p>Status bar: <code>Minified — 200 B → 150 B (−25.0%)</code>. The comment is gone and each run of indentation became one space. The spaces between tags stay because the tool keeps every whitespace-only text node as a single space: in <code>&lt;p&gt;Hello &lt;strong&gt;world&lt;/strong&gt;!&lt;/p&gt;</code> the space before <code>&lt;strong&gt;</code> is visible, and the tool does not try to decide which spaces are safe to drop. Build-time minifiers such as <a href="https://github.com/terser/html-minifier-terser" target="_blank" rel="noopener">html-minifier-terser</a> remove more with options like <code>collapseWhitespace</code>.</p>

<h2>What Gets Minified</h2>
<ul>
  <li>Whitespace between tags (inter-tag whitespace) is collapsed.</li>
  <li>HTML comments are removed — except IE conditional comments (<code>&lt;!--[if IE]&gt;</code>).</li>
  <li>Boolean attribute values like <code>disabled=""</code> are simplified to <code>disabled</code>.</li>
  <li>Whitespace runs in text collapse to a single space. Whitespace-only text between tags becomes one space; it is not removed, because the parser cannot tell which of those spaces are visible.</li>
  <li>When a block element such as <code>&lt;p&gt;</code> or <code>&lt;h1&gt;</code> contains only text, the leading and trailing whitespace of that text is removed. Inline elements such as <code>&lt;strong&gt;</code>, <code>&lt;a&gt;</code> or <code>&lt;span&gt;</code> keep one space at each edge, because that space is visible: <code>&lt;strong&gt;Note: &lt;/strong&gt;read this.</code> stays as it is.</li>
</ul>

<h2>What Stays Verbatim</h2>
<ul>
  <li>Content inside <code>&lt;script&gt;</code>, <code>&lt;style&gt;</code>, <code>&lt;pre&gt;</code>, <code>&lt;textarea&gt;</code>, <code>&lt;code&gt;</code>, <code>&lt;samp&gt;</code>, <code>&lt;kbd&gt;</code>.</li>
  <li>Attribute values, including quoted whitespace and inline event handlers.</li>
  <li>The <code>&lt;!DOCTYPE&gt;</code> declaration.</li>
</ul>

<h2>When to Minify Production HTML</h2>
<p>Most modern build pipelines minify HTML as part of the bundler step (Vite, Webpack, Astro, Next.js). Use this tool when you need a one-off minify — pasting from a CMS export, comparing before/after sizes, or sanity-checking a hand-written template. Beautify is the daily driver: paste minified HTML from production, get a readable copy to debug or diff.</p>

<h2>Limits</h2>
<ul>
  <li>Inline elements keep a collapsed space at their edges even where CSS would hide it, for example at the start of a line. The tool does not read your CSS, so it cannot tell when <code>display</code> or <code>white-space</code> changes how spaces render.</li>
  <li>Only HTML whitespace (space, tab, line feed, form feed, carriage return) is collapsed. Non-breaking spaces are kept: <code>Price:&amp;nbsp;&amp;nbsp;10&amp;nbsp;EUR</code> comes out with the same three non-breaking spaces, written as the character U+00A0 instead of <code>&amp;nbsp;</code>. The full-width space U+3000 is also kept.</li>
  <li>In a fragment, content that the HTML parser moves out of <code>&lt;body&gt;</code> is written back in its original order: a conditional comment such as <code>&lt;!--[if mso]&gt;</code> before the first element, and <code>&lt;title&gt;</code>, <code>&lt;meta&gt;</code>, <code>&lt;link&gt;</code> or <code>&lt;style&gt;</code> before the body content. Ordinary comments are removed wherever they are.</li>
  <li>Inline JavaScript and CSS are copied as they are. They are not minified.</li>
  <li>The HTML is parsed by the browser's <code>DOMParser</code>, so invalid markup comes out repaired (missing end tags added, stray tags dropped), and the doctype is written as <code>&lt;!doctype html&gt;</code>.</li>
</ul>
