<h2>例</h2>

<h3>基本的な変換</h3>
{/* jtc-check */}
<p>入力JSON：</p>
<pre><code>{`[{"id":1,"name":"Alice"},{"id":2,"name":"Bob"}]`}</code></pre>
<p>出力CSV：</p>
<pre><code>{`id,name\n1,Alice\n2,Bob`}</code></pre>

<h3>ネストオブジェクトの展開</h3>
{/* jtc-check */}
<p>入力JSON：</p>
<pre><code>{`[{"user":{"name":"Alice","age":30}}]`}</code></pre>
<p>出力CSV（展開オン）：</p>
<pre><code>{`user.name,user.age\nAlice,30`}</code></pre>

<h3>郵便番号検索 API の結果を表にする</h3>
<p>
  <a href="https://zipcloud.ibsnet.co.jp/doc/api" target="_blank" rel="noopener">zipcloud の郵便番号検索API</a> は、日本郵便の郵便番号データを検索して JSON で返します。レスポンスは <code>message</code>・<code>results</code>・<code>status</code> を持つオブジェクトなので、そのまま貼り付けると「入力はオブジェクトの JSON 配列である必要があります」と表示されます。表にしたいのは <code>results</code> の配列だけです。ドキュメントのレスポンスサンプルにある 2 件を貼り付けると、次のようになります。
</p>
{/* jtc-check */}
<pre><code>{`[{"address1":"北海道","address2":"美唄市","address3":"上美唄町協和","kana1":"ﾎｯｶｲﾄﾞｳ","kana2":"ﾋﾞﾊﾞｲｼ","kana3":"ｶﾐﾋﾞﾊﾞｲﾁｮｳｷｮｳﾜ","prefcode":"1","zipcode":"0790177"},
 {"address1":"北海道","address2":"美唄市","address3":"上美唄町南","kana1":"ﾎｯｶｲﾄﾞｳ","kana2":"ﾋﾞﾊﾞｲｼ","kana3":"ｶﾐﾋﾞﾊﾞｲﾁｮｳﾐﾅﾐ","prefcode":"1","zipcode":"0790177"}]`}</code></pre>
<p>出力CSV：</p>
<pre><code>{`address1,address2,address3,kana1,kana2,kana3,prefcode,zipcode
北海道,美唄市,上美唄町協和,ﾎｯｶｲﾄﾞｳ,ﾋﾞﾊﾞｲｼ,ｶﾐﾋﾞﾊﾞｲﾁｮｳｷｮｳﾜ,1,0790177
北海道,美唄市,上美唄町南,ﾎｯｶｲﾄﾞｳ,ﾋﾞﾊﾞｲｼ,ｶﾐﾋﾞﾊﾞｲﾁｮｳﾐﾅﾐ,1,0790177`}</code></pre>
<p>
  カナは API が返す半角カナのまま書き出され、全角への変換はしません。郵便番号 <code>0790177</code> も JSON の文字列どおりに先頭の 0 が残ります。注意が必要なのは Excel で開くときです。Microsoft のサポートページ
  <a href="https://support.microsoft.com/ja-jp/office/keeping-leading-zeros-and-large-numbers-1bf7b935-36e1-4985-842f-5dfa51f85fe7" target="_blank" rel="noopener">先頭のゼロおよび大きい数値の保持</a>
  によると、Excel は先頭のゼロを自動的に削除し、有効桁数は最大 15 桁です。そのままダブルクリックで開くと <code>zipcode</code> 列が <code>790177</code> になります。0 を残すには、同じページの手順どおり［データ］タブの［テキスト/CSV から］で読み込み、クエリ エディターでその列のデータ型を［テキスト］に変えてください。
</p>

<h3>全角の記号で始まる値</h3>
<p>IME で入力したメモには、全角の <code>－</code> や <code>＋</code> で始まる値が混ざることがあります。ツールは半角の <code>=</code> <code>+</code> <code>-</code> <code>@</code> に加えて全角の <code>＝</code> <code>＋</code> <code>－</code> <code>＠</code> で始まる文字列も数えます。「その他の CSV 設定」で数式対策を「' を付ける」にした場合：</p>
{/* jtc-check: {"guard":"quote","status":true} */}
<pre><code>{`[{"商品":"マグカップ","メモ":"－30%（セール）"},{"商品":"タンブラー","メモ":"在庫あり"}]`}</code></pre>
<p>出力CSV：</p>
<pre><code>{`商品,メモ
マグカップ,"'－30%（セール）"
タンブラー,在庫あり`}</code></pre>
<p>ステータス欄には <code>2 行を変換しました · 1 個の値に数式対策を付けました。</code> と表示されます。数式対策がオフのままなら値は変わらず、該当する値の数だけが警告として表示されます。</p>

<h2>RFC 4180 準拠</h2>
<p>
  このツールはRFC 4180 CSV標準に従います。区切り文字・ダブルクォート・改行を含むフィールドはダブルクォートで囲まれ、フィールド内のダブルクォートは<code>""</code>にエスケープされます。行区切りは RFC 4180 の CR LF ではなく LF です（Excel・LibreOffice・pandas はどちらも読めます）。
</p>

<h2>数式対策</h2>
<p>
  <code>=</code>、<code>+</code>、<code>-</code>、<code>@</code>、タブ、改行で始まるセルは、表計算ソフトで開いたときに数式として実行されるおそれがあります（<a href="https://owasp.org/www-community/attacks/CSV_Injection" target="_blank" rel="noopener">OWASP: CSV Injection</a>）。全角の <code>＝</code> などにも反応します。ツールはこうした文字列の値を数えてステータス欄に表示します。<strong>数式対策</strong>をオンにすると、OWASP の推奨どおり前置文字を付けて引用符で囲みます。<strong>' を付ける</strong> は <code>'</code>、<strong>タブを付ける（Excel）</strong> はタブを付けます（OWASP によれば、Excel で保存して開き直してもタブは残ります）。入力：
</p>
{/* jtc-check: {"guard":"quote"} */}
<pre><code>{`[{"name":"Ann","comment":"=HYPERLINK(\\"http://example.com\\",\\"Click\\")"}]`}</code></pre>
<p>「' を付ける」の出力：</p>
<pre><code>{`name,comment
Ann,"'=HYPERLINK(""http://example.com"",""Click"")"`}</code></pre>
<p>対象は JSON の文字列だけで、<code>-5</code> などの数値、真偽値、JSON テキストとして書かれる配列・オブジェクトは変わりません。電話番号 <code>+81 3 1234 5678</code> のような値にも前置文字が付き、データが変わるため、既定ではオフです。該当する値があるとステータス欄に表示されます。</p>

<h2>Excel と BOM</h2>
<p>
  ダウンロードしたファイルは既定で UTF-8 の BOM（バイト <code>EF BB BF</code>）で始まります。Microsoft のサポートページ <a href="https://support.microsoft.com/en-us/office/opening-csv-utf-8-files-correctly-in-excel-8a935af5-3416-4edd-ba7e-3dfd2bc4a032" target="_blank" rel="noopener">Opening CSV UTF-8 files correctly in Excel</a> は、BOM 付きで保存された UTF-8 の CSV はそのまま開けると説明しています。BOM がないと、Windows 版 Excel はダブルクリックで開いた CSV をシステムのコードページ（日本語環境では Shift_JIS（CP932））で読み、日本語が文字化けします。BOM を想定しないプログラムは BOM を最初の列名の一部として読むことがあります（Python で <code>encoding="utf-8"</code> なら <code>\ufeffid</code>、<code>"utf-8-sig"</code> なら取り除かれます）。その場合は「ダウンロードに UTF-8 BOM を付ける」をオフにしてください。<strong>コピー</strong>した内容には BOM は付きません。
</p>

<h2>制限</h2>
<ul>
  <li>入力は JSON の配列に限ります。オブジェクトを 1 つだけ貼ると「入力はオブジェクトの JSON 配列である必要があります」と表示されるので、<code>[ ]</code> で囲んでください。<code>[1,"two",null]</code> のようにオブジェクトでない要素は、1 つの <code>value</code> 列に入ります。</li>
  <li>空のネストオブジェクトと配列は展開しません。<code>{`"meta":{}`}</code> は <code>meta</code> 列になり、値は <code>{`{}`}</code> です。<code>["a","b"]</code> のような配列は JSON テキストとして 1 列に入ります。</li>
  <li>2<sup>53</sup> を超える整数は JSON の解析時に精度が落ちます。<code>12345678901234567890</code> は <code>12345678901234567000</code> として書き出されます。長い ID は JSON 側で文字列にしてください。</li>
  <li>文字コードの変換はしません。Shift_JIS の CSV が必要な場合は、ダウンロード後に別のツールで変換してください。</li>
  <li>行区切りは LF です。CR LF が必要なプログラムでは変換が必要です。</li>
  <li>変換は JSON から CSV への一方向です。逆方向は <a href="/ja/tools/csv-json/">CSV → JSON 変換ツール</a> を使ってください。</li>
</ul>
