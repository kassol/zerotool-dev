<h2>예제</h2>

<h3>기본 변환</h3>
{/* jtc-check */}
<p>입력 JSON:</p>
<pre><code>{`[{"id":1,"name":"Alice"},{"id":2,"name":"Bob"}]`}</code></pre>
<p>출력 CSV:</p>
<pre><code>{`id,name\n1,Alice\n2,Bob`}</code></pre>

<h3>중첩 객체 펼치기</h3>
{/* jtc-check */}
<p>입력 JSON:</p>
<pre><code>{`[{"user":{"name":"Alice","age":30}}]`}</code></pre>
<p>출력 CSV (펼치기 켬):</p>
<pre><code>{`user.name,user.age\nAlice,30`}</code></pre>

<h3>회원 명단: 0으로 시작하는 우편번호</h3>
<p>회원 정보 JSON에서 우편번호는 보통 문자열로 들어 있고 주소는 중첩 객체입니다.</p>
{/* jtc-check */}
<pre><code>{`[{"이름":"김민수","우편번호":"06236","주소":{"시도":"서울","구":"강남구"}}]`}</code></pre>
<p>출력 CSV:</p>
<pre><code>{`이름,우편번호,주소.시도,주소.구
김민수,06236,서울,강남구`}</code></pre>
<p>
  한글 키는 그대로 열 이름이 되고, 주소는 <code>주소.시도</code>, <code>주소.구</code> 두 열로 펼쳐집니다. 우편번호 <code>06236</code>도 JSON 문자열 그대로 앞의 0이 남습니다. 문제는 Excel에서 열 때입니다. Microsoft 지원 페이지
  <a href="https://support.microsoft.com/ko-kr/office/keeping-leading-zeros-and-large-numbers-1bf7b935-36e1-4985-842f-5dfa51f85fe7" target="_blank" rel="noopener">앞에 오는 0과 더 큰 숫자를 유지</a>에
  따르면 Excel은 앞에 오는 0을 자동으로 제거하고 숫자는 15자리 정밀도까지만 유지합니다. 파일을 그대로 열면 이 열은 <code>6236</code>이 됩니다. 0을 남기려면 같은 페이지의 방법대로 [데이터] 탭에서 [텍스트/CSV에서]를 선택해 가져온 뒤, 쿼리 편집기에서 해당 열의 데이터 형식을 텍스트로 바꾸세요.
</p>

<h3>-로 시작하는 메모</h3>
<p>상품 메모에 <code>-50% 할인</code>처럼 <code>-</code>로 시작하는 값이 있으면 수식 방지 대상입니다. 추가 CSV 옵션에서 수식 방지를 "' 붙이기"로 바꾸면:</p>
{/* jtc-check: {"guard":"quote","status":true} */}
<pre><code>{`[{"상품":"텀블러","메모":"-50% 할인"},{"상품":"머그컵","메모":"1+1 행사"}]`}</code></pre>
<p>출력 CSV:</p>
<pre><code>{`상품,메모
텀블러,"'-50% 할인"
머그컵,1+1 행사`}</code></pre>
<p>상태 줄에는 <code>2행 변환됨 · 1개 값에 수식 방지를 적용했습니다.</code>가 표시됩니다. 검사하는 것은 값의 첫 글자뿐이라서, <code>+</code>가 중간에 있는 <code>1+1 행사</code>는 바뀌지 않습니다. 숫자 <code>-5</code>처럼 JSON에서 숫자인 값도 그대로입니다.</p>

<h2>RFC 4180 준수</h2>
<p>
  이 도구는 RFC 4180 CSV 표준을 따릅니다. 구분자, 큰따옴표, 줄바꿈을 포함한 필드는 큰따옴표로 감싸지며, 필드 내 큰따옴표는 <code>""</code>로 이스케이프됩니다. 행 구분은 RFC 4180의 CR LF가 아니라 LF입니다(Excel, LibreOffice, pandas 모두 읽을 수 있음).
</p>

<h2>수식 방지</h2>
<p>
  <code>=</code>, <code>+</code>, <code>-</code>, <code>@</code>, 탭, 줄바꿈으로 시작하는 셀은 스프레드시트에서 열 때 수식으로 실행될 수 있습니다(<a href="https://owasp.org/www-community/attacks/CSV_Injection" target="_blank" rel="noopener">OWASP: CSV Injection</a>). 도구는 이런 문자열 값을 세어 상태 줄에 표시합니다. <strong>수식 방지</strong>를 켜면 OWASP 권장대로 앞에 문자를 붙이고 따옴표로 감쌉니다. <strong>' 붙이기</strong>는 <code>'</code>를, <strong>탭 붙이기 (Excel)</strong>는 탭을 붙입니다(OWASP에 따르면 Excel에서 저장 후 다시 열어도 탭은 남습니다). 입력:
</p>
{/* jtc-check: {"guard":"quote"} */}
<pre><code>{`[{"name":"Ann","comment":"=HYPERLINK(\\"http://example.com\\",\\"Click\\")"}]`}</code></pre>
<p>"' 붙이기" 출력:</p>
<pre><code>{`name,comment
Ann,"'=HYPERLINK(""http://example.com"",""Click"")"`}</code></pre>
<p>JSON 문자열만 바꾸며, <code>-5</code> 같은 숫자, 불리언, JSON 텍스트로 쓰는 배열·객체는 그대로입니다. <code>+82 2 1234 5678</code> 같은 전화번호에도 접두 문자가 붙어 데이터가 바뀌므로 기본값은 꺼짐이고, 해당 값이 있으면 상태 줄에 알려 줍니다.</p>

<h2>Excel과 BOM</h2>
<p>
  다운로드한 파일은 기본적으로 UTF-8 BOM(바이트 <code>EF BB BF</code>)으로 시작합니다. Microsoft 지원 페이지 <a href="https://support.microsoft.com/en-us/office/opening-csv-utf-8-files-correctly-in-excel-8a935af5-3416-4edd-ba7e-3dfd2bc4a032" target="_blank" rel="noopener">Opening CSV UTF-8 files correctly in Excel</a>은 BOM과 함께 저장된 UTF-8 CSV는 그대로 열 수 있다고 설명합니다. BOM이 없으면 Windows용 Excel은 더블클릭으로 연 CSV를 시스템 코드 페이지(한국어 환경은 CP949)로 읽어 한글이 깨집니다. BOM을 예상하지 않는 프로그램은 BOM을 첫 열 이름의 일부로 읽을 수 있습니다(Python에서 <code>encoding="utf-8"</code>이면 <code>\ufeffid</code>, <code>"utf-8-sig"</code>이면 제거됨). 이때는 "다운로드에 UTF-8 BOM 추가"를 끄세요. <strong>복사</strong>한 내용에는 BOM이 붙지 않습니다.
</p>

<h2>제한 사항</h2>
<ul>
  <li>입력은 JSON 배열이어야 합니다. 객체 하나만 붙여 넣으면 "입력은 객체의 JSON 배열이어야 합니다"가 표시되니 <code>[ ]</code>로 감싸세요. <code>[1,"two",null]</code>처럼 객체가 아닌 요소는 하나의 <code>value</code> 열에 들어갑니다.</li>
  <li>빈 중첩 객체와 배열은 펼치지 않습니다. <code>{`"meta":{}`}</code>는 <code>meta</code> 열이 되고 값은 <code>{`{}`}</code>입니다. <code>["a","b"]</code> 같은 배열은 JSON 텍스트로 한 열에 들어갑니다.</li>
  <li>2<sup>53</sup>을 넘는 정수는 JSON을 읽을 때 정밀도가 떨어집니다. <code>12345678901234567890</code>은 <code>12345678901234567000</code>으로 출력됩니다. 긴 ID는 JSON에서 문자열로 두세요.</li>
  <li>문자 인코딩은 바꾸지 않습니다. 출력은 UTF-8이며, CP949 CSV가 필요하면 내려받은 뒤 다른 도구로 변환하세요.</li>
  <li>행 구분은 LF입니다. CR LF가 필요한 프로그램에서는 변환이 필요합니다.</li>
  <li>JSON에서 CSV로만 변환합니다. 반대 방향은 <a href="/ko/tools/csv-json/">CSV → JSON 변환기</a>를 쓰세요.</li>
</ul>
