<h2>Worked Examples</h2>

<h3>Basic conversion</h3>
{/* jtc-check */}
<p>Input JSON:</p>
<pre><code>{`[{"id":1,"name":"Alice"},{"id":2,"name":"Bob"}]`}</code></pre>
<p>Output CSV:</p>
<pre><code>{`id,name\n1,Alice\n2,Bob`}</code></pre>

<h3>Nested object flattening</h3>
<p>Input JSON:</p>
<pre><code>{`[{"user":{"name":"Alice","age":30}}]`}</code></pre>
<p>Output CSV (flatten on):</p>
<pre><code>{`user.name,user.age\nAlice,30`}</code></pre>

<h3>Fields with commas</h3>
<p>A field value containing a comma is automatically quoted:</p>
<pre><code>{`name,description\nWidget,"Small, round widget"`}</code></pre>

<h3>Arrays, missing keys and quotes</h3>
{/* jtc-check */}
<p>Input JSON with an array, a two-level nested object, a missing key and a value with quotes:</p>
<pre><code>{`[{"id":1,"name":"Ann","tags":["a","b"],"address":{"city":"Paris","geo":{"lat":48.85}}},
 {"id":2,"name":"Bo, Jr.","note":"says \\"hi\\""}]`}</code></pre>
<p>Output CSV with flatten on:</p>
<pre><code>{`id,name,tags,address.city,address.geo.lat,note
1,Ann,"[""a"",""b""]",Paris,48.85,
2,"Bo, Jr.",,,,"says ""hi"""`}</code></pre>
<p>Flattening follows nested objects to any depth (<code>address.geo.lat</code>). Arrays are not split into columns: <code>tags</code> is written as the JSON text <code>["a","b"]</code>, quoted because it contains <code>"</code>. The header is the union of the keys of all rows, in the order they first appear, so <code>note</code> comes last and row 1 leaves it empty. With flatten off, <code>address</code> becomes one column holding <code>{`{"city":"Paris","geo":{"lat":48.85}}`}</code>.</p>

<h3>Semicolon delimiter for European Excel</h3>
<p>Excel in locales that use a decimal comma (German, French and others) reads <code>;</code> as the list separator. <code>{`[{"sku":"A-1","price":9.5,"active":true},{"sku":"B-2","price":null}]`}</code> with the semicolon delimiter gives <code>sku;price;active</code>, <code>A-1;9.5;true</code> and <code>B-2;;</code>. Numbers keep the JSON decimal point, <code>true</code> is written as text, and <code>null</code> becomes an empty field. The Tab delimiter gives TSV, which pastes straight into spreadsheet cells.</p>

<h2>Quoting and Line Breaks</h2>
<p>
  Quoting follows <a href="https://www.rfc-editor.org/rfc/rfc4180#section-2" target="_blank" rel="noopener">RFC 4180 §2</a>: a field that contains the delimiter, a double quote, a line feed or a carriage return
  is enclosed in double quotes, and a literal double quote is written as <code>""</code>. Rows are separated
  by a line feed (LF), not the CR LF that the RFC describes; Excel, LibreOffice, pandas and Python's <code>csv</code>
  module all read both.
</p>

<h2>Formula Guard</h2>
<p>
  A cell that starts with <code>=</code>, <code>+</code>, <code>-</code> or <code>@</code>, a Tab or a line break can be run as a formula when the CSV is opened in a spreadsheet
  (<a href="https://owasp.org/www-community/attacks/CSV_Injection" target="_blank" rel="noopener">OWASP: CSV Injection</a>). The tool counts such string values and the status line reports them. With the guard on, each of them gets a prefix and is quoted, as the OWASP page recommends:
  <strong>' prefix</strong> adds <code>'</code>, and <strong>Tab prefix (Excel)</strong> adds a Tab, which OWASP gives as the form Excel keeps after the file is saved and opened again. Input:
</p>
{/* jtc-check: {"guard":"quote"} */}
<pre><code>{`[{"name":"Ann","comment":"=HYPERLINK(\\"http://example.com\\",\\"Click\\")"}]`}</code></pre>
<p>Output with the <code>'</code> prefix:</p>
<pre><code>{`name,comment
Ann,"'=HYPERLINK(""http://example.com"",""Click"")"`}</code></pre>
<p>
  Only JSON strings are changed. Numbers such as <code>-5</code>, booleans, and arrays or objects written as JSON text are left as they are. The guard also changes the data: a phone number such as <code>+81 3 1234 5678</code> keeps the prefix, so the guard is off by default and the status line tells you when it would apply.
</p>

<h2>Excel and the Byte Order Mark</h2>
<p>
  The downloaded file starts with the UTF-8 byte order mark (bytes <code>EF BB BF</code>) by default. Microsoft's support page
  <a href="https://support.microsoft.com/en-us/office/opening-csv-utf-8-files-correctly-in-excel-8a935af5-3416-4edd-ba7e-3dfd2bc4a032" target="_blank" rel="noopener">Opening CSV UTF-8 files correctly in Excel</a> says a UTF-8 CSV opens normally when it was saved with a BOM; without one, Excel on Windows reads a double-clicked file in the system code page, and accented or CJK text appears garbled.
  Programs that do not expect a BOM can read it as part of the first header name: Python's <code>open(..., encoding="utf-8")</code> gives <code>\ufeffid</code>, while <code>encoding="utf-8-sig"</code> removes it. Turn the option off for those. <strong>Copy</strong> never adds a BOM.
</p>

<h2>Limits</h2>
<ul>
  <li>The input must be a JSON array. A single object gives "Input must be a JSON array of objects"; wrap it in <code>[ ]</code>. Items that are not objects, such as <code>[1,"two",null]</code>, become a single <code>value</code> column.</li>
  <li>Empty nested objects and arrays are not expanded: <code>{`"meta":{}`}</code> gives a <code>meta</code> column holding <code>{`{}`}</code>.</li>
  <li>Integers above 2<sup>53</sup> lose precision when the JSON is parsed: <code>12345678901234567890</code> is written as <code>12345678901234567000</code>. Store long IDs as strings in the JSON.</li>
  <li>Rows are separated by LF. Excel, LibreOffice, pandas and Python's <code>csv</code> module read it; tools that require CR LF need a conversion.</li>
</ul>
