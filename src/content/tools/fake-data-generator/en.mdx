<h2>Use Cases</h2>
<p>
  Fake data helps at many stages of software development. Seed a dev database without
  copying real user records into it. Mock an API response for frontend development.
  Fill a spreadsheet for QA testing or a UI demo that needs to look realistic.
</p>
<p>
  The values are drawn from fixed word lists and random numbers in the page script, with no
  external library. UUIDs come from the browser's <code>crypto.randomUUID()</code>; the other
  fields use <code>Math.random()</code>, which is fine for test data but not for secrets.
</p>

## Field Formats

Every value comes from a fixed English word list or a random number. The formats below match the generator code:

| Field | Format | Example |
|---|---|---|
| Full Name | first name + last name (40 × 30 names) | `Susan Smith` |
| Email | `first.last` + two digits + `@` provider domain | `richard.hernandez90@hotmail.com` |
| Phone | US style `(NXX) NXX-XXXX` | `(545) 491-8460` |
| Street / City / State / Zip | house number + street name; US state code; 5-digit ZIP | `2275 Main St`, `Franklin`, `NJ`, `81966` |
| UUID | version 4 from `crypto.randomUUID()` | `94095dcb-d3ad-42d5-8a12-f082307eeaff` |
| Date | `YYYY-MM-DD`, 2020–2026, day 1–28 | `2022-11-19` |
| IP Address | IPv4 only | `208.157.61.111` |
| URL | `https://` + name + TLD + one path segment | `https://danieldavis.app/login` |
| Color (Hex) | `#` + 6 lowercase hex digits | `#69daa0` |

## Examples

A seed file for a `contacts` table: Full Name, Company and Date checked, Count 3, CSV. One run gave this result:

{/* fdg-check: {"fields":["fullName","company","date"],"count":3,"format":"csv"} */}

```csv
fullName,company,date
Charles Lee,Massive Dynamic,2023-03-09
Linda Smith,Weyland-Yutani,2022-06-11
Mary Gonzalez,Pied Piper,2020-06-01
```

Your run will show other names, because every Generate draws new values. What stays the same: the header row uses the field keys (`fullName`, not the checkbox label "Full Name"), the columns follow the order of the field list, and no value is quoted because none of the word lists contain a comma or a double quote. Lines end with LF, not the CRLF that [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180#section-2) describes; set your importer to accept LF if it insists on CRLF.

{/* fdg-count: {"count":"150"} */}

Count accepts whole numbers from 1 to 100. Typing 150 and clicking Generate gives `100` records. The field changes to 100 and the status line says `Enter a whole number from 1 to 100. Records generated: 100.` A decimal such as 2.9 keeps its whole-number part (2 records), and an empty field or 0 gives 10.

## Limits

- **Fields are independent.** In one record, Email is not built from Full Name, and City, State, Zip, and Country do not form a real address. A record can have `"state": "NJ"` and `"country": "United Kingdom"`.
- **US and English only.** The data is the same on every language version of this page: English names, US state codes, US phone numbers.
- **Values repeat.** With 40 first names and 30 last names there are 1,200 full names, so the chance that 100 records contain a repeated Full Name is {/* fdg-dup: {"field":"fullName","n":100,"digits":1} */}`98.6%`. Emails have 864,000 possible values (names × 90 two-digit numbers × 8 domains), and the chance of a repeat in 100 records is {/* fdg-dup: {"field":"email","n":100,"digits":2} */}`0.57%`. Use UUID when you need a unique key.
- **Some values can be real.** Email domains include real providers such as gmail.com, and phone numbers and IPv4 addresses are random, so a value can belong to a real person or host. Do not send mail to them or call them. For values that are reserved for documentation, use `example.com` ([RFC 2606](https://www.rfc-editor.org/rfc/rfc2606)) and `192.0.2.0/24` ([RFC 5737](https://www.rfc-editor.org/rfc/rfc5737)); for phone numbers, the 555-01XX range ([NANPA](https://www.nanpa.com/numbering/555-line-numbers)).
- **100 records per run.** There is no SQL export and no custom fields, and the same settings never give the same output twice (there is no seed).

## When to Use a Library Instead

Use [@faker-js/faker](https://fakerjs.dev/) in code when you need related fields, other locales, thousands of rows, or the same data on every run:

```javascript
import { faker } from '@faker-js/faker';

faker.seed(42); // same output on every run
const firstName = faker.person.firstName();
const lastName = faker.person.lastName();
const user = {
  name: `${firstName} ${lastName}`,
  email: faker.internet.email({ firstName, lastName }),
};
```
