<h2>활용 사례</h2>
<p>
  가짜 데이터는 개발의 여러 단계에서 쓰입니다. 실제 사용자 기록을 옮기지 않고 개발용 데이터베이스를 채우거나, 프론트엔드 개발용 API 응답을 모킹하거나, QA 테스트와 그럴듯하게 보여야 하는 UI 데모용 스프레드시트를 채울 수 있습니다.
</p>
<p>
  값은 페이지 스크립트에 있는 고정 단어 목록과 난수로 만들며 외부 라이브러리는 쓰지 않습니다. UUID는 브라우저의 <code>crypto.randomUUID()</code>로 만들고, 나머지 필드는 <code>Math.random()</code>을 씁니다. 테스트 데이터로는 충분하지만 비밀번호나 키를 만드는 용도에는 맞지 않습니다.
</p>

## 필드 형식

모든 값은 고정된 영어 단어 목록이나 난수로 만들어집니다. 아래 표는 생성 코드와 일치합니다.

| 필드 | 형식 | 예시 |
|---|---|---|
| 전체 이름 | 이름 + 성 (이름 40개 × 성 30개) | `Susan Smith` |
| 이메일 | `이름.성` + 두 자리 숫자 + `@` + 메일 서비스 도메인 | `richard.hernandez90@hotmail.com` |
| 전화 | 미국 형식 `(NXX) NXX-XXXX` | `(545) 491-8460` |
| 거리 / 도시 / 주·도 / 우편번호 | 번지 + 거리 이름, 미국 주 코드, 5자리 ZIP | `2275 Main St`, `Franklin`, `NJ`, `81966` |
| UUID | `crypto.randomUUID()`로 만든 v4 | `94095dcb-d3ad-42d5-8a12-f082307eeaff` |
| 날짜 | `YYYY-MM-DD`, 2020–2026년, 일은 1–28 | `2022-11-19` |
| IP 주소 | IPv4만 | `208.157.61.111` |
| URL | `https://` + 이름 + TLD + 경로 한 단계 | `https://danieldavis.app/login` |
| 색상 (Hex) | `#` + 소문자 16진수 6자리 | `#69daa0` |

## 예시: 회원 테이블에 넣을 CSV

회원 목록 화면을 테스트하려고 이름, 휴대전화, 주소 열이 있는 테이블에 CSV를 넣는다고 해 봅시다. ‘전체 이름’, ‘전화’, ‘거리’를 체크하고 개수 3, CSV로 생성했더니 이런 결과가 나왔습니다.

{/* fdg-check: {"fields":["fullName","phone","street"],"count":3,"format":"csv"} */}

```csv
fullName,phone,street
Linda Garcia,(297) 268-2584,9415 Maple Ave
Susan Ramirez,(397) 968-4268,3964 Oak St
Richard Garcia,(998) 425-5774,7857 Riverside Rd
```

생성할 때마다 값은 달라지지만 형식은 같습니다. 첫 줄은 화면의 한국어 라벨이 아니라 `fullName,phone,street` 같은 필드 키 이름이고, 어느 단어 목록에도 쉼표나 큰따옴표가 없어서 따옴표로 감싼 칸이 없습니다. 전화번호는 괄호와 공백이 들어간 미국식 14자이므로, 010으로 시작하는 11자리만 받는 검증(예: `^010\d{8}$`)은 세 값을 모두 거부합니다. 형식 오류 메시지를 확인하는 테스트에는 그대로 쓸 수 있지만, 정상 흐름 테스트에는 한국 번호를 따로 준비해야 합니다. 이 근거가 되는 010 통합 방침은 [방송통신위원회 보도자료(2010-09-15)](https://kcc.go.kr/user.do?boardId=1113&boardSeq=29628&cp=349&dc=K00000001&mode=view&page=A05030000)에 있습니다.

## 예시: 개수 입력

{/* fdg-count: {"count":"150"} */}

개수에 150을 넣고 생성하면 `100`개가 만들어지고, 입력란이 100으로 바뀌며 상태 표시줄에 `개수는 1~100 사이의 정수로 입력하세요. 이번에는 100개를 생성했습니다.`가 나타납니다. 2.9는 2개, 빈 값이나 0은 10개이며, 어느 경우든 입력란이 실제 개수로 바뀌므로 입력한 값과 결과가 다를 때 바로 알 수 있습니다.

## 제한 사항

- **필드끼리 관련이 없습니다.** 같은 레코드라도 이메일은 전체 이름으로 만들지 않으며, 도시·주·우편번호·국가는 실제 주소가 되지 않습니다. `"state": "NJ"`와 `"country": "United Kingdom"`이 함께 나올 수 있습니다.
- **미국·영어 데이터만 있습니다.** 한국어 페이지에서도 영어 이름, 미국 주 코드, 미국 전화 형식이 나오며 한국 이름·주소·010 번호는 만들지 않습니다.
- **값이 중복됩니다.** 전체 이름은 40 × 30 = 1,200가지뿐이라 100개 중 같은 이름이 하나 이상 있을 확률은 {/* fdg-dup: {"field":"fullName","n":100,"digits":1} */}`98.6%`입니다. 이메일은 864,000가지(이름 × 두 자리 숫자 90 × 도메인 8)이고 100개에서 겹칠 확률은 {/* fdg-dup: {"field":"email","n":100,"digits":2} */}`0.57%`입니다. 고유 키가 필요하면 UUID를 쓰세요.
- **실제로 존재하는 값이 나올 수 있습니다.** 이메일 도메인에는 gmail.com 같은 실제 서비스가 있고 전화번호와 IPv4 주소는 난수이므로, 실제 사람이나 호스트의 값과 같을 수 있습니다. 메일을 보내거나 전화를 걸지 마세요. 문서용으로 예약된 값이 필요하면 `example.com`([RFC 2606](https://www.rfc-editor.org/rfc/rfc2606))과 `192.0.2.0/24`([RFC 5737](https://www.rfc-editor.org/rfc/rfc5737))를 사용합니다.
- **한 번에 100개까지, 시드 없음.** SQL 내보내기와 필드 추가는 지원하지 않고, 같은 설정이라도 매번 다른 결과가 나옵니다. CSV 줄바꿈은 LF이며 [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180#section-2)의 CRLF가 아닙니다.

## 라이브러리를 쓰는 편이 나은 경우

필드 간 연관, 한국 데이터, 수천 행 이상, 매번 같은 결과가 필요하면 코드에서 [@faker-js/faker](https://fakerjs.dev/)를 사용합니다 (`fakerKO`로 한국어 이름과 주소를 만들 수 있습니다).

```javascript
import { fakerKO as faker } from '@faker-js/faker';

faker.seed(42); // 매번 같은 출력
const user = {
  name: faker.person.fullName(),
  city: faker.location.city(),
};
```
