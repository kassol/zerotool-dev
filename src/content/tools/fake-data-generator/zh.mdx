<h2>使用场景</h2>
<p>
  假数据在软件开发各阶段不可或缺：用于填充开发数据库而不污染真实用户数据，为前端开发模拟 API 响应，或为需要看起来真实的 QA 测试和 UI 演示填充电子表格。
</p>
<p>
  所有生成均在客户端完成，零依赖。姓名、地址等值从精选词库中随机组合。UUID 生成使用浏览器的 <code>crypto.randomUUID()</code> API，具备加密级别的随机性。
</p>

## 字段格式

所有值都来自固定的英文词表或随机数。下表与生成器代码一致：

| 字段 | 格式 | 示例 |
|---|---|---|
| 全名 | 名 + 姓（40 个名 × 30 个姓） | `Susan Smith` |
| 邮箱 | `名.姓` + 两位数字 + `@` 邮件服务商域名 | `richard.hernandez90@hotmail.com` |
| 电话 | 美国格式 `(NXX) NXX-XXXX` | `(545) 491-8460` |
| 街道 / 城市 / 州 / 邮编 | 门牌号 + 街道名；美国州代码；5 位 ZIP | `2275 Main St`、`Franklin`、`NJ`、`81966` |
| UUID | `crypto.randomUUID()` 生成的 v4 | `94095dcb-d3ad-42d5-8a12-f082307eeaff` |
| 日期 | `YYYY-MM-DD`，2020–2026 年，日为 1–28 | `2022-11-19` |
| IP 地址 | 仅 IPv4 | `208.157.61.111` |
| URL | `https://` + 名字 + 顶级域 + 一段路径 | `https://danieldavis.app/login` |
| 颜色 (Hex) | `#` + 6 位小写十六进制 | `#69daa0` |

## 限制

- **字段之间互不关联。** 同一条记录里，邮箱不是由全名拼出来的；城市、州、邮编、国家也组不成真实地址，可能出现 `"state": "NJ"` 配 `"country": "United Kingdom"`。
- **只有美国 / 英文数据。** 中文页面生成的也是英文姓名、美国州代码和美国电话格式，没有中文姓名、省市或 11 位手机号。
- **值会重复。** 实测 2,000 次、每次 100 条：98.9% 的批次里至少有一个全名重复，1% 的批次有邮箱重复。需要唯一键时用 UUID。
- **个别值可能真实存在。** 邮箱域名包含 gmail.com 等真实服务商，电话和 IPv4 地址是随机数，生成的值可能恰好属于真实的人或主机，不要向它们发邮件或拨打。需要保留给文档使用的值时，用 `example.com`（[RFC 2606](https://www.rfc-editor.org/rfc/rfc2606)）和 `192.0.2.0/24`（[RFC 5737](https://www.rfc-editor.org/rfc/rfc5737)）。
- **每次最多 100 条。** 超出的数量按 100 处理；不支持导出 SQL，也不能自定义字段。

## 什么时候改用代码库

需要字段之间互相关联、其他地区的数据、成千上万行，或每次运行得到相同数据时，在代码里用 [@faker-js/faker](https://fakerjs.dev/)（`fakerZH_CN` 提供中文姓名与地址）：

```javascript
import { fakerZH_CN as faker } from '@faker-js/faker';

faker.seed(42); // 每次运行输出相同
const user = {
  name: faker.person.fullName(),
  city: faker.location.city(),
};
```
