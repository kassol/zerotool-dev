<h2>使用场景</h2>
<p>
  开发测试中经常需要一批「像真的」数据：填充开发数据库而不复制真实用户记录，为前端模拟 API 响应，为 QA 测试或 UI 演示准备一张表格。
</p>
<p>
  这些值来自页面脚本里固定的词表和随机数，不依赖外部库。UUID 用浏览器的 <code>crypto.randomUUID()</code> 生成；其他字段用 <code>Math.random()</code>，用作测试数据没有问题，但不能用来生成密码或密钥。
</p>

## 字段格式

所有值都来自固定的英文词表或随机数。下表与生成器代码一致：

| 字段 | 格式 | 示例 |
|---|---|---|
| 全名 | 名 + 姓（40 个名 × 30 个姓） | `Susan Smith` |
| 邮箱 | `名.姓` + 两位数字 + `@` 邮件服务商域名 | `richard.hernandez90@hotmail.com` |
| 电话 | 美国格式 `(NXX) NXX-XXXX` | `(545) 491-8460` |
| 街道 / 城市 / 州 / 邮编 | 门牌号 + 街道名；美国州代码；5 位 ZIP | `2275 Main St`、`Franklin`、`NJ`、`81966` |
| UUID | `crypto.randomUUID()` 生成的 v4 | `94095dcb-d3ad-42d5-8a12-f082307eeaff` |
| 日期 | `YYYY-MM-DD`，2020–2026 年，日为 1–28 | `2022-11-19` |
| IP 地址 | 仅 IPv4 | `208.157.61.111` |
| URL | `https://` + 名字 + 顶级域 + 一段路径 | `https://danieldavis.app/login` |
| 颜色 (Hex) | `#` + 6 位小写十六进制 | `#69daa0` |

## 示例：给注册接口准备测试数据

假设要测一个用户注册接口，请求体里有 `name` 和 `mobile` 两个字段，后端按中国大陆手机号校验 `mobile`。勾选「全名」和「电话」，数量填 2，格式选 JSON，某一次生成的结果是：

{/* fdg-check: {"fields":["fullName","phone"],"count":2,"format":"json"} */}

```json
[
  {
    "fullName": "Joseph Rodriguez",
    "phone": "(291) 650-9868"
  },
  {
    "fullName": "Amelia Jackson",
    "phone": "(896) 469-7301"
  }
]
```

每次生成的姓名和号码都不同，但格式固定：键名是 `fullName` 和 `phone`，与界面上的中文标签无关；电话一律是 14 个字符的美国写法。按工信部[《电信网编号计划（2017年版）》](https://www.miit.gov.cn/n1146295/n1652858/n1652930/n3757020/c5623267/part/5623278.doc)，公众移动网电话号码的国内有效号码位长为 11 位、首位为 1，所以这两个值都会被 `^1\d{10}$` 一类的校验拒绝。这正好可以拿来测「格式错误」的分支；要测成功的分支，`mobile` 需要另外准备。注意：随手拼出来的 11 位号码可能就是别人在用的号码，测试环境里不要真的给它发验证码短信。

另外，全名是英文的 `名 姓`，没有中文姓名；如果接口限制 `name` 只能是汉字，这些值同样会被拒绝。

## 示例：数量输入框

{/* fdg-count: {"count":"0"} */}

「数量」填 0 再点击生成，得到 `10` 条记录，输入框变成 10，状态栏提示 `数量须为 1–100 的整数，本次生成了 10 条。`。填 2.9 会生成 2 条（取整数部分），填 150 会生成 100 条，输入框都会改成实际使用的数字，不会出现「填的是 150、实际只生成 100 条」却看不出来的情况。

## 限制

- **字段之间互不关联。** 同一条记录里，邮箱不是由全名拼出来的；城市、州、邮编、国家也组不成真实地址，可能出现 `"state": "NJ"` 配 `"country": "United Kingdom"`。
- **只有美国 / 英文数据。** 中文页面生成的也是英文姓名、美国州代码和美国电话格式，没有中文姓名、省市或 11 位手机号。
- **值会重复。** 全名只有 40 × 30 = 1,200 种组合，100 条记录里至少有一个全名重复的概率是 {/* fdg-dup: {"field":"fullName","n":100,"digits":1} */}`98.6%`；邮箱有 864,000 种（姓名 × 90 个两位数 × 8 个域名），100 条里出现重复的概率是 {/* fdg-dup: {"field":"email","n":100,"digits":2} */}`0.57%`。需要唯一键时用 UUID。
- **个别值可能真实存在。** 邮箱域名包含 gmail.com 等真实服务商，电话和 IPv4 地址是随机数，生成的值可能恰好属于真实的人或主机，不要向它们发邮件或拨打。需要保留给文档使用的值时，用 `example.com`（[RFC 2606](https://www.rfc-editor.org/rfc/rfc2606)）和 `192.0.2.0/24`（[RFC 5737](https://www.rfc-editor.org/rfc/rfc5737)）。
- **每次最多 100 条，没有种子。** 不支持导出 SQL，也不能自定义字段；同样的设置每次生成的结果都不同。CSV 行尾是 LF，不是 [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180#section-2) 写的 CRLF。

## 什么时候改用代码库

需要字段之间互相关联、其他地区的数据、成千上万行，或每次运行得到相同数据时，在代码里用 [@faker-js/faker](https://fakerjs.dev/)（`fakerZH_CN` 提供中文姓名与地址）：

```javascript
import { fakerZH_CN as faker } from '@faker-js/faker';

faker.seed(42); // 每次运行输出相同
const user = {
  name: faker.person.fullName(),
  city: faker.location.city(),
};
```
