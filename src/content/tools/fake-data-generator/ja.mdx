<h2>活用シーン</h2>
<p>
  フェイクデータは開発のいろいろな場面で使えます。実ユーザーのデータを持ち込まずに開発用データベースを埋める、フロントエンド開発用に API レスポンスをモックする、QA テストや見た目を確かめる UI デモ用のスプレッドシートを作る、といった用途です。
</p>
<p>
  値はページのスクリプトにある固定の単語リストと乱数から作り、外部ライブラリは使いません。UUID はブラウザの <code>crypto.randomUUID()</code> で生成し、ほかのフィールドは <code>Math.random()</code> を使います。テストデータには十分ですが、パスワードや鍵の生成には向きません。
</p>

## フィールドの形式

値はすべて固定の英語の単語リストか乱数から作られます。下の表は生成コードと一致しています。

| フィールド | 形式 | 例 |
|---|---|---|
| フルネーム | 名 + 姓（名 40 × 姓 30） | `Susan Smith` |
| メール | `名.姓` + 2 桁の数字 + `@` + メールサービスのドメイン | `richard.hernandez90@hotmail.com` |
| 電話 | 米国形式 `(NXX) NXX-XXXX` | `(545) 491-8460` |
| 番地 / 市区町村 / 都道府県 / 郵便番号 | 番地 + 通り名、米国の州コード、5 桁の ZIP | `2275 Main St`、`Franklin`、`NJ`、`81966` |
| UUID | `crypto.randomUUID()` による v4 | `94095dcb-d3ad-42d5-8a12-f082307eeaff` |
| 日付 | `YYYY-MM-DD`、2020〜2026 年、日は 1〜28 | `2022-11-19` |
| IPアドレス | IPv4 のみ | `208.157.61.111` |
| URL | `https://` + 名前 + TLD + パス 1 階層 | `https://danieldavis.app/login` |
| カラー (Hex) | `#` + 小文字の 16 進 6 桁 | `#69daa0` |

## 例：会員登録フォームのテスト

氏名・都道府県・郵便番号・電話番号を入力する会員登録フォームに、テスト用の値を流し込む場面を考えます。「フルネーム」「都道府県」「郵便番号」「電話」をチェックし、件数 2、JSON で生成したところ、次の結果になりました。

{/* fdg-check: {"fields":["fullName","state","zip","phone"],"count":2,"format":"json"} */}

```json
[
  {
    "fullName": "Jennifer Moore",
    "state": "VT",
    "zip": "74552",
    "phone": "(497) 426-1678"
  },
  {
    "fullName": "Susan Williams",
    "state": "ME",
    "zip": "62854",
    "phone": "(390) 238-8259"
  }
]
```

値は生成のたびに変わりますが、形は毎回同じです。ラベルは「都道府県」でも中身は `VT` のような米国の州コードで、「郵便番号」は 5 桁の ZIP、電話は米国式の 14 文字です。総務省の[電気通信番号制度](https://www.soumu.go.jp/main_sosiki/joho_tsusin/top/tel_number/index.html)では、音声伝送携帯電話番号は 060・070・080・090 で始まる 11 桁なので、`^0[6-9]0\d{8}$` のような入力チェックはこの電話番号をすべて拒否します。「形式エラー」の表示を確かめるテストにはそのまま使えますが、正常系のテストには日本の値を別に用意する必要があります。キー名は `fullName`、`state` のように英語のままで、画面のラベルとは関係ありません。

## 例：件数の入力

{/* fdg-count: {"count":"2.5"} */}

件数に 2.5 と入れて生成すると `2` 件になり、入力欄が 2 に変わってステータス欄に `件数は 1〜100 の整数で指定してください。今回は 2 件を生成しました。` と表示されます。150 なら 100 件、空欄や 0 なら 10 件で、いずれも入力欄が実際の件数に書き換わるので、指定と結果の食い違いに気付けます。

## 制限事項

- **フィールドは互いに無関係です。** 同じレコードでもメールはフルネームから作られず、市区町村・都道府県・郵便番号・国は実在の住所になりません。`"state": "NJ"` と `"country": "United Kingdom"` が並ぶこともあります。
- **米国・英語のデータだけです。** 日本語の氏名・住所・日本の電話番号は生成されません。
- **値は重複します。** フルネームは 40 × 30 = 1,200 通りしかないので、100 件の中に同じフルネームが 1 つ以上ある確率は {/* fdg-dup: {"field":"fullName","n":100,"digits":1} */}`98.6%` です。メールは 864,000 通り（氏名 × 2 桁の数字 90 × ドメイン 8）で、100 件で重複する確率は {/* fdg-dup: {"field":"email","n":100,"digits":2} */}`0.57%` です。一意のキーには UUID を使ってください。
- **実在する値が混ざることがあります。** メールのドメインには gmail.com などの実在サービスが含まれ、電話番号と IPv4 アドレスは乱数なので、実在の人やホストと一致する可能性があります。メール送信や発信には使わないでください。ドキュメント用に予約された値が必要なら `example.com`（[RFC 2606](https://www.rfc-editor.org/rfc/rfc2606)）と `192.0.2.0/24`（[RFC 5737](https://www.rfc-editor.org/rfc/rfc5737)）を使います。
- **1 回 100 件まで、シードなし。** SQL 出力やフィールドの追加はできず、同じ設定でも毎回違う結果になります。CSV の改行は LF で、[RFC 4180](https://www.rfc-editor.org/rfc/rfc4180#section-2) の CRLF ではありません。

## ライブラリを使うべき場面

フィールド同士の関連、日本のデータ、数千件以上、毎回同じ結果が必要なときは、コードで [@faker-js/faker](https://fakerjs.dev/) を使います（`fakerJA` で日本語の氏名や住所を生成できます）。

```javascript
import { fakerJA as faker } from '@faker-js/faker';

faker.seed(42); // 毎回同じ出力
const user = {
  name: faker.person.fullName(),
  city: faker.location.city(),
};
```
