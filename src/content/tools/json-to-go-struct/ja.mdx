<h2>型マッピング</h2>
<ul>
  <li><code>null</code> → <code>interface{"{}"}</code></li>
  <li>文字列 → <code>string</code></li>
  <li>整数 → <code>int</code></li>
  <li>浮動小数点数 → <code>float64</code></li>
  <li>真偽値 → <code>bool</code></li>
  <li>配列 → <code>[]T</code></li>
  <li>nullable/省略可能 → ポインタ（<code>*T</code>）</li>
  <li>ネストオブジェクト → 独立した名前付き <code>struct</code></li>
</ul>

## 例：API レスポンス

```json
{
  "user": {
    "id": 42,
    "name": "Alice",
    "email": "alice@example.com",
    "is_active": true,
    "roles": ["admin", "editor"],
    "address": { "city": "New York", "country": "US", "zip_code": "10001" },
    "last_login": null
  }
}
```

から次の構造体が生成されます。

```go
type RootObject struct {
	User User `json:"user"`
}

type User struct {
	Id int `json:"id"`
	Name string `json:"name"`
	Email string `json:"email"`
	IsActive bool `json:"is_active"`
	Roles []string `json:"roles"`
	Address Address `json:"address"`
	LastLogin interface{} `json:"last_login"`
}

type Address struct {
	City string `json:"city"`
	Country string `json:"country"`
	ZipCode string `json:"zip_code"`
}
```

`snake_case` のキーは `CamelCase` のフィールド名になり、`json` タグに元のキーが残るので、`encoding/json` で双方向に対応します。フィールドは揃えられていないため、`gofmt`（または保存時に整形するエディタ）でタグを揃えてください。標準ライブラリでデコードします：

```go
var root RootObject
if err := json.Unmarshal(data, &root); err != nil {
	log.Fatal(err)
}
fmt.Println(root.User.Name) // Alice
```

## 例：トップレベルが配列の場合

```json
[{"sku": "A1", "qty": 2}, {"sku": "B2", "note": "gift"}]
```

から次の構造体が生成されます。

```go
type RootObject struct {
	Sku string `json:"sku"`
	Qty *int `json:"qty,omitempty"`
	Note *string `json:"note,omitempty"`
}
```

トップレベルが配列のとき、構造体は要素1つ分を表すので `[]RootObject` にデコードします。一部の要素にないキーは `omitempty` 付きのポインタになります。

## 例：同じキー名、小数、数字で始まるキー

```json
{
  "order": { "id": "A-1001", "total": 19.0, "meta": { "createdBy": "alice", "source": "web" } },
  "payment": { "status": "paid", "meta": { "provider": "stripe", "fee": 0.3 } },
  "2fa": true
}
```

から生成される構造体：

```go
type RootObject struct {
	Order Order `json:"order"`
	Payment Payment `json:"payment"`
	X2fa bool `json:"2fa"`
}

type Order struct {
	Id string `json:"id"`
	Total float64 `json:"total"`
	Meta Meta `json:"meta"`
}

type Meta struct {
	CreatedBy string `json:"createdBy"`
	Source string `json:"source"`
}

type Payment struct {
	Status string `json:"status"`
	Meta PaymentMeta `json:"meta"`
}

type PaymentMeta struct {
	Provider string `json:"provider"`
	Fee float64 `json:"fee"`
}
```

`payment.meta` は `order.meta` とフィールドが違うので別の構造体になり、親の名前を前に付けた `PaymentMeta` になります（同じフィールドなら両方で `Meta` を共有）。`19.0` は小数点付きで書かれているので `total` は `float64` です。`encoding/json` は `19.0` を `int` のフィールドにデコードしません。ツールはブラウザの JSON ソーステキストアクセス（Chrome 114+、Firefox 135+、Safari 18.4+）で数値の書き方を読みます。対応していないブラウザでは `19` に見えるため `int` のままです。キー `2fa` はエクスポートされる名前の先頭に使えないので、フィールド名は `X2fa`、タグは `2fa` のままです。

## 生成後に直すところ

- `null` は `interface{}` になります。API ドキュメントを確認して `*string` や `*time.Time` など実際の型のポインタに変えてください。
- `.` や指数のない数値は `int`、`19.0` や `1e3` は `float64` になります。同じ配列やキーに整数と小数が混ざると `float64` です。サンプルがたまたま整数だけのフィールド（価格など）は `int` のままなので確認してください。64 ビット環境では `int` は 64 ビットです。
- `[]` と、それ以外で要素の型が混在する配列は `[]interface{}` になります。
- フィールド名は Go の頭字語の慣習に合わせて調整されません。`id` は `Id`、`url` は `Url` になりますが、[Go Code Review Comments](https://go.dev/wiki/CodeReviewComments#initialisms) は `ID`・`URL` を推奨しています。どちらでも `json` タグがあるのでデコードは正しく動きます。
- フィールド名が大文字で始まらないキー（`2fa`、`名前`）は先頭に `X` を付けます（`X2fa`）。同じフィールド名になる 2 つのキー（`user_id`、`userId`）には番号を付けます（`UserId2`）。空のキーや、構造体タグに書けない文字（`"`、`,` など）を含むキーは、`encoding/json` がタグで対応付けられないため、フィールドではなくコメントに書きます。
- `PaymentMeta` や `Meta2` のような名前は JSON のキーから作られます。用途に合わせて名前を変えてください。
- 出力されるのは `json` タグだけです。`gorm`・`bson`・`validate` のタグは自分で追加します。

## 制限

- {/* jgs-error: {"input":"{\"a\": 1,}"} */}入力は有効な JSON である必要があります。無効なときは出力を消去してコピーを無効にし、ステータスに行・列と考えられる原因を表示します。行と列は入力したままのテキストで数えます（末尾のカンマがある `{"a": 1,}` なら `無効なJSON：1 行 8 列目、閉じかっこの前に余分なカンマがあります。`）。
- 型は貼り付けたサンプルだけから決まります。
