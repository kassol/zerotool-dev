<h2>转换示例</h2>

<h3>YAML 输入</h3>

```yaml
database:
  host: localhost
  port: 5432
  enabled: true
tags:
  - web
  - backend
```

<h3>等效 TOML 输出</h3>

```toml
tags = [ "web", "backend" ]

[database]
host = "localhost"
port = 5432
enabled = true
```

<h2>日期和时间</h2>
<p>YAML 时间戳写成 TOML 日期，不写成字符串：</p>

```yaml
release:
  date: 2026-10-01
  at: 2026-10-01 09:30:00 +9
  utc: 2026-10-01T00:30:00Z
  label: "2026-10-01"
  ratio: .inf
```

```toml
[release]
date = 2026-10-01
at = 2026-10-01T09:30:00.000+09:00
utc = 2026-10-01T00:30:00.000Z
label = "2026-10-01"
ratio = inf
```

<p>只有日期时写成 TOML 本地日期。日期时间保留偏移，写成 <code>+09:00</code>；没有偏移的日期时间写成 <code>Z</code>，因为 <a href="https://yaml.org/type/timestamp.html">YAML 时间戳类型</a>把它读作 UTC。加引号的 <code>"2026-10-01"</code> 仍是字符串，<code>.inf</code> 写成 TOML 的 <code>inf</code>。TOML 日期只保留到毫秒，<code>09:30:00.123456Z</code> 这类更精确的时间戳和 <code>2026-02-31</code> 这类不存在的日期会停止转换。</p>

<p>反方向时，TOML 解析器只保留到毫秒、舍去后面的位数，所以更精确的时间会停止 TOML → YAML：<code>[build]</code> 表里的 <code>started = 2026-10-01T09:30:00.123456Z</code> 得到 <code>未转换：YAML 无法原样保存下列值：/build/started：2026-10-01T09:30:00.123456Z 的精度超过毫秒</code>。TOML 本地日期时间没有偏移，而 YAML 把不带偏移的时间戳读作 UTC，所以 <code>[build]</code> 表里的 <code>started = 2026-10-01T09:30:00</code> 也会停止：<code>未转换：YAML 无法原样保存下列值：/build/started：2026-10-01T09:30:00 是本地日期时间，YAML 会把不带偏移的时间读作 UTC</code>。YAML → TOML 时，YAML 的 <code>-0.0</code> 写成 TOML 的 <code>-0.0</code>，保留负号；<code>ratio: 1.0</code> 这样的整数值浮点数仍写成浮点数（<code>ratio = 1.0</code>）。</p>

<h2>TOML 无法保存的值</h2>
<p>值在转换中会改变时，工具不转换，状态栏按 JSON Pointer 列出每个字段和原因：</p>

```yaml
service:
  id: 9007199254740993
  owner: ~
```

<p><code>未转换：TOML 无法原样保存下列值：/service/id：整数 9007199254740993 超出 ±(2^53 − 1)，JavaScript 会把它四舍五入；/service/owner：null，TOML 没有 null</code></p>
<p>TOML 面板被清空，复制按钮停用，不会误复制旧结果。给大 ID 加引号（<code>{'id: "9007199254740993"'}</code>），替换或删除 null 后再转换。−(2<sup>53</sup> − 1) 到 2<sup>53</sup> − 1 之间的整数原样转换。</p>
<p><code>!!binary</code> 数据同样会停止转换，因为 TOML 没有二进制类型：<code>photo: !!binary aGVsbG8=</code> 得到 <code>未转换：TOML 无法原样保存下列值：/photo：!!binary 二进制值，TOML 没有二进制类型</code>。</p>

<h2>限制</h2>
<ul>
  <li><strong>根必须是映射，一次一个文档。</strong>含 <code>---</code> 的多文档输入会报错 <code>expected a single document in the stream, but found more</code>。</li>
  <li><strong>两个方向都拒绝大整数。</strong>TOML → YAML 时 <code>big = 9007199254740993</code> 报错 <code>integer value cannot be represented losslessly</code> 并标出行；YAML → TOML 时按上文列出字段。</li>
  <li><strong>js-yaml 的处理上限。</strong>js-yaml 4.3.2 遇到嵌套超过 100 层、合并键（<code>{'<<'}</code>）累计处理的映射和键超过 10,000 个、一个合并键列出超过 100 个映射的文档会停止，错误信息写明上限和行列。</li>
  <li><strong>注释不保留，锚点会展开。</strong></li>
</ul>

<h2>YAML 与 TOML 对比</h2>
<p>
  <strong>YAML</strong> 以其人性化的缩进语法，广泛用于应用配置（Docker Compose、Kubernetes、GitHub Actions）。
  <strong>TOML</strong> 是 Rust 项目（<code>Cargo.toml</code>）、Python 打包（<code>pyproject.toml</code>）以及 Hugo、Zola 等工具的标准配置格式。
  本工具在两者之间对两种格式共同支持的数据类型进行转换。
</p>
