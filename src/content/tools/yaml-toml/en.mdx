<h2>How to Use</h2>
<ol>
  <li>To convert <strong>YAML → TOML</strong>: paste your YAML into the left panel — the TOML output updates automatically.</li>
  <li>To convert <strong>TOML → YAML</strong>: paste your TOML into the right panel — the YAML output updates automatically.</li>
  <li>Click <strong>Swap</strong> to exchange both panels and flip the conversion direction.</li>
  <li>Use <strong>Ctrl+Enter</strong> (or <strong>Cmd+Enter</strong> on Mac) as a keyboard shortcut from whichever panel you are editing.</li>
  <li>Click <strong>Copy</strong> on either panel to copy the result to your clipboard.</li>
</ol>

<h2>Worked Example</h2>

<h3>YAML input</h3>

```yaml
database:
  host: localhost
  port: 5432
  enabled: true
tags:
  - web
  - backend
```

<h3>Equivalent TOML output</h3>

```toml
tags = [ "web", "backend" ]

[database]
host = "localhost"
port = 5432
enabled = true
```

<p>
  Notice that <code>tags</code> moved above <code>[database]</code>. In TOML every key after a <code>[table]</code> header belongs
  to that table, so top-level plain values must come first. The converter (<a href="https://github.com/squirrelchat/smol-toml">smol-toml</a>
  1.6.1 for TOML, <a href="https://github.com/nodeca/js-yaml">js-yaml</a> 4.1.1 for YAML) reorders keys this way: within each table, plain values keep their order and sub-tables follow them.
</p>

<h2>Example: a Cargo.toml to YAML</h2>
<p>Pasting this into the TOML panel:</p>

```toml
[package]
name = "zerotool"
version = "0.1.0"
edition = "2021"

[dependencies]
serde = { version = "1.0", features = ["derive"] }

[[bin]]
name = "cli"
path = "src/main.rs"
```

<p>gives this YAML:</p>

```yaml
package:
  name: zerotool
  version: 0.1.0
  edition: '2021'
dependencies:
  serde:
    version: '1.0'
    features:
      - derive
bin:
  - name: cli
    path: src/main.rs
```

<p>
  The inline table becomes a nested mapping and <code>[[bin]]</code> (an array of tables) becomes a list. The strings
  <code>"2021"</code> and <code>"1.0"</code> are quoted in YAML because unquoted they would be read as numbers; <code>0.1.0</code>
  is not a number, so it stays unquoted. Going the other way, a YAML list of mappings such as a <code>services:</code> list becomes
  repeated <code>[[services]]</code> blocks.
</p>

<h2>Limits and Error Messages</h2>
<ul>
  <li><strong>Root must be a mapping.</strong> A YAML list or scalar at the top level gives "YAML root must be a mapping (object), not a scalar or sequence."</li>
  <li><strong>One document.</strong> YAML with <code>---</code> between documents gives "expected a single document in the stream, but found more".</li>
  <li><strong>Large TOML integers are rejected,</strong> not rounded: <code>big = 9007199254740993</code> gives "integer value cannot be represented losslessly" with the line shown. The YAML → TOML direction does not have this check (see the table above).</li>
  <li><strong>Duplicate TOML keys</strong> give "trying to redefine an already defined table or value", with the line and a caret under the problem.</li>
  <li><strong>Comments are dropped</strong> in both directions, because both parsers return plain data. Keep a copy of a commented file before converting it.</li>
  <li><strong>Anchors are expanded.</strong> <code>y: *a</code> becomes a full copy of the anchored mapping; the TOML output has no way to share it.</li>
</ul>

<h2>YAML vs TOML</h2>
<p>
  <strong>YAML</strong> is widely used for application configuration (Docker Compose, Kubernetes, GitHub Actions) due to its human-friendly, indentation-based syntax.
  <strong>TOML</strong> is the standard for Rust projects (<code>Cargo.toml</code>), Python packaging (<code>pyproject.toml</code>), and tools like Hugo and Zola.
  This tool converts between them for data types common to both formats. To convert either one to JSON instead, use the <a href="/tools/yaml-json/">YAML ↔ JSON</a> or <a href="/tools/toml-json/">TOML ↔ JSON</a> converter.
</p>
