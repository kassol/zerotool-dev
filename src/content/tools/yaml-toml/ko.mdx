<h2>변환 예시</h2>

<h3>YAML 입력</h3>

```yaml
database:
  host: localhost
  port: 5432
  enabled: true
tags:
  - web
  - backend
```

<h3>TOML 출력</h3>

```toml
tags = [ "web", "backend" ]

[database]
host = "localhost"
port = 5432
enabled = true
```

<h2>날짜와 시간</h2>
<p>YAML 타임스탬프는 문자열이 아니라 TOML 날짜로 출력합니다.</p>

```yaml
release:
  date: 2026-10-01
  at: 2026-10-01 09:30:00 +9
  utc: 2026-10-01T00:30:00Z
  label: "2026-10-01"
  ratio: .inf
```

```toml
[release]
date = 2026-10-01
at = 2026-10-01T09:30:00.000+09:00
utc = 2026-10-01T00:30:00.000Z
label = "2026-10-01"
ratio = inf
```

<p>날짜만 있으면 TOML 로컬 날짜가 됩니다. 날짜·시간은 오프셋을 유지해 <code>+09:00</code>으로 씁니다. 오프셋이 없는 날짜·시간은 <code>Z</code>를 붙입니다. <a href="https://yaml.org/type/timestamp.html">YAML 타임스탬프 타입</a>이 이를 UTC로 정의하기 때문입니다. 따옴표로 감싼 <code>"2026-10-01"</code>은 문자열로 남고, <code>.inf</code>는 TOML <code>inf</code>가 됩니다. TOML 날짜는 밀리초까지만 담으므로 <code>09:30:00.123456Z</code>처럼 더 정밀한 타임스탬프나 <code>2026-02-31</code>처럼 없는 날짜가 있으면 변환을 멈춥니다.</p>

<p>반대 방향에서는 TOML 파서가 밀리초 아래 자릿수를 버리므로 더 정밀한 시간이 있으면 TOML → YAML 변환을 멈춥니다. <code>[build]</code> 테이블의 <code>started = 2026-10-01T09:30:00.123456Z</code>는 <code>변환하지 않았습니다: YAML에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /build/started: 2026-10-01T09:30:00.123456Z — 밀리초보다 정밀합니다</code> 메시지를 냅니다. TOML 로컬 날짜·시간에는 오프셋이 없고 YAML은 오프셋 없는 타임스탬프를 UTC로 읽으므로, <code>[build]</code> 테이블의 <code>started = 2026-10-01T09:30:00</code>도 <code>변환하지 않았습니다: YAML에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /build/started: 2026-10-01T09:30:00 — 로컬 날짜·시간입니다. YAML은 오프셋이 없는 시간을 UTC로 읽습니다</code> 메시지와 함께 멈춥니다. YAML → TOML에서는 YAML의 <code>-0.0</code>이 부호를 유지한 TOML <code>-0.0</code>이 되고, <code>ratio: 1.0</code>처럼 값이 정수인 부동소수점도 부동소수점(<code>ratio = 1.0</code>)으로 남습니다.</p>

<h2>TOML로 나타낼 수 없는 값</h2>
<p>변환 중 값이 바뀌면 아무것도 변환하지 않고, 상태 줄에 각 필드를 JSON Pointer로 표시하고 이유를 씁니다.</p>

```yaml
service:
  id: 9007199254740993
  owner: ~
```

<p><code>변환하지 않았습니다: TOML에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /service/id: 정수 9007199254740993 — ±(2^53 − 1) 범위를 벗어나 JavaScript에서 반올림됩니다; /service/owner: null — TOML에는 null이 없습니다</code></p>
<p>TOML 패널은 비워지고 복사 버튼은 비활성화되어 이전 결과를 잘못 복사하지 않습니다. 큰 ID는 따옴표로 감싸고(<code>{'id: "9007199254740993"'}</code>) null을 바꾸거나 지운 뒤 다시 변환하세요. −(2<sup>53</sup> − 1)부터 2<sup>53</sup> − 1까지의 정수는 그대로 변환됩니다.</p>
<p><code>!!binary</code> 데이터도 TOML에 바이너리 자료형이 없어 변환하지 않습니다. <code>photo: !!binary aGVsbG8=</code>는 <code>변환하지 않았습니다: TOML에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: /photo: !!binary 값 — TOML에는 바이너리 자료형이 없습니다</code> 메시지를 냅니다.</p>
<p><code>!!binary</code>를 키로 쓴 경우에도 변환하지 않습니다. js-yaml은 이 키를 바이트 값 목록(아래 예에서는 <code>107,49</code>)으로 바꿉니다. PyYAML 6.0.3은 <code>bytes</code> 키를 이렇게 쓰며, <code>{"yaml.dump({b'k1': 1})"}</code>의 출력은 다음과 같습니다.</p>

```yaml
? !!binary |
  azE=
: 1
```

<p>도구는 <code>변환하지 않았습니다: TOML에서는 다음 값을 바꾸지 않고 나타낼 수 없습니다: (루트): !!binary 키 azE= — TOML의 키는 문자열만 쓸 수 있습니다</code> 메시지를 냅니다. <code>{'m: {<<: !!binary aGk=}'}</code>처럼 <code>{'<<'}</code>로 <code>!!binary</code> 데이터를 병합해도 <code>{'/m: !!binary aGk= — <<로는 매핑만 병합할 수 있습니다'}</code>로 멈춥니다.</p>

<h2>제한 사항</h2>
<ul>
  <li><strong>루트는 매핑이어야 하고 문서는 하나만 됩니다.</strong> <code>---</code>로 구분한 여러 문서는 <code>expected a single document in the stream, but found more</code> 오류가 납니다.</li>
  <li><strong>큰 정수는 양방향 모두 멈춥니다.</strong> TOML → YAML에서는 <code>big = 9007199254740993</code>이 <code>integer value cannot be represented losslessly</code> 오류와 줄 번호를 냅니다. YAML → TOML에서는 위처럼 필드를 표시합니다.</li>
  <li><strong>js-yaml 처리 한도.</strong> js-yaml 4.3.2는 중첩이 100단계를 넘거나, 병합 키(<code>{'<<'}</code>)가 처리하는 매핑과 키가 모두 10,000개를 넘거나, 병합 키 하나에 매핑을 100개 넘게 나열한 문서에서 멈춥니다. 오류에는 한도와 줄·열이 나옵니다.</li>
  <li><strong>주석은 남지 않고 앵커는 펼쳐집니다.</strong></li>
</ul>

<h2>YAML과 TOML 비교</h2>
<p>
  <strong>YAML</strong>은 들여쓰기 기반 문법으로 가독성이 높아 Docker Compose, Kubernetes, GitHub Actions 등의 애플리케이션 설정에 널리 사용됩니다.
  <strong>TOML</strong>은 Rust(<code>Cargo.toml</code>), Python 패키징(<code>pyproject.toml</code>), Hugo, Zola 등 도구의 표준 설정 형식입니다.
  이 도구는 두 형식이 공통으로 지원하는 데이터 타입을 상호 변환합니다.
</p>
