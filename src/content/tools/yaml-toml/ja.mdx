<h2>使い方</h2>
<ol>
  <li><strong>YAML → TOML</strong>：左パネルにYAMLを貼り付けると、TOML出力が自動的に更新されます。</li>
  <li><strong>TOML → YAML</strong>：右パネルにTOMLを貼り付けると、YAML出力が自動的に更新されます。</li>
  <li><strong>入れ替え</strong>をクリックすると、両パネルの内容が交換され変換方向が切り替わります。</li>
  <li>編集中のパネルで<strong>Ctrl+Enter</strong>（MacはCmd+Enter）のショートカットが使えます。</li>
  <li>各パネルの<strong>コピー</strong>ボタンで結果をクリップボードにコピーできます。</li>
</ol>

<h2>変換例</h2>

<h3>YAML入力</h3>

```yaml
database:
  host: localhost
  port: 5432
  enabled: true
tags:
  - web
  - backend
```

<h3>TOML出力</h3>

```toml
tags = [ "web", "backend" ]

[database]
host = "localhost"
port = 5432
enabled = true
```

<h2>日付と時刻</h2>
<p>YAML のタイムスタンプは文字列ではなく TOML の日付として書き出します。</p>

```yaml
release:
  date: 2026-10-01
  at: 2026-10-01 09:30:00 +9
  utc: 2026-10-01T00:30:00Z
  label: "2026-10-01"
  ratio: .inf
```

```toml
[release]
date = 2026-10-01
at = 2026-10-01T09:30:00.000+09:00
utc = 2026-10-01T00:30:00.000Z
label = "2026-10-01"
ratio = inf
```

<p>日付だけなら TOML のローカル日付になります。日時はオフセットを残して <code>+09:00</code> と書きます。オフセットのない日時は <code>Z</code> を付けます。<a href="https://yaml.org/type/timestamp.html">YAML のタイムスタンプ型</a>はこれを UTC と定めているためです。引用符付きの <code>"2026-10-01"</code> は文字列のまま、<code>.inf</code> は TOML の <code>inf</code> になります。TOML の日付はミリ秒までなので、<code>09:30:00.123456Z</code> のように細かいタイムスタンプや、<code>2026-02-31</code> のような存在しない日付があると変換を止めます。</p>

<h2>TOML で表せない値</h2>
<p>変換で値が変わる場合は何も変換せず、ステータス行に各フィールドを JSON Pointer で示して理由を書きます。</p>

```yaml
service:
  id: 9007199254740993
  owner: ~
```

<p><code>変換していません：TOML では次の値を変えずに表せません：/service/id：整数 9007199254740993 は ±(2^53 − 1) を超えるため、JavaScript では丸められます；/service/owner：null — TOML には null がありません</code></p>
<p>TOML パネルは空になり、コピーボタンは無効になるので、古い結果を誤ってコピーすることはありません。大きな ID は引用符で囲み（<code>{'id: "9007199254740993"'}</code>）、null を置き換えるか削除してから変換し直してください。−(2<sup>53</sup> − 1) から 2<sup>53</sup> − 1 までの整数はそのまま変換されます。</p>

<h2>制限事項</h2>
<ul>
  <li><strong>ルートはマッピング、文書は 1 つだけです。</strong><code>---</code> で区切った複数文書は <code>expected a single document in the stream, but found more</code> になります。</li>
  <li><strong>大きな整数はどちらの方向でも止まります。</strong>TOML → YAML では <code>big = 9007199254740993</code> が <code>integer value cannot be represented losslessly</code> となり行が示されます。YAML → TOML では上のようにフィールドを示します。</li>
  <li><strong>js-yaml の処理上限。</strong>js-yaml 4.3.2 は、ネストが 100 階層を超える文書、マージキー（<code>{'<<'}</code>）で処理するマッピングとキーが合計 10,000 個を超える文書、1 つのマージキーに 100 個を超えるマッピングを並べた文書を止めます。エラーには上限と行・列が出ます。</li>
  <li><strong>コメントは残らず、アンカーは展開されます。</strong></li>
</ul>

<h2>YAMLとTOMLの違い</h2>
<p>
  <strong>YAML</strong>はインデントベースの構文で可読性が高く、Docker Compose・Kubernetes・GitHub Actionsなどのアプリケーション設定に広く使われています。
  <strong>TOML</strong>はRust（Cargo.toml）・Python（pyproject.toml）・HugoやZolaなどのツールの標準設定形式です。
  本ツールは両形式に共通するデータ型を相互変換します。
</p>
