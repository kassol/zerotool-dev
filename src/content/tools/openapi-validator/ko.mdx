<h2>사용 방법</h2>
<ol>
  <li>OpenAPI 스펙(YAML 또는 JSON)을 에디터에 붙여넣습니다.</li>
  <li><strong>검증</strong>을 클릭하거나 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>를 누릅니다.</li>
  <li>유효하면 API 제목, 버전, 경로 수, 오퍼레이션 수가 요약 패널에 표시됩니다.</li>
  <li>유효하지 않으면 각 오류가 JSON 경로와 설명과 함께 나열됩니다.</li>
</ol>

<h2>OpenAPI 3.x 필수 필드</h2>
<ul>
  <li><code>openapi</code> — 버전 문자열 (예: <code>"3.0.3"</code> 또는 <code>"3.1.0"</code>)</li>
  <li><code>info.title</code> — API 이름</li>
  <li><code>info.version</code> — API 버전 (예: <code>"1.0.0"</code>)</li>
  <li><code>paths</code> — 경로 항목 맵; 각 키는 <code>/</code>로 시작해야 함</li>
</ul>

<h2>자주 발생하는 실수</h2>
<ul>
  <li>OpenAPI 3.x 대신 Swagger 2.x 형식(<code>swagger: "2.0"</code>) 사용 — <code>swagger</code>를 <code>openapi: "3.0.3"</code>으로 변경하고 <code>definitions</code>를 <code>components/schemas</code>로 업데이트하세요.</li>
  <li>오퍼레이션 내에 <code>responses</code> 객체 없음 — 모든 오퍼레이션은 최소 하나의 응답을 선언해야 합니다.</li>
  <li><code>/</code>로 시작하지 않는 경로 키 — 모든 경로는 절대 경로여야 합니다 (예: <code>/users/&#123;id&#125;</code>).</li>
  <li>YAML 들여쓰기 오류 — 먼저 <a href="/ko/tools/yaml-validator/">YAML 유효성 검사기</a>로 구문 문제를 해결하세요.</li>
</ul>

<h2>검증기가 확인하는 것</h2>

<ul>
  <li><code>{"openapi"}</code>가 있고 <code>{"3.x.y"}</code> 형태인지. <code>{"swagger: \"2.0\""}</code> 문서에는 마이그레이션 안내를 보여 줍니다.</li>
  <li><code>{"info"}</code>가 있고 <code>{"title"}</code>과 <code>{"version"}</code>을 갖는지.</li>
  <li><code>{"paths"}</code>가 있고, 모든 경로 키가 <code>{"/"}</code>로 시작하며, 모든 오퍼레이션(get, put, post, delete, options, head, patch, trace)에 비어 있지 않은 <code>{"responses"}</code>가 있는지.</li>
</ul>

<p>세 군데가 틀린 입력:</p>

<pre><code>{`openapi: 3.0.3
info:
  title: Orders API
paths:
  orders/{id}:
    get:
      summary: Get one order
  /orders:
    post:
      responses:
        "201":
          description: Created`}</code></pre>

<p>보고되는 오류:</p>

<pre><code>{`info.version            Missing required field "info.version".
paths.orders/{id}       Path key "orders/{id}" must start with "/".
paths.orders/{id}.get.responses
                        Operation "GET orders/{id}" must have a non-empty "responses" object.`}</code></pre>

<h2>확인하지 않는 것</h2>

<p>위 확인은 구조만 봅니다. 공개 전에는 <a href="https://redocly.com/docs/cli/commands/lint" target="_blank" rel="noopener">Redocly CLI</a>(<code>{"redocly lint openapi.yaml"}</code>)나 <a href="https://github.com/stoplightio/spectral" target="_blank" rel="noopener">Spectral</a> 같은 완전한 검증기도 돌리세요. 특히 주의할 결과가 두 가지 있습니다:</p>

<ul>
  <li><strong><code>{"$ref"}</code> 대상을 해석하지 않습니다.</strong> 다음 문서는 <code>{"#/components/schemas/User"}</code>가 없고 경로 파라미터 <code>{"id"}</code>도 선언되지 않았는데 「유효」로 표시됩니다:</li>
</ul>

<pre><code>{`openapi: 3.0.3
info:
  title: Broken refs
  version: 1.0.0
paths:
  /users/{id}:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"`}</code></pre>

<ul>
  <li><strong>OpenAPI 3.1 문서에도 3.0 규칙을 적용합니다.</strong> 3.1에서는 <code>{"paths"}</code>, <code>{"components"}</code>, <code>{"webhooks"}</code> 중 하나만 있으면 되고(<a href="https://spec.openapis.org/oas/v3.1.0#openapi-object" target="_blank" rel="noopener">OpenAPI 3.1.0 §4.8.1</a>), 오퍼레이션에 <code>{"responses"}</code>가 없어도 됩니다. 다음의 webhooks만 있는 3.1 문서는 유효하지만 도구는 <code>{"Missing required object \"paths\"."}</code>를 보고합니다:</li>
</ul>

<pre><code>{`openapi: 3.1.0
info:
  title: Order events
  version: 1.0.0
webhooks:
  orderCreated:
    post:
      responses:
        "200":
          description: OK`}</code></pre>

<p>스키마, 파라미터 정의, 보안 스킴, 예시도 검증하지 않습니다. YAML 문법 오류는 이 확인들보다 먼저 YAML 파서가 보고합니다.</p>
