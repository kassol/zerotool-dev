<p>OpenAPI나 Swagger 문서를 붙여넣거나 파일·폴더를 여세요. 버전에 맞는 공식 JSON Schema로 구조를 검증하고, 파일 사이의 <code>$ref</code>를 따라가며, 스키마만으로는 표현할 수 없는 규칙도 확인합니다. 모든 문제에는 줄과 열이 붙고, 누르면 편집기에서 그 줄을 선택합니다.</p>

<h2>공공데이터포털 Swagger 2.0 문서</h2>
<p>공공데이터포털(data.go.kr)의 일부 API는 명세를 Swagger 2.0 문서로 제공합니다. 예를 들어 「예방접종센터 위치정보 API」 문서(<code>infuser.odcloud.kr/oas/docs?namespace=15077586/v1</code>, 2026-10-03 조회)를 넣으면 오류 3건과 OpenAPI 3 변환 안내가 나옵니다. 오류는 아래에 설명한 <code>exclusiveMinimum</code> 문제입니다. 이 문서는 <code>Authorization</code> 헤더(<code>ApiKeyAuth</code>)와 <code>serviceKey</code> 쿼리(<code>ApiKeyAuth2</code>) 두 가지 인증을 선언합니다. 아래 발췌본처럼 보안 요구사항의 이름을 잘못 쓰면 오류가 됩니다.</p>

{/* ov */}
<pre><code>{`{
  "swagger": "2.0",
  "info": {"version": "1", "title": "예방접종센터 위치정보 API (발췌)"},
  "host": "api.odcloud.kr",
  "basePath": "/api",
  "schemes": ["https"],
  "securityDefinitions": {
    "ApiKeyAuth": {"type": "apiKey", "in": "header", "name": "Authorization"},
    "ApiKeyAuth2": {"type": "apiKey", "in": "query", "name": "serviceKey"}
  },
  "paths": {
    "/15077586/v1/centers": {
      "get": {
        "parameters": [
          {"name": "page", "in": "query", "type": "integer", "format": "int64", "default": 1},
          {"name": "perPage", "in": "query", "type": "integer", "format": "int64", "default": 10}
        ],
        "responses": {"200": {"description": "성공적으로 수행 됨"}},
        "security": [{"ApiKeyAuth": []}, {"ApiKeyAuth3": []}]
      }
    }
  }
}`}</code></pre>

{/* ov-out */}
<pre><code>{`2:3  정보  Swagger 2.0 문서이며 Swagger 2.0 스키마로 검증했습니다. OpenAPI 3로 옮기려면 변환한 뒤(예: npx swagger2openapi swagger.yaml -o openapi.yaml) 결과를 다시 검증하세요.
9:5  경고  보안 정의 "ApiKeyAuth2"을(를) 참조하는 곳이 없습니다.
19:43  오류  보안 스킴 "ApiKeyAuth3"이(가) securityDefinitions에 선언되지 않았습니다.`}</code></pre>

<p>원본 문서의 쿼리 파라미터 세 개(<code>page</code>, <code>perPage</code>, <code>returnType</code>)에는 <code>minimum</code> 없이 <code>"exclusiveMinimum": false</code>가 붙어 있습니다. Swagger 2.0이 따르는 JSON Schema draft 4는 「exclusiveMinimum이 있으면 minimum도 있어야 한다」(MUST)고 정하므로, 이 도구는 세 곳을 각각 오류로 냅니다. <code>"exclusiveMinimum": false</code>를 지우면 통과합니다. Spectral 6.17.0은 같은 규칙을 기본값(<code>default</code>)이 있는 두 파라미터의 예제 확인에서만 오류로 내고, Redocly CLI 2.57.0은 보고하지 않습니다.</p>

<h2>같은 경로 템플릿과 예제 값</h2>
<p><code>/members/{'{memberId}'}</code>와 <code>/members/{'{id}'}</code>처럼 파라미터 이름만 다른 경로는 같은 URL에 맞기 때문에 사양에서 허용하지 않습니다(Paths Object의 MUST). 예제에서는 <code>enum</code>에 없는 등급 값이 경고로 나옵니다.</p>

{/* ov */}
<pre><code>{`openapi: 3.0.3
info:
  title: 회원 API
  version: 1.0.0
paths:
  /members/{memberId}:
    get:
      parameters:
        - {name: memberId, in: path, required: true, schema: {type: string}}
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Member"
              example:
                memberId: M-0001
                phone: 010-1234-5678
                grade: VVIP
  /members/{id}:
    delete:
      parameters:
        - {name: id, in: path, required: true, schema: {type: string}}
      responses:
        "204": {description: 삭제됨}
components:
  schemas:
    Member:
      type: object
      required: [memberId, phone]
      properties:
        memberId: {type: string}
        phone: {type: string, pattern: "^01[0-9]-?[0-9]{3,4}-?[0-9]{4}$"}
        grade: {type: string, enum: [BASIC, VIP]}
    Address:
      type: object`}</code></pre>

{/* ov-out */}
<pre><code>{`20:17  경고  예제가 스키마와 맞지 않습니다 (/grade): 다음 중 하나여야 합니다: "BASIC", "VIP".
21:3  오류  경로 "/members/{id}"는 "/members/{memberId}"와 같은 템플릿입니다(파라미터 이름만 다름). 사양상 둘 다 둘 수 없습니다.
36:5  경고  스키마 "Address"을(를) 참조하는 곳이 없습니다.`}</code></pre>

<h2>중복된 파라미터</h2>
<p>같은 이름과 위치(<code>in</code>)의 파라미터는 한 목록에 한 번만 올 수 있습니다. 공식 스키마는 이 규칙을 확인하지 않으므로, 아래 문서는 스키마 검증만으로는 통과합니다. <code>info.version</code>의 따옴표 없는 날짜는 YAML 1.2 Core Schema에 따라 문자열로 읽으므로 오류가 아닙니다.</p>

{/* ov */}
<pre><code>{`openapi: 3.1.0
info:
  title: 결제 API
  version: 2026-10-02
paths:
  /payments:
    post:
      parameters:
        - {name: Idempotency-Key, in: header, required: true, schema: {type: string}}
        - {name: Idempotency-Key, in: header, schema: {type: string}}
      responses:
        "200": {description: OK}`}</code></pre>

{/* ov-out */}
<pre><code>{`10:11  오류  파라미터 "Idempotency-Key"(in: header)이(가) 이 목록의 1번째에도 있습니다. 같은 이름과 위치는 한 번만 쓸 수 있습니다.`}</code></pre>

<h2>다른 도구와 비교</h2>
<p>2026-10-02에 같은 시험 문서로 비교했습니다. 선언하지 않은 경로 파라미터, 선언하지 않은 보안 스킴, 이름만 다른 두 경로, 속성의 <code>required: true</code>라는 네 가지 오류와, 따옴표 없는 날짜로 쓴 <code>info.version</code>이 들어 있습니다.</p>
<ul>
  <li>Redocly CLI 2.57.0과 Spectral 6.17.0은 네 가지를 모두 찾았고, summary나 4XX 응답 같은 스타일 규칙도 많이 냅니다. swagger-parser 13.1.0은 유효하다고 판정했습니다.</li>
  <li>Swagger Editor 5.8.9(editor.swagger.io)는 브라우저에서 동작하며 경로 파라미터와 <code>required</code> 문제는 찾았지만, 같은 템플릿의 경로와 선언되지 않은 스킴은 표시하지 않았습니다.</li>
  <li>DevUtilities의 OpenAPI 검증기는 서버로 보내지 않고 동작하지만 결과는 「VALID WITH WARNINGS」였고, 경고는 servers가 없다는 한 건뿐이었습니다.</li>
</ul>

<h2>제한</h2>
<ul>
  <li>이름 짓기나 설명 같은 스타일 규칙은 다루지 않습니다. 팀 규칙은 이 도구 다음에 Redocly CLI나 Spectral로 확인하세요.</li>
  <li><code>$ref</code>의 URL은 가져오지 않으니 파일을 추가하세요. 앵커 참조(<code>#name</code>)는 확인하지 않습니다.</li>
  <li>JSON이 아닌 미디어 타입(<code>application/xml</code> 등)의 문자열 예제는 직렬화된 본문으로 보고 스키마와 비교하지 않습니다.</li>
  <li>매우 큰 문서는 예제 확인을 4초에서 멈추고 알려 줍니다. 2 MB가 넘는 입력은 「검증」을 눌렀을 때 확인하고, 합계 50 MB가 넘는 파일은 불러오지 않습니다.</li>
  <li>연 파일이 512 K자를 넘으면 전체를 검증하지만 편집 칸에는 최대 300줄을 읽기 전용으로 보여 줍니다. 10 MB 정도를 편집 칸에 넣으면 페이지가 0.5초쯤 멈추기 때문입니다. 줄 번호를 누르면 그 줄로 이동하고, 「전체 복사」「다운로드」「전체 편집(느림)」으로 전체 내용을 다룰 수 있습니다. 직접 그만큼 붙여 넣으면 여전히 페이지가 멈춥니다.</li>
  <li>YAML은 js-yaml 4.3.2로 읽습니다. 중첩이 100단계를 넘거나, 병합 키가 처리하는 매핑과 키가 모두 10,000개를 넘거나, 병합 키 하나에 매핑을 100개 넘게 나열한 문서는 멈추고, 오류에 한도와 줄 번호가 나옵니다.</li>
</ul>
