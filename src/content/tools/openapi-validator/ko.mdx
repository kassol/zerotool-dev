<h2>OpenAPI 유효성 검사기</h2>
<p>YAML 또는 JSON 형식의 OpenAPI 3.0, 3.1, 3.2 문서를 붙여 넣어 API 게이트웨이, SDK 생성기, 문서 도구에 넘기기 전에 확인하세요. <code>openapi</code> 필드에 맞는 공식 JSON Schema를 골라 Ajv로 검사하고, Schema만으로는 확인할 수 없는 부분을 추가로 검사합니다.</p>

<h2>사용 방법</h2>
<ol>
  <li>OpenAPI 스펙(YAML 또는 JSON)을 편집기에 붙여 넣습니다.</li>
  <li><strong>검증</strong>을 누르거나 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>를 누릅니다.</li>
  <li>유효하면 API 제목, 버전, OpenAPI 버전, 경로 수, 오퍼레이션 수를 보여 줍니다.</li>
  <li>유효하지 않으면 오류마다 위치를 JSON Pointer(<code>$ref</code>와 같은 표기)로 보여 줍니다.</li>
  <li>따라가지 않은 참조는 <strong>확인하지 않음</strong>에 나열됩니다.</li>
</ol>

<h2>검증기가 확인하는 것</h2>
<ul>
  <li><strong>구조</strong>: <a href="https://spec.openapis.org/" target="_blank" rel="noopener">spec.openapis.org</a>가 공개한 공식 Schema로 검사합니다. 3.0(Schema 2024-10-18), 3.1(2026-08-03), 3.2(2026-08-30). 필수 필드와 알 수 없는 필드, 값 타입, 파라미터·응답·보안 스킴 등의 형태를 확인합니다. <code>x-</code>로 시작하는 필드는 스펙이 확장을 허용하는 곳이면 어디서나 쓸 수 있습니다.</li>
  <li><strong>문서 안의 <code>$ref</code></strong>: <code>#/components/schemas/User</code>가 문서에 있어야 합니다. 포인터의 <code>~1</code>, <code>~0</code>, 퍼센트 인코딩은 먼저 디코딩합니다. <code>example</code>, <code>default</code>, Example 객체의 <code>value</code> 안의 <code>$ref</code>는 데이터이므로 확인하지 않습니다.</li>
  <li><strong>경로 파라미터</strong>: 경로의 <code>&#123;name&#125;</code>마다 Path Item이나 오퍼레이션에 <code>in: path</code> 파라미터가 있어야 하고, <code>in: path</code> 파라미터는 경로에 나타나야 합니다(스펙의 Path Templating).</li>
  <li><strong>operationId</strong>는 <code>paths</code>와 <code>webhooks</code> 전체에서 중복되면 안 됩니다.</li>
</ul>

<p>세 곳이 잘못된 입력:</p>

{/* ov: {"errors": ["#/info Missing required field \"version\".", "#/paths Path \"orders/{id}\" must start with \"/\".", "#/paths/orders~1{id}/get GET orders/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Orders API
paths:
  orders/{id}:
    get:
      summary: Get one order
  /orders:
    post:
      responses:
        "201":
          description: Created`}</code></pre>

<p>보고되는 오류:</p>

<pre><code>{`#/info
    Missing required field "version".
#/paths
    Path "orders/{id}" must start with "/".
#/paths/orders~1{id}/get
    GET orders/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p><code>get</code> 오퍼레이션에도 <code>responses</code>가 없지만, 경로 키 자체가 잘못되어 Schema가 그 안을 검사하지 않습니다. 보고된 오류를 고친 뒤 다시 검사하세요.</p>

<p>존재하지 않는 Schema 참조와 선언되지 않은 경로 파라미터:</p>

{/* ov: {"errors": ["#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref Reference \"#/components/schemas/User\" does not point to anything in this document.", "#/paths/~1users~1{id}/get GET /users/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Broken refs
  version: 1.0.0
paths:
  /users/{id}:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"`}</code></pre>

<pre><code>{`#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref
    Reference "#/components/schemas/User" does not point to anything in this document.
#/paths/~1users~1{id}/get
    GET /users/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p><code>webhooks</code>만 있는 3.1 문서는 유효합니다. OpenAPI 3.1은 <code>paths</code>, <code>components</code>, <code>webhooks</code> 중 하나 이상을 요구하고(<a href="https://spec.openapis.org/oas/v3.1.0#openapi-object" target="_blank" rel="noopener">OpenAPI 3.1.0 §4.8.1</a>), <code>responses</code>도 생략할 수 있습니다.</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.1.0
info:
  title: Order events
  version: 1.0.0
webhooks:
  orderCreated:
    post:
      requestBody:
        content:
          application/json:
            schema:
              type: object`}</code></pre>

<h2>확인하지 않는 것</h2>

<p>외부 참조는 나열만 하고 가져오지 않습니다. 다음 문서는 유효로 판정되고 '확인하지 않음'에 한 건이 표시됩니다.</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Pets
  version: 1.0.0
paths:
  /pets:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "./schemas/pet.yaml"`}</code></pre>

<ul>
  <li>공식 Schema는 Schema 객체의 내용을 자세히 검사하지 않습니다(3.1, 3.2는 객체나 불리언이기만 하면 됩니다). Schema 안의 키워드 오타는 보고되지 않습니다.</li>
  <li>위 세 가지 외에 본문에만 적힌 규칙은 확인하지 않습니다. 예시 값을 Schema로 검사하지 않고, 보안 요구 사항을 보안 스킴과 대조하지도 않습니다.</li>
  <li>이름, 설명, 태그 같은 스타일은 <a href="https://redocly.com/docs/cli/commands/lint" target="_blank" rel="noopener">Redocly CLI</a>나 <a href="https://github.com/stoplightio/spectral" target="_blank" rel="noopener">Spectral</a> 같은 린터로 확인하세요.</li>
  <li>YAML 구문 오류는 YAML 파서가 먼저 보고합니다. 줄 번호는 <a href="/ko/tools/yaml-validator/">YAML 검사기</a>에서 볼 수 있습니다.</li>
</ul>

<p>OpenAPI Initiative의 <a href="https://github.com/OAI/learn.openapis.org/tree/main/examples" target="_blank" rel="noopener">learn.openapis.org 예제</a> 11개(petstore, uspto, tictactoe, 3.2 query 예제 등)는 모두 오류 없이 검사됩니다.</p>
