<h2>OpenAPI Validator Online</h2>
<p>Paste an OpenAPI 3.0 or 3.1 document in YAML or JSON and validate the structure before sharing it with frontend teams, API gateways, SDK generators, or documentation tools. The validator highlights missing required fields, invalid paths, and operations without responses.</p>

<h2>How to Use</h2>
<ol>
  <li>Paste your OpenAPI spec (YAML or JSON) into the editor.</li>
  <li>Click <strong>Validate</strong> or press <kbd>Ctrl</kbd>+<kbd>Enter</kbd>.</li>
  <li>If valid, a summary panel shows the API title, version, path count, and operation count.</li>
  <li>If invalid, each error is listed with its JSON path and a description.</li>
</ol>

<h2>Required OpenAPI 3.x Fields</h2>
<ul>
  <li><code>openapi</code> — version string, e.g. <code>"3.0.3"</code> or <code>"3.1.0"</code></li>
  <li><code>info.title</code> — human-readable API name</li>
  <li><code>info.version</code> — API version, e.g. <code>"1.0.0"</code></li>
  <li><code>paths</code> — map of path item objects; each key must begin with <code>/</code></li>
</ul>

<h2>Common Mistakes</h2>
<ul>
  <li>Using Swagger 2.x format (<code>swagger: "2.0"</code>) instead of OpenAPI 3.x — migrate by replacing <code>swagger</code> with <code>openapi: "3.0.3"</code> and updating <code>definitions</code> to <code>components/schemas</code>.</li>
  <li>Missing <code>responses</code> object inside an operation — every operation must declare at least one response.</li>
  <li>Path keys that do not begin with <code>/</code> — all paths must be absolute, e.g. <code>/users/&#123;id&#125;</code>.</li>
  <li>YAML indentation errors — use the <a href="/tools/yaml-validator/">YAML Validator</a> to fix syntax issues first.</li>
</ul>

<h2>What the Validator Checks</h2>

<ul>
  <li><code>{"openapi"}</code> is present and looks like <code>{"3.x.y"}</code>; a <code>{"swagger: \"2.0\""}</code> document gets a migration hint instead.</li>
  <li><code>{"info"}</code> exists with <code>{"title"}</code> and <code>{"version"}</code>.</li>
  <li><code>{"paths"}</code> exists, every path key starts with <code>{"/"}</code>, and every operation (get, put, post, delete, options, head, patch, trace) has a non-empty <code>{"responses"}</code> object.</li>
</ul>

<p>Example input with three mistakes:</p>

<pre><code>{`openapi: 3.0.3
info:
  title: Orders API
paths:
  orders/{id}:
    get:
      summary: Get one order
  /orders:
    post:
      responses:
        "201":
          description: Created`}</code></pre>

<p>Errors reported:</p>

<pre><code>{`info.version            Missing required field "info.version".
paths.orders/{id}       Path key "orders/{id}" must start with "/".
paths.orders/{id}.get.responses
                        Operation "GET orders/{id}" must have a non-empty "responses" object.`}</code></pre>

<h2>What It Does Not Check</h2>

<p>The checks above are structural only. Run a full validator such as <a href="https://redocly.com/docs/cli/commands/lint" target="_blank" rel="noopener">Redocly CLI</a> (<code>{"redocly lint openapi.yaml"}</code>) or <a href="https://github.com/stoplightio/spectral" target="_blank" rel="noopener">Spectral</a> before publishing. Two results to be aware of:</p>

<ul>
  <li><strong><code>{"$ref"}</code> targets are not resolved.</strong> This document reports "valid" although <code>{"#/components/schemas/User"}</code> does not exist, and the path parameter <code>{"id"}</code> is not declared:</li>
</ul>

<pre><code>{`openapi: 3.0.3
info:
  title: Broken refs
  version: 1.0.0
paths:
  /users/{id}:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"`}</code></pre>

<ul>
  <li><strong>OpenAPI 3.1 rules are applied as if the file were 3.0.</strong> In 3.1 a document needs at least one of <code>{"paths"}</code>, <code>{"components"}</code> or <code>{"webhooks"}</code> (<a href="https://spec.openapis.org/oas/v3.1.0#openapi-object" target="_blank" rel="noopener">OpenAPI 3.1.0 §4.8.1</a>), and an operation does not have to declare <code>{"responses"}</code>. This webhooks-only 3.1 document is valid, but the tool reports <code>{"Missing required object \"paths\"."}</code>:</li>
</ul>

<pre><code>{`openapi: 3.1.0
info:
  title: Order events
  version: 1.0.0
webhooks:
  orderCreated:
    post:
      responses:
        "200":
          description: OK`}</code></pre>

<p>Schemas, parameter definitions, security schemes and examples are not validated either. YAML syntax errors are reported by the YAML parser before these checks run.</p>
