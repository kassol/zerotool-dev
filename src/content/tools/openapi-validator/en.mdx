<h2>OpenAPI Validator Online</h2>
<p>Paste an OpenAPI 3.0, 3.1 or 3.2 document in YAML or JSON and check it before you hand it to API gateways, SDK generators or documentation tools. The tool picks the official JSON Schema that matches the <code>openapi</code> field, validates the document with Ajv, and then runs the checks the schema cannot do on its own.</p>

<h2>How to Use</h2>
<ol>
  <li>Paste your OpenAPI spec (YAML or JSON) into the editor.</li>
  <li>Click <strong>Validate</strong> or press <kbd>Ctrl</kbd>+<kbd>Enter</kbd>.</li>
  <li>If valid, a summary panel shows the API title, version, OpenAPI version, path count and operation count.</li>
  <li>If invalid, each error is listed with its location as a JSON Pointer (the same syntax as <code>$ref</code>) and a description.</li>
  <li>References the tool did not follow are listed under <strong>Not checked</strong>.</li>
</ol>

<h2>What the Validator Checks</h2>
<ul>
  <li><strong>Structure</strong>, against the official schemas published at <a href="https://spec.openapis.org/" target="_blank" rel="noopener">spec.openapis.org</a>: 3.0 (schema 2024-10-18), 3.1 (2026-08-03) and 3.2 (2026-08-30). Required and unknown fields, value types, the shape of parameters, responses, security schemes and so on. Field names starting with <code>x-</code> are allowed everywhere the specification allows extensions.</li>
  <li><strong>Internal <code>$ref</code></strong>: <code>#/components/schemas/User</code> must exist in the document. <code>~1</code>, <code>~0</code> and percent-encoding in the pointer are decoded. <code>$ref</code> inside <code>example</code>, <code>default</code> or an Example Object's <code>value</code> is data and is skipped.</li>
  <li><strong>Path parameters</strong>: each <code>&#123;name&#125;</code> in a path needs a parameter with <code>in: path</code> on the Path Item or the operation, and each <code>in: path</code> parameter must appear in the path (Path Templating in the specification).</li>
  <li><strong>operationId</strong> must be unique across <code>paths</code> and <code>webhooks</code>.</li>
</ul>

<p>Example input with three mistakes:</p>

{/* ov: {"errors": ["#/info Missing required field \"version\".", "#/paths Path \"orders/{id}\" must start with \"/\".", "#/paths/orders~1{id}/get GET orders/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Orders API
paths:
  orders/{id}:
    get:
      summary: Get one order
  /orders:
    post:
      responses:
        "201":
          description: Created`}</code></pre>

<p>Errors reported:</p>

<pre><code>{`#/info
    Missing required field "version".
#/paths
    Path "orders/{id}" must start with "/".
#/paths/orders~1{id}/get
    GET orders/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p>The <code>get</code> operation has no <code>responses</code> either, but the path key itself is invalid, so the schema does not look inside it. Fix the reported errors and validate again.</p>

<p>A reference to a schema that does not exist and an undeclared path parameter:</p>

{/* ov: {"errors": ["#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref Reference \"#/components/schemas/User\" does not point to anything in this document.", "#/paths/~1users~1{id}/get GET /users/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Broken refs
  version: 1.0.0
paths:
  /users/{id}:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"`}</code></pre>

<pre><code>{`#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref
    Reference "#/components/schemas/User" does not point to anything in this document.
#/paths/~1users~1{id}/get
    GET /users/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p>A 3.1 document with only <code>webhooks</code> is valid: OpenAPI 3.1 requires at least one of <code>paths</code>, <code>components</code> or <code>webhooks</code> (<a href="https://spec.openapis.org/oas/v3.1.0#openapi-object" target="_blank" rel="noopener">OpenAPI 3.1.0 §4.8.1</a>), and <code>responses</code> is optional:</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.1.0
info:
  title: Order events
  version: 1.0.0
webhooks:
  orderCreated:
    post:
      requestBody:
        content:
          application/json:
            schema:
              type: object`}</code></pre>

<h2>What It Does Not Check</h2>

<p>An external reference is listed, not fetched. This document is reported as valid with one entry under Not checked:</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Pets
  version: 1.0.0
paths:
  /pets:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "./schemas/pet.yaml"`}</code></pre>

<ul>
  <li>The official schemas do not validate the contents of Schema Objects in detail (the 3.1 and 3.2 schemas only require an object or boolean), so a misspelled keyword inside a schema is not reported.</li>
  <li>Rules written only in prose are not checked, except the three listed above. Examples are not validated against their schemas, and security requirements are not matched against security schemes.</li>
  <li>For style rules (naming, descriptions, tags) run a linter such as <a href="https://redocly.com/docs/cli/commands/lint" target="_blank" rel="noopener">Redocly CLI</a> or <a href="https://github.com/stoplightio/spectral" target="_blank" rel="noopener">Spectral</a>.</li>
  <li>YAML syntax errors are reported by the YAML parser before these checks run; the <a href="/tools/yaml-validator/">YAML Validator</a> shows the line.</li>
</ul>

<p>All eleven example documents in the OpenAPI Initiative's <a href="https://github.com/OAI/learn.openapis.org/tree/main/examples" target="_blank" rel="noopener">learn.openapis.org examples</a> (petstore, uspto, tictactoe, the 3.2 query example and others) validate with no errors.</p>
