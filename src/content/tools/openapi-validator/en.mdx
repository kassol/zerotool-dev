<p>Paste an OpenAPI or Swagger document, open the files, or drop a folder. The validator checks it against the official JSON Schema for its version, follows <code>$ref</code> between files, and adds the rules that the schemas cannot express. Every problem shows the line and column; click it to select that line in the editor.</p>

<h2>How to use</h2>
<ol>
  <li>Paste YAML or JSON into the editor, click <strong>Open files</strong> or <strong>Open folder</strong>, or drop files on the tool. With several files, the one that has an <code>openapi</code> or <code>swagger</code> field becomes the main document.</li>
  <li>The check runs while you type (inputs under 2 MB) or when you click <strong>Validate</strong> or press <kbd>Ctrl</kbd>+<kbd>Enter</kbd>.</li>
  <li>Read the list: <strong>Error</strong>, <strong>Warning</strong> and <strong>Note</strong>, each with line:column, a message and the JSON Pointer of the field. Filter by level, or copy the list as tab-separated text.</li>
  <li>If a <code>$ref</code> needs a file you have not added, click the <strong>Add</strong> button that appears and paste its content.</li>
</ol>

<h2>Example: a 3.1 description with four problems</h2>
<p>This is the built-in example. The <code>version</code> field is an unquoted date, which YAML 1.2 reads as a string, so it is not reported.</p>

{/* ov */}
<pre><code>{`openapi: 3.1.0
info:
  title: Orders API
  version: 2026-10-02
security:
  - bearerAuth: []
paths:
  /orders/{orderId}:
    get:
      operationId: getOrder
      responses:
        "200":
          description: One order
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Order"
              example:
                id: 42
                total: "19.90"
components:
  schemas:
    Order:
      type: object
      required: [id, total]
      properties:
        id: {type: integer}
        total: {type: number}
  securitySchemes:
    bearer:
      type: http
      scheme: bearer`}</code></pre>

{/* ov-out */}
<pre><code>{`6:5  Error  Security scheme "bearerAuth" is not declared in components.securitySchemes.
9:5  Error  GET /orders/{orderId}: path parameter "orderId" is not declared. Add a parameter with in: path and name: orderId.
20:17  Warning  Example does not match the schema at /total: Must be number.
30:5  Warning  Security scheme "bearer" is not referenced anywhere.`}</code></pre>

<p>The official 3.1 schema accepts this document: a security requirement is a map of names, and the schema does not compare those names with <code>components.securitySchemes</code>. The two errors come from the extra rules below.</p>

<h2>What is checked</h2>
<table>
  <thead><tr><th>Check</th><th>Level</th><th>Source</th></tr></thead>
  <tbody>
    <tr><td>Structure: required and unknown fields, types, parameter and response shapes</td><td>Error</td><td>Official JSON Schema for the version</td></tr>
    <tr><td>Schema Objects in 3.1 / 3.2 (for example <code>required: true</code> on a property, <code>type: int</code>)</td><td>Error</td><td>JSON Schema 2020-12 meta-schema, which 3.1 adopts</td></tr>
    <tr><td>Every <code>$ref</code> points to something, in this file or another one</td><td>Error</td><td>Reference Object</td></tr>
    <tr><td>Each <code>{'{name}'}</code> in a path has an <code>in: path</code> parameter, and the other way round</td><td>Error</td><td><a href="https://spec.openapis.org/oas/v3.1.1.html#parameter-object" target="_blank" rel="noopener">Parameter Object</a></td></tr>
    <tr><td>Paths that differ only in parameter names</td><td>Error</td><td><a href="https://spec.openapis.org/oas/v3.1.1.html#paths-object" target="_blank" rel="noopener">Paths Object</a></td></tr>

<h2>Example: two paths that are the same template</h2>
<p>GitHub publishes its REST API description as <a href="https://github.com/github/rest-api-description" target="_blank" rel="noopener">api.github.com.yaml</a> (9.9 MB, main branch on 2026-10-02). The validator finds 2 errors in it: two pairs of attestation paths that differ only by the parameter name. Redocly CLI 2.57.0 and Spectral 6.17.0 report the same two pairs. This excerpt reproduces one:</p>

{/* ov */}
<pre><code>{`openapi: 3.0.3
info:
  title: Attestations (excerpt)
  version: 1.1.4
paths:
  /orgs/{org}/attestations/{attestation_id}:
    delete:
      parameters:
        - {name: org, in: path, required: true, schema: {type: string}}
        - {name: attestation_id, in: path, required: true, schema: {type: integer}}
      responses:
        "204": {description: Deleted}
  /orgs/{org}/attestations/{subject_digest}:
    get:
      parameters:
        - {name: org, in: path, required: true, schema: {type: string}}
        - {name: subject_digest, in: path, required: true, schema: {type: string}}
      responses:
        "200": {description: OK}`}</code></pre>

{/* ov-out */}
<pre><code>{`13:3  Error  Path "/orgs/{org}/attestations/{subject_digest}" is the same template as "/orgs/{org}/attestations/{attestation_id}" (only the parameter names differ). The specification does not allow both.`}</code></pre>

<p>A router cannot tell <code>/orgs/acme/attestations/42</code> apart for these two paths. On the full file the tool also lists 187 examples that do not match their schema and 7 unused schemas. It took 2.7 seconds in Node.js 24 on an Apple M1 Max; the page runs the same code in a Web Worker, so the page stays usable.</p>

<h2>Swagger 2.0 and YAML details</h2>
<p>Swagger 2.0 documents are checked against the Swagger 2.0 schema with the same reference, path parameter, security and example rules. A note suggests converting with <a href="https://github.com/Mermade/oas-kit" target="_blank" rel="noopener">swagger2openapi</a> if you want OpenAPI 3.</p>

{/* ov */}
<pre><code>{`swagger: "2.0"
info:
  title: Pets
  version: "1.0"
paths:
  /pets/{petId}:
    get:
      parameters:
        - {name: id, in: path, required: true, type: integer}
      responses:
        "200":
          description: OK
          schema:
            $ref: "#/definitions/Pett"
definitions:
  Pet:
    type: object`}</code></pre>

{/* ov-out */}
<pre><code>{`1:1  Note  Swagger 2.0 document, checked against the Swagger 2.0 schema. To move to OpenAPI 3, convert it (for example: npx swagger2openapi swagger.yaml -o openapi.yaml) and validate the result.
7:5  Error  GET /pets/{petId}: path parameter "petId" is not declared. Add a parameter with in: path and name: petId.
7:5  Error  GET /pets/{petId}: parameter "id" has in: path, but the path has no {id}.
14:13  Error  Reference "#/definitions/Pett" does not point to anything in this document.
16:3  Warning  Definition "Pet" is not referenced anywhere.`}</code></pre>

<p>YAML is read with the <a href="https://yaml.org/spec/1.2.2/#1023-core-schema" target="_blank" rel="noopener">YAML 1.2 core schema</a>, plus merge keys (<code>{'<<: *anchor'}</code>). A key that appears twice in one mapping is a syntax error with its line, in JSON input too. Integers larger than 2<sup>53</sup>, such as <code>maximum: 9223372036854775807</code>, get a note because JavaScript reads them as approximate values.</p>

<h2>How it compares</h2>
<p>We ran the same test file through other validators on 2026-10-02. It had four errors (an undeclared path parameter, an undeclared security scheme, two equivalent paths, <code>required: true</code> on a property) and an unquoted date in <code>info.version</code>.</p>
<ul>
  <li><strong>Redocly CLI 2.57.0</strong> and <strong>Spectral 6.17.0</strong> (<code>spectral:oas</code>) found all four. They also apply style rules (summaries, 4XX responses, license, servers), and both flag example strings for XML media types; this tool treats a string example of a non-JSON media type as the serialized form and does not compare it with the schema. On the 9.9 MB GitHub description Spectral took 32 s and Redocly 5 s.</li>
  <li><strong>swagger-parser 13.1.0</strong> reported the document as valid.</li>
  <li><strong>Swagger Editor 5.8.9</strong> (editor.swagger.io) checks in the browser and found the path parameter and the <code>required</code> problem, not the equivalent paths or the undeclared scheme.</li>
  <li><strong>ApiNotes</strong> (apinotes.io, first Bing result for "openapi validator") sent the document to <code>api.apinotes.io</code> and reported <code>info.version</code> "must be string", a false error caused by reading the date as a timestamp.</li>
  <li><strong>APIMatic</strong> validates through its VS Code extension, which needs an APIMatic account and an internet connection (its documentation), so we did not test it.</li>
</ul>

<h2>Limits</h2>
<ul>
  <li>No style rules. For naming, descriptions or a team ruleset, run Redocly CLI or Spectral after this check.</li>
  <li>URLs in <code>$ref</code> are not fetched; add the files instead. Anchor references (<code>#name</code>) are not checked.</li>
  <li>Example checks stop after 4 seconds on very large descriptions, with a note. Each example reports its first mismatch and a count of the rest.</li>
  <li>Inputs over 2 MB are checked when you click Validate; files over 50 MB in total are not loaded.</li>
</ul>
