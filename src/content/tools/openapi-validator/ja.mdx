<h2>使い方</h2>
<ol>
  <li>OpenAPIスペック（YAMLまたはJSON）をエディターに貼り付けます。</li>
  <li><strong>検証</strong>をクリックするか <kbd>Ctrl</kbd>+<kbd>Enter</kbd> を押します。</li>
  <li>有効な場合、APIタイトル・バージョン・パス数・オペレーション数がサマリーパネルに表示されます。</li>
  <li>無効な場合、各エラーがJSONパスと説明付きでリスト表示されます。</li>
</ol>

<h2>OpenAPI 3.x 必須フィールド</h2>
<ul>
  <li><code>openapi</code> — バージョン文字列（例: <code>"3.0.3"</code>・<code>"3.1.0"</code>）</li>
  <li><code>info.title</code> — API名</li>
  <li><code>info.version</code> — APIバージョン（例: <code>"1.0.0"</code>）</li>
  <li><code>paths</code> — パスアイテムマップ（各キーは <code>/</code> で始まる必要あり）</li>
</ul>

<h2>よくあるミス</h2>
<ul>
  <li>OpenAPI 3.xの代わりにSwagger 2.x形式（<code>swagger: "2.0"</code>）を使用 — <code>swagger</code>を<code>openapi: "3.0.3"</code>に置き換え、<code>definitions</code>を<code>components/schemas</code>に更新します。</li>
  <li>オペレーション内に<code>responses</code>オブジェクトがない — すべてのオペレーションは少なくとも1つのレスポンスを宣言する必要があります。</li>
  <li><code>/</code>で始まらないパスキー — すべてのパスは絶対パスである必要があります（例: <code>/users/&#123;id&#125;</code>）。</li>
  <li>YAMLインデントエラー — まず<a href="/ja/tools/yaml-validator/">YAML バリデーター</a>で構文の問題を修正してください。</li>
</ul>

<h2>バリデーターが確認すること</h2>

<ul>
  <li><code>{"openapi"}</code> があり、<code>{"3.x.y"}</code> の形であること。<code>{"swagger: \"2.0\""}</code> の文書には移行のヒントを出します。</li>
  <li><code>{"info"}</code> があり、<code>{"title"}</code> と <code>{"version"}</code> を持つこと。</li>
  <li><code>{"paths"}</code> があり、各パスのキーが <code>{"/"}</code> で始まり、各オペレーション（get、put、post、delete、options、head、patch、trace）に空でない <code>{"responses"}</code> があること。</li>
</ul>

<p>3 か所に誤りがある入力：</p>

<pre><code>{`openapi: 3.0.3
info:
  title: Orders API
paths:
  orders/{id}:
    get:
      summary: Get one order
  /orders:
    post:
      responses:
        "201":
          description: Created`}</code></pre>

<p>報告されるエラー：</p>

<pre><code>{`info.version            Missing required field "info.version".
paths.orders/{id}       Path key "orders/{id}" must start with "/".
paths.orders/{id}.get.responses
                        Operation "GET orders/{id}" must have a non-empty "responses" object.`}</code></pre>

<h2>確認しないこと</h2>

<p>上の確認は構造だけです。公開前には <a href="https://redocly.com/docs/cli/commands/lint" target="_blank" rel="noopener">Redocly CLI</a>（<code>{"redocly lint openapi.yaml"}</code>）や <a href="https://github.com/stoplightio/spectral" target="_blank" rel="noopener">Spectral</a> のような完全なバリデーターも通してください。特に注意すべき結果が 2 つあります：</p>

<ul>
  <li><strong><code>{"$ref"}</code> の参照先を解決しません。</strong>次の文書は <code>{"#/components/schemas/User"}</code> が存在せず、パスパラメーター <code>{"id"}</code> も宣言されていないのに「有効」と表示されます：</li>
</ul>

<pre><code>{`openapi: 3.0.3
info:
  title: Broken refs
  version: 1.0.0
paths:
  /users/{id}:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"`}</code></pre>

<ul>
  <li><strong>OpenAPI 3.1 の文書にも 3.0 のルールを当てはめます。</strong>3.1 では <code>{"paths"}</code>・<code>{"components"}</code>・<code>{"webhooks"}</code> のどれか 1 つがあればよく（<a href="https://spec.openapis.org/oas/v3.1.0#openapi-object" target="_blank" rel="noopener">OpenAPI 3.1.0 §4.8.1</a>）、オペレーションに <code>{"responses"}</code> がなくてもかまいません。次の webhooks だけの 3.1 文書は有効ですが、ツールは <code>{"Missing required object \"paths\"."}</code> と報告します：</li>
</ul>

<pre><code>{`openapi: 3.1.0
info:
  title: Order events
  version: 1.0.0
webhooks:
  orderCreated:
    post:
      responses:
        "200":
          description: OK`}</code></pre>

<p>スキーマ、パラメーター定義、セキュリティスキーム、例も検証しません。YAML の構文エラーは、これらの確認の前に YAML パーサーが報告します。</p>
