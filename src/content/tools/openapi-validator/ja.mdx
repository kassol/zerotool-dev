<h2>OpenAPI バリデーター</h2>
<p>YAML または JSON の OpenAPI 3.0・3.1・3.2 文書を貼り付け、API ゲートウェイや SDK ジェネレーター、ドキュメントツールに渡す前に確認できます。<code>openapi</code> フィールドに合う公式 JSON Schema を選んで Ajv で検証し、Schema だけでは確認できない点を追加で調べます。</p>

<h2>使い方</h2>
<ol>
  <li>OpenAPI 仕様（YAML または JSON）をエディターに貼り付けます。</li>
  <li><strong>検証</strong>をクリックするか <kbd>Ctrl</kbd>+<kbd>Enter</kbd> を押します。</li>
  <li>有効なら、API タイトル、バージョン、OpenAPI バージョン、パス数、オペレーション数を表示します。</li>
  <li>無効なら、エラーごとに位置を JSON Pointer（<code>$ref</code> と同じ書き方）で示します。</li>
  <li>たどらなかった参照は<strong>未確認</strong>に一覧表示します。</li>
</ol>

<h2>バリデーターが確認すること</h2>
<ul>
  <li><strong>構造</strong>：<a href="https://spec.openapis.org/" target="_blank" rel="noopener">spec.openapis.org</a> が公開する公式 Schema で検証します。3.0（Schema 2024-10-18）、3.1（2026-08-03）、3.2（2026-08-30）。必須フィールドと未知のフィールド、値の型、パラメーター・レスポンス・セキュリティスキームなどの形を確認します。<code>x-</code> で始まるフィールドは、仕様が拡張を認める場所ならどこでも使えます。</li>
  <li><strong>文書内の <code>$ref</code></strong>：<code>#/components/schemas/User</code> が文書内に存在する必要があります。ポインターの <code>~1</code>・<code>~0</code>・パーセントエンコードは先にデコードします。<code>example</code>、<code>default</code>、Example オブジェクトの <code>value</code> 内の <code>$ref</code> はデータなので確認しません。</li>
  <li><strong>パスパラメーター</strong>：パス中の <code>&#123;name&#125;</code> ごとに、Path Item かオペレーションに <code>in: path</code> のパラメーターが必要です。逆に <code>in: path</code> のパラメーターはパスに現れる必要があります（仕様の Path Templating）。</li>
  <li><strong>operationId</strong> は <code>paths</code> と <code>webhooks</code> 全体で一意である必要があります。</li>
</ul>

<p>3 か所に誤りがある入力：</p>

{/* ov: {"errors": ["#/info Missing required field \"version\".", "#/paths Path \"orders/{id}\" must start with \"/\".", "#/paths/orders~1{id}/get GET orders/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Orders API
paths:
  orders/{id}:
    get:
      summary: Get one order
  /orders:
    post:
      responses:
        "201":
          description: Created`}</code></pre>

<p>報告されるエラー：</p>

<pre><code>{`#/info
    Missing required field "version".
#/paths
    Path "orders/{id}" must start with "/".
#/paths/orders~1{id}/get
    GET orders/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p><code>get</code> オペレーションにも <code>responses</code> がありませんが、パスのキー自体が無効なので Schema はその中を確認しません。報告されたエラーを直してから再度検証してください。</p>

<p>存在しない Schema への参照と、宣言されていないパスパラメーター：</p>

{/* ov: {"errors": ["#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref Reference \"#/components/schemas/User\" does not point to anything in this document.", "#/paths/~1users~1{id}/get GET /users/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Broken refs
  version: 1.0.0
paths:
  /users/{id}:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"`}</code></pre>

<pre><code>{`#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref
    Reference "#/components/schemas/User" does not point to anything in this document.
#/paths/~1users~1{id}/get
    GET /users/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p><code>webhooks</code> だけの 3.1 文書は有効です。OpenAPI 3.1 は <code>paths</code>・<code>components</code>・<code>webhooks</code> のいずれかを必須とし（<a href="https://spec.openapis.org/oas/v3.1.0#openapi-object" target="_blank" rel="noopener">OpenAPI 3.1.0 §4.8.1</a>）、<code>responses</code> も省略できます。</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.1.0
info:
  title: Order events
  version: 1.0.0
webhooks:
  orderCreated:
    post:
      requestBody:
        content:
          application/json:
            schema:
              type: object`}</code></pre>

<h2>確認しないこと</h2>

<p>外部参照は一覧に載せるだけで取得しません。次の文書は有効と判定され、「未確認」に 1 件表示されます。</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Pets
  version: 1.0.0
paths:
  /pets:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "./schemas/pet.yaml"`}</code></pre>

<ul>
  <li>公式 Schema は Schema オブジェクトの中身を細かく検証しません（3.1・3.2 はオブジェクトか真偽値であることだけを求めます）。Schema 内のキーワードの綴り間違いは報告されません。</li>
  <li>上の 3 つ以外の、本文にだけ書かれた規則は確認しません。例の値を Schema で検証することも、セキュリティ要件をセキュリティスキームと照合することもしません。</li>
  <li>命名・説明・タグなどのスタイルは <a href="https://redocly.com/docs/cli/commands/lint" target="_blank" rel="noopener">Redocly CLI</a> や <a href="https://github.com/stoplightio/spectral" target="_blank" rel="noopener">Spectral</a> などのリンターで確認してください。</li>
  <li>YAML の構文エラーは先に YAML パーサーが報告します。行番号は <a href="/ja/tools/yaml-validator/">YAML バリデーター</a>で確認できます。</li>
</ul>

<p>OpenAPI Initiative の <a href="https://github.com/OAI/learn.openapis.org/tree/main/examples" target="_blank" rel="noopener">learn.openapis.org のサンプル</a> 11 件（petstore、uspto、tictactoe、3.2 の query サンプルなど）はすべてエラーなしで検証されます。</p>
