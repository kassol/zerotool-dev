<h2>在线 OpenAPI 验证器</h2>
<p>粘贴 YAML 或 JSON 格式的 OpenAPI 3.0、3.1 或 3.2 文档，在交给 API 网关、SDK 生成器或文档工具之前先检查一遍。工具按 <code>openapi</code> 字段选择对应的官方 JSON Schema，用 Ajv 校验，再补上 Schema 本身做不到的检查。</p>

<h2>使用方法</h2>
<ol>
  <li>把 OpenAPI 规范（YAML 或 JSON）粘贴到编辑框。</li>
  <li>点击<strong>验证</strong>或按 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>。</li>
  <li>有效时，摘要面板显示 API 名称、版本、OpenAPI 版本、路径数和接口数。</li>
  <li>无效时，逐条列出错误，位置写成 JSON Pointer（与 <code>$ref</code> 的写法相同）。</li>
  <li>工具没有跟进的引用列在<strong>未检查</strong>下。</li>
</ol>

<h2>校验器检查什么</h2>
<ul>
  <li><strong>结构</strong>：按 <a href="https://spec.openapis.org/" target="_blank" rel="noopener">spec.openapis.org</a> 发布的官方 Schema 校验，3.0（Schema 2024-10-18）、3.1（2026-08-03）、3.2（2026-08-30）。包括必填与未知字段、值类型、参数、响应、安全方案等的形式。以 <code>x-</code> 开头的字段在规范允许扩展的位置都可以使用。</li>
  <li><strong>文档内的 <code>$ref</code></strong>：<code>#/components/schemas/User</code> 必须在文档中存在。指针中的 <code>~1</code>、<code>~0</code> 与百分号编码会先解码。<code>example</code>、<code>default</code> 和 Example 对象的 <code>value</code> 里的 <code>$ref</code> 属于数据，不检查。</li>
  <li><strong>路径参数</strong>：路径里的每个 <code>&#123;name&#125;</code> 都要在 Path Item 或接口上有 <code>in: path</code> 参数，每个 <code>in: path</code> 参数也必须出现在路径中（规范的 Path Templating 一节）。</li>
  <li><strong>operationId</strong> 在 <code>paths</code> 与 <code>webhooks</code> 中不能重复。</li>
</ul>

<p>有三处错误的输入：</p>

{/* ov: {"errors": ["#/info Missing required field \"version\".", "#/paths Path \"orders/{id}\" must start with \"/\".", "#/paths/orders~1{id}/get GET orders/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Orders API
paths:
  orders/{id}:
    get:
      summary: Get one order
  /orders:
    post:
      responses:
        "201":
          description: Created`}</code></pre>

<p>报告的错误：</p>

<pre><code>{`#/info
    Missing required field "version".
#/paths
    Path "orders/{id}" must start with "/".
#/paths/orders~1{id}/get
    GET orders/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p><code>get</code> 接口也缺少 <code>responses</code>，但它所在的路径键本身无效，Schema 不会再往里检查。改正报告的错误后再验证一次即可看到。</p>

<p>引用了不存在的 Schema，且路径参数未声明：</p>

{/* ov: {"errors": ["#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref Reference \"#/components/schemas/User\" does not point to anything in this document.", "#/paths/~1users~1{id}/get GET /users/{id}: path parameter \"id\" is not declared (add a parameter with in: path, name: id)."]} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Broken refs
  version: 1.0.0
paths:
  /users/{id}:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"`}</code></pre>

<pre><code>{`#/paths/~1users~1{id}/get/responses/200/content/application~1json/schema/$ref
    Reference "#/components/schemas/User" does not point to anything in this document.
#/paths/~1users~1{id}/get
    GET /users/{id}: path parameter "id" is not declared (add a parameter with in: path, name: id).`}</code></pre>

<p>只有 <code>webhooks</code> 的 3.1 文档是有效的：OpenAPI 3.1 要求 <code>paths</code>、<code>components</code>、<code>webhooks</code> 至少有一个（<a href="https://spec.openapis.org/oas/v3.1.0#openapi-object" target="_blank" rel="noopener">OpenAPI 3.1.0 §4.8.1</a>），<code>responses</code> 也可以省略：</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.1.0
info:
  title: Order events
  version: 1.0.0
webhooks:
  orderCreated:
    post:
      requestBody:
        content:
          application/json:
            schema:
              type: object`}</code></pre>

<h2>它不检查什么</h2>

<p>外部引用只列出，不获取。下面的文档判为有效，「未检查」下列出一条：</p>

{/* ov: {"errors": []} */}

<pre><code>{`openapi: 3.0.3
info:
  title: Pets
  version: 1.0.0
paths:
  /pets:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "./schemas/pet.yaml"`}</code></pre>

<ul>
  <li>官方 Schema 不细查 Schema 对象的内容（3.1、3.2 的 Schema 只要求是对象或布尔值），Schema 里拼错的关键字不会报出。</li>
  <li>除上面三条外，只写在正文里的规则不检查。示例值不按其 Schema 校验，安全需求也不与安全方案对照。</li>
  <li>命名、描述、标签等风格规则请用 <a href="https://redocly.com/docs/cli/commands/lint" target="_blank" rel="noopener">Redocly CLI</a> 或 <a href="https://github.com/stoplightio/spectral" target="_blank" rel="noopener">Spectral</a> 之类的 linter。</li>
  <li>YAML 语法错误由 YAML 解析器先报出；<a href="/zh/tools/yaml-validator/">YAML 验证器</a>会给出行号。</li>
</ul>

<p>OpenAPI Initiative 的 <a href="https://github.com/OAI/learn.openapis.org/tree/main/examples" target="_blank" rel="noopener">learn.openapis.org 示例</a>中的全部 11 份文档（petstore、uspto、tictactoe、3.2 query 示例等）验证结果均为无错误。</p>
