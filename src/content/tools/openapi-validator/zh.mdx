<p>把 Swagger 或 OpenAPI 文档粘贴进来，或打开文件、拖入整个文件夹。工具按版本选用官方 JSON Schema 校验结构，跨文件解析 <code>$ref</code>，再补上 schema 表达不了的规则。每条问题都带行号和列号，点一下就在编辑框里选中那一行。</p>

<h2>使用步骤</h2>
<ol>
  <li>粘贴 YAML 或 JSON，或点「打开文件」「打开文件夹」，也可以直接把文件拖到工具上。多个文件时，含 <code>openapi</code> 或 <code>swagger</code> 字段的文件作为主文档。</li>
  <li>2 MB 以内的内容边输入边校验；更大的内容点「校验」或按 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>。</li>
  <li>结果分为错误、警告、提示三级，可以按级别筛选，也可以把整份结果复制成制表符分隔的文本，贴进工单或代码评审。</li>
  <li>如果某个 <code>$ref</code> 需要的文件还没添加，结果下方会出现「添加 …」按钮，点击后粘贴内容即可。</li>
</ol>

<h2>示例一：swag 生成的 Swagger 2.0</h2>
<p>Gin 项目常用 <a href="https://github.com/swaggo/swag" target="_blank" rel="noopener">swaggo/swag</a> 从注释生成文档，它的 README 写明输出是 Swagger 2.0。下面是按 swag 输出格式写的一份 <code>docs/swagger.yaml</code>：路由写的是 <code>{'{accountId}'}</code>，注释里的 <code>@Param</code> 却叫 <code>id</code>；处理函数加了 <code>@Security ApiKeyAuth</code>，<code>main.go</code> 里漏写了对应的 <code>@securityDefinitions.apikey</code>。</p>

{/* ov */}
<pre><code>{`basePath: /api/v1
definitions:
  model.Account:
    properties:
      id:
        example: 1
        type: integer
      name:
        example: 张三
        type: string
    type: object
info:
  contact: {}
  title: 账户服务 API
  version: "1.0"
paths:
  /accounts/{accountId}:
    get:
      parameters:
      - description: 账户 ID
        in: path
        name: id
        required: true
        type: integer
      responses:
        "200":
          description: OK
          schema:
            $ref: '#/definitions/model.Account'
      security:
      - ApiKeyAuth: []
      summary: 查询账户
swagger: "2.0"`}</code></pre>

{/* ov-out */}
<pre><code>{`18:5  错误  GET /accounts/{accountId}：路径参数 "accountId" 没有声明。请添加 in: path、name: accountId 的参数。
18:5  错误  GET /accounts/{accountId}：参数 "id" 写了 in: path，但路径里没有 {id}。
31:9  错误  安全方案 "ApiKeyAuth" 没有在 securityDefinitions 中声明。
33:1  提示  Swagger 2.0 文档，已按 Swagger 2.0 的 schema 校验。如需迁移到 OpenAPI 3，可先转换（例如 npx swagger2openapi swagger.yaml -o openapi.yaml），再校验转换结果。`}</code></pre>

<p>这三处错误单靠 Swagger 2.0 的官方 schema 都查不出来：schema 只管字段的形状，不会把参数名和路径模板对照，也不会去 <code>securityDefinitions</code> 里找名字。</p>

<h2>示例二：springdoc 输出的 3.0 文档里混进了 3.1 写法</h2>
<p>Spring Boot 项目用 <a href="https://springdoc.org/" target="_blank" rel="noopener">springdoc-openapi</a> 时，文档默认在 <code>/v3/api-docs</code>（YAML 在 <code>/v3/api-docs.yaml</code>）。导出后手工改过的文件常见两类问题：在 <code>openapi: 3.0.x</code> 里写 3.1 的类型列表，示例值的类型与 schema 不一致。</p>

{/* ov */}
<pre><code>{`openapi: 3.0.1
info:
  title: 订单服务
  version: v1
paths:
  /orders:
    get:
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Order"
components:
  schemas:
    Order:
      type: object
      properties:
        remark:
          type: [string, "null"]
        amount:
          type: number
          example: "¥19.90"`}</code></pre>

{/* ov-out */}
<pre><code>{`21:11  错误  OpenAPI 3.0 不允许把 type 写成列表。请写单个类型并加 nullable: true；[string, "null"] 这类写法要 OpenAPI 3.1。
24:11  警告  示例与 schema 不符：类型应为 number。`}</code></pre>

<h2>示例三：3.1 文档的服务器变量与重复路径</h2>
<p>下面的 <code>version</code> 没加引号，YAML 1.2 把它读成字符串，所以不报错。真正的问题是变量默认值不在 <code>enum</code> 里（3.1 规定 MUST），以及两条只差参数名的路径。</p>

{/* ov */}
<pre><code>{`openapi: 3.1.0
info:
  title: 门店 API
  version: 2026-10-02
servers:
  - url: https://{env}.api.example.cn/v1
    variables:
      env:
        default: prod
        enum: [test, pre]
paths:
  /stores/{storeId}:
    get:
      parameters:
        - {name: storeId, in: path, required: true, schema: {type: string}}
      responses:
        "200": {description: OK}
  /stores/{id}:
    delete:
      parameters:
        - {name: id, in: path, required: true, schema: {type: string}}
      responses:
        "204": {description: 已删除}`}</code></pre>

{/* ov-out */}
<pre><code>{`9:9  错误  变量 "env" 的默认值 "prod" 不在 enum 中。
18:3  错误  路径 "/stores/{id}" 与 "/stores/{storeId}" 是同一个模板（只有参数名不同），规范不允许两者并存。`}</code></pre>

<h2>与其他工具的差异</h2>
<p>2026-10-02 我们用同一份测试文档（含未声明的路径参数、未声明的安全方案、两条等价路径、属性上的 <code>required: true</code>，<code>info.version</code> 是不带引号的日期）对比了几款工具：</p>
<ul>
  <li>命令行的 Redocly CLI 2.57.0 与 Spectral 6.17.0 都找出了四处问题，另外还有大量风格规则；swagger-parser 13.1.0 判为有效。</li>
  <li>Elysia Tools 的 OpenAPI / Swagger 校验器把文档 POST 到 <code>api.elysiatools.com</code>，只报了一条「info.version 必须是非空字符串」，这是把日期读成时间戳造成的误报。</li>
  <li>AppKits 的 Swagger/OpenAPI 校验工具在本地运行，同样误报 <code>/info/version</code>；把日期加上引号后显示「验证通过，0 个错误」，四处问题都没有发现。</li>
</ul>

<h2>限制</h2>
<ul>
  <li>不做命名、描述等风格检查，团队规则请在本工具之后跑 Redocly CLI 或 Spectral。</li>
  <li>不下载 <code>$ref</code> 里的网址，请把文件添加进来；锚点引用（<code>#name</code>）不检查。</li>
  <li>非 JSON 媒体类型（如 <code>application/xml</code>）的字符串示例视为序列化后的原文，不与 schema 比对。</li>
  <li>超大文档的示例检查 4 秒后停止并给出提示；超过 2 MB 的内容需点「校验」，文件合计超过 50 MB 不载入。</li>
</ul>
