<h2>자주 사용하는 퍼미션</h2>
<ul>
  <li><code>644</code> (rw-r--r--): 일반 파일(소유자가 읽기·쓰기, 나머지는 읽기 전용)</li>
  <li><code>755</code> (rwxr-xr-x): 디렉토리·실행 파일(소유자가 전체 권한, 나머지는 읽기·실행만)</li>
  <li><code>600</code> (rw-------): 개인 키 등 기밀 파일(소유자만 읽기·쓰기)</li>
  <li><code>777</code> (rwxrwxrwx): 모든 사용자에게 전체 권한(보안 위험이 있으므로 일반적으로 피해야 함)</li>
</ul>

<h2>그누보드5 data 디렉토리: 707과 705</h2>
<p>
  그누보드5를 설치하려면 루트(<code>common.php</code>가 있는 디렉토리)에 <code>data</code> 디렉토리를 직접 만들어야 합니다(<code>mkdir data</code>). 디렉토리가 없으면 설치 화면이 만들라고 안내하고, 있으면 웹 프로그램이 그 안에 파일을 쓸 수 있는지 확인합니다.
  <a href="https://github.com/gnuboard/gnuboard5/blob/master/install/install.inc.php">설치 스크립트(install/install.inc.php)</a>를 보면
  PHP가 CGI 방식으로 실행될 때(<code>php_sapi_name()</code>이 <code>cgi</code>로 시작할 때)는 읽기와 실행만 확인해 705를, 그 밖의 경우에는 읽기·쓰기·실행을 모두 확인해
  "data 디렉토리의 퍼미션을 707로 변경하여 주십시오."라고 안내합니다. 두 값을 숫자 칸에 넣으면 다음과 같습니다.
</p>
{/* chmod-page: {"numeric":"707","show":["symbolic","sym"]} */}
<pre><code>{`707  rwx---rwx  chmod u=rwx,g=,o=rwx filename`}</code></pre>
{/* chmod-page: {"numeric":"705","show":["symbolic","sym"]} */}
<pre><code>{`705  rwx---r-x  chmod u=rwx,g=,o=rx filename`}</code></pre>
<p>
  707은 그룹에는 아무것도 주지 않고 '기타'에 쓰기까지 허용합니다. 안내문에는 <code>chmod 707 data</code> 외에 <code>chmod uo+rwx data</code>도 적혀 있는데,
  두 명령은 결과가 다를 수 있습니다. <code>+</code>는 현재 권한에 더하기만 하고 그룹의 권한은 건드리지 않기 때문입니다.
  권한이 755인 디렉토리에서 각각 실행해 본 결과는 다음과 같습니다.
</p>
{/* chmod-sys: {"start":"755","cmd":"uo+rwx","mode":"757"} */}
<pre><code>{`chmod 755 data
chmod uo+rwx data   # → 757 (rwxr-xrwx)`}</code></pre>
{/* chmod-sys: {"start":"755","cmd":"707","mode":"707"} */}
<pre><code>{`chmod 755 data
chmod 707 data      # → 707 (rwx---rwx)`}</code></pre>
<p>
  757은 707보다 권한이 넓으므로 설치 검사는 통과하지만, 707과 달리 그룹에 읽기·실행이 남습니다.
  CGI 방식일 때의 안내문 <code>chmod 705 data 또는 chmod uo+rx data</code>도 두 명령의 결과가 다를 수 있습니다. 755인 디렉토리에 <code>uo+rx</code>를 실행하면 이미 있는 권한이라 그대로 755이고, 700인 디렉토리라면 705가 됩니다.
</p>
{/* chmod-sys: {"start":"755","cmd":"uo+rx","mode":"755"} */}
<pre><code>{`chmod 755 data
chmod uo+rx data    # → 755 (변화 없음)`}</code></pre>
{/* chmod-sys: {"start":"700","cmd":"uo+rx","mode":"705"} */}
<pre><code>{`chmod 700 data
chmod uo+rx data    # → 705 (rwx---r-x)`}</code></pre>
<p>
  이 도구는 항상 <code>u=…,g=…,o=…</code> 형태의 절대 지정을 출력하므로,
  복사한 명령은 시작 권한과 상관없이 같은 결과가 됩니다.
</p>

<h2>ls -l 출력 붙여넣기</h2>
<p>
  <code>ls -l</code>에 보이는 권한을 그대로 기호 칸에 붙여넣어도 됩니다. 맨 앞의 파일 종류 문자와 끝의 <code>+</code> <code>@</code> <code>.</code> 표시는 제거됩니다.
  <a href="https://www.gnu.org/software/coreutils/manual/html_node/What-information-is-listed.html">GNU ls 매뉴얼</a>에 따르면 <code>.</code>은 보안 컨텍스트(SELinux)는 있고 ACL 같은 다른 접근 방식은 없는 파일,
  <code>+</code>는 ACL 같은 다른 접근 방식이 있는 파일을 뜻합니다. 이 경우 실제 접근 권한은 아홉 자리 표기와 다를 수 있습니다.
</p>
{/* chmod-page: {"symbolic":"drwxrwxrwt","show":["numeric","sym"]} */}
<pre><code>{`drwxrwxrwt  →  1777
chmod u=rwx,g=rwx,o=rwx,+t filename`}</code></pre>
<p>
  <code>/tmp</code>에서 흔히 보는 <code>drwxrwxrwt</code>는 누구나 파일을 만들 수 있지만 남의 파일은 지울 수 없는 스티키 비트 디렉토리입니다.
  기호 명령어는 스티키를 별도의 <code>+t</code>로 씁니다. macOS chmod는 <code>o+t</code>를 무시하지만 <code>+t</code>는 GNU와 macOS 모두에서 동작합니다.
</p>
{/* chmod-page: {"symbolic":"-rwsr-xr-x","show":["numeric","description"]} */}
<pre><code>{`-rwsr-xr-x  →  4755
소유자: 읽기, 쓰기, 실행, setuid; 그룹: 읽기, 실행; 기타: 읽기, 실행`}</code></pre>

<h2>제한 사항</h2>
<ul>
  <li>절대 지정(<code>u=…,g=…,o=…</code>)만 출력합니다. <code>chmod g+w</code>, <code>a-x</code> 같은 상대 지정이나 디렉토리에만 실행 권한을 주는 <code>X</code>는 만들지 않습니다.</li>
  <li>숫자 칸은 0–7로 된 3자리나 4자리를 받습니다. 앞뒤 공백과 Python식 <code>0o</code> 접두사(<code>0o644</code>)는 무시하고, 전각 숫자는 반각으로 읽습니다. 그 밖의 문자(<code>7558</code>의 8 등), 2자리 이하, 5자리 이상은 '잘못된 8진수' 오류를 표시하고 마지막 유효한 결과를 유지합니다.</li>
  <li>GNU chmod는 4자리 이하 숫자(<code>755</code>, <code>0755</code>)나 s를 언급하지 않는 기호 지정으로는 디렉토리의 SUID·SGID를 바꾸지 않습니다(<a href="https://www.gnu.org/software/coreutils/manual/html_node/Directory-Setuid-and-Setgid.html">coreutils 매뉴얼</a>). <code>2775</code> 디렉토리는 <code>chmod 755</code> 뒤에도 <code>2775</code>이며, 지우려면 <code>chmod 00755</code>나 <code>chmod g-s</code>를 씁니다.</li>
  <li><code>find . -type f -perm 0644</code>는 권한이 정확히 644인 파일만 찾습니다. 그 비트를 모두 가진 파일은 <code>-perm -644</code>, 하나라도 가진 파일은 <code>-perm /644</code>(GNU find)로 찾습니다.</li>
  <li>실제 접근 가능 여부는 ACL, SELinux, <code>noexec</code> 같은 마운트 옵션, 상위 디렉토리 권한에도 좌우됩니다.</li>
</ul>
