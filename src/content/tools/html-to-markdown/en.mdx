  - question: "What HTML elements are supported?"
    answer: "All common HTML elements: h1–h6, p, strong/b, em/i, a, img, code, pre+code (with language class), ul, ol, li, blockquote, hr, table (GFM format), and br. Unknown elements, including del, s, mark and form inputs, fall back to their text content."
  - question: "How are code blocks handled?"
    answer: "Inline <code> becomes backtick-delimited code. A <pre><code class=\"language-javascript\"> block becomes a fenced code block with the language tag preserved: ```javascript. If no language class is present, a plain ``` fence is used."
  - question: "Are GFM tables supported?"
    answer: "Yes, when the first row contains th cells. Such tables become GitHub Flavored Markdown (GFM) pipe tables with a separator row; a | inside a cell is written as \\| and a <br> inside a cell stays <br>. A table with no th in its first row is copied as HTML, because a GFM table needs a header row."
  - question: "What happens with invalid or incomplete HTML?"
    answer: "The browser's built-in HTML parser is used for parsing, so it applies the same tolerance as any browser. Malformed HTML is corrected automatically where possible, and conversion proceeds on the resulting DOM."
  - question: "Can I convert a full HTML page?"
    answer: "Yes, but remove what you do not want first. The converter has no rule that drops <script>, <style> or <title>, so their text appears in the Markdown output. Copy the article element from DevTools (right-click, Copy outerHTML) instead of the whole page."
  - question: "Is my HTML sent to a server?"
    answer: "No. All conversion happens entirely in your browser using the turndown.js library. Nothing is transmitted over the network."

<h2>Examples</h2>
<p>The outputs below come from the tool's converter: <a href="https://github.com/mixmark-io/turndown" target="_blank" rel="noopener">Turndown</a> 7.2.4 with the tables rule of turndown-plugin-gfm 1.0.2 and the options listed under "Output Style".</p>
<p><strong>A heading, inline code and a link with a title.</strong> Input:</p>
<p><code>{'<h2>Install</h2><p>Run <code>npm i turndown</code> and see the <a href="https://github.com/mixmark-io/turndown" title="repo">README</a>.</p>'}</code></p>
<p>Output:</p>

```markdown
## Install

Run `npm i turndown` and see the [README](https://github.com/mixmark-io/turndown "repo").
```

<p>The <code>title</code> attribute is kept as a Markdown link title in quotes.</p>
<p><strong>A table cell with a pipe and a line break.</strong> Input:</p>
<p><code>{'<table><thead><tr><th>Option</th><th>Values</th></tr></thead><tbody><tr><td><code>--format</code></td><td>json | yaml<br>default: json</td></tr></tbody></table>'}</code></p>
<p>Output:</p>

```markdown
| Option | Values |
| --- | --- |
| `--format` | json \| yaml<br>default: json |
```

<p>GFM ends a cell at every unescaped <code>|</code>, and a table row cannot span two lines (<a href="https://github.github.com/gfm/#tables-extension-" target="_blank" rel="noopener">GFM spec, Tables extension</a>). The converter therefore writes <code>{'\\|'}</code> and keeps the line break as <code>&lt;br&gt;</code>, so the row still has two cells.</p>
<p><strong>A nested list and an ordered list that starts at 3.</strong> Input <code>{'<ul><li>Step one</li><li>Step two<ul><li>Sub step</li></ul></li></ul><ol start="3"><li>Third</li><li>Fourth</li></ol>'}</code> gives:</p>

```markdown
-   Step one
-   Step two
    -   Sub step

3.  Third
4.  Fourth
```

<h2>Output Style</h2>
<ul>
  <li>Headings use <code>#</code> (ATX), bullets use <code>-</code> followed by three spaces, emphasis uses <code>{'*'}</code> and strong uses <code>{'**'}</code>.</li>
  <li>A <code>&lt;pre&gt;&lt;code class="language-x"&gt;</code> block becomes a <code>{'```x'}</code> fence. A <code>&lt;pre&gt;</code> without an inner <code>&lt;code&gt;</code> is not fenced: its text is copied with its line breaks, so wrap it in a fence by hand.</li>
  <li>Characters that would start Markdown syntax in plain text are escaped: <code>{'5 * 3'}</code> becomes <code>{'5 \\* 3'}</code>, <code>{'_a_'}</code> becomes <code>{'\\_a\\_'}</code>.</li>
  <li>Whitespace inside paragraphs is collapsed the way a browser renders it.</li>
</ul>

<h2>Limits</h2>
<ul>
  <li>Strikethrough (<code>&lt;del&gt;</code>, <code>&lt;s&gt;</code>), highlight (<code>&lt;mark&gt;</code>) and task-list checkboxes are not converted; only their text remains.</li>
  <li><code>colspan</code> and <code>rowspan</code> are ignored, because GFM tables have no merged cells. A header cell with <code>colspan="2"</code> becomes one header column above a two-column body, so fix the header by hand.</li>
  <li>The text inside <code>&lt;script&gt;</code>, <code>&lt;style&gt;</code> and <code>&lt;title&gt;</code> is not removed. Paste only the part of the page you need.</li>
  <li>Input over 1 MB (1,048,576 characters) shows "Input is very large — conversion may be slow." The conversion still runs in the page.</li>
  <li>Relative links and image paths are copied as written. They resolve against the page where the Markdown is published, not the page you copied from.</li>
</ul>
