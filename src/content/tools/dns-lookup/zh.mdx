## 使用方法

1. 输入域名。粘贴完整网址、带端口的地址、全角字符或中文域名都可以，页面会先转换成纯 ASCII 域名（中文域名转成 `xn--` 开头的 Punycode）。
2. 选记录类型。选 **ALL** 会同时查 A、AAAA、CNAME、MX、TXT、NS、SOA、CAA 八种。
3. 选解析器：Cloudflare（`cloudflare-dns.com`）或 Google（`dns.google`）。
4. 点 **查询** 或按回车；也可以直接点下方的示例域名。
5. 先看结果上方的标签（响应码、记录数、DNSSEC、解析器、耗时），再切到 **原文** 看 dig 风格的输出，或切到 **JSON** 看解析器原样返回的内容。

## 实测：百度的 CNAME 链和 QQ 邮箱的记录

以下结果在 2026-09-29 查询，重查时 TTL 会不同。

**同一个域名，两个解析器给出不同 IP。** 查 `www.baidu.com` 的 A 记录，两个解析器都先返回两条 CNAME：`www.a.shifen.com.`，再到 `www.wshifen.com.`。最后的 IP 不一样：Cloudflare 给出 `103.235.46.96`、`103.235.47.188`，Google 给出 `45.113.192.102`、`45.113.192.101`。原因之一是 Google 会把用户 IP 的一部分（[EDNS Client Subnet](https://developers.google.com/speed/public-dns/docs/ecs)）发给权威服务器，Cloudflare [不发](https://developers.cloudflare.com/1.1.1.1/faq/)，CDN 就可能按不同位置返回不同节点。这也说明本页的结果是公共解析器所在位置看到的结果，不等于你家运营商 DNS 的结果。

**检查一个邮箱域名的配置。** `qq.com` 的 MX 返回 `10 mx3.qq.com.`、`20 mx2.qq.com.`、`30 mx1.qq.com.`，数字越小越优先。`_dmarc.qq.com` 的 TXT 返回 `v=DMARC1; p=quarantine; rua=mailto:mailauth-reports@qq.com`，表示没通过验证的邮件按隔离处理（DMARC 记录的位置见 [RFC 7489 §6.1](https://www.rfc-editor.org/rfc/rfc7489#section-6.1)）。自己的域名配邮件时，按同样的顺序查 MX、根域名的 TXT（SPF）、`_dmarc` 的 TXT。

**签名验证失败的域名。** `dnssec-failed.org` 是 [Google 文档](https://developers.google.com/speed/public-dns/docs/doh/json) 里用来演示验证失败的域名。两个解析器都返回 **SERVFAIL**。Cloudflare 的备注是 `EDE(9): DNSKEY Missing ...`，即 [RFC 8914](https://www.rfc-editor.org/rfc/rfc8914#section-4.10) 定义的扩展错误码 9。

## 为什么本机 dig 查到的不一样

在一台开着代理软件 fake-ip 模式的测试机上，`dig @1.1.1.1 dnssec-failed.org` 返回 NOERROR 和 `198.18.2.147`。198.18.0.0/15 是保留给性能测试的地址段（[RFC 6890](https://www.rfc-editor.org/rfc/rfc6890#section-2.2.2)），mihomo（Clash Meta）的 [默认 fake-ip 范围](https://wiki.metacubex.one/config/dns/) 就在这段里。也就是说，即使写了 `@1.1.1.1`，发往 53 端口的查询也被代理软件截下并编了一个地址。本页走 HTTPS，拿到的是真实的 SERVFAIL。

排查「本机打不开，但别人能打开」时，先在本页查一次，再和本机 dig 的结果对照：两边不同，问题多半在本机的代理、hosts 或运营商 DNS。

## 与 dig、nslookup 和其他在线查询站的区别

- **dig / nslookup**：能指定任意权威服务器（`dig @ns1.example.com`），适合脚本和服务器上使用；结果受本机网络环境影响，如上所述。
- **[Google Admin Toolbox Dig](https://toolbox.googleapps.com/apps/dig/)**：查询由它的后端（`/apps/dig/lookup`）发出。查 `dnssec-failed.org` 时主界面只显示「Record not found!」，原始视图里才有 `rcode SERVFAIL`；查 `example.com` 时标志行是 `QR RD RA`，看不到 AD 标志。
- **本页**：浏览器直接问 Cloudflare 或 Google，可以切换对比；显示 DNSSEC 验证结果和解析器备注；JSON 原样可复制。

域名解析出 IP 后，可以用 [HTTP Header 分析器](/zh/tools/http-header-analyzer/) 看服务器返回什么，用 [SSL 证书解码器](/zh/tools/ssl-certificate-decoder/) 看它用的证书。

## 限制

- 只能选 Cloudflare 和 Google，不能填自己的 DoH 地址，也不能直接问权威服务器。
- 每个解析器只有一个观察点，不做多地区传播检测。
- ALL 只查八种类型。PTR 要自己输入 `1.1.1.1.in-addr.arpa` 这种反向名称；SRV 要输入完整名称，如 `_xmpp-server._tcp.jabber.org`。下拉框以外的类型（DS、DNSKEY、HTTPS、TLSA）查不了。
- TXT 记录超过 255 字节时会拆成多段（[RFC 1035 §3.3](https://www.rfc-editor.org/rfc/rfc1035#section-3.3)）。Cloudflare 按段加引号、用空格分隔，Google 拼成一整段、不加引号，两者是同一条记录。
- 域名至少两段；每段 1–63 个字母、数字、连字符或下划线，总长不超过 253。
