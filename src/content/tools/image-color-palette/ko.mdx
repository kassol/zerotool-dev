<h2>계산 방식</h2>
<ul>
  <li><strong>표본 추출</strong>: 262,144픽셀 이하 이미지는 모든 픽셀을 셉니다. 더 큰 이미지는 줄여서 읽되 부드럽게 보간하지 않으므로, 모든 표본이 원본의 실제 픽셀입니다. 경계에서 원본에 없는 중간색이 생기지 않습니다.</li>
  <li><strong>색 그룹</strong>: 채널마다 32단계(한 단계는 256개 값 중 8개), 모두 32,768개 그룹으로 셉니다. <a href="https://github.com/lokesh/color-thief" target="_blank" rel="noopener">Color Thief</a>의 미디언 컷과 같은 5비트 정밀도입니다. 픽셀은 불투명도로 가중합니다.</li>
  <li><strong>클러스터링</strong>: <a href="https://bottosson.github.io/posts/oklab/" target="_blank" rel="noopener">OKLab</a>에서 가중 k-means를 합니다. OKLab의 직선 거리는 눈에 보이는 색 차이에 가깝습니다. 초깃값은 정해진 순서로 고르며 무작위가 없습니다. ‘선명한 강조색 우선’을 켜면 색상과 채도 차이를 두 배로 셉니다.</li>
  <li><strong>병합</strong>: 0.02 미만으로 떨어진 클러스터는 합칩니다. 0.02는 <a href="https://drafts.csswg.org/css-color-4/#binsearch" target="_blank" rel="noopener">CSS Color 4</a> 색역 매핑이 쓰는 최소 식별 차이입니다.</li>
</ul>
<p>코드 내보내기는 화면 순서대로 <code>palette-1</code>부터 이름을 붙이고 비율을 주석으로 적습니다. .gpl은 GIMP, <a href="https://inkscape-manuals.readthedocs.io/en/latest/palette.html" target="_blank" rel="noopener">Inkscape</a>(팔레트 폴더에 넣기), <a href="https://docs.krita.org/ko/reference_manual/dockers/palette_docker.html" target="_blank" rel="noopener">Krita</a>에서, .ase는 <a href="https://helpx.adobe.com/kr/illustrator/desktop/manage-colors/use-swatches/share-swatches-between-applications.html" target="_blank" rel="noopener">Illustrator·Photoshop·InDesign</a>의 견본으로 씁니다.</p>

<h2>다른 추출 도구와 비교</h2>
<p>2026년 10월 2일, 위 배너와 고흐 「별이 빛나는 밤」 이미지로 확인했습니다.</p>
<ul>
  <li><strong>vivoldi 이미지 색상 추출기</strong>는 같은 이미지를 두 번 열어도 결과가 같지만, 채널 값을 10 단위로 맞춘 색을 돌려줍니다. 배너의 남색 <code>#1E3A8A</code>는 <code>#1E3C8C</code>, 주황 <code>#F97316</code>은 <code>#FA7814</code>가 되며 비율은 나오지 않습니다.</li>
  <li><strong>imageonline.io</strong>는 배너의 세 색을 정확히 돌려주지만 비율은 없습니다.</li>
  <li>라이브러리 <strong>node-vibrant 4.0.4</strong>는 ‘Vibrant’, ‘Muted’ 등 6가지 역할로 색을 고르고 5비트 그룹에서 색을 다시 만들어, 배너 남색이 <code>#1C3C8C</code>가 됩니다.</li>
</ul>

<h2>제한 사항</h2>
<ul>
  <li>262,144픽셀이 넘는 이미지는 표본으로 세므로 몇 픽셀 크기의 작은 부분은 빠질 수 있습니다.</li>
  <li>‘가장 많은 색조’가 원래 색과 정확히 같으려면 한 색이 그 색 그룹의 절반을 넘어야 합니다. 그렇지 않으면 그룹의 평균색입니다.</li>
  <li>sRGB 밖의 색(Display P3 사진 등)은 sRGB로 잘립니다. 팔레트가 표시된 뒤 같은 표본 픽셀을 Display P3로 다시 읽어, 완전히 불투명한 픽셀 중 sRGB 밖에 있는 비율을 상태 줄에 표시합니다. 브라우저가 OffscreenCanvas를 지원하면 연 파일은 백그라운드 Worker에서 디코딩해 검사하므로 큰 사진을 Display P3로 변환하는 작업이 페이지 스레드에서 실행되지 않습니다(안내가 팔레트보다 몇 초 늦게 나올 수 있습니다). 예시 일러스트와 SVG 파일은 페이지에서 16행씩 나눠 읽습니다. 브라우저가 Display P3로 그릴 수 없으면 검사할 수 없다고 상태 줄에 표시합니다.</li>
  <li>움직이는 GIF는 첫 프레임만 씁니다. HEIC는 Safari에서만 열리고, 카메라 RAW는 먼저 변환해야 합니다.</li>
</ul>
