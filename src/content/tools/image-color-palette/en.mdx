faqItems:
  - question: "Is my image uploaded?"
    answer: "No. The browser decodes the image, the tool counts its pixels and clusters them in JavaScript in your tab, and the page sends no request with the image or the colors. Only your settings (number of colors, sort, swatch mode, filters, export format) are saved in the browser; the image and the palette are not."
  - question: "Why do I get the same palette every time?"
    answer: "The clustering has no random step. It starts from the heaviest color group, adds seeds in a fixed order and breaks ties by index, so the same image and the same settings always give the same colors and shares. Many extractors seed k-means at random, and their palette changes when you run them again."
  - question: "What does the percentage on each color mean?"
    answer: "It is the share of the visible image that belongs to that color's cluster. Pixels count with their opacity, and fully transparent pixels are not counted. Pixels removed by Ignore near-white or Ignore near-black still count in the total, so the shares then add up to less than 100% and the status line says how much was ignored."
  - question: "Why does it show fewer colors than I asked for?"
    answer: "The tool groups pixels into 32,768 color groups (8 levels per channel). If the visible pixels fall into fewer groups than the number you asked for, every group becomes its own color and the status line says so. Clusters that end up less than 0.02 apart in OKLab are also merged, because they would look the same."
  - question: "Which apps open the .gpl and .ase files?"
    answer: "The .gpl file is the GIMP palette format, which GIMP, Inkscape and Krita read. The .ase file is Adobe Swatch Exchange, which Illustrator, Photoshop and InDesign load as a swatch library; Krita and GIMP can import it too. Both files hold the colors in the order shown, named by their hex value."

<h2>How the Palette Is Computed</h2>
<ul>
  <li><strong>Sampling.</strong> Images up to 262,144 pixels are read in full; larger ones are read at a reduced size without smoothing, so every sample is a real pixel.</li>
  <li><strong>Color groups.</strong> Pixels are counted in 32,768 groups of 8 levels per channel, the same 5-bit precision as the median-cut quantizer in <a href="https://github.com/lokesh/color-thief" target="_blank" rel="noopener">Color Thief</a>.</li>
  <li><strong>Clustering.</strong> The groups are clustered with weighted k-means in <a href="https://bottosson.github.io/posts/oklab/" target="_blank" rel="noopener">OKLab</a>, where straight-line distance follows how different two colors look. Seeds are chosen in a fixed order (heaviest group first, then the largest weight × squared distance), so nothing is random.</li>
  <li><strong>Vivid accents.</strong> With the option on, hue and chroma differences count twice in the distance, so a small saturated area keeps its own cluster.</li>
  <li><strong>Merging.</strong> Clusters less than 0.02 apart in OKLab are merged; 0.02 is the just-noticeable difference that <a href="https://drafts.csswg.org/css-color-4/#binsearch" target="_blank" rel="noopener">CSS Color 4</a> uses for gamut mapping.</li>
</ul>

<h2>Export and Palette Files</h2>
<p>Code exports name the colors <code>palette-1</code> to <code>palette-n</code> in screen order, with each share as a comment. Values can be hex, <code>rgb()</code>, <code>hsl()</code> or <code>oklch()</code>, written with just enough decimals to give back the same 8-bit color. The Tailwind v4 export is an <code>@theme</code> block (<code>bg-palette-1</code> works at once). The .gpl file follows the GIMP palette format and opens in GIMP, in <a href="https://inkscape-manuals.readthedocs.io/en/latest/palette.html" target="_blank" rel="noopener">Inkscape</a> (copy it into the palettes folder) and in <a href="https://docs.krita.org/en/reference_manual/dockers/palette_docker.html" target="_blank" rel="noopener">Krita</a>. The .ase file is Adobe Swatch Exchange, which <a href="https://helpx.adobe.com/illustrator/desktop/manage-colors/use-swatches/share-swatches-between-applications.html" target="_blank" rel="noopener">Illustrator, Photoshop and InDesign</a> load as a swatch library.</p>

<h2>Compared with Other Extractors</h2>
<p>Tested on 2 October 2026:</p>
<ul>
  <li><strong>Color Thief 2.7.0</strong> (npm <code>colorthief</code>, median cut) returns the three banner colors exactly but gives no shares. <strong>node-vibrant 4.0.4</strong> sorts colors into six roles (Vibrant, Muted and so on) and finds the yellow in The Starry Night, but rebuilds colors from 5-bit groups: the banner navy comes back as <code>#1C3C8C</code> instead of <code>#1E3A8A</code>.</li>
  <li><strong>imageonline.io</strong> returns the banner colors exactly, without shares. <strong>Pantone Tools</strong> rounds every channel to multiples of 32: the banner becomes <code>#002080</code>, <code>#E0E0E0</code> and <code>#E06000</code>, plus a navy–white blend <code>#8080C0</code> that is not in the image.</li>
  <li><strong>Coolors</strong> and <strong>ColorKit</strong> are pickers: they place five points on the image and use the colors under them, so the result depends on where the points land, not on area.</li>
</ul>
<p>imageonline.io and Pantone Tools made no network request with the image after it was opened (checked in the browser's resource timing list).</p>

<h2>Limits</h2>
<ul>
  <li>Images above 262,144 pixels are sampled, so a detail smaller than a few pixels of the reduced image can be missed.</li>
  <li>A most common shade is exact only when one color fills more than half of its 8-level group; otherwise it is that group's average.</li>
  <li>Colors outside sRGB, such as in Display P3 photos, are clipped to sRGB. After the palette appears, the tool reads the same sampled pixels again in Display P3 and the status line gives the share of fully opaque pixels outside sRGB. An opened file is decoded for this check in a background worker where the browser supports it (OffscreenCanvas), so converting a large photo to Display P3 does not run on the page's thread (the note can arrive a few seconds after the palette); the sample illustration and SVG files are read here in strips of 16 rows. If the browser cannot draw in Display P3, the status line says the check is unavailable.</li>
  <li>Animated GIFs give the palette of the first frame. HEIC opens only in Safari; camera RAW files need converting first.</li>
</ul>
<p>To pick one exact pixel instead of a palette, use the <a href="/tools/eyedropper-color-picker/">color picker</a>. To see how the palette looks to people with color vision deficiency, paste it into the <a href="/tools/color-blindness-simulator/">Color Blindness Simulator</a>, and check text on it with the <a href="/tools/color-contrast-checker/">Color Contrast Checker</a>.</p>
