## 使用步骤

1. 把证书粘贴进输入框，或把 `.crt`、`.cer`、`.der`、`.pem`、`.p7b` 文件拖进去，也可以点**打开文件**。单张证书和整条链都可以。
2. 输入后自动解析；点**解析**（或 Ctrl/⌘+Enter）重新运行。
3. 先看证书链卡片：顺序、每一级签名、是否缺少颁发者。
4. 点列表里的某张证书，查看检查结果、有效期、主题、SAN、公钥、指纹和全部扩展。
5. 在**检查域名**里输入域名，确认这张证书能否用于它。

## 实例：www.baidu.com 返回的证书链

点**示例**会载入 2026-10-01 用 `openssl s_client -showcerts` 从 `www.baidu.com` 取到的 3 张证书。{/* scd-check: {"chain":"www.baidu.com","field":"count","expect":"3"} */}工具给出的结果：

| # | 主题 CN | 角色 | 由下一张签发 |
|---|---|---|---|
| 1 | baidu.com | 服务器证书 | 签名验证通过 |
| 2 | GlobalSign RSA OV SSL CA 2018 | 中间 CA | 签名验证通过 |
| 3 | GlobalSign | 中间 CA | 颁发者不在输入里 |

第 3 张是 GlobalSign Root CA - R3 的交叉签名版本，它的颁发者是 `CN=GlobalSign Root CA,OU=Root CA,O=GlobalSign nv-sa,C=BE`。{/* scd-check: {"chain":"www.baidu.com","index":2,"field":"issuer","expect":"CN=GlobalSign Root CA,OU=Root CA,O=GlobalSign nv-sa,C=BE"} */}这张老根证书没有发送，客户端信任库里本来就有，所以没有问题。

服务器证书这几项值得看：

- 主题写成 `CN=baidu.com,O=Beijing Baidu Netcom Science Technology Co.\, Ltd.,L=Beijing,ST=Beijing,C=CN`。{/* scd-check: {"chain":"www.baidu.com","field":"subject","expect":"CN=baidu.com,O=Beijing Baidu Netcom Science Technology Co.\\, Ltd.,L=Beijing,ST=Beijing,C=CN"} */}公司名里的逗号按 [RFC 4514](https://www.rfc-editor.org/rfc/rfc4514) 转义成 `\,`，和 `openssl x509 -subject -nameopt RFC2253` 的输出一致。
- SAN 有 53 个条目。{/* scd-check: {"chain":"www.baidu.com","field":"sanCount","expect":"53"} */}输入 `www.baidu.com` 会提示与通配符 `*.baidu.com` 匹配；通配符只覆盖一级（[RFC 9525 §6.3](https://www.rfc-editor.org/rfc/rfc9525#section-6.3)）。{/* scd-check: {"chain":"www.baidu.com","field":"host","host":"www.baidu.com","expect":"match"} */}
- 有效期从 `2026-07-09 02:32:55 UTC` 到 `2027-01-24 02:32:55 UTC`，工具算出 **200 天**。{/* scd-check: {"chain":"www.baidu.com","field":"days","expect":"200"} */}{/* scd-check: {"chain":"www.baidu.com","field":"notBefore","expect":"2026-07-09 02:32:55 UTC"} */}两个时间点相差 199 天，但 RFC 5280 把起止两端都算进有效期，多出的 1 秒按 [CA/B 论坛 BR §6.3.2](https://github.com/cabforum/servercert/blob/main/docs/BR.md) 的算法记为 1 天。2026-03-15 起签发的公开信任证书最长 200 天（SC-081 投票），这张正好卡在上限。
- 3 个证书透明度 SCT，列出日志 ID 和时间戳。{/* scd-check: {"chain":"www.baidu.com","field":"sct","expect":"3"} */}

## 证书链顺序和 Nginx

Nginx 文档要求合并文件里「服务器证书必须在链上的其他证书之前」（[Configuring HTTPS servers](https://nginx.org/en/docs/http/configuring_https_servers.html)），TLS 1.3 也规定每张证书后面应是签发它的证书（[RFC 8446 §4.4.2](https://www.rfc-editor.org/rfc/rfc8446#section-4.4.2)）。拼 `fullchain.pem` 时把顺序弄反，是常见的错误。

把上面 3 张证书倒过来粘贴，工具会提示：**顺序不对，或输入里混有不同的链。从服务器证书出发的路径：#3 → #2 → #1。**{/* scd-check: {"chain":"www.baidu.com","field":"reversedPath","expect":"#3 → #2 → #1"} */}每一级仍显示「签名验证通过」，说明证书是一套的，只是顺序错了。点**按建议顺序复制**即可得到正确的文件。

只粘贴服务器证书时，卡片会写明颁发者不在输入里，并给出 AIA 里的下载地址。浏览器常会借助它补全缺失的中间证书，但 [Java](https://docs.oracle.com/en/java/javase/21/security/java-pki-programmers-guide.html) 默认关闭这一功能，Go 的 TLS 也不做（[golang/go#31773](https://go.dev/issue/31773)），应在服务器上补齐。

## 工具检查哪些问题

- 外层与 tbsCertificate 内的签名算法是否一致（[RFC 5280 §4.1.1.2](https://www.rfc-editor.org/rfc/rfc5280#section-4.1.1.2)）。
- 序列号是否为正数、是否超过 20 字节（§4.1.2.2）；时间是否带秒和 `Z`，2049 年及以前是否用 UTCTime（§4.1.2.5）。
- 无法识别的关键扩展、重复扩展（§4.2）。
- 没有 SAN：浏览器不再看 CN，Chrome 从 [58 版](https://chromestatus.com/feature/4981025180483584)起移除了 CN 匹配。
- SHA-1 / MD5 签名、不足 2048 位的 RSA 密钥。
- 颁发者是否为 CA、是否有 keyCertSign、是否超出路径长度限制。

公钥长度按密钥本身计算：P-521 显示 521 位。指纹卡片给出 DER 的 SHA-256、SHA-1、MD5，以及公钥（SPKI）的 SHA-256 Base64 值，也就是 [RFC 7469](https://www.rfc-editor.org/rfc/rfc7469#section-2.4) 的 pin-sha256 格式，Android 的网络安全配置和 OkHttp 证书固定都用这种格式。

## 支持的输入

- PEM：`CERTIFICATE`、旧写法 `X509 CERTIFICATE`、OpenSSL 的 `TRUSTED CERTIFICATE`；块前后的文字、CRLF 换行、多余空格都会忽略。
- 没有 BEGIN / END 行的纯 Base64。
- 二进制 DER 文件和 PKCS #7（`.p7b`），载入后会转成 PEM 显示在输入框里。
- CSR、公钥、CRL 会被识别并说明，不会当成证书。CSR 请用 [CSR 解码器](/zh/tools/csr-decoder/)。

出错时会指出位置，例如复制时丢了一行 Base64：「第 0 字节处的 Certificate 需要 2543 字节，但只剩 2495 字节」。{/* scd-check: {"chain":"www.baidu.com","field":"cutNeed","expect":"2543"} */}{/* scd-check: {"chain":"www.baidu.com","field":"cutHave","expect":"2495"} */}

## 与常见工具的差异

2026-10-01 用同一组证书实测：

| 工具 | 在哪里解析 | 粘贴 4 张证书的链 |
|---|---|---|
| MySSL 证书查看 | 把证书提交到服务器（`/api/v1/tools/cert_decode`） | 只显示第 1 张 |
| SSL Shopper | 把证书提交到服务器 | 提示无法解析 |
| 本工具 | 当前页面内 | 4 张全部解析，并检查顺序和签名 |

MySSL 把 `2026-09-26 22:49:11 UTC` 显示为「2026-09-27 06:49:11」，换算成了北京时间但没有标时区，对照 `openssl` 输出时容易看错。

## 限制

- 没有信任库，不查 OCSP / CRL 吊销，也不连接服务器。在线取证书链可以用 `openssl s_client -connect 域名:443 -showcerts`；查记录用 [DNS 查询](/zh/tools/dns-lookup/)，看响应头用 [HTTP Header 分析器](/zh/tools/http-header-analyzer/)。
- 签名验证用 Web Crypto：RSA（PKCS #1 v1.5、PSS）、P-256 / P-384 / P-521 的 ECDSA，以及浏览器支持时的 Ed25519。国密 SM2、ML-DSA、Ed448、DSA 的签名会解析，但标为未验证。
- 名称约束只显示，不套用到服务器证书的域名上。
- 文件不超过 1 MB，一次最多 200 张证书。
