<h2>(a, b, c) タプルの読み方</h2>
<ul>
  <li><strong>a — ID</strong>: <code>#id</code> セレクター1つにつき +1。</li>
  <li><strong>b — クラス / 属性 / 疑似クラス</strong>: <code>.class</code>・<code>[attr]</code>・<code>:疑似クラス</code> 1つにつき +1。</li>
  <li><strong>c — 要素 / 疑似要素</strong>: タグ名または <code>::疑似要素</code> 1つにつき +1。</li>
</ul>
<p>左から順に比較します。最初に異なる列が勝敗を決めます。<code>(1,0,0)</code> は常に <code>(0,99,99)</code> に勝ちます。</p>

<h2>よくある例</h2>
<ul>
  <li><code>*</code> → <code>(0, 0, 0)</code></li>
  <li><code>p</code> → <code>(0, 0, 1)</code></li>
  <li><code>.class</code> → <code>(0, 1, 0)</code></li>
  <li><code>#id</code> → <code>(1, 0, 0)</code></li>
  <li><code>#id .class:hover</code> → <code>(1, 2, 0)</code></li>
  <li><code>div > p + span::before</code> → <code>(0, 0, 4)</code></li>
</ul>

<h2>関数型の疑似クラス</h2>
<p>Selectors Level 4 §17 は次の疑似クラスに個別の規則を定めています。手計算で間違えやすいところです。</p>
<ul>
  <li><code>:is(.a, #b)</code> → <code>(1, 0, 0)</code>：要素が実際に <code>.a</code> に一致しても、引数のうち最も詳細度が高いものを使います。</li>
  <li><code>:not(.a, .b.c)</code> → <code>(0, 2, 0)</code>：引数どうしは足さずに最大値を取ります。</li>
  <li><code>article:has(> img, > .figure)</code> → <code>(0, 1, 1)</code></li>
  <li><code>:where(#app .card) p</code> → <code>(0, 0, 1)</code>：<code>:where()</code> は常に 0 で、リセット CSS やライブラリが詳細度を下げるのに使います。</li>
  <li><code>li:nth-child(2n+1)</code> → <code>(0, 1, 1)</code></li>
  <li><code>li:nth-child(2n+1 of .important)</code> → <code>(0, 2, 1)</code>：疑似クラス 1 つに、<code>of</code> 以降の最大値を加えます。</li>
  <li><code>a[href="#top"]</code> → <code>(0, 1, 1)</code>：引用符内の <code>#</code> は ID ではありません。</li>
</ul>

## WordPress 6.6 のブロックスタイルと :root :where()

WordPress 6.6 の開発者ノート「WordPress 6.6 CSS Specificity」によると、theme.json とグローバルスタイルが出力するブロックのスタイルは詳細度 0-1-0 にそろえられ、それより高いセレクターは `:root :where(...)` で包む形に変わりました。ノートの例では、画像ブロックの角丸スタイル `.wp-block-image.is-style-rounded img` が `:root :where(.wp-block-image.is-style-rounded img)` になっています。

{/* csc-check: {"in":".wp-block-image.is-style-rounded img, :root :where(.wp-block-image.is-style-rounded img)"} */}

2 つを並べて `.wp-block-image.is-style-rounded img, :root :where(.wp-block-image.is-style-rounded img)` と入力すると、`(0, 2, 1)` と `(0, 1, 0)` です。`:root` は疑似クラスなので 1 つ数え、`:where()` の中身は数えません。テーマが従来どおり `.wp-block-image.is-style-rounded img` で角丸を書くと、サイトエディターのグローバルスタイルで変えた値より強くなってしまうため、ノートはテーマ側も `:root :where()` で包むよう勧めています。

{/* csc-check: {"in":"body, :root :where(body)"} */}

逆に詳細度が上がりすぎた例もあります。6.6 では body のスタイルが `:root :where(body)` として出力され、従来の `body` の `(0, 0, 1)` から `(0, 1, 0)` になりました。テーマの指定が効かなくなるとして Trac チケット #61704 で報告され、changeset 58874 で 6.6 ブランチの出力は `body` に戻されています。

## 全角で入力されたセレクター

{/* csc-check: {"in":"＃ｍａｉｎ．ｎａｖ, #main.nav","fullwidth":true} */}

全角のまま入力された `＃ｍａｉｎ．ｎａｖ` は、CSS では ID とクラスにはなりません。全角の「＃」「．」は名前に使える文字なので、全体が「＃ｍａｉｎ．ｎａｖ」という名前の要素セレクター 1 つとして読まれます。結果は `(0, 0, 1)` で、カードには全角文字を含むという注意が出ます。半角の `#main.nav` なら `(1, 1, 0)` です。全角の「：」「［」も同じで、`:` や `[` としては働きません。

<h2>カスケードの中での詳細度</h2>
<p>CSS Cascade Level 5 §6 では、オリジンと重要度、コンテキスト、style 属性、カスケードレイヤーの順に比べ、その後で詳細度と出現順を比べます。<code>!important</code> 付きの宣言や後ろの <code>@layer</code> にある宣言は、詳細度が高いセレクターにも勝ちます。</p>

<h2>制限事項</h2>

{/* csc-check: {"in":".card:not(.featured"} */}

<ul>
  <li>ネストセレクター <code>&amp;</code> はここでは 0 として数えます。実際の CSS では親ルールのセレクターリストの最大値になります（CSS Nesting §4）が、セレクター単体からは親ルールがわかりません。</li>
  <li>構文だけを確認し、疑似クラス名が存在するかは確認しません。綴りを誤った <code>:hovr</code> も疑似クラス 1 つとして数えますが、ブラウザーはルール全体を無視します。</li>
  <li>解析できない入力（閉じていない括弧や引用符、単独の <code>#</code> や <code>.</code>）は、理由と位置を結果カードに表示します。たとえば <code>.card:not(.featured</code> には「10 文字目の括弧に対応する「)」がありません」と表示されます。</li>
  <li>複合セレクター内の順序は確認しません。<code>[x]p</code> は <code>(0, 1, 1)</code> と数えますが、ブラウザーは属性セレクターの後ろに置いた要素セレクターを受け付けません。</li>
</ul>

{/* csc-check: {"in":"div　p"} */}

名前の間に全角スペース（U+3000）やノーブレークスペース（U+00A0）が入るとエラーになります。`div　p` を入力すると「4 文字目の U+3000 は CSS の空白ではなく、名前にも使えません」と表示されます。[CSS Syntax 3 §4.2](https://www.w3.org/TR/css-syntax-3/#non-ascii-ident-code-point) では空白はスペース・タブ・改行だけで、名前に使える文字の一覧にもこの 2 文字は入っていません。ただしブラウザーの実装はまだそろっていません。2026-10-09 に Chrome 152 で試すと、`document.querySelector()` は `div　p` をエラーにせず「div　p」という名前の要素セレクター 1 つとして読みました。そのため `div` の中の `p` には一致しません。
