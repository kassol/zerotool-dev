<h2>Reading the (a, b, c) Tuple</h2>
<ul>
  <li><strong>a — ID</strong>: Each <code>#id</code> selector adds 1 here.</li>
  <li><strong>b — Class / Attribute / Pseudo-class</strong>: Each <code>.class</code>, <code>[attr]</code>, or <code>:pseudo-class</code> adds 1.</li>
  <li><strong>c — Element / Pseudo-element</strong>: Each tag name or <code>::pseudo-element</code> adds 1. The legacy one-colon forms <code>:before</code>, <code>:after</code>, <code>:first-line</code> and <code>:first-letter</code> are pseudo-elements too.</li>
</ul>
<p>Compare left to right. The first column where two selectors differ decides which one wins. <code>(1,0,0)</code> always beats <code>(0,99,99)</code>. If all three columns are equal, the rule that appears later in the stylesheet wins.</p>

<h2>Common Examples</h2>
<ul>
  <li><code>*</code> → <code>(0, 0, 0)</code></li>
  <li><code>p</code> → <code>(0, 0, 1)</code></li>
  <li><code>.class</code> → <code>(0, 1, 0)</code></li>
  <li><code>#id</code> → <code>(1, 0, 0)</code></li>
  <li><code>#id .class:hover</code> → <code>(1, 2, 0)</code></li>
  <li><code>div > p + span::before</code> → <code>(0, 0, 4)</code></li>
  <li><code>a[href="#top"]</code> → <code>(0, 1, 1)</code> — the <code>#</code> inside the quoted value is not an ID.</li>
</ul>

<h2>Functional Pseudo-classes</h2>
<p>Selectors Level 4 §17 gives these pseudo-classes their own rules, and they are where hand counting usually goes wrong:</p>
<ul>
  <li><code>:is(.a, #b)</code> → <code>(1, 0, 0)</code> — the most specific argument counts, even if the element matched <code>.a</code>.</li>
  <li><code>:not(.a, .b.c)</code> → <code>(0, 2, 0)</code> — the arguments are compared, never added up.</li>
  <li><code>article:has(> img, > .figure)</code> → <code>(0, 1, 1)</code></li>
  <li><code>:where(#app .card) p</code> → <code>(0, 0, 1)</code> — <code>:where()</code> always counts zero, which is why reset and library styles use it.</li>
  <li><code>li:nth-child(2n+1)</code> → <code>(0, 1, 1)</code></li>
  <li><code>li:nth-child(2n+1 of .important)</code> → <code>(0, 2, 1)</code> — one pseudo-class plus the most specific selector after <code>of</code>.</li>
  <li><code>::slotted(span.note)</code> → <code>(0, 1, 2)</code> and <code>:host(.dark)</code> → <code>(0, 2, 0)</code> — CSS Scoping adds the argument to the pseudo-element or pseudo-class.</li>
</ul>

## Worked Examples

{/* csc-check: {"in":":where(.btn), .btn, .ui .btn"} */}

A component library ships `:where(.btn) { color: gray }` and your app adds `.btn { color: navy }`. Enter `:where(.btn), .btn, .ui .btn` to compare the three forms: `(0, 0, 0)`, `(0, 1, 0)` and `(0, 2, 0)`. The library rule loses to yours no matter which file loads last. If the library had written `.ui .btn` instead, you would need a second class or a cascade layer to override it.

{/* csc-check: {"in":"#nav a:hover, nav .nav-link.active"} */}

A navigation link stays red on hover even though the active state sets it blue. Compare `#nav a:hover` and `nav .nav-link.active`: `(1, 1, 1)` against `(0, 2, 1)`. The first column decides, so the ID wins even with fewer classes. Lowering the first rule to `.nav a:hover` would make it `(0, 2, 1)` as well, and then the later rule wins.

{/* csc-check: {"in":".card:not(.featured"} */}

Pasting `.card:not(.featured` with the closing bracket missing gives an error card instead of a tuple: `Missing ")" (position 10)`. Position 10 is the `(` that is never closed; the browser would drop the whole rule.

<h2>Where Specificity Sits in the Cascade</h2>
<p>CSS Cascade Level 5 §6 sorts declarations by origin and importance, then by context, then the <code>style</code> attribute, then cascade layer, and only then by specificity and order of appearance. A declaration marked <code>!important</code> or placed in a later <code>@layer</code> can beat a selector with a higher tuple. This tool calculates the specificity step only.</p>

<h2>Limitations</h2>
<ul>
  <li>The nesting selector <code>&amp;</code> counts as zero here. In real CSS it has the specificity of the parent rule's most specific selector (CSS Nesting §4), which a single selector on its own does not show.</li>
  <li>The tool checks the structure of the selector, not whether a pseudo-class name exists. An unknown name such as <code>:hovr</code> still counts as one pseudo-class, while a browser would drop the whole rule.</li>
  <li>Inline styles, <code>!important</code> and <code>@layer</code> are outside the calculation, as described above.</li>
  <li>Full-width characters such as <code>＃</code>, <code>．</code> and <code>：</code> are name characters in CSS, not <code>#</code>, <code>.</code> or <code>:</code>. <code>＃ｍａｉｎ</code> is one type selector, <code>(0, 0, 1)</code>, and the card adds a note when it sees them.</li>
  <li>The order inside a compound selector is not checked. <code>[x]p</code> counts as <code>(0, 1, 1)</code>, although a browser rejects a type selector after an attribute selector.</li>
</ul>
