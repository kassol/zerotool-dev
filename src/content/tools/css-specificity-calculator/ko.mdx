<h2>(a, b, c) 튜플 읽기</h2>
<ul>
  <li><strong>a — ID</strong>: <code>#id</code> 선택자 하나당 +1.</li>
  <li><strong>b — 클래스 / 속성 / 가상 클래스</strong>: <code>.class</code>, <code>[attr]</code>, <code>:가상클래스</code> 하나당 +1.</li>
  <li><strong>c — 요소 / 가상 요소</strong>: 태그 이름 또는 <code>::가상요소</code> 하나당 +1.</li>
</ul>
<p>왼쪽부터 비교합니다. 처음으로 다른 열이 승패를 결정합니다. <code>(1,0,0)</code>은 항상 <code>(0,99,99)</code>를 이깁니다.</p>

<h2>일반적인 예시</h2>
<ul>
  <li><code>*</code> → <code>(0, 0, 0)</code></li>
  <li><code>p</code> → <code>(0, 0, 1)</code></li>
  <li><code>.class</code> → <code>(0, 1, 0)</code></li>
  <li><code>#id</code> → <code>(1, 0, 0)</code></li>
  <li><code>#id .class:hover</code> → <code>(1, 2, 0)</code></li>
  <li><code>div > p + span::before</code> → <code>(0, 0, 4)</code></li>
</ul>

<h2>함수형 가상 클래스</h2>
<p>Selectors Level 4 §17은 다음 가상 클래스에 별도 규칙을 둡니다. 손으로 계산할 때 가장 자주 틀리는 부분입니다.</p>
<ul>
  <li><code>:is(.a, #b)</code> → <code>(1, 0, 0)</code>: 요소가 실제로 <code>.a</code>에 일치해도 인수 중 명시도가 가장 높은 것을 씁니다.</li>
  <li><code>:not(.a, .b.c)</code> → <code>(0, 2, 0)</code>: 인수끼리 더하지 않고 최댓값을 씁니다.</li>
  <li><code>article:has(> img, > .figure)</code> → <code>(0, 1, 1)</code></li>
  <li><code>:where(#app .card) p</code> → <code>(0, 0, 1)</code>: <code>:where()</code>는 항상 0이어서 리셋 CSS와 라이브러리가 명시도를 낮출 때 씁니다.</li>
  <li><code>li:nth-child(2n+1)</code> → <code>(0, 1, 1)</code></li>
  <li><code>li:nth-child(2n+1 of .important)</code> → <code>(0, 2, 1)</code>: 가상 클래스 하나에 <code>of</code> 뒤의 최댓값을 더합니다.</li>
  <li><code>a[href="#top"]</code> → <code>(0, 1, 1)</code>: 따옴표 안의 <code>#</code>는 ID가 아닙니다.</li>
</ul>

## KRDS 버튼 스타일 덮어쓰기

KRDS의 npm 패키지 `krds-uiux` 1.1.0에 들어 있는 `component.css`를 보면, 기본(primary) 버튼의 호버는 `.krds-btn.primary:hover`, 비활성 버튼의 호버는 `.krds-btn.primary[disabled]:hover`, 고대비 모드의 호버는 `[data-krds-mode=high-contrast] .krds-btn.primary:hover`로 정의되어 있습니다.

{/* csc-check: {"in":".krds-btn.primary:hover, .krds-btn.primary[disabled]:hover, [data-krds-mode=high-contrast] .krds-btn.primary:hover"} */}

세 선택자를 쉼표로 이어 `.krds-btn.primary:hover, .krds-btn.primary[disabled]:hover, [data-krds-mode=high-contrast] .krds-btn.primary:hover`를 입력하면 `(0, 3, 0)`, `(0, 4, 0)`, `(0, 4, 0)`이 나옵니다. 비활성 상태와 고대비 모드 규칙은 b 열이 하나 더 많아 일반 호버 규칙을 이깁니다. 뒤의 두 규칙처럼 명시도가 같으면 파일에서 나중에 나오는 규칙이 적용됩니다.

{/* csc-check: {"in":".my-page .krds-btn, .my-page .krds-btn.primary:hover"} */}

페이지에서 버튼 색을 바꾸려고 `.my-page .krds-btn`을 쓰면 `(0, 2, 0)`이라 호버 규칙의 `(0, 3, 0)`에 집니다. 그렇다고 `.my-page .krds-btn.primary:hover`로 쓰면 `(0, 4, 0)`이 되어, 불러오는 순서와 관계없이 일반 호버 규칙은 이기지만 비활성·고대비 호버 규칙과는 같아집니다. 이때 KRDS CSS보다 뒤에 불러오면 비활성 버튼과 고대비 모드의 호버 색까지 내 색으로 바뀝니다.

{/* csc-check: {"in":":where(.my-page) .krds-btn.primary:hover, .krds-btn.primary[disabled]:hover"} */}

일반 호버만 바꾸려면 범위를 정하는 클래스를 `:where()`로 감싸 명시도를 KRDS와 같게 맞춥니다. `:where(.my-page) .krds-btn.primary:hover`는 `:where()` 안이 0으로 계산되어 `(0, 3, 0)`이고, 비활성 호버 `.krds-btn.primary[disabled]:hover`는 `(0, 4, 0)`입니다. KRDS CSS 뒤에 불러오면 같은 `(0, 3, 0)`인 일반 호버 규칙은 순서로 이기고, `(0, 4, 0)`인 비활성·고대비 호버 규칙에는 순서와 관계없이 집니다.

{/* csc-check: {"in":".krds-btn, :where(.my-page) .krds-btn, [data-krds-mode=high-contrast] .krds-btn"} */}

변수를 바꾸는 방법도 같은 원리입니다. `component.css`에서 `--krds-button--color-primary-fill-hover` 같은 버튼 색 변수는 `.krds-btn`, 즉 `(0, 1, 0)`에서 정의되고, 고대비 모드에서는 `[data-krds-mode=high-contrast] .krds-btn`(`(0, 2, 0)`)이 같은 변수를 다시 정의합니다. `:where(.my-page) .krds-btn`(`(0, 1, 0)`) 안에서 변수 값을 바꾸고 KRDS CSS 뒤에 불러오면 일반 모드의 변수만 바뀌고, 고대비 모드의 값은 그대로 남습니다. 비활성 버튼은 별도 변수(`--krds-button--color-primary-fill-disabled`)를 쓰므로 영향을 받지 않습니다.

## 한글 클래스 이름

{/* csc-check: {"in":".메인 .버튼, #공지 a"} */}

클래스와 ID에는 한글도 쓸 수 있고, 명시도는 영문 이름과 똑같이 셉니다. `.메인 .버튼`은 `(0, 2, 0)`, `#공지 a`는 `(1, 0, 1)`입니다.

<h2>캐스케이드 안에서의 명시도</h2>
<p>CSS Cascade Level 5 §6은 출처와 중요도, 컨텍스트, style 속성, 캐스케이드 레이어 순으로 비교한 뒤에야 명시도와 등장 순서를 비교합니다. <code>!important</code>가 붙은 선언이나 뒤쪽 <code>@layer</code>의 선언은 명시도가 더 높은 선택자도 이깁니다.</p>

<h2>제한 사항</h2>

{/* csc-check: {"in":".card:not(.featured"} */}

예를 들어 `.card:not(.featured`처럼 괄호가 닫히지 않은 선택자를 넣으면, 결과 카드에 `10번째 문자의 괄호를 닫는 ")" 문자가 없습니다`라는 안내가 표시됩니다.

<ul>
  <li>중첩 선택자 <code>&amp;</code>는 여기서 0으로 셉니다. 실제 CSS에서는 부모 규칙 선택자 목록의 최댓값이 됩니다(CSS Nesting §4). 선택자 하나만으로는 부모 규칙을 알 수 없습니다.</li>
  <li>구조만 확인하고 가상 클래스 이름이 실제로 있는지는 확인하지 않습니다. 철자가 틀린 <code>:hovr</code>도 가상 클래스 하나로 세지만, 브라우저는 규칙 전체를 버립니다.</li>
  <li>해석할 수 없는 입력(닫히지 않은 괄호나 따옴표, 단독 <code>#</code>나 <code>.</code>)은 이유와 위치를 결과 카드에 표시합니다.</li>
  <li>복합 선택자 안의 순서는 확인하지 않습니다. <code>[x]p</code>는 <code>(0, 1, 1)</code>로 세지만, 브라우저는 속성 선택자 뒤에 붙은 요소 선택자를 받아들이지 않습니다.</li>
  <li>전각 문자(<code>＃</code>, <code>．</code>, <code>：</code> 등)는 CSS에서 이름에 쓰이는 문자이므로 <code>#</code>, <code>.</code>, <code>:</code>로 읽히지 않습니다. 이런 문자가 있으면 결과 카드에 안내가 표시됩니다.</li>
</ul>

{/* csc-check: {"in":"div　p","space":true} */}

이름 사이에 전각 공백(U+3000)이나 줄바꿈 없는 공백(U+00A0)이 들어가도 자손 결합자가 되지 않습니다. 2026-10-09에 Chrome 152에서 `document.querySelector()`와 규칙을 넣은 뒤의 `selectorText`로 확인하니, 이 문자는 이름의 일부로 읽혔습니다. `div　p`는 "div　p"라는 이름의 요소 선택자 하나로 `(0, 0, 1)`이고, `div` 안의 `p`와는 일치하지 않습니다. 이 도구도 같은 방식으로 세고 결과 카드에 안내를 표시합니다. 사양은 다릅니다. [CSS Syntax 3 §4.2](https://www.w3.org/TR/css-syntax-3/#non-ascii-ident-code-point)에서 공백은 줄바꿈, 탭, 스페이스뿐이고, 이름에 쓸 수 있는 비 ASCII 문자 목록에도 U+00A0과 U+3000은 없습니다(U+3001부터 다시 포함). 사양상으로는 이 선택자가 무효입니다.
