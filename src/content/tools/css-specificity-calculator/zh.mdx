<h2>理解 (a, b, c) 元组</h2>
<ul>
  <li><strong>a — ID</strong>：每个 <code>#id</code> 选择器加 1。</li>
  <li><strong>b — 类 / 属性 / 伪类</strong>：每个 <code>.class</code>、<code>[attr]</code> 或 <code>:伪类</code> 加 1。</li>
  <li><strong>c — 元素 / 伪元素</strong>：每个标签名或 <code>::伪元素</code> 加 1。</li>
</ul>
<p>从左到右对比。第一个不同的列决定胜负。<code>(1,0,0)</code> 始终胜过 <code>(0,99,99)</code>。</p>

<h2>常见示例</h2>
<ul>
  <li><code>*</code> → <code>(0, 0, 0)</code></li>
  <li><code>p</code> → <code>(0, 0, 1)</code></li>
  <li><code>.class</code> → <code>(0, 1, 0)</code></li>
  <li><code>#id</code> → <code>(1, 0, 0)</code></li>
  <li><code>#id .class:hover</code> → <code>(1, 2, 0)</code></li>
  <li><code>div > p + span::before</code> → <code>(0, 0, 4)</code></li>
</ul>

<h2>函数式伪类</h2>
<p>Selectors Level 4 §17 为下面这些伪类单独规定了算法，手算最容易出错：</p>
<ul>
  <li><code>:is(.a, #b)</code> → <code>(1, 0, 0)</code>：取参数中优先级最高的一项，即使元素实际匹配的是 <code>.a</code>。</li>
  <li><code>:not(.a, .b.c)</code> → <code>(0, 2, 0)</code>：参数之间取最大值，不相加。</li>
  <li><code>article:has(> img, > .figure)</code> → <code>(0, 1, 1)</code></li>
  <li><code>:where(#app .card) p</code> → <code>(0, 0, 1)</code>：<code>:where()</code> 始终计 0，重置样式与组件库常用它降低优先级。</li>
  <li><code>li:nth-child(2n+1)</code> → <code>(0, 1, 1)</code></li>
  <li><code>li:nth-child(2n+1 of .important)</code> → <code>(0, 2, 1)</code>：一个伪类，加上 <code>of</code> 后面优先级最高的一项。</li>
  <li><code>a[href="#top"]</code> → <code>(0, 1, 1)</code>：引号里的 <code>#</code> 不是 ID。</li>
</ul>

## Ant Design 为什么用 :where() 包住类名

Ant Design 文档的「样式兼容」一页写道：「Ant Design 的 CSS-in-JS 默认通过 :where 选择器降低 CSS Selector 优先级，以减少用户升级时额外调整自定义样式的成本」。同一页给出了生成结果的对比：默认是 `:where(.css-bAMboO).ant-btn`，在 `StyleProvider` 上设置 `hashPriority="high"` 后变成 `.css-bAMboO.ant-btn`。

{/* csc-check: {"in":":where(.css-bAMboO).ant-btn, .css-bAMboO.ant-btn"} */}

把这两个选择器一起输入 `:where(.css-bAMboO).ant-btn, .css-bAMboO.ant-btn`，得到 `(0, 1, 0)` 和 `(0, 2, 0)`。哈希类名被 `:where()` 包住后不计分，只剩 `.ant-btn` 这一个类。

{/* csc-check: {"in":".my-btn, #root .my-btn"} */}

再看自己写的覆盖样式。`.my-btn` 是 `(0, 1, 0)`，和默认的组件样式打平，这时按出现顺序，后出现的规则生效。关掉降权后组件样式变成 `(0, 2, 0)`，`.my-btn` 就压不住了；文档举的提升写法是 `#root .my-btn`，即 `(1, 1, 0)`。

## 全角冒号让伪类变成了类名

{/* csc-check: {"in":".btn：hover, .btn:hover","fullwidth":true} */}

从中文文档或聊天记录里复制选择器时，冒号偶尔会是全角的「：」（U+FF01–FF5E 区的字符）。CSS 不把全角字符当作 `:`，而是当作名称的一部分，所以 `.btn：hover` 是一个名为「btn：hover」的类，工具算出 `(0, 1, 0)`，并在卡片上提示含有全角字符。改回半角的 `.btn:hover` 才是类加伪类，`(0, 2, 0)`。全角的 `＃`、`．`、`［` 也是同样的情况。

<h2>优先级在层叠中的位置</h2>
<p>CSS Cascade Level 5 §6 先按来源与重要性、上下文、style 属性、层叠层排序，最后才比较优先级和出现顺序。带 <code>!important</code> 的声明或位于更靠后 <code>@layer</code> 的声明，可以胜过元组更大的选择器。</p>

<h2>限制</h2>

{/* csc-check: {"in":".card:not(.featured"} */}

<ul>
  <li>嵌套选择器 <code>&amp;</code> 在这里计 0。实际 CSS 中它等于父规则选择器列表里优先级最高的一项（CSS Nesting §4），单独一个选择器看不出父规则。</li>
  <li>工具只检查选择器结构，不检查伪类名称是否存在。拼错的 <code>:hovr</code> 仍计为一个伪类，浏览器则会丢弃整条规则。</li>
  <li>无法解析的输入（括号或引号未闭合、单独的 <code>#</code> 或 <code>.</code>）会在结果卡片里写明原因与位置，例如 <code>.card:not(.featured</code> 显示「第 10 个字符处的括号缺少对应的「)」」。</li>
  <li>不检查复合选择器内部的顺序。<code>[x]p</code> 计为 <code>(0, 1, 1)</code>，但浏览器不接受写在属性选择器后面的元素选择器。</li>
</ul>

{/* csc-check: {"in":"div　p"} */}

名称之间夹着全角空格（U+3000）或不换行空格（U+00A0）时，工具会报错。输入 `div　p` 显示「第 4 个字符是 U+3000，它在 CSS 里不是空格，也不能用在名称里」。依据是 [CSS Syntax 3 §4.2](https://www.w3.org/TR/css-syntax-3/#non-ascii-ident-code-point)：空白只有空格、制表符和换行，名称字符的列表里也没有这两个字符。浏览器还没有全部照此实现：2026-10-09 实测 Chrome 152 的 `document.querySelector()` 接受 `div　p`，不报错，把它当作一个名为「div　p」的元素选择器，所以它不会选中 `div` 里的 `p`。
