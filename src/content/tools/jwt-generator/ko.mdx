<h2>사용 방법</h2>
<ol>
  <li>서명 <strong>알고리즘</strong>을 선택합니다 (HS256, HS384, HS512).</li>
  <li>필요한 경우 <strong>헤더</strong> JSON을 편집합니다. <code>alg</code> 필드는 알고리즘 변경 시 자동으로 동기화됩니다.</li>
  <li><strong>페이로드</strong> JSON에 클레임을 입력합니다.</li>
  <li><strong>비밀 키</strong>를 입력합니다 (UTF-8 또는 Base64 형식).</li>
  <li>결과 박스에서 생성된 토큰을 복사합니다.</li>
</ol>

<h2>주요 사용 사례</h2>
<ul>
  <li><strong>로컬 개발:</strong> 백엔드 없이 API 엔드포인트나 인증 흐름 테스트용 토큰을 빠르게 생성.</li>
  <li><strong>디버깅:</strong> 헤더와 페이로드 JSON이 JWT에 어떻게 인코딩되는지 확인.</li>
  <li><strong>문서화:</strong> API 문서나 README 파일용 예시 토큰 생성.</li>
  <li><strong>학습:</strong> JWT의 구조와 서명 방식 이해.</li>
</ul>

<h2>예시: 로컬 API 테스트용 토큰</h2>

<p>헤더(기본값 그대로)와 페이로드를 아래처럼 입력하고 UTF-8 시크릿은 <code>{"dev-secret-at-least-32-bytes-long!!"}</code>로 합니다:</p>

<pre><code>{`{
  "alg": "HS256",
  "typ": "JWT"
}`}</code></pre>

<pre><code>{`{
  "sub": "user-42",
  "role": "admin",
  "iat": 1767225600,
  "exp": 1767229200
}`}</code></pre>

<p>도구는 헤더와 페이로드를 입력란의 텍스트 그대로(줄바꿈과 들여쓰기 포함) 인코딩하므로, 압축한 JSON으로 만든 토큰보다 깁니다(서명 앞부분 160자, 압축 시 125자). 그래도 올바른 JWS입니다. PyJWT로 검증:</p>

<pre><code>{`import jwt  # PyJWT 2.10

jwt.decode(token, "dev-secret-at-least-32-bytes-long!!", algorithms=["HS256"],
           options={"verify_exp": False})
# {'sub': 'user-42', 'role': 'admin', 'iat': 1767225600, 'exp': 1767229200}

jwt.decode(token, "dev-secret-at-least-32-bytes-long!!", algorithms=["HS256"])
# jwt.exceptions.ExpiredSignatureError: Signature has expired`}</code></pre>

<p><code>{"iat"}</code> 1767225600은 2026-01-01 00:00:00 UTC이고 <code>{"exp"}</code>는 1시간 뒤이므로, 만료를 확인하는 라이브러리는 지금 이 토큰을 거부합니다. 도구는 <code>{"iat"}</code>, <code>{"exp"}</code>, <code>{"nbf"}</code>를 추가하거나 확인하지 않으니 필요한 타임스탬프는 직접 쓰세요(Unix 초, <a href="https://www.rfc-editor.org/rfc/rfc7519#section-4.1" target="_blank" rel="noopener">RFC 7519 §4.1</a>).</p>

<h2>제한</h2>

<ul>
  <li>HMAC 알고리즘(HS256, HS384, HS512)만 지원합니다. 개인 키가 필요한 RS256, ES256은 지원하지 않습니다.</li>
  <li><a href="https://www.rfc-editor.org/rfc/rfc7518#section-3.2" target="_blank" rel="noopener">RFC 7518 §3.2</a>는 키 길이를 해시 출력 이상으로 요구합니다(HS256은 32바이트, HS384는 48, HS512는 64). 도구는 더 짧은 시크릿도 경고 없이 받아들입니다.</li>
  <li>Base64 모드에서는 시크릿을 먼저 디코딩합니다(표준·URL 안전 알파벳 모두 가능, 패딩 생략 가능). 서버가 키를 Base64로 저장할 때 쓰세요. 그렇지 않으면 서명이 맞지 않습니다.</li>
  <li>운영 환경의 서명 시크릿은 어떤 웹 페이지에도 붙여 넣지 마세요. 테스트 전용 시크릿을 쓰세요.</li>
</ul>
