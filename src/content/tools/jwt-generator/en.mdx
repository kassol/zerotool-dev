<h2>Common Use Cases</h2>
<ul>
  <li><strong>Local development:</strong> Quickly generate tokens for testing API endpoints or auth flows without running a backend.</li>
  <li><strong>Debugging:</strong> Inspect how header and payload JSON is encoded into a JWT.</li>
  <li><strong>Documentation:</strong> Generate example tokens for API docs or README files.</li>
  <li><strong>Learning:</strong> Understand how JWTs are structured and signed.</li>
</ul>

<h2>Example: A Token for a Local API Test</h2>

{/* jwt-check: {"algo":"HS256","fmt":"utf8","secret":"dev-secret-at-least-32-bytes-long!!","header":"{\n  \"alg\": \"HS256\",\n  \"typ\": \"JWT\"\n}","payload":"{\n  \"sub\": \"user-42\",\n  \"role\": \"admin\",\n  \"iat\": 1767225600,\n  \"exp\": 1767229200\n}","inputLen":160} */}

<p>Header (unchanged default) and payload as typed into the tool, with the UTF-8 secret <code>{"dev-secret-at-least-32-bytes-long!!"}</code>:</p>

<pre><code>{`{
  "alg": "HS256",
  "typ": "JWT"
}`}</code></pre>

<pre><code>{`{
  "sub": "user-42",
  "role": "admin",
  "iat": 1767225600,
  "exp": 1767229200
}`}</code></pre>

<p>Generated HS256 token:</p>

<pre><code>{`ewogICJhbGciOiAiSFMyNTYiLAogICJ0eXAiOiAiSldUIgp9.ewogICJzdWIiOiAidXNlci00MiIsCiAgInJvbGUiOiAiYWRtaW4iLAogICJpYXQiOiAxNzY3MjI1NjAwLAogICJleHAiOiAxNzY3MjI5MjAwCn0.Bv_t0OCTXuNeir4XkkMmC0CJs8jGuy1knb6zZGgSRTs`}</code></pre>

<p>The tool encodes the header and payload text exactly as typed, including line breaks and indentation, so this token is longer than one made from minified JSON (160 vs 125 characters before the signature). It is still a valid JWS. Verifying it with PyJWT:</p>

{/* jwt-py: {"expect":"{'sub': 'user-42', 'role': 'admin', 'iat': 1767225600, 'exp': 1767229200}\nExpiredSignatureError: Signature has expired"} */}

<pre><code>{`import jwt  # PyJWT 2.10.1

token = "ewogICJhbGciOiAiSFMyNTYiLAogICJ0eXAiOiAiSldUIgp9.ewogICJzdWIiOiAidXNlci00MiIsCiAgInJvbGUiOiAiYWRtaW4iLAogICJpYXQiOiAxNzY3MjI1NjAwLAogICJleHAiOiAxNzY3MjI5MjAwCn0.Bv_t0OCTXuNeir4XkkMmC0CJs8jGuy1knb6zZGgSRTs"
key = "dev-secret-at-least-32-bytes-long!!"
print(jwt.decode(token, key, algorithms=["HS256"], options={"verify_exp": False}))
try:
    jwt.decode(token, key, algorithms=["HS256"])
except jwt.ExpiredSignatureError as e:
    print("ExpiredSignatureError:", e)`}</code></pre>

<p>Output:</p>

<pre><code>{`{'sub': 'user-42', 'role': 'admin', 'iat': 1767225600, 'exp': 1767229200}
ExpiredSignatureError: Signature has expired`}</code></pre>

<p><code>{"iat"}</code> 1767225600 is 2026-01-01 00:00:00 UTC and <code>{"exp"}</code> is one hour later, so a library that checks expiry rejects the token today. The tool does not add or check <code>{"iat"}</code>, <code>{"exp"}</code> or <code>{"nbf"}</code>; write the timestamps you need yourself (Unix seconds, <a href="https://www.rfc-editor.org/rfc/rfc7519#section-4.1" target="_blank" rel="noopener">RFC 7519 §4.1</a>).</p>

<p>Editing Header alg to HS512 while HS256 remains selected shows an error and clears the previous token.</p>

<h2>Example: The Same Key Text in UTF-8 and Base64 Mode</h2>

<p>A key generated with <code>{"openssl rand -base64 32"}</code> is 44 characters of Base64 text that stand for 32 random bytes. This demo key was made up for the page:</p>

<pre><code>{`q83vEjRWeJCrze8SNFZ4kKvN7xI0VniQq83vEjRWeJA=`}</code></pre>

<p>With compact JSON in both fields:</p>

<pre><code>{`{"alg":"HS256","typ":"JWT"}`}</code></pre>

<pre><code>{`{"sub":"user-42","iat":1767225600}`}</code></pre>

{/* jwt-check: {"algo":"HS256","fmt":"base64","secret":"q83vEjRWeJCrze8SNFZ4kKvN7xI0VniQq83vEjRWeJA=","header":"{\"alg\":\"HS256\",\"typ\":\"JWT\"}","payload":"{\"sub\":\"user-42\",\"iat\":1767225600}","inputLen":83} */}

<p>Base64 mode signs with the 32 decoded bytes:</p>

<pre><code>{`eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c2VyLTQyIiwiaWF0IjoxNzY3MjI1NjAwfQ.ObzNwrIiJoDqNA5f-RGsGcZB1_yg_YfeziEmaFgph6Q`}</code></pre>

{/* jwt-check: {"algo":"HS256","fmt":"utf8","secret":"q83vEjRWeJCrze8SNFZ4kKvN7xI0VniQq83vEjRWeJA=","header":"{\"alg\":\"HS256\",\"typ\":\"JWT\"}","payload":"{\"sub\":\"user-42\",\"iat\":1767225600}"} */}

<p>UTF-8 mode signs with the 44 bytes of the text itself, so only the signature changes:</p>

<pre><code>{`eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c2VyLTQyIiwiaWF0IjoxNzY3MjI1NjAwfQ.JQZj6nLnAjm412MFmVpVqGVWBXx3MVzFUWA6IvPHjVw`}</code></pre>

<p>Neither mode shows a warning, because both keys are at least 32 bytes. A server that decodes the key before verifying accepts only the first token:</p>

{/* jwt-py: {"expect":"{'sub': 'user-42', 'iat': 1767225600}\nInvalidSignatureError: Signature verification failed"} */}

<pre><code>{`import base64
import jwt  # PyJWT 2.10.1

key = base64.b64decode("q83vEjRWeJCrze8SNFZ4kKvN7xI0VniQq83vEjRWeJA=")
base64_mode = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c2VyLTQyIiwiaWF0IjoxNzY3MjI1NjAwfQ.ObzNwrIiJoDqNA5f-RGsGcZB1_yg_YfeziEmaFgph6Q"

    jwt.decode(utf8_mode, key, algorithms=["HS256"])

    print("InvalidSignatureError:", e)`}</code></pre>

<p>Output:</p>

<pre><code>{`{'sub': 'user-42', 'iat': 1767225600}
InvalidSignatureError: Signature verification failed`}</code></pre>

<h2>Choosing a Key</h2>

<p>An HMAC-signed JWT is only as strong as its secret. Anyone who holds one token can try candidate secrets offline until a signature matches; hashcat has a mode for exactly this (mode 16500, "JWT (JSON Web Token)"). <a href="https://www.rfc-editor.org/rfc/rfc8725#section-3.5" target="_blank" rel="noopener">RFC 8725 §3.5</a>, the JWT best-practice document, warns that human-memorable passwords must not be used as HMAC keys. Generate random bytes instead and paste them in Base64 mode:</p>

<pre><code>{`openssl rand -base64 32   # HS256
openssl rand -base64 64   # HS512`}</code></pre>

<p>Select <strong>Base64</strong> beside the Secret label so the tool signs with the decoded 32 or 64 bytes, the same bytes your server should load. If the server reads the key as a plain string instead, keep UTF-8 mode and paste the same text.</p>

<h2>Limits</h2>

<ul>
  <li>Only HMAC algorithms (HS256, HS384, HS512). RS256 and ES256 tokens need a private key and are not supported.</li>
  <li><a href="https://www.rfc-editor.org/rfc/rfc7518#section-3.2" target="_blank" rel="noopener">RFC 7518 §3.2</a> requires a key at least as long as the hash output: 32 bytes for HS256, 48 for HS384, 64 for HS512. The tool still signs with a shorter secret but shows a warning with the byte count; the default sample secret <code>your-256-bit-secret</code> is only 19 bytes and triggers it.</li>
  <li>In Base64 mode the secret is decoded first (standard or URL-safe alphabet, padding optional). Use it when the server stores the key as Base64; otherwise the signature will not match.</li>
  <li>The Payload must be a JSON object. An array, string, number or <code>{"null"}</code> shows an error instead of a token, because <a href="https://www.rfc-editor.org/rfc/rfc7519#section-7.2" target="_blank" rel="noopener">RFC 7519 §7.2</a> requires the claims to be a JSON object and libraries such as PyJWT reject anything else.</li>
  <li>Header and Payload lose only their leading and trailing whitespace. The secret is used exactly as typed, so a trailing space or line break changes the signature.</li>
  <li>Half of an emoji (an unpaired UTF-16 surrogate) in any field is rejected with its position, because UTF-8 cannot encode it.</li>
  <li>Do not paste production signing secrets into any web page. Use a dedicated test secret.</li>
</ul>
