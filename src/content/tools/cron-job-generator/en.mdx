<h2>Examples</h2>

The descriptions and run times below are the tool's own output, computed from 2026-10-01 10:00 UTC with the UTC switch on. To explain an expression you already have, paste it into the box above or into the [Cron Expression Parser](/tools/cron-parser/).

{/* cjg-check: {"from":"2026-10-01T10:00:00Z","cases":[{"expr":"0 9 * * 1-5","runs":3},{"expr":"0 0 1,15 * 1","runs":4},{"expr":"0 0 \u002a/2 * 1","runs":3}]} */}

| Expression | Description | Next runs |
|---|---|---|
| `0 9 * * 1-5` | `At 9:00, on Monday through Friday` | `2026-10-02 09:00 UTC`, `2026-10-05 09:00 UTC`, `2026-10-06 09:00 UTC` |
| `0 0 1,15 * 1` | `At midnight, on day 1, 15 of the month or on Monday` | `2026-10-05 00:00 UTC`, `2026-10-12 00:00 UTC`, `2026-10-15 00:00 UTC`, `2026-10-19 00:00 UTC` |
| `0 0 */2 * 1` | `At midnight, on every 2 days of the month and on Monday` | `2026-10-05 00:00 UTC`, `2026-10-19 00:00 UTC`, `2026-11-09 00:00 UTC` |

The second and third rows show the rule that surprises most people. When both the day-of-month and the weekday field are restricted, cron runs the job on days that match **either** field, so `0 0 1,15 * 1` fires on the 1st, the 15th and every Monday. But a field that starts with `*`, including a step such as `*/2`, does not count as a restriction, so in the third row both fields must match: only Mondays that fall on an odd date (`*/2` in the day field is 1, 3, 5 … 31). The tool follows cronie, the cron on most Linux distributions, which marks a day field as unrestricted when its first character is `*` (crontab(5) describes the either-field rule).

<h2>Time Zones</h2>

A cron expression has no time zone of its own; the scheduler that reads it supplies one. System cron uses the server's local time (cronie also reads a `CRON_TZ` variable in the crontab). GitHub Actions schedules run in UTC unless the schedule sets a `timezone` (an IANA name such as `America/New_York`). A Kubernetes CronJob uses the time zone of the kube-controller-manager unless `.spec.timeZone` is set. Pick **UTC** in the tool when the target evaluates in UTC, and **Local** when it uses the same zone as your computer. With UTC selected, `0 9 * * 1-5` lists 09:00 UTC on weekdays; with Local selected in Tokyo it lists 09:00 Japan time.

<h2>Limitations</h2>

{/* cjg-check: {"cases":[{"expr":"0 0 L * *","error":true},{"expr":"75 * * * *","error":true},{"expr":"\u002a/0 * * * *","error":true}]} */}

- Five fields only: no seconds field and no Quartz or Spring extensions (`?`, `L`, `W`, `#`). An expression typed with them names the field and the value, for example `Day: "L" is not valid. Use numbers from 1 to 31, *, -, / and commas.`
- Numbers must be whole decimal numbers: `1.5`, `5abc` and `1#2` are rejected. A step needs `*` or a range in front of it, so `5/10` is rejected, as cronie rejects it.
- Weekdays are 0–7 and the names `sun`–`sat`; 0 and 7 are both Sunday, as in cronie's crontab(5). A typed range that ends in 7, such as `5-7`, is shown with the weekday buttons (Friday, Saturday, Sunday), because the Range boxes stop at 6; the expression box keeps what you typed.
- Values typed into the Minute box are checked. `75` shows `Minute: "75" is not valid. Use numbers from 0 to 59, *, -, / and commas.` and the description and run list stay empty and Copy is disabled until it is fixed.
- The Step, From and To boxes give the value you type. A step of 0 shows `Minute: "*/0" is not valid. Use numbers from 0 to 59, *, -, / and commas.`, and a range from 17 to 9 is reported in the same way rather than swapped. A step larger than the field is valid cron (cronie prints a warning but accepts it) and is kept: `*/75` in Minute runs once an hour, at :00.
- A schedule that never occurs, such as `0 0 30 2 *` (30 February), shows an empty run list.
- The description is in English on every language version of this page.

<h2>Cron Expression Field Reference</h2>

| Field | Position | Allowed Values | Special Chars |
|-------|----------|----------------|---------------|
| Minute | 1st | 0–59 | `*` `/` `-` `,` |
| Hour | 2nd | 0–23 | `*` `/` `-` `,` |
| Day of Month | 3rd | 1–31 | `*` `/` `-` `,` |
| Month | 4th | 1–12 | `*` `/` `-` `,` |
| Day of Week | 5th | 0–7 (Sun = 0 or 7) | `*` `/` `-` `,` |
