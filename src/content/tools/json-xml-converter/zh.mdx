<h2>示例</h2>

<h3>中文键名</h3>
<p>XML 1.0 的名称可以使用中文等多数文字，键名原样作为元素名，文本中的 <code>&lt;</code> 与 <code>&amp;</code> 会被转义：</p>

{/* jx-to-xml */}
```json
{"订单": {"编号": "A-1001", "收货人": "张三", "备注": "易碎 & 勿压"}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <订单>
    <编号>A-1001</编号>
    <收货人>张三</收货人>
    <备注>易碎 &amp; 勿压</备注>
  </订单>
</root>
```

<h3>数组、null 与空对象</h3>
<p>数组按键名重复生成元素，顶层数组使用 <code>item</code>；<code>null</code> 和 <code>{'{}'}</code> 都生成空元素：</p>

{/* jx-to-xml */}
```json
{"商品": [{"名称": "键盘", "数量": 2}, {"名称": "鼠标", "数量": 1}], "优惠券": null, "扩展": {}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <商品>
    <名称>键盘</名称>
    <数量>2</数量>
  </商品>
  <商品>
    <名称>鼠标</名称>
    <数量>1</数量>
  </商品>
  <优惠券></优惠券>
  <扩展></扩展>
</root>
```

<h3>JSON 转 XML 何时停止</h3>
<p>工具不会为了让 XML 成立而改键名或丢数据，而是不输出 XML，并显示第一个无法转换的位置：</p>
<ul>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"2026年\": \"Q1\"}"} */}
    <code>{'{"2026年": "Q1"}'}</code> 得到 <code>{'无法转换为 XML: $["2026年"]：该名称不能用作 XML 元素名。'}</code>
    XML 名称不能以数字开头，也不能包含空格；含 <code>:</code> 的名称同样拒绝，因为前缀需要命名空间声明，而这种映射写不出声明。
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"坐标\": [[116.4, 39.9], [121.5, 31.2]]}"} */}
    <code>{'{"坐标": [[116.4, 39.9], [121.5, 31.2]]}'}</code> 得到 <code>{'无法转换为 XML: $["坐标"][0]：空数组或嵌套数组无法用重复 XML 元素表示。'}</code>
    重复的元素无法标出内层数组在哪里结束。
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"标签\": []}"} */}
    <code>{'{"标签": []}'}</code> 得到 <code>{'无法转换为 XML: $["标签"]：空数组或嵌套数组无法用重复 XML 元素表示。'}</code>
    空数组不会留下任何元素。
  </li>
</ul>

<h3>XML 转 JSON</h3>

{/* jx-to-json */}
```xml
<响应>
  <状态>成功</状态>
  <记录>
    <姓名>李四</姓名>
    <金额>88.50</金额>
  </记录>
  <记录>
    <姓名>王五</姓名>
    <金额>12.00</金额>
  </记录>
</响应>
```

<p>得到（开启格式化输出）：</p>

```json
{
  "响应": {
    "状态": "成功",
    "记录": [
      {
        "姓名": "李四",
        "金额": "88.50"
      },
      {
        "姓名": "王五",
        "金额": "12.00"
      }
    ]
  }
}
```

<p>两个 <code>记录</code> 合并为数组；<code>88.50</code> 是字符串，末尾的 0 保留。</p>

<h3>XML 转 JSON 何时停止</h3>
<ul>
  <li>
    {/* jx-error: {"dir":"xml","input":"<响应><记录 id=\"7\"><姓名>李四</姓名></记录></响应>"} */}
    <code>{'<响应><记录 id="7">…</记录></响应>'}</code> 得到 <code>{'无法转换为 JSON: /响应/记录[1]/@id：当前 JSON 映射无法表示 XML 属性。'}</code>
    把属性值改写成子元素后再转换。
  </li>
  <li>
    {/* jx-error: {"dir":"xml","input":"<说明>请在 <b>3 日内</b> 付款</说明>"} */}
    <code>{'<说明>请在 <b>3 日内</b> 付款</说明>'}</code> 得到 <code>{'无法转换为 JSON: /说明：当前 JSON 映射无法表示文本与子元素混排。'}</code>
  </li>
</ul>
<p>路径中的序号按同名元素从 1 开始计数，<code>记录[2]</code> 是父元素下的第二个 <code>记录</code>。</p>

<h2>限制</h2>
<ul>
  <li><strong>XML 转 JSON 的值都是字符串。</strong>XML 没有数字和布尔类型，<code>{'<数量>2</数量>'}</code> 变成 <code>"2"</code>。空元素变成 <code>""</code>，所以 JSON 的 <code>null</code> 和 <code>{'{}'}</code> 往返一次后都是 <code>""</code>。</li>
  <li><strong>一个子元素和多个子元素的结构不同。</strong>只有一个 <code>记录</code> 时得到对象，两个以上得到数组，读取 JSON 的代码要两种都处理。</li>
  <li><strong>叶子元素的文本原样保留</strong>，包括首尾的空格和换行；只有子元素之间的空白会被忽略。注释和处理指令跳过。</li>
  <li><strong>属性、命名空间声明和混排文本会让转换停止</strong>（见上文），工具不提供 <code>@id</code> 这类属性映射。</li>
  <li><strong>XML 语法错误的提示来自浏览器的解析器</strong>，Chrome、Firefox、Safari 的措辞不同。只想缩进或压缩 XML 时，用 <a href="/zh/tools/xml-formatter/">XML 格式化工具</a>。</li>
</ul>

<h2>JSON 与 XML</h2>
<p>
  <strong>JSON</strong> 是 REST API 和 Web 服务的常用数据格式，简洁、可读、各语言原生支持。
  <strong>XML</strong> 在企业系统、SOAP API、配置文件（Maven、Spring）和文档格式（SVG、XHTML、RSS）中仍被广泛使用。
  对接两种格式的系统时，可以用本工具先看一份数据在另一种格式里的样子，并找出无法对应的结构。
</p>
