<h2>使い方</h2>
<ol>
  <li><strong>JSON → XML</strong>：左のパネルに JSON を貼り付けて <strong>JSON → XML</strong> をクリックします。入力を止めて少し待つと自動でも変換されます。</li>
  <li><strong>XML → JSON</strong>：右のパネルに XML を貼り付けて <strong>XML → JSON</strong> をクリックします。</li>
  <li><strong>ルート要素</strong> 欄で、JSON → XML のときのルート要素名を設定します。</li>
  <li><strong>整形出力</strong> で、出力をインデントするかどうかを切り替えます。</li>
  <li>パネル内で <strong>Ctrl+Enter</strong>（Mac は <strong>Cmd+Enter</strong>）を押すと、そのパネルの内容を変換します。</li>
</ol>
<p>片方のパネルを編集すると、もう片方は空になり、新しい変換が成功するまで<strong>コピー</strong>ボタンは使えません。変換に失敗したときも空のままなので、古い入力の結果をコピーすることはありません。</p>

<h2>変換例</h2>

<h3>日本語のキー名</h3>
<p>XML 1.0 の名前には漢字・ひらがな・カタカナも使えるため、キー名はそのまま要素名になります。テキスト中の <code>&lt;</code> と <code>&amp;</code> はエスケープされます。</p>

{/* jx-to-xml */}
```json
{"会員": {"氏名": "山田太郎", "フリガナ": "ヤマダタロウ", "メモ": "A&B 社 <担当>"}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <会員>
    <氏名>山田太郎</氏名>
    <フリガナ>ヤマダタロウ</フリガナ>
    <メモ>A&amp;B 社 &lt;担当&gt;</メモ>
  </会員>
</root>
```

<h3>配列・null・空オブジェクト</h3>
<p>配列はキー名の要素を繰り返し、トップレベルの配列は <code>item</code> を使います。<code>null</code> と <code>{'{}'}</code> はどちらも空要素になります。</p>

{/* jx-to-xml */}
```json
[{"品番": "A-1", "在庫": 12}, {"品番": "B-7", "在庫": null}]
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <item>
    <品番>A-1</品番>
    <在庫>12</在庫>
  </item>
  <item>
    <品番>B-7</品番>
    <在庫></在庫>
  </item>
</root>
```

<h3>JSON → XML が止まる場合</h3>
<p>XML に合わせるためにキー名を書き換えたりデータを捨てたりはせず、XML を出力しないまま、最初に変換できない位置を表示します。</p>
<ul>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"郵便 番号\": \"100-0001\"}"} */}
    <code>{'{"郵便 番号": "100-0001"}'}</code> は <code>{'XMLに変換できません: $["郵便 番号"]：この名前はXML要素名に使用できません。'}</code>
    XML 名は空白を含められず、数字で始めることもできません。<code>:</code> を含む名前も、接頭辞に必要な名前空間宣言を書けないため止まります。IME で入った全角スペース（U+3000）も名前に使えない文字です。
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"座標\": [[139.76, 35.68], [135.50, 34.69]]}"} */}
    <code>{'{"座標": [[139.76, 35.68], [135.50, 34.69]]}'}</code> は <code>{'XMLに変換できません: $["座標"][0]：空配列と入れ子の配列は繰り返しXML要素で表現できません。'}</code>
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"タグ\": []}"} */}
    <code>{'{"タグ": []}'}</code> は <code>{'XMLに変換できません: $["タグ"]：空配列と入れ子の配列は繰り返しXML要素で表現できません。'}</code>
  </li>
</ul>

<h3>XML → JSON</h3>

{/* jx-to-json */}
```xml
<注文>
  <番号>20261003-01</番号>
  <明細>
    <商品>ノート</商品>
    <数量>3</数量>
  </明細>
  <明細>
    <商品>ボールペン</商品>
    <数量>10</数量>
  </明細>
</注文>
```

<p>整形出力をオンにすると次のようになります。</p>

```json
{
  "注文": {
    "番号": "20261003-01",
    "明細": [
      {
        "商品": "ノート",
        "数量": "3"
      },
      {
        "商品": "ボールペン",
        "数量": "10"
      }
    ]
  }
}
```

<h3>XML → JSON が止まる場合</h3>
<ul>
  <li>
    {/* jx-error: {"dir":"xml","input":"<注文><明細 行=\"1\"><商品>ノート</商品></明細></注文>"} */}
    <code>{'<注文><明細 行="1">…</明細></注文>'}</code> は <code>{'JSONに変換できません: /注文/明細[1]/@行：このJSON変換規則ではXML属性を表現できません。'}</code>
  </li>
  <li>
    {/* jx-error: {"dir":"xml","input":"<備考>お届けは<b>翌日</b>以降です</備考>"} */}
    <code>{'<備考>お届けは<b>翌日</b>以降です</備考>'}</code> は <code>{'JSONに変換できません: /備考：このJSON変換規則ではテキストと子要素の混在を表現できません。'}</code>
  </li>
</ul>
<p>位置の番号は同じ名前の要素を 1 から数えたもので、<code>明細[2]</code> は親要素の下の 2 つ目の <code>明細</code> です。</p>

<h2>制限</h2>
<ul>
  <li><strong>XML → JSON の値はすべて文字列です。</strong>XML には数値や真偽値の型がないため、<code>{'<数量>3</数量>'}</code> は <code>"3"</code> になります。空要素は <code>""</code> になるので、JSON の <code>null</code> と <code>{'{}'}</code> は往復すると <code>""</code> になります。</li>
  <li><strong>子要素が 1 つか複数かで形が変わります。</strong><code>明細</code> が 1 つならオブジェクト、2 つ以上なら配列です。JSON を読むコードは両方を扱う必要があります。</li>
  <li><strong>子要素のない要素のテキストはそのまま残ります。</strong>前後の空白や改行も含みます。無視するのは子要素の間の空白だけです。コメントと処理命令は読み飛ばします。</li>
  <li><strong>属性・名前空間宣言・混在テキストは変換を止めます</strong>（上記参照）。<code>@id</code> のような属性用キーへの変換はありません。</li>
  <li><strong>XML の構文エラーはブラウザのパーサーのメッセージ</strong>で、Chrome・Firefox・Safari で文言が異なります。変換せずに XML を整形・圧縮したい場合は <a href="/ja/tools/xml-formatter/">XML フォーマッター</a> を使ってください。</li>
</ul>

<h2>JSONとXML</h2>
<p>
  <strong>JSON</strong>はREST APIとWebサービスで広く使われるデータ形式で、コンパクトで読みやすく、あらゆる言語で扱えます。
  <strong>XML</strong>はエンタープライズシステム、SOAP API、設定ファイル（Maven・Spring）、ドキュメント形式（SVG・XHTML・RSS）で今も広く使われています。
  形式の違うシステムをつなぐとき、このツールで同じデータがもう一方の形式でどうなるか、どの構造が対応しないかを確認できます。
</p>
