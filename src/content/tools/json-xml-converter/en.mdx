<h2>How to Use</h2>
<ol>
  <li>To convert <strong>JSON → XML</strong>: paste your JSON into the left panel and click <strong>JSON → XML</strong>, or type and conversion runs automatically.</li>
  <li>To convert <strong>XML → JSON</strong>: paste your XML into the right panel and click <strong>XML → JSON</strong>.</li>
  <li>Customize the <strong>Root element</strong> name used when wrapping JSON output in XML.</li>
  <li>Toggle <strong>Pretty print</strong> to control whether output is indented or compact.</li>
  <li>Use <strong>Ctrl+Enter</strong> (or <strong>Cmd+Enter</strong> on Mac) as a shortcut from whichever panel you're editing.</li>
</ol>

<h2>Worked Examples</h2>

<h3>Simple object</h3>
<p>Input JSON:</p>

```json
{"name": "Alice", "age": 30, "active": true}
```

<p>Output XML (root element: <code>root</code>):</p>

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <name>Alice</name>
  <age>30</age>
  <active>true</active>
</root>
```

<h3>Nested objects</h3>
<p>Input JSON:</p>

```json
{"server": {"host": "localhost", "port": 8080}}
```

<p>Output XML:</p>

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <server>
    <host>localhost</host>
    <port>8080</port>
  </server>
</root>
```

<h3>Arrays</h3>
<p>JSON arrays produce repeated XML elements with the tag name <code>item</code> at the top level, or the parent key name for nested arrays:</p>

```json
{"tags": ["js", "xml", "api"]}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <tags>js</tags>
  <tags>xml</tags>
  <tags>api</tags>
</root>
```

<h3>Arrays of objects and null</h3>
<p>Each object in an array becomes one element named after the key, and <code>null</code> becomes an empty element:</p>

```json
{"order":{"id":1001,"items":[{"sku":"A-1","qty":2},{"sku":"B-7","qty":1}],"note":null}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <order>
    <id>1001</id>
    <items>
      <sku>A-1</sku>
      <qty>2</qty>
    </items>
    <items>
      <sku>B-7</sku>
      <qty>1</qty>
    </items>
    <note></note>
  </order>
</root>
```

<p>
  Keys that are not valid XML names are rewritten: characters other than ASCII letters, digits, <code>{'_'}</code>, <code>-</code> and
  <code>.</code> become <code>{'_'}</code>, and a name that would start with a digit, <code>-</code> or <code>.</code> gets a leading
  <code>{'_'}</code>, because XML names must start with a letter or underscore. <code>{'{"2026": "q", "first name": "Ann", "a&b": "x<y"}'}</code> becomes
  <code>{'<_2026>q</_2026>'}</code>, <code>{'<first_name>Ann</first_name>'}</code> and <code>{'<a_b>x&lt;y</a_b>'}</code>. The root element name
  is cleaned the same way.
</p>

<h3>XML to JSON</h3>
<p>Pasting this XML into the right panel:</p>

```xml
<catalog>
  <book id="bk101">
    <author>Gambardella, Matthew</author>
    <price>44.95</price>
  </book>
  <book id="bk102">
    <author>Ralls, Kim</author>
    <price>5.95</price>
  </book>
</catalog>
```

<p>gives <code>{'{"catalog": {"book": [{"author": "Gambardella, Matthew", "price": "44.95"}, {"author": "Ralls, Kim", "price": "5.95"}]}}'}</code> (indented in the tool).
The two <code>book</code> elements form an array, the <code>id</code> attributes are gone, and <code>44.95</code> is a string.</p>

<h2>Limits</h2>
<ul>
  <li><strong>XML → JSON values are always strings.</strong> XML has no number or boolean type, so <code>{'<qty>2</qty>'}</code> becomes <code>"2"</code>. Empty elements such as <code>{'<b/>'}</code> become <code>""</code>.</li>
  <li><strong>One child or many changes the shape.</strong> <code>{'<order><item>A</item></order>'}</code> gives <code>{'{"item": "A"}'}</code>, but two <code>item</code> elements give an array. Code that reads the JSON must handle both.</li>
  <li><strong>Attributes are dropped</strong> and <strong>mixed content loses its text</strong>: <code>{'<p>Hello <b>world</b>!</p>'}</code> gives <code>{'{"p": {"b": "world"}}'}</code>. Namespace prefixes stay in the keys (<code>"x:v"</code>).</li>
  <li><strong>Nested and empty arrays do not survive.</strong> <code>{'{"m": [[1, 2], [3]]}'}</code> flattens to three <code>{'<m>'}</code> elements, and an empty array or object writes no child element, so a round trip does not give back the original JSON.</li>
  <li><strong>Non-ASCII keys are replaced.</strong> A key such as <code>名前</code> becomes <code>{'__'}</code>, although XML allows such names. Rename keys in the JSON first if the element names matter.</li>
  <li><strong>XML errors come from the browser's parser</strong>, for example <code>error on line 1 at column 20: Premature end of data in tag a</code> in Chrome. To indent or minify XML without converting it, use the <a href="/tools/xml-formatter/">XML formatter</a>.</li>
</ul>

<h2>JSON vs XML</h2>
<p>
  <strong>JSON</strong> (JavaScript Object Notation) is the standard data format for REST APIs and web services — compact, human-readable, and natively supported in every language.
  <strong>XML</strong> (eXtensible Markup Language) remains widely used in enterprise systems, SOAP APIs, configuration files (Maven, Spring), and document formats (SVG, XHTML, RSS).
  This tool helps you bridge the two formats when integrating systems that speak different data languages.
</p>
