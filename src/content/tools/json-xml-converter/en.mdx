<h2>How to Use</h2>
<ol>
  <li>To convert <strong>JSON → XML</strong>: paste your JSON into the left panel and click <strong>JSON → XML</strong>, or stop typing for a moment and the conversion runs.</li>
  <li>To convert <strong>XML → JSON</strong>: paste your XML into the right panel and click <strong>XML → JSON</strong>.</li>
  <li>Set the <strong>Root element</strong> name used when wrapping JSON output in XML.</li>
  <li>Toggle <strong>Pretty print</strong> to control whether output is indented or compact.</li>
  <li>Press <strong>Ctrl+Enter</strong> (<strong>Cmd+Enter</strong> on Mac) in a panel to convert that panel.</li>
</ol>
<p>
  While you edit one panel, the other panel is emptied and its <strong>Copy</strong> button is disabled until the new conversion
  succeeds. A failed conversion leaves the other panel empty, so you never copy a result that belongs to older input.
</p>

<h2>Worked Examples</h2>

<h3>Simple object</h3>
<p>Input JSON:</p>

{/* jx-to-xml */}
```json
{"name": "Alice", "age": 30, "active": true}
```

<p>Output XML (root element: <code>root</code>):</p>

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <name>Alice</name>
  <age>30</age>
  <active>true</active>
</root>
```

<h3>Nested objects</h3>

{/* jx-to-xml */}
```json
{"server": {"host": "localhost", "port": 8080}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <server>
    <host>localhost</host>
    <port>8080</port>
  </server>
</root>
```

<h3>Arrays, null and empty objects</h3>
<p>An array repeats the element of its key. A top-level array uses <code>item</code>. <code>null</code> and <code>{'{}'}</code> both become an empty element:</p>

{/* jx-to-xml */}
```json
{"order":{"id":1001,"items":[{"sku":"A-1","qty":2},{"sku":"B-7","qty":1}],"note":null,"meta":{}}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <order>
    <id>1001</id>
    <items>
      <sku>A-1</sku>
      <qty>2</qty>
    </items>
    <items>
      <sku>B-7</sku>
      <qty>1</qty>
    </items>
    <note></note>
    <meta></meta>
  </order>
</root>
```

<h3>Element names are kept as written</h3>
<p>
  XML 1.0 allows letters from most scripts in names, so keys such as <code>名前</code> or <code>straße</code> become elements with the same
  name. Text is escaped (<code>&lt;</code> and <code>&amp;</code>):
</p>

{/* jx-to-xml */}
```json
{"名前": "Ann", "straße": "Hauptstr. 1", "a-b.c": "x<y & z"}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <名前>Ann</名前>
  <straße>Hauptstr. 1</straße>
  <a-b.c>x&lt;y &amp; z</a-b.c>
</root>
```

<p>A single value is written as the root text, with no extra spaces or line breaks inside the root element:</p>

{/* jx-to-xml */}
```json
"hello"
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>hello</root>
```

<h3>When JSON → XML stops</h3>
<p>
  The tool does not rename keys or drop data to make the XML fit. It writes nothing and shows the path of the first value it cannot
  map:
</p>
<ul>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"2026\": \"q\", \"first name\": \"Ann\"}"} */}
    <code>{'{"2026": "q", "first name": "Ann"}'}</code> gives <code>{'Cannot convert to XML: $["2026"]: this name cannot be used as an XML element name.'}</code>
    XML names cannot start with a digit or contain spaces. Names with <code>:</code> are refused as well, because a prefix needs a
    namespace declaration that this mapping cannot write.
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"m\": [[1, 2], [3]]}"} */}
    <code>{'{"m": [[1, 2], [3]]}'}</code> gives <code>{'Cannot convert to XML: $["m"][0]: empty or nested arrays cannot be represented by repeated XML elements.'}</code>
    Repeated elements cannot show where one inner array ends and the next begins.
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"tags\": []}"} */}
    <code>{'{"tags": []}'}</code> gives <code>{'Cannot convert to XML: $["tags"]: empty or nested arrays cannot be represented by repeated XML elements.'}</code>
    An empty array would leave no element at all.
  </li>
</ul>
<p>Strings with characters that XML 1.0 forbids, such as U+0000, stop the conversion the same way.</p>

<h3>XML to JSON</h3>
<p>Pasting this XML into the right panel:</p>

{/* jx-to-json */}
```xml
<catalog>
  <book>
    <id>bk101</id>
    <author>Gambardella, Matthew</author>
    <price>44.95</price>
  </book>
  <book>
    <id>bk102</id>
    <author>Ralls, Kim</author>
    <price>5.95</price>
  </book>
</catalog>
```

<p>gives (pretty print on):</p>

```json
{
  "catalog": {
    "book": [
      {
        "id": "bk101",
        "author": "Gambardella, Matthew",
        "price": "44.95"
      },
      {
        "id": "bk102",
        "author": "Ralls, Kim",
        "price": "5.95"
      }
    ]
  }
}
```

<p>The two <code>book</code> elements form an array, and <code>44.95</code> is a string.</p>

<h3>When XML → JSON stops</h3>
<ul>
  <li>
    {/* jx-error: {"dir":"xml","input":"<catalog><book id=\"bk101\"><author>Gambardella, Matthew</author></book></catalog>"} */}
    <code>{'<catalog><book id="bk101">…</book></catalog>'}</code> gives <code>{'Cannot convert to JSON: /catalog/book[1]/@id: XML attributes cannot be represented by this JSON mapping.'}</code>
    Move the value into a child element, as in the example above.
  </li>
  <li>
    {/* jx-error: {"dir":"xml","input":"<p>Hello <b>world</b>!</p>"} */}
    <code>{'<p>Hello <b>world</b>!</p>'}</code> gives <code>{'Cannot convert to JSON: /p: mixed text and child elements cannot be represented by this JSON mapping.'}</code>
    Text next to child elements has no place in a JSON object.
  </li>
</ul>
<p>
  The path counts elements with the same name from 1, so <code>book[2]</code> is the second <code>book</code> under its parent.
</p>

<h2>Limits</h2>
<ul>
  <li><strong>XML → JSON values are always strings.</strong> XML has no number or boolean type, so <code>{'<qty>2</qty>'}</code> becomes <code>"2"</code>. Empty elements such as <code>{'<b/>'}</code> become <code>""</code>, which means JSON <code>null</code> and <code>{'{}'}</code> come back as <code>""</code> after a round trip.</li>
  <li><strong>One child or many changes the shape.</strong> <code>{'<order><item>A</item></order>'}</code> gives <code>{'{"item": "A"}'}</code>, but two <code>item</code> elements give an array. Code that reads the JSON must handle both.</li>
  <li><strong>Text in leaf elements is kept exactly</strong>, including spaces and line breaks around it. Only whitespace between child elements is ignored. Comments and processing instructions are skipped.</li>
  <li><strong>Attributes, namespace declarations and mixed content stop the conversion</strong> (see above). This tool does not offer an attribute mapping such as <code>@id</code> keys.</li>
  <li><strong>XML syntax errors come from the browser's parser</strong>, so the wording differs between Chrome, Firefox and Safari. To indent or minify XML without converting it, use the <a href="/tools/xml-formatter/">XML formatter</a>.</li>
</ul>

<h2>JSON vs XML</h2>
<p>
  <strong>JSON</strong> (JavaScript Object Notation) is the standard data format for REST APIs and web services — compact, human-readable, and natively supported in every language.
  <strong>XML</strong> (eXtensible Markup Language) remains widely used in enterprise systems, SOAP APIs, configuration files (Maven, Spring), and document formats (SVG, XHTML, RSS).
  This tool helps you bridge the two formats when integrating systems that speak different data languages.
</p>
