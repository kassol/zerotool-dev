<h2>변환 예시</h2>

<h3>한글 키 이름</h3>
<p>XML 1.0 이름에는 한글도 쓸 수 있으므로 키 이름이 그대로 요소 이름이 됩니다. 텍스트 안의 <code>&lt;</code>와 <code>&amp;</code>는 이스케이프됩니다.</p>

{/* jx-to-xml */}
```json
{"주문": {"주문번호": "K-2026-0042", "받는분": "홍길동", "요청사항": "문 앞 & 경비실"}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <주문>
    <주문번호>K-2026-0042</주문번호>
    <받는분>홍길동</받는분>
    <요청사항>문 앞 &amp; 경비실</요청사항>
  </주문>
</root>
```

<h3>배열, null, 빈 객체</h3>
<p>배열은 키 이름의 요소를 반복하고, 최상위 배열은 <code>item</code>을 씁니다. <code>null</code>과 <code>{'{}'}</code>는 모두 빈 요소가 됩니다.</p>

{/* jx-to-xml */}
```json
{"상품": [{"이름": "키보드", "수량": 1}, {"이름": "마우스", "수량": 2}], "쿠폰": null, "옵션": {}}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <상품>
    <이름>키보드</이름>
    <수량>1</수량>
  </상품>
  <상품>
    <이름>마우스</이름>
    <수량>2</수량>
  </상품>
  <쿠폰></쿠폰>
  <옵션></옵션>
</root>
```

<h3>JSON → XML이 멈추는 경우</h3>
<p>XML에 맞추려고 키 이름을 바꾸거나 데이터를 버리지 않습니다. XML을 출력하지 않고 처음으로 변환할 수 없는 위치를 보여 줍니다.</p>
<ul>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"우편 번호\": \"04524\"}"} */}
    <code>{'{"우편 번호": "04524"}'}</code>은 <code>{'XML로 변환할 수 없습니다: $["우편 번호"]: 이 이름은 XML 요소 이름으로 사용할 수 없습니다.'}</code>
    XML 이름에는 공백을 넣을 수 없고 숫자로 시작할 수도 없습니다. <code>:</code>가 들어간 이름도 접두사에 필요한 네임스페이스 선언을 쓸 수 없어 멈춥니다.
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"좌표\": [[126.98, 37.57], [129.08, 35.18]]}"} */}
    <code>{'{"좌표": [[126.98, 37.57], [129.08, 35.18]]}'}</code>은 <code>{'XML로 변환할 수 없습니다: $["좌표"][0]: 빈 배열과 중첩 배열은 반복 XML 요소로 표현할 수 없습니다.'}</code>
  </li>
  <li>
    {/* jx-error: {"dir":"json","input":"{\"태그\": []}"} */}
    <code>{'{"태그": []}'}</code>는 <code>{'XML로 변환할 수 없습니다: $["태그"]: 빈 배열과 중첩 배열은 반복 XML 요소로 표현할 수 없습니다.'}</code>
  </li>
</ul>

<h3>XML → JSON</h3>

{/* jx-to-json */}
```xml
<응답>
  <결과코드>00</결과코드>
  <항목>
    <지역>서울</지역>
    <기온>18.0</기온>
  </항목>
  <항목>
    <지역>부산</지역>
    <기온>21.5</기온>
  </항목>
</응답>
```

<p>보기 좋게 출력을 켜면 다음과 같습니다.</p>

```json
{
  "응답": {
    "결과코드": "00",
    "항목": [
      {
        "지역": "서울",
        "기온": "18.0"
      },
      {
        "지역": "부산",
        "기온": "21.5"
      }
    ]
  }
}
```

<p><code>결과코드</code>의 <code>00</code>과 <code>18.0</code>은 문자열이라 앞뒤의 0이 그대로 남습니다.</p>

<h3>XML → JSON이 멈추는 경우</h3>
<ul>
  <li>
    {/* jx-error: {"dir":"xml","input":"<응답><항목 순번=\"1\"><지역>서울</지역></항목></응답>"} */}
    <code>{'<응답><항목 순번="1">…</항목></응답>'}</code>은 <code>{'JSON으로 변환할 수 없습니다: /응답/항목[1]/@순번: 현재 JSON 변환 규칙으로 XML 속성을 표현할 수 없습니다.'}</code>
  </li>
  <li>
    {/* jx-error: {"dir":"xml","input":"<안내>배송은 <b>3일</b> 걸립니다</안내>"} */}
    <code>{'<안내>배송은 <b>3일</b> 걸립니다</안내>'}</code>는 <code>{'JSON으로 변환할 수 없습니다: /안내: 현재 JSON 변환 규칙으로 텍스트와 자식 요소의 혼합을 표현할 수 없습니다.'}</code>
  </li>
</ul>
<p>위치의 번호는 같은 이름의 요소를 1부터 센 값으로, <code>항목[2]</code>는 부모 요소 아래 두 번째 <code>항목</code>입니다.</p>

<h2>제한</h2>
<ul>
  <li><strong>XML → JSON 값은 모두 문자열입니다.</strong> XML에는 숫자·불리언 타입이 없어 <code>{'<수량>2</수량>'}</code>는 <code>"2"</code>가 됩니다. 빈 요소는 <code>""</code>가 되므로 JSON의 <code>null</code>과 <code>{'{}'}</code>는 왕복하면 <code>""</code>가 됩니다.</li>
  <li><strong>자식 요소가 하나인지 여럿인지에 따라 모양이 달라집니다.</strong> <code>항목</code>이 하나면 객체, 둘 이상이면 배열입니다. JSON을 읽는 코드는 두 경우를 모두 처리해야 합니다.</li>
  <li><strong>자식 요소가 없는 요소의 텍스트는 그대로 유지됩니다.</strong> 앞뒤 공백과 줄바꿈도 포함합니다. 무시하는 것은 자식 요소 사이의 공백뿐입니다. 주석과 처리 명령은 건너뜁니다.</li>
  <li><strong>속성, 네임스페이스 선언, 혼합 텍스트는 변환을 멈춥니다</strong>(위 참고). <code>@id</code> 같은 속성용 키로 바꾸는 기능은 없습니다.</li>
  <li><strong>XML 문법 오류는 브라우저 파서의 메시지</strong>라서 Chrome, Firefox, Safari마다 문구가 다릅니다. 변환 없이 XML을 정렬·압축하려면 <a href="/ko/tools/xml-formatter/">XML 포매터</a>를 쓰세요.</li>
</ul>

<h2>JSON vs XML</h2>
<p>
  <strong>JSON</strong>은 REST API와 웹 서비스에서 널리 쓰이는 데이터 형식으로 간결하고 읽기 쉬우며 모든 언어에서 다룰 수 있습니다.
  <strong>XML</strong>은 엔터프라이즈 시스템, SOAP API, 설정 파일(Maven, Spring), 문서 형식(SVG, XHTML, RSS)에서 여전히 널리 사용됩니다.
  형식이 다른 시스템을 연결할 때 같은 데이터가 다른 형식에서 어떻게 보이는지, 어떤 구조가 대응되지 않는지 이 도구로 확인할 수 있습니다.
</p>
