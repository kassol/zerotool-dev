<h2>어떤 효과를 써야 할까</h2>
<ul>
  <li><strong>모자이크</strong> — 블록별 평균 색상으로 채웁니다. 의도적인 모자이크 느낌이나 일반적인 가림에 적합합니다. 텍스트에는 적합하지 않으며, 블록을 크게 해도 얼굴이 식별되지 않는다고 보장할 수 없습니다.</li>
  <li><strong>블러</strong> — 부드럽게 흐리는 효과입니다. 보기에는 "가림 처리"처럼 보이지 않지만, 강력한 디블러 처리로 복원될 수 있어 텍스트에는 마찬가지로 안전하지 않습니다.</li>
  <li><strong>단색 채우기</strong> — 영역을 단색으로 완전히 덮습니다. 원본 픽셀 정보를 완전히 없애는 유일한 방법입니다. 비밀번호, 토큰, API 키, AI 채팅에 붙여넣을 내용에는 반드시 이것을 사용하세요.</li>
</ul>

<h2>세 가지 효과가 픽셀에 하는 일</h2>
<p>
  설정을 바꿀 때마다 도구는 원본 이미지를 다시 그린 뒤 효과를 새로 적용하므로 효과가 겹치지 않습니다. 아래 숫자는 도구의 모자이크 함수로 계산한 값입니다.
</p>
<ul>
  <li><strong>모자이크</strong>(블록 크기 4–64 px, 기본 16)는 영역의 왼쪽 위를 기준으로 정사각형 칸을 나누고, 각 칸을 그 안 픽셀의 평균색으로 칠합니다. 검은 픽셀 2개와 흰 픽셀 2개가 있는 2 × 2 칸은 <code>rgb(128, 128, 128)</code>이 됩니다. 색은 투명도로 가중 평균하므로, 불투명한 빨강 2개와 완전히 투명한 픽셀 2개가 있는 칸은 어두운 빨강이 아니라 반투명 빨강(<code>255, 0, 0, alpha 128</code>)이 됩니다.</li>
  <li><strong>가장자리 칸은 남은 크기에 맞춰 줄어듭니다.</strong> 너비 100 px 영역을 블록 16으로 처리하면 16 px 열 6개와 마지막 4 px 열(96–99번째 픽셀)이 생깁니다. 가장자리 칸은 자기 픽셀만 평균하고 영역 밖 픽셀은 읽지 않습니다.</li>
  <li><strong>블러</strong>(반경 2–40 px, 기본 12)는 영역을 <code>ceil(너비 / 반경)</code> × <code>ceil(높이 / 반경)</code> 크기의 작은 캔버스에 스무딩을 켜고 그린 뒤 원래 크기로 다시 늘립니다. 300 × 40 영역을 반경 12로 블러하면 남는 샘플은 25 × 4 = 100개이고, 같은 영역을 블록 16으로 모자이크하면 19 × 3 = 57칸입니다. 블러가 남기는 정보량은 모자이크와 비슷하며, 스무딩은 칸의 경계만 감춥니다.</li>
  <li><strong>단색 채우기</strong>는 영역을 불투명한 한 가지 색(기본 검정)으로 칠하므로 원래 픽셀이 전혀 남지 않습니다.</li>
  <li>점선 테두리는 미리보기에만 그려집니다. 다운로드와 이미지 복사는 다시 렌더링하므로 테두리가 들어가지 않습니다.</li>
</ul>

<h2>모자이크한 글자가 복원되는 이유</h2>
<p>모자이크와 블러는 정보를 잃지만, 공격자는 계산을 거꾸로 풀 필요가 없습니다. 같은 글꼴로 후보 글자를 그리고, 같은 필터를 적용한 뒤 블록끼리 비교하면 됩니다. 알려진 글꼴의 글자는 후보가 적어서 이 방법이 잘 통합니다.</p>
<ul>
  <li><a href="https://github.com/spipm/Depix">Depix</a>(2020년)는 선형 박스 필터로 모자이크한 스크린샷에서, 렌더링한 문자열과 블록을 대조해 글자를 복원합니다. 이 도구의 모자이크도 같은 종류의 필터입니다.</li>
  <li>Bishop Fox의 <a href="https://bishopfox.com/blog/unredacter-tool-never-pixelation">Unredacter</a>(2022년)는 한 글자씩 추측하고 격자 오프셋도 모두 시도하므로, 격자가 글자와 맞지 않아도 막지 못합니다.</li>
  <li><a href="https://petsymposium.org/popets/2016/popets-2016-0047.php">Hill, Zhou, Saul, Shacham(PoPETs 2016)</a>은 모자이크 칸이 글자 크기보다 큰 경우, 강한 JPEG 압축 이후, 블러한 글자 모두에서 읽을 수 있는 글자를 복원했고, 모자이크와 블러는 글자를 가리는 방법으로 쓸 수 없다고 결론지었습니다.</li>
</ul>
<p>얼굴의 경우 <a href="https://arxiv.org/abs/1609.00408">McPherson, Shokri, Shmatikov(2016년)</a>가 모자이크·블러 처리한 이미지 속 인물을 식별하는 모델을 보였습니다. 신원을 숨겨야 할 때는 단색 채우기를 쓰세요.</p>

<h2>제대로 가린 뒤에도 남는 정보</h2>
<ul>
  <li><strong>길이.</strong> 글자에 딱 맞춘 검은 막대는 글자 수를 드러냅니다. 고정폭 글꼴이면 정확한 글자 수입니다. PIN 같은 짧은 비밀은 글자보다 넓게 칠하세요.</li>
  <li><strong>파일 이름.</strong> 다운로드한 파일은 원래 이름 뒤에 <code>-pixelated</code>가 붙어 <code>신분증-홍길동.jpg</code>가 <code>신분증-홍길동-pixelated.png</code>가 됩니다. 붙여넣은 이미지는 <code>pasted-image-pixelated</code>로 저장됩니다. 이름으로 사람을 알아볼 수 있으면 공유 전에 바꾸세요.</li>
  <li><strong>스크린샷의 다른 부분.</strong> 탭 제목, 주소 표시줄, 알림, 자동 완성 목록, 로그 아래쪽에 다시 나오는 같은 키에 가린 정보가 또 찍혀 있는 경우가 많습니다.</li>
  <li><strong>원본 파일.</strong> 가리기는 새 파일을 만들 뿐이고 원본은 디스크와 사진 백업에 남습니다. 내보낸 파일은 캔버스 픽셀만으로 만들므로 원본의 EXIF·GPS도, 원본 파일의 바이트도 들어 있지 않습니다. 2023년 aCropalypse에서는 Google Pixel 마크업(<a href="https://www.cve.org/CVERecord?id=CVE-2023-21036">CVE-2023-21036</a>)과 Windows 캡처 도구(<a href="https://www.cve.org/CVERecord?id=CVE-2023-28303">CVE-2023-28303</a>)가 자른 이미지로 원본 파일을 덮어쓰면서 길이를 줄이지 않아, 자르기 전 부분을 파일 끝에서 복원할 수 있었습니다.</li>
</ul>

<h2>주요 활용 예시</h2>
<ul>
  <li><strong>AI 채팅, 고객 지원 티켓, 포럼에 올리기 전 스크린샷 정리</strong> — API 키, 토큰, 계정 ID, 이메일 주소, 내부 URL을 단색 채우기로 가립니다.</li>
  <li><strong>사진 공개 전 얼굴이나 번호판 가리기</strong> — 신원을 확실히 숨겨야 한다면 단색 채우기를 사용하세요. 모자이크나 블러 처리된 얼굴도 인식 모델로 대조될 수 있습니다.</li>
  <li><strong>레트로 픽셀 아트 효과</strong> — "전체 이미지에 적용"을 켜고 큼직한 모자이크 블록 크기를 선택합니다.</li>
</ul>

<h2>개인정보: 업로드 없음</h2>
<p>
  디코딩, 효과 렌더링, 내보내기는 모두 <code>createImageBitmap</code>과 Canvas 2D API를 통해 브라우저에서 처리됩니다.
  서버 처리 과정이 전혀 없어 비행기 모드에서도 그대로 동작합니다. 이 도구의 저장 정책은 <code>disabled</code>로,
  이미지를 로컬 스토리지에 저장하지 않으며 이 페이지는 분석·광고 스크립트도 불러오지 않습니다.
</p>

<h2>제한 사항</h2>
<ul>
  <li>얼굴이나 텍스트 자동 인식 기능은 없습니다. 영역은 직접 그려야 합니다. 신뢰할 만한 얼굴·텍스트 인식에는 머신러닝 모델이 필요하며, 이는 전용 AI 이미지 도구가 더 적합한 역할입니다.</li>
  <li>그린 영역은 이후 이동, 크기 조절, 개별 효과 지정이 불가능합니다. 다시 그리려면 실행 취소 후 새로 그리세요.</li>
  <li>한 번에 이미지 한 장만 처리하며, 여러 파일 일괄 처리는 지원하지 않습니다.</li>
  <li>애니메이션 GIF는 설계상 정적 이미지 한 프레임으로 내보내집니다. 모든 프레임을 개별 이미지로 받으려면 <a href="/ko/tools/gif-splitter/">GIF 프레임 추출기</a>를 사용하세요.</li>
  <li>효과는 한 번에 한 종류이며 모든 영역에 같은 효과가 적용됩니다. 같은 이미지에서 얼굴은 모자이크, 비밀번호는 단색으로 가리려면 첫 결과를 다운로드한 뒤 그 파일을 다시 불러와 두 번째 효과를 적용하세요.</li>
  <li>너비나 높이가 2 px 미만인 영역은 버려지므로 잘못 클릭해도 빈 영역이 생기지 않습니다. 「전체 이미지에 적용」이 켜져 있는 동안에는 영역을 그릴 수 없습니다.</li>
  <li>JPEG에는 투명도가 없어 투명한 부분은 흰색으로 채워집니다. 브라우저가 WebP를 인코딩하지 못하면(MDN 호환성 데이터 기준 Safari) WebP를 골라도 PNG 파일로 저장됩니다. 「이미지 복사」로 클립보드에 들어가는 것은 항상 PNG입니다.</li>
  <li>캔버스 크기에는 브라우저 상한이 있어, 내보내기에 실패하면 「내보내기 실패 — 더 작은 이미지로 시도해 보세요」가 표시됩니다.</li>
  <li>HEIC 사진은 Safari 17 이상에서만 열립니다(<a href="https://caniuse.com/heif">Can I use</a>). 다른 브라우저에서는 먼저 JPEG로 변환하세요.</li>
  <li>PDF 가림 처리는 지원 범위 밖입니다. 로컬 PDF 편집기의 가림 처리 기능을 사용하세요.</li>
</ul>
