프로그래밍 언어, 프레임워크, API마다 고유한 네이밍 컨벤션이 있습니다. JavaScript는 변수에 camelCase, 클래스에 PascalCase를 사용합니다. Python은 snake_case를 전반적으로 채택합니다. CSS는 kebab-case를 선호합니다. 데이터베이스 컬럼명은 snake_case가 일반적입니다. 여러 단어로 된 식별자를 손으로 일일이 변환하는 작업은 번거롭지만, 텍스트 케이스 변환 도구를 사용하면 즉시 처리됩니다.

[텍스트 케이스 온라인 변환하기 →](/ko/tools/text-case/)

## 주요 케이스 종류

### camelCase

단어를 공백 없이 연결합니다. 첫 번째 단어는 소문자, 이후 단어의 첫 글자는 대문자로 시작합니다:

```
userLoginCount
fetchApiResponse
isAuthenticated
```

**사용 위치**: JavaScript/TypeScript 변수·함수, JSON 키, Java 메서드, Swift 프로퍼티.

### PascalCase(UpperCamelCase)

camelCase와 동일하지만 첫 번째 단어도 대문자로 시작합니다:

```
UserLoginCount
FetchApiResponse
IsAuthenticated
```

**사용 위치**: JavaScript/TypeScript 클래스명, React 컴포넌트명, C# 타입, Python 클래스명.

### snake_case

언더스코어로 단어를 구분하고 모두 소문자로 작성합니다:

```
user_login_count
fetch_api_response
is_authenticated
```

**사용 위치**: Python 변수·함수, Ruby, PostgreSQL 컬럼명, PHP, Rust 상수(SCREAMING 변형 포함).

### SCREAMING_SNAKE_CASE

snake_case와 동일하지만 모두 대문자로 작성합니다:

```
USER_LOGIN_COUNT
MAX_RETRY_COUNT
API_BASE_URL
```

**사용 위치**: 대부분의 언어에서 상수(Python `CONSTANTS`, Java `FINAL_FIELDS`), 환경 변수, C/C++ 매크로.

### kebab-case(dash-case)

하이픈으로 단어를 구분하고 모두 소문자로 작성합니다:

```
user-login-count
fetch-api-response
is-authenticated
```

**사용 위치**: CSS 클래스명·커스텀 프로퍼티, HTML 속성, URL 슬러그, npm 패키지명, CLI 플래그.

### Title Case

각 단어의 첫 글자를 대문자로 시작합니다:

```
User Login Count
Fetch Api Response
Is Authenticated
```

**사용 위치**: 블로그 포스트 제목, 페이지 헤딩, 버튼 레이블, 메뉴 항목.

### UPPER CASE / lower case

단순 대문자·소문자 변환. 데이터베이스 키, enum 값, 표시 포매팅에 유용합니다.

## 실무 활용 사례

### API → 코드 매핑

REST API는 camelCase JSON 키를 사용하는 경우가 많지만, Python 클라이언트는 snake_case 변수를 기대합니다. 데이터 모델이나 매퍼를 작성할 때:

API 입력:
```json
{ "userId": 42, "firstName": "Alice", "createdAt": "2026-01-01" }
```

Python 모델 필드(snake_case):
```python
user_id: int
first_name: str
created_at: datetime
```

{/* tc-check: {"input":"userId","snake":"user_id"} */}
{/* tc-check: {"input":"firstName","snake":"first_name"} */}
{/* tc-check: {"input":"createdAt","snake":"created_at"} */}
{/* tc-check: {"input":"userId firstName createdAt","snake":"user_id_first_name_created_at"} */}
{/* tc-check: {"input":"userId,firstName,createdAt","snake":"user_id_first_name_created_at"} */}
{/* tc-check: {"input":"userId\nfirstName\ncreatedAt","snake":"user_id_first_name_created_at"} */}

변환 도구는 camelCase의 대소문자 경계에서 단어를 나누므로, `userId`, `firstName`, `createdAt`을 붙여넣으면 snake_case 줄이 `user_id`, `first_name`, `created_at`이 됩니다. 이름은 하나씩 붙여넣으세요. 공백, 쉼표, 줄바꿈도 구분자라서 세 이름을 한꺼번에 넣으면 `user_id_first_name_created_at` 하나가 됩니다.

### 데이터베이스 컬럼 → 코드 변수

PostgreSQL은 snake_case 컬럼명을 사용합니다. 컬럼명을 하나씩 붙여넣고 camelCase 줄을 복사하면 TypeScript 인터페이스의 필드 이름이 됩니다. 대소문자를 손으로 고칠 필요가 없습니다.

### 코드베이스 전체에서 변수명 변경

리팩토링 시 여러 단어로 된 식별자를 변경해야 할 때, 기존 이름을 목표 케이스로 변환한 다음 에디터의 찾기·바꾸기를 사용합니다.

### URL 슬러그 생성

"My Favorite Developer Tools" 같은 페이지 제목을 URL 슬러그용 `my-favorite-developer-tools`(kebab-case)로 변환합니다.

### CSS 커스텀 프로퍼티명

```css
/* 변환 전: userPrimaryColor (JS에서 camelCase) */
/* 변환 후: --user-primary-color (CSS용 kebab-case) */
```

## 변환 도구의 작동 원리

{/* tc-check: {"input":"XMLHttpRequest","snake":"xml_http_request"} */}
{/* tc-check: {"input":"base64","snake":"base_64"} */}
{/* tc-check: {"input":"don't","snake":"dont"} */}

camelCase, PascalCase, kebab-case, snake_case, CONSTANT_CASE 다섯 가지 코드용 케이스는 입력을 단어로 나눈 뒤 각 규칙대로 이어 붙입니다. 단어를 나누는 곳은 네 가지입니다. 소문자나 숫자 뒤에 대문자가 올 때(`userId` → user, Id), 연속된 대문자 뒤에 새 단어가 시작될 때(`XMLHttpRequest` → XML, Http, Request, snake_case는 `xml_http_request`), 글자와 숫자 사이(`base64` → base, 64, snake_case는 `base_64`), 그리고 공백, 언더스코어, 하이픈, 기호처럼 글자도 숫자도 아닌 문자입니다. 아포스트로피는 먼저 지우므로 `don't`는 한 단어로 남고 snake_case는 `dont`입니다.

{/* tc-check: {"input":"userLoginCount","title":"Userlogincount","sentence":"Userlogincount"} */}
{/* tc-check: {"input":"my_variable_name","title":"My_variable_name"} */}

UPPER CASE, lower case, Title Case, Sentence case 네 줄은 단어를 나누지 않고 대소문자만 바꿉니다. Title Case는 공백으로 나뉜 각 단어의 첫 글자를 대문자로, 나머지를 소문자로 바꾸므로 `userLoginCount`의 Title Case와 Sentence case는 모두 `Userlogincount`, `my_variable_name`의 Title Case는 `My_variable_name`입니다.

{/* tc-check: {"input":"myVariableName","camel":"myVariableName","snake":"my_variable_name","kebab":"my-variable-name"} */}
{/* tc-check: {"input":"MY VARIABLE NAME","camel":"myVariableName","snake":"my_variable_name","kebab":"my-variable-name"} */}
{/* tc-check: {"input":"café au lait","snake":"café_au_lait"} */}
{/* tc-check: {"input":"사용자 이름","snake":"사용자_이름"} */}

- `my_variable_name`, `my-variable-name`, `MY VARIABLE NAME`, `myVariableName`은 모두 `myVariableName`, `my_variable_name`, `my-variable-name`이 됩니다
- 악센트가 있는 글자는 그대로 남습니다. `café au lait`의 snake_case는 `café_au_lait`입니다
- 한글은 대소문자가 없어 그대로 남습니다. `사용자 이름`의 snake_case는 `사용자_이름`입니다

공백, 쉼표, 줄바꿈도 구분자라서 입력 전체가 이름 하나로 합쳐집니다. 이름은 하나씩 붙여넣으세요.

## 주의해야 할 엣지 케이스

{/* tc-check: {"input":"userID","camel":"userId","snake":"user_id"} */}
{/* tc-check: {"input":"user ID","camel":"userId","snake":"user_id"} */}

**약어**: `userId`(ID를 접미사로 처리) vs `userID`(약어 보존) 중 어느 쪽을 쓸지 팀에서 통일하세요. 변환 도구는 `ID`를 한 단어로 보므로 camelCase에서는 첫 글자만 대문자로 남깁니다. `userID`와 `user ID` 모두 camelCase는 `userId`, snake_case는 `user_id`입니다. `userID`로 정했다면 변환한 뒤 직접 고치세요.

{/* tc-check: {"input":"item3d","camel":"item3D","snake":"item_3_d"} */}
{/* tc-check: {"input":"item3D","camel":"item3D","snake":"item_3_d"} */}
{/* tc-check: {"input":"item_3d","camel":"item3D","snake":"item_3_d"} */}

**숫자**: `item3d`·`item3D`·`item_3d`? 컨벤션은 다양합니다. 변환 도구는 숫자를 별도 단어로 나누므로 세 입력 모두 snake_case는 `item_3_d`, camelCase는 `item3D`가 됩니다.

{/* tc-check: {"input":"_private","camel":"private","snake":"private","kebab":"private"} */}

**앞뒤 구분자**: `_private`(Python의 프라이빗 속성 컨벤션)에서 이 변환 도구는 앞의 언더스코어를 제거합니다. snake_case, kebab-case, camelCase 모두 `private`가 됩니다.
