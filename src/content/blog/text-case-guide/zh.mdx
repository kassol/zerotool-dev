每门语言都有自己的命名惯例。JavaScript 变量用 camelCase，Python 函数用 snake_case，CSS 类名用 kebab-case，数据库列名通常是 snake_case，React 组件是 PascalCase，常量是 SCREAMING_SNAKE_CASE。写跨语言代码、对接 API、做数据库字段映射时，在各种命名风格之间手动转换既枯燥又容易出错。

## 常见的命名风格

### camelCase（小驼峰）

多个单词连在一起，第一个单词全小写，后续每个单词首字母大写：

```
userLoginCount
fetchApiResponse
isAuthenticated
```

**使用场合**：JavaScript / TypeScript 变量和函数、JSON key、Java 方法名、Swift 属性。

### PascalCase（大驼峰 / UpperCamelCase）

和 camelCase 一样，但第一个单词首字母也大写：

```
UserLoginCount
FetchApiResponse
IsAuthenticated
```

**使用场合**：JavaScript / TypeScript 类名、React 组件名、C# 类型、Python 类名。

### snake_case（下划线命名）

单词之间用下划线连接，全小写：

```
user_login_count
fetch_api_response
is_authenticated
```

**使用场合**：Python 变量和函数、Ruby、PostgreSQL 列名、PHP、C/C++ 结构体字段。

### SCREAMING_SNAKE_CASE（全大写下划线）

和 snake_case 一样，但全部大写：

```
USER_LOGIN_COUNT
MAX_RETRY_COUNT
API_BASE_URL
```

**使用场合**：各语言的常量——Python 的模块级常量、Java 的 `static final`、环境变量、C/C++ 的宏定义。

### kebab-case（短横线命名）

单词之间用连字符（`-`）连接，全小写：

```
user-login-count
fetch-api-response
is-authenticated
```

**使用场合**：CSS 类名和自定义属性、HTML 属性、URL slug、npm 包名、CLI 命令行参数。

### Title Case（标题大写）

每个单词首字母大写：

```
User Login Count
Fetch Api Response
Is Authenticated
```

**使用场合**：博客标题、页面标题、按钮文字、菜单项。

## 实战场景

### REST API 响应 → 后端模型字段

API 返回 camelCase，Python 代码用 snake_case。把字段名逐个粘进转换器，复制 snake_case 一行即可：

API 返回：
```json
{ "userId": 42, "firstName": "Alice", "createdAt": "2026-01-01" }
```

Python 模型字段：
```python
user_id: int
first_name: str
created_at: datetime
```

{/* tc-check: {"input":"userId","snake":"user_id"} */}
{/* tc-check: {"input":"firstName","snake":"first_name"} */}
{/* tc-check: {"input":"createdAt","snake":"created_at"} */}
{/* tc-check: {"input":"userId firstName createdAt","snake":"user_id_first_name_created_at"} */}

转换器在 camelCase 的大小写交界处拆词，直接粘贴 `userId`、`firstName`、`createdAt`，snake_case 一行就是 `user_id`、`first_name`、`created_at`。一次只粘一个字段名：空格、逗号和换行都是分隔符，三个名字一起粘会合成一个 `user_id_first_name_created_at`。

### 数据库列名 → 代码变量

PostgreSQL 用 snake_case。把列名逐个粘进去，复制 camelCase 一行，就是 TypeScript interface 的字段名，不用自己改大小写。

### URL Slug 生成

文章标题 "我最常用的开发工具 Top 10" → 转 kebab-case 后得到 `我最常用的开发工具-top-10`（英文部分生效），或者先把英文标题转一下：`My-Top-10-Developer-Tools` → `my-top-10-developer-tools`。

### CSS 自定义属性

从 JavaScript 拿到 camelCase 的变量名，转成 CSS 变量需要的 kebab-case：

```css
/* JS: userPrimaryColor */
/* CSS: --user-primary-color */
```

### 重构时批量改名

重构旧代码，需要把一批 camelCase 函数名改成 snake_case。先用转换器把所有名字转好，再用编辑器的批量替换。

## 转换器的工作原理

转换器先把输入拆成单词，再按各风格拼起来，所有目标风格同时输出。拆词的位置有四种：小写字母或数字后面跟大写字母（`userId` 拆成 user、Id），连续大写后面跟一个新单词（`XMLHttpRequest` 拆成 XML、Http、Request），字母和数字之间（`base64` 拆成 base、64），以及空格、下划线、连字符、标点这类既不是字母也不是数字的字符。撇号先删掉，所以 `don't` 仍是一个词。

{/* tc-check: {"input":"myVariableName","camel":"myVariableName","snake":"my_variable_name","kebab":"my-variable-name"} */}
{/* tc-check: {"input":"MY VARIABLE NAME","camel":"myVariableName","snake":"my_variable_name","kebab":"my-variable-name"} */}
{/* tc-check: {"input":"café au lait","snake":"café_au_lait"} */}
{/* tc-check: {"input":"用户 登录","snake":"用户_登录"} */}

- `my_variable_name`、`my-variable-name`、`MY VARIABLE NAME`、`myVariableName` 都得到 `myVariableName`、`my_variable_name`、`my-variable-name`
- 带重音的字母保留：`café au lait` 的 snake_case 是 `café_au_lait`
- 汉字没有大小写，原样保留：`用户 登录` 的 snake_case 是 `用户_登录`

整段输入按一个名字处理，空格、逗号和换行也是分隔符，所以一次只粘贴一个名字。

## 几个需要注意的边界情况

{/* tc-check: {"input":"userID","camel":"userId","snake":"user_id"} */}
{/* tc-check: {"input":"user ID","camel":"userId","snake":"user_id"} */}

**缩写词**：`userId` 还是 `userID`？两种写法都有人用，团队内统一就好。转换器把 `ID` 当成一个词，camelCase 里只保留首字母大写：输入 `userID` 或 `user ID`，camelCase 都是 `userId`，snake_case 都是 `user_id`。团队选了 `userID` 的写法，转换后要手动改回。

{/* tc-check: {"input":"item3d","camel":"item3D","snake":"item_3_d"} */}

**数字**：`item3d` 还是 `item_3d`？习惯不一。转换器把数字当作单独的词：`item3d` 的 snake_case 是 `item_3_d`，camelCase 是 `item3D`。想要 `item_3d` 就得转换后手动改。

{/* tc-check: {"input":"_private","camel":"private","snake":"private","kebab":"private"} */}

**前导下划线**：Python 的 `_private` 约定表示私有属性，本转换器会去掉开头的下划线：snake_case、kebab-case 和 camelCase 都得到 `private`。
