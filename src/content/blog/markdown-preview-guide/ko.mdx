Markdown 렌더러는 모두 같은 질문에 다른 답을 냅니다. 이 글은 다른 환경에서 렌더링하면 어떻게 보일까 하는 질문입니다. 이 페이지는 이 사이트의 [Markdown 미리보기](/ko/tools/markdown-preview/)가 실제로 적용하는 규칙을 기록해, 문서가 잘못된 것인지 렌더러가 다른 것인지 구분할 수 있게 합니다. 아래 내용은 2026-11-03에 도구 컴포넌트와 micromark 4.0.2, micromark-extension-gfm 3.0.0을 기준으로 확인했습니다. 인용한 HTML은 모두 그 입력에 대한 렌더러의 실제 출력입니다.

## CommonMark와 GFM: 이 미리보기가 렌더링하는 범위

[CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)(2024-01-28 공개)가 바탕입니다. 문단, ATX와 setext 제목, 인용, 순서 있는 목록과 없는 목록, 펜스 코드와 들여쓰기 코드, 인라인 링크와 참조 링크, 이미지, 강조, 코드 스팬, 구분선, 백슬래시 이스케이프, 엔터티 참조를 포함합니다.

[GitHub Flavored Markdown 0.29-gfm](https://github.github.com/gfm/)(2019-04-06 공개)은 CommonMark의 엄격한 상위 집합이며, 명세는 다섯 가지 확장을 더합니다. 표(4.10절), 작업 목록 항목(5.3절), 취소선(6.5절), 자동 링크(6.9절), 허용되지 않는 원시 HTML(6.11절)입니다. 1.1절에는 GitHub가 변환 후 추가 후처리와 정리를 한다는 사실도 적혀 있습니다.

미리보기는 micromark와 GFM 확장을 쓰고, 이 패키지가 제공하는 확장을 모두 켭니다. 명세의 다섯 가지에 각주를 더한 것입니다. 실제 동작은 다음과 같습니다.

- 표는 열 정렬을 지원합니다.
- 작업 목록의 체크박스는 `disabled`로 출력되어 상태는 읽을 수 있지만 미리보기 안에서는 누를 수 없습니다.
- 취소선은 물결표 하나나 둘 다 됩니다. `~one~`과 `~~two~~` 모두 `del` 요소가 됩니다.
- 맨 URL, `www.`로 시작하는 호스트, 이메일 주소가 자동으로 링크가 됩니다. 이메일에는 `mailto:`가 붙습니다.
- 각주는 위첨자 참조와 되돌아가기 링크를 가집니다.

누를 버튼은 없습니다. 입력이 멈춘 뒤 300 ms 후에 렌더링되므로, 빠르게 입력하는 사람에게는 키 하나마다가 아니라 멈출 때마다 한 번 갱신됩니다.

## 렌더링하지 않는 것

렌더러가 구현하는 것은 CommonMark와 위의 GFM 확장입니다. 그 바깥의 표기는 여기서 의미가 없고, 쓴 글자가 그대로 남습니다.

- 수식: `$x^2$`와 `$$` 블록은 글자로 남고 조판되지 않습니다.
- Mermaid 같은 다이어그램: `mermaid` 블록은 평범한 코드 블록이 됩니다. 그림도 색도 없습니다.
- 이모지 단축 코드, 멘션, 이슈 참조: `:tada:`, `@octocat`, `#123`은 입력한 그대로입니다.
- GitHub 알림 블록: `> [!NOTE]`는 인용으로 남고 첫 줄이 글자로 표시됩니다. 인용 자체는 렌더링됩니다.
- 제목 앵커: 어떤 제목에도 `id`가 붙지 않습니다. 렌더러가 만드는 식별자는 각주 영역의 `footnote-label` 하나뿐입니다.
- front matter, 정의 목록, include, 목차 표식: 제거되지 않고 해석되지도, 치환되지도 않습니다.

이 목록은 예측 가능성의 대가입니다. 특정 플랫폼을 위해 쓴 문서에는 이런 표기가 자주 들어갑니다. 미리보기는 그것을 글자로 남기므로 공개 전에 차이가 보입니다.

## 원시 HTML은 모두 이스케이프

렌더러는 `allowDangerousHtml: false`로 만들어지므로, Markdown 안의 모든 HTML 태그가 이스케이프되어 글자로 표시됩니다. 다음 입력은

```markdown
<details>
<summary>더 보기</summary>

숨긴 줄.

</details>
```

이렇게 출력됩니다.

```html
&lt;details&gt;
&lt;summary&gt;더 보기&lt;/summary&gt;
<p>숨긴 줄.</p>
&lt;/details&gt;
```

이스케이프된 태그 줄 사이에 빈 줄이 있으면 그 안의 문단은 Markdown으로 해석됩니다. 컨테이너 자체는 요소가 되지 않습니다.

이유는 실행 위치에 있습니다. 미리보기는 zerotool.dev에서 돌아가고, 입력을 브라우저 저장소에 보관하는 다른 도구와 같은 출처를 씁니다. 원시 HTML을 렌더링하면 붙여 넣은 글의 `onerror`가 붙은 `img` 태그가 이 사이트에서 스크립트로 실행되어, 다른 도구가 저장한 내용에도 닿을 수 있습니다. 이스케이프는 그 경로를 없앱니다. 쓴 글자 가운데 살아 있는 요소가 되는 태그는 하나도 없습니다.

GitHub는 더 좁은 길을 갑니다. GFM 6.11절은 아홉 개 태그 이름(title, textarea, style, xmp, iframe, noembed, noframes, script, plaintext)의 왼쪽 꺾쇠만 이스케이프하고, 그다음 GitHub가 정리합니다(1.1절). 이 미리보기는 모든 태그를 이스케이프하므로 두 단계보다 엄격합니다.

링크와 이미지도 같은 원칙입니다. 링크 주소는 상대 주소이거나 `http`, `https`, `mailto`, `irc`, `ircs`, `xmpp`일 때만 남습니다. 이미지는 상대 주소이거나 `http`, `https`일 때만 남습니다. 나머지는 주소가 비고 링크 글자만 남습니다.

```markdown
[docs](javascript:alert(1)) 그리고 ![x](data:image/png;base64,AAAA)
```

의 출력은 다음과 같습니다.

```html
<p><a href="">docs</a> 그리고 <img src="" alt="x" /></p>
```

링크, 이미지, 강조는 Markdown 문법으로 쓰세요. 문단 안 줄바꿈은 줄 끝 백슬래시나 줄 끝 공백 두 개로 만들 수 있습니다. 둘 다 `br` 요소가 되고 원시 HTML에 기대지 않습니다. `details`, `kbd`, `sub`가 꼭 필요한 문서는 실제로 공개할 플랫폼에서 확인하세요.

"HTML 복사"가 돌려주는 것은 이 이스케이프된 출력입니다. 미리보기 전용 색 강조 태그와 링크에 붙는 `target`, `rel`은 포함하지 않습니다. 복사본의 원시 HTML은 이스케이프된 상태로 남으므로, 붙여 넣은 페이지에서 요소가 되는 것은 Markdown이 만든 부분뿐입니다.

## 한국어 문장 부호 뒤에서 굵게가 안 되는 이유

한국어 문서에서 가장 자주 걸리는 경우입니다. 이렇게 쓰면

```markdown
**중요!**합니다
```

미리보기는 별표를 그대로 보여 줍니다.

```html
<p>**중요!**합니다</p>
```

고장이 아닙니다. CommonMark는 구분자 연속으로 강조를 결정합니다. 6.2절은 "오른쪽 플랭킹"을, 앞이 공백이 아니고, 앞이 문장 부호가 아니거나 앞이 문장 부호이면서 뒤가 공백이나 문장 부호인 연속으로 정의합니다. 여기서 닫는 `**`의 앞은 느낌표 `!`이고, 이는 Unicode 문장 부호이며, 뒤는 한글 `합`으로 문자입니다. 두 조건 모두 성립하지 않아 닫히지 않고, 여는 쪽도 글자로 남습니다.

고치는 방법은 세 가지이며 모두 뜻을 유지합니다.

- 닫는 기호 뒤에 공백을 넣습니다. `**중요!** 합니다`는 `<strong>중요!</strong> 합니다`가 됩니다.
- 전각 공백(U+3000)을 넣습니다. `**중요!**　합니다`. U+3000은 Unicode의 Zs 범주라 CommonMark가 공백으로 봅니다. 닫히고 넓은 간격도 남습니다.
- 문장 부호를 기호 밖으로 뺍니다. `**중요**!합니다`는 `<strong>중요</strong>!합니다`가 됩니다.

이 규칙은 한글만의 문제가 아닙니다. 조건은 "문장 부호가 글자에 바로 닿는 것"입니다. 영어에서도 `**Note:**this`는 글자로 남고 `**Note:** this`만 굵게 됩니다. 한국어가 자주 걸리는 이유는 콜론이나 느낌표를 다음 글자에 붙여 쓰는 습관 때문입니다.

같은 원인으로 `**주의:**입니다`와 `**10%**할인`도 되지 않습니다. 닫는 쪽 앞이 콜론이나 퍼센트 기호이고 뒤가 한글이기 때문입니다. 공백을 넣거나 문장 부호를 기호 밖으로 빼면 됩니다.

이 사이트의 [Markdown Word 변환](/ko/tools/markdown-to-word/)은 micromark의 CJK-friendly 확장을 켜 두어 공백 없이도 이런 표기를 인식합니다. 미리보기는 일부러 켜지 않습니다. 같은 글을 CommonMark나 GFM 렌더러가 어떻게 다루는지 보여 주는 것이 역할이기 때문입니다. [Markdown 치트시트](/ko/blog/markdown-cheat-sheet/)에서 같은 표기와 렌더링 결과를 나란히 볼 수 있습니다.

## 코드, 표, 목록, 인용, front matter

펜스 코드는 시작 펜스 뒤에 언어 이름을 적으면 그 이름으로 색이 입혀집니다.

```js
const greet = name => `Hello, ${name}!`;
console.log(greet("ZeroTool"));
```

등록된 언어는 12가지이며 사용할 수 있는 이름은 다음과 같습니다. JavaScript(`js`), TypeScript(`ts`), Python(`py`), Go, PHP, Ruby(`rb`), Java, Bash(`sh`, `shell`), JSON, XML(`html`), CSS, Markdown(`md`). 그 밖의 이름은 평범한 코드 블록이 되어 글자가 이스케이프되고 고정폭으로 색 없이 표시됩니다. 네 칸 들여쓰기 코드도 되지만 언어는 붙지 않습니다.

표에는 머리글 행과 구분 행이 필요합니다. 구분 행의 콜론이 정렬을 정하고, 셀 안의 세로줄은 `\|`로 씁니다.

```markdown
| 설정 | 기본값 |
|:-----|-------:|
| 재시도 | 3 |
```

출력은 각 셀에 정렬을 붙입니다. 이 예에서는 `align="left"`와 `align="right"`입니다. 처음과 끝 세로줄은 생략할 수 있고, 열 수는 구분 행이 정합니다.

중첩 목록은 부모 항목의 내용 열에 맞춥니다. 글머리 기호와 공백 하나가 두 칸이므로 자식 항목은 공백 두 칸이면 됩니다.

```markdown
- 부모
  - 자식
```

번호 목록은 시작 번호를 유지합니다. `3.`으로 시작하는 목록은 출력에 `start="3"`이 붙습니다. 인용은 두 번째 `>`로 중첩되고, 인용 안의 빈 줄은 같은 인용 안의 새 문단이 됩니다.

front matter는 CommonMark에도 GFM에도 속하지 않으며 미리보기는 제거하지 않습니다. `---`로 시작하는 파일에서는 그 줄이 구분선이 되고, 끝의 `---`가 바로 위 줄의 setext 제목 밑줄로 동작합니다.

```markdown
---
title: "릴리스 노트"
---

본문
```

의 출력은 다음과 같습니다.

```html
<hr />
<h2>title: &quot;릴리스 노트&quot;</h2>
<p>본문</p>
```

실무에서는 붙여 넣기 전에 front matter를 지우거나, 파일 전체를 펜스 코드에 넣어 확인합니다. setext 제목(`제목` 아래 `====`)과 참조 링크는 그대로 동작합니다.

## 각주

GFM 명세는 각주를 정의하지 않지만 미리보기에서는 켜져 있습니다. GitHub가 2021-09-30에 Markdown 필드에 각주를 추가했고, micromark의 GFM 패키지도 구현을 포함합니다. 본문의 참조와 다른 곳의 정의를 씁니다.

```markdown
덧붙입니다.[^1]

[^1]: 덧붙이는 글.
```

첫 줄은 위첨자 링크가 되고 식별자는 `user-content-fn-1`입니다. 정의는 `footnotes` 클래스의 `section`이 되어 순서 목록과 되돌아가기 링크를 담습니다. 생성되는 제목은 영어 Footnotes이고 `sr-only`가 붙으며 네 언어 페이지에서 같습니다. 도구에 번역은 없습니다. 참조는 조각 링크라서 눌러도 새 탭이 열리지 않고 미리보기 안에서만 스크롤됩니다.

정의는 문서 어디에나 둘 수 있습니다. 참조하는 문단보다 앞에 있어도 되고, 하나의 정의를 여러 번 참조할 수 있습니다. 번호는 정의 순서가 아니라 처음 참조된 순서를 따릅니다.

## 개인정보: 페이지 안에서 끝나는 렌더링

Markdown은 브라우저의 JavaScript가 해석하고 렌더링합니다. 업로드하지 않으며 도구도 저장하지 않습니다. 컴포넌트는 사이트의 저장 API를 호출하지 않으므로 도구가 글을 localStorage, 쿠키, 주소 표시줄에 쓰지 않습니다. "지우기"는 편집창, 미리보기, 글자 수를 비우고 대기 중인 갱신을 취소합니다. 도구 안에 포커스가 있을 때 Ctrl/⌘+L도 같습니다.

예외는 이미지입니다. `![설명](https://…)`는 이미지 요소를 만들고 브라우저가 그 주소에서 내려받으므로, 이미지 서버에 IP 주소와 브라우저 정보가 전달됩니다. `images/a.png` 같은 상대 경로는 zerotool.dev로 요청되지만 그곳에 파일이 없습니다. `file:` 주소는 비워집니다. 요청을 전혀 일으키고 싶지 않은 글이라면 이미지를 넣지 말거나 자리 표시자를 쓰세요.

"HTML 복사"는 클립보드 쓰기가 성공한 뒤에만 도구 이름과 동작만 담은 통계 이벤트를 한 번 기록합니다. 실패했거나 새 동작으로 대체된 복사는 기록하지 않고, Markdown과 렌더링 결과도 이벤트에 들어가지 않습니다. 도구 페이지는 다른 도구 페이지처럼 사이트의 통계와 광고 스크립트를 불러오지만, Markdown은 그 입력이 아닙니다.

## GitHub, GitLab, Notion과의 차이

미리보기가 보여 주는 것은 CommonMark와 GFM 계층입니다. 다른 제품은 그 위에 자체 계층을 얹고, 놀라움은 대개 그 계층에서 옵니다.

GitHub는 GFM을 변환한 뒤 후처리와 정리를 합니다(GFM 1.1절). 제목 앵커를 만들기 때문에 `#installation` 같은 링크가 GitHub에서는 동작하고 여기서는 동작하지 않습니다. 이슈와 풀 리퀘스트에서는 작업 목록 상자를 누를 수 있지만 이 미리보기에서는 비활성 상태입니다. 알림 블록, 수식, Mermaid 다이어그램, 이모지 단축 코드, 멘션, 이슈 참조는 GitHub 자체 표기이며 CommonMark 의미가 없습니다. 이런 표기를 쓴 문서는 여기서 평범한 글자로 보입니다.

GitLab의 공식 문서는 GitLab Flavored Markdown을 CommonMark와 GFM 확장, 그리고 GitLab 자체 확장의 조합으로 설명하고, front matter, 알림, 설명 목록, 수식, 다이어그램, GitLab 참조 등을 추가 항목으로 듭니다. 모든 제목에 앵커도 만듭니다. 이 미리보기가 구분선과 제목으로 바꾸는 front matter는 GitLab에서는 메타데이터입니다.

Notion은 블록 편집기입니다. 도움말은 Markdown을 입력할 때 쓰는 단축키로 설명하고, 페이지는 블록으로 이루어져 Markdown 텍스트가 아닙니다. 직접 비교는 블록 내용으로 남는 글자에만 성립합니다. 토글, 데이터베이스, 동기화 블록에는 Markdown 형식이 없어 Markdown 렌더러가 보여 줄 것이 없습니다.

쓸 만한 판단은 이렇습니다. 이 미리보기는 "CommonMark와 GFM 계층이 무엇을 내는가"에 답하고, 플랫폼 계층은 더해집니다. 특정 플랫폼에서 올바르게 보여야 하는 문서는 공개 전에 그곳에서 한 번 렌더링해 확인하세요.

## 제한과 관련 도구

단어 수는 앞뒤 공백을 제거한 글을 공백으로 나눠 셉니다. 한국어 문단은 한 단어가 됩니다. 글자 수는 문자열의 UTF-16 코드 단위 길이로, 공백과 줄바꿈을 포함하고 기본 다국어 평면 밖의 문자는 두 개로 셉니다. 파일 선택도 내보내기도 없으며, 편집창은 일반 텍스트 입력란입니다.

"HTML 복사"는 렌더러의 HTML을 돌려줍니다. 미리보기가 붙이는 색 강조 태그와 조각 링크가 아닌 링크에 붙는 `target`, `rel`은 포함하지 않습니다. 원시 HTML은 복사본에서도 이스케이프된 상태입니다. 이미지는 원래 주소를 유지하므로 붙여 넣은 페이지도 같은 호스트로 요청을 보냅니다.
