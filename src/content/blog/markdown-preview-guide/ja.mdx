Markdown のレンダラーはどれも同じ問いに違う答えを返します。このテキストは、別の環境で描画したらどう見えるのか。本ページは、このサイトの [Markdown プレビュー](/ja/tools/markdown-preview/) が実際に適用する規則を記録し、「文書が悪いのか、レンダラーが違うのか」を切り分けられるようにします。以下の記述は 2026-11-03 にツールのコンポーネントと micromark 4.0.2、micromark-extension-gfm 3.0.0 に照らして確認しました。引用している HTML は、その入力に対するレンダラーの実際の出力です。

## CommonMark と GFM：このプレビューが描画する範囲

[CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)（2024-01-28 公開）が土台です。段落、ATX 見出しと setext 見出し、引用、順序付き・順序なしリスト、フェンスコードとインデントコード、インラインリンクと参照リンク、画像、強調、コードスパン、区切り線、バックスラッシュエスケープ、実体参照を含みます。

[GitHub Flavored Markdown 0.29-gfm](https://github.github.com/gfm/)（2019-04-06 公開）は CommonMark の厳密な上位集合で、仕様は 5 つの拡張を追加します。テーブル（4.10 節）、タスクリスト項目（5.3 節）、打ち消し線（6.5 節）、自動リンク（6.9 節）、許可されない生の HTML（6.11 節）です。1.1 節には、GitHub が変換の後に後処理とサニタイズを行うことも書かれています。

プレビューは micromark と GFM 拡張を使い、このパッケージが提供する拡張をすべて有効にします。仕様の 5 つに脚注を加えたものです。実際の挙動は次のとおりです。

- テーブルは列の配置に対応します。
- タスクリストのチェックボックスは `disabled` 付きで出力され、状態は読めますがプレビュー内では操作できません。
- 打ち消し線はチルダ 1 つでも 2 つでも有効です。`~one~` も `~~two~~` も `del` 要素になります。
- URL、`www.` で始まるホスト名、メールアドレスが自動でリンクになります。メールは `mailto:` 付きです。
- 脚注は上付きの参照と戻りリンクを持ちます。

ボタンはありません。入力が止まって 300 ms 後に描画されるので、速く打つ人には「キーごと」ではなく「区切りごと」の更新に見えます。

## 描画しないもの

レンダラーが実装するのは CommonMark と上記の GFM 拡張です。その外側はここでは意味を持たず、書いた文字がそのまま残ります。

- 数式：`$x^2$` も `$$` ブロックも文字のままで、組版されません。
- Mermaid などの図：`mermaid` ブロックは普通のコードブロックになります。図も色分けもありません。
- 絵文字ショートコード、メンション、課題参照：`:tada:`、`@octocat`、`#123` は入力どおりです。
- GitHub のアラート：`> [!NOTE]` は引用のまま残り、1 行目が文字列として表示されます。引用そのものは描画されます。
- 見出しアンカー：どの見出しにも `id` は付きません。レンダラーが生成する識別子は、脚注の `footnote-label` だけです。
- front matter、定義リスト、include、目次マーカー：取り除かれず、解析も置換もされません。

あるプラットフォーム向けに書いた文書は、これらの記法のどれかを含みがちです。プレビューはそれを文字として残すので、公開前に違いが見えます。

## 生の HTML はすべてエスケープ

レンダラーは `allowDangerousHtml: false` で生成されるため、Markdown 中の HTML タグはすべてエスケープされ、文字として表示されます。次の入力は、

```markdown
<details>
<summary>続きを読む</summary>

隠れた行。

</details>
```

こう出力されます。

```html
&lt;details&gt;
&lt;summary&gt;続きを読む&lt;/summary&gt;
<p>隠れた行。</p>
&lt;/details&gt;
```

エスケープされたタグ行の間に空行があると、その中の段落は Markdown として解析されます。入れ物そのものは要素になりません。

理由は生成元にあります。プレビューは zerotool.dev 上で動き、入力をブラウザーのストレージに保存する他のツールと同じ起源を持ちます。生の HTML を描画すると、貼り付けたテキスト中の `onerror` 付き `img` タグがこのサイトでスクリプトとして動き、他のツールが保存した内容にも手が届きます。エスケープはその経路を丸ごと消します。書いた文字の中から、生きた要素になるタグは一つも出ません。

GitHub はもっと狭い経路を取ります。GFM 6.11 節は 9 つのタグ名（title、textarea、style、xmp、iframe、noembed、noframes、script、plaintext）の左山括弧だけをエスケープし、その後に GitHub がサニタイズします（1.1 節）。このプレビューはすべてのタグをエスケープするので、どちらの段階よりも厳しい設定です。

リンクと画像も同じ考え方です。リンク先は相対 URL、または `http`、`https`、`mailto`、`irc`、`ircs`、`xmpp` のときだけ残ります。画像は相対 URL、または `http`、`https` のときだけ残ります。それ以外はアドレスが空になり、リンク文字だけが残ります。

```markdown
[docs](javascript:alert(1)) と ![x](data:image/png;base64,AAAA)
```

の出力は次のとおりです。

```html
<p><a href="">docs</a> と <img src="" alt="x" /></p>
```

リンク、画像、強調は Markdown の記法で書いてください。段落内の改行は行末のバックスラッシュか行末の空白 2 つで作れます。どちらも `br` 要素になり、生の HTML に依存しません。`details`、`kbd`、`sub` が本当に必要な文書は、実際に公開するプラットフォームで確認してください。

「HTML コピー」が返すのはこのエスケープ済みの出力です。プレビュー専用の色分けタグや、リンクに付ける `target` と `rel` は含みません。コピー内の生の HTML はエスケープされたままなので、貼り付け先で要素になるのは Markdown が生成した部分だけです。

## 日本語の句読点で太字が効かない理由

日本語の文章で最もよく踏むのがこれです。次のように書くと、

```markdown
**注意：**ここは必須です
```

プレビューはアスタリスクをそのまま表示します。

```html
<p>**注意：**ここは必須です</p>
```

壊れているわけではありません。CommonMark は区切り文字の並びで強調を決めます。6.2 節は「右フランキング」を、直前が空白でなく、かつ「直前が句読点でない」か「直前が句読点で直後が空白か句読点」である並びと定義します。ここでは閉じる `**` の直前が全角コロン「：」で、Unicode の句読点であり、直後は「こ」で文字です。どちらの条件も成り立たないため閉じられず、開く側も文字のまま残ります。

直し方は 3 つで、どれも意味を変えません。

- 閉じる記号の後に半角スペースを入れる：`**注意：** ここは必須です` は `<strong>注意：</strong> ここは必須です` になります。
- 全角スペース（U+3000）を入れる：`**注意：**　ここは必須です`。U+3000 は Unicode の Zs に属し、CommonMark はこれを空白として扱います。閉じられ、広い隙間もそのまま残ります。
- 句読点を記号の外へ出す：`**注意**：ここは必須です` は `<strong>注意</strong>：ここは必須です` になります。

この規則は漢字のためのものではありません。条件は「句読点が文字に直接触れていること」です。英語でも `**Note:**this` は文字のままで、`**Note:** this` が太字になります。日本語が頻繁に踏むのは、全角コロンや鉤括弧が次の文字に直接続くのが普通で、間に空白を置く習慣がないからです。

同じ原因で `**「重要」**です` と `**10%**の割引` も効きません。閉じる側の直前が閉じ括弧やパーセント記号で、直後が文字だからです。空白を足すか、句読点を記号の外に出せば直ります。

このサイトの [Markdown Word 変換](/ja/tools/markdown-to-word/) は micromark の CJK-friendly 拡張を有効にしているため、空白なしでもこれらの並びを認識します。プレビューは意図的に有効にしていません。同じテキストを CommonMark や GFM のレンダラーがどう扱うかを見せるのが役割だからです。[Markdown チートシート](/ja/blog/markdown-cheat-sheet/) では、同じ記法と描画結果を並べて確認できます。

## コード、テーブル、リスト、引用、front matter

フェンスコードは開始フェンスの後に言語名を書くと、その名前で色分けされます。

```js
const greet = name => `Hello, ${name}!`;
console.log(greet("ZeroTool"));
```

登録されている言語は 12 種類で、使える名前は次のとおりです。JavaScript（`js`）、TypeScript（`ts`）、Python（`py`）、Go、PHP、Ruby（`rb`）、Java、Bash（`sh`、`shell`）、JSON、XML（`html`）、CSS、Markdown（`md`）。それ以外の名前は普通のコードブロックになり、文字はエスケープされ、等幅で色なしに表示されます。4 スペースのインデントコードも使えますが、言語は付きません。

テーブルにはヘッダー行と区切り行が必要です。区切り行のコロンが配置を決め、セル内の縦棒は `\|` と書きます。

```markdown
| 設定 | 既定値 |
|:-----|-------:|
| 再試行 | 3 |
```

出力では各セルに配置が付きます。この例では `align="left"` と `align="right"` です。先頭と末尾の縦棒は省略でき、列数は区切り行で決まります。

入れ子のリストは親項目の内容列に合わせます。箇条書き記号と空白 1 つで 2 列なので、子項目は 2 スペースで足ります。

```markdown
- 親
  - 子
```

番号付きリストは開始番号を保ちます。`3.` で始まるリストは出力に `start="3"` が付きます。引用は 2 つ目の `>` で入れ子になり、引用内の空行は同じ引用の中の新しい段落になります。

front matter は CommonMark にも GFM にも属さず、プレビューは取り除きません。`---` で始まるファイルでは、その行が区切り線になり、末尾の `---` が直前の行の setext 見出し下線として働きます。

```markdown
---
title: "リリースノート"
---

本文
```

の出力は次のとおりです。

```html
<hr />
<h2>title: &quot;リリースノート&quot;</h2>
<p>本文</p>
```

実務では、貼り付ける前に front matter を消すか、ファイル全体をフェンスコードに入れて確認します。setext 見出し（`見出し` の下に `====`）と参照リンクはそのまま動きます。

## 脚注

GFM 仕様は脚注を定義していませんが、プレビューでは有効です。GitHub が 2021-09-30 に Markdown フィールドへ脚注を追加し、micromark の GFM パッケージも実装を含んでいます。本文中の参照と、別の場所の定義を書きます。

```markdown
補足です。[^1]

[^1]: 補足の本文。
```

1 行目は上付きリンクになり、識別子は `user-content-fn-1` です。定義は `footnotes` クラスの `section` になり、順序付きリストと戻りリンクを含みます。生成される見出しは英語の Footnotes で `sr-only` が付き、4 言語のページで共通です。ツールに翻訳はありません。参照はフラグメントリンクなので、クリックしても新しいタブは開かず、プレビュー内をスクロールします。

定義は文書内のどこにでも置けます。参照する段落より前でもよく、1 つの定義を複数回参照できます。番号は定義順ではなく、最初に参照された順です。

## プライバシー：ページ内で完結する描画

Markdown はブラウザーの JavaScript が解析して描画します。アップロードはなく、ツールも保存しません。コンポーネントはサイトの保存用 API を呼ばないので、ツールがテキストを localStorage、Cookie、アドレスバーに書き込むことはありません。「クリア」は編集欄、プレビュー、文字数を空にし、待機中の更新を取り消します。ツール内にフォーカスがあるときの Ctrl/⌘+L も同じです。

例外は画像です。`![説明](https://…)` は画像要素を作り、ブラウザーがそのアドレスから取得するため、画像のサーバーには IP アドレスとブラウザー情報が伝わります。`images/a.png` のような相対パスは zerotool.dev へ要求され、そこにファイルはありません。`file:` のアドレスは空になります。リクエストを一切起こしたくないテキストでは、画像を置かないか、プレースホルダーにしてください。

「HTML コピー」はクリップボードへの書き込みが成功した後にだけ、ツール名と操作名だけの統計イベントを 1 件記録します。失敗した場合や新しい操作に置き換えられた場合は記録せず、Markdown と描画結果もイベントに含まれません。ツールページは他のツールページと同じくサイトの統計と広告のスクリプトを読み込みますが、Markdown はその入力ではありません。

## GitHub・GitLab・Notion との違い

プレビューが見せるのは CommonMark と GFM の層です。他の製品はその上に独自の層を重ねるので、驚きの多くはその層から来ます。

GitHub は GFM を変換した後に後処理とサニタイズを行います（GFM 1.1 節）。見出しのアンカーを生成するため、`#installation` のようなリンクは GitHub では動き、ここでは動きません。issue と pull request ではタスクリストの箱を操作できますが、このプレビューでは無効のままです。アラート、数式、Mermaid の図、絵文字ショートコード、メンション、課題参照は GitHub 独自の記法で、CommonMark の意味を持ちません。これらを使った文書はここでは普通の文字に見えます。

GitLab の公式ドキュメントは、GitLab Flavored Markdown を CommonMark と GFM 拡張、さらに GitLab 独自の拡張の組み合わせと説明し、front matter、アラート、説明リスト、数式、図、GitLab の参照などを追加項目として挙げています。すべての見出しにアンカーも生成します。このプレビューが区切り線と見出しに変える front matter は、GitLab ではメタデータです。

Notion はブロックエディターです。ヘルプでは Markdown を入力時のショートカットとして説明しており、ページはブロックで構成され、Markdown のテキストそのものではありません。直接の比較が成り立つのは、ブロックの内容として残る文字だけです。トグル、データベース、同期ブロックには Markdown の形式がなく、Markdown レンダラーが見せるものはありません。

使える判断はこうです。このプレビューが答えるのは「CommonMark と GFM の層が何を出すか」で、プラットフォームの層は加算されます。あるプラットフォームで正しく見せたい文書は、公開前にそこで一度描画して確認してください。

## 制限と関連ツール

語数は、前後の空白を除いたテキストを空白で区切って数えます。日本語の段落は 1 語になります。文字数は文字列の UTF-16 コード単位の長さで、空白と改行を含み、基本多言語面の外の文字は 2 と数えます。ファイル選択も書き出しもなく、編集欄はプレーンテキストの入力欄です。

「HTML コピー」はレンダラーの HTML を返します。プレビューが付ける色分けのタグと、フラグメント以外のリンクに付ける `target` と `rel` は含みません。生の HTML はコピーでもエスケープされたままです。画像は元のアドレスを保つので、貼り付け先のページも同じホストへ要求を送ります。

関連ツール：[Markdown 表作成ツール](/ja/tools/markdown-table-generator/) は縦棒のエスケープと日本語を含む列の桁揃えを扱います。[Markdown Word 変換](/ja/tools/markdown-to-word/) は見出しスタイル、番号、表、脚注を持つ文書を書き出し、日本語の句読点の隣の太字も認識します。[Markdown チートシート](/ja/blog/markdown-cheat-sheet/) は記法と生成される HTML を並べています。[Markdown プレビュー](/ja/tools/markdown-preview/) は、どこかへ貼る前の確認に使ってください。
